Configuring HTTPS URL Filtering in Non-decryption Mode

Context

Encrypted traffic filtering can be configured to implement HTTPS URL filtering in non-decryption mode.

A device enabled with encrypted traffic filtering does not decrypt HTTPS traffic. Instead, it implements URL filtering by obtaining the domain name of the website that a user accesses through the SNI field in a Client Hello packet sent by the client in addition to the CN fields in a Certificate packet sent by the server.

Procedure

  1. Enter the system view.

    system-view

  2. Configure the service performance mode of the device.

    forward performance mode { routing | security | security-enhance }

    To enable security services, you are advised to switch the device's service performance mode to the secure forwarding mode (security) or enhanced security mode (security-enhance).

    You can run the display forward performance mode command to check the current service performance mode of the device.

    Some models do not support this command or some parameters. For details, see the command reference.

  3. Create a URL filtering profile.

    profile type url-filter name name

  4. Enable encrypted traffic filtering.

    https-filter enable

    Encrypted traffic filtering takes effect only on the URL filtering profile where it resides, but not globally.

  5. Return to the system view.

    quit

  6. Commit the configuration.

    engine configuration commit

    A new or modified URL filtering profile takes effect only after you commit the configuration.

Follow-up Procedure

This section focuses only on configuration of enabling encrypted traffic filtering in a URL filtering profile. To make the encrypted traffic filtering to take effect, you also need to configure a blacklist, whitelist, or URL category and then reference the URL filtering profile in the security policy. For details, see Configuring Blacklist- and Whitelist-based URL Filtering and Configuring URL Category-based URL Filtering.
