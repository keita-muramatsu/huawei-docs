Configuring a Network-Wide Username and Password and SSL Policy

Context

After the network-wide username and password are configured, the configuration process on the master and member devices is as follows:

  • The master device creates a local administrator with the same username and password as the network-wide username and password.
  • After a member device is approved, a secure HTTPS communication channel is established between it and the master device. Through this channel, the master device sends a packet carrying the network-wide username and password to the member device. After receiving the packet, the member device creates a local administrator with the same network-wide username and password. The master device uses the CA certificate in the PKI realm specified in the SSL policy to verify the local certificate provided by the member device.
  • The master device can then log in to and manage the member device by using the username and password.

All commands in this section need to be configured on the master device.

Procedure

  1. Enter the system view.

    system-view

  2. Load the initial CA certificate to the default realm.

    pki import-certificate default_ca realm default

    The initial CA certificate has been saved to the NVRAM before the device is delivered. To use the initial CA certificate and load it to the default realm, run this command.

  3. Enter the net assistant view.

    net-assistant

    By default, the net assistant view is not displayed.

  4. Enter the system management view.

    system-management

    By default, the system management view is not displayed.

  5. Create a network-wide username and password.

    user name-paravalue password [ password-paravalue ]

    By default, no network-wide username and password are created.

  6. Return to the net assistant view.

    quit

  7. Return to the system view.

    quit

  8. (Optional) Configure an SSL policy on the master device.

    • Using the initial certificate in the default domain poses security risks. To enhance security, you can use your own digital certificate and bind it to the SSL policy. For details about how to apply for and load a certificate, see CLI Configuration Guide - PKI Configuration.
    • The certificates of the master device and member devices must be the same. If the SSL policy bound to the master device changes, the SSL certificates of the member device must be replaced. The procedure is as follows:
      1. To apply for a local certificate for a member device, use the device's ESN as the CN field in its local certificate. The CN field must be in the format XXXX.huawei.com (XXXX indicates the ESN of the member device).
      2. To configure a local certificate for a member device, run the web-manager security server-certificate server-certificate-file command.

    1. Create a PKI realm and enter its view.
      pki realm realm-name 
quit
    2. Import the CA certificate to the device memory.
      pki import-certificate ca [ [ realm realm-name ] { der | pkcs12 | pem } ] filename file-name [ cert-name cert-name ] [ no-check-hash-alg ] [ no-check-same-name ]
    3. Create an SSL policy and bind it to the PKI realm.
      ssl policy sslPolicyName
pki-domain pki-domain 
quit
    4. Configure an SSL policy for the net assistant function.
      net-assistant
system-management
ssl-policy sslPolicyName
    5. Configure the HTTPS server to perform SSL verification on the client.
      ssl-verify-peer enable

Result

Run the display net-assistant system-management history-accounts command to view historical network-wide usernames.
