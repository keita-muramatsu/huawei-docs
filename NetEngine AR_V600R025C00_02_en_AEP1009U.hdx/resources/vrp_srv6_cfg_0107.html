Configuring a BGP Extended Community Attribute

Context

The route coloring process is as follows:

  1. Configure a route-policy and set a specific color value for the desired route.

  2. Apply the route-policy to a BGP peer or a VPN instance as an import or export policy.

After the color extended community attribute is added, routes carrying color values can perform SRv6 recursion based on these values.

Procedure

  1. Configure a route-policy.
    1. Enter the system view.

      system-view

    2. Create a route-policy with a specified node and enter the route-policy view.

      route-policy route-policy-name { deny | permit } node node

    3. (Optional) Configure an if-match clause for the route-policy. The community attributes of routes can be added or modified only if the routes match specified if-match clauses.

      For details, see Table 1.

    4. Configure the BGP color extended community attribute.

      apply extcommunity color color

      The color value ranges from 0 to 4294967295. Currently, it can only be set to 0.

  2. Apply the route-policy.
    • Apply the route-policy to a BGP IPv4 unicast peer.
      1. Enter the system view.
        system-view
      2. Enter the BGP view.
        bgp as-number
      3. Specify a BGP peer.
        peer { ipv4-address | group-name } as-number as-number
      4. Enter the IPv4 unicast address family view.
        ipv4-family unicast
      5. Configure an import or export BGP route-policy.
        peer { ipv4-address | group-name } route-policy route-policy-name { import | export }
    • Apply the route-policy to a BGP IPv6 unicast peer.
      1. Enter the system view.
        system-view
      2. Enter the BGP view.
        bgp as-number
      3. Specify a BGP peer.
        peer { ipv6-address | group-name } as-number as-number
      4. Enter the IPv6 unicast address family view.
        ipv6-family unicast
      5. Configure an import or export BGP route-policy.
        peer { ipv6-address | group-name } route-policy route-policy-name { import | export }
    • Apply the route-policy to a BGP EVPN peer.
      1. Enter the system view.
        system-view
      2. Enter the BGP view.
        bgp as-number
      3. Specify a BGP peer.
        peer { ipv6-address | group-name } as-number as-number
      4. Enter the BGP EVPN address family view.
        l2vpn-family  evpn
      5. Enable the device to exchange routing information with a specified BGP EVPN peer.
        peer { ipv6-address | group-name } enable
      6. Configure an import or export BGP EVPN route-policy.
        peer { ipv6-address | group-name } route-policy route-policy-name { import | export }
    • Apply the route-policy to a VPN instance IPv4 address family.
      1. Enter the system view.
        system-view
      2. Enter the VPN instance view.
        ip vpn-instance vpn-instance-name
      3. Enter the VPN instance IPv4 address family view.
        ipv4-family
      4. Configure an import route-policy for the VPN instance IPv4 address family.
        import route-policy policy-name
      5. Configure an export route-policy for the VPN instance IPv4 address family.
        export route-policy policy-name
    • Apply the route-policy to a VPN instance IPv6 address family.
      1. Enter the system view.
        system-view
      2. Enter the VPN instance view.
        ip vpn-instance vpn-instance-name
      3. Enter the VPN instance IPv6 address family view.
        ipv6-family
      4. Configure an import route-policy for the VPN instance IPv6 address family.
        import route-policy policy-name
      5. Configure an export route-policy for the VPN instance IPv6 address family.
        export route-policy policy-name
