Example for Establishing an IPsec Tunnel in ISAKMP Mode (Using Certificate Authentication)

Networking Requirements

In Figure 1, networks A and B connect to the Internet through DeviceA and DeviceB respectively, and there are reachable routes between the two devices. An ISAKMP IPsec tunnel needs to be established between public network interfaces (interface 1 and interface 3) on the two devices. The two ends of the tunnel use Rivest-Shamir-Adleman (RSA) signature authentication to ensure secure transmission of data flows on specific network segments in networks A and B.

Figure 1 Establishing an IPsec tunnel in ISAKMP mode (using certificate authentication)

In this example, interface 1 and interface 2 represent 10GE 0/0/1 and 10GE 0/0/2 on DeviceA, and interface 3 and interface 4 represent 10GE 0/0/1 and 10GE 0/0/2 on DeviceB.

Configuration Roadmap

The tunnel negotiation parameter settings on DeviceA and DeviceB must be the same.

This example uses default security algorithms of IPsec.

For security purposes, you are advised not to use the weak security algorithm or weak security protocol of this feature. If you must use such a weak security algorithm or protocol, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA.

The configuration roadmap is as follows:
  1. Configure interfaces.
  2. Configure static routes to divert tunnel negotiation packets and encrypted data packets transmitted through the tunnel.
  3. Apply for the local certificate and CA certificate in offline mode and import the certificates to the devices.
  4. Configure ISAKMP IPsec policies and apply an IPsec policy group to an interface.

Procedure

  1. Configure public and private network interfaces on DeviceA.

    # Configure the public network interface 10GE 0/0/1.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] undo portswitch
[DeviceA-10GE0/0/1] ip address 1.1.1.1 24
[DeviceA-10GE0/0/1] quit

    # Configure the private network interface 10GE 0/0/2.

    [DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] undo portswitch
[DeviceA-10GE0/0/2] ip address 10.1.0.1 24
[DeviceA-10GE0/0/2] quit

  2. Configure static routes on DeviceA to divert tunnel negotiation packets and encrypted data packets transmitted through the tunnel.

    Assume that the next-hop IP address of the route from DeviceA to the Internet is 1.1.1.254.

    # Configure a static route to DeviceB to divert tunnel negotiation packets.

    [DeviceA] ip route-static 2.2.2.0 255.255.255.0 1.1.1.254

    # Configure a static route to network B to divert encrypted data packets transmitted through the tunnel.

    [DeviceA] ip route-static 10.1.1.0 255.255.255.0 1.1.1.254

  3. Apply for the local certificate and CA certificate in offline mode and import the certificates to the device.
    1. Create a 3072-bit RSA key pair and allow it to be exported from the device.

      [DeviceA] pki rsa local-key-pair create rsakey_a exportable
 Info: The name of the new key-pair will be: rsakey_a
 The size of the public key ranges from 2048 to 4096.
 Input the bits in the modulus:3072
 Generating key-pairs...
 Generating key-pairs finished

    2. Configure a PKI entity to identify a certificate applicant.

      [DeviceA] pki entity user_a
[DeviceA-pki-entity-user_a] common-name devicea
[DeviceA-pki-entity-user_a] country cn
[DeviceA-pki-entity-user_a] email testa@user.com
[DeviceA-pki-entity-user_a] fqdn testa.abc.com
[DeviceA-pki-entity-user_a] ip-address 1.1.1.1
[DeviceA-pki-entity-user_a] state beijing
[DeviceA-pki-entity-user_a] organization huawei
[DeviceA-pki-entity-user_a] organization-unit dev
[DeviceA-pki-entity-user_a] quit

    3. Apply for a local certificate for the PKI entity in offline mode.

      # Create a PKI realm.

      [DeviceA] pki realm a
[DeviceA-pki-realm-a] entity user_a
[DeviceA-pki-realm-a] rsa local-key-pair rsakey_a
[DeviceA-pki-realm-a] quit

      # Save certificate application information to a certificate request file in PKCS#10 format.

      [DeviceA] pki enroll-certificate realm a pkcs10 filename cer_req
 Info: Creating certificate request file...                                     
 Info: Create certificate request file successfully.

    4. Download the certificate request file using a file transfer protocol, and send the file to the CA server in out-of-band mode, such as through the web system, using a disk, or through an email, to apply for a local certificate from the CA server.

      After a local certificate is successfully requested, download the local certificate a_local.cer and CA certificate a_ca.cer in out-of-band mode. Transfer the certificates to the device storage using a file transfer protocol.

    5. Import the CA certificate into the device memory.

      After the certificate is imported, the a_ca.cer file is deleted from the storage medium by default. To keep it, select N as prompted.

      [DeviceA] pki import-certificate ca filename a_ca.cer
 The CA's Subject is /CN=ca_root 
 The CA's fingerprint is:
   MD5  fingerprint:1135 25D8 96D3 5936 C382 35EA 2CEE 80EB 
   SHA1 fingerprint:6330 974F B2FE 3C52 D16B DAC4 0140 918B 4BCD 3EC7
 Is the fingerprint correct?(Y/N):y
 Info: Succeeded in importing the certificate.  
 Warning: The file in the flash will be deleted. Please select 'N' if you want to keep it. Please select [Y/N]:y 
 Info: Delete Success.

    6. Import the local certificate into the device memory.

      After the certificate is imported, the a_local.cer file is deleted from the storage medium by default. To keep it, select N as prompted.

      [DeviceA] pki import-certificate local filename a_local.cer 
 Info: Succeeded in importing file.
 Warning: The file in the flash will be deleted. Please select 'N' if you want to keep it. Please select [Y/N]:y 
 Info: Delete Success

  4. Configure ISAKMP IPsec policies on DeviceA and apply an IPsec policy group to 10GE 0/0/1.
    1. Create the advanced ACL 3000, define the data flow to be protected, and allow devices on the network segment 10.1.0.0/24 to access the network segment 10.1.1.0/24.

      [DeviceA] acl 3000
[DeviceA-acl4-advance-3000] rule 5 permit ip source 10.1.0.0 0.0.0.255 destination 10.1.1.0 0.0.0.255
[DeviceA-acl4-advance-3000] quit

    2. Configure an IPsec proposal.

      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceA-ipsec-proposal-tran1] quit

    3. Configure an IKE proposal.

      [DeviceA] ike proposal 10
[DeviceA-ike-proposal-10] authentication-method rsa-signature
[DeviceA-ike-proposal-10] prf hmac-sha2-256
[DeviceA-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceA-ike-proposal-10] dh group14
[DeviceA-ike-proposal-10] integrity-algorithm hmac-sha2-256  
[DeviceA-ike-proposal-10] quit

    4. Configure an IKE peer.

      [DeviceA] ike peer b
[DeviceA-ike-peer-b] ike-proposal 10
[DeviceA-ike-peer-b] local-id-type dn
[DeviceA-ike-peer-b] remote-id-type dn
[DeviceA-ike-peer-b] certificate local-filename a_local.cer
[DeviceA-ike-peer-b] remote-address 2.2.2.2
[DeviceA-ike-peer-b] remote-id /C=CN/ST=beijing/O=huawei/OU=dev/CN=deviceb
[DeviceA-ike-peer-b] quit

    5. Configure an IPsec policy.

      [DeviceA] ipsec policy map1 10 isakmp
[DeviceA-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceA-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceA-ipsec-policy-isakmp-map1-10] ike-peer b
[DeviceA-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceA-ipsec-policy-isakmp-map1-10] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

    6. Apply an IPsec policy group to 10GE 0/0/1.

      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ipsec policy map1
[DeviceA-10GE0/0/1] quit

  5. Configure public and private network interfaces on DeviceB.

    # Configure the public network interface 10GE 0/0/1.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] undo portswitch
[DeviceB-10GE0/0/1] ip address 2.2.2.2 24
[DeviceB-10GE0/0/1] quit

    # Configure the private network interface 10GE 0/0/2.

    [DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] undo portswitch
[DeviceB-10GE0/0/2] ip address 10.1.1.1 24
[DeviceB-10GE0/0/2] quit

  6. Configure static routes on DeviceB to divert tunnel negotiation packets and encrypted data packets transmitted through the tunnel.

    Assume that the next-hop IP address of the route from DeviceB to the Internet is 2.2.2.254.

    # Configure a static route to DeviceA to divert tunnel negotiation packets.

    [DeviceB] ip route-static 1.1.1.0 255.255.255.0 2.2.2.254

    # Configure a static route to network A to divert encrypted data packets transmitted through the tunnel.

    [DeviceB] ip route-static 10.1.0.0 255.255.255.0 2.2.2.254

  7. Apply for the local certificate and CA certificate in offline mode and import the certificates to the device.
    1. Create a 3072-bit RSA key pair and allow it to be exported from the device.

      [DeviceB] pki rsa local-key-pair create rsakey_b exportable
 Info: The name of the new key-pair will be: rsakey_b
 The size of the public key ranges from 2048 to 4096.
 Input the bits in the modulus:3072
 Generating key-pairs...
 Generating key-pairs finished

    2. Configure a PKI entity to identify a certificate applicant.

      [DeviceB] pki entity user_b
[DeviceB-pki-entity-user_b] common-name deviceb
[DeviceB-pki-entity-user_b] country cn
[DeviceB-pki-entity-user_b] email testb@user.com
[DeviceB-pki-entity-user_b] fqdn testb.abc.com
[DeviceB-pki-entity-user_b] ip-address 2.2.2.2
[DeviceB-pki-entity-user_b] state beijing
[DeviceB-pki-entity-user_b] organization huawei
[DeviceB-pki-entity-user_b] organization-unit dev
[DeviceB-pki-entity-user_b] quit

    3. Apply for a local certificate for the PKI entity in offline mode.

      # Create a PKI realm.

      [DeviceB] pki realm b
[DeviceB-pki-realm-b] entity user_b
[DeviceB-pki-realm-b] rsa local-key-pair rsakey_b
[DeviceB-pki-realm-b] quit

      # Save certificate application information to a certificate request file in PKCS#10 format.

      [DeviceB] pki enroll-certificate realm b pkcs10 filename cer_req
 Info: Creating certificate request file...                                     
 Info: Create certificate request file successfully.

    4. Download the certificate request file using a file transfer protocol, and send the file to the CA server in out-of-band mode, such as through the web system, using a disk, or through an email, to apply for a local certificate from the CA server.

      After a local certificate is successfully requested, download the local certificate b_local.cer and CA certificate b_ca.cer in out-of-band mode. Transfer the certificates to the device storage using a file transfer protocol.

    5. Import the CA certificate into the device memory.

      [DeviceB] pki import-certificate ca filename b_ca.cer
 The CA's Subject is /CN=ca_root 
 The CA's fingerprint is:
   MD5  fingerprint:1135 25D8 96D3 5936 C382 35EA 2CEE 80EB 
   SHA1 fingerprint:6330 974F B2FE 3C52 D16B DAC4 0140 918B 4BCD 3EC7
 Is the fingerprint correct?(Y/N):y
 Info: Succeeded in importing file.

    6. Import the local certificate into the device memory.

      [DeviceB] pki import-certificate local filename b_local.cer 
 Info: Succeeded in importing file.

  8. Configure ISAKMP IPsec policies on DeviceB and apply an IPsec policy group to 10GE 0/0/1.
    1. Create the advanced ACL 3000, define the data flow to be protected, and allow devices on the network segment 10.1.1.0/24 to access the network segment 10.1.0.0/24.

      [DeviceB] acl 3000
[DeviceB-acl4-advance-3000] rule 5 permit ip source 10.1.1.0 0.0.0.255 destination 10.1.0.0 0.0.0.255
[DeviceB-acl4-advance-3000] quit

    2. Configure an IPsec proposal.

      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceB-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceB-ipsec-proposal-tran1] quit

    3. Configure an IKE proposal.

      [DeviceB] ike proposal 10
[DeviceB-ike-proposal-10] authentication-method rsa-signature
[DeviceB-ike-proposal-10] prf hmac-sha2-256
[DeviceB-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceB-ike-proposal-10] dh group14
[DeviceB-ike-proposal-10] integrity-algorithm hmac-sha2-256  
[DeviceB-ike-proposal-10] quit

    4. Configure an IKE peer.

      [DeviceB] ike peer a
[DeviceB-ike-peer-a] ike-proposal 10
[DeviceB-ike-peer-a] local-id-type dn
[DeviceB-ike-peer-a] remote-id-type dn
[DeviceB-ike-peer-a] certificate local-filename b_local.cer
[DeviceB-ike-peer-a] remote-address 1.1.1.1
[DeviceB-ike-peer-a] remote-id /C=CN/ST=beijing/O=huawei/OU=dev/CN=devicea
[DeviceB-ike-peer-a] quit

    5. Configure an IPsec policy.

      [DeviceB] ipsec policy map1 10 isakmp
[DeviceB-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceB-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceB-ipsec-policy-isakmp-map1-10] ike-peer a

    6. Apply an IPsec policy group to 10GE 0/0/1.

      [DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] ipsec policy map1
[DeviceB-10GE0/0/1] quit

Verifying the Configuration

  1. After the configuration is complete, run the ping command on a device in the protected network segment of network A or network B to trigger IKE negotiation.

    If IKE negotiation succeeds, devices in the protected network segments at both ends of the tunnel can ping each other successfully. Otherwise, IKE negotiation fails.

  2. On DeviceA and DeviceB, run the display ike sa and display ipsec sa commands to check SA establishment information. The following example uses the command output on DeviceB, which shows that IKE SAs and IPsec SAs have been established successfully.
