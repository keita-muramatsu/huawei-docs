Module Management Security

Overview

A module file running on a device may be tampered with before being uploaded onto the device. If the device runs the tampered module file, the device is controlled and attacked. The following security mechanisms can be used to secure the entire process from transfer to running of the module file.

  • Digital signatures are supported.

    When a module file is released, a digital signature is added to the module file and the digital signature information file is packed into the module file. When an NMS distributes the module file to an NE or directly loads the module file onto the NE, the digital signature is verified. The module file is complete and reliable only if the verification is passed. Otherwise, the module file is invalid.

  • The module file in the running state is protected as a system file. In this case, the module file cannot be modified or deleted.

Before installing a module file, verify the integrity of the module file. Integrity verification includes digital signature verification and protection mechanism verification. Integrity verification can be performed in either of the following ways:

  • Before the installation, manually verify the integrity of the module file.
  • When a module file is installed in in-service mode or when a module file that takes effect at the next startup is specified and the device is restarted, the integrity of the module file is automatically verified.

If the integrity verification of the module file fails, you are advised to restart the system instead of trying for multiple times.

Impact on the System

None

Procedure

  • Before the installation, manually verify the integrity of the module file. The following uses the module file XXX.MOD in the $_install_mod folder as an example.

    <HUAWEI> check software file-name $_install_mod/XXXMOD001.MOD 
Warning: Software file verification consumes CPU resources. Are you sure you want to continue? [Y/N]:Y

    If the verification is successful, the following message will be displayed:

    Info: The integrity check for the module software of the XXXMOD001 version succeeds.

    If the verification fails, the following message will be displayed:

    Error: Failed to check the integrity of the module software of the unknown version.

  • When a module file is installed in in-service mode or when a module file that takes effect at the next startup is specified and the device is restarted, the integrity of the module file is automatically verified.

Checking the Security Hardening Result

  • When the integrity of the module file is manually verified, the system will prompt a message:
    • If the verification is successful, the following message will be displayed:
      Info: The integrity check for the module software of the XXXMOD001 version succeeds.
    • If the verification fails, the following message will be displayed:
      Error: Failed to check the integrity of the module software of the unknown version.
  • When the module file integrity is automatically verified:
    • If the verification is successful, the module file is properly installed and the system is successfully started.
    • If the verification fails, the module file fails to be installed.
