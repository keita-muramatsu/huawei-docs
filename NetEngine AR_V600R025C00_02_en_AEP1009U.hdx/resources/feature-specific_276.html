Example for Configuring Queue Scheduling HQoS (Configuring a Connection-based QoS Policy in CBQ Mode)

Networking Requirements

This example is supported only by the AR8000 series and AR6700-H series.

On an SD-WAN EVPN network shown in Figure 1, an enterprise has the headquarters (HQ) and multiple branches, and subscribes to 50 Mbit/s bandwidth. When the downstream bandwidth usage of the HQ exceeds 50 Mbit/s, traffic sent from the HQ to branches is discarded at random. The enterprise has the following QoS requirements:

  • Limit the bandwidth allocated to Site2 and Site3 in the outbound direction of the HQ site.
  • Ensure the bandwidth for high-priority services (voice and video conference services) when traffic is sent from the HQ site to branch sites.

In this example, interface 1 represents 10GE 0/0/1.1.


Configuration Roadmap

The configuration roadmap is as follows:

  1. On DeviceB and DeviceC, set the inbound bandwidth of the peer site to 50 Mbit/s (50000 kbit/s). The bandwidth value will be used as the base value of the connection-based QoS policy on DeviceA, that is, the base value in step 5.
  2. Configure a CBQ traffic policy on DeviceA to set bandwidth values for services at branch sites.

    Application identification is used to differentiate services. The enterprise uses WeLink to carry office applications. Table 1 lists the bandwidth allocated to the voice service (WeLink_VideoCall), video conference service (WeLink_Meeting), and other services.

  3. Enable the application identification function on the SD-WAN tunnel interface of DeviceA because this function needs to be used.
  4. To prevent other traffic classifiers that match ACL rules from failing to be matched in this scenario, you are advised to configure the packet pre-extraction function on the tunnel interface.
  5. Configure a site group on DeviceA and set the bandwidth percentage for each branch site. The outbound bandwidth limit of the connection-based QoS policy is the product of the bandwidth percentage configured in this step and the inbound bandwidth of the peer site (the value configured in step 1).

    According to Table 1, the HQ outbound bandwidth limits for Site2 and Site3 are 30 Mbit/s and 20 Mbit/s, respectively, and the inbound bandwidth limit for the peer site is 50 Mbit/s. As such, you need to set the bandwidth percentages for Site2 and Site3 to 60% and 40%, respectively.

  6. Apply the CBQ traffic policy to the site group view of DeviceA to ensure the bandwidth for high-priority services at branch sites.
  7. In this example, the outbound interface of DeviceA is a sub-interface. You need to enable the queue capability of the sub-interface.
  8. Configure a bypass QoS policy on the outbound interface of DeviceA to ensure the bandwidth for sites that are not added to any site group. In addition, the CBQ traffic policy may fail to be applied to sites in a site group due to insufficient resources on the device. For this reason, the bypass QoS policy must be configured.
  • This example describes only the configuration roadmap and procedure for configuring a connection-based QoS policy. Assume that SD-WAN EVPN network configurations have been completed. You need to ensure that SD-WAN EVPN site connections have been established. Before configuring a connection-based QoS policy, run the display evpn connection all command to check whether the connections have been established.
  • For details about SD-WAN EVPN configurations, see "SD-WAN EVPN Configuration" in CLI Configuration Guide > VPN Configuration.
  • In practice, if the application identification function is used to differentiate service traffic, you can query the names of related applications in Huawei security center or by running the display application command.

Procedure

  1. On DeviceB and DeviceC, configure the inbound bandwidth of the peer site.

    # Configure DeviceB.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] evpn site 2
[DeviceB-site-2] system-id 10.2.2.2
[DeviceB-site-2] transport-network-port 1
[DeviceB-site-2-transport-network-port-1] bandwidth input 50000
[DeviceB-site-2-transport-network-port-1] quit
[DeviceB-site-2] quit

    # Configure DeviceC.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceC
[DeviceC] evpn site 3
[DeviceC-site-3] system-id 10.3.3.3
[DeviceC-site-3] transport-network-port 1
[DeviceC-site-3-transport-network-port-1] bandwidth input 50000
[DeviceC-site-3-transport-network-port-1] quit
[DeviceC-site-3] quit

  2. Configure a CBQ traffic policy on DeviceA.

    # Configure an FQ profile for a CBQ traffic policy.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] flow-queue fq1
[DeviceA-flow-queue-fq1] queue service1 pq shaping cir-shaping-percentage 20
[DeviceA-flow-queue-fq1] queue service2 pq shaping cir-shaping-percentage 40
[DeviceA-flow-queue-fq1] queue service3 pq shaping cir-shaping-percentage 40
[DeviceA-flow-queue-fq1] quit

    In this example, the PIR value is not specified and is the same as the CIR value.

    # Configure a CBQ traffic policy.

    [DeviceA] traffic classifier service1
[DeviceA-classifier-service1] if-match application WeLink_VideoCall
[DeviceA-classifier-service1] quit
[DeviceA] traffic classifier service2
[DeviceA-classifier-service2] if-match application WeLink_Meeting
[DeviceA-classifier-service2] quit
[DeviceA] traffic classifier service3
[DeviceA-classifier-service3] if-match any
[DeviceA-classifier-service3] quit
[DeviceA] traffic behavior service1
[DeviceA-behavior-service1] flow-queue fq1 queue service1
[DeviceA-behavior-service1] quit
[DeviceA] traffic behavior service2
[DeviceA-behavior-service2] flow-queue fq1 queue service2
[DeviceA-behavior-service2] quit
[DeviceA] traffic behavior service3
[DeviceA-behavior-service3] flow-queue fq1 queue service3
[DeviceA-behavior-service3] quit
[DeviceA] traffic policy site-policy
[DeviceA-trafficpolicy-site-policy] classifier service1 behavior service1
[DeviceA-trafficpolicy-site-policy] classifier service2 behavior service2
[DeviceA-trafficpolicy-site-policy] classifier service3 behavior service3
[DeviceA-trafficpolicy-site-policy] quit

  3. Enable the application identification function on the SD-WAN tunnel interface of DeviceA.

    [DeviceA] interface tunnel100
[DeviceA-Tunnel100] tunnel-protocol sd-wan
[DeviceA-Tunnel100] sd-wan service enable
[DeviceA-Tunnel100] ip binding vpn-instance vpn1
[DeviceA-Tunnel100] sa enable

  4. Configure the packet pre-extraction function on the SD-WAN tunnel interface of DeviceA.

    [DeviceA-Tunnel100] qos pre-classify
[DeviceA-Tunnel100] quit

  5. Configure a site group on DeviceA and configure bandwidth percentages for different branch sites.

    [DeviceA] evpn site-group group1
[DeviceA-evpn-site-group-group1] peer-site 2 bandwidth percentage 60
[DeviceA-evpn-site-group-group1] peer-site 3 bandwidth percentage 40

  6. Apply the CBQ traffic policy in the site group view of DeviceA.

    [DeviceA-evpn-site-group-group1] traffic-policy site-policy outbound 
[DeviceA-evpn-site-group-group1] quit

  7. Enable the queue capability on the outbound interface 10GE 0/0/1.1 of DeviceA. (This step needs to be performed when the outbound interface is a sub-interface.)

    [DeviceA] interface 10ge 0/0/1.1
[DeviceA-10GE0/0/1.1] qos queue-scheduling enable

  8. Configure a bypass QoS policy on the outbound interface of DeviceA. You can use the traffic policy site-policy configured in step 2 or configure a new traffic policy as the bypass QoS policy. In this example, the configured traffic policy site-policy is used.

    [DeviceA-10GE0/0/1.1] qos lr cir 50000 kbps outbound
[DeviceA-10GE0/0/1.1] traffic-policy site-policy outbound
[DeviceA-10GE0/0/1.1] quit

Configuration Scripts

The following configuration scripts provide only the configuration information related to this example.

  • DeviceA
    # 
sysname DeviceA                           
#                                                                               
flow-queue fq1
 queue service1 pq shaping cir-shaping-percentage 20
 queue service2 pq shaping cir-shaping-percentage 40
 queue service3 pq shaping cir-shaping-percentage 40
#
traffic classifier service1 type or
 if-match application WeLink_VideoCall  
#
traffic classifier service2 type or
 if-match application WeLink_Meeting  
#
traffic classifier service3 type or
 if-match any
#
traffic behavior service1
 flow-queue fq1 queue service1 
#
traffic behavior service2
 flow-queue fq1 queue service2 
#
traffic behavior service3
 flow-queue fq1 queue service3 
#
traffic policy site-policy 
 classifier service1 behavior service1 precedence 5
 classifier service2 behavior service2 precedence 10
 classifier service3 behavior service3 precedence 15
#
interface 10GE0/0/1.1
 qos lr cir 50000 kbps outbound
 qos queue-scheduling enable
 traffic-policy site-policy outbound 
#
interface Tunnel100
 tunnel-protocol sd-wan
 sd-wan service enable
 ip binding vpn-instance vpn1
 qos pre-classify
 sa enable
#
