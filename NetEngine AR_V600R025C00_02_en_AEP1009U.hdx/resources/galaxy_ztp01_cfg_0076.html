Understanding Option Parameters

The DHCP server uses Option parameters to transmit network configurations to devices to implement automatic configuration during ZTP.

The device sends a DHCP Discover message that carries DHCPv4 Option parameters when the DHCP Discover phase starts in DHCPv4 scenarios. Table 1 describes the parameters.

The device sends a DHCPv6 Solicit message that carries DHCPv6 Option parameters when the DHCPv6 Solicit phase starts in DHCPv6 scenarios. Table 2 describes the parameters.

Table 3 describes the DHCPv4 Option parameters to be configured on the DHCPv4 server. Table 4 describes the DHCPv6 Option parameters to be configured on the DHCPv6 server.

  • The DHCP server does not support authentication and may be spoofed. You are advised to use a trusted DHCP server for deployment on a secure network.

Option43 (suboption 5)

Mandatory when no initial certificate is available on the controller

Address and port number of the bootstrap server, from which the device can download a CA certificate.

The value format is bootstrap-domain=https://ip-address-or-hostname:port;bootstrap-trust=xxx;bootstrap-voucher=xxx.

  • bootstrap-domain: IPv4 address or domain name, and port number of the bootstrap server. In the value format, port is optional and its default value is 443.
  • (Optional) bootstrap-trust: indicates whether to trust the downloaded CA certificate. The value can be true or false.

    If the value is true, the CA certificate sent by the bootstrap server is trusted. If the CA certificate is not signed, the device directly verifies the certificate without verifying the signature of the certificate. If the CA certificate has been signed, the device verifies the signature of the certificate and then verifies the certificate.

    If the value is false, the CA certificate sent by the bootstrap server is not trusted. In this case, the device verifies the signature of the CA certificate regardless of whether the CA certificate has been signed. Only when the signature verification is successful, the device verifies the certificate.

    If bootstrap-trust is not specified, the default value false is used.

  • (Optional) bootstrap-voucher: CA certificate verification mode. The value can be DOMAIN_IP or ESN. The value DOMAIN_IP indicates that the IP address is used to verify the validity of the certificate, and the value ESN indicates that the device ESN is used to verify the validity of the certificate. The CA certificate can be obtained only after being successfully verified.

    If bootstrap-voucher is not specified, DOMAIN_IP is used by default.

Option 148

Yes

URL/IP address and port number of the iMaster NCE-Campus server, which are used by devices to register with iMaster NCE-Campus.

The value format is as follows: agilemanage-mode=ip;agilemanage-domain=ipv41&ipv42;agilemanage-port=port1&port2;agilemanage-backup-address=ipv4:port, whereby:

  • agilemanage-mode: indicates whether the device obtains the URL or IP address of iMaster NCE-Campus. When agilemanage-mode is set to domain, the device obtains the URL, and agilemanage-domain is set to domain-name accordingly. When agilemanage-mode is set to ip, the device obtains the IP address, and agilemanage-domain is set to ip-address accordingly.
  • agilemanage-domain: URL/IPv4 address of the active iMaster NCE-Campus. You can configure one or more URLs/IPv4 addresses. Use ampersands (&) to separate multiple URLs/IPv4 addresses.
  • agilemanage-port: port number of the active iMaster NCE-Campus. You can configure one or more port numbers. Use ampersands (&) to separate multiple port numbers.
  • (Optional) agilemanage-backup-address: URL/IPv4 address and port number of the standby iMaster NCE-Campus.
NOTE:
  • agilemanage-domain and agilemanage-port must be used together and have the same number of values.
  • When multiple URLs/IP addresses are configured, a maximum of two values can take effect. If both agilemanage-domain (primary address) and agilemanage-backup-address (secondary address) are configured, the first primary and secondary addresses take effect. If only agilemanage-domain (primary address) is configured, the first two primary addresses take effect.

Yes

IPv6 address and port number of iMaster NCE-Campus and IPv6 address of the bootstrap server so that devices can download CA certificates from the bootstrap server and register with iMaster NCE-Campus.

The value format is agilemanage-domain=ipv61&ipv62;agilemanage-port=port1&port2;bootstrap-domain=https://ip-address-or-hostname:port;bootstrap-trust=xxx;bootstrap-voucher=xxx.

  • agilemanage-domain: IPv6 address of iMaster NCE-Campus. You can configure one or more IPv6 addresses. Use ampersands (&) to separate multiple IPv6 addresses.
  • agilemanage-port: port number of iMaster NCE-Campus. You can configure one or more port numbers. Use ampersands (&) to separate multiple port numbers.
  • bootstrap-domain: IPv6 address or domain name, and port number of the bootstrap server. In the value format, port is optional and its default value is 443. If an IP address is used, the format is [ip-address]:port, for example, https://[2001:db8:1::2]:200.

    If the value is true, the CA certificate sent by the bootstrap server is trusted. If the CA certificate is not signed, the device directly verifies the certificate without verifying the signature of the certificate. If the CA certificate has been signed, the device verifies the signature of the certificate and then verifies the certificate.

    If the value is false, the CA certificate sent by the bootstrap server is not trusted. In this case, the device verifies the signature of the CA certificate regardless of whether the CA certificate has been signed. Only when the signature verification is successful, the device verifies the certificate.

    If bootstrap-trust is not specified, the default value false is used.

  • bootstrap-voucher: CA certificate verification mode. The value can be DOMAIN_IP or ESN. The value DOMAIN_IP indicates that the IP address is used to verify the validity of the certificate, and the value ESN indicates that the device ESN is used to verify the validity of the certificate. The CA certificate can be obtained only after being successfully verified.
    NOTE:

    agilemanage-domain and agilemanage-port must be used together and have the same number of values.
