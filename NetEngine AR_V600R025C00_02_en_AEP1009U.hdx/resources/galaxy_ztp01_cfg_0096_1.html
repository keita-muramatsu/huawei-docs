Understanding SZTP

SZTP uses two-way authentication and data encryption to ensure data trustworthiness during device deployment. It involves certificate authentication, and a bootstrap server is required. Figure 1 shows the SZTP process.

Figure 1 SZTP process
  1. Preparing deployment files

    An engineer prepares deployment files in advance.

  2. Deploying the DHCP server, bootstrap server, and deployment file server

    The engineer configures the DHCP server, bootstrap server, and deployment file server, and saves the deployment files to the deployment file server. The engineer can also configure the DHCP relay agent, DNS server, and Syslog server as required. The functions of each device are as follows:

    • DHCP relay agent: relays DHCP packets between the device and the DHCP server when they are located on different network segments.
    • DHCP server: assigns a temporary management IP address, default gateway address, DNS server address, and bootstrap server address to the device.
    • Bootstrap server: is used to guide SZTP. After a secure connection is established between the device and bootstrap server, the device can obtain deployment file information such as the address of the deployment file server and deployment file name from the bootstrap server.

    • Deployment file server: stores the deployment files to be loaded to the device, including the system software, configuration file, and patch file. A deployment file server must be an HTTPS server.

    • DNS server: provides mappings between domain names and IP addresses, and resolves the domain name of the bootstrap server to an IP address.

    • Syslog server: records important information in user logs during ZTP deployment and uploads the logs to the NMS.

  3. Powering on the device

    The deployment person powers on and starts the device. The device starts with a configuration file if one is available. Otherwise, the device automatically starts the ZTP process.

  4. Obtaining DHCP information

    • The device sends DHCP request packets through its Layer 3 physical interface.
    • The DHCP server sends a DHCP reply packet to the device. The Option parameters in the packet specify the information that the device needs to obtain from the DHCP server.
  5. Establishing a secure connection

    The device and bootstrap server perform two-way authentication. After establishing a secure connection, the device obtains deployment file information from the bootstrap server.

  6. Obtaining deployment files

    After establishing a secure connection with the bootstrap server, the device functions as an HTTPS client to establish an HTTPS connection with the deployment file server and downloads deployment files.

  7. (Optional) Starting the Syslog server

    The device obtains the IP address of the Syslog server from the DHCP reply packet and enables the Syslog server function. Information about important phases during device deployment is recorded in user logs, which the Syslog server will upload to the NMS.

  8. Automatically completing deployment

    The device automatically sets the downloaded deployment files as those to be loaded for its next startup. The device then restarts to complete automatic deployment.

  • When deploying an unconfigured device, you are advised not to manually deliver the same configurations as those delivered during ZTP. Doing so will cause the configurations to be deleted if the deployment fails.
  • ZTP depends on OPS. You can run the display ops process current command to obtain the task ID, which indicates the ZTP process ID, and then run the ops stop process process-id command to stop the ongoing ZTP process. This operation, however, may cause the configurations that have been delivered during ZTP to be retained on the device.
