Configuring URPF

Prerequisites

Before configuring URPF, you have completed the following tasks:

  • Configure link layer attributes of interfaces.
  • Configure IP addresses for interfaces.
  • If an ACL is used as a matching rule, configure an ACL for URPF.

Context

URPF check can be performed in strict or loose mode. You can configure the allow-default-route parameter to allow packets to match the default route. If a packet does not pass URPF check, the device can match the packet against an ACL.

The URPF process is as follows:

  1. Check whether the source address of the packet exists in the FIB table of the device.
    • In strict mode, the device conducts a reverse lookup for the outbound interface of the packet. If only one outbound interface matches the inbound interface of the packet, the packet passes the URPF check. Otherwise, the packet is discarded. If more than one outbound interface matches the inbound interface of the packet, you must use the loose mode. (Reverse lookup indicates searching for the outbound interface of another packet whose destination IP address is the source IP address of the packet.)
    • In loose mode, if the source IP address of the packet exists in the FIB table of the device and the route is not a black hole route (regardless of the consistency between the outbound interface searched for by reverse lookup and the inbound interface of the packet), the packet passes the URPF check. Otherwise, the packet is discarded.
  2. If the source IP address of the packet does not exist in the FIB table of the device, check whether the default route and the allow-default-route parameter for URPF are configured.
    • If the default route is configured, but the allow-default-route parameter is not specified:

      As the source IP address of the packet does not exist in the FIB table of the device, the packet is denied regardless of whether the URPF check is in strict or loose mode.

    • If the default route is configured, and the allow-default-route parameter is specified:
      • In strict mode, if the outbound interface of the default route is the same as the inbound interface of the packet, the packet passes the URPF check and is forwarded normally. Otherwise, the packet is denied.
      • In loose mode, the packet passes the URPF check and is forwarded normally.
  3. The packet is matched against an ACL only when it is denied. If the ACL permits the packet, the packet is forwarded normally. If the ACL denies the packet, the packet is discarded.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the interface view.

    interface interface-type interface-number

  3. Change the working mode of the interface from Layer 2 to Layer 3.

    undo portswitch

    Decide whether to perform this step based on the actual interface type.

  4. Configure URPF check for packets on the interface. A basic or advanced ACL (numbered from 2000 to 3999) can be specified.

    IPv4 network:

    ip urpf { loose | strict } [ allow-default-route ] [ acl acl-number ]

    IPv6 network:

    ipv6 urpf { loose | strict } [ allow-default-route ] [ acl6 acl-number ]

    To configure URPF check for IPv6 packets on an interface, enable the IPv6 function on the interface first. To do so, run the ipv6 enable command in the interface view.
