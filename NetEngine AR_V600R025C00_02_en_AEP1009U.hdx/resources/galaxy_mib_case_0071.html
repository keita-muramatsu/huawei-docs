Querying Mappings Between VLANs and Interfaces in the VLANs

Description of MIB Objects

dot1qVlanCurrentTable describes information about VLANs on a device, including statically configured VLANs, dynamic VLANs generated using VLAN registration protocols, and interfaces added to the VLANs.

dot1qVlanCurrentEgressPorts describes the VLANs to which tagged and untagged interfaces are added, and dot1qVlanCurrentUntaggedPorts describes the VLANs to which untagged interfaces are added. You can use dot1qVlanCurrentEgressPorts to query mappings between a VLAN and all interfaces added to the VLAN, and use dot1qVlanCurrentUntaggedPorts to query mappings between a VLAN and untagged interfaces added to the VLAN.

Object

OID

dot1qVlanCurrentEgressPorts

1.3.6.1.2.1.17.7.1.4.2.1.4

dot1qVlanCurrentUntaggedPorts

1.3.6.1.2.1.17.7.1.4.2.1.5

Procedure

  1. Search for an object in the MIB tree. However, it is difficult to locate an object if a large number of MIB files are imported to the MIB Browser. In this case, you can press Ctrl+F to locate an object.

  2. Use dot1qVlanCurrentEgressPorts to query information about interfaces added to a VLAN, as shown in Figure 1.

    Figure 1 Querying information about interfaces in a VLAN

    The return value of dot1qVlanCurrentEgressPorts indicates indexes of the interfaces added to the VLAN. The indexes start from 1 and indicate interface 1, interface 2, interface 3, and so on. The value 1 indicates that the corresponding interface is added to the VLAN.

    The query result is displayed in hexadecimal format and needs to be converted into binary format. In Figure 1, the hexadecimal value 00.00.04 can be converted to the binary value 00000000 00000000 00000100, indicating that interface 22 is added to VLAN 2.
