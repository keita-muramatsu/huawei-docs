Example for Configuring IPsec VPN in a VPN Instance

Context

In Figure 1, the headquarters is connected to the Internet through DeviceA, and the branch is connected to the Internet through DeviceB. DeviceA and DeviceB establish an IPsec tunnel for secure communication. To prevent IPsec services on DeviceA from being affected by other services, the enterprise requires that a VPN instance be created on DeviceA and bound to the IPsec tunnel for service isolation.

Figure 1 Configuring an IPsec tunnel in a VPN instance

In this example, interface 1 and interface 2 represent 10GE 0/0/1 and 10GE 0/0/2, respectively.


Configuration Roadmap

This example uses default security algorithms of IPsec.

For security purposes, you are advised not to use the weak security algorithm or weak security protocol of this feature. If you must use such a weak security algorithm or protocol, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA.

  1. Create a VPN instance named vpn1 on DeviceA.
  2. Configure routes for the VPN instance.
  3. Set IPsec policy parameters for the VPN instance. When configuring an IKE peer, you need to bind an IPsec tunnel to a VPN instance.

Procedure

  • Configure DeviceA (at the headquarters).
    1. Configure a VPN instance named vpn1.

      <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] ip vpn-instance vpn1
[DeviceA-vpn-instance-vpn1] route-distinguisher 100:1
[DeviceA-vpn-instance-vpn1] quit

    2. Configure IP addresses for interfaces.

      # Configure an IP address for 10GE 0/0/1.
      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] undo portswitch
[DeviceA-10GE0/0/1] ip binding vpn-instance vpn1
[DeviceA-10GE0/0/1] ip address 10.1.1.1 24
[DeviceA-10GE0/0/1] quit
      # Configure an IP address for 10GE 0/0/2.
      [DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] undo portswitch
[DeviceA-10GE0/0/2] ip binding vpn-instance vpn1
[DeviceA-10GE0/0/2] ip address 1.1.3.1 24
[DeviceA-10GE0/0/2] quit

    3. Configure a static route destined for DeviceB. The following assumes that the next-hop IP address is 1.1.3.2. This route instructs DeviceA to forward packets from the headquarters to the branch.

      [DeviceA] ip route-static vpn-instance vpn1 1.1.5.0 24 1.1.3.2
[DeviceA] ip route-static vpn-instance vpn1 10.1.2.0 24 1.1.3.2

    4. Configure IPsec.

      Configure an ACL to define the data flows to be protected, and bind the ACL to the specified VPN instance.
      [DeviceA] acl 3000
[DeviceA-acl4-advance-3000] rule 5 permit ip source 10.1.1.0 0.0.0.255 destination 10.1.2.0 0.0.0.255 vpn-instance vpn1
[DeviceA-acl4-advance-3000] quit
      # Configure an IPsec proposal.
      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] transform esp
[DeviceA-ipsec-proposal-tran1] encapsulation-mode tunnel
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceA-ipsec-proposal-tran1] quit
      # Create an IKE proposal. You can use the default parameter settings.
      [DeviceA] ike proposal 1
[DeviceA-ike-proposal-1] dh group14
[DeviceA-ike-proposal-1] quit
      # Configure an IKE peer.
      [DeviceA] ike peer b
[DeviceA-ike-peer-b] ike-proposal 1
[DeviceA-ike-peer-b] pre-shared-key Key123
[DeviceA-ike-peer-b] remote-address vpn-instance vpn1 1.1.5.1
[DeviceA-ike-peer-b] sa binding vpn-instance vpn1
[DeviceA-ike-peer-b] quit
      # Configure an ISAKMP IPsec policy.
      [DeviceA] ipsec policy map1 1 isakmp
[DeviceA-ipsec-policy-isakmp-map1-1] ike-peer b
[DeviceA-ipsec-policy-isakmp-map1-1] proposal tran1
[DeviceA-ipsec-policy-isakmp-map1-1] security acl 3000
[DeviceA-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceA-ipsec-policy-isakmp-map1-1] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply an IPsec policy to 10GE 0/0/2.
      [DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] ipsec policy map1
[DeviceA-10GE0/0/2] quit

  • Configure DeviceB (at the branch).
    1. Configure IP addresses for interfaces.

      # Configure an IP address for 10GE 0/0/1.
      <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] ip address 10.1.2.1 24
[DeviceB-10GE0/0/1] quit
      # Configure an IP address for 10GE 0/0/2.
      [DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] ip address 1.1.5.1 24
[DeviceB-10GE0/0/2] quit

    2. Configure a static route destined for DeviceA. The following assumes that the next-hop IP address is 1.1.5.2. This route instructs DeviceB to forward packets from the branch to the headquarters.

      [DeviceB] ip route-static 10.1.1.0 24 1.1.5.2
[DeviceB] ip route-static 1.1.3.0 24 1.1.5.2

    3. Configure IPsec.

      # Configure an ACL to define the data flow to be protected.
      [DeviceB] acl 3000
[DeviceB-acl4-advance-3000] rule 5 permit ip source 10.1.2.0 0.0.0.255 destination 10.1.1.0 0.0.0.255
[DeviceB-acl4-advance-3000] quit
      # Configure an IPsec proposal.
      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] transform esp
[DeviceB-ipsec-proposal-tran1] encapsulation-mode tunnel
[DeviceB-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceB-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceB-ipsec-proposal-tran1] quit
      # Create an IKE proposal. You can use the default parameter settings.
      [DeviceB] ike proposal 1
[DeviceB-ike-proposal-1] dh group14
[DeviceB-ike-proposal-1] quit
      # Configure an IKE peer.
      [DeviceB] ike peer a
[DeviceB-ike-peer-a] ike-proposal 1
[DeviceB-ike-peer-a] pre-shared-key Key123
[DeviceB-ike-peer-a] remote-address 1.1.3.1
[DeviceB-ike-peer-a] quit
      # Configure a non-template IPsec policy.
      [DeviceB] ipsec policy map1 1 isakmp
[DeviceB-ipsec-policy-isakmp-map1-1] ike-peer a
[DeviceB-ipsec-policy-isakmp-map1-1] proposal tran1
[DeviceB-ipsec-policy-isakmp-map1-1] security acl 3000
[DeviceB-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceB-ipsec-policy-isakmp-map1-1] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply an IPsec policy to 10GE 0/0/2.
      [DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] ipsec policy map1
[DeviceB-10GE0/0/2] quit

Verifying the Configuration

After the configuration is complete, users at the headquarters and branch can communicate with each other. Run the display ike sa and display ipsec sa brief commands on DeviceA and DeviceB to check SA information. The following shows the command outputs of DeviceA, which if similar, indicate that IKE SAs and IPsec SAs have been established.
