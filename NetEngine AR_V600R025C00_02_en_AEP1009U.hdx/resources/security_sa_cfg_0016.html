(Optional) Configuring a User-defined Application

Procedure

  1. Enter the system view.

    system-view

  2. Enter the SA view.

    sa

  3. Create a user-defined application and enter its view.

    user-defined-application name name [ app-id app-id ]

    You can specify the ID (an integer) of a new user-defined application on the device. If app-id is not specified, the device randomly allocates IDs from 60000 to 65535 to user-defined applications. If app-id is specified, the value range is 65536 to 100000.

  4. Optional: Configure a description for the user-defined application.

    description description

  5. Configure basic attributes for the user-defined application.

    You can use attributes to describe an application, helping accurately reference it.

    Operation

    Command

    Configure a category and sub-category for the user-defined application.

    category category sub-category sub-category

    Configure a data model for the user-defined application.

    data-model { unassigned | client-server | browser-based | networking | peer-to-peer }

    Configure a label for the user-defined application.

    label label-name

  6. Configure a rule for the user-defined application.

    A rule identifies an application and defines its signature. You can configure one or more rules, with multiple rules forming an OR relationship. If a data flow or packet matches a rule, this flow or packet belongs to the corresponding application.

    1. Create a rule for the user-defined application and enter its view.

      rule name rule-name

    2. Optional: Configure a description for the rule of the user-defined application.

      description description

    3. Configure a rule for the user-defined application.

      A device allows you to create a rule based on the multi-tuple (protocol type, IP address, and port number), keyword (signature information), or multi-tuple+keyword. If you create a rule based on the multi-tuple, the rule must contain at least one IP address or port number.

      Configuration Item

      Command

      Description

      Protocol type

      protocol { tcp | udp }

      A rule configured with only a transport layer protocol does not take effect. Therefore, you are advised to specify other configuration items in addition to the protocol type.

      IP address

      ip-address ipv4-address [ ipv4-mask-address | masklength ] [ source | destination ]

      ipv6-address ipv6-address [ ipv6-prefix ] [ source | destination ]

      The total number of IPv4 and IPv6 addresses supported by a user-defined application rule cannot exceed 4.

      If the source and destination parameters are not specified, the destination IP address is used for rule matching.

      The relationships between source address conditions and between destination address conditions are both OR. However, the relationship between source and destination address conditions is AND. Specifically, if both the source and destination addresses are specified in a rule, a packet matches the rule only when the packet matches both the source and destination addresses.

      Port number

      port port [ end-port ] [ source | destination ]

      The total number of ports and port ranges supported by a user-defined application rule cannot exceed four.

      end-port is used to define a port range. The value of end-port minus the value of port must range from 1 to 127, meaning that a port range contains 2 to 128 ports. If the source and destination parameters are not specified, the destination port is used for rule matching.

      The relationships between source port conditions and between destination port conditions are both OR. However, the relationship between source and destination port conditions is AND. Specifically, if both the source and destination ports are specified in a rule, a packet matches the rule only when the packet matches both the source and destination ports.

      Signature information

      signature context { flow | packet } direction { request | response | both } { plain-string plain-string | regular-expression regular-expression } [ field field-name ]

      A signature refers to the characteristic of a data packet or flow corresponding to an application. This characteristic can uniquely identify the application. Signature information of a user-defined application's rule contains:

      • Matching range (context): The keyword is matched by flow or packet based on the characteristic of the application. Select packet if the keyword exists in one data packet, or select flow if it exists in multiple data packets.

        If the protocol is TCP, flow must be configured; if the protocol is UDP, packet must be configured. Otherwise, the matching fails.

      • Detection direction (direction): Set this parameter based on the application identification direction. request indicates that the data sent to the server is detected; response indicates that the response data of the server is detected; both indicates that both the request data and response data are detected.
      • Matching mode: If the signature keyword of an application is fixed, you can select plain-string and enter the text to be matched. Conversely, if the signature keyword is not fixed, select regular-expression and enter the regular expression to be matched.

        A regular expression consists of common characters and metacharacters (which are dedicated characters with special meanings). You can use metacharacters to flexibly configure user-defined applications. For details, see Regular Expression Configuration for Rules of a User-defined Application.

      • Protocol field (field): Set this parameter to specify the searching range of the signature keyword. When the protocol is TCP and the matching mode is regular-expression, the following protocol fields can be searched for: General-payload, HTTP.Body, HTTP.Content-Type, HTTP.Cookie, HTTP.Host, HTTP.Method, HTTP.URI, and HTTP.User-Agent. In other cases, the protocol field that can be searched for is General-payload.

    4. Return to the user-defined application view.

      quit

  7. Configure a domain name rule for the user-defined application.

    A domain name rule identifies an application and defines its domain name signature. The device identifies domain name information in DNS packets and matches the information with the domain name rule, quickly obtaining application identification results. You can configure one rule or multiple rules that form an OR relationship. If a data flow or packet matches a rule, this flow or packet belongs to the corresponding application.

    dns-rule name rule-name protocol { tcp | udp | any } domain plain-string [ { port-equal port [ next-port ] | port-range start-port end-port } ] [ priority priority ] [ description description ]

    A domain name is a string of 3 to 127 case-sensitive characters. When configuring a domain name, note the following:

    • Only digits, uppercase letters, lowercase letters, wildcard asterisks (*), periods (.), and hyphens (-) are allowed.
    • Consecutive wildcard asterisks (*) are not allowed, and there can be no more than three wildcard asterisks.
    • The character string must contain at least three consecutive non-wildcard characters. For example, abcd* meets the requirement but ab* does not.

  8. Return to the system view.

    quit

  9. Commit the configuration in the system view.

    engine configuration commit

    After a user-defined application is created or modified, the configuration does not take effect immediately. You need to commit the configuration for activation, which takes a long time to complete. To save time, you are advised to perform all operations on the user-defined application before committing the configuration. If this configuration is committed too frequently, the commitment may fail, indicated by an error message displayed on the CLI. In this case, manually run the engine configuration commit command again to commit the configuration.

Regular Expression Configuration for Rules of a User-defined Application

When configuring regular expressions for rules of a user-defined application, note the following:

  • Regular expressions are case-insensitive for all rules of a user-defined application.
  • The character string must start with at least four consecutive common characters. For example, the character string abcd* meets the requirement, but abc* does not because * is not a common character.
  • {} can be used only for {n,m} and {n}.
  • A comma (,) can be used only in {} or must follow a backslash (\) if the comma appears in another place.
  • +, *, ?, and {} are modifiers and must follow common characters.
  • (), [], and {} must be used in pairs.
  • When the protocol type is TCP and the protocol field is HTTP.Body or General-payload, or when the protocol type is UDP and the protocol field is General-payload, the regular expression cannot use {m} or {m,n} if three consecutive common characters exist and the last character is repeated. For example, abc{5} must be written as abccccc.
  • When the protocol field is HTTP.Method, the regular expression supports only the metacharacters (, ), and |. It does not support the matching of other characters except English letters.
  • When the protocol field is HTTP.Content-Type, HTTP.Cookie, HTTP.Host, HTTP.URI, or HTTP.User-Agent, the regular expression supports only the metacharacters *, (, ), and |.
  • When the protocol field is HTTP.Content-Type, HTTP.Cookie, HTTP.Host, HTTP.Method, HTTP.URI, or HTTP.User-Agent, the asterisk (*) indicates any non-line feed character of any length. When the protocol field is another value, the asterisk (*) indicates that zero or more occurrences of the preceding character are matched in the target object. For example, in the HTTP.Host protocol field, abcd* can match abcd, abcdef, and abcdddddd; in the HTTP.Body protocol field, abcd* can match abc, abcd, and abcdddd.

The preceding points describe the general requirements on regular expressions for rules of a user-defined application. The actual configuration depends on a device's support. Table 1 describes the metacharacters supported in regular expressions and their usage.

Table 1 Metacharacter

Symbol

Meaning

Description

^

Matches the beginning of the entered string in single line mode.

Matches all strings following the newline character \n in multi-line mode.
For example, if the entered regular expression is ^abcdefg and a packet contains the string abcdefg\nabcdefgxxx:
  • In single line mode, the first abcdefg (that is, the bold characters in abcdefg\nabcdefgxxx) is matched.
  • In multi-line mode, the abcdefg following \n (that is, the bold characters in abcdefg\nabcdefgxxx) is matched.

$

Matches the end of the entered string in single line mode.

Matches the string prior to \n.
For example, if the entered regular expression is abcdefg$ and a packet contains the string defabcdefg\nxxabcdefg:
  • In single line mode, the last abcdefg (that is, the bold characters in defabcdefg\nxxabcdefg) is matched.
  • In multi-line mode, the abcdefg prior to \n (that is, the bold characters in defabcdefg\nxxabcdefg) is matched.

[]

Matches any single character that is contained within the brackets.

A hyphen (-) can be used to specify a range of characters. The special characters listed in Table 2 are not supported.
  • [xyz] is a positive character set. For example, the regular expression abcdefg[abc] can match abcdefga, abcdefgb, and abcdefgc.
  • [^xyz] is a negative character set. For example, the regular expression abcdefg[^ab] can match any character, but not abcdefga or abcdefgb.
  • [x-y] is a range character set. For example, the regular expression abcdefg[a-c] can match abcdefga, abcdefgb, and abcdefgc.
  • A maximum of 64 characters can be entered in [ ].
  • The regular expression cannot contain the string [[:.
  • The regular expression does not support the [xyz]* or [xyz]+ format.

()

Indicates the beginning and end of a subexpression.
  • The regular expression cannot contain character strings such as (?=), (?!), (?<=), (?<!), (?i), (?s), (?m), (?x), (?@0), (?s), (?:), or (?.=[xyz]).
  • The regular expression does not support the (xyz)*, (xyz){…}, or (xyz)+ format.

.

Matches any single character, but not \n.

For example, the regular expression abcdefg.h can match abcdefgah, abcdefgbh, and abcdefgch, but not abcdefgaah.

|

Indicates that characters on both sides of the vertical bar (|) are logically ORed.

Characters or expressions must exist before and after the vertical bar (|). For example, ab| is incorrect. For the regular expression abcdefg(a|b), it can match abcdefga or abcdefgb.

\

Indicates an escape character.

Added prior to metacharacters to be matched. For example, to match a backslash (\), enter \\.

  • An escape character cannot be followed by b, B, Q, E, 1, 2, 3, 4, 5, 6, 7, 8, or 9.
  • If an escape character is followed by the character x, \x{ cannot be used. If an escape character is followed by a hexadecimal value, the format must be \xhh.
  • If an escape character is followed by the character d, D, h, H, s, S, v, V, w, or W, these characters are not used for matching as exact characters.

-

A hyphen (-) can be used to specify a range of characters.

For example, the regular expression abcdefg[a-c] can match abcdefga, abcdefgb, and abcdefgc.

*

Matches zero or more occurrences of the preceding character in the target object.
The following restrictions apply to the preceding character or character set:
  • The preceding string cannot be a subexpression. For example, (abcdefg)* is not supported.
  • The numbers of characters in {} and [] are less than or equal to 64.
  • .*, *?, and *+ are not supported.

For example, the regular expression abcdefg* can match abcdef, abcdefg, and abcdefggg.

+

Matches one or more occurrences of the preceding character in the target object.
The following restrictions apply to the preceding character or character set:
  • The preceding string cannot be a subexpression. For example, (abcdefg)+ is not supported.
  • The numbers of characters in {} and [] are less than or equal to 64.
  • .+, +?, and ++ are not supported.

For example, the regular expression abcdefg+ can match abcdefg, abcdefgg, and abcdefggg.

?

Matches zero or one occurrence of the preceding character in the target object.

For example, the regular expression abcdefg? can match abcdef and abcdefg.

?? and ?+ are not supported.

{n}

Matches a specific number (n) of instances of the preceding character in the target object.

For example, the regular expression abcdefg{3} can match abcdefggg.

The restrictions on n are as follows:

  • n must be less than or equal to 64.
  • The preceding string cannot be a subexpression. For example, (abcdefg){n} is not supported.

{n,m}

Matches a specific range (n through m) of instances of the preceding character in the target object.

For example, the regular expression abcdefg{0,8} has a minimum of 0 gs and a maximum of 8 gs.

The restrictions on m and n are as follows:

  • n must be less than or equal to m.
  • m must be less than or equal to 64.
  • The preceding string cannot be a subexpression. For example, (abcdefg){n,m} is not supported.
