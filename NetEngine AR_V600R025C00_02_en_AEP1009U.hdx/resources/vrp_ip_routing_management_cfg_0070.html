Configuring Route Recursion to LSPs

Context

When users access the Internet through a carrier network, the network's core devices between the users and the Internet are forced to learn a large number of Internet routes if IP forwarding is implemented for packets. This burdens the core devices and adversely affects their performance. To solve this problem, you can configure route recursion to LSPs on access devices so that users can access the Internet through LSPs. In this way, core devices do not need to learn a large number of Internet routes, saving routing table storage space and CPU resources.

Prerequisites

Before configuring route recursion to LSPs, you have completed the following tasks:

  • Configure routing protocols or static routes.

  • Establish an MPLS LSP, BGP LSP, or MPLS Local Ifnet.

  • Configure an IP prefix list or a tunnel policy if you want to recurse only desired routes to LSPs.

Procedure

  • Configure the device to recurse non-labeled public network BGP routes and static routes to LSPs.
    1. Enter the system view.

      system-view

    2. Allow non-labeled public network routes to be recursed to LSPs.

      route recursive-lookup tunnel [ ip-prefix ip-prefix-name ] [ tunnel-policy policy-name ]

      By default, non-labeled public network routes can be recursed only to outbound interfaces and next hops, but not to tunnels.

      The route recursive-lookup tunnel command can be used to recurse non-labeled public network BGP routes and static routes to BGP LSPs, LDP LSPs, or MPLS local Ifnet tunnels.

      • LDP LSPs: Non-labeled public network BGP routes and static routes can be recursed to LDP LSPs and can carry unicast and multicast services.

      • BGP LSPs: Both non-labeled public network BGP routes and static routes can be recursed to BGP LSPs and can carry unicast services rather than multicast services.

      • MPLS local Ifnet tunnels: Only non-labeled public network BGP routes can be recursed to MPLS local Ifnet tunnels and carry unicast and multicast services.

      If neither ip-prefix ip-prefix-name nor tunnel-policy policy-name is specified, all non-labeled public network BGP routes and static routes are preferentially recursed to LSPs.

  • Configure the device to recurse static routes to LSPs.
    1. Enter the system view.

      system-view

    2. Allow static routes to be recursed to LSPs.

      ip route-static recursive-lookup tunnel [ ip-prefix ip-prefix-name ] [ tunnel-policy policy-name ]
