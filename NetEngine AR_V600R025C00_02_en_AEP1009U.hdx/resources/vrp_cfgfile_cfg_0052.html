Entering the Configuration Trial Run Mode

Context

The configuration trial run mode allows you to test new functions and services without affecting those running on the live network, which improves network reliability.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the configuration trial run mode.

    commit trial [ timelen ] [ label labelstring ] [ persist persistId ] [ description descriptionstring ]

    When the timeout interval configured for trial run is reached, the system automatically rolls back configurations to those before the trial run.

  3. Perform configurations based on service requirements. For example, run the sysname command to set the host name of the device.

    sysname host-name

  4. (Optional) Commit the configurations in trial run.

    commit [ persist persistId ]

    If the persist parameter is specified when you configure the trial run mode, you can run the commit persist persistId command in any session to commit the configurations in the persistent trial run mode. If the persist parameter is not specified, you can run the commit command only in the current session to commit the configurations in the trial run mode.

  5. (Optional) Cancel the trial run mode.

    abort trial [ { session session-id | persist persistId } ]

    After the command is executed, the system configurations are rolled back to those before the trial run.

    The trial run state does not terminate when a session ends. If the persist parameter is specified when you configure the trial run mode and the corresponding session has ended, you can run the abort trial persist persistId command in a new session to terminate the configuration trial run state. If the persist parameter is not specified, you can run the abort trial session session-id command in a new session after re-login to terminate the configuration trial run state.

Verifying the Configuration

Run the display configuration trial status command to query the configuration trial run status.
