Checking System Diagnosis Information

Context

If an exception or a fault occurs on a device, you need to promptly and accurately collect information generated during device running. The system log module continuously records logs generated during device service running, ensuring complete log records. You can perform the one-click diagnostic function to quickly view the diagnostic information of a device, and collect the current log information and performance indicator data of the system, providing a reliable basis for subsequent diagnosis analysis and system maintenance.

Procedure

  • Collect system logs, one-click diagnostic command output, and KPI information and save them into a package. Run the following command in the diagnostic view or user view:

    collect diagnostic information [ slot slot-id [ cpu cpu-id ] ] [ file-type { { logtype } &<1-5> | all } ] [ { all-time | start-time starttime [ end-time endtime ] } ] [ out-file outfile ] [ force ]
    • The file-type parameter is of the enumerated type. If it is not specified, diagnostic logs, user logs, and KPI information are collected by default. Table 1 lists the values supported by this parameter.
      Table 1 Log collection scope

      Enumerated Value of the file-type Parameter

      Log to Be Collected

      Collection Content

      File Name

      Storage Path

      all

      All types of logs

      One-click diagnostic command output, diagnostic logs, user logs, and KPI information

      -

      -

      cmd-diag-info

      One-click diagnostic logs

      Output of the display diagnostic-information command
      • slot not specified: diagnostic-information.txt
      • slot specified: diagnostic-information_slot-id.txt

      -

      user-log

      User logs

      User logs and security logs
      • log.log and log_XXX_XXX.log.zip: user operation logs
      • security.log and security_XXX_XXX.log.zip: security logs
      • log.log and log_XXX_XXX.log.zip: flash:/logfile/
      • security.log and security_XXX_XXX.log.zip: flash:/logfile/security/

      diag-log

      Diagnostic logs

      Diagnostic logs
      • diaglog.log and diaglog_XXX_XXX.log.zip: diagnostic logs
      • pads.pads and pads_XXX_XXX.pads.zip: maintenance logs
      • Private logs
      • diaglog.log, diaglog_XXX_XXX.log.zip: flash:/logfile/
      • pads.pads and pads_XXX_XXX.pads.zip: flash:/logfile/pads/
      • Private logs: Their storage path cannot be viewed.

      kpi

      KPI information

      KPI statistics of the device, such as the CPU and memory usage
      • cpu.csv and cpu.zip: KPI statistics of the device, such as the CPU and memory usage
      • iface.csv and iface.zip: information about inbound and outbound interfaces
      • kpi.dat and kpi.dat.zip: KPI data excluding the preceding two types
      • kpi.dat and kpi.dat.zip: flash:/full_kpi
      • cpu.csv and cpu.zip: flash:/key_kpi
      • iface.csv and iface.zip: flash:/key_kpi
    • Path and name of the compressed package
      • If the path and name of the log file package are not specified, the diagnostic_information_host name_timestamp.zip file is generated in the flash memory.
      • If only the name of the log file package is specified, the package is saved in the current path (you can run the dir command to view the directory). If only the path of the log file package is specified, the diagnostic_information_host name_timestamp.zip file is generated in the specified path.

  • Display diagnostic information about the current system. If you only need to view the one-click diagnostic information, run the following command in any view:

    display diagnostic-information [ level level_value ] [ module-name ] &<1-8> [ slot slot-id ] [ file-name ]

    The display diagnostic-information command output includes the output for multiple display commands, such as display clock, display version, and display current-configuration. Running the display diagnostic-information command is equivalent to running these display commands in batches.

    Diagnostic information is mainly used for fault locating. Collecting such information may affect system performance. For example, it may increase CPU usage. As such, you are advised not to perform this operation when the system is running properly.
