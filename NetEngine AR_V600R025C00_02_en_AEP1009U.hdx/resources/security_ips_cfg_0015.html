Manually Creating an IPS Profile

Context

To filter signatures based on the actual network and services, you can manually create an IPS profile and reference it in a security policy.

In addition, the manually created IPS profile provides the exception signature function to adjust the action for a single signature.

Procedure

  1. Enter the system view.

    system-view

  2. Configure the service performance mode of the device.

    forward performance mode { routing | security | security-enhance }

    To enable security services, you are advised to switch the device's service performance mode to the secure forwarding mode (security) or enhanced security mode (security-enhance).

    You can run the display forward performance mode command to check the current service performance mode of the device.

    Some models do not support this command or some parameters. For details, see the command reference.

  3. Create an IPS profile.

    profile type ips name name

    If the content of a new IPS profile is similar to that of an existing IPS profile, you can run the profile type ips copy name new-name command to copy the existing IPS profile to create a new one.

  4. Create an IPS signature filter.

    signature-set name name

  5. Configure filtering conditions and actions for an IPS signature filter.

    Item

    Command

    Attack target of a signature

    target { both | client | server }

    Severity of a signature

    severity { high | medium | low | information } *

    Operating system for a signature

    os { android | ios | unix-like | windows | other } *

    Protocol for a signature

    protocol { protocol-name &<1-100> | all }

    NOTE:

    To specify a protocol after running the protocol all command, run the undo protocol all command first and then run the protocol protocol-name command.

    Attack type of a signature

    category { category-name &<1-100> | all }

    NOTE:

    To specify a category after running the category all command, run the undo category all command first and then run the category category-name command.

    Action for an IPS signature filter

    action { alert | block | default }

    Generally, the action set for a signature filter is default, that is, the default action is taken for a signature.

  6. Return to the IPS profile view.

    quit

  7. Optional: Configure exception signatures in the IPS profile view.

    exception ips-signature-id ips-signature-id [ action { alert | allow | block | { block-source-ip | block-destination-ip } [ timeout timeout ] }]

    You can configure response actions for exception signatures, including alert, allow, block, and blacklisting the source or destination address of traffic matching exception signatures. In addition, you can set the timeout period of the blacklist by setting the timeout timeout parameter.

  8. Return to the system view.

    quit

  9. Reference the IPS profile in a security policy.
    1. Enter the security policy view.

      security-policy

    2. Create a security policy rule and enter its view.

      rule name rule-name

    3. Reference the IPS profile.

      profile ips profile-name

      This section describes only the procedure for referencing the IPS profile in a security policy. For details about matching conditions in a security policy, see "Security Policy Configuration" in CLI Configuration Guide > Security Configuration.

    4. Set the action of the security policy rule to permit.

      action permit

    5. Return to the system view.

      quit
quit

  10. Commit the configuration in the system view.

    engine configuration commit

    The IPS profile configuration does not take effect immediately. The activation process takes a long time. You are advised to complete all the IPS profile configurations and then submit the configurations at a time.

Verifying the Configuration

Run the display ips statistics [ slot slot-id cpu cpu-id ] command to check IPS statistics.
