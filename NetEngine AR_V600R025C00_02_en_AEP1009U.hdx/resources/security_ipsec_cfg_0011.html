Understanding IPsec Encapsulation Modes

IPsec encapsulation is a process of adding AH or ESP fields to original IP packets for packet authentication and encryption. This process is implemented in either transport or tunnel mode.

Transport Mode

IPsec transport mode works by inserting an AH or ESP header between an IP header and a transport-layer protocol header to protect the payload. As no additional IP header is added, IP addresses in the original packets are visible in the IP header of the post-encrypted packet. Tunnel Mode

IPsec tunnel mode works by encrypting and authenticating an entire IP packet, including the IP header and payload. In this mode, an AH or ESP header is added before the raw IP header, and a new IP header is added before the AH or ESP header. Figure 2 shows an example of TCP packet encapsulation in tunnel mode.

The encapsulated new IP header inherits the Type of Service (TOS) field from the original IP header. This means that the new IP header preserves the priority of the original packet.

Comparisons Between Transport Mode and Tunnel Mode

The following describes the major differences between transport mode and tunnel mode:

  • Security

    The tunnel mode is more secure because original IP packets are completely authenticated and encrypted. This mode hides the IP address, protocol type, and port number in an original IP packet.

  • Usage scenarios

    • The transport mode is mainly used for communication between two hosts or between a host and a gateway.
    • The tunnel mode is mainly used for communication between two gateways or between a host and a gateway.

  • Impact on performance

    The tunnel mode generates an additional IP header, occupying more bandwidth than the transport mode.

  • Payload type identified by the Next Header field in the AH or ESP header
    • In transport mode, the Next Header field in the AH header identifies the protected upper-layer protocol number or ESP protocol number, and the Next Header field in the ESP header identifies the protected upper-layer protocol number.
    • In tunnel mode, the Next Header field in the AH header identifies the IP protocol number or ESP protocol number, and the Next Header field in the ESP header identifies the IP protocol number.
    • When both AH and ESP are used to protect traffic, they must use the same encapsulation mode, and the Next Header field in the AH header is the ESP header.

Automatic TCP MSS Adjustment

A SYN or SYN-ACK packet transmitted during TCP connection setup may contain a maximum segment size (MSS) option field to specify the MSS value on the local device to avoid truncation. After two devices exchange their MSS values, they compare the MSS values and forward packets based on the smaller MSS value to prevent packets from being fragmented on the network. Provided that packets remain unfragmented, a larger MSS value allows a greater amount of data to be sent per segment, which increasing network efficiency.

Devices support dynamic MSS adjustment of SYN or SYN-ACK packets during TCP connection setup. MSS adjustment can reduce the possibility of packet fragmentation and promote more reliable transmission of large data packets, improving end-to-end TCP transmission efficiency.

Table 1 shows the implementation of automatic TCP MSS adjustment.

Table 1 Implementation of automatic TCP MSS adjustment

Criteria

MSS Value

A SYN or SYN-ACK packet does not contain the MSS option field.

An MSS value MTU-40–APPENDLEN is automatically added to the packet.

A SYN or SYN-ACK packet contains the MSS option field.

The value of MTU-40-APPENDLEN is greater than or equal to that of MSS-APPENDLEN.

The original MSS value is retained.

The value of MTU-40-APPENDLEN is less than that of MSS-APPENDLEN.

The value of MTU-40-APPENDLEN is used as the new MSS value.

In the preceding information:

  • MSS indicates the MSS value automatically added to a SYN or SYN-ACK packet.
  • MTU indicates the maximum transmission unit (MTU) of an interface.
  • APPENDLEN indicates the packet length to be added during virtual private network (VPN) encryption and encapsulation.

Only pure IPsec supports this function, whereas GRE over IPsec does not support this function. The TCP MSS value is automatically adjusted only when the MTU values of the interfaces through which VPN encrypted traffic passes are the same and in a range from 256 to 9600 bytes.
