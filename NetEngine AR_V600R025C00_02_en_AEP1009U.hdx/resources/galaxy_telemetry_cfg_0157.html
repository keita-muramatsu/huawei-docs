Writing Code

This section only provides the code that you need to pay attention to. The code is for reference only.

You need to develop all the code except for the auto-generated code by yourself.

After adding the auto-generated Python files to a Python project, use the data push RPC service to receive telemetry data from the device. The telemetry header is parsed first, and then sampled data is parsed according to the sampled data structure defined in the .proto file matching the sensor_path field.

  1. Override the dataPublish method in the auto-generated RPC service and write code to retrieve sampled data.
    1. Override the dataPublish method in the RPC service.

      The abstract class gRPCDataserviceServicer is defined in the auto-generated RPC service Python file huawei_grpc_dialout_pb2_grpc.py. You need to override this abstract class in the dataPublish method to implement the class.

      Create a class (for example, DialoutServicer) to override that abstract class. The sample code is as follows:

      class DialoutServicer(huawei_grpc_dialout_pb2_grpc.gRPCDataserviceServicer):
    # In dataPublish method, use the TelemetryParser class to decode the received data.
    def dataPublish(self, request_iterator, context):
        for req in request_iterator:
            # Parse telemetry data.
            try:
                tel = telemetry_parser.TelemetryParser()
                # The final sampled data is stored in sample_datas.
                sample_datas = tel.parse_telemetry(req)           
                if sample_datas is None:
                    print("Parsing Wrong!")
            except Exception as e:
                logging.error(e)
    2. Write code for data parsing.

      The dataPublish method uses the input parameter request_iterator to obtain serviceArgs defined in the gRPC service. serviceArgs is triple-layered, carrying RPC parameters, a telemetry header, and sampled data, all of which must be parsed sequentially.

      1. The RPC parameters are defined in the huawei-grpc-dialout.proto file as follows:
        message serviceArgs {                       //Describes the message format.
    int64 ReqId = 1;                        //Indicates the request ID.
    oneof MessageData {
        bytes data = 2;         //Indicates that sampled data is encoded in GPB.
        string data_json = 4;   //Indicates that sampled data is encoded in JSON.
    }
    string errors = 3;         //Indicates error information.
}

        In this example, according to the sampled data format defined in huawei-cpu-memory.proto:

        Since the sampled data in this example is encoded in GPB, it is stored in the data field in binary form. If the sampled data is encoded in JSON, it is stored in the data_json field. The following sample code retrieves the GPB-encoded telemetry data from the data field and deserializes it using the ParseFromString method of the telemetry structure.

        # Retrieve sampled data from the data field.
tel_data = serArgs.data
 
# Deserialize the data.
telemetry = huawei_telemetry_pb2.Telemetry()
telemetry.ParseFromString(tel_data)
      2. The telemetry message structure is defined in the huawei-telemetry.proto file:
        message Telemetry {        //Defines the telemetry message structure.
   string node_id_str = 1;    //Indicates the device name.
   string subscription_id_str = 2;   //Indicates the name of a static subscription.
   string sensor_path = 3;           //Indicates the sampling path.
   string proto_path = 13;          //Indicates the message path that maps the sampling path in the .proto file.
   uint64 collection_id = 4;         //Indicates the sampling round.
   uint64 collection_start_time = 5;//Indicates the start time of a sampling round.
   uint64 msg_timestamp = 6;        //Indicates the timestamp when the message is generated.
   TelemetryGPBTable data_gpb = 7; //Indicates that the carried data is defined by TelemetryGPBTable.
   uint64 collection_end_time = 8;  //Indicates the end time of a sampling round.
   uint32 current_period = 9;       //Indicates sampling precision, in milliseconds.
   string except_desc = 10;        //Indicates an exception description, which is reported when a sampling exception occurs.
   string product_name = 11;       //Indicates the product name.
   enum Encoding {
    Encoding_GPB = 0;        //Indicates GPB encoding.
    Encoding_JSON = 1;       //Indicates JSON encoding.
  };
   Encoding encoding = 12;          //If GPB encoding is used, the data_gpb field is valid. If another encoding format is used, the data_str field is valid.
   string data_str = 14;            //This field is valid only when the data is not GPB encoded, and is empty if GPB encoding is used.
  string ne_id = 15;               //Indicates the unique ID of the NE to which data belongs in the gateway scenario.
  string software_version = 16;    //Indicates the software version number.
}
message TelemetryGPBTable {           //Defines the TelemetryGPBTable message structure.
   repeated TelemetryRowGPB row = 1;  //Array indicating that the data consists of multiple TelemetryRowGPB structures.
  repeated DataPath delete = 2;      //Deletes a data path.
  Generator generator = 3;           //Indicates the data source description, which applies to the OnChange+ service that requires high reliability.
}
message TelemetryRowGPB {
   uint64 timestamp = 1;            //Timestamp of the current sampling instance.
   bytes content = 11;              //Indicates the sampled data. The sensor_path field must be used to determine which .proto file is used for data encoding.
}

        The telemetry message includes both the sampling information and the actual sampled data. The sampled data encoded in GPB is stored in the data_gpb field and needs to be retrieved and then deserialized using the ParseFromString method. The data_gpb field contains a list of TelemetryRowGPB structures, each of which carries sampled data in the content field.

        tele_gpb_table = telemetry.data_gpb #Carries sampled data.

      3. The type of sampled data is determined by the sensor_path field in the telemetry header. An appropriate Python class must be selected based on sensor_path to deserialize the sampled data carried in content.

        In this example, sensor_path is huawei-cpu-memory:cpu-memory/board-cpu-infos/board-cpu-info, so the sampled data must be deserialized using the Python class generated from huawei-cpu-memory.proto. If sensor_path is huawei-mac:mac/mac-statistics/mac-statistic, the Python class generated from huawei-mac.proto should be used instead.

        Since all .proto files corresponding to sampling paths have been compiled and added to the Python project, the appropriate Python class can be selected based on sensor_path when the telemetry header is parsed. For easy implementation, the following sample code identifies the required Python files based on proto_path and dynamically imports them to the Python project.

        def parse_sample_data_gpb(self, byte_content, proto_path):
    # Identify the required.proto files based on proto_path, along with message names in those files.
    str_proto = re.split("\.", proto_path)
    proto_file = str_proto[0]
    proto_obj = str_proto[1]
    import_file = 'protos.proto_py.' + proto_file + '_pb2'
    pb2 = importlib.import_module(import_file)
    sample_data = eval('pb2.' + proto_obj)()
    sample_data.ParseFromString(byte_content)
    return sample_data

  2. Register the created class with the gRPC service framework. After writing the code for data parsing, define a network service and port for the server and register the gRPC API with the network service so that the server can receive data from the device.

    The sample Python code is as follows:

    try:
    grpcServer = grpc.server(futures.ThreadPoolExecutor(max_workers=4))  #Specifies the maximum number of worker threads that the server can use concurrently to handle requests.
    grpcServer.add_insecure_port (host + ':' + port) #Specifies the address and port for establishing a connection with the server.
except RuntimeError as e:
    sys.exit(1)
huawei_grpc_dialout_pb2_grpc.add_gRPCDataserviceServicer_to_server(DialoutServicer(), self.grpcServer) # Adds a function and the server. The server will deserialize data.
grpcServer.start() #Start the server.
grpcServer.wait_for_termination()
try:
    while True:
        time.sleep(1)
