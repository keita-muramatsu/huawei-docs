Configuring SaaS Traffic Steering

Prerequisites

Before configuring SaaS traffic steering, you have configured an NQA test instance.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the SaaS cloud access view.

    saas-cloud-express

  3. Specify a path index. The device supports the configuration of the DIA path index or SIG path index in different scenarios.

    • For link selection between multiple DIA links, specify the DIA path index.

      For link selection between multiple DIA links, a link quality change affects only the link selection result of new users. The historical session path of existing users remains unchanged to prevent sessions of existing users from being interrupted due to link switchover.

      1. Specify the DIA path index.
        path-index index interface { interface-name | interface-type interface-number } [ next-hop-address ] [ track nqa nqa-admin-name nqa-test-name ]

        By default, no DIA path index is specified in the system.

      2. (Optional) Establish the mapping between the local path index and the local breakout tunnel.
        local-path path-index inter-tunnel tunnel-number

        By default, the mapping between the local path index and the local breakout tunnel is not specified in the system.

    • For link selection between multiple DIA links in SIG proxy mode, specify the SIG path index.
      path-index index sig-tunnel tunnel-number [ track nqa nqa-admin-name nqa-test-name ] [ backup-tunnel backup-tunnel-number [ track nqa backup-nqa-admin-name backup-nqa-test-name ] ]

      By default, no SIG path index is specified in the system.

  4. Configure a SaaS path profile.
    1. Define a SaaS path profile and enter the SaaS path profile view, or enter the view of an existing SaaS path profile.

      saas-path profile profile-name

      By default, no SaaS path profile is created in the system.

    2. Specify the path index in the SaaS path profile.

      path-index index

      By default, no path index is specified in a SaaS path profile.

    3. (Optional) In a dual-gateway scenario, specify the peer path index in the SaaS path profile.

      peer-path-index index

      By default, no peer path index is specified in a SaaS path profile in a dual-gateway scenario.

    4. Return to the SaaS cloud access view.

      quit

  5. Configure a SaaS policy node.
    1. Define a SaaS policy node and enter the SaaS policy node view, or enter the view of an existing SaaS policy node.

      saas-policy node node-index

      By default, no SaaS policy node is created in the system.

    2. Bind a specified application group to the SaaS policy node.

      binding application-group application-group-name

      By default, no application group is bound to a SaaS policy node.

    3. (Optional) Set the base values of traffic steering evaluation parameters for the SaaS policy node, as described in the following table.

      Table 1 Base values of traffic steering evaluation parameters for the SaaS policy node

      Function

      Command

      Default Setting

      Set the base value of the delay for the SaaS policy node.

      delay-baseline value

      No base value of the delay (in milliseconds) is configured for a SaaS policy node in the system.

      Set the base value of the packet loss rate for the SaaS policy node.

      loss-baseline value

      No base value of the packet loss rate (in percentage) is configured for a SaaS policy node in the system.

      Set the packet loss rate weight for the SaaS policy node.

      loss-factor value

      No packet loss rate weight (in percentage) is configured for a SaaS policy node in the system.

    4. Configure the SaaS policy node to obtain the link detection result by tracking an NQA test instance.

      track nqa nqa-admin-name nqa-test-name

      By default, no NQA test instance is specified for a SaaS policy node.

    5. Bind a specified SaaS path profile to the SaaS policy node.

      saas-path-profile profile-name

      By default, no SaaS path profile is bound to a SaaS policy node.

    6. Apply the SaaS policy node to a specified VPN instance.

      apply-to vpn-instance vpn-instance-name

      By default, a SaaS traffic steering policy is applied to the instance _public_.

    7. (Optional) Configure the traffic steering mode.

      best-path

      The best-path command enables the optimal path mode. By default, the optimal path mode is disabled, and the load balancing mode is used in the system.

    8. (Optional) In load balancing mode, set the acceptable delay difference between the load-balancing link and the optimal link.

      load-balance delay-differ value

      By default, the delay difference is 50 ms.

    9. (Optional) In load balancing mode, set the acceptable packet loss rate difference between the load-balancing link and the optimal link.

      load-balance loss-differ value

      By default, the packet loss rate difference is 10%.

    10. (Optional) In load balancing mode, enable source IP address-based traffic steering.

      load-balance source-ip-based

      By default, 5-tuple-based traffic steering is used in load balancing mode, and source IP address-based traffic steering is disabled.

    11. Return to the SaaS cloud access view.

      quit

  6. (Optional) Set the base values of traffic steering evaluation parameters in the SaaS cloud access view. The base values configured in the SaaS policy node view take precedence over those configured in the SaaS cloud access view.

    Table 2 Base values of traffic steering evaluation parameters configured in the SaaS cloud access view

    Function

    Command

    Default Setting

    Set the base value of the delay in SaaS traffic steering evaluation parameters.

    saas-network-assessment delay-baseline value

    The base value of the delay in SaaS traffic steering evaluation parameters is 100 ms.

    Set the base value of the packet loss rate in SaaS traffic steering evaluation parameters.

    saas-network-assessment loss-baseline value

    The base value of the packet loss rate in SaaS traffic steering evaluation parameters is 1%.

    Set the packet loss rate weight in SaaS traffic steering evaluation parameters.

    saas-network-assessment loss-factor value

    The packet loss rate weight in SaaS traffic steering evaluation parameters is 50%.

  7. (Optional) Disable SaaS application identification and SaaS traffic steering for DNS packets.

    saas-dns bypass

    By default, SaaS application identification and SaaS traffic steering are performed for DNS packets.

Verifying the Configuration

  • Run the display saas policy { all | node-index } command to check the policy table of a SaaS policy node.
  • Run the display saas dns server command to check the DNS server list.
