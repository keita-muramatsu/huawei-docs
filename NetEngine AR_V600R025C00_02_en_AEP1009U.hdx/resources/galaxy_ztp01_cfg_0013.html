Understanding Email-based Deployment

Email-based deployment requires only simple operations on the web UI, greatly reducing labor and time costs. Figure 1 shows the deployment process.

Figure 1 Email-based deployment process
  1. A network administrator configures and sends a deployment email.
    1. The network administrator logs in to iMaster NCE-Campus, enters the device ESN, and configures network deployment parameters.
    2. The network administrator configures a deployment email (it is recommended that the email contain the guide for instructing the deployment person to perform the deployment) and sends the email to the specified email address. The URL in the email links to the network configurations of the corresponding device.
  2. A deployment person receives the deployment email.

    The deployment person logs in to the mailbox, confirms that the deployment email has been received, and takes a deployment terminal (a laptop or PC) to the deployment site.

  3. The deployment person powers on the device and obtains the configurations from the URL.
    1. After the device is installed and started, the deployment person connects the deployment terminal to the management interface of the device using an Ethernet cable and clicks the URL in the deployment email. The deployment terminal then sends the URL to the device to start the deployment process.
    2. The device resolves configuration parameters in the URL and pushes the deployment Portal page to the deployment terminal. After the deployment person confirms deployment on the Portal page, the device automatically completes configurations (including interface, network access, and VPN configurations) based on the parameters in the URL.
  4. The device automatically connects to the network and registers with iMaster NCE-Campus.
    1. After the device completes configurations, it automatically connects to the network based on the network access mode configured in the URL. Email-based deployment supports the following network access modes: static, DHCP, Point-to-Point Protocol over Ethernet (PPPoE), and Long-Term Evolution (LTE) dial-up.
    2. The device automatically initiates a NETCONF registration request to iMaster NCE-Campus based on the address and port number of iMaster NCE-Campus in the URL. If the registration succeeds, the deployment process ends. If the registration fails, the deployment person needs to locate the fault. After the fault is rectified, the device initiates registration with iMaster NCE-Campus again.
  • When deploying an unconfigured device, you are advised not to manually deliver the same configurations as those delivered during ZTP. Doing so will cause the configurations to be deleted if the deployment fails.
  • ZTP depends on OPS. You can run the display ops process current command to obtain the task ID, which indicates the ZTP process ID, and then run the ops stop process process-id command to stop the ongoing ZTP process. This operation, however, may cause the configurations that have been delivered during ZTP to be retained on the device.
