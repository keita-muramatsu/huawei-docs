Example for Checking Whether the Configurations of a Device Are Changed in a Specified Period

Networking Requirements

  • Most problems on the live network are caused by configuration changes. If a device service is abnormal or an alarm is generated, you can check whether the exception is caused by recent configuration changes. If the exception is caused by configuration changes, you can roll back the configurations to quickly restore services. In earlier versions, you need to run the display configuration commit changes command to query the configuration differences between configuration rollback points and run the display history-command all-users command to view the historical commands executed by all users recently. Then, determine the configuration changes in a certain period based on the command output. In the current version, you can run display configuration changes start-time startTime [ end-time endTime ] command to directly query configuration changes in a specified period, which is more convenient.
  • For a single device, you can perform the configuration restoration operations as instructed in this section. If multiple devices are deployed on a network and have been interconnected with the controller, you are advised to query and manage configuration changes on the controller for more efficient device management.
  • After configuring the IP addresses of the interfaces shown in Figure 1, the user finds that the IP addresses are incorrectly planned. As a result, services on the device are abnormal.
Figure 1 Configuration rollback

In this example, Interface1, Interface2, Interface3, and Interface4 represent 10GE0/0/1, 10GE0/0/2, 10GE0/0/3, and 10GE0/0/4 respectively.


Configuration Roadmap

The configuration roadmap is as follows:
  1. Configure IP addresses for interfaces.
  2. Services on the device are abnormal, or alarms are generated.
  3. Check whether the configurations are changed in the specified period.
  4. Roll back the configurations to the rollback point before the configurations are changed.

Procedure

  1. Generate a configuration rollback point.

    <HUAWEI> system-view
[HUAWEI] sysname Device
[Device] commit label label_test

  2. Configure IP addresses for 10GE0/0/1, 10GE0/0/2, 10GE0/0/3, and 10GE0/0/4 on the device. The IP addresses for these interfaces are as follows: 10.0.0.1/30, 10.0.1.1/30, 10.0.2.1/30, and 10.0.3.1/30.

    <HUAWEI> system-view
[HUAWEI] sysname Device
[Device] interface 10ge 0/0/1
[Device-10GE0/0/1] ip address 10.0.0.1 30
[Device-10GE0/0/1] quit
[Device] interface 10ge 0/0/2
[Device-10GE0/0/2] ip address 10.0.1.1 30
[Device-10GE0/0/2] quit
[Device] interface 10ge 0/0/3
[Device-10GE0/0/3] ip address 10.0.2.1 30
[Device-10GE0/0/3] quit
[Device] interface 10ge 0/0/4
[Device-10GE0/0/4] ip address 10.0.3.1 30
[Device-10GE0/0/4] quit
[Device] commit label label_ipaddress
[Device] quit

  3. Services on the device are abnormal, or alarms are generated.
  4. Check whether the configurations are changed in the specified period.

    <Device> display configuration changes start-time 2025/06/29,12:01:18 end-time 2025/06/29,16:55:20

+  ip address 10.0.3.1 255.255.255.252
  #

  5. Perform configuration rollback.

    # Roll back the configurations to the rollback point before the configurations are changed.

    Run the display configuration changes start-time 2025/06/29,12:01:18 end-time 2025/06/29,16:55:20 command to query configuration differences within a specified period. The command output shows that configurations have been changed between rollback points 1000000005 and 1000000006. In this example, you can run the rollback configuration to commit-id 1000000005 command to roll back the system configurations to what they are before the specified configuration rollback point is generated.

    <Device> rollback configuration to commit-id 1000000005

Please use 'display configuration commit changes last 1' to view the changes.
