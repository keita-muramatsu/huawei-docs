DSVPN Security

Security Policy Introduction

  • NHRP negotiation authentication

    In DSVPN, Next Hop Resolution Protocol (NHRP) enables a source spoke on a public network to dynamically obtain the public address of a destination spoke. When a spoke connects to a public network, it sends an NHRP Registration Request message to the hub using the public address of the outbound interface as the source address. The hub then creates or updates the corresponding NHRP mapping entry based on the message received. Two spokes also exchange NHRP Resolution Request and Reply messages to create or update NHRP mapping entries for each other.

    To prevent unauthorized spokes from registering with the hub, NHRP negotiation authentication can be enabled between the hub and spokes. In this way, after receiving an NHRP Registration Request message from a spoke, the hub checks for the authentication string in the message, and processes the message only if the authentication string carried in the message is the same as that configured on itself.

  • DSVPN over IPsec

    Data transmitted between the hub and spokes, as well as between spokes, can be encrypted to increase data security. During DSVPN deployment, an IPsec profile can be bound to DSVPN so that mGRE and IPsec tunnels are dynamically established between spokes.

    • The establishment of an mGRE tunnel immediately triggers that of an IPsec tunnel.
    • Typical IPsec technology uses ACLs to identify unicast traffic to be encrypted. An IPsec policy requires a large number of ACLs to be defined, which is difficult to implement. DSVPN uses both NHRP and mGRE technologies. Deploying DSVPN together with IPsec helps simplify device configurations, ensuring data transmission security and facilitating network deployment.
    • Because IPsec tunnels are dynamically established between spokes, IPsec data exchanged between spokes does not need to be decrypted or encrypted by the hub, minimizing data transmission delay.

Attack Methods

  • Listening to data transmitted between the hub and spokes and between spokes.
  • Masquerading as authorized spokes to register with the hub. The hub receives registration request messages from all spokes. When receiving registration request messages from unauthorized spokes, it also creates NHRP mapping entries for them. After the number of created NHRP mapping entries exceeds the upper limit, excess NHRP mapping entries are discarded.

Impact on the System

None

Procedure

  • Configure NHRP negotiation authentication.

    Configure the hub.

    1. Enter the system view.

      system-view

    2. Enable NHRP globally.

      nhrp enable

    3. Enter the tunnel interface view.

      interface tunnel interface-number

    4. Enable NHRP on the interface.

      nhrp enable

    5. (Optional) Configure the NHRP domain to which the interface belongs.

      nhrp network-id netId

      By default, an interface belongs to NHRP domain 0.

    6. Configure the NHRP multicast member table.

      nhrp entry multicast dynamic

    7. Specify an authentication string for NHRP negotiation.

      nhrp authentication [ hash { sha2-256 | sha2-384 | sha2-512 | md5 | sha1 } ] cipher authenString

      As MD5 and SHA1 algorithms are insecure, you are advised to use a more secure authentication mode.

    8. (Optional) Configure the hold time of NHRP mapping entries.

      nhrp entry holdtime holdtime

      By default, the hold time of NHRP mapping entries is 7200s.

    9. (Optional) Enable the NHRP redirect function.

      nhrp redirect

      Configure this command only when the shortcut function is configured for DSVPN. When forwarding traffic between spokes of the same DSVPN network, the hub sends an NHRP Redirect message to the source spoke. This triggers the source spoke to send NHRP Resolution Request messages and establish tunnels with other spokes for direct communication. By default, the NHRP redirect function is disabled.

    Configure spokes.

    1. Enter the system view.

      system-view

    2. Enable NHRP globally.

      nhrp enable

    3. Enter the tunnel interface view.

      interface tunnel interface-number

    4. Enable NHRP on the interface.

      nhrp enable

    5. (Optional) Configure the NHRP domain to which the interface belongs.

      nhrp network-id netId

      By default, an interface belongs to NHRP domain 0.

    6. (Optional) When the shortcut function is configured for DSVPN, enable the NHRP shortcut function on spokes.

      nhrp shortcut

      By default, the NHRP shortcut function is disabled.

    7. Configure the NHRP multicast member table.

      nhrp entry multicast dynamic

      By default, the NHRP multicast member table is not configured.

    8. Configure an NHRP mapping entry.

      nhrp entry protocol-address nbma-address [ register ]

    9. (Optional) Enable the device to send NHRP messages with the no-unique flag to instruct the peer end to overwrite conflicting NHRP mapping entries.

      nhrp registration no-unique

      By default, the device sends NHRP messages without the no-unique flag to instruct the peer end not to overwrite conflicting NHRP mapping entries.

    10. Specify an authentication string for NHRP negotiation.

      nhrp authentication [ hash { sha2-256 | sha2-384 | sha2-512 | md5 | sha1 } ] cipher authenString

      Perform this configuration on spokes if you have performed it on the hub.

      For security purposes, it is recommended that the authentication string contain at least six characters, including at least two of the following types: lowercase letters, uppercase letters, digits, and special characters.

    11. (Optional) Set the NHRP registration interval.

      nhrp registration interval regInterval

      By default, a spoke registers with the hub at an interval of 2400s.

    12. (Optional) Configure the hold time of NHRP mapping entries.

      nhrp entry holdtime holdtime

      By default, the hold time of NHRP mapping entries is 7200s.

  • Configure DSVPN over IPsec.

    1. Configure an IKE proposal. For details, see Configuring an IKE Proposal.
    2. Configure an IKE peer. For details, see Configuring an IKE Peer.

      There is no need to configure a peer ID or peer IP address in DSVPN.

    3. Configure an IPsec proposal. For details, see Configuring an IPsec Proposal.
    4. Configure an IPsec profile.
      1. Enter the system view.
        system-view
      2. Create an IPsec profile and enter the IPsec profile view.
        ipsec profile profile-name
      3. Reference an IPsec proposal.
        proposal proposal-name
      4. Reference an IKE peer.
        ike-peer peer-name
      5. (Optional) Configure the perfect forward secrecy (PFS) feature used when the local end initiates negotiation.
        pfs { dh-group1 | dh-group2 | dh-group5 | dh-group14 | dh-group15 | dh-group16 | dh-group18 | dh-group19 | dh-group20 | dh-group21 | dh-group24 }

        By default, PFS is not used when the local end initiates IPsec tunnel negotiation.

        When the local end initiates negotiation, there is an additional DH exchange in IKEv1 phase 2 or IKEv2 Create_Child_SA Exchange, which ensures security of the IPsec SA key and improves communication security. Diffie-Hellman (DH) groups 1, 2, and 5 are not recommended because they cannot meet security requirements.

        If PFS is specified at the local end, you also need to specify PFS at the peer end. The DH groups specified on the two ends must be the same. Otherwise, the negotiation fails.

      6. Exit the IPsec profile view.
        quit
    5. Apply the IPsec profile.
      1. Enter the tunnel interface view.
        interface tunnel interface-number
      2. Apply the IPsec profile to the tunnel interface.
        ipsec profile profile-name
      3. Commit the configuration.
        commit
