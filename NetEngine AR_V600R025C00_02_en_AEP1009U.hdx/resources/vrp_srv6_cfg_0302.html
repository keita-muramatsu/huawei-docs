Configuring EVPN L3VPNv4 over SRv6 TE Policy

Prerequisites

Before configuring EVPN L3VPNv4 over SRv6 TE Policy, you have completed the following tasks:

  • Configure an SRv6 TE Policy manually or use a controller to dynamically deliver an SRv6 TE Policy.

  • Configuring Color-based Traffic Steering into an SRv6 TE Policy or Configuring TE-Class-based Traffic Steering into an SRv6 TE Policy.

Context

EVPN L3VPNv4 over SRv6 TE Policy uses public network SRv6 TE Policies to carry EVPN L3VPNv4 services.

As shown in Figure 1, PE1 and PE2 communicate through an IPv6 public network. An SRv6 TE Policy can be deployed on the IPv6 public network to carry EVPN L3VPNv4 services.

Figure 1 Network diagram of EVPN L3VPNv4 over SRv6 TE Policy

Procedure

  1. Configure an L3VPN instance.

    1. Create a VPN instance and enter the VPN instance view.

      ip vpn-instance vpn-instance-name

    2. Enable the VPN instance IPv4 address family and enter the VPN instance IPv4 address family view.

      ipv4-family

    3. Configure an RD for the VPN instance IPv4 address family.

      route-distinguisher route-distinguisher

    4. Configure VPN targets for the VPN instance IPv4 address family to implement route leaking into the specified EVPN instance.

      vpn-target vpn-target &<1-8> [ both | export-extcommunity | import-extcommunity ] evpn

    5. (Optional) Configure a default color for L3VPNv4 services to recurse to an SRv6 TE Policy.

      default-color color-value evpn

      If a remote EVPN route without carrying the color extended community is leaked to a local VPN instance, the default color value is used for the recursion to the SRv6 TE Policy.

    6. (Optional) Associate the VPN instance IPv4 address family with an import route-policy to filter routes imported from the EVPN instance to the VPN instance IPv4 address family.

      import route-policy policy-name evpn

      Perform this step to associate the VPN instance IPv4 address family with an import route-policy and set attributes for eligible routes. This enables you to more precisely control the routes to be imported from the EVPN instance to the VPN instance IPv4 address family.

    7. (Optional) Associate the VPN instance IPv4 address family with an export route-policy to filter routes to be advertised from the VPN instance IPv4 address family to the EVPN instance.

      export route-policy policy-name evpn

      Perform this step to associate the VPN instance IPv4 address family with an export route-policy and set attributes for eligible routes. This enables you to more precisely control the routes to be advertised from the VPN instance IPv4 address family to the EVPN instance.

    8. Exit the VPN instance IPv4 address family view.

      quit

    9. Exit the VPN instance view.

      quit

  2. Bind an access-side interface to the L3VPN instance.
    1. Enter the interface view.

      interface interface-type interface-number

    2. Bind the interface to the VPN instance.

      ip binding vpn-instance vpn-instance-name

    3. Configure an IPv4 address for the interface.

      ip address ip-address { mask | mask-length }

    4. Exit the interface view.

      quit

  3. Configure BGP EVPN peer relationships.

    If a BGP RR needs to be deployed on the network, establish BGP EVPN peer relationships between all the PEs and the RR.

    1. Enable BGP and enter the BGP view.

      bgp { as-number-plain | as-number-dot }

    2. Specify the remote PE as a peer.

      peer { ipv6-address | group-name } as-number { as-number-plain | as-number-dot }

    3. (Optional) Specify the source interface and source address used to establish a TCP connection with the BGP peer.

      peer { ipv6-address | group-name } connect-interface interface-type interface-number

      If loopback interfaces are used to establish a BGP connection, you are advised to run the peer connect-interface command on both ends to ensure connectivity. If this command is run on only one end, the BGP connection may fail to be established.

    4. Enter the BGP-VPN instance IPv4 address family view.

      ipv4-family vpn-instance vpn-instance-name

    5. Import routes of other protocols to the BGP-VPN instance IPv4 address family view.

      import-route { direct | isis process-id | ospf process-id | rip process-id | static } [ med med | route-policy route-policy-name ] *

      To advertise host IP routes, you only need to configure import of direct routes. To advertise the subnet route of the host, use a dynamic routing protocol (such as OSPF) to advertise the route and then perform this step to import the routes of the dynamic routing protocol.

    6. Configure the device to advertise IP prefix routes.

      advertise l2vpn evpn

      These routes can be either host IP routes or subnet routes.

    7. Exit the BGP-VPN instance IPv4 address family view.

      quit

    8. Enter the BGP-EVPN address family view.

      l2vpn-family evpn

    9. Enable the ability to exchange EVPN routes with a specified peer or peer group.

      peer { ipv6-address | group-name } enable

    10. Configure the device to advertise EVPN routes carrying SRv6 encapsulation attributes to a specified peer.

      peer { ipv6-address | group-name } advertise encap-type srv6

    11. Exit the BGP-EVPN address family view.

      quit

    12. Exit the BGP view.

      quit

  4. On each PE, configure EVPN L3VPNv4 services to recurse to an SRv6 TE Policy.
    1. Enable Segment Routing in the IPv6 forwarding plane and enter the SRv6 view.

      segment-routing ipv6

    2. Configure a source address for SRv6 EVPN encapsulation.

      encapsulation source-address ipv6-address

      Alternatively:

      encapsulation source-interface { intfname | interfaceType interfaceNum }

      You only need to run one of the preceding commands. If they are both run, the later configuration overrides the previous one. If no IPv6 global address is configured for the interface specified using the encapsulation source-interface command, the source address for SRv6 encapsulation is not configured.

    3. Configure an SRv6 locator.

      locator locator-name [ ipv6-prefix ipv6-address mask-length [ static static-length | args args-length ] * ]

    4. (Optional) Configure a static End.DT4 SID opcode.

      opcode func-opcode end-dt4 vpn-instance vpn-instance-name evpn

      The preceding type of SID can be dynamically allocated by BGP or manually configured. If you want to use the segment-routing ipv6 locator locator-name command to enable dynamic SID allocation through BGP in the future, skip this step.

    5. Exit the SRv6 locator view.

      quit

    6. Exit the SRv6 view.

      quit

    7. Enter the BGP view.

      bgp { as-number-plain | as-number-dot }

    8. Enter the BGP-VPN instance IPv4 address family view.

      ipv4-family vpn-instance vpn-instance-name

    9. Enable the device to add SIDs to VPN routes to be sent to EVPN.

      segment-routing ipv6 locator locator-name evpn

    10. Enable the function of EVPN L3VPNv4 service recursion to SRv6 TE Policies.

      segment-routing ipv6 traffic-engineer [ best-effort ] evpn

      If an SRv6 BE path exists on the network, you can set the best-effort parameter, allowing the SRv6 BE path to function as a best-effort path in the case of an SRv6 TE Policy fault.

    Verifying the Configuration

    • Run the display bgp vpnv4 { all | route-distinguisher route-distinguisher | vpn-instance vpn-instance-name } routing-table [ network [ prefix-length ] ] command to check BGP VPNv4 route information. The command output shows that the value of Relay Tunnel Out-Interface is SRv6 TE Policy.

    • Run the display bgp evpn all routing-table prefix-route prefix command to check EVPN IP prefix route information.
    • Run the display ip routing-table vpn-instance vpn-instance-name command to check IPv4 VPN route information received from the remote end.
