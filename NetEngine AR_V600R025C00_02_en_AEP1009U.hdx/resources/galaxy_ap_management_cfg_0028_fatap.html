Resetting APs

Context

You can reset APs after they are upgraded or when they are not working properly. Run the display ap all command and check the State field in the command output. The ver-mismatch, config, config-failed, committing, or commit-failed state indicates that an AP is not working properly.

APs are detected before they go online to ensure that they can send and receive packets. During the detection, an AP automatically resets if it does not go online for more than 24 consecutive hours (when the CAPWAP tunnel is up) and no users (including the offline management users, service-holding users, console port user, and remote user) exist on the AP.

Resetting APs will interrupt services of STAs connected to the APs. Therefore, exercise caution when you perform this operation.

Procedure

  • Run the ap-reset { ap-mac ap-mac | all | ap-group ap-group | ap-type { type-id type-id | type type-name } | ap-id ap-id } command in the WLAN view to reset APs.
  • Run the ap-reset wait-rtu-validate command in the WLAN view to reset APs on which RTU licenses have been loaded but have not taken effect.
