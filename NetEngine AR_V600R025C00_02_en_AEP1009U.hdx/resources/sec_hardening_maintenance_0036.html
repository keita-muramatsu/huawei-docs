OSPF/OSPFv3

Overview

OSPF/OSPFv3 security hardening policies are classified into the following two types:

  • OSPF/OSPFv3 GTSM

    GTSM checks TTL values to defend against attacks. GTSM checks the TTL values of only the packets that match the GTSM policy. You can set the default action taken on the packets that do not match the policy to pass or drop. If the default action is set to drop, you need to specify all possible device connections in the GTSM policy. Because the local device drops any packet it receives from another device with which no connection is specified in the GTSM policy, no connection can be established between the two devices. As such, GTSM improves security but reduces the ease of use.

  • OSPF/OSPFv3 packet authentication

    OSPF/OSPFv3 supports packet authentication, whereby packets are accepted only if they are authenticated. If packets fail to be authenticated, a neighbor relationship cannot be established. If area authentication is configured, all the devices in an area must use the same authentication mode and password. When interface authentication is used, an authentication mode and password are set between neighboring devices. Interface authentication takes precedence over area authentication.

OSPF/OSPFv3 is susceptible to forged packet-based attacks. To identify and discard these packets, packet authentication can be configured.

An attacker may use the following methods to initiate attacks:

  • Change the aging time of packets to the maximum value so that all devices flood these packets.

  • Advertise the LSAs in which the sequence numbers are equal to or close to the maximum value.

  • Change the sequence number when the state of the encryption sequence number resets during a neighbor restart.

  • Change the neighbor list in Hello packets.

Impact on the System

None

Procedure

  • Configure OSPF GTSM.
    1. Enter the system view.

      system-view

    2. Configure OSPF GTSM.

      ospf valid-ttl-hops hops [ nonstandard-multicast ] [ vpn-instance vpn-instance-name ]

      After this step is performed, only the packets matching the OSPF GTSM policy are sent to the control plane for processing. Note the following:

      • The ospf valid-ttl-hops command has two functions: enabling OSPF GTSM and specifying a TTL value for check. If you specify vpn-instance in the command, the device checks the TTL values of packets only in this VPN instance.

      • The valid TTL range of detected packets is [255 – ttl + 1, 255].

    3. Set a default action taken on the packets that do not match the GTSM policy.

      gtsm default-action { drop | pass }

      You can set the default action taken on the packets that do not match a GTSM policy to pass or drop. By default, the packets that do not match a GTSM policy can pass filtering.

      To facilitate fault locating, you can enable the device to log information about discarded packets.

  • Configure OSPF area authentication.
    1. Enter the system view.

      system-view

    2. Enter the OSPF view.

      ospf [ process-id ]

    3. Enter the OSPF area view.

      area area-id

    4. Configure one of the following authentication modes for the OSPF area as required:

      • Configure simple authentication.

        authentication-mode simple [ plain SPlainText | [ cipher ] SCipherText ]
        plain indicates the cleartext mode. cipher indicates the ciphertext mode.

        When configuring an authentication password, you are advised to use the ciphertext mode. If you select the plaintext mode, the password is saved as a plaintext in the configuration file, which has a high risk. To ensure device security, change the password periodically.

      • Configure ciphertext authentication.

        authentication-mode { md5 | hmac-md5 | hmac-sha256 } [ KeyID { plain SPlainText | [ cipher ] SCipherText } ]

        plain indicates the cleartext mode. cipher indicates the ciphertext mode. By default, the cipher mode is used.

        For security purposes, you are advised to use HMAC-SHA256 authentication rather than simple, MD5, or HMAC-MD5 authentication.

      • Configure keychain authentication.

        authentication-mode keychain Keychain-Name

        If keychain authentication is used, configure a keychain first.

  • Configure OSPF interface authentication.
    1. Enter the system view.

      system-view

    2. Enter the interface view.

      interface interface-type interface-number

    3. Switch the interface working mode to Layer 3.

      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    4. Configure one of the following authentication modes for the OSPF interface as required:

      • Configure simple authentication.

        ospf authentication-mode simple [ plain plain-text | [ cipher ] cipher-text ]
        plain indicates the cleartext mode. cipher indicates the ciphertext mode.

        When configuring an authentication password, you are advised to use the ciphertext mode. If you select the plaintext mode, the password is saved as a plaintext in the configuration file, which has a high risk. To ensure device security, change the password periodically.

      • Configure ciphertext authentication.

        ospf authentication-mode { md5 | hmac-md5 | hmac-sha256 } [ KeyID { plain plain-text | [ cipher ] cipher-text } ]

        plain indicates the cleartext mode. cipher indicates the ciphertext mode. For MD5, HMAC-MD5, or HMAC-SHA256 authentication, cipher is used by default.

        For security purposes, you are advised to use HMAC-SHA256 authentication rather than simple, MD5, or HMAC-MD5 authentication.

      • Configure keychain authentication.

        ospf authentication-mode keychain keychain-name

        If keychain authentication is used, configure a keychain first.

  • Configure OSPFv3 area authentication.
    1. Enter the system view.

      system-view

    2. Enter the OSPFv3 view.

      ospfv3 [ process-id ]

    3. Enter the OSPFv3 area view.

      area area-id

    4. Configure an authentication mode for the OSPFv3 area as required.

      • Configure HMAC-SHA256 or HMAC-SM3 authentication for the OSPFv3 area.

        authentication-mode { hmac-sha256 | hmac-sm3 } key-id KeyId  { plain PlainText | [ cipher ] CipherText }

        plain indicates the cleartext mode. cipher indicates the ciphertext mode. By default, the cipher mode is used.

        When configuring an authentication password, you are advised to use the ciphertext mode. If you select the cleartext mode, the password is saved in configuration scripts in cleartext, which poses a high security risk. For security purposes, you are advised to change the password periodically.

      • Configure keychain authentication.

        authentication-mode keychain Keychain-Name

        If keychain authentication is used, configure a keychain first.

  • Configure OSPFv3 process authentication.
    1. Enter the system view.

      system-view

    2. Enter the OSPFv3 view.

      ospfv3 [ process-id ]

    3. Switch the interface working mode to Layer 3.

      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    4. Configure an authentication mode for the OSPFv3 process as required.

      • Configure ciphertext authentication.

        authentication-mode { hmac-sha256 | hmac-sm3 } key-id KeyId  { plain PlainText | [ cipher ] CipherText }

        plain indicates the cleartext mode. cipher indicates the ciphertext mode. By default, the cipher mode is used.

        When configuring an authentication password, you are advised to use the ciphertext mode. If you select the cleartext mode, the password is saved in configuration scripts in cleartext, which poses a high security risk. For security purposes, you are advised to change the password periodically.

      • Configure keychain authentication.

        authentication-mode { keychain Keychain-Name }

        If keychain authentication is used, configure a keychain first.

  • Configure OSPFv3 interface authentication.
    1. Enter the system view.

      system-view

    2. Enter the interface view.

      interface interface-type interface-number

    3. Switch the interface working mode to Layer 3.

      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    4. Configure an authentication mode for the OSPFv3 interface as required.

      • Configure ciphertext authentication.

        authentication-mode { hmac-sha256 | hmac-sm3 } key-id KeyId  { plain PlainText | [ cipher ] CipherText }

        plain indicates the cleartext mode. cipher indicates the ciphertext mode. By default, the cipher mode is used.

        When configuring an authentication password, you are advised to use the ciphertext mode. If you select the cleartext mode, the password is saved in configuration scripts in cleartext, which poses a high security risk. For security purposes, you are advised to change the password periodically.

      • Configure keychain authentication.

        ospfv3 authentication-mode { keychain Keychain-Name }

        If keychain authentication is used, configure a keychain first.

Verifying the Security Hardening Result

  • Run the display ospf [ process-id ] brief command to check OSPF area authentication configurations.
  • Run the display ospf [ process-id ] interface [ interface-name | interface-type interface-number | all ] [ verbose ] command to check OSPF interface authentication configurations.
