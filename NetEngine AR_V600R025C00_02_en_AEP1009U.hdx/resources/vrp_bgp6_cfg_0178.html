Configuring IPv6 BGP-LS

Prerequisites

Before configuring IPv6 BGP-LS, you have completed the following tasks:
  • Configure basic IPv6 IS-IS functions.

Context

On a network without BGP-LS, a device uses an IGP (IS-IS) to collect information about the network topology and report information about each area's topology separately to an upper-layer controller. This method has the following disadvantages:
  • The controller must have high computing capabilities and support both the IGP and its algorithm.
  • The controller cannot obtain complete information about the inter-IGP area topology. As a result, it cannot compute E2E optimal paths.
  • Different routing protocols report topology information separately to the controller, which complicates the controller's analysis and processing.
After BGP-LS is introduced, BGP summarizes topology information collected by the IGP and reports it to an upper-layer controller. With BGP's powerful route selection capabilities, BGP-LS has the following advantages:
  • Lowers the requirements on the controller's computing capabilities and no longer requires IGP capabilities on the controller.
  • Facilitates route selection and computation on the controller by using BGP to summarize process or AS topology information and report the complete information to the controller.
  • Requires only one routing protocol (BGP) to report topology information to the controller.

BGP-LS needs to be deployed on the devices connected to the controller.

Procedure

  1. Enable IS-IS topology advertisement.
    1. Enter the system view.

      system-view

    2. Start an IS-IS process and enter the IS-IS view.

      isis [ process-id ] [ vpn-instance vpn-instance-name ]

    3. Configure an IS-IS cost style.

      cost-style { { narrow | wide | wide-compatible } | { compatible | narrow-compatible } [ relax-spf-limit ] }

      By default, a device sends and accepts routes with the IS-IS cost style being narrow. The cost value range of an interface and the cost value range of the routes that can be accepted by the interface vary with the cost style.

      If the cost style is narrow, the cost of an interface ranges from 1 to 63. The maximum cost of the routes accepted by the device is 1023.

      If the cost style is narrow-compatible or compatible, the cost of an interface ranges from 1 to 63. The cost of the routes accepted by the device is related to relax-spf-limit.

      If the cost style is wide or wide-compatible, the cost of an interface ranges from 1 to 16777214 or the maximum value (16777215). The maximum cost of the routes that can be accepted by the interface is 16777214.

    4. Enable TE for the IS-IS process of a specified level.

      traffic-eng [ level-1 | level-2 | level-1-2 ]

    5. Enable IPv6 TE for the IS-IS process of a specified level.

      ipv6 traffic-eng [ level-1 | level-2 | level-1-2 ]

    6. Enable IS-IS SRv6.

      segment-routing ipv6 locator locator-name [ auto-sid-disable ]

    7. Enable IS-IS topology advertisement.

      ipv6 bgp-ls enable [ level-1 | level-2 | level-1-2 ] [ exclude-prefix ]

    8. (Optional) Set a BGP-LS identifier for IS-IS.

      bgp-ls identifier identifier-value

      The default BGP-LS identifier of IS-IS is 0.

  2. Enable BGP-LS.
    1. Enter the system view.

      system-view

    2. Enter the BGP view.

      bgp as-number

    3. Specify the IP address of a peer and the number of the AS where the peer resides.

      peer ipv6-address as-number as-number

    4. Enable BGP-LS and enter the BGP-LS address family view.

      link-state-family unicast

    5. Enable the device to exchange BGP-LS routes with the specified peer.

      peer ipv6-address enable

    6. (Optional) Set a BGP-LS domain ID.

      domain identifier domain-id

      A BGP-LS domain ID identifies a device on which BGP-LS is enabled. If no BGP-LS domain ID is set, the router ID of BGP is used as a BGP-LS domain ID by default. The same BGP-LS domain ID can be configured for different devices. This is required if a controller needs to compute paths based on the combined topology information reported by the devices.

      If the BGP-LS domain ID is set to 0.0.0.0, this domain ID does not take effect.

    7. (Optional) Set a BGP-LS domain AS number.

      domain as domain-asNum

      By default, the AS number of BGP is used as a BGP-LS domain AS number. If a controller needs to compute paths based on the combined topology information reported by two devices that have different BGP AS numbers, run the domain as command to set the same BGP-LS domain AS number for the two devices.

    8. (Optional) Configure the device as an RR, and specify a client for it.

      peer ipv6-address reflect-client

      The device configured with the peer reflect-client command functions as an RR, and the specified peer functions as a client.

      If the clients of an RR are fully meshed, you can run the undo reflect between-clients command to disable route reflection among these clients through the RR to reduce the cost.

      If a cluster has multiple RRs, you can configure the same cluster ID for them using the reflector cluster-id { cluster-id-value | cluster-id-ipv4 } command. This command can be configured only on RRs.

    9. (Optional) Set the maximum number of BGP-LS routes that can be accepted from the specified peer.

      peer ipv6-address route-limit limit [ percentage ] [ alert-only | idle-forever | idle-timeout times ]

      Generally, a BGP-LS routing table contains a large number of routes. If a large number of routes are received from peers, excessive system resources are consumed. To prevent this problem, run this command to set the maximum number of routes that a BGP device is allowed to receive from a peer. By default, there is no limit on the number of routes that can be accepted from a peer.

    10. (Optional) Apply a route-policy to BGP-LS routes to be received from or advertised to the specified peer.

      peer ipv6-address route-policy route-policy-name { import | export }

      After a route-policy is created, you can run the peer route-policy command to apply the route-policy to filter the BGP-LS routes to be received from or advertised to a specified peer. The command configuration ensures that only desired routes are accepted or advertised. This facilitates route management and reduces the size of the BGP-LS routing table and consumption of system resources.

    11. (Optional) Set an interval at which Update messages carrying the same route prefix are sent to the specified peer.

      peer ipv6-address route-update-interval interval

      When BGP-LS routes change, a device sends Update messages to notify its peers of the changes. If a route changes frequently, run this command to set a proper interval at which the device sends Update messages carrying the same route prefix to a specified peer. This prevents the device from sending Update messages upon each route change. By default, a device sends Update messages to IBGP peers at an interval of 15s and to EBGP peers at an interval of 30s.

    12. (Optional) Configure a mode in which the device processes specified BGP path attributes.

      peer ipv6-address path-attribute-treat attribute-id { id [ to id2 ] } &<1-255> { discard | withdraw | treat-as-unknown }

      BGP Update messages contain various path attributes. If the local device receives any Update message with an incorrect format, BGP session flapping may occur. To enhance reliability, you can run this command to configure a mode for the device to process specified BGP path attributes. By default, BGP path attributes are processed according to the standard protocol.

    13. (Optional) Set the maximum number of AS number repetitions in the AS_Path attribute allowed by a peer.

      peer ipv6-address allow-as-loop [ number ]

Verifying the Configuration

After the configuration is complete, verify it.

  • Run the display bgp link-state unicast peer command to check information about BGP-LS peers and their status.
  • Run the display bgp link-state unicast routing-table command to check information about BGP-LS routes.
  • Run the display bgp link-state unicast routing-table statistics command to check statistics about BGP-LS routes.
