Configuring Session Aging

Context

After a session is created, if no packet matches the session for a long time, the connection is torn down, and the session is considered unnecessary. To save system resources, the system deletes the session that is not matched for a certain period of time; that is, the session is aged out.

The impact of aging time on forwarding is as follows:

  • If the aging time is too long, a large number of sessions whose corresponding connections have been torn down may exist in the system and consume system resources. In addition, new sessions may not be created, thus affecting the forwarding of other services.
  • If the aging time is too short, some sessions may be aged out before packet transmission is finished, resulting in service interruptions.

Generally, the default session aging time is used. You can also modify the aging time based on the traffic type and number of connections.

Procedure

  1. Enter the system view.

    system-view

  2. Configure the session aging time.

    session { { dns | ftp | http | icmp | tcp | udp | sip | rtsp | pptp | others | sac-cache } | { tcp | udp } user-define port-number } aging-time aging-time

    For the default aging time of sessions of different protocol types, see Default Settings for Session Management. For TCP/UDP packets, the aging time configured with a user-defined port number specified is preferentially used.

  3. (Optional) Enable the session table leak check.

    session leak-check [ auto-recover ] enable

    By default, the session table leak check is disabled.

    After the session table leak check is enabled, if the number of session resources remains full for a long time, the device may restart. Therefore, exercise caution when performing the configurations.

  4. (Optional) Set the maximum rate of new sessions.

    session create-rate-limit limit-value

    By default, the rate of new sessions is not limited.

Follow-up Procedure

  • Check the session aging time on the device.
    display session aging-time
  • Check the result of the session table leak check.
    display session leak-check result
    display ipv6 session leak-check result
