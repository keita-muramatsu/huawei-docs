MAC Address Authentication Trigger Mode and Packet Exchange Process

Passwords of MAC address authentication users can be processed using Password Authentication Protocol (PAP) or Challenge Handshake Authentication Protocol (CHAP).
  • PAP: The access device arranges the MAC address, shared key, and random value in that sequence, hashes them using the Message Digest Algorithm 5 (MD5 algorithm), and encapsulates the hash result into the User-Password attribute.
  • CHAP: The access device arranges the CHAP ID, MAC address, and random value in that sequence, hashes them using the MD5 algorithm, and encapsulates the hash result into the CHAP-Password and CHAP-Challenge attributes.
Figure 1 and Figure 2 show the process of MAC address authentication using PAP and CHAP, respectively. Their implementations are similar. The following example uses a RADIUS server as the authentication server to describe MAC address authentication using PAP.
Figure 1 MAC address authentication process using PAP
  1. The access device receives an ARP, DHCP, DHCPv6, or ND packet from a terminal, which triggers MAC address authentication.
  2. The access device generates a random value, arranges the terminal MAC address, shared key, and random value in sequence, and performs hash processing on them using the MD5 algorithm. It then encapsulates the user name, hash result, and random value into a RADIUS Access-Request packet, and sends the packet to the RADIUS server for MAC address authentication.
  3. Based on the received random value, the RADIUS server arranges the terminal MAC address, shared key, and random value in the local database in sequence, and performs hash processing on them using the MD5 algorithm. If the hash result of the RADIUS server is the same as that carried in the received packet, the RADIUS server sends an Access-Accept packet to the access device, indicating that MAC address authentication of the user is successful. The user is then allowed to access the network.
