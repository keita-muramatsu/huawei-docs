Configuring DPD

Prerequisites

DPD takes effect only for the following IPsec:

  • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
  • Route-based IPsec (involving IPsec profiles)

Context

The DPD mechanism determines whether IPsec traffic is received to minimize the number of packets to be sent for peer status detection, effectively saving CPU resources. Unlike the heartbeat detection mechanism (refer to Configuring Heartbeat Detection), the DPD mechanism does not need to periodically send heartbeat packets. If the local end can receive IPsec traffic from the remote end, it considers the remote end as active. The local end sends DPD packets to detect the status of the remote end only when it does not receive IPsec traffic from the remote end for a certain amount of time.

The local end retransmits DPD request packets to the remote end if it does not receive any DPD response packet from the remote end within the retransmission interval. If the local end still does not receive any DPD response packet within the retransmission interval after the maximum number of retransmissions is reached, the local end considers that the remote end is offline and deletes the IKE SAs and IPsec SAs established with the remote end. When configuring DPD, ensure that the payload sequence in DPD packets on the local end matches that on the remote end. The DPD idle time and DPD packet retransmission interval on the local end do not need to be the same as those on the remote end.

Two DPD types are available:
  • On-demand DPD: If the local end needs to send IPsec packets to the remote end, it sends a DPD request packet to the remote end when it determines that the time since it received the last IPsec packet from the remote end exceeds the DPD idle time.
  • Periodic DPD: If the time since the local end received the last IPsec packet or DPD request packet from the remote end exceeds the DPD idle time, the local end sends a DPD request packet to the remote end.

On-demand DPD and periodic DPD can be configured globally or on an IKE peer. The DPD configuration in the IKE peer view takes precedence over that in the system view. When there is no DPD configuration in the IKE peer view, the DPD configuration in the system view takes effect.

Procedure

  • Configure DPD globally.
    1. Enter the system view.

      system-view

    2. Optional: Configure the version of DPD packets sent by the local end when SM digital envelope authentication is used during IKEv1 negotiation.

      ike dpd version { 1.0 | 1.1 }

      This command takes effect only when SM digital envelope authentication is used during IKEv1 negotiation. Both ends of an IPsec tunnel must send DPD packets of the same version. If not, they cannot identify the DPD packets sent by each other.

      By default, the device does not support this command, that is, SA negotiation through IKEv1 is not supported. To use this command, install the IKEv1 feature package.

      If the dpd version command is configured for an IKE peer, the local end sends DPD packets of the version specified in this command to that peer. If only the ike dpd version command is configured globally, the local end sends DPD packets of the version specified in that command.

      If the peer end is the initiator, the local end sends DPD packets of the same version as those received from the peer end.

    3. Optional: Configure the payload sequence in DPD packets globally.

      ike dpd msg { seq-hash-notify | seq-notify-hash }

      By default, the payload sequence in DPD packets is seq-hash-notify globally.

      The two ends must use the same payload sequence in DPD packets; otherwise, DPD does not take effect.

    4. Set the DPD type globally.

      ike dpd type { on-demand | periodic }

      By default, the global DPD type is not configured, and DPD is disabled.

      When the DPD type is configured, DPD is enabled.

      By default, the device does not support this command (the device does not support SA negotiation through IKEv1). To use this command, you need to load the IKEv1 feature package.

    5. Optional: Set the DPD idle time, DPD packet retransmission interval, and maximum number of DPD packet retransmissions globally.

      ike dpd { idle-time idle-time | retransmit-interval interval | retry-limit times }

      By default, the DPD idle time is 30s, the DPD packet retransmission interval is 15s, and the maximum number of DPD packet retransmissions is 3 globally.

    6. Optional: Enable the function of checking whether the interface receiving DPD packets is the interface establishing an IPsec SA globally.

      ike dpd packet receive if-related enable

      By default, the function of checking whether the interface receiving DPD packets is the interface establishing an IPsec SA is disabled globally.

      This function applies only when IPsec policies have been applied to physical interfaces. When IPsec policies with different names and the same parameters have been applied to multiple interfaces of the device and post-IPsec check has been enabled, the device discards encrypted traffic if the interface that receives encrypted traffic is not the interface that establishes an IPsec SA during an interface switchover. However, the DPD detection result of IKE peers is still normal, causing a failure to trigger IKE renegotiation. As a result, services are interrupted for a long period of time. After this function is enabled, if the interface that receives DPD packets is not the interface that establishes an IPsec SA, the device discards DPD packets, making DPD detection become abnormal. The device then deletes the IPsec SA and triggers IKE renegotiation.

  • Configure DPD on a specific IKE peer.
    1. Enter the system view.

      system-view

    2. Enter the IKE peer view.

      ike peer peer-name

    3. Optional: Configure the version of DPD packets sent by the local end when SM digital envelope authentication is used during IKEv1 negotiation.

      dpd version { 1.0 | 1.1 }

      This command takes effect only when SM digital envelope authentication is used during IKEv1 negotiation. Both ends of an IPsec tunnel must send DPD packets of the same version. If not, they cannot identify the DPD packets sent by each other.

      By default, the device does not support this command, that is, SA negotiation through IKEv1 is not supported. To use this command, install the IKEv1 feature package.

      If the dpd version command is configured for an IKE peer, the local end sends DPD packets of the version specified in this command to that peer. If only the ike dpd version command is configured globally, the local end sends DPD packets of the version specified in that command.

      If the peer end is the initiator, the local end sends DPD packets of the same version as those received from the peer end.

    4. Optional: Configure the payload sequence in DPD packets for the IKE peer.

      dpd msg { seq-hash-notify | seq-notify-hash }

      By default, the payload sequence in DPD packets for an IKE peer is seq-hash-notify.

      The two ends must use the same payload sequence in DPD packets; otherwise, DPD does not take effect.

    5. Optional: Enable the function of automatically learning the payload sequence in DPD packets from the IKE peer.

      dpd msg notify-hash-sequence learning

      By default, the function of automatically learning the payload sequence in DPD packets from an IKE peer is enabled.

      When the local end receives a DPD packet from the peer end, the local end learns the payload sequence in the DPD packet, and sends a DPD packet with the same payload sequence to the peer end.

    6. Set the DPD type on the IKE peer.

      dpd type { on-demand | periodic }

      By default, the DPD type is not set on an IKE peer.

    7. Optional: Set the DPD idle time, DPD packet retransmission interval, and maximum number of DPD packet retransmissions on the IKE peer.

      dpd { idle-time interval | retransmit-interval interval | retry-limit times }

      By default, the DPD idle time is 30s, the DPD packet retransmission interval is 15s, and the maximum number of DPD packet retransmissions is 3 on an IKE peer.

    8. Optional: Enable the function of checking whether the interface that receives DPD packets is the interface that establishes an IPsec SA on the IKE peer.

      dpd packet receive if-related enable

      By default, the function of checking whether the interface that receives DPD packets is the interface that establishes an IPsec SA is disabled on an IKE peer.

      This function applies only when IPsec policies have been applied to physical interfaces. When IPsec policies with different names and the same parameters have been applied to multiple interfaces of the device and post-IPsec check has been enabled, the device discards encrypted traffic if the interface that receives encrypted traffic is not the interface that establishes an IPsec SA during an interface switchover. However, the DPD detection result of IKE peers is still normal, causing a failure to trigger IKE renegotiation. As a result, services are interrupted for a long period of time. After this function is enabled, if the interface that receives DPD packets is not the interface that establishes an IPsec SA, the device discards DPD packets, making DPD detection become abnormal. The device then deletes the IPsec SA and triggers IKE renegotiation.
