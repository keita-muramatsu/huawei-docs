Configuring Heartbeat Interfaces

Prerequisites

Before configuring heartbeat interfaces, you need to plan and connect them. For details, see Heartbeat Link.

Context

On the two devices that form a hot standby group, all configurations (except IP addresses) related to heartbeat interfaces and HRP packets must be consistent. Otherwise, a hot standby relationship may fail to be established.

Procedure

  1. Enter the system view.

    system-view

  2. Configure an IP address for a heartbeat interface.
    1. Enter the interface view.

      interface interface-type interface-number

    2. Configure an IPv4 or IPv6 address.

      ip address ip-address { mask | mask-length }
ipv6 address { ipv6-address prefix-length | ipv6-address/prefix-length }

    3. Return to the system view.

      quit

  3. Specify the heartbeat interface and configure the IP address of the peer heartbeat interface.

    hrp interface { interface-type interface-number | interface-name } remote { ipv4-address | ipv6-address } [ heartbeat-only ]

    It is recommended that you configure multiple heartbeat interfaces as standby interfaces. If a standby interface transmits service traffic, you can disable the interface from transmitting backup packets by specifying heartbeat-only. This reduces bandwidth consumption, ensures transmission of heartbeat packets, and prevents services from being affected by dual active devices.

  4. Configure an authentication key for HRP packets.

    hrp authentication-key key

    For security purposes, the key must contain at least two of the following types: uppercase letters (A to Z), lowercase letters (a to z), digits (0 to 9), and special characters (such as !, @, #, $, and %).

  5. Optional: Configure validity check for HRP packets.

    hrp checksum enable

    This function can be configured to check whether heartbeat packets are tampered with. If heartbeat interfaces are not directly connected, enable this function, and you are advised to keep it enabled.

  6. Optional: Configure encryption for HRP packets.

    hrp encryption enable

    This function encrypts sensitive information contained in heartbeat packets and is enabled by default. You are advised to keep this function enabled.

  7. Optional: Configure an interval at which heartbeat packets and link detection packets are sent.

    hrp timer hello interval

    Set the interval based on the service loads. If the interval is too short, the task for sending heartbeat packets may not be scheduled within five intervals, triggering an unnecessary active/standby switchover. Conversely, if the interval is too long, faults on the peer device cannot be promptly detected. If the CPU usage of the device management plane is high, you are advised to set the interval to a large value.

  8. Optional: Configure a priority in the IP header of a heartbeat packet.

    hrp ip-packet priority priority-number

    A larger value indicates a higher priority. A device preferentially forwards the packets with a higher priority.
