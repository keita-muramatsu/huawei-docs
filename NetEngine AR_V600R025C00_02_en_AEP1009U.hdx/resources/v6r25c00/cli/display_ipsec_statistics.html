display ipsec statistics

Function

The display ipsec statistics command displays IPsec packet statistics.

Format

display ipsec statistics [ policy-name policy-name [ seq-number ] | profile-name profile-name ] [ slot slot-id cpu cpu-id ]

display ipsec statistics tunnel-number

display ipsec statistics service

Parameters

Parameter Description Value
policy-name policy-name

Displays IPsec packet statistics in an IPsec policy with a specified name.

The IPsec policy group name must exist.
seq-number

Displays IPsec packet statistics in an IPsec policy with a specified sequence number.

The IPsec policy number must exist.
profile-name profile-name

Displays IPsec packet statistics in an IPsec profile with a specified name.

The value must be an existing IPsec profile name.
slot slot-id

Displays IPsec packet statistics in a specified slot.

The value varies depending on device models.
cpu cpu-id

Displays IPsec packet statistics of a specified CPU.

The value varies depending on device models.
tunnel-number

Displays the number of IPsec tunnels.

-
service

Displays statistics about advertisement and subscription events exchanged between the IPsec and NHRP modules.

-

Views

All views

Default Level

1: Monitoring level

Usage Guidelines

Usage Scenario

To view statistics about IPsec packets, run the display ipsec statistics command. The command output includes statistics about incoming and outgoing packets protected by IPsec, encrypted and decrypted packets, discarded packets protected by IPsec, and IKE negotiation packets. The command output helps diagnose IPsec faults and maintain IPsec.

Prerequisites

To view IPsec packet statistics in an IPsec policy or profile, run the ipsec policy-statistics enable command to enable IPsec policy-based traffic statistics collection.

Precautions

The display ipsec statistics command output displays the number of bytes only in plain text.

These statistics are included in the statistics about encrypted and decrypted IPsec packets if an IPsec P2MP policy is configured in an SD-WAN EVPN scenario, because packets are encrypted and decrypted by the IPsec module in this scenario.
