nhrp authentication

Function

The nhrp authentication command configures an authentication character string for NHRP negotiation.

The undo nhrp authentication command deletes an authentication character string for NHRP negotiation.

By default, no authentication character string is configured for NHRP negotiation.

Format

nhrp authentication [ hash { sha2-256 | sha2-384 | sha2-512 | md5 | sha1 } ] cipher authenString

undo nhrp authentication

Parameters

Parameter Description Value
hash

Specifies the hash algorithm used to encrypt the authentication string in NHRP packets. By default, the authentication string is not encrypted.

-
sha2-256

Specifies SHA2-256 as the NHRP authentication algorithm.

-
sha2-384

Specifies SHA2-384 as the NHRP authentication algorithm.

-
sha2-512

Specifies SHA2-512 as the NHRP authentication algorithm.

-
md5

Specifies MD5 as the authentication algorithm for NHRP negotiation.

For security purposes, you are advised not to use weak security algorithms provided by this feature.

To ensure security, the SHA2-256, SHA2-384, and SHA2-512 algorithms are recommended.

-
sha1

Specifies SHA1 as the authentication algorithm for NHRP negotiation.

For security purposes, you are advised not to use weak security algorithms provided by this feature.

To ensure security, the SHA2-256, SHA2-384, and SHA2-512 algorithms are recommended.

-
cipher authenString

Specifies the NHRP authentication string.

The value is a string of 1 to 8 case-sensitive characters in cleartext (with question marks and spaces not supported) or a string of 128 characters in ciphertext.

For security purposes, it is recommended that the authentication string contain at least 6 characters, including at least three types of the following: lowercase letters, uppercase letters, digits, and special characters.

Views

Tunnel interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

This command configures the NHRP authentication string on a spoke and the hub. This command enables the hub to reject the illegal registration of a spoke.

Configuration Impact

After this command is executed on a spoke and the hub, the spoke sends an NHRP Registration Request packet to the hub, and the hub decides whether to process this packet based on the NHRP authentication string in the packet. If this NHRP authentication string is different from that configured on the hub, the hub does not process this packet. If the two NHRP authentication strings are the same, the hub processes this packet.

Precautions

If an authentication string is configured on the branch but the hash algorithm for encrypting the authentication string is not configured, the authentication string in NHRP packets is in plaintext. To improve security, you are advised to use a hash algorithm to encrypt the authentication string.

Example

# Set the NHRP authentication string.
<HUAWEI> system-view
[HUAWEI] nhrp enable
[HUAWEI] interface tunnel 0
[HUAWEI-Tunnel0] tunnel-protocol gre p2mp
[HUAWEI-Tunnel0] nhrp enable
[HUAWEI-Tunnel0] nhrp authentication cipher huawei_123
