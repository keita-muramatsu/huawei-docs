srv6-te-policy bfd no-bypass

Function

The srv6-te-policy bfd no-bypass command enables BFD no-bypass for all SRv6 TE Policies.

The srv6-te-policy bfd no-bypass preferred command enables BFD packets of all SRv6 TE Policies not to preferentially use a local protection path.

The undo srv6-te-policy bfd no-bypass command disables BFD no-bypass for all SRv6 TE Policies.

The undo srv6-te-policy bfd no-bypass preferred command disables BFD packets of all SRv6 TE Policies from not preferentially using a local protection path.

By default, the BFD no-bypass function is not enabled for any SRv6 TE Policy.

Format

srv6-te-policy bfd no-bypass [ preferred ]

undo srv6-te-policy bfd no-bypass [ preferred ]

Parameters

Parameter Description Value
preferred

Enables BFD packets of all SRv6 TE Policies not to preferentially use a local protection path.

If this parameter is selected and an SRv6 TE Policy has a backup path, BFD packets on the primary path are not transmitted over a local protection path such as TI-LFA or TE FRR. If the primary path fails, the BFD session goes Down, and traffic is transmitted over the backup path. BFD packets on the backup path can be transmitted over the local protection path to ensure service continuity.

-
no-bypass

Enables BFD no-bypass for all SRv6 TE Policies.

If this parameter is selected, BFD packets of each SRv6 TE Policy do not pass through a local protection path such as a TI-LFA and TE FRR path. If the primary path fails, the BFD session goes Down directly, triggering an SRv6 TE Policy primary/backup switchover.

-

Views

Segment routing IPv6 view

Default Level

2: Configuration level

Usage Guidelines

Run the srv6-te-policy bfd no-bypass command to enable the BFD no-bypass function for all SRv6 TE Policies so that BFD for SRv6 TE Policy packets are not transmitted over local protection paths such as TI-LFA and TE FRR paths.

During BFD for SRv6 TE Policy deployment, if the segment list of the primary candidate path fails and a local protection path (for example, a TI-LFA or TE FRR path) exists, the BFD session remains Up, and data traffic is diverted to the TI-LFA or TE FRR path. However, the performance such as the bandwidth/latency of the TI-LFA or TE FRR path may be unstable, preventing the path from meeting the strict SLA requirements of high-value private line services. To resolve this problem, disable BFD from using the local protection path. If the segment list of the primary candidate path fails, the BFD session status changes to Down, and the candidate path status changes to Down, triggering traffic to be switched to the backup candidate path or another SRv6 TE Policy.

Example

# Enable BFD packets of all SRv6 TE Policies not to preferentially use a local protection path.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] srv6-te-policy bfd no-bypass preferred
# Enable BFD no-bypass for all SRv6 TE Policies.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] srv6-te-policy bfd no-bypass
