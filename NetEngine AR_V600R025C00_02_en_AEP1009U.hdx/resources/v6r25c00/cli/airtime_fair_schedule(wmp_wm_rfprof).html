airtime-fair-schedule

Function

The airtime-fair-schedule command configures airtime scheduling on an AP radio.

The undo airtime-fair-schedule command restores the default configuration of airtime scheduling.

By default, airtime scheduling is enabled adaptively on an AP radio.

Format

airtime-fair-schedule { enable | disable | auto }

undo airtime-fair-schedule

Parameters

Parameter Description Value
enable

Enables airtime scheduling on an AP radio.

-
disable

Disables airtime scheduling on an AP radio.

-
auto

Configures the adaptive mode for airtime scheduling on an AP radio. The device automatically enables or disables this function based on the number of associated APs.

-

Views

RRM profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

On a WLAN, the PHY rates of STAs greatly differ depending on the radio modes supported by the STAs and the radio environment where the STAs reside. If the STAs with lower PHY rates occupy wireless channels for a long period, user experience of the entire WLAN is affected. Airtime scheduling calculates the channel occupation time of STAs transmitting the same service and preferentially schedules resources for the STAs that occupy the wireless channels for a shorter period. This ensures that STAs leverage channel resources in a relatively fair manner.

After airtime scheduling is enabled, the device collects statistics on the channel occupation time used by STAs connected to the same radio for sending packets, creates a mapping table recording the channel occupation time of each STA in accumulated mode, and establishes a sorted link table based on the time in an ascending order. Based on the mapping table, an AP transmits data with the STA that occupies the channel for the shortest time, ensuring that each STA can occupy the wireless channels in a nearly equal way. The data packets of high-speed STAs are transmitted quickly, which is not affected by the data transmission time of low-speed STAs. This improves the overall user experience.

After WMM is enabled on the device and STAs, user packets are scheduled based on different service types including VI, VO, BE, and BK. For example, voice packets are only scheduled together with other voice packets, and video packets are only scheduled together with other video packets.

Precautions

If the packet types of multiple STAs are different, airtime scheduling is not performed. For example, two STAs need to transmit voice and video packets, respectively. In this case, airtime scheduling is not performed for the two STAs.

When the command is executed, the system displays the message "Warning: This action may cause service interruption. Continue?[Y/N]", asking you whether you want to continue.

• AirEngine X776

• AirEngine X576

The following models support airtime scheduling (enabled adaptively by default from V200R023C10, which supports command-based configuration; enabled by default in V200R023C00 and earlier versions, which does not support command-based configuration):

• AirEngine X761

• AirEngine X762

• AirEngine X771

• AirEngine X56X

When the AC connects to an AP running a version earlier than V200R023C10 and auto is configured on the AC, the parameter disable is delivered to the AP.

Example

# Enable airtime scheduling in the RRM profile default.
<HUAWEI> system-view
[HUAWEI] wlan
[HUAWEI-wlan] rrm-profile name default
[HUAWEI-wlan-rrm-prof-default] airtime-fair-schedule enable
