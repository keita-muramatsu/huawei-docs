prf

Function

The prf command configures the pseudo-random function (PRF) algorithm used in IKEv2 negotiation.

The undo prf command restores the default configuration.

By default, HMAC-SHA2-256 is used as the PRF algorithm in IKEv2 negotiation.

Format

prf { aes-xcbc-128 | hmac-md5 | hmac-sha1 | hmac-sha2-256 | hmac-sha2-384 | hmac-sha2-512 } *

undo prf

Parameters

Parameter Description Value
aes-xcbc-128

Indicates the AES-XCBC-128 authentication algorithm.

This algorithm applies only to IKEv2 negotiation.

-
hmac-md5

Indicates the HMAC-MD5 authentication algorithm.

-
hmac-sha1

Indicates the HMAC-SHA1 authentication algorithm.

-
hmac-sha2-256

Indicates the HMAC-SHA2-256 authentication algorithm.

-
hmac-sha2-384

Indicates the HMAC-SHA2-384 authentication algorithm.

-
hmac-sha2-512

Indicates the HMAC-SHA2-512 authentication algorithm.

-

Views

IKE proposal view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The PRF algorithm is required in IKEv2 negotiation. The PRF algorithm is listed as follows from the highest security level to the lowest security level: hmac-sha2-512 > hmac-sha2-384 > hmac-sha2-256 > aes-xcbc-128 > hmac-sha1 > hmac-md5. If multiple PRF algorithms are configured, the device selects the algorithm in the following sequence: aes-xcbc-128 > hmac-sha2-512 > hmac-sha2-384 > hmac-sha2-256 > hmac-sha1 > hmac-md5.

If you run the prf command multiple times, only the latest configuration takes effect.

Precautions

The hmac-md5, hmac-sha1, and aes-xcbc-128 algorithms are not recommended because they are insecure.

Parameters hmac-md5, hmac-sha1, and aes-xcbc-128 in this command can be used only after the weak security algorithm/protocol feature package (WEAKEA) has been installed using the install feature-software WEAKEA command.

Example

# Set hmac-sha2-256 as the PRF algorithm. 
<HUAWEI> system-view
[HUAWEI] ike proposal 10
[HUAWEI-ike-proposal-10] prf hmac-sha2-256
