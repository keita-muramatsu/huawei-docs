if-match extcommunity-list priority-color

Function

The if-match extcommunity-list priority-color command configures a filtering rule that is based on a priority-color extended community filter.

The undo if-match extcommunity-list priority-color command cancels this configuration.

By default, no filtering rule based on a priority-color extended community filter is configured.

Format

if-match extcommunity-list priority-color priority-color-name [ not-match-priority ]

undo if-match extcommunity-list priority-color priority-color-name [ not-match-priority ]

Parameters

Parameter Description Value
priority-color-name

Specifies the name of a priority-color extended community filter.

The value is a string of 1 to 51 case-sensitive characters. It cannot be comprised of only digits. If spaces are used, the string must start and end with double quotation marks (").
not-match-priority

Ignores the priority values when the priority-color extended community attribute is used to filter routes.

-

Views

Route-policy view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

To configure a filtering rule that is based on a priority-color extended community filter for a route-policy node to filter routes, run the if-match extcommunity-list priority-color command.

Before using this command, note the following:

  • Create a route-policy using the route-policy command.
  • A route-policy may consist of multiple nodes, and the relationship among these nodes is OR. The device matches routes against the nodes in a route-policy in order of node indexes. If a route matches one of the nodes, the route is considered to match this route-policy and will not be matched against the next node.
  • Each node consists of a set of if-match and apply clauses. The if-match clauses define filtering rules that are based on route attributes. The relationship among if-match clauses that are based on different route attributes is AND in the same route-policy node. Specifically, a route is considered to match a node only when it matches all the if-match clauses of the node. The relationship among if-match clauses that are based on the same route attribute is OR in the same route-policy node. Specifically, a route is matched against the if-match clauses in order; if the route matches an if-match clause, the route is considered to match the route-policy and will not be matched against the rest if-match clauses. The apply clauses specify actions. If a route matches a node, route attributes will be set for the route based on the defined apply clauses.
  • If you want the device to match routes only against the color values and ignore the priority values in a filtering rule, you can specify the not-match-priority parameter when running the if-match extcommunity-list priority-color command. If the not-match-priority parameter is not specified, both the priority and color values are used for matching after the command is run.

    The if-match extcommunity-list priority-color command is applicable only to EVPN routes and must be used together with the ip extcommunity-list priority-color command. For example:
  • If the if-match extcommunity-list priority-color basic aaa command is run but the priority-color extended community filter named aaa is not configured, all routes will be permitted.
  • If both the if-match extcommunity-list priority-color basic aaa and ip extcommunity-list priority-color basic aaa permit 1:100 commands are run, BGP EVPN routes with the priority-color extended community attribute value being 1:100 will be permitted.

Prerequisites

A priority-color extended community filter has been configured using the ip extcommunity-list priority-color command.

Implementation Procedure

After the if-match extcommunity-list priority-color command is run, the routes that match the filtering rule are permitted, whereas the routes that do not match the filtering rule are denied.

Precautions

When you run the if-match extcommunity-list priority-color command to filter routes based on the priority-color extended community attribute and you want the device to match routes only against color values and ignore priority values, specify the not-match-priority parameter in the command. If this parameter is not specified, both the priority and color values are used for matching after the command is run.

The not-match-priority parameter takes effect only when the priority-color extended community filter is a basic one (rather than an advanced one).

Example

# Define a filtering rule to match routes against a specified priority-color extended community filter.
<HUAWEI> system-view
[HUAWEI] ip extcommunity-list priority-color basic aaa permit 1:100
[HUAWEI] route-policy rp1 permit node 1
[HUAWEI-route-policy] if-match extcommunity-list priority-color aaa
