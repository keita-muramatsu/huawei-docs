authentication-mode (BFD session view)

Function

The authentication-mode command configures BFD session authentication.

The undo authentication-mode command disables BFD session authentication.

By default, authentication is not configured for a BFD session.

Format

authentication-mode met-sha1 key-id key-id cipher cipher-text nego-packet [ enhanced ] [ timeout-interval interval-value ]

undo authentication-mode

Parameters

Parameter Description Value
key-id key-id

Specifies an authentication key ID.

The value is an integer ranging from 1 to 255.
cipher cipher-text

Specifies an authentication key.

The value is a string of case-sensitive characters, which can contain uppercase letters A to Z, lowercase letters a to z, digits 0 to 9, periods (.), hyphens (-), or underscores (_). It cannot contain question marks (?) or spaces. However, if the password is enclosed in double quotation marks (" "), spaces are allowed.

  • The value is a string of 1 to 20 characters for plaintext authentication keys.
  • The value is a string of 20 to 148 characters for ciphertext authentication keys. The password is recommended to contain at least eight characters and at least two types of the following characters: uppercase letters, lowercase letters, digits, and special characters.
nego-packet

Specifies authentication for BFD session negotiation packets.

-
enhanced

Configures the enhanced authentication function.

-
timeout-interval interval-value

Specifies the timeout period of negotiation packet authentication.

The value is an integer ranging from 1 to 10000, in seconds.
met-sha1

Specifies the SHA1 algorithm.

-

Views

BFD session view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

If a network requires high security, you can configure BFD session authentication information to improve network security. BFD session authentication verifies BFD packets when a BFD session is created, improving network security. When a BFD session is set up, the devices at both ends of the BFD session are in the DOWN state initially. After a device receives a BFD packet with the State field set to DOWN from the peer, the device does not switch the BFD session state to INIT. Instead, it checks whether the authentication information in the packet is the same as the local authentication information. If they are the same, the device sends a BFD packet with the State field set to INIT to the peer. After receiving the packet with the State field set to INIT, the peer device compares the authentication information in the packet with the local authentication information. If the authentication information is the same, it changes the local BFD session state to UP.

In enhanced authentication mode, a BFD session in the Up state needs to be authenticated when it receives AdminDown, Down, or P/F packets.

This command applies only to multicast BFD scenarios.

Prerequisites

A BFD session has been set up.

Precautions

When you run this command to configure BFD session authentication, the BFD session is renegotiated. BFD session negotiation can succeed only when the BFD session authentication information on both ends is consistent.

To ensure high security, do not use the SHA-1 algorithm.

Example

# Configure enhanced authentication information for a BFD session.
<HUAWEI> system-view
[HUAWEI] bfd
[HUAWEI-bfd] quit
[HUAWEI] bfd test bind peer-ip default-ip interface 10GE0/0/0
[HUAWEI-bfd-session-test] min-rx-interval 100
[HUAWEI-bfd-session-test] authentication-mode met-sha1 key-id 5 cipher aaa nego-packet enhanced
# Configure BFD session authentication information.
<HUAWEI> system-view
[HUAWEI] bfd
[HUAWEI-bfd] quit
[HUAWEI] bfd test bind peer-ip default-ip interface 10GE0/0/0
[HUAWEI-bfd-session-test] authentication-mode met-sha1 key-id 5 cipher aaa nego-packet timeout-interval 5
