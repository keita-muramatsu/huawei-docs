qos pre-classify

Function

The qos pre-classify command pre-extracts original packet information.

The undo qos pre-classify command disables the device from pre-extracting original packet information.

By default, the system does not pre-extract original packet information.

Format

qos pre-classify

undo qos pre-classify

Parameters

None

Views

10GE sub-interface view, 10GE interface view, 40GE sub-interface view, 40GE interface view, Dialer interface view, GE sub-interface view, GE interface view, MP-group interface view, Tunnel interface view, Virtual serial interface view, Interface group view, Ethernet interface view, Ethernet sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The pre-extraction function applies to tunnel packets and NAT protocols.

For tunnel packets such as GRE packets, QoS parameters such as the packet header and protocol of the original packets cannot be obtained. Although the protocol requires that the DSCP field in the tunnel header use the DSCP of the original packet, some QoS functions require 5-tuple information (source IP address, destination IP address, protocol type, source port number, and destination port number) to work properly. 5-tuple information can be pre-extracted to implement refined QoS management of tunnel packets.

After NAT is configured on a device, the device translates the private IP address of an IP packet into a public IP address. Therefore, the outbound interface on the device cannot identify the pre-NAT private IP address. As a result, the device cannot classify packets based on the private IP address. To resolve this problem, configure the pre-extraction function so that the private IP address information is transmitted to the outbound interface. In this way, packets can be classified based on private IP addresses, providing differentiated services for the packets.

Follow-up Procedure

After the original packet information pre-extraction function is configured, run the if-match acl command in the QoS traffic classifier view to create an ACL-based matching rule.

Precautions

This command is supported only on Layer 3 interfaces.

Example

# Configure the device to pre-extract original packet information in the tunnel view.
<HUAWEI> system-view
[HUAWEI] interface Tunnel 100
[HUAWEI-Tunnel100] qos pre-classify
