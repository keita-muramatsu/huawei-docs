bgp path-attribute

Function

The bgp path-attribute command configures the processing mode of the specified incorrect path attribute.

The undo bgp path-attribute command restores the default configuration.

By default, path attribute messages are processed according to the standard protocol.

If the value of the Originator_ID attribute is 0, the route corresponding to the attribute is withdrawn. If the value of the Originator_ID attribute in the Attr_Set attribute is 0, the route corresponding to the attribute is withdrawn. If the value of the Aggregator attribute is 0, the attribute is discarded. If the value of the Aggregator attribute in the Attr_Set attribute is 0, the attribute is discarded. If the value of the AS4_Aggregator attribute is 0, the attribute is discarded. If the value of the AS4_Aggregator attribute in the Attr_Set attribute is 0, the attribute is discarded.

If the length of the Community, Ext-community, IPv6 ext-community, Large-community, Wide-community, or Cluster_List attribute is 0, the route corresponding to the attribute is withdrawn. If the length of the Community, Ext-community, IPv6 ext-community, Large-community, Wide-community, or Cluster_List sub-attribute in the Attr_Set attribute is 0, the route corresponding to the attribute is withdrawn.

If the transposition field of the Prefix-SID attribute does not comply with the protocol, the route corresponding to this attribute needs to be set to invalid.

Format

bgp path-attribute { originator-id | attr-set | aggregator | as4-aggregator } accept-zero-value

bgp path-attribute { community | ext-community | ipv6-ext-community | large-community | attr-set | wide-community | cluster-list } accept-zero-length

bgp path-attribute prefix-sid accept-non-standard transposition-field

undo bgp path-attribute { originator-id | attr-set | aggregator | as4-aggregator } accept-zero-value

undo bgp path-attribute { community | ext-community | ipv6-ext-community | large-community | attr-set | wide-community | cluster-list } accept-zero-length

undo bgp path-attribute prefix-sid accept-non-standard transposition-field

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

If the local device receives an Update message with an incorrect format (containing a path attribute with a length of 0 or a value of 0), BGP session flapping may occur. To resolve this problem, run the bgp path-attribute command to configure special processing for the specified incorrect BGP path attribute. The options are as follows:

  • accept-zero-value: indicates that the path attribute with a zero value is accepted.
  • accept-zero-length: indicates that the zero-length path attribute is accepted.
  • accept-non-standard: indicates that the path attributes with non-standard values are accepted.

After the bgp path-attribute attr-set accept-zero-value command is run, if the Originator_ID value in the Attr_Set attribute is 0, the route corresponding to the attribute can be accepted. If the Aggregator or AS4-Aggregator value in the Attr_Set attribute is 0, the route corresponding to the attribute can be accepted.

After the bgp path-attribute attr-set accept-zero-length command is run, if the length of the Community, Ext-community, IPv6 ext-community, Large-community, Wide-community, or Cluster_List attribute in the Attr_Set attribute is 0, the route corresponding to the attribute can be accepted.

After the bgp path-attribute prefix-sid accept-non-standard transposition-field command is run, if the transposition field in the Prefix-SID attribute does not comply with the protocol, the route becomes valid.

Precautions

This function takes effect immediately for the routes received after this command is executed. However, for the routes received before this command is run, the function does not take effect immediately unless you run the refresh bgp command.

The bgp path-attribute wide-community accept-zero-length command does not take effect for the RPD address family. After an RPD route with the Wide-Community attribute of 0 is received, the route is still withdrawn.

After bgp path-attribute prefix-sid accept-non-standard transposition is configured, the function takes effect immediately for all the routes that carry the Prefix-SID attribute whose transposition field does not comply with the protocol, and the routes become valid.

Example

# Configure the device to accept the community path attribute with the length of 0.
<HUAWEI> system-view
[HUAWEI] bgp path-attribute community accept-zero-length
# Configure the Originator_ID path attribute with a value of 0 to be accepted.
<HUAWEI> system-view
[HUAWEI] bgp path-attribute originator-id accept-zero-value
# Configure the device to accept the Prefix-SID path attribute with a non-standard transposition field.
<HUAWEI> system-view
[HUAWEI] bgp path-attribute prefix-sid accept-non-standard transposition-field
