pre-shared-key

Function

The pre-shared-key command configures the pre-shared key used by IKE peers to perform pre-shared key authentication.

The undo pre-shared-key command deletes the pre-shared key used by IKE peers to perform pre-shared key authentication.

By default, the pre-shared key used by IKE peers to perform pre-shared key authentication is not configured.

Format

pre-shared-key [ key ]

undo pre-shared-key

Parameters

Parameter Description Value
key

Specifies the pre-shared key used by IKE users when IKE peers use pre-shared key authentication during IKE negotiation.

If this parameter is not specified in this command, a PSK needs to be entered in interactive mode.

The value is a string of case-sensitive characters. If the value is in plaintext, it can contain 1 to 128 characters. If the value is in ciphertext, it can contain 128 to 268 characters. For upgrade compatibility with V5R5 and V6R7 devices, the ciphertext length ranges from 48 to 188 characters.

  • The string cannot contain question marks (?). A question mark is identified as a help character.
  • If the string is enclosed in double quotation marks ("") and the string contains spaces, the double quotation marks are not considered as part of the key. For example, if the entered string is "huawei 123", the actual key is huawei 123.
  • For security purposes, it is recommended that the pre-shared key contain at least three types of lowercase letters, uppercase letters, digits, and special characters and contain at least 6 characters.

Views

IKE peer view, IKE user view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

During IKE negotiation, IPsec can use pre-shared key authentication to verify identities of communication parties. After pre-shared key authentication is configured, the initiator encrypts data using the pre-shared key before transmitting the data, and the receiver decrypts the data using the same pre-shared key. If the receiver succeeds in data decryption, the initiator passes the identity verification.

Prerequisites

Pre-shared key authentication has been specified in an IKE proposal.

Precautions

  • After the IKE user table is referenced by an IKE peer, the pre-shared key configured in the IKE user table takes precedence over that configured in the IKE peer view.
  • Both ends of IKE negotiation must use the same pre-shared key.

Example

# Configure the pre-shared key as Test!123 for IKE users. 
<HUAWEI> system-view
[HUAWEI] ike user-table 10
[HUAWEI-ike-user-table-10] user user1
[HUAWEI-ike-user-table-10-user1] pre-shared-key Test!123
[HUAWEI-ike-user-table-10-user1] quit
[HUAWEI] ike user-table 11
[HUAWEI-ike-user-table-11] user user1
[HUAWEI-ike-user-table-11-user1] pre-shared-key

 Please enter the password again:
[HUAWEI-ike-user-table-11-user1]
# Configure the pre-shared key used by IKE peers to perform pre-shared key authentication as Test!123. 
<HUAWEI> system-view
[HUAWEI] ike peer peer1
[HUAWEI-ike-peer-peer1] pre-shared-key Test!123
[HUAWEI-ike-peer-peer1] quit
[HUAWEI] ike peer peer2
[HUAWEI-ike-peer-peer2] pre-shared-key
 Please enter the password:
 Please enter the password again:
[HUAWEI-ike-peer-peer2]
