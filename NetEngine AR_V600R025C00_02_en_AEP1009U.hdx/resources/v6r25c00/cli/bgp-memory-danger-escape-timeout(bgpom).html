bgp memory-usage danger-threshold escape timeout

Function

The bgp memory-usage danger-threshold escape timeout command configures the device to tear down BGP peer relationships if the device memory remains in the danger state and the memory usage of the BGP component ranks in the top 3 for a specified period, and to reset the process if the device memory still remains in the danger state and the memory usage of the BGP component still ranks in the top 3 after the peer relationships are torn down.

The undo bgp memory-usage danger-threshold escape timeout command deletes the configuration of delaying to tear down peer relationships and restores the default configuration.

The bgp memory-usage danger-threshold escape disable command configures BGP not to attempt to escape from the danger state when the device memory is in the danger state.

The undo bgp memory-usage danger-threshold escape disable command deletes the configuration of not escaping from the danger state and restores the default configuration.

By default, after a device is in the memory danger state for 24 hours, BGP starts to disconnect peers. If the device is still in the memory danger state after the disconnection, BGP resets the current process.

Format

bgp memory-usage danger-threshold escape timeout time [ minute ]

bgp memory-usage danger-threshold escape disable

undo bgp memory-usage danger-threshold escape timeout time [ minute ]

undo bgp memory-usage danger-threshold escape disable

Parameters

Parameter Description Value
time

Specifies the timeout duration, in hours.

The value is an integer that ranges from 0 to 72, in hours. The default value is 24.
minute

Specifies the timeout duration, in minutes.

The value is an integer ranging from 1 to 59, in minutes.
disable

Disables escape from the memory danger state.

-

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

If the device memory still remains in the danger state for a long time after BGP is enabled to discard newly received routes when the device memory is in the danger state, memory resources may be exhausted. To prevent this problem, you can run the bgp memory-usage danger-threshold escape timeout command to configure the device to tear down BGP peer relationships if the device memory remains in the danger state and the memory usage of the BGP component ranks in the top 3 for a specified period, and to reset the process if the device memory still remains in the danger state and the memory usage of the BGP component still ranks in the top 3 after the peer relationships are torn down.

Prerequisites

The device has been enabled to discard new routes when the device memory is in the danger state using the bgp memory-usage danger-threshold command.

Precautions

After the bgp memory-usage danger-threshold escape timeout command is run, if the device has been enabled to discard newly received routes when the device memory is in the danger state and the device memory remains in the danger state throughout the configured period, BGP disconnects peers in batches. If the device memory is still in the danger state after the disconnection is complete, the BGP process is reset in 10 minutes. This may affect services such as IGP and route management and cause service interruptions. Therefore, exercise caution when running this command.

During the disconnection period, peers do not enter the GR state, and disconnected peer relationships are not re-established.

Example

# Enable BGP to escape from the danger state when the device memory remains in the danger state for a long time and set the escape timeout period to 24 hours and 30 minutes.
<HUAWEI> system-view
[HUAWEI] bgp memory-usage danger-threshold discard new-route
Warning: When the memory usage of the device is in the dangerous state and the memory usage of the BGP component ranks top 3, BGP will discard new routes. Continue? [Y/N]:Y
[HUAWEI] bgp memory-usage danger-threshold escape timeout 24 30
