ipsec policy (Interface view)

Function

The ipsec policy command binds an IPsec policy group of the current system to an interface of the current system.

The undo ipsec policy command unbinds an IPsec policy group from an interface.

By default, no IPsec policy group is bound to an interface. In IPsec hot standby scenarios, hot standby is enabled by default for interfaces that IPsec policies apply to.

Format

ipsec policy policy-name

undo ipsec policy

Parameters

Parameter Description Value
policy policy-name

Specifies the name of an IPsec policy group bound to an interface.

The value must be the name of an existing IPsec policy group on the device.

Views

10GE sub-interface view, 10GE interface view, Cellular interface view, Cellular channel interface view, Dialer interface view, Eth-Trunk sub-interface view, Eth-Trunk interface view, GE sub-interface view, GE interface view, Tunnel interface view, VLANIF interface view, Ethernet interface view, Ethernet sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

To protect data flows on an interface, you need to apply an IPsec policy group to the interface. In addition to physical interfaces such as serial interfaces and Ethernet interfaces, IPsec policy groups can also be applied to virtual interfaces such as tunnel interfaces. In this way, the IPsec policy group can be applied based on the actual networking requirements. After an IPsec policy group is unbound from an interface, the interface no longer provides the IPsec protection function.

After an IPsec policy group is applied to an interface, all IPsec policies in the IPsec policy group are applied to the interface. In this way, different IPsec policies can be used to protect different data flows.

When data is transmitted over an interface, the base station searches for IPsec policies in the IPsec policy group in ascending order of sequence numbers. If a data flow matches an ACL referenced by an IPsec policy, the base station processes the data flow using this IPsec policy. If no match is found, the base station searches for the next IPsec policy. If no match is found, the base station directly transmits the data flow without IPsec protection.

Precautions

  • Only one IPsec policy group can be applied to an interface, and an IPsec policy group can be applied to only one interface. To apply another IPsec policy group to an interface, cancel the IPsec policy group applied to the interface and then apply the other IPsec policy group to the interface.
  • If an IPsec policy group contains template IPsec policies and ISAKMP IPsec policies and an ISAKMP IPsec policy needs to be matched against, ensure that the sequence number of the ISAKMP IPsec policy is smaller than that of a template IPsec policy.
  • If multiple IPsec policies in an IPsec policy group are bound to different IKE peers, the peer addresses specified for the IKE peers must be different. Otherwise, IKE negotiation of some IPsec policies fails.
  • If multiple IPsec policies in an IPsec policy group are bound to the same IKE peer, the same tunnel local address must be configured for these policies. Otherwise, IKE negotiation of some IPsec policies fails.

Example

# Apply the IPsec policy group policy1 to interface 10GE 0/0/2. 
<HUAWEI> system-view
[HUAWEI] acl 3000
[HUAWEI-acl4-advance-3000] rule 5 permit ip source 1.1.1.1 32 destination 2.2.2.2 32
[HUAWEI-acl4-advance-3000] quit
[HUAWEI] ike peer peer1
[HUAWEI-ike-peer-peer1] remote-address 1.2.3.4
[HUAWEI-ike-peer-peer1] quit
[HUAWEI] ipsec proposal 1
[HUAWEI-ipsec-proposal-1] quit
[HUAWEI] ipsec policy policy1 1 isakmp
[HUAWEI-ipsec-policy-isakmp-policy1-1] security acl 3000
[HUAWEI-ipsec-policy-isakmp-policy1-1] ike-peer peer1
[HUAWEI-ipsec-policy-isakmp-policy1-1] proposal 1
[HUAWEI-ipsec-policy-isakmp-policy1-1] quit
[HUAWEI] interface 10GE 0/0/2
[HUAWEI-10GE0/0/2] ipsec policy policy1
