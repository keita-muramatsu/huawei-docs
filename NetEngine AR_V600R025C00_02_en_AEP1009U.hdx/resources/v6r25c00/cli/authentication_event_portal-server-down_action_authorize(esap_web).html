authentication event portal-server-down action authorize

Function

The authentication event portal-server-down action authorize command configures network access rights for users when the Portal server is Down.

The undo authentication event portal-server-down action authorize command deletes the network access rights granted to users when the Portal server is Down.

By default, no network access rights are configured for users when the Portal server is Down.

Format

authentication event portal-server-down action authorize service-scheme name

undo authentication event portal-server-down action authorize

Parameters

Parameter Description Value
service-scheme name

Specifies the name of a service scheme.

The value is a string of 1 to 32 case-sensitive characters. It cannot contain spaces. The service scheme must exist.

Views

Portal access profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

If the Portal server is down, users cannot be authenticated and do not have network access rights. Before being successfully authenticated, some users may need certain basic network access rights to download client software and update the antivirus database. In this case, you can configure network access rights for users when the Portal server is Down so that the users can access specified network resources.

Prerequisites

Run the service-scheme command in the AAA view to create a service scheme view.

Precautions

  • This function takes effect only for users who go online after the configuration is successful.
  • To make this function take effect, the server must support heartbeat detection, and the server-detect command must be run on the access device to enable the server detection function.
  • When the Portal server is Down, the redirect ACL function is not supported. For details, see the redirect-acl command.
  • When both network access rights assigned when the Portal server is Down and authorization upon user authentication failures are configured, if a user fails to be authenticated, a Portal server Down message is triggered, and the user obtains the network access rights assigned when the Portal server is Down. If no Portal server Down message is triggered, the user obtains the network access rights assigned when the authentication fails.

Example

# In the Portal access profile p1, configure the device to assign network access rights to users based on the service scheme s1 when the Portal server is Down.
<HUAWEI> system-view
[HUAWEI] aaa
[HUAWEI-aaa] service-scheme s1
[HUAWEI-aaa] quit
[HUAWEI] portal-access-profile name p1
[HUAWEI-portal-access-profile-p1] authentication event portal-server-down action authorize service-scheme s1
