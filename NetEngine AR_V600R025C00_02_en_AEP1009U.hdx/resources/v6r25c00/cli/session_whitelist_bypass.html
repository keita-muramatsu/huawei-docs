session whitelist bypass

Function

The session whitelist bypass command configures a whitelist. When a service is run, no session table is created for the traffic that matches the whitelist.

The undo session whitelist bypass command cancels the whitelist configurations.

By default, no whitelist is specified, indicating that session tables are created for all traffic based on the configuration.

Format

session whitelist acl { acl-number | acl-name } bypass { { spr | sac | sec-policy | tcpfpm } * | all }

undo session whitelist acl { acl-number | acl-name } bypass { { spr | sac | sec-policy | tcpfpm } * | all }

Parameters

Parameter Description Value
spr

Indicates that SPR is not performed on the traffic matching the ACL.

-
sac

Indicates that application identification is not performed on the traffic matching the ACL.

-
sec-policy

Indicates that the security policy is not performed for the traffic matching the ACL.

-
tcpfpm

Indicates that TCP FPM is not performed on the traffic that matches the ACL.

-
all

Indicates that SPR, application identification, security policy, and TCP FPM are not performed on the traffic that matches the ACL.

-
acl acl-name

Specifies a named ACL.

The value is a string of 1 to 32 case-sensitive characters. It cannot contain spaces and starts with a letter (a to z or A to Z).
acl acl-number

Specifies the number of the ACL.

The value is an integer that ranges from 2000 to 2999 or 3000 to 3999 for an IPv4 ACL.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

If the session whitelist bypass command is not configured, a session table is created based on the configuration for service processing. After the configuration, no session table is created for the traffic that matches the policy.

A session table can be created for traffic only when application identification, NAT, smart policy routing, SaaS link selection, security policies, or TCP FPM is enabled or application traffic aggregation is enabled for a link. A session table is created only when the intelligent policy routing mode is load balancing or the path selection mode is symmetric.

Prerequisites

Create an ACL and configure rules.

Precautions

After the session whitelist bypass spr or session whitelist bypass all command is run, no session table is created for the traffic that matches the smart policy routing (SPR) rule, but packets are still forwarded according to the SPR result.

Example

# Configure the session bypass whitelist.
<HUAWEI> system-view
[HUAWEI] acl 3000
[HUAWEI-acl4-advance-3000] rule 5 permit ip source 1.1.1.1 255.255.255.255
[HUAWEI-acl4-advance-3000] quit
[HUAWEI] session whitelist acl 3000 bypass all
