dot1x no-response authorize authen-server-down

Function

The dot1x no-response authorize authen-server-down command enables the function of not responding to the EAPoL-Start packets sent by clients when the AAA server is down.

The undo dot1x no-response authorize authen-server-down command disables the function.

By default, the device does not respond to the EAPoL-Start packets sent by the client when the AAA server is Down.

Format

dot1x no-response authorize authen-server-down

undo dot1x no-response authorize authen-server-down

Parameters

None

Views

802.1X access profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

A user uses a Cisco AnyConnect client for EAP-FAST authentication. The client sends an EAPoL-Start packet to the device. After receiving the packet, the device responds to the packet. When the AAA server is down, the client enters the abnormal state after receiving the response packet and cannot access the network. To prevent the client from being abnormal when the AAA server is down, you can run this command to disable the device from responding to EAPoL-Start packets from the client so that the client can obtain access rights when the AAA server is down.

Precautions

This function takes effect only for users who go online after this function is configured.

This function is supported only for wired users.

This command takes effect for ARP, ND, DHCP, DHCPv6, and any Layer 2 packets.

For new users who do not have entries on the device, you need to run the access-domain domain-name [ dot1x ] force command in the authentication profile view to configure a forcible domain for the users so that this function takes effect.

This command takes effect only after you run the authentication event authen-server-down action authorize command in the authentication profile view to configure the network access rights available to users when the authentication server is down.

You are advised to run both this command and the authentication event authen-server-up action re-authen command so that the authentication server can re-authenticate users in bypass state in time after the authentication server goes up. This meets normal network access requirements of the users.

After this function is configured, MAC address migration cannot be triggered through EAPoL-Start packets.

Example

# Enable the function of not responding to the EAPoL-Start packets sent by clients when the AAA server is down.
<HUAWEI> system-view
[HUAWEI] dot1x-access-profile name d1
[HUAWEI-dot1x-access-profile-d1] dot1x no-response authorize authen-server-down
