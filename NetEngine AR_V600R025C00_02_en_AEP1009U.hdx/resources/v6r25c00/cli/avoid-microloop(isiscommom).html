avoid-microloop frr-protected rib-update-delay

Function

The avoid-microloop frr-protected rib-update-delay command configures a delay after which IS-IS delivers routes.

The undo avoid-microloop frr-protected rib-update-delay command restores the default delay.

By default, IS-IS delays route delivery for 100 ms.

Format

avoid-microloop frr-protected rib-update-delay delay-interval

undo avoid-microloop frr-protected rib-update-delay

Parameters

Parameter Description Value
delay-interval

Specifies a delay after which IS-IS delivers routes.

The value is an integer ranging from 100 to 5000, in ms.

Views

IS-IS view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

After IS-IS TI-LFA FRR is enabled, if the primary link fails, traffic is switched to the backup link. When routes converge, traffic is switched from the backup link to the new primary link. During the process of switching traffic to the new primary link, loops may occur on the network and last for a short period of time. To prevent this problem, IS-IS automatically enables the microloop avoidance function. This function prevents loops by delaying switching to the new primary next hop. Using the avoid-microloop frr-protected rib-update-delay command, you can set the delay in delivering IS-IS routes. That is, if the primary link fails, route convergence is performed after the specified delay, preventing short-time loops.

Prerequisites

You have created an IS-IS process and entered the IS-IS view using the isis command.

Example

# Configure IS-IS to delay route delivery for 1000 ms.
<HUAWEI> system-view
[HUAWEI] isis 1
[HUAWEI-isis-1] avoid-microloop frr-protected rib-update-delay 1000
