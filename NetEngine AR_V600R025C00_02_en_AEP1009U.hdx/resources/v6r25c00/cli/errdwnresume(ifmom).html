error-down auto-recovery

Function

The error-down auto-recovery command enables an interface in the error-down state to go up automatically and sets the auto-recovery delay.

The undo error-down auto-recovery command disables an interface in the error-down state from going up automatically.

By default:

  1. You can run the display current configuration | include error-down auto-recovery command to check whether interfaces in the error-down state can automatically recover to the up state during device startup with factory settings.
  2. When a device loads a configuration file during startup, if the configuration file does not contain the error-down auto-recovery configuration, the function to automatically recover interfaces in the error-down state to the up state is not enabled.

Format

error-down auto-recovery cause error-down-type interval interval-value

undo error-down auto-recovery cause error-down-type

Parameters

Parameter Description Value
interval interval-value

Specifies the auto recovery delay.

The value is an integer ranging from 5 to 86400, in seconds.
cause error-down-type

Specifies the cause of the error-down event.

The value is a string. You can enter a question mark (?) and select a value from the displayed value range.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

On a network running the Spanning Tree Protocol (STP), after BPDU protection is configured on an edge port, if attackers send pseudo BPDUs to attack a switching device, the switching device automatically brings the edge port down immediately after the edge port receives BPDUs. As a result, all services on the edge port are interrupted.

By default, an interface in the down state can communicate with other interfaces only after the administrator manually brings it up. To configure an interface to restore to the up state automatically, run this command to enable the function of automatically restoring the interface status to up. This command can also set an auto-recovery delay. After the delay time elapses, the interface goes up automatically.

After an interface restores to the up state, if it receives BPDUs again or its link is considered unavailable within a specific period of time, the interface goes down again.

Configuration Impact

After the error-down auto-recovery command is run, the port goes from Down to Up after the delay expires.

Precautions

There is no default value for the recovery time. Therefore, you must specify a delay when configuring this command.

If you run the error-down auto-recovery command to modify the auto-recovery delay, the modification will not take effect on the interface that has been in the error-down state due to a specific cause. The modification takes effect only on the interface that has gone up from the error-down state.

An interface enters the error-down state after being shut down due to an error.

The precision of the auto-recovery delay set using the error-down auto-recovery command is 2s.

Example

# Set the auto-recovery delay to 50s after enabling this function.
<HUAWEI> system-view
[HUAWEI] error-down auto-recovery cause bpdu-protection interval 50
