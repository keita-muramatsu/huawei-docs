metric (SRv6 TE Policy view)

Function

The metric command enables metric inheritance.

The undo metric command disables metric inheritance.

By default, metric inheritance is disabled.

Format

metric { inherit-igp | inherit-te | inherit-delay | inherit-disable }

undo metric { inherit-igp | inherit-te | inherit-delay | inherit-disable }

Parameters

Parameter Description Value
inherit-igp

Enables IGP metric inheritance.

-
inherit-te

Enables TE metric inheritance.

-
inherit-delay

Enables delay metric inheritance.

-
inherit-disable

Disables metric inheritance.

-

Views

SRv6 TE policy view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

After metric inheritance is configured, the metric of an SRv6 TE Policy can be reported to the tunnel management module.

  • If the metric absolute command has been run, the configured value is used as the metric of the SRv6 TE Policy.
  • If a metric is carried when a primary candidate path is created or updated through PCEP/BGP and the path carries traffic, the metric carried by the path is reported to the tunnel management module as the metric of the SRv6 TE Policy.
  • The subscribed cost of the route to the SRv6 TE Policy endpoint is used as the metric of the SRv6 TE Policy. In this case, the cost of the route may be different from that of the actual path of the SRv6 TE Policy.
  • If metric inheritance is not configured, the metric of the SRv6 TE Policy reported to the tunnel management module is 0.

The statically configured metric has the highest priority, the metric delivered by the controller has the second highest priority, and the subscribed route cost has the lowest priority.

If metric inheritance is configured in both the Segment Routing IPv6 view and the SRv6 TE Policy view, the configuration in the SRv6 TE Policy view takes effect.

Precautions

SRv6 TE Policies to which the same service recurses must be configured with the same metric inheritance type. Assume that a VPN service has two next hops, which recurse to different SRv6 TE Policies. It is expected that the next hop is preferentially selected based on the costs of the two SRv6 TE Policies.

In this case, the two SRv6 TE Policies should be configured with the same metric inheritance type, such as IGP metric inheritance.

If different metric inheritance types are configured for SRv6 TE Policies, VPN routes are selected based on the different types of metric values inherited. This configuration is meaningless.

Example

# Enable metric inheritance.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] srv6-te policy p1 endpoint 2001:DB8:1::1 color 10
[HUAWEI-segment-routing-ipv6-policy-policy1] metric inherit-igp
