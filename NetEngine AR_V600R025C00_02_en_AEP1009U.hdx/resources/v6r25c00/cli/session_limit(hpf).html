session limit

Function

The session limit command sets the maximum number of sessions that can be used by a user.

The undo session limit command cancels the configuration.

By default, the maximum number of sessions that can be allocated to a user is not configured.

Format

session limit limit-number { per-source-ip | per-destination-ip | per-source-port | per-destination-port } [ acl { acl-number | acl-name } ]

undo session limit [ limit-number { per-source-ip | per-destination-ip | per-source-port | per-destination-port } [ acl { acl-number | acl-name } ] ]

Parameters

Parameter Description Value
limit-number

Specifies the maximum number of sessions.

The value is an integer from 1 to 65535.
per-source-ip

Limits the number of sessions based on the source IP address of a user.

-
per-destination-ip

Limits the number of sessions based on the destination IP address of a user.

-
per-source-port

Limits the number of sessions based on the source port number of a user.

-
per-destination-port

Limits the number of sessions based on the destination port number of a user.

-
acl

Indicates ACL information.

-
acl-number

Specifies the number of the ACL.

The value is an integer ranging from 2000 to 3999.
acl-name

Indicates the ACL name.

The value is a string of 1 to 32 case-sensitive characters. It cannot contain spaces and must start with a letter.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Since endpoints are vulnerable to network attacks on a complex network, the devices connected to the endpoints under network attacks will create a large number of sessions. Once the session resources of a device are exhausted, endpoints cannot perform corresponding services because they cannot be allocated session resources. In this case, you can run this command to set the maximum number of sessions that can be used by a user. When the number of sessions established by the user exceeds the configured limit, the device does not establish new sessions. In this way, the user is restricted on using session resources.

Precautions

  • If an ACL is configured, updating ACL rules does not affect the configured maximum number of sessions.
  • If an ACL is configured and the ACL rule is deny, the number of sessions is not limited.
  • Before this command is run, statistics on the sessions that have been established on the device are not collected.
  • If the source IP address, destination IP address, source port, and destination port are specified to limit the number of sessions, the number of sessions for each protocol is counted. For example, if session limit 100 per-source-port is configured and there are 200 TCP flows with the source port number 500 and 200 UDP flows with the source port number 500, 100 sessions are generated on the device.

    In the dual-gateway scenario, the number of sessions synchronized between the two ends is not limited by session limit by default. The actual number of established sessions exceeds the configured limit. The maximum number is twice the limit. You can execute the session dual-gateway-backup limit enable command to enable dual-gateway backup sessions to be restricted by the session limit field. In this way, the value of the session limit field is the maximum number of sessions that can be actually established by a user.

– For the AR6700-H series, after an active/standby switchover is performed, the device clears the number of sessions that have been collected before the switchover and collects statistics again.

Example

# Set the maximum number of sessions that can be used by each source IP address to 1000.
<HUAWEI> system-view
[HUAWEI] session limit 1000 per-source-ip
Warning:After this command is configured, the number of sessions available for users is limited. Continue? [Y/N]:y
