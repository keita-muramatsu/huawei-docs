authentication control-direction

Function

The authentication control-direction command configures the direction for flow control.

The undo authentication control-direction command restores the default configuration.

By default, the device only controls the upstream traffic.

Format

authentication control-direction all

authentication control-direction inbound

undo authentication control-direction

Parameters

Parameter Description Value
inbound

Configures upstream traffic control.

-
all

Configures bidirectional traffic control.

-

Views

Authentication profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

By default, an authentication access device discards all the traffic sent from the users who fail the 802.1X authentication or MAC address authentication. However, these users can still receive packets broadcast from network devices to successfully authenticated users in the same VLAN. To disable the users who fail the authentication from receiving the broadcast packets, run the authentication control-direction all command to configure bidirectional traffic control. To restore the default situation, run the authentication control-direction inbound command so that the device only controls the traffic sent from the users who fail the authentication.

Precautions

  • This function applies only to 802.1X authentication and MAC address authentication.
  • When users have authentication event entries, bidirectional flow control does not take effect. You are advised not to run the authentication event command to configure network access rights for users in each phase before user authentication succeeds.
  • When both authenticated users and unauthenticated users exist on the same interface and in the same VLAN, bidirectional flow control does not take effect.
  • Layer 3 interfaces do not support bidirectional flow control.
  • You are advised to run the stp edged-port enable command to configure an interface as an edge port and ensure that the number of VLANs to which the interface is added does not exceed 4.
  • When this function is configured and the STP mode is MSTP or STP, run the instance command to map VLANs to different spanning tree instances. If the STP mode is changed after users go online, user traffic will be interrupted for a short period of time.
  • A user VLAN cannot be configured as a control VLAN for a ring network.
  • VLANIF interfaces and routed main interfaces are not supported.
  • After the authentication control-direction all command is run, the access device removes VLAN tags from 802.1X packets sent to terminals.

Example

# Configure upstream traffic control in the authentication profile authen1.
<HUAWEI> system-view
[HUAWEI] authentication-profile name authen1
[HUAWEI-authen-profile-authen1] authentication control-direction inbound
