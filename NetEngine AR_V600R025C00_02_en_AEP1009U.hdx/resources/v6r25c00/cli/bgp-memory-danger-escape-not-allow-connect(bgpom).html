bgp memory-usage danger-threshold not-allow-connect

Function

The bgp memory-usage danger-threshold not-allow-connect command configures the device not to reestablish the BGP peer relationships that fail to go up within a specified period when the device memory is in the danger state and the memory usage of the BGP component ranks in the top 3.

The undo bgp memory-usage danger-threshold not-allow-connect command restores the configuration that configures the device not to reestablish the BGP peer relationships that fail to go up within 72 hours when the device memory is in the danger state and the memory usage of the BGP component ranks in the top 3.

By default, when the device memory is in the danger state and the memory usage of the BGP component ranks in the top 3, the device does not reestablish peer relationships with the BGP peers that fail to go up within 72 hours.

Format

bgp memory-usage danger-threshold not-allow-connect [ escape time time-value ]

undo bgp memory-usage danger-threshold not-allow-connect [ escape time time-value ]

Parameters

Parameter Description Value
escape

Indicates escape from the memory danger state.

-
time time-value

Specifies the upper limit of the period during which a neighbor relationship is not up.

The value is an integer ranging from 0 to 255, in hours. The default value is 72.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Based on the device memory usage, the device memory states are classified as follows:

  • Warning: The device memory usage exceeds the warning threshold (also called the notification threshold). The default threshold is 70 (in percentage).
  • Danger: The device memory usage exceeds the danger threshold (also called the overload threshold). The default threshold is 85 (in percentage).
  • Exception: The device memory usage exceeds the exception threshold. The default threshold is 90 (in percentage).

If BGP peer relationships are re-established when the device memory is in danger state, the memory usage increases and may enter the exception state, triggering an active/standby switchover. To prevent this problem, run the bgp memory-usage danger-threshold not-allow-connect command, which configures the device not to reestablish the BGP peer relationships that fail to go up within a specified period when the device memory is in danger state and the memory usage of the BGP component ranks in the top 3. This prevents the memory usage from increasing.

Precautions

This command takes effect only for the peers whose down state is not triggered by disconnection in case of memory overload. You can run the display bgp peer log-info command to check the reason why a BGP peer goes down. If the sub-error code indicates resource threshold-crossing, the BGP peer is down due to memory overload.

To prevent key services from being affected, you can run the peer low-memory exempt command to configure BGP to exempt a peer when BGP escape starts.

Example

# Configure the device not to reestablish the BGP peer relationships that fail to go up within 48 hours when the device memory is in the danger state and the memory usage of the BGP component ranks in the top 3.
<HUAWEI> system-view
[HUAWEI] bgp memory-usage danger-threshold not-allow-connect escape time 48
