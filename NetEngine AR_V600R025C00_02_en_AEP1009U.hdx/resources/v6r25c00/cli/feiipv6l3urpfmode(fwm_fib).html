ipv6 urpf

Function

The ipv6 urpf command configures the URPF check mode on an interface.

The undo ipv6 urpf command cancels the configured URPF check mode on an interface.

By default, URPF check is disabled on all interfaces.

Format

ipv6 urpf { strict | loose } [ allow-default-route ] [ acl6 acl-number ]

undo ipv6 urpf

Parameters

Parameter Description Value
strict

Strict mode.

-
loose

Loose mode.

-
allow-default-route

Allows default routes.

-
acl6 acl-number

Specifies the number of the bound ACL.

The value is an integer ranging from 2000 to 3999.

Views

10GE sub-interface view, 10GE interface view, 25GE sub-interface view, 25GE interface view, 40GE sub-interface view, 40GE interface view, Dialer interface view, Eth-Trunk sub-interface view, Eth-Trunk interface view, Ethernet sub-interface view, Ethernet interface view, GE sub-interface view, GE interface view, IP-Trunk interface view, POS interface view, Tunnel interface view, VLANIF interface view, Serial interface view, Multi-GE sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Using the ipv6 urpf command, you can configure the URPF check mode on an interface. When the strict check mode is configured, the device checks the first packet and subsequent packets to prevent loops and ensure customer network availability.

Using the undo ipv6 urpf command, you can delete the URPF check mode configured on an interface.

By default, URPF check is disabled on an interface.

Configuration Impact

The URPF check can be implemented in strict or loose mode. In addition, the device supports the check of ACLs and default routes.

The URPF process is as follows:

If the source address of the packet exists in the FIB table of the device,

  • In strict mode, the device searches for the outbound interface of the packet reversely. If only one outbound interface matches the inbound interface of the packet, the packet passes the check. Otherwise, the packet is discarded. If there are multiple outbound interfaces matching the packet inbound interface, the loose check is required. (Reverse lookup indicates searching for the outbound interface of another packet whose destination IP address is the source IP address of the packet.)
  • In loose mode, if the source address of the packet exists in the FIB table of the device (regardless of consistency between the reversely searched outbound interface and the inbound interface of the packet), the packet passes the URPF check. Otherwise, the packet is discarded.

    If the source IP address of the packet does not exist in the FIB table of the device, check whether the default route and the allow-default-route parameter for URPF are configured.
  • If the default route is configured but the allow-default-route parameter is not specified,

    If the source address of the packet does not exist in the FIB table of the device, the packet is denied regardless of whether the URPF check is in strict or loose mode.
  • If both the default route and the allow-default-route parameter are configured,

    In the case of strict check, when the outbound interface of the default route is consistent with the inbound interface of the packet, the packet passes the URPF check and is forwarded normally. Otherwise, the packet is denied.

    In loose mode, all packets pass the URPF check and are forwarded.

    The packet is matched against an ACL only when it is denied. If the packet is allowed by the ACL, the packet is forwarded normally. If the packet is denied by the ACL, the packet is discarded.

Example

# Enable URPF strict check on 10GE 0/0/1 and allow special processing and ACL check on the default route. 
<HUAWEI> system-view
[HUAWEI] acl ipv6 number 2000
[HUAWEI-acl6-basic-2000] quit
[HUAWEI] interface 10GE0/0/1
[HUAWEI-10GE0/0/1] ipv6 enable
[HUAWEI-10GE0/0/1] ipv6 urpf strict allow-default-route acl6 2000
