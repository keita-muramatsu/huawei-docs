portal timer offline-detect

Function

The portal timer offline-detect command sets the offline detection period for Portal authentication users.

The undo portal timer offline-detect command restores the default offline detection period for Portal authentication users.

By default, the offline detection period of Portal authentication users is 300 seconds.

Format

portal timer offline-detect time-length

undo portal timer offline-detect

Parameters

Parameter Description Value
time-length

Specifies the offline detection period.

The value is 0 or an integer ranging from 30 to 7200, in seconds. The default value is 300.

The value 0 indicates that offline detection is not performed.

Views

Portal access profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

If a Portal authentication user goes offline due to a power outage or network interruption, the device and authentication server may retain the user information, leading to problems such as incorrect accounting. In addition, a limited number of users are allowed access to the device. If a user goes offline unexpectedly but the device retains the user information, other users may fail to access the network.

After the offline detection period is set for Portal authentication users, if a user does not respond within the period, the device considers that the user is offline. The device and authentication server then delete the user information to ensure efficient resource use.

Precautions

  • After the configuration is modified, the new configuration takes effect only for new access users.
  • This command applies only to Layer 2 Portal authentication users.

    For Layer 3 Portal authentication users, the heartbeat detection function of the authentication server can ensure that the online status of the users is normal. After detecting that a user goes offline, the authentication server instructs the device to disconnect the user.
  • For the device that supports traffic detection, if no traffic of a user passes through the device within the offline detection period, the device considers that the user has logged out. If traffic (such as service packets) of a user passes through the device within the offline detection period, the device does not consider that the user has logged out even if the user does not respond to the offline detection packet.
  • If the number of offline detection packets (ARP packets) exceeds the default CAR value, the detection fails and users are disconnected. To check whether ARP request and reply packets are lost, run the display cpu-defend statistics command. To solve this problem, you are advised to perform the following operations:
    • Increase the detection period based on the number of users. You are advised to use the default detection period when there are less than 8000 users and set the detection period to greater than or equal to 600 seconds when there are more than 8000 users.
    • Configure the port attack defense function on the access device to limit the rate of packets sent to the CPU.

Example

# In the Portal access profile p1, set the offline detection period of Portal authentication users to 400 seconds.
<HUAWEI> system-view
[HUAWEI] portal-access-profile name p1
[HUAWEI-portal-acces-profile-p1] portal timer offline-detect 400
