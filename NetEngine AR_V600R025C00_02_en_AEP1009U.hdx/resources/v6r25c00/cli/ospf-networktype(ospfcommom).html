ospf network-type

Function

The ospf network-type command sets the network type for an OSPF interface.

The undo ospf network-type command restores the default network type.

By default, the network type of an interface is determined by the physical interface. For details, see Configuration Guide > IP Routing Configuration > OSPF Configuration > Configuring Network Types for OSPF Interfaces > Understanding the Network Types Supported by OSPF.

Format

ospf network-type { broadcast | p2p | p2mp | nbma }

undo ospf network-type

Parameters

Parameter Description Value
broadcast

Indicates that the network type of the interface is changed to broadcast.

-
p2p

Indicates that the network type of the interface is changed to point-to-point.

-
p2mp

Indicates that the network type of the interface is changed to point-to-multipoint.

-
nbma

Indicates that the network type of the interface is changed to NBMA.

-

Views

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

You can change network types and configure OSPF features to flexibly build networks without changing link layer protocols.

  • If there are devices that do not support multicast addresses on a broadcast network, you can change the network types of interfaces to NBMA.
  • If the network types of interfaces are NBMA, no neighbors need to be configured after the network types are changed to broadcast.

    The condition for changing an NBMA network to a broadcast network is that there is a direct virtual circuit between any two devices. In other words, the network must be fully meshed. If the preceding condition is not met, the network types of interfaces must be changed to to point-to-multipoint. In this manner, two indirectly connected devices can exchange routing information through a device that is directly reachable to them. After the network types of the interfaces are changed to point-to-multipoint, no neighbors need to be configured.

    If only two devices run OSPF on the same network segment, you can change the network types of interfaces to P2P.

Precautions

  • OSPF does not support the configuration on null interfaces.
  • If the network type of an interface is NBMA or the network type of an interface is manually changed to NBMA, the peer command must be run to configure an adjacent node.
  • Generally, the network types of the OSPF interfaces on both ends of a link must be the same. Otherwise, the OSPF neighbor relationship cannot be established. If the network type of the local interface is set to P2P or P2MP, the interface checks the DR and Router Priority fields in received Hello packets. If neither of the two fields is 0, the local device considers that the peer configuration is incorrect and discards the packets. In this case, no neighbor relationship can be established between the two devices. Otherwise, a neighbor relationship can be established even when the network type of the peer interface is not P2P or P2MP (for example, broadcast network), but routes cannot be correctly calculated.
  • The network type of an interface on a star network cannot be set to P2P. Otherwise, a deadlock tends to occur if the Layer 2 link connected to the interface goes down and then recovers.

Example

# Set network type of an interface to NBMA. 
<HUAWEI> system-view
[HUAWEI] interface 10GE0/0/0
[HUAWEI-10GE0/0/0] undo portswitch
[HUAWEI-10GE0/0/0] ospf network-type nbma
