bestroute non-gr-prior

Function

The bestroute non-gr-prior command configures a device to preferentially select the routes received from peers that are not in GR state.

The undo bestroute non-gr-prior command cancels the configuration of the function of preferentially selecting the routes received from the peers that are not in GR state.

By default, the function of preferentially selecting the routes received from the peers that are not in GR state is not configured.

Format

bestroute non-gr-prior

undo bestroute non-gr-prior

Parameters

None

Views

BGP IPv6 SR-Policy address family view

Default Level

2: Configuration level

Usage Guidelines

When GR is enabled on the local device and the peer from which the optimal route is received restarts, the peer enters the GR state and the local device continues to prefer the route received from this peer. As a result, traffic is not switched to other paths, leading to packet loss. To solve this problem, you can run the bestroute non-gr-prior command on the local device to preferentially select a route received from a peer not in GR state as the optimal route.

Example

# Enable the device to preferentially select the SRv6 TE Policy routes received from peers that are not in GR state. 
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] ipv6-family sr-policy
[HUAWEI-bgp-af-ipv6-srpolicy] bestroute non-gr-prior
