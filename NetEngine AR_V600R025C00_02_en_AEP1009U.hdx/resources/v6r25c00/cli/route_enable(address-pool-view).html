route enable (NAT instance address pool view)

Function

The route enable command enables open programming routes (OPRs) for addresses in the NAT address pool.

The undo route enable command disables OPRs for addresses in the NAT address pool.

By default, OPRs are disabled for addresses in the NAT address pool.

Format

route enable

undo route enable

Parameters

None

Views

NAT instance address pool view

Default Level

2: Configuration level

Usage Guidelines

When a host on the Internet proactively sends a request packet destined for an IP address in a NAT address pool, the device forwards the packet to the connected router according to the default route, as the device has no session entry matching the packet. When receiving the packet, the router sends the packet back to the device according to the routing table. As a result, the packet is indefinitely forwarded between the device and router, causing a routing loop.

After this command is configured, the device generates an OPR for addresses in the NAT address pool. This OPR, like the blackhole route, can prevent route loops and can be imported and advertised by dynamic routing protocols, such as OSPF.

If an address in the NAT address pool and the WAN interface address are in different network segments, a blackhole route is required. If they are in the same network segment, a blackhole route is recommended.

If an address in the address pool is the same as the WAN interface address, no routing loop will occur, and therefore no blackhole route is required.

Example

# Enable OPRs for addresses in the NAT address pool.
<HUAWEI> system-view
[HUAWEI] nat address-group nataddr 1
[HUAWEI-address-group-nataddr] route enable
