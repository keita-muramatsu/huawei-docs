capwap dtls no-auth enable

Function

The capwap dtls no-auth enable command enables a CAPWAP client to establish a DTLS session with a CAPWAP server in non-authentication mode.

The undo capwap dtls no-auth enable command disables a CAPWAP client from establishing a DTLS session with a server in non-authentication mode.

By default, non-authentication is disabled for CAPWAP DTLS sessions.

Format

capwap dtls no-auth enable

undo capwap dtls no-auth enable

Parameters

None

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

In site deployment scenarios, CAPWAP clients need to have CAPWAP DTLS PSKs to access a server; otherwise, CAPWAP DTLS negotiation fails. When there are a large number of CAPWAP clients, the DTLS PSK configuration workload will be heavy. If a device does not support authentication based on the initial certificate, this function allows the device to establish a temporary link with the server in none authentication mode. After the link is established, the server delivers an encrypted PSK to the device. Then the device uses the new PSK to negotiate access.

Follow-up Procedure

After all STAs successfully connect to the AP, run the undo capwap dtls no-auth enable command to disable this function.

Example

# Disable non-authentication for CAPWAP DTLS sessions.
<HUAWEI> system-view
[HUAWEI] undo capwap dtls no-auth enable
