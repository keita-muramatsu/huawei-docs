display hrp state

Function

The display hrp state command displays status information of hot standby.

Format

display hrp state [ verbose ]

Parameters

Parameter Description Value
verbose

Displays detailed status information of hot standby.

-

Views

All views

Default Level

1: Monitoring level

Usage Guidelines

Usage Scenario

To view status information of hot standby, run the display hrp state command. The information includes the roles of the local and peer devices, priorities, bandwidth usage of heartbeat interfaces, last status switchover, configurations of hot standby parameters and functions, priority calculation details, and status of monitoring items.

Precautions

You can view status information of hot standby only after running the hrp enable command to enable it.

Table 1 Description of the display hrp state command output
Item Description
Local role: Active, Peer role: Standby

Roles of the local and peer devices. The value can be:

  • Standby.
  • Active.
  • Load Sharing(Primary): active in load balancing mode.
  • Load Sharing(Secondary): standby in load balancing mode.
  • Unknown: unknown when the heartbeat link between the local and peer devices fails.
Local priority: x:y, Peer priority: x:y

Device priorities of the local and peer devices. The value is x:y, where x indicates the fault indicator and y indicates the robustness indicator. The device with a smaller fault indicator has a higher priority. When the fault indicators are different, the robustness indicator is no longer compared. When the fault indicators are the same, the device with a larger robustness indicator has a higher priority.
Connection state: succeeded

Whether the connection is successful. The connection status can be:

  • failed: failed.
  • succeeded: success.
Stable time

Stable running time, which means the time span since the last HRP status change. This value indicates whether the HRP status changes or a fault occurs recently.
Last state change information: 2020-05-11 20:16:23 The HRP link changes to up. local device ID is xx-xx-xx-xx-xx-xx, peer device ID is xx-xx-xx-xx-xx-xx.

Information about the last status switching of the local device.
Configuration:

Configuration information.
Hello interval

Interval at which HRP heartbeat packets and HRP link detection packets are sent. The configuration command is hrp timer hello.
Preempt delay

Preemption delay, in seconds. The configuration command is hrp preempt delay interval.
Preempt

Status of the preemption function. The configuration command is hrp preempt.
Track trunk member

Status of the function of monitoring Eth-Trunk or IP-Trunk member interfaces. The configuration command is hrp track trunk-member enable.
Auto-Sync connection status

Status of automatic status entry backup. The configuration command is hrp auto-sync connection-status.
Adjust OSPF-Cost

Status of the function of adjusting the cost values of OSPF routes based on the active/standby status. The configuration command is hrp adjust ospf-cost enable.
Adjust OSPFv3-Cost

Status of the function of adjusting the cost values of OSPFv3 routes based on the active/standby status. The configuration command is hrp adjust ospfv3-cost enable.
Adjust BGP-Cost

Status of the function of adjusting the cost values of BGP routes based on the active/standby status. The configuration command is hrp adjust bgp-cost enable.
Total

Fault indicator and robustness indicator of the local device.
Manual

Impact of the hrp switch command on the device fault indicator. For details, see the influence of the hrp switch command.
BFD

If the BFD session status is down, the fault indicator is increased. The indicator is twice the number of BFD sessions in the Down state.
BFD session

Status of the monitored BFD session. The command is hrp track bfd-session.

  • init.
  • administratively down.
  • down.
  • up.
Tracked interface

If an interface is down, the fault indicator is increased. The indicator is twice the number of down interfaces.
CPU

If the CPU status is not faulty, the robustness indicator increases. The indicator value is the number of CPUs in the normal state multiplied by 2.

The CPU status does not affect the fault indicator.
ospf-cost

Cost value of OSPF routes.

If two devices work in active/standby backup mode, the cost value of OSPF routes on the active device is +0, indicating that the cost value of OSPF routes is subject to the configuration and not adjusted. The cost value of OSPF routes on the standby device is +65500 by default, controlled by the hrp adjust ospf-cost enable command, indicating that the cost value of OSPF routes is 65500.

If two devices work in load balancing mode, the cost values of OSPF routes on both devices are +0.
ospfv3-cost

Cost value of OSPFv3 routes.

If two devices work in active/standby backup mode, the cost value of OSPFv3 routes on the active device is +0, indicating that the cost value of OSPFv3 routes is subject to the configuration and not adjusted. The cost value of OSPFv3 routes on the standby device is +65500 by default, controlled by the hrp adjust ospf-cost enable command, indicating that the cost value of OSPFv3 routes is 65500.

If two devices work in load balancing mode, the cost values of OSPFv3 routes on both devices are +0.
bgp-cost

Added MED value of BGP routes.

If two devices work in active/standby backup mode, the added MED value of BGP routes on the active device is +0, indicating that the MED value of BGP routes is subject to the configuration and not adjusted. The added MED value of BGP routes on the standby device is +100 by default, controlled by the hrp adjust bgp-cost enable command, indicating that the MED value of BGP routes increases by 100.

If two devices work in load balancing mode, the added MED values of BGP routes on both devices are +0.
Eth-Trunk111

Status of the monitored interface. The command is hrp track interface.

  • up.
  • down.
Abnormal HPL heartbeat: Slot CPU index

Information about the HPL heartbeat interface associated with HRP. The HPL heartbeat on the CPU is abnormal.

Slot: indicates the ID of the slot where the HPL heartbeat interface is located.

CPU: indicates the CPU ID of the HPL heartbeat interface.
