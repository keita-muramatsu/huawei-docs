route recursive-lookup tunnel

Function

The route recursive-lookup tunnel command enables tunnel recursion.

The undo route recursive-lookup tunnel command restores the default configuration.

By default, tunnel recursion is disabled.

Format

route recursive-lookup tunnel [ ip-prefix ip-prefix-name ] [ tunnel-policy policy-name ]

undo route recursive-lookup tunnel

Parameters

Parameter Description Value
ip-prefix ip-prefix-name

Specifies the name of an IP prefix list.

The value is a string of 1 to 169 case-sensitive characters, with spaces not supported. When double quotation marks are used around the string, spaces are allowed in the string.
tunnel-policy policy-name

Specifies the name of a tunnel policy.

The value is a string of 1 to 39 case-sensitive characters, spaces not supported. If the string is enclosed in quotation marks, the string can contain spaces.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

By default, non-labeled public network BGP IPv4 routes and IPv4 static routes can recurse to outbound interfaces and next hops, but not to tunnels. To allow the preceding routes to preferentially recurse to tunnels, run this command. If no tunnel is available after the command is run, the preceding routes recurse to outbound interfaces and next hops.

  • If tunnel-policy policy-name is specified, the corresponding tunnel policy is used when the routes recurse to tunnels. For details about how to configure a tunnel policy, see "Configuring and Applying a Tunnel Policy" in Configuration Guide > VPN > VPN Tunnel Management Configuration.
  • If tunnel-policy policy-name is not specified, all non-labeled public network BGP routes and static routes recurse to LDP LSPs and BGP LSPs in descending order of priority.
  • If ip-prefix ip-prefix-name is specified, only the non-labeled public network BGP routes or static routes that match the IP prefix list can recurse to tunnels.

Precautions

  • If you run this command multiple times, the latest configuration overrides the previous one.
  • Static routes recurse to IP routes first. If a static route recurses to a BGP route, the static route inherits the recursion result of the BGP route and no longer recurses to a tunnel. If a static route recurses to a direct route, the static route inherits the recursion result of the direct route and no longer recurses to a tunnel. If the IP route recursion result is not a BGP route or direct route, the device recurses the route to a tunnel based on the tunnel policy. If the IP route recursion result is a network segment instead of a host route, the device uses the network segment address to subscribe to the tunnel. Therefore, the next hop of a static route must not be a BGP route or direct route so that the static route can use the next hop address to recurse to a tunnel (a public network tunnel). If the recursion result contains a BGP LSP, the BGP LSP is discarded. If the recursion result contains other types of tunnels, the other types of tunnels are selected. Otherwise, the IP recursion result is used.
  • This command and the unicast-route recursive-lookup tunnel command are mutually exclusive and cannot be configured together.

Example

# Enable tunnel recursion for static routes and unlabeled BGP public network routes.
<HUAWEI> system-view
[HUAWEI] route recursive-lookup tunnel
