carrier down-hold-time

Function

The carrier down-hold-time command configures a delay in reporting a down event when an interface goes down.

The undo carrier down-hold-time command restores the default delay in reporting a down event when an interface goes down.

By default, the delay in reporting a down event when an interface goes down is 0s.

Format

carrier down-hold-time hold-value period period-value times times-value

undo carrier down-hold-time [ hold-value period period-value times times-value ]

Parameters

Parameter Description Value
hold-value

Specifies a delay in reporting a down event when an interface goes down.

The value is an integer that ranges from 0 to 3600000, in milliseconds.
period period-value

Specifies a detection period during which the device delays reporting an interface down event. The device records the number of times that the interface goes down within this period.

The value is an integer ranging from 0 to 172800, in seconds.
times times-value

Specifies the number of suppressions within the detection period. If the number of times that the interface goes down exceeds the number of suppressions within the detection period, the device reports an interface down event.

The value is an integer ranging from 0 to 100.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

An Ethernet interface can be physically up or down. When the physical interface status changes, the system notifies the upper-layer protocol modules (such as routing and forwarding modules) to guide packet sending and receiving. The system also generates traps and logs to ask users whether to process the physical link.

Note that in some scenarios (for example, during route learning), if an interface alternates between up and down, the device immediately reports an interface down event. As a result, route learning may be interrupted.

In this case, you can run this command to configure a delay in reporting an interface down event. The system does not detect the physical status change (from up to down) of the interface within the delay. If the physical status of the interface is still down after the delay expires, the system reports the physical status change.

Precautions

This command takes effect on all interfaces of the device. If the carrier down-hold-time hold-downcommand is also run on an interface, the configuration on the interface takes effect.

The interface status scanning period is 750 ms. It is recommended that the delay be greater than the scanning period.

Example

# Set the delay in reporting a down event to 3000 ms, the detection period to 3600s, and the number of suppressions to 30 when an interface goes down.
<HUAWEI> system-view
[HUAWEI] carrier down-hold-time 3000 period 3600 times 30
