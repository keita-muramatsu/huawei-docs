ospf timer hello

Function

The ospf timer hello command sets the interval at which Hello packets are sent on an interface.

The undo ospf timer hello command restores the default value.

By default, for P2P and broadcast interfaces, the interval is 10 seconds, for P2MP and NBMA interfaces, the interval is 30 seconds.

Format

ospf timer hello interval [ conservative ]

undo ospf timer hello

Parameters

Parameter Description Value
interval

Specifies the interval at which Hello packets are sent on an interface.

The value is an integer ranging from 1 to 65535, in seconds.

Setting hello interval to be longer than 2s is recommended.
conservative

Configures the conservative mode for the dead timer.

Usage Guidelines

Usage Scenario

Hello packets are periodically exchanged between OSPF-enabled interfaces to establish and maintain neighbor relationships. A Hello packet includes information about the designated router (DR), backup designated router (BDR), timers, and known neighbors.

The interval value is added to Hello packets. The smaller the interval value, the faster a network topology change can be detected, and the larger the route cost. Ensure that the parameters on the interface and the adjacent device are consistent. To speed up OSPF convergence in the case of a link failure, configuring BFD for OSPF is recommended. If the peer end does not support BFD for OSPF or the user does not want to configure BFD for OSPF, the conservative parameter is recommended. In this way, if the dead timer configured using the ospf timer dead command is less than 10s, the configured value takes effect. Otherwise, convergence is performed based on the OSPF neighbor dead timer, and the convergence takes a long time and has a severe impact on services.

Precautions

  • OSPF does not support the configuration on null interfaces.
  • If the configured interval (X) for sending Hello packets is less than 10s, the actual interval for sending Hello packets is calculated using the following formula: Actual interval = X/2 + X%2, where X/2 refers to the rounded-off value of X divided by 2, and X%2 refers to X mod 2. For example, if X equals 5, then X/2 equals 2, and X%2 equals 1.
  • If OSPF packets are encapsulated into GRE packets, you are advised to set the interval for sending Hello packets to a large value. As OSPF Hello packets are encapsulated into GRE data packets, which have a low priority and may be easily discarded during network congestion, OSPF may fail to receive Hello packets within the dead time, interrupting the neighbor relationship.
  • If the interval for sending Hello packets is set but the ospf timer dead command is not configured, the dead timer of the OSPF neighbor is four times the interval for sending Hello packets. Therefore, if the interval for sending Hello packets is less than or equal to 2s, the dead timer of the OSPF neighbor is less than 10s. In this case, if no Hello packets are received within the dead timer, the neighbor relationships are disconnected. To prevent this problem, if the interval for sending Hello packets is set to 1s, the system automatically sets the dead timer of the OSPF neighbor to 10s. If the interval for sending Hello packets is set to 2s, the system automatically sets the dead timer of the OSPF neighbor to 16s. This prevents neighbor flapping and improves network reliability. If the conservative mode is enabled, the dead timer of the OSPF neighbor is still four times the interval for sending Hello packets. That is, the system determines whether the neighbor is invalid based on the configured value.
  • If the interval for sending Hello packets is set and the ospf timer dead command is configured, the dead timer of the OSPF neighbor takes effect based on the configured ospf timer dead value. If the dead timer is too short, neighbor flapping may occur. Therefore, when the configured dead timer is less than 10s, special processing is performed on the value that takes effect. For details, see the description of the ospf timer dead command. To allow the configured dead timer to take effect in this case, configure the conservative parameter.
  • If the dead timer is too short, OSPF neighbor relationships may easily go down due to timeout, affecting services. To prevent this problem, you are advised to keep the default configurations of the ospf timer hello and ospf timer dead commands. Alternatively, set a value that is no less than 40s for the dead timer using the ospf timer dead command.

Example

# Set the interval at which Hello packets are sent by the specified interface to 20s. 
<HUAWEI> system-view
[HUAWEI] interface 10GE0/0/0
[HUAWEI-10GE0/0/0] undo portswitch
[HUAWEI-10GE0/0/0] ospf timer hello 20
