route duplicate check disable

Function

The route duplicate check disable command disables prefix conflict check for static and direct routes.

The undo route duplicate check disable command restores prefix conflict check for static and direct routes.

By default, the device is enabled to perform the prefix conflict check for static and direct routes.

Format

route duplicate check disable

undo route duplicate check disable

Parameters

None

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

When a static or direct route is added and its prefix is the same as that of another route that belongs to a different routing protocol in the routing table, only one of the routes (the one with higher priority) takes effect. This may affect existing configurations. To prevent this problem, the system performs the prefix conflict check by default. This can identify risks. If the prefix of a newly configured static route or direct route is the same as that of another route in the routing table, the system performs a prefix conflict check and displays a message indicating that the destination address already exists in the routing table and that this configuration may cause a route conflict.

If you do not want the system to perform the prefix conflict check, run the route duplicate check disable command to disable the function.

Precautions

If you proceed with the configuration upon a prompt when trying to disable or enable prefix conflict check, the existing configuration may be affected. Therefore, exercise caution when performing this operation.

Example

# Disable the prefix conflict check for static and direct routes.
<HUAWEI> system-view
[HUAWEI] route duplicate check disable
