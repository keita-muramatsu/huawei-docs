peer slice-id non-standard-compatible

Function

The peer slice-id non-standard-compatible command configures the device to parse the non-standard slice ID received from a neighbor and advertise the non-standard slice ID to the neighbor.

The undo peer slice-id non-standard-compatible command restores the default configuration.

By default, the capability of parsing non-standard slice IDs received from neighbors is disabled, and the function of advertising non-standard slice IDs to neighbors is disabled.

Format

peer peerIpv6Addr slice-id non-standard-compatible

peer peerIpv6Addr slice-id non-standard-compatible disable

undo peer peerIpv6Addr slice-id non-standard-compatible

undo peer peerIpv6Addr slice-id non-standard-compatible disable

Parameters

Parameter Description Value
peerIpv6Addr

Specifies an IPv6 peer address.

The value is a 32-bit hexadecimal string in format X:X:X:X:X:X:X:X.
disable

The capability of discarding non-standard slice IDs received from peers is deleted. The difference between this command and the undo command is that this command does not inherit the capability of discarding non-standard slice IDs received from peers.

-

Views

BGP IPv6 SR-Policy address family view

Default Level

2: Configuration level

Usage Guidelines

Slice ID is a new sub-TLV. In earlier versions, the value of Type is 126, which is a non-standard slice ID. In the current version, the value of Type is 123, which is a standard slice ID. To prevent version incompatibility caused by slice ID version changes, you can configure the device to parse non-standard slice IDs received from neighbors and advertise non-standard slice IDs to neighbors.

When the peer slice-id non-standard-compatible command is not configured:

  • If TLV 123 is received, TLV 123 is advertised.
  • If TLV 126 is received, the TLV is transparently transmitted.
  • If TLVs 123 and 126 are received at the same time, TLV 126 is transparently transmitted and TLV 123 is advertised.

    After the peer slice-id non-standard-compatible command is run:
  • If TLV 123 is received, the type of TLV 123 is changed to 126 before being advertised.
  • If TLV 126 is received and can be parsed as a slice ID, TLV 126 is advertised.
  • If a TLV of type 126 is received and cannot be parsed as a slice ID, the TLV is discarded.
  • If TLVs of types 123 and 126 are received at the same time, TLVs of type 126 are not sent, TLVs of type 123 are changed to TLVs of type 126, and then TLVs of type 126 are advertised.

    After the peer slice-id non-standard-compatible disable command is run on a peer, the peer does not inherit the capabilities of parsing and advertising non-standard slice IDs from the peer group.

Example

# Configure the device to parse the non-standard slice ID received from an IPv6 neighbor and advertise the non-standard slice ID to the neighbor.
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] peer 2001:DB8:1::1 as-number 100
[HUAWEI-bgp] ipv6-family sr-policy
[HUAWEI-bgp-af-ipv6-srpolicy] peer 2001:DB8:1::1 enable
[HUAWEI-bgp-af-ipv6-srpolicy] peer 2001:DB8:1::1 slice-id non-standard-compatible
