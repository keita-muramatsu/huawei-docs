if-match community-count

Function

The if-match community-count command configures a matching rule based on the number of community attributes.

The undo if-match community-count command deletes the matching rule.

By default, no matching rule based on the number of community attributes is configured.

Format

if-match community-count { equal-value | { greater-equal greater-equal-value | less-equal less-equal-value } }

if-match community-count greater-equal greater-equal-value less-equal less-equal-value

undo if-match community-count [ equal-value | greater-equal greater-equal-value less-equal less-equal-value ]

Parameters

Parameter Description Value
equal-value

Specifies the number of community attributes.

The value is an integer ranging from 0 to 1024.
greater-equal greater-equal-value

Specifies the lower limit of the number of community attributes.

The value is an integer ranging from 0 to 1023.
less-equal less-equal-value

Specifies the maximum number of community attributes.

The value of less-equal-value must be greater than that of greater-equal-value. If only greater-equal-value is configured, less-equal-value takes the maximum value 1024. If only less-equal-value is configured, greater-equal-value takes the minimum value 0.

The value is an integer ranging from 1 to 1024.

Views

Route-policy view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The if-match community-count command is used to configure a node to filter routes based on the matching rule of the number of community attributes. After the matching rule based on the number of community attributes is configured, the apply clause is used to modify the attributes of the routes that match the rule.

You can run the route-policy command to enter the route-policy view.

A route-policy can consist of multiple nodes. The relationship between different nodes is OR. The system checks each node according to the node sequence number. If a route matches one node, the route matches the route-policy and is no longer matched against other nodes.

Each node may consist of a group of if-match and apply clauses. An if-match clause defines matching rules. The matching objects are some attributes of the routing information. The relationship between multiple if-match clauses for different attributes of a node is AND. A node can pass the matching test only when all the matching conditions specified by the if-match clauses are met. The relationship between multiple if-match clauses for the same attribute is OR, and the system checks the if-match clauses in sequence. If a route matches one of the if-match clauses, the route matches the route-policy and is not matched against other if-match clauses. For example, in node 10, the if-match community-filter 1 and if-match as-path-filter 1 commands are configured. Because different attributes are used, the relationship between the two commands is AND. In node 20, if-match community-filter 1 and if-match community-filter 2 are used to filter routes based on communities. The relationship between if-match community-filter 1 and if-match community-filter 2 is OR. The apply clauses specify actions. That is, the apply clauses set some attributes of the route after the route matches the node.

Prerequisites

The if-match community-count command can be used only after the route-policy command is used.

Configuration Impact

After the device is configured to filter routes based on the number of community attributes, only the routes that meet the filtering conditions can match the policy.

Example

# Match routes based on the specified number of route community attributes.
<HUAWEI> system-view
[HUAWEI] route-policy policy permit node 10
[HUAWEI-route-policy] if-match community-count 8
# Match routes based on the specified number range of community attributes.
<HUAWEI> system-view
[HUAWEI] route-policy policy permit node 10
[HUAWEI-route-policy] if-match community-count greater-equal 1 less-equal 5
