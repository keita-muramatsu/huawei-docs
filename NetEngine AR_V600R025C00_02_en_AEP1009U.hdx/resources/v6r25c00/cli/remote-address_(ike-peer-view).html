remote-address (IKE peer view)

Function

The remote-address command configures an IP address/IP address segment or domain name for the remote IKE peer during IKE negotiation.

The undo remote-address command cancels the configuration.

By default, no IP address/IP address segment or domain name is configured for the remote IKE peer during IKE negotiation.

Format

remote-address { [ vpn-instance vpn-instance-name ] { { start-ip-address [ end-ip-address ] | start-ipv6-adddress [ end-ipv6-adddress ] } | host-name host-name } | authentication-address start-ip-address [ end-ip-address ] }

undo remote-address [ ip-address | ipv6-address | host-name host-name | authentication-address ]

Parameters

Parameter Description Value
vpn-instance vpn-instance-name

Specifies the name of a VPN instance.

The value is a string of 1 to 31 case-sensitive characters without spaces. The VPN instance name cannot be _public_. The character string can contain spaces if it is enclosed with double quotation marks (").
start-ip-address

Specifies the start IPv4 address of the remote end.

The value is in dotted decimal notation.
end-ip-address

Specifies the end IPv4 address of the IPv4 address segment. If no end address is specified, the IPv4 address segment contains only one IP address.

The value is in dotted decimal notation.
start-ipv6-adddress

Specifies the start address of the remote IPv6 address segment.

IPv6-related parameters cannot be configured for the IKE peer referenced by an IPsec profile.

The value is in colon-separated hexadecimal notation.
end-ipv6-adddress

Specifies the end IPv6 address of the IPv6 address segment. If no end address is specified, the IPv6 address segment contains only one IP address.

IPv6-related parameters cannot be configured for the IKE peer referenced by an IPsec profile.

The value is in colon-separated hexadecimal notation.
host-name host-name

Specifies the domain name of the remote IKE peer.

The value must be an existing remote IKE peer domain name.
authentication-address

Specifies the pre-NAT IP address as the authentication address.

-
ip-address

Specifies an IPv4 address.

The value is in dotted decimal notation.
ipv6-address

Specifies an IPv6 address.

IPv6-related parameters cannot be configured for the IKE peer referenced by an IPsec profile.

The value is in colon-separated hexadecimal notation.

Views

IKE peer view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The remote address used in IKE negotiation can be configured as either an IP address or a domain name.

If the remote address is set to an IP address and the gateway IP address of the remote end is fixed, configure a fixed IP address as the remote address. If the gateway IP address of the remote end is not fixed and IPsec is deployed using a template, configure an IP address segment as the remote address.

If the remote address is set to a domain name, the device can obtain the IP address of the remote end in either of the following ways:

  • Static mode: by using a manually configured mapping between the domain name and IP address of the remote end.
  • Dynamic mode: by resolving the remote end's domain name through a DNS server.

To improve network reliability, the HQ can provide up to four gateways for a branch gateway to access. Accordingly, the branch gateway is configured with an IKE peer that includes the IP addresses or domain names of these four HQ gateways, allowing it to establish IKE connections with them. The branch gateway first attempts to establish an IKE connection with an HQ gateway using the first IP address or domain name. If this attempt fails or DPD fails, the branch gateway switches to the next IP address or domain name. Subsequent attempts follow the same process.

In IKEv2-based IPsec NAT traversal scenarios, if both ends need to verify each other's IP address, configure the remote-address authentication-address command with the pre-NAT IP address or IP address segment.

Prerequisites

If the vpn-instance parameter is specified, a VPN instance must have been created by using the ip vpn-instance command and a route distinguisher must have been configured by using the route-distinguisher command.

Precautions

  • When an IPsec policy is used, if the local end is the initiator, you need to run the remote-address command to enable the initiator to search for the peer end during negotiation. Since both ends may be initiators, this command needs to be configured on both of them. The remote-address command does not need to be configured only when the device functions as the IKE negotiation responder, for example, in policy template mode.
  • When an IPsec policy is applied to a tunnel interface and the source command is configured to specify an IP address for the interface, you must run the tunnel local command to configure a local IP address for the tunnel. Otherwise, IKE negotiation fails.
  • When an IPsec profile is used, the address configured using the destination command on the IPsec tunnel interface is preferentially used as the remote address for IKE negotiation. If the destination command is not configured, the address set by the remote-address command on the IKE peer is used instead for IKE negotiation. If both the remote-address and destination commands are configured, ensure that the IP addresses configured in the two commands are the same. Otherwise, IKE negotiation fails. If multiple IKE peers are referenced in an IPsec profile, do not run the destination command on an IPsec tunnel interface. Instead, you need to run the remote-address command on each IKE peer referenced in the IPsec profile.
  • If multiple remote IP addresses or domain names are configured, the same VPN instance must be specified.
  • If the remote-address start-ip-addressend-ip-addresscommand is configured, the device can function only as the responder in IKE negotiation.
  • If one end is configured with multiple remote IP addresses, it must function as the IKE negotiation initiator, not the IKE negotiation responder.
  • After a domain name is specified using the remote-address command, the IP address obtained by IPsec first takes effect, and the IP addresses of other versions corresponding to the domain name do not take effect. Even if the mapping between the domain name and IP address is deleted, the IP address obtained by IPsec first still takes effect.
  • A maximum of four remote addresses can be configured for an IKE peer. For multi-CPU models, only one remote address can be configured for an IKE peer.

Example

# Set the remote IP address of IKE peer peer1 to 10.1.1.1. 
<HUAWEI> system-view
[HUAWEI] ike peer peer1
[HUAWEI-ike-peer-peer1] remote-address 10.1.1.1
