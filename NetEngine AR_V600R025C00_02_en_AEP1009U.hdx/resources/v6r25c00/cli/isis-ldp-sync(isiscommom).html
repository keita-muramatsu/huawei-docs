isis ldp-sync

Function

The isis ldp-sync command enables LDP and IS-IS synchronization on an interface.

The undo isis ldp-sync command disables LDP and IS-IS synchronization on an interface.

By default, LDP and IS-IS synchronization is disabled on an interface.

Format

isis ldp-sync

undo isis ldp-sync

Parameters

None

Views

10GE interface view, 25GE sub-interface view, 25GE interface view, 40GE interface view, Cellular channel interface view, Eth-Trunk sub-interface view, Eth-Trunk interface view, Ethernet interface view, GE optical interface view, GE electrical interface view, IP-Trunk interface view, MP-group interface view, POS interface view, Tunnel interface view, VLANIF interface view, 40GE sub-interface view, 10GE sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

LDP convergence depends on IS-IS route convergence. Therefore, LDP convergence is slower than IS-IS route convergence. The following problems occur when MPLS LDP is used on a network with primary and backup links:

  • If the primary link fails, both IS-IS routes and LSPs are switched to the backup link (generally implemented through LDP FRR). When the primary link recovers, IS-IS routes are switched back to the primary link earlier than LDP LSPs. As a result, traffic on LSPs is lost.
  • When IS-IS runs properly on the primary link but an LDP session or LDP adjacency between two nodes on the primary link fails, IS-IS routes still use the primary link, but the LSP on the primary link is deleted. In addition, the backup link does not have a preferred IS-IS route. As a result, the LSP cannot be established on the backup link, causing traffic loss on the LSP.

    To prevent traffic loss, run the isis ldp-sync command to enable LDP and IS-IS synchronization. This command needs to be run only on the interface where the primary and backup links intersect.

Prerequisites

An IS-IS process has been enabled using the isis enable command in the interface view.

Precautions

If LDP-IGP synchronization is enabled and no value is set for the hold-max-cost timer, the IGP advertises the maximum cost of a link during the interruption of the LDP session or LDP adjacency. The cost can be restored only after the LDP session recovers. In a scenario where a backup link exists, after the primary link recovers, LDP attempts to reestablish the session. Because the IGP advertises the maximum cost for the primary link, TCP connection establishment or LDP packets are sent to the peer end through the backup link. If the backup link fails to forward traffic or a security policy is configured, the TCP connection establishment or LDP packets may be discarded. As a result, the LDP session cannot be established, and the IGP continues to advertise the maximum cost for the primary link. Therefore, when LDP-IGP synchronization is used, ensure that the backup link can properly forward LDP packets. Otherwise, routes may always select the backup link.

In addition, when the IGP carries multiple types of services, including LDP services, LDP-IGP synchronization is enabled, and no value is set for the hold-max-cost timer, the IGP keeps advertising the maximum cost for the primary link during the interruption of the LDP session or LDP adjacency on the primary link. As a result, IGP route selection and other services may be affected. Therefore, when the IGP carries multiple types of services, including LDP services, you can set a proper value for the hold-max-cost timer to reduce the impact of the LDP session or LDP adjacency interruption on IGP route selection and other services.

Example

# Enable LDP and IS-IS synchronization on the interface. 
<HUAWEI> system-view
[HUAWEI] isis 1
[HUAWEI-isis-1] quit
[HUAWEI] interface 10GE 0/0/0
[HUAWEI-10GE0/0/0] isis enable 1
[HUAWEI-10GE0/0/0] isis ldp-sync
