display distribute-ap

Function

The display distribute-ap command displays information about RUs.

Format

display distribute-ap { all | ap-id ap-id | ap-mac ap-mac | central-ap-id central-ap-id | central-ap-mac central-ap-mac }

Parameters

Parameter Description Value
all

Displays information about all RUs.

-
ap-id ap-id

Displays information about the RU of a specified ID.

For the AR5710-S8TWDSE-LTE4EA, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR5710-S10T1X2, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T and AR5710-S8P1XDSE-2LTE4EA:The value is an integer ranging from 0 to 127.

For the AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4 and AR6700-H series:The value is an integer in the range from 0 to 1023.

For the AR8700 series and AR8100 series:The value is an integer that ranges from 0 to 2047.
ap-mac ap-mac

Displays information about the RU of a specified MAC address.

The RU's MAC address must exist.
central-ap-id central-ap-id

Displays information about the RUs connected to the central AP of a specified ID.

For the AR5710-S8TWDSE-LTE4EA, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR5710-S10T1X2, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T and AR5710-S8P1XDSE-2LTE4EA:The value is an integer ranging from 0 to 127.

For the AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4 and AR6700-H series:The value is an integer in the range from 0 to 1023.

For the AR8700 series and AR8100 series:The value is an integer that ranges from 0 to 2047.
central-ap-mac central-ap-mac

Displays information about the RUs connected to the central AP of a specified MAC address.

The MAC address of the central AP must exist.

Views

All views

Default Level

1: Monitoring level

Usage Guidelines

Usage Scenario

You can run this command to check RU information.

Precautions

AP state list

AP State Description Possible Cause Handling Procedure
commit-failed (cmtfa) WLAN service configurations fail to be delivered to an AP after it goes online on a WAC. After an AP goes online on the WAC, WLAN service configurations are performed for the AP. If the link between the AP and WAC is disconnected or the peer end has no response, the AP enters the commit-failed state. Check the network connection.
committing (cmt) WLAN service configurations are being delivered to an AP after it goes online on a WAC. After an AP goes online on the WAC, WLAN service configurations are delivered to the AP. During this process, the AP is in committing state. This is a normal state, and no action is required.
config (cfg) WLAN service configurations are being delivered to an AP when it is going online on a WAC. After an AP establishes a link with the WAC, WLAN service configurations are delivered to the AP. During this process, the AP is in config state. This is a normal state, and no action is required.
config-failed (cfgfa) WLAN service configurations fail to be delivered to an AP when the AP is going online on a WAC. After an AP establishes a link with the WAC, WLAN service configurations are delivered to the AP. If the configuration delivery fails due to various reasons (such as link disconnection), the AP enters the config-failed state. Check the network connection.
download (dload) An AP is being upgraded. When an AP is performing an upgrade, it enters the download state. Check the AP status again after the AP upgrade is complete.
fault An AP fails to go online.

An AP onboarding failure is usually caused by the following:

- The AP fails to obtain an IP address or obtains an incorrect IP address.

- The network between the AP and WAC is faulty.

- The AP fails to be authenticated.

- The number of APs on the WAC has reached the maximum value.

- The AP device is faulty.

Handle the AP onboarding failure by referring to AP Online Failure in the Troubleshooting Insights
idle It is the initialization state of an AP before it establishes a link with a WAC for the first time. When an AP has not established a CAPWAP link with the WAC, the MAC address and SN of an AP that is added offline are different from the actual MAC address and SN of the AP, or the WAC cannot manage an AP due to license resource insufficiency, the AP enters the idle state.

Perform the following operations:

Check whether the AP is connected to the network. If the AP connection is normal, go to next step.

Check the MAC address and SN of the AP that is added offline are different from the actual MAC address and SN of the AP. If not, perform the following operations:

1. Run the display ap all command to obtain AP information.

2. Run the undo ap { ap-id ap-id| ap-mac ap-mac| ap-group group-name| all } command to delete the AP.

3. Run the ap-id ap-id[ [ type-id type-id| ap-type ap-type] { ap-mac ap-mac| ap-sn ap-sn| ap-mac ap-macap-sn ap-sn} ] command to add the correct AP information.

If the fault persists, expand the license capacity. Note that RUs managed by the WAC do not occupy license resources of the WAC.

name-conflicted (namec) The name of an AP conflicts with that of another AP. The name of an AP conflicts with the name of another AP that has been online on the same WAC. Run the ap-name command to change the AP name.
normal (nor) An AP is working properly. An AP successfully goes online on a WAC. This is a normal state, and no action is required.
standby (stdby) The AP is in normal state on the standby WAC. In the WAC backup scenario, if the link between the active and standby WACs is established properly, an AP is in standby state on the standby WAC and in normal state on the active WAC. This is a normal state, and no action is required.
ver-mismatch (vmiss) The WAC and AP versions do not match. The versions of the AP and WAC do not match.

Log in to Huawei technical support website and download the release notes. Based on the version mapping, upgrade the AP or WAC to the matching version.

- Enterprise technical support website: https://support.huawei.com/enterprise

- Carrier technical support website: https://support.huawei.com

countryCode-mismatch (cmiss) The country codes of the WAC and AP do not match.

The AP's current version does not support the country code configured on the WAC.

The country code of the AP is locked, and the country code configured on the WAC is not supported.

The AP does not support the country code. Upgrade the AP or modify the country code configuration on the WAC.

The country code of the AP is locked. Replace the AP or change the country code on the WAC to be the same as that of the AP.

type-mismatch (tmiss) The AP type does not match. The AP type configured on the WAC does not match the actual AP type. Change the AP type configured on the WAC.
unauth The AP is not authenticated. The AP fails to be authenticated.

Run the display ap unauthorized record command to query APs that fail to be authenticated.

Run the ap-confirm command to confirm these APs and allow them to go online.
