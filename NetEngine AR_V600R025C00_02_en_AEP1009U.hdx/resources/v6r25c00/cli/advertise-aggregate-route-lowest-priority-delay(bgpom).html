advertise aggregate-route lowest-priority

Function

The advertise aggregate-route lowest-priority command minimizes the priority of BGP summary routes.

The undo advertise aggregate-route lowest-priority command restores the default configuration.

By default, BGP does not adjust the priority of summary routes.

Format

advertise aggregate-route lowest-priority [ delay-time time-value ]

undo advertise aggregate-route lowest-priority [ delay-time time-value ]

Parameters

Parameter Description Value
delay-time time-value

Specifies the delay for advertising summary routes with the lowest priority.

The value is an integer ranging from 1 to 86400, in seconds.

The default value is 0 seconds.

Views

BGP-IPv4 unicast address family view, BGP-IPv6 unicast address family view, BGP-VPN instance IPv4 address family view, BGP-VPN instance IPv6 address family view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

For a BGP summary route, the default MED value is 0, and the default Local_Pref value is 100. Due to the high priority, this route may divert traffic too early, causing traffic loss. You can run the advertise aggregate-route lowest-priority command on the device to minimize the priority of the BGP summary route by changing its MED value to 4294967295 and the Local_Pref value to 0. This prevents the BGP summary route from diverting traffic too early, thereby avoiding the traffic loss. You can also run the advertise aggregate-route lowest-priority delay-time time-valuecommand on the device to minimize the priority of the summary route within the specified delay time. After the delay time expires, the priority of the summary route is automatically restored. The delay time should be set to the maximum time for learning specific routes (for example, 1s can be reserved for learning 1000 routes). You can set a proper delay time based on the actual situation to ensure that the device has finished learning specific routes when the priority of the summary route is restored. To restore the priority of the summary route, run the undo advertise aggregate-route lowest-priority [ delay-time time-value] command.

Precautions

  1. The advertise aggregate-route lowest-priority command takes effect only on the summary routes that are obtained through manual summarization after the command is run.
  2. If an active/standby switchover is performed, the priorities of summary routes are restored.
  3. If the reset bgp command is run, the system regenerates summary routes, and the priorities of these routes are minimized.
  4. If the attribute-policy parameter is specified for a summary route, the attributes of the summary route are modified according to the corresponding policy, but during the period for minimizing the priorities of summary routes, this summary route carries the maximum MED value and the minimum Local_Pref value when it is advertised to BGP peers.
  5. By default, the MEDs of routes received from different ASs are not compared, and the Local_Pref attribute is exchanged only between IBGP peers. That is, minimizing the priorities of summary routes does not take effect on the routes received from different ASs. To configure the device to compare the MEDs of these routes, run the compare-different-as-med command.
  6. If both this command and the peer route-policy export command are run, the MED or Local_Pref value set in the export policy does not take effect on the summary routes to be advertised to the specified BGP peer during the period for minimizing the priorities of summary routes.
  7. When the summary routes with the lowest priority in the VPN instance IPv4 address family are advertised to the BGP-VPNv4 address family or BGP-EVPN address family or the summary routes with the lowest priority in the VPN instance IPv6 address family are advertised to the BGP-VPNv6 address family or BGP-EVPN address family, and the peer route-policy export command is run in the target address family, the MED or Local_Pref value set in the export policy does not take effect on these summary routes.

Example

# Configure the device to advertise summary routes with the lowest priority in the BGP IPv4 VPN address family. 
<HUAWEI> system-view
[HUAWEI] ip vpn-instance vpn1
[HUAWEI-vpn-instance-vpn1] ipv4-family unicast
[HUAWEI-vpn-instance-vpn1-af-ipv4] route-distinguisher 100:1
[HUAWEI-vpn-instance-vpn1-af-ipv4] vpn-target 1:1
 IVT Assignment result:
Info: VPN-Target assignment is successful.
 EVT Assignment result:
Info: VPN-Target assignment is successful.
[HUAWEI-vpn-instance-vpn1-af-ipv4] quit
[HUAWEI-vpn-instance-vpn1] quit
[HUAWEI] bgp 100
[HUAWEI-bgp] ipv4-family vpn-instance vpn1
[HUAWEI-bgp-vpn1] advertise aggregate-route lowest-priority delay-time 100
# Configure the device to advertise summary routes with the lowest priority in the BGP IPv4 unicast address family. 
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] ipv4-family unicast
[HUAWEI-bgp-af-ipv4] advertise aggregate-route lowest-priority delay-time 100
# Configure the device to advertise summary routes with the lowest priority in the BGP IPv6 unicast address family. 
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] ipv6-family unicast
[HUAWEI-bgp-af-ipv6] advertise aggregate-route lowest-priority
