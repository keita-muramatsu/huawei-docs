ping srv6-te policy

Function

The ping srv6-te policy command checks the connectivity of an SRv6 TE Policy and whether the SRv6 TE Policy can ensure normal forwarding.

Format

ping srv6-te policy { policy-name policyName | endpoint-ip endpointIpv6 color colorId | binding-sid bsid } [ force-match-slice ] [ end-op endOp | destination dest ] [ segment-list slid ] [ -a sourceAddr6 | -c count | -m interval | -s packetSize | -t timeout | -tc tc | -h hopLimit ] *

Parameters

Parameter Description Value
policy-name policyName

Specifies the name of an SRv6 TE Policy.

The value is a string of 1 to 255 case-sensitive characters. It cannot contain spaces.
endpoint-ip endpointIpv6

Specifies the endpoint of an SRv6 TE Policy.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.
color colorId

Specifies the color of an SRv6 TE Policy. This parameter applies to the scenario where traffic is diverted to an SRv6 TE Policy based on the color value.

The value is an integer ranging from 0 to 4294967295.
binding-sid bsid

Specifies a binding SID for an SRv6 TE Policy. The End.B6 type defined by a binding SID is mainly used in scenarios such as traffic diversion to SRv6 TE Policies and tunnel interworking.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.
force-match-slice

Forcibly matches slices and takes effect only for segment lists with slice attributes.

-
end-op endOp

Specifies the ID of an End.OP segment. The configuration of this field is as follows:

  • If a ping test is implemented using an End.OP SID in SRv6 OAM extension, you can run the remote end-op command or specify a remote End.OP SID to enable the device to initiate a ping test. Note that if the last SID of an SRv6 TE Policy's segment list is an End.X SID, End.XU SID, or binding SID, the remote end-op command configuration does not take effect. In this case, you need to specify a remote End.OP SID when running the ping srv6-te policy command.
  • If an End SID is used to implement a ping test, you can initiate a ping operation without needing to run the remote end-op command or specify a remote End.OP SID. Note that if the last SID of an SRv6 TE Policy's segment list is an End.X SID, End.XU SID, or binding SID, you need to specify the destination parameter.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.
destination dest

Specifies the local IPv6 address or SRv6 local SID of the destination.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.
segment-list slid

Specify a segment list ID for an SRv6 TE Policy. You can run the display srv6-te policy command to view the segment list ID.

The value is an integer in the range from 1 to 4294967295.
-a sourceAddr6

Specifies the source IPv6 address.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.
-c count

Specifies the number of ICMPv6 Echo Request packets to be sent.

The value is an integer ranging from 1 to 4294967295. The default value is 5.
-m interval

Specifies the waiting time for sending the next ICMPv6 Echo Request packet.

The value is an integer ranging from 1 to 10000, in milliseconds. The default value is 2000.
-s packetSize

Specifies the payload length of an ICMPv6 Echo Request message. The formula for calculating the packet payload length is as follows: Packet payload length = 9600 (MTU) – IPv6 header length – Hop-by-Hop Options header length – SRH length – ICMP header length.

The value is an integer ranging from 65 to 9600, in bytes. The default value is 100.
-t timeout

Specifies the timeout period for waiting for the response to an ICMPv6 Echo Request packet.

The value is an integer ranging from 0 to 65535, in milliseconds. The default value is 2000 milliseconds.
-tc tc

Specifies the traffic class of ICMPv6 Echo Request packets.

The value is an integer ranging from 0 to 255. The default value is 0.
-h hopLimit

Specifies a hop limit value.

The value is an integer ranging from 1 to 255. The default value is 255.

Views

All views

Default Level

0: Visit level

Usage Guidelines

Usage Scenario

On an SRv6 TE Policy network, if data forwarding fails over the SRv6 TE Policy, the control plane for SRv6 establishment cannot detect this failure, making network maintenance difficult. The SRv6 TE Policy ping mechanism can be used to detect such faults and locate faulty nodes. This mechanism is implemented using the ping srv6-te policy command. To test the connectivity of an SRv6 TE Policy, run the ping srv6-te policy command.

Prerequisites

SRv6 has been enabled on the device and is working properly.

Precautions

  • During an SRv6 TE Policy ping test, if the segment list of the SRv6 TE Policy changes, the ping result may be inaccurate. You are advised to press Ctrl_C to stop the test and then initiate the test again.
  • By default, Encapsulation source-address is selected as the source IPv6 address of test packets. If this parameter is not set, select IPv6 router ID. If neither of them is configured, you are advised to use the -a parameter to specify the source address. Otherwise, the test may fail.
  • In a non-TE FRR scenario, if the headend of an SRv6 TE Policy is a local End SID, the next SID cannot be a local End, End.X, or End.XU SID. Otherwise, the ping test fails.
  • In a TE FRR scenario, if there is only one tunnel, the FRR path cannot be used, and the ping test fails.
  • If the last SID of an SRv6 TE Policy is a BSID, the ping command output may be incorrect. You need to run the remote end-op command or specify an End.OP SID or destination to initiate a test. In a scenario where a binding SID is configured on the ingress, you can initiate a test only by specifying an End.OP SID or destination.
  • If the last SID of an SRv6 TE Policy is a compressed SID, you need to specify end-op/destination to initiate a test.
  • When the next hop is specified for a test, the specified next hop address must be the next hop address of the tunnel. Otherwise, the test result may be inaccurate.
  • If both the next hop and outbound interface are specified, they must match each other. Otherwise, the test result may be inaccurate.
  • If the destination parameter is not specified, ping checks only the reachable paths of segment list SIDs.
