display dying-gasp information

Function

The display dying-gasp information command displays the SNMP NMSs that receive dying gasp alarms stored in the chip, including the IP address of the NMS server and the VPN channel through which SNMP packets are reported.

This command is supported only on the AR5710-S8TWDSE-LTE4EA, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5710-S10T1X2, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T and AR5710-S8P1XDSE-2LTE4EA.

Format

display dying-gasp information

Parameters

None

Views

All views

Default Level

3: Management level

Usage Guidelines

Usage Scenario

For devices located at the edge of the network, the power supply conditions are relatively poor. As a result, the devices are prone to power failures. Through the NMS, users can find that a device is unreachable after a period of time, but cannot determine whether the fault is caused by a device fault (power-off) or a network fault (fiber cut).

To resolve this problem, the dying gasp function can be used. After the device is powered off, the chip of the device can still run for a short period of time with the help of the capacitor. In addition, the chip sends the preset dying gasp alarm to the NMS. In this way, the user is notified of the power-off event, which helps the user quickly locate the fault.

A maximum of 20 SNMP NMSs can be configured, but the chip can store only four copies of preset dying gasp alarms. You can run the display dying-gasp information command to check the SNMP NMSs that receive dying gasp alarms stored in the chip, including the IP address of the NMS server and the VPN channel for reporting SNMP packets.

Prerequisites

To trigger the dying gasp function, perform the following operations to ensure that the device can communicate with the NMS through SNMP and send traps to the NMS. For details, see CLI Configuration Guide > System Management Configuration > SNMP Configuration.

  • Configure basic SNMP functions on the device.
  • Configure the SNMP trap function on the device.
  • Configure the NMS (by referring to the NMS configuration manual) so that the device can communicate with the NMS.

Precautions

  • Only Ethernet interfaces that carry services can send dying gasp alarms to the NMS.
  • If multiple NMSs are configured using the snmp-agent target-host command, only the dying gasp alarms of the last two NMSs can be stored in the chip and sent out when the device is powered off.
  • The alarm message is updated every 2 minutes to ensure that the alarm time received by the NMS is correct.
  • The rules for storing alarm messages in the chip are as follows:

    Rule 1: After an SNMP configuration is added, if the number of SNMP configurations on the device is less than or equal to 2, the device stores all preset dying gasp messages in the chip.

    Rule 2: After an SNMP configuration is added, if the number of SNMP configurations on the device is greater than 2, the device randomly selects two preset dying gasp messages and stores them in the chip.

    Rule 3: After an SNMP configuration is deleted, if the number of SNMP configurations on the device is less than 2, the device immediately updates the preset dying gasp messages stored in the chip.

    Rule 4: After an SNMP configuration is deleted, if the number of SNMP configurations on the device is greater than or equal to 2, the device immediately deletes the specified preset dying gasp messages from the chip and randomly selects two preset dying gasp messages within 2 minutes.

    Rule 5: When the VPN in the SNMP configuration is modified, the old preset dying gasp messages stored in the chip are not deleted immediately. Instead, a new preset dying gasp message is added according to rules 1 and 2. During query, the Vpn-instance field of the old preset dying gasp messages is empty and the dying gasp messages are aged within 5 minutes.

    Rule 6: If two or more SNMP configurations contain the same VPN and IP address, the device randomly selects one preset dying gasp message and stores it in the chip. When one of the SNMP configurations is deleted, the preset dying gasp messages in the chip are also deleted. The remaining preset dying gasp messages are stored in the chip within 2 minutes.

Example

The actual command output varies according to the device. The command output here is only an example.

# Query the dying gasp information.
<HUAWEI> display dying-gasp information
Dying-gasp IP Information:
[No.0]
  IP:10.1.1.1
  Vpn-instance:_public_
[No.1]
  IP:10.1.1.2
  Vpn-instance:_public_
Table 1 Description of the display dying-gasp information command output
Item Description
IP

Indicates the IP address of the NMS server that receives the dying gasp alarm.
Vpn-instance

Indicates the VPN channel from which SNMP packets are sent to the NMS.
