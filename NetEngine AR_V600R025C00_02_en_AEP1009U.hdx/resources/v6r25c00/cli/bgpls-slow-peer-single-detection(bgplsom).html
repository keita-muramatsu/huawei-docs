slow-peer single-group detection(BGP-LS address family view)

Function

The slow-peer single-group detection threshold command sets the absolute time threshold for detecting slower peers in a slow update peer-group.

The undo slow-peer single-group detection threshold command restores the default absolute time threshold for detecting slower peers in a slow update peer-group.

By default, the absolute threshold for slower peer detection in a slow update peer-group is 300s.

Format

slow-peer single-group detection threshold threshold-value

undo slow-peer single-group detection threshold threshold-value

Parameters

Parameter Description Value
threshold-value

Specifies the absolute detection time threshold for detecting a slower peer in a slow update peer-group. If the time taken to send messages to a slow peer in the slow update peer-group is greater than the specified threshold, the slow peer is considered as a slower peer in the slow update peer-group.

The value is an integer that ranges from 300 to 3600, in seconds. The default value is 300.

Views

BGP-LS address family view

Default Level

2: Configuration level

Usage Guidelines

A slow update peer-group may contain multiple slow peers. If a network problem (congestion for example) occurs and slows down the speed at which the local device advertises routes to a slow peer, the speed at which the local device advertises routes to other peers in the slow update peer-group is also affected. To prevent this problem, you can enable hierarchical slow-peer switching, which allows the slowest peer in a slow update peer-group to be automatically switched to a new slow update peer-group. This new slow update peer-group consists of only this peer.

After hierarchical slow-peer switching is enabled, the local device calculates the time taken to send messages to each slow peer in the slow update peer-group. If the time taken to send messages to a peer is greater than or equal to the absolute time threshold for detecting slower peers to implement hierarchical slow-peer switching, the local device considers this peer as a slower peer. If all the other peers in the slow update peer-group have received messages from the device at this time, the device switches the preceding slower peer from the current update peer-group to a single-peer update peer-group, which prevents this slower peer from affecting route advertisement to other peers in the current update peer-group.

For example, there are three slow peers A, B, and C in a slow update peer-group on the local device, and the absolute time threshold for detecting slower peers in the slow update peer-group is 300s. The local device calculates the time taken to send messages to each slow peer in the slow update peer-group in sequence. If the time taken to send messages to slow peer A is 400s and slow peers B and C have received messages from the device, slow peer A is removed from the current slow update peer-group and added to a single-peer update peer-group. If slow peers B and C have not received messages from the device, slow peer A is not removed from the current slow update peer-group. Instead, the device continues to calculate the time taken to send messages to slow peer B or C and repeats the comparison rule for slow peer A.

Example

# Set the absolute threshold for slower peer detection in a slow update peer-group to 600s.
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] link-state-family unicast
[HUAWEI-bgp-af-ls] slow-peer single-group detection threshold 600
