tracert srv6-te policy

Function

The tracert srv6-te policy command tests the nodes through which an SRv6 TE Policy passes.

Format

tracert srv6-te policy { policy-name policyName | endpoint-ip endpointIpv6 color colorId | binding-sid bsid } [ force-match-slice ] [ end-op endOp | destination dest ] [ segment-list slid ] [ -a sourceAddr6 | -f initHl | -m maxHl | -s packetSize | -w timeout | -p destPort | -tc tc ] *

Parameters

Parameter Description Value
policy-name policyName

Specifies the name of an SRv6 TE Policy.

The value is a string of 1 to 255 case-sensitive characters. It cannot contain spaces.
endpoint-ip endpointIpv6

Specifies the endpoint of an SRv6 TE Policy.

The value is a 32-digit hexadecimal number in format X:X:X:X:X:X:X:X.
color colorId

Specifies a color value for an SRv6 TE Policy. This parameter applies to the scenario where traffic is diverted to an SRv6 TE Policy based on the color value.

The value is an integer ranging from 0 to 4294967295.
binding-sid bsid

Specifies a binding SID for an SRv6 TE Policy. The End.B6 type defined by a binding SID is mainly used in scenarios such as traffic diversion to SRv6 TE Policies and tunnel interworking.

The value is a 32-digit hexadecimal number in format X:X:X:X:X:X:X:X.
force-match-slice

Forcibly matches slices, taking effect only for segment lists with slice attributes.

-
end-op endOp

Specifies the ID of an End.OP segment. The configuration of this field is as follows:

  • If a tracert test is implemented using an End.OP SID in SRv6 OAM extension, you can run the remote end-op command or specify a remote End.OP SID to enable the device to initiate a tracert test. Note that if the last SID of an SRv6 TE Policy's segment list is an End.X SID, End.XU SID, or binding SID, the remote end-op command configuration does not take effect. In this case, you need to specify a remote End.OP SID when running the tracert srv6-te policy command.
  • If an End SID is used to implement a tracert test, you can initiate a tracert operation without needing to run the remote end-op command or specify a remote End.OP SID. Note that if the last SID of an SRv6 TE Policy's segment list is an End.X SID, End.XU SID, or binding SID, you need to specify the destination parameter.

The value is a 32-digit hexadecimal number in format X:X:X:X:X:X:X:X.
destination dest

Specifies the local IPv6 address or SRv6 local SID of the destination.

The value is a 32-digit hexadecimal number in format X:X:X:X:X:X:X:X.
segment-list slid

Specify a segment list ID for an SRv6 TE Policy. You can run the display srv6-te policy command to view the segment list ID.

The value is an integer in the range from 1 to 4294967295.
-a sourceAddr6

Specifies the source IPv6 address.

The value is a 32-digit hexadecimal number in format X:X:X:X:X:X:X:X.
-f initHl

Specifies the initial hop limit.

The value is an integer ranging from 1 to 255. The default value is 1.
-m maxHl

Specifies the maximum hop limit.

The value is an integer ranging from 1 to 255. The default value is 64.
-s packetSize

Specifies the payload length of a UDP packet.

The value is an integer ranging from 65 to 9600, in bytes. The default value is 100.
-w timeout

Specifies a timeout time for waiting for the response to a UDP packet.

The value is an integer ranging from 1 to 65535, in milliseconds. The default value is 2000.
-p destPort

Specifies a destination UDP port number.

The value is an integer ranging from 1 to 65535. The default value is 33434.
-tc tc

Specifies a traffic class for UDP packets to be sent.

The value is an integer ranging from 0 to 255. The default value is 0.

Views

All views

Default Level

0: Visit level

Usage Guidelines

Usage Scenario

On a network with an SRv6 TE Policy deployed, if data forwarding fails over the SRv6 TE Policy, the control plane (responsible for SRv6 TE Policy establishment) cannot detect this failure, complicating network maintenance. The SRv6 TE Policy tracert mechanism can be used to detect such failures and quickly locate faulty nodes. You can run this command to check the gateways through which an SRv6 TE Policy passes. The command output helps you locate faulty nodes on the network, facilitating fault diagnosis.

The formula for calculating the packet payload length is as follows:

Packet payload length = 9600 (MTU) – IPv6 header length – Hop-by-Hop Options header length – SRH length – UDP header length

Prerequisites

SRv6 has been enabled on the device and is working properly.

Precautions

  • During an SRv6 TE Policy tracert test, if the segment list of the SRv6 TE Policy changes, the tracert result may be inaccurate. You are advised to press Ctrl_C to stop the test and then initiate the test again.
  • By default, Encapsulation source-address is selected as the source IPv6 address of test packets. If this parameter is not set, select IPv6 router ID. If neither of them is configured, you are advised to use the -a parameter to specify the source address. Otherwise, the test may fail.
  • In a non-TE FRR scenario, if the headend of an SRv6 TE Policy is a local End SID, the next SID cannot be a local End, End.X, or End.XU SID. Otherwise, the tracert test fails.
  • During BSID encapsulation, the newly encapsulated IPv6 header does not inherit the inner TTL value. As a result, the transit paths may not be displayed in the tracert command output.
  • If the last SID of an SRv6 TE Policy is a BSID, the tracert command output may be incorrect. You need to run the remote end-op command or specify an End.OP SID or destination to initiate a test. In a scenario where a binding SID is configured on the ingress, you can initiate a test only by specifying an End.OP SID or destination.
  • If the last SID of an SRv6 TE Policy is a compressed SID, you need to specify end-op/destination to initiate a test.
  • When the next hop is specified for a test, the specified next hop address must be the next hop address of the tunnel. Otherwise, the test result may be inaccurate.
  • If both the next hop and outbound interface are specified, they must match each other. Otherwise, the test result may be inaccurate.
  • If a binding SID is configured for a transit node and the binding policy has only one local SID, the tracert result may be inaccurate.
  • If the destination parameter is not specified, tracert checks only the reachable paths of segment list SIDs.
