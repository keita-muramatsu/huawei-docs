hrp preempt delay

Function

The hrp preempt delay command configures an HRP preemption delay.

The undo hrp preempt delay command restores the HRP preemption delay to the default value.

By default, the HRP preemption delay is 60s.

Format

hrp preempt delay interval

undo hrp preempt delay

Parameters

Parameter Description Value
interval

Specifies a preemption delay.

The value is an integer ranging from 0 to 1800, in seconds.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

In active/standby networking, if the active device fails, the standby device takes over the services. To configure the active device to automatically take over the services after it recovers, enable the HRP preemption function on the active device.

In load-balancing networking, two devices process services. If one device fails, the other device takes over the services immediately. Generally, the device that recovers is expected to take over services so that the two devices work in load-balancing mode. To achieve this, enable the HRP preemption function on the two devices in load-balancing mode.

Configuration Impact

If the preemption delay is set to 0, the device immediately preempts the active role right after a fault is rectified. If the preemption delay is set to a non-0 value, the device preempts the active role only after the preemption delay expires. In general, you are advised to set a preemption delay for route convergence and entry backup.

On a network where traffic is heavy and route convergence takes a long time, it is recommended to set the preemption delay to a large value or disable proactive preemption to prevent service anomalies caused by preemption.

The new preemption delay takes effect next time a fault recovers and preemption delay is calculated. If the device is waiting for preemption after a fault recovery, the configuration change does not take effect immediately.

Precautions

The preempt delay takes effect only after the hrp preempt enable command is enabled. Setting the preempt delay to 0 or a small value is not recommended as service exceptions may occur.

In hot standby mode, if VRRP and dynamic routing protocols run on the devices and their upstream and downstream devices, ensure that the preemption delay for the HRP groups is longer than the convergence period of the dynamic routing protocols (such as OSPF) to prevent service interruptions. Or you can disable the preemption function.

Example

# Set the HRP preemption delay to 100s.
<HUAWEI> system-view
[HUAWEI] hrp preempt delay 100
