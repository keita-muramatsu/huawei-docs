mtu (interface view)

Function

The mtu command sets the maximum transmission unit (MTU) value for an interface to send IPv4 packets.

The undo mtu command restores the default MTU value for an interface to send IPv4 packets.

The default MTU value varies according to the hardware and interface. For details, see the parameter description field.

Format

mtu mtu

undo mtu

Parameters

Parameter Description Value
mtu

Specifies the MTU of an Ethernet interface.

The value is an integer. The value ranges and default values of common interfaces are as follows:

  • Ethernet interface and its sub-interfaces: The value is an integer ranging from 46 to 9216, in bytes. The default value is 1500.
  • Tunnel interface: The value is an integer ranging from 46 to 9216, in bytes. The default value is 1500.
  • Eth-Trunk interface and its sub-interfaces: The value is an integer ranging from 46 to 9216, in bytes. The default value is 1500.
  • VLANIF interface: The value is an integer ranging from 46 to 9216, in bytes. The default value is 1500.
  • Dialer interface: The value is an integer ranging from 128 to 2000, in bytes. The default value is 1492.

The preceding values are for reference only. The value ranges and default values vary according to hardware and interfaces. The supported interface types, value ranges, and default values depend on the device model. You can run the display default-parameter interface command to check the MTU of an interface.

Usage Guidelines

Usage Scenario

The maximum length of frames that are sent each time is typically limited during network transmission. Each time the IP layer receives an IP packet to be sent, it checks which local interface the packet needs to be sent to and queries the interface's MTU. The IP layer then compares the MTU with the length of the packet to be sent. If the packet length exceeds the MTU, the IP layer fragments the packet to ensure that each fragment is no longer than the MTU.

If forcible unfragmentation is configured, certain packets are lost during data transmission at the IP layer. To ensure that jumbo packets are not dropped during transmission, you need to configure forcible fragmentation. To set the MTU for fragments, run this command.

Configuration Impact

If the MTU is set too small and the size of packets is large, packets are broken into a great number of fragments, and may be discarded by QoS queues.

Precautions

The MTU cannot be configured for sub-interfaces. You can configure the MTU for a main interface and then run the mtu spread command to spread the MTU to its sub-interfaces.

You are advised to set the same MTU value on both ends of a link to prevent the impact on the running of protocols (such as OSPF and IS-IS) and packet forwarding. After an OSPF or IS-IS neighbor relationship is established, changing the MTU of the interface on a single end may cause the neighbor relationship to go down.

For IS-IS:

  • If the MTU is changed after an IS-IS neighbor relationship is established, IS-IS services may be interrupted. Exercise caution when performing this operation.
  • If the MTU configured on an interface is smaller than the value of max-size configured using the lsp-length originate command plus 3, the neighbor relationship on the interface goes down immediately.
  • By default, a broadcast interface sends standard Hello packets with the padding field. If the MTU values on both ends of a link are different, the local or remote neighbor relationship may go down due to timeout.
  • After a neighbor relationship is established on a P2P interface or a broadcast interface configured with the isis small-hello command, the interface sends small Hello packets without the padding field. After a neighbor relationship is established, if the MTU values of the interfaces on both ends of the link are changed to be different, the neighbor relationship does not go down immediately. However, the neighbor relationship may fail to be re-established after it goes down due to other reasons.

For OSPF:

  • By default, MTU check is disabled on an OSPF interface, and the MTU value in DD packets is 0 before the interface sends them. If the MTU values on both ends of a link are different, an OSPF neighbor relationship can be established. Changing the interface MTU value does not re-establish the neighbor relationship. However, the packets whose length exceeds the local MTU value sent by the peer end may be discarded, and the routes carried in the packets cannot be learned. As a result, services may be interrupted.
  • After the ospf mtu-enable command is run on an OSPF interface and MTU check is enabled, the interface fills the MTU value in DD packets before sending them. In addition, the device checks whether the MTU value carried in DD packets from the neighbor exceeds the local MTU value. If this occurs, the device does not establish an OSPF neighbor relationship. If the interface MTU value is changed, the device attempts to re-establish an OSPF neighbor relationship. If the MTU values are different, the OSPF neighbor relationship cannot be established.
  • If there is a transmission device between the devices that establish an OSPF neighbor relationship, ensure that the MTU value configured for the transmission device is not less than the MTU value configured for the OSPF interface. Otherwise, packet loss may occur, affecting the establishment of the OSPF neighbor relationship.

Example

# Set the MTU of an interface to 1400 bytes. The example is for reference only. Set the MTU as required. 
<HUAWEI> system-view
[HUAWEI] interface 10GE0/0/1
[HUAWEI-10GE0/0/1] mtu 1400
