add (URL filtering profile view)

Function

The add command adds blacklist and whitelist rules to a URL filtering profile.

The undo add command deletes blacklist and whitelist rules from the URL filtering profile.

By default, no configuration is performed.

This command is supported only on the AR5710-S8TWDSE-LTE4EA, AR8700 series, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4, AR8100 series, AR5710-S8P1XDSE-2LTE4EA and AR6700-H series.

Format

add { blacklist | whitelist } { url url-text | host host-text }

undo add { blacklist | whitelist } { url { url-text | all } | host { host-text | all } | all }

Parameters

Parameter Description Value
blacklist

Adds a blacklist rule.

-
whitelist

Adds a whitelist rule.

-
url url-text

Adds a URL rule.

The value is a string of 4 to 255 case-insensitive characters without question marks (?).

The system removes the prefix http:// or https:// from the entered character string.

The value cannot start with a backslash (\) or slash (/).

The asterisk (*) can be used at the beginning, middle, or end of a rule to indicate a wildcard.

The value must contain three or more consecutive character strings before or after the wildcard. If the string contains three characters, it cannot end with a period (.). For example, ab.*, *ab., and ab*cd. are not supported.

If the entered domain name does not contain the wildcard, it must contain at least four consecutive characters and cannot end with a period (.). For example, abc. is not supported.

There are at least three consecutive character strings that are not asterisks (*) before the number sign (#). If the length of the character string before the number sign (#) is 3 (excluding *), the last character cannot be a period (.).

If the rule contains spaces, enclose it with double quotation marks ("") and ensure that the quotation marks are used in pairs, for example, "abc def".

If the value contains double quotation marks (""), it must be converted to %22, for example, "abc%22def".
host host-text

Adds a domain name rule.

The value is a string of 4 to 255 case-insensitive characters. It cannot contain special characters such as /, \, #, ", ?, and spaces.

The system removes the prefix http:// or https:// from the entered character string.

The asterisk (*) can be used at the beginning, middle, or end of a rule to indicate a wildcard.

The value must contain three or more consecutive character strings before or after the wildcard. If the string contains three characters, it cannot end with a period (.). For example, ab.*, *ab., and ab*cd. are not supported.

If the entered domain name does not contain the wildcard, it must contain at least four consecutive characters and cannot end with a period (.). For example, abc. is not supported.
all

Deletes all rules.

-

Views

URL filtering profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Blacklist:

To improve work efficiency of employees and fully utilize network bandwidth, enterprises need to control online behaviors of employees and prevent them from accessing entertainment, game, and video websites.<br /> The URL blacklist enables the device to match HTTP requests. If a URL in an HTTP request matches an entry in the configured blacklist, the device prevents the access to the requested website.

Whitelist:

When enterprises have special requirements and do not need to filter requests for certain websites.

The URL whitelist enables the device to match HTTP requests. If a URL in an HTTP request matches an entry in the configured whitelist, the device allows access to the requested website. The whitelist can improve the match efficiency.

Precautions

The same URL or host rule configured in different URL filtering profiles is counted in the configured URL blacklist and whitelist entries, but does not occupy extra user-defined URL resources. Therefore, the number of used exact URL (user-defined url) and fuzzy URL (user-defined rule) resources displayed in the display engine resource information command output may be different from the actual number of configured URL blacklist and whitelist entries.

After running this command, run the engine configuration commit command to commit the configuration for the configuration to take effect. You are advised to commit the configuration after all content security configurations are complete.

Example

# Create URL filtering profile profile_development and add www.example.com to the blacklist. 
<HUAWEI> system-view
[HUAWEI] profile type url-filter name profile_development
[HUAWEI-profile-url-filter-profile_development] add blacklist url www.example.com
