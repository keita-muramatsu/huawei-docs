peer bfd frr-binding single-hop(BGP-VPN instance IPv6 address family view)(group)

Function

The peer bfd frr-binding single-hop command configures single-hop BGP BFD FRR for a peer group.

The undo peer bfd frr-binding single-hop command restores the default configuration.

By default, single-hop BGP BFD FRR is not enabled.

Format

peer peerGroupName bfd frr-binding single-hop

undo peer peerGroupName bfd frr-binding single-hop

Parameters

Parameter Description Value
peerGroupName

Specifies the name of a peer group.

The name is a string of 1 to 47 case-sensitive characters, with spaces not supported. When double quotation marks are used around the string, spaces are allowed in the string.

Views

BGP-VPN instance IPv6 address family view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

After BFD is enabled on a directly connected BGP peer, BGP dynamically creates a single-hop BFD session for the peer. If the auto FRR function is configured but the peer bfd frr-binding single-hop command is not run on the device, it takes about 100 ms for BGP to switch traffic to the backup link after the primary link fails. During this period, traffic may be interrupted. After this command is run and BGP auto FRR is enabled on the device, if an interface or link fault occurs on a remote Layer 2 device or a transmission device, the underlying layer can quickly respond to the link change, the BFD session goes down, and BGP then rapidly switches traffic to the backup link, implementing FRR and protecting traffic.

Prerequisites

The corresponding peer group relationship has been established using the group command.

Precautions

If the peer bfd frr-binding single-hop command is run on a peer to be added to a peer group or on a peer already in a peer group, the peer does not inherit the configuration of the peer group. If a peer that has inherited the configuration of its peer group is removed from the group, the peer retains the configuration of the peer group and changes the configuration to its own configuration.

If the address of a specified peer is an IPv6 link-local address, single-hop BGP BFD FRR cannot be enabled for the peer.

If the address of a peer in a specified peer group is an IPv6 link-local address, single-hop BGP BFD FRR can be enabled for the peer group only after the peer bfd frr-binding single-hop disable command is run for this peer.

After the peer bfd frr-binding single-hop command is run, single-hop BFD sessions are preferentially established. If the BFD session types at both ends are different after this command is run, the peer bfd enable [ single-hop-prefer ] compatible command must be run first. Otherwise, the BFD sessions cannot go up.

Example

# Enable single-hop BGP BFD FRR for a peer group.
<HUAWEI> system-view
[HUAWEI] ip vpn-instance vrf1
[HUAWEI-vpn-instance-vrf1] ipv6-family unicast
[HUAWEI-vpn-instance-vrf1-af-ipv6] route-distinguisher 1:2
[HUAWEI-vpn-instance-vrf1-af-ipv6] quit
[HUAWEI-vpn-instance-vrf1] quit
[HUAWEI] bgp 100
[HUAWEI-bgp] ipv6-family vpn-instance vrf1
[HUAWEI-bgp-6-vrf1] group a
[HUAWEI-bgp-6-vrf1] peer a bfd frr-binding single-hop
