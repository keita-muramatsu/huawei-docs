ldp-sync enable (IS-IS view)

Function

The ldp-sync enable command enables LDP-IGP synchronization on all IGP interfaces in an IGP process or instance.

The undo ldp-sync enable command disables LDP-IGP synchronization on all interfaces in an IGP process or instance.

LDP-IGP synchronization is disabled on all IGP interfaces by default.

Format

ldp-sync enable

ldp-sync enable mpls-binding-only

undo ldp-sync enable

Parameters

Parameter Description Value
mpls-binding-only

Enables synchronization between LDP and IS-IS only on MPLS LDP interfaces in an IS-IS process. This parameter can only be configured in the IS-IS view.

-

Views

IS-IS view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

LDP-IGP synchronization reduces LSP traffic loss on a network with both primary and backup LSPs. Traffic loss occurs in either of the following situations:

  • The primary link works properly and an LDP local session or LDP adjacency between two nodes on the primary LSP fails. IGP still uses the primary link. As a result, LSP traffic cannot be switched to the standby link, and traffic is continuously discarded. In this situation, you can configure LDP-IGP synchronization. If an LDP local session or LDP adjacency fails, the IGP advertises the maximum cost of the faulty link. The route is switched to the standby link, and the LSP is also switched to the standby link.
  • If a link on the primary LSP recovers, IGP routes converge. IGP routes associated with the primary LSP become reachable earlier than the primary LSP because IGP routes converge faster than LDP routes. Revertive traffic is discarded because the backup LSP becomes unavailable after the IGP convergence is complete but the primary LSP is not established. In this situation, you can configure LDP-IGP synchronization. If a link on the primary LSP recovers, IGP advertises the maximum cost of the active link, delaying the IGP route switchback until LDP convergence is complete.
  • IS-IS view: IS-IS-enabled interface on a local device. If the mpls-binding-only parameter is configured, synchronization between LDP and IS-IS can only be enabled on MPLS LDP-enabled IS-IS interfaces.

Follow-up Procedure

After this command is run, LDP-IGP synchronization is enabled on all interfaces in an IGP process or instance. To disable LDP-IGP synchronization on an interface, run the isis ldp-sync block command.

Precautions

LDP-IGP synchronization can be configured globally or on a specified interface. The system preferentially uses the configuration on the interface. Therefore, for IS-IS, if the isis ldp-sync command is run on an interface, synchronization between LDP and IS-IS is still enabled on the interface even if mpls-binding-only is configured.

Before running this command, ensure that LDP is enabled on all IGP-enabled interfaces. Otherwise, services on LDP-disabled interfaces may be affected.

If LDP-IGP synchronization is enabled and the value of the hold-max-cost timer is not set, the IGP advertises the maximum cost of the link during the interruption of an LDP session or LDP adjacency. The cost can be restored only after the LDP session recovers. In a scenario where a backup link exists, after the primary link recovers, the LDP session attempts to be reestablished. Because the IGP advertises the maximum cost on the primary link, TCP connection establishment or LDP packets are sent to the peer end through the backup link. If the backup link fails to forward traffic or a security policy is configured, TCP connections may fail to be established or LDP packets may be discarded. As a result, LDP sessions cannot be established, and the IGP continuously advertises the maximum cost on the primary link. Therefore, when LDP-IGP synchronization is used, ensure that LDP packets are forwarded properly on the backup link. Otherwise, the backup link is used all the time.

In addition, when the IGP carries multiple types of services, including LDP services, LDP-IGP synchronization is enabled, and the hold-max-cost timer is not set, the IGP keeps advertising the maximum cost on the primary link when the LDP session or LDP adjacency on the primary link is interrupted. As a result, IGP route selection and other services may be affected. Therefore, when the IGP carries multiple types of services, including LDP services, you can set a proper value for the hold-max-cost timer to reduce the impact of the LDP session or LDP adjacency interruption on IGP route selection and other services.

Example

# Enable LDP and IS-IS synchronization on all interfaces in an IS-IS instance.
<HUAWEI> system-view
[HUAWEI] isis 100
[HUAWEI-isis-100] network-entity 10.0001.1010.1020.1030.00
[HUAWEI-isis-100] ldp-sync enable
