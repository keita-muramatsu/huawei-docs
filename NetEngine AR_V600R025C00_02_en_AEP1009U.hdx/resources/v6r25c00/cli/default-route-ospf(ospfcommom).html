default-route-advertise (OSPF view)

Function

The default-route-advertise command advertises default routes to a common OSPF area.

The undo default-route-advertise command disables advertisement of default routes to a common OSPF area.

By default, default routes are not advertised to a common OSPF area.

Format

default-route-advertise [ [ always | permit-calculate-other ] | cost costvalue | type typevalue | route-policy route-policy-name [ match-any ] | distribute-delay delaytimer | tag tagvalue ] *

default-route-advertise summary cost costvalue

default-route-advertise [ permit-calculate-other | cost costvalue | type typevalue | route-policy route-policy-name [ match-any ] | distribute-delay delaytimer | permit-ibgp | tag tagvalue | permit-preference-less-than preference-val ] *

undo default-route-advertise summary cost costvalue

undo default-route-advertise [ [ always | permit-calculate-other ] | cost costvalue | type typevalue | route-policy route-policy-name [ match-any ] | distribute-delay delaytimer | tag tagvalue ] *

undo default-route-advertise [ permit-calculate-other | cost costvalue | type typevalue | route-policy route-policy-name [ match-any ] | distribute-delay delaytimer | permit-ibgp | tag tagvalue | permit-preference-less-than preference-val ] *

Parameters

Parameter Description Value
always

Generates and advertises an LSA that describes a default route, regardless of whether the local device has active default routes from processes other than the local OSPF process.

-
permit-calculate-other

Configures the device to calculate default Type 5 LSAs from other devices if this parameter is specified and the OSPF process has advertised Type 5 LSAs that describe a default route. If this parameter is not specified, the OSPF process does not calculate default Type 5 LSAs from other devices.

If an OSPF process does not advertise Type 5 LSAs that describe a default route, the OSPF process calculates the default Type 5 LSAs from other devices, regardless of whether this parameter is specified.

-
cost costvalue

Specifies the cost of external routes.

  • Cost of a Type 1 external route = Cost of the route from the Router to the related ASBR + Cost of the route from the ASBR to the destination.
  • Cost of a Type 2 external route = Cost of the route from the ASBR to the destination.

The value is an integer ranging from 0 to 16777214. The default value is 1.
type typevalue

Specifies the type of the external routes.

The value is 1 or 2.

  • 1: Type 1 external route
  • 2: Type 2 external route

The default value is 2.
route-policy route-policy-name

Specifies the name of a route-policy. When the device's routing table contains matching routes that are not generated by the local OSPF process, the device advertises the default routes based on parameters of the route-policy.

The value is a string of 1 to 200 case-sensitive characters without spaces. The character string can contain spaces if it is enclosed with double quotation marks (").
match-any

Configures OSPF to advertise the default route as long as any route in the IP routing table matches the specified route-policy and to generate the default route based on the attributes of the optimal route if multiple routes match the route-policy.

-
distribute-delay delaytimer

Specifies the delay timer for advertising the default route.

The value is an integer ranging from 1 to 65535, in seconds.
tag tagvalue

Indicates the tag value of the default route to be advertised.

The value is an integer ranging from 0 to 4294967295. The default value is 1.
summary

Advertises the Type 3 summary LSA of the specified default route. Before specifying this parameter, ensure that VPN is enabled. Otherwise, routes cannot be advertised.

-
permit-ibgp

Imports IBGP routes.

-
permit-preference-less-than preference-val

Configures OSPF to advertise a default LSA for an active route in the IP routing table only when the preference of this route is smaller than the configured value.

It is recommended that this parameter be set to a value less than the preference of external routes in the current OSPF process. The default preference of external routes in an OSPF process is 150.

The value is an integer ranging from 1 to 256.

Views

OSPF view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The import-route (OSPF) command cannot be used to import external default routes. To import the default routes generated by other protocols, you need to run the default-route-advertise command on the ASBR to advertise the default routes to the entire common OSPF areas.

If the ASBR has a default route 0.0.0.0, it advertises the default route in the entire OSPF areas after the default-route-advertise command is run.

If the ASBR does not have a default route, when running the default-route-advertise command, determine whether to specify the always parameter.

  • If always is configured, the ASBR advertises the default route 0.0.0.0 in the entire OSPF areas regardless of whether the ASBR has a default route, and the ASBR no longer calculates the default routes from other devices.
  • If always is not configured, the device generates the LSA for the default route only if there are active default routes that do not belong to the current OSPF process (except BGP) in the local routing table.

If the local routing table contains active default BGP routes, the following situations occur:

  • If the ospf vpn-instance command is not run, the active EBGP default routes in the routing table can be imported to OSPF after the default-route-advertise command is run. In this case, the OSPF process cannot import IBGP routes. The active IBGP default routes in the routing table can be imported to OSPF only after the default-route-advertise permit-ibgp command is run.
  • If the ospf vpn-instance command is run:
    • If the vpn-instance-capability simple command is also run, the active EBGP default routes in the routing table can be imported to OSPF after the default-route-advertise command is run. In this case, the OSPF process cannot import IBGP default routes. The active IBGP default routes in the routing table can be imported to OSPF only after the default-route-advertise permit-ibgp command is run.
    • If the vpn-instance-capability simple command is not run, active BGP (including EBGP and IBGP) default routes in the routing table can be imported to OSPF after the default-route-advertise command is run.

      Importing IBGP routes may cause routing loops. Therefore, exercise caution when configuring IBGP route import.

If both primary and backup paths exist, packets may get lost after traffic switches back to the primary path from the backup path. When there are a large number of routes, traffic loss is more serious. To solve this problem, run the default-route-advertise distribute-delay delaytimercommand on the device on the primary path to delay sending the OSPF default route. This ensures that traffic is switched back after the device on the primary path completes updating forwarding entries.

If match-any is specified, all routes in the IP routing table are traversed. If a route meets the specified conditions, the OSPF default route is advertised. However, the following types of routes are not traversed:

  • Routes advertised by the local OSPF process in the IP routing table.
  • IBGP routes on the device if the device is not a PE and permit-ibgp is not specified in the default-route-advertise command.
  • Routes whose preference value is greater than or equal to the specified preference if permit-preference-less-than is specified in the default-route-advertise command.

If match-any is configured and multiple routes meet the conditions of the specified route-policy, the device selects the optimal route according to the following rules and generates a default route based on the attributes of the optimal route:

  • First, the routes whose cost-type is set through the route-policy are preferred to those whose cost-type is not set through the route-policy. If all the routes have their cost-type set through the route-policy, the one with the smallest cost-type value is preferred.
  • Second, the routes whose cost values are set through a route-policy are preferred to those whose cost values are not set through a route-policy. If all the routes have their cost values set through a route-policy, the one with the smallest cost value is preferred.
  • Last but not least, the routes whose tag values are set through a route-policy are preferred to those whose tag values are not set through a route-policy. If all the routes have their tag values set through a route-policy, the one with the smallest tag value is preferred.

Configuration Impact

After the default-route-advertise command is configured on the ASBR, the ASBR will generate a Type 5 ASE LSA with link state ID 0.0.0.0 and mask 0.0.0.0. In addition, it will advertise the ASE LSA in an entire OSPF area.

If a route-policy is configured, default routes are advertised based on the following principles:

  • If a default route matches the route-policy, a new default route is generated on an OSPF device based on the parameters configured in the route-policy. Parameters such as cost, tag, and type can be configured in the route-policy.
  • If the default route does not match the route-policy, and always is configured, the default route is still advertised.
  • If always is not configured, the OSPF device will not advertise the default route.
  • If always is configured, OSPF devices will advertise the default route. In addition, only always configured in the default-route-advertise command takes effect on advertisement of default routes.

Precautions

  • The OSPF default route advertisement mode depends on the type of area to which the default route is imported. This command is used to advertise default routes to a common OSPF area. Default routes are automatically advertised in stub areas, totally stub areas, and totally NSSAs. To advertise default routes in an NSSA, run the nssa default-route-advertise command.
  • If the default-route-advertise command is run for an OSPF process and always is not specified, the default LSA is advertised based on the active default route that does not belong to the current OSPF process in the IP routing table. The priority of this default route must be higher than that of OSPF routes; otherwise, OSPF may fail to advertise the default LSA, or a routing loop may occur. To prevent low-priority active default routes from being imported, which would otherwise cause routing loops, you are advised to specify the permit-preference-less-than parameter. This parameter is used only when always is not specified.
  • After always is configured, the device advertises default routes unconditionally. Therefore, if some route sources are unreachable due to faults, route blackholes may occur. You are advised to select always based on the networking plan.
  • If permit-calculate-other is not specified and OSPF advertises a default route first, the device does not calculate the default routes from other devices. If OSPF learns a default route first and the route is active, OSPF does not advertise its own default routes. If a device restarts or route flapping occurs, the sequence in which OSPF learns and advertises default routes may change, causing service traffic changes. To prevent this problem, you are advised to specify the permit-calculate-other parameter.
  • If a route-policy or route-filter is used, attributes (cost-type, cost, and tag) configured in the route-policy or route-filter (rather than the attributes configured in the command) are preferentially used as the advertised LSA attributes.
  • If route-policy route-policy-nameis specified in this command, the following items can be matched: the AS_Path filter, community filter, VPN-Target extended community filter, outbound interface, IP route destination address ACL, IP route destination address prefix list, IP route next-hop address ACL, IP route next-hop address prefix list, route source IP address, route source IP address ACL, route cost, route type, route tag, MPLS label, RPKI origin AS validation, SoO extended community filter, and route preference. The following items can be set: next hop address, cost type, cost, and tag.

    If the referenced policy contains unsupported attribute matching or behavior setting, unexpected results may occur.
  • If the default-route-advertise command with always specified is run in an OSPF process and a route-policy is used to set route attributes, the route-policy takes effect only when there are active default routes that do not belong to the current OSPF process in the local routing table.

Example

# Configure OSPF to advertise a default LSA for the active default route in the IP routing table only when the preference of this route is smaller than 140.
<HUAWEI> system-view
[HUAWEI] ospf 1
[HUAWEI-ospf-1] default-route-advertise permit-preference-less-than 140
# Advertise the ASE LSA of the default route to the OSPF area, with no default route on the local device.
<HUAWEI> system-view
[HUAWEI] ospf 1
[HUAWEI-ospf-1] default-route-advertise always
