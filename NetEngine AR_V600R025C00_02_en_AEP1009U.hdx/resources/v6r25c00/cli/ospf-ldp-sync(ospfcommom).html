ospf ldp-sync

Function

The ospf ldp-sync command enables LDP-OSPF synchronization on an interface.

The undo ospf ldp-sync command disables LDP-OSPF synchronization on an interface.

The ospf ldp-sync block command blocks LDP-OSPF synchronization on an interface.

The undo ospf ldp-sync block command restores the default configuration.

By default, LDP-OSPF synchronization is not configured on an interface, but LDP-OSPF synchronization is not blocked on the interface.

Format

ospf ldp-sync

ospf ldp-sync block

undo ospf ldp-sync

undo ospf ldp-sync block

Parameters

None

Views

10GE interface view, 25GE sub-interface view, 25GE interface view, 40GE interface view, Cellular channel interface view, Eth-Trunk interface view, Ethernet interface view, GE optical interface view, GE sub-interface view, GE electrical interface view, IP-Trunk interface view, MP-group interface view, POS interface view, Tunnel interface view, VLANIF interface view, 40GE sub-interface view, 10GE sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

LDP-OSPF synchronization prevents LSP traffic loss on a network with active and standby LSPs and shortens the traffic interruption time to milliseconds.

After the ldp-sync enable command is run for an IGP process, LDP-IGP synchronization is enabled on all interfaces whose neighbor status is Up on a P2P network, and LDP-IGP synchronization is enabled on all interfaces whose neighbor status is Up on a broadcast network between a DR and a non-DR/BDR. Do not configure the interface connected to the node that carries important services as an interface on the backup link. LDP-IGP synchronization can be blocked on a specified interface.

Precautions

The display ospf ldp-sync interface command can be used to display the synchronization status of an interface on which LDP-OSPF synchronization is blocked.

If LDP-IGP synchronization is enabled and no value is set for the hold-max-cost timer, the IGP advertises the maximum cost of a link during the interruption of an LDP session or LDP adjacency. The cost can be restored only after the LDP session recovers. In a scenario where a backup link exists, after the primary link recovers, LDP attempts to reestablish the session. Because the IGP advertises the maximum cost for the primary link, TCP connection establishment or LDP packets are sent to the peer end through the backup link. If the backup link fails to forward traffic or security authentication is configured, the TCP connection establishment or LDP packets may be discarded. As a result, the LDP session cannot be established, and the IGP continues to advertise the maximum cost for the primary link. Therefore, when LDP-IGP synchronization is used, ensure that the backup link can properly forward LDP packets. Otherwise, routes may always select the backup link.

In addition, when the IGP carries multiple types of services, including LDP services, LDP-IGP synchronization is enabled, and no value is set for the hold-max-cost timer, the IGP keeps advertising the maximum cost for the primary link during the interruption of the LDP session or LDP adjacency on the primary link. As a result, IGP route selection and other services may be affected. Therefore, when the IGP carries multiple types of services, including LDP services, you can set a proper value for the hold-max-cost timer to reduce the impact of the LDP session or LDP adjacency interruption on IGP route selection and other services.

Example

# Enable LDP-OSPF synchronization on 10GE 0/0/0. 
<HUAWEI> system-view
[HUAWEI] interface 10GE 0/0/0
[HUAWEI-10GE0/0/0] ospf ldp-sync block
# Enable LDP-OSPF synchronization on 10GE 0/0/0. 
<HUAWEI> system-view
[HUAWEI] interface 10GE 0/0/0
[HUAWEI-10GE0/0/0] ospf ldp-sync
