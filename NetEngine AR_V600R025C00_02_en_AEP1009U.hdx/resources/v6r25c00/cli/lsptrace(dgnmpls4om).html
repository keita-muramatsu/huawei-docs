tracert lsp (General)

Function

The tracert lsp command enables the system to trace the gateways along the LSP from the source to the destination.

Format

tracert lsp [ -a source-ip | -exp exp-value | -h ttl-value | -r reply-mode | -t time-out | -s packet-size | -g ] * ip destination-iphost mask-length [ ip-address ] [ nexthop nexthopAddr ] [ detail ]

Parameters

Parameter Description Value
-a source-ip

Specifies the source address of MPLS Echo Request packets to be sent.

If no source IP address is specified, the MPLS LSR ID is used as the source IP address of MPLS Echo Request packets.

The value is in dotted decimal notation.
-exp exp-value

Specifies the number of MPLS Echo Request packets to be sent.

When the network quality is poor, you can increase the number of sent packets to detect the network quality based on the packet loss rate.

The value is an integer ranging from 0 to 7.
-h ttl-value

Specifies the TTL value.

During packet forwarding, if the value of the TTL field is reduced to 0, the router that the packet reaches sends an ICMP timeout packet to the source end, indicating that the remote device is unreachable.

The value is an integer ranging from 1 to 255.
-r reply-mode

Specifies a mode in which the peer sends MPLS Echo Reply packets in response.

The value is a decimal integer ranging from 1 to 2. The default value is 2.

  • 1: no reply.
  • 2: responds with IPv4/IPv6 UDP packets.
-t time-out

Specifies the timeout period for waiting for an MPLS Echo Reply packet after an MPLS Echo Request packet is sent.

The value is an integer that ranges from 0 to 65535, in milliseconds.
-s packet-size

Specifies the length of the sent payload packet, that is, the length of the packet excluding the IP header and UDP header.

The value is an integer that ranges from 84 to 9600, in bytes.
-g

Specifies MPLS packet fragmentation.

-
ip destination-iphost

Specifies an IPv4 address or host name for the destination.

If the value is an IP address, it is in dotted decimal notation. If the value is a hostname, it is a string of 1 to 255 case-sensitive characters. It cannot contain spaces.
mask-length

Specifies a mask length for the destination address.

The value is an integer ranging from 0 to 32.
ip-address

Specifies the destination address in the IP header of the MPLS tracert packet, with the prefix being 127.0.0.0/8.

You can trace test packets by changing the destination address in the IP header.

By default, the destination IP address in the IP header of an MPLS tracert packet is 127.0.0.1.
nexthop nexthopAddr

Specifies an IP address for the next hop. This parameter is used when the ingress node has one or more next hops. You can specify this parameter to select one tunnel for connectivity check.

The value is in dotted decimal notation.
detail

Displays detailed information.

-

Views

All views

Default Level

0: Visit level

Usage Guidelines

Usage Scenario

The ping lsp command can be used to check the connectivity of LSPs on an MPLS network, and the tracert lsp command can be used to locate the faulty node.

The tracert lsp command uses MPLS Echo Request packets and MPLS Echo Reply packets to detect the connectivity of LSPs. Both Echo Request and Echo Reply packets are transmitted in the format of UDP packets through port 3503. The receiver distinguishes these two types of packets based on the port number. An MPLS Echo Request packet carries FEC information to be detected, and is sent along the same LSP as other packets carrying the same FEC information. In this manner, the connectivity of the LSP is checked. Echo Request packets are transmitted to the destination using MPLS, whereas MPLS Echo Reply packets are transmitted to the source using IP.

LDP LSP tracert: Run the tracert lsp ip destination-iphost mask-length command on the ingress to initiate a tracert test to the egress to locate the failure point on the LSP.

Prerequisites

  • Ensure that the UDP module of each node works properly; otherwise, the tracert test fails.
  • Ensure that the MPLS module of each node is enabled and works properly.
  • Ensure that the ICMP module of each node works properly; otherwise, *** is returned, indicating that the test times out.

Implementation Procedure

The process of the tracert lsp command is as follows:

  • The source sends an MPLS Echo Request packet with the TTL being 1. After the TTL times out, the first hop sends an MPLS Echo Reply packet to the source.
  • The source sends an MPLS Echo Request packet with the TTL being 2. After the TTL times out, the second hop sends an MPLS Echo Reply packet to the source.
  • The source sends an MPLS Echo Request packet with the TTL being 3. After the TTL times out, the third hop sends an MPLS Echo Reply packet to the source.
  • The preceding process proceeds until an MPLS Echo Request packet reaches the destination.

    In each probe, when receiving an MPLS Echo Request packet, the device on the last hop replies with an MPLS Echo Reply packet, indicating that the LSP tracert test ends. In this manner, the result of each probe is displayed on the source, based on which you can find the path from the source to the destination.

Configuration Impact

To prevent the egress from forwarding a received MPLS Echo Request packet to another node, you can set the destination address in the IP header of the packet to a loopback address with the prefix being 127.0.0.0/8.

Precautions

In load balancing scenarios, the downstream command output may be different from the next-hop replier command output.

Example

# Trace the LSP to 4.4.4.9/32.
<HUAWEI> tracert lsp ip 4.4.4.9 32
  LSP Trace Route FEC: LDP IPV4 PREFIX 4.4.4.9/32 , press CTRL_C to break.

  0                                Ingress   10.1.2.2/[1028 ]
  1     10.1.2.2           94 ms   Transit   10.1.5.2/[3 ]
  2     10.1.5.2           94 ms   Egress

You can press CTRL+C to stop the ongoing tracert test.
TTL

TTL in an MPLS echo request packet. It indicates the number of hops of the tunnel, through which an echo request packet passes.
