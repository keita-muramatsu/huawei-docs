peer enable(IPv4)

Function

The peer enable command enables a device to exchange routes with a specified peer or peer group in the address family view.

The undo peer enable command disables a device from exchanging routes with a specified peer or peer group.

By default, route exchange with a specified peer is enabled only in the BGP-IPv4 unicast address family.

Format

peer ipv4-address enable

undo peer ipv4-address enable

Parameters

Parameter Description Value
ipv4-address

Specifies an IPv4 peer address.

The value is in dotted decimal notation.

Views

BGP-IPv4 unicast address family view, BGP-IPv6 unicast address family view, BGP-VPNv4 address family view, BGP-VPNv6 address family view, BGP-VPN instance IPv4 address family view, BGP-VPN instance IPv6 address family view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

By default, route exchange is automatically enabled only between peers in the BGP-IPv4 unicast address family. That is, after the peer as-number command is run in the BGP view, the system automatically configures the peer enable command. In other address family views, however, a peer must be enabled manually.

Configuration Impact

Enabling or disabling a BGP peer in this address family causes the BGP connection with the peer in another address family to be disconnected and automatically renegotiated.

Precautions

If the device has established peer relationships with a peer (using one address) in other address families, running the peer enable command may disconnect and re-establish all the peer relationships with the peer in all the other address families, causing route flapping. Therefore, exercise caution when running this command. In addition, when you run this command in this case, the following warning is displayed:

Warning: This operation will reset the peer session. Continue? [Y/N]:

Enter y if you confirm to execute this command.

By default, the routes that are learned from IBGP peers in the BGP-VPNv4 or BGP-VPNv6 address family and leaked to a BGP VPN instance are advertised to the IBGP peers in the VPN instance, which may cause routing loops. Therefore, you are advised to configure a routing loop prevention mechanism, such as SoO.

By default, the routes learned from IBGP peers in the BGP-VPN instance IPv4 address family or BGP-VPN instance IPv6 address family and reported to VPNv4 or VPNv6 are advertised to VPNv4 or VPNv6 IBGP peers.

Example

# Enable the device to exchange routing information with a specified peer in the address family view. 
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] peer 10.1.1.1 as-number 100
[HUAWEI-bgp] ipv4-family unicast
[HUAWEI-bgp-af-ipv4] peer 10.1.1.1 enable
