filter-policy import (OSPF view)

Function

The filter-policy import command configures the device to filter the routes calculated by OSPF according to a filtering policy. Only the routes that pass the filtering can be added to the RIB.

The undo filter-policy import command disables OSPF from filtering received routes.

By default, OSPF does not filter received routes.

Format

filter-policy acl-number import

filter-policy { acl-name acl-name | ip-prefix ip-prefix-name | route-policy route-policy-name [ secondary ] | route-policy route-policy-name [ strict-match-tag ] } import

undo filter-policy [ acl-number | acl-name acl-name | ip-prefix ip-prefix-name | route-policy route-policy-name [ secondary ] | route-policy route-policy-name [ strict-match-tag ] ] import

Parameters

Parameter Description Value
acl-number

Specifies the number of a basic ACL.

The value is an integer ranging from 2000 to 2999.
acl-name acl-name

Specifies the name of a named basic ACL.

The value is a string of 1 to 32 case-sensitive characters without spaces. The value must start with a letter or digit, and cannot contain only digits.
ip-prefix ip-prefix-name

Specifies the name of an IP prefix list.

The value is a string of 1 to 169 case-sensitive characters, with spaces not supported. When double quotation marks are used around the string, spaces are allowed in the string.
route-policy route-policy-name

Specifies the name of the route-policy.

The value is a string of 1 to 200 case-sensitive characters without spaces. The character string can contain spaces if it is enclosed with double quotation marks (").
secondary

Indicates the suboptimal route.

-
strict-match-tag

Filters routes based on the next hop tag of each path in equal-cost multi-path load balancing scenarios.

-

Views

OSPF view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

You can run the filter-policy import command to set a filtering policy for received routes. Only the routes that pass the filtering are added to the RIB. OSPF is a link-state dynamic routing protocol, with routing information stored in the link-state database (LSDB). Therefore, the filter-policy import command cannot be used to filter received LSAs or those to be advertised. If the LSAs advertised by the local device depend on the routes that are filtered out, the LSAs are no longer advertised. This command is actually used to filter the routes calculated by OSPF. Only the routes that pass the filtering are added to the RIB.

Precautions

  • For a named ACL, only the source address range specified by the source parameter and the time period specified by the time-range parameter are valid for the configured filtering rule.
  • If route-policy route-policy-nameis specified in this command, the following items can be matched: IP route destination address ACL, IP route destination address prefix list, IP route next hop address ACL, IP route next hop address prefix list, route cost, route type, route tag, route preference, routing protocol type, prefix modulo operation result, and outbound interface. QoS parameters can be set.

    If the referenced policy contains unsupported attribute matching or behavior setting, unexpected results may occur.
  • If secondary is configured, strict-match-tag does not need to be configured.
  • If an ABR learns valid routes from the original area based on inter-area LSAs, it floods the LSAs to other areas.

    If the routes learned from the original area are filtered out by a routing policy, the corresponding inter-area LSAs are no longer flooded to other areas.
  • If an ABR learns valid routes from an NSSA based on external LSAs, it floods the LSAs to non-NSSAs.

    If the routes learned from the NSSA are filtered out by a routing policy, the corresponding external LSAs are no longer flooded to non-NSSAs.

    If ip-pool or port-pool in an ACL rule is empty, the rule cannot match any IP address or port. The matching result of the ACL rule is determined by all the rules configured for the corresponding service.

Example

# Configure OSPF to filter the received routes.
<HUAWEI> system-view
[HUAWEI] ip ip-prefix prefix1 permit 1.1.1.1 24
[HUAWEI] ospf 100
[HUAWEI-ospf-100] filter-policy ip-prefix prefix1 import
# Configure OSPF to strictly filter the received routes based on the next hop tag when the route-policy is used.
<HUAWEI> system-view
[HUAWEI] route-policy aaa permit node 10
[HUAWEI] ospf 100
[HUAWEI-ospf-100] filter-policy route-policy aaa strict-match-tag import
