nexthop recursive-lookup route-policy (BGP-VPNv4 address family view)

Function

The nexthop recursive-lookup route-policy command configures BGP to perform next hop recursion based on a route-policy or route-filter.

The undo nexthop recursive-lookup route-policy command cancels the configuration of BGP next hop recursion based on a route-policy or route-filter.

By default, route-policy-based next hop recursion is disabled.

Format

nexthop recursive-lookup route-policy route-policy-name

undo nexthop recursive-lookup route-policy

undo nexthop recursive-lookup route-policy route-policy-name

Parameters

Parameter Description Value
route-policy route-policy-name

Indicates the name of a route-policy.

The name is a string of 1 to 200 case-sensitive characters, with spaces not supported. When double quotation marks are used around the string, spaces are allowed in the string.

Views

BGP-VPNv4 address family view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

BGP needs route recursion in case of next hops. If route recursion is not limited, BGP routes may be incorrectly iterated, causing traffic loss. Therefore, next hops should perform recursion according to certain conditions.

To control route recursion based on a route-policy, run the nexthop recursive-lookup route-policy command. If a target recursive route is filtered out by the route-policy, the route is considered unreachable. In this manner, BGP route recursion will fail.

Prerequisites

The target recursive route has been determined, and a route-policy has been configured.

Note:

Before configuring a route-policy, ensure that all desired target recursive routes will not be filtered out by the route-policy.

Precautions

This command does not take effect for the routes received from link-local peers.

If route-policy route-policy-nameis specified in the command, the following items can be matched: the outbound interface, destination IP address ACL, destination IP address prefix ACL, next-hop IP address ACL, next-hop IP address prefix ACL, source IP address ACL, source IP address prefix list, route cost, route type, route tag field, MPLS label, destination address ACL list of IPv6 routing information, destination address prefix list of IPv6 routing information, next hop address ACL list of IPv6 routing information, next-hop address prefix list, source IPv6 address ACL list, source IPv6 address prefix list, routing protocol type, route preference, and route modulo attribute of IPv6 routes. You can set the AS_Path attribute, BGP community attribute, local preference of BGP routes, route source of BGP routes, MED of BGP routes, preferred value of BGP routes, specified color extended community attribute of BGP routes, BGP large-community attribute, and the number of times that the most recent AS number is added.

If the referenced policy contains an unsupported attribute matching behavior, unexpected results may occur.

Example

# Configure BGP to filter routes based on a specified route-policy.
<HUAWEI> system-view
[HUAWEI] ip ip-prefix ip_nexthop permit 0.0.0.0 32 greater-equal 32 less-equal 32
[HUAWEI] route-policy nexthop permit node 0
[HUAWEI-route-policy] if-match ip-prefix ip_nexthop
[HUAWEI-route-policy] quit
[HUAWEI] bgp 100
[HUAWEI-bgp] ipv4-family vpnv4
[HUAWEI-bgp-af-vpnv4] nexthop recursive-lookup route-policy nexthop
