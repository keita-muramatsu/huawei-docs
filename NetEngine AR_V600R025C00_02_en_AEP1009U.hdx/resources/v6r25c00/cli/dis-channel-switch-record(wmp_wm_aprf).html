display channel switch-record

Function

The display channel switch-record command displays channel switching records on the device.

Format

display channel switch-record { all | calibrate | ap-id ap-id radio radio-id | reason { unknown | dfs | configuration | unsupported | 3gpp-bs-notification | iot-notification | ap-sync } }

Parameters

Parameter Description Value
all

Displays all channel switching records.

-
calibrate

Displays radio calibration switching records.

-
ap-id ap-id

Displays channel switching records of the AP with a specified ID.

For the AR5710-S8TWDSE-LTE4EA, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR5710-S10T1X2, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T and AR5710-S8P1XDSE-2LTE4EA:The value is an integer ranging from 0 to 127.

For the AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4 and AR6700-H series:The value is an integer in the range from 0 to 1023.

For the AR8700 series and AR8100 series:The value is an integer that ranges from 0 to 2047.
radio radio-id

Displays channel switching records of a specified AP radio.

The value is an integer ranging from 0 to 4.
reason

Displays records of channel switching caused by a specified reason.

-
unknown

A channel change of an unknown type occurs. For example, a channel change type is added in a later version, and an AP of a later version is connected.

-
dfs

Displays records of channel switching triggered by radar signals.

-
configuration

Displays records of channel switching caused by configuration.

-
unsupported

Displays records of channel switching because the AP does not support the channel delivered from the AC.

-
3gpp-bs-notification

Displays records of channel switching triggered by avoiding signals of 3GPP base stations.

-
iot-notification

Displays records of channel switching triggered by avoiding signals of IoT devices.

-
ap-sync

Displays records of channel switching caused by configuration synchronization (through AC-AP channel synchronization).

-

Views

All views

Default Level

1: Monitoring level

Usage Guidelines

You can run this command to view channel switching records on a device.

Run the display channel switch-record calibrate command to query channel or power switching records caused by radio calibration to check the calibration results.

Switch reason

Reason for channel switching.

  • calibration: channel switching caused by radio calibration.
  • configuration: channel switching caused by configuration.
  • dfs: channel switching performed to avoid radar channels.
  • dfs(In AC): channel switching caused by channel delivery by the AC to avoid radar channels.
  • dfs recover: channel switching caused by DFS channel switchback.
  • unsupported: channel switching performed because the AP does not support the channel delivered by the AC.
  • 3gpp-bs-notification: channel switching notified by a 3GPP base station.
  • iot-notification: channel switching notified by an IoT card.
  • AP sync: channel switching caused by configuration synchronization (through AC-AP channel synchronization).
  • CI-notification: channel switching notified by the analyzer during calibration.
  • Poor quality: channel switching caused by radio calibration triggered when the analyzer identifies poor-QoE APs.
Switch time

Time when channel switching occurred.
PCH

Channels before calibration.
CCH

Channel after calibration.
PBW

Bandwidth before calibration.
CBW

Bandwidth after calibration.
PE

Power before calibration.
CE

Power after calibration.
PR

Interference values before calibration.
CR

Interference values after calibration.
PCH/CCH

Channels before and after calibration.

PCH/CCH changes may be discontinuous for a radio.
PBW/CBW

Bandwidth before and after calibration.
PE/CE

Power before and after calibration.

PE/CE changes may be discontinuous for a radio.
PR/CR

Interference values before and after calibration.
Reason

Reason for triggering calibration.

  • Period recheck: periodic calibration.
  • Bad env: environment deterioration.
  • Non-Wi-Fi report: non-Wi-Fi report.
  • Rogue AP report: rogue AP report.
  • Noise interfere: noise interference.
  • Global plan: network-wide plan.
  • AP online: The AP radio is enabled, the radio is switched between the 2.4 GHz and 5 GHz bands, the radio working mode changes, or the AP goes online.
  • AP offline: The AP radio is disabled, the radio is switched between the 2.4 GHz and 5 GHz bands, the radio working mode changes, or the AP goes offline.
  • Bad channel: The channel deteriorates, causing the loss of Beacon frames.
  • iot-notification: An IoT card notifies calibration.
  • DFS(In AC): The AC delivers a channel to avoid radar channels.
  • High interfere: high interference.
  • Unknown: unknown reason.
Time

Time when calibration is triggered.
Trigger ID(Radio)

ID of the AP (radio) that triggers partial radio calibration.

If global radio calibration is triggered, this field displays -.
