default send-key-id

Function

The default send-key-id command configures a particular key-id as the default send-key-id for that keychain.

The undo default send-key-id command deletes the default send-key-id.

By default, no key-id is configured as default send-key-id.

Format

default send-key-id

undo default send-key-id

Parameters

None

Views

weekly Key-ID view, yearly Key-ID view, daily Key-ID view, monthly Key-ID view, absolute Key-ID view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

In keychain authentication, the authentication algorithm and key are dynamically changed to ensure secure protocol packet transmission. This reduces the workload of manually changing the algorithm and key. A keychain consists of multiple key-ids, each of which has its own sending and receiving time. Different key-ids are active within different periods.

If no send-key-id exists in a keychain or no active send-key-id exists in a certain period, the keychain cannot send protocol packets. As a result, the application protocol connection is torn down. To address this issue, configure a default send-key-id so that the keychain can use it to authenticate and encrypt protocol packets when no active key-id exists. This ensures normal communication of protocol packets.

Precautions

Each keychain can have only one default key ID for packet sending.

  • If the default key ID for packet sending is an existing key ID, the authentication and encryption algorithms, and key corresponding to the key ID are used.
  • If the default key ID for packet sending is a newly created key ID, configure the authentication and encryption algorithms, and key for the key ID.

Example

# Configure the send-key-id 1 as default in keychain huawei.
<HUAWEI> system-view
[HUAWEI] keychain huawei mode absolute
[HUAWEI-keychain-huawei] key-id 1
[HUAWEI-keychain-huawei-keyid-1] default send-key-id
