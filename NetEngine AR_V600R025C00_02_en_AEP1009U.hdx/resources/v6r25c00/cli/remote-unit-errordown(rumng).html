remote-unit protect-action error-down

Function

The remote-unit protect-action error-down enable command enables RU protection by setting interfaces to the Error-Down state.

The remote-unit protect-action error-down disable command disables RU protection by setting interfaces to the Error-Down state.

By default, an RU is enabled to enter the Error-Down state for exception protection.

Format

remote-unit protect-action error-down { disable | enable }

undo remote-unit protect-action error-down disable

Parameters

Parameter Description Value
disable

Disable an RU from entering the Error-Down state for exception protection.

-
enable

Enables an RU to enter the Error-Down state for exception protection.

-

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

During RU deployment, a configuration error or link fault may occur. After detecting the fault, the central device sets the interface connected to the RU to the Error-Down state.

An interface connecting the central device to an RU goes Error-Down if one of the following configuration errors occurs:

  1. The two downlink interfaces on the central device connected to the same RU are not added to an Eth-Trunk. In this case, the interface connected later goes Error-Down.
  2. The two downlink interfaces on the central device connected to the same RU are added to two Eth-Trunks respectively. In this case, the interface connected later goes Error-Down.
  3. Two central devices are connected to the same RU, and the two central devices do not set up a stack. In this case, the interface with a larger system MAC address on the central devices goes Error-Down.

    If an interface connecting the central device to an RU goes Error-Down due to incorrect configurations, the interface can go up automatically after a delay. To implement this function, you need to run the error-down auto-recovery cause remote-unit-misconfig command to set an auto-recovery delay.

    The following link faults may occur when an RU is connected to the central device:
  4. A unidirectional fault occurs on the link connecting the central device to the RU. In this case, the interface on the central device goes Error-Down. This fault occurs if either of the following conditions is met:

    • The central device does not receive heartbeat packets from the RU for three consecutive periods (30s in total).

    • The heartbeat packets sent by the RU do not carry central device information in three consecutive periods (30s in total).
  5. When the central device is connected to the RU through two links and the interface of one link goes Error-Down due to a unidirectional link fault, the interface of the other link does not enter the Error-Down state even if this link fails.

    If an interface on the central device goes Error-Down due to a link fault, the interface can go up automatically after a delay. To implement this function, you need to run the error-down auto-recovery cause remote-unit-link interval command to set an auto-recovery delay.

Prerequisites

XLDP has been enabled on all interfaces of the central device.

Precautions

The effect of the undo remote-unit protect-action error-down disable command is the same as that of the remote-unit protect-action error-down enable command.

Example

# Enable RU protection by setting interfaces to the Error-Down state when the topology link of the RU is abnormal.
<HUAWEI> system-view
[HUAWEI] undo remote-unit protect-action error-down disable
