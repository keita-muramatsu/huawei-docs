apply as-path prepend

Function

The apply as-path prepend command prepends AS numbers to the local AS number.

The undo apply as-path prepend command cancels this configuration.

By default, no AS number is prepended to the local AS number.

Format

apply as-path prepend asValues

undo apply as-path prepend [ asValues ]

Parameters

Parameter Description Value
asValues

Prepends AS numbers to the local AS number.

AS attribute value. The value is a string of 1 to 3071 characters. This parameter is used together with quotation marks. At least one group of AS numbers can be configured, and a maximum of 256 groups of AS numbers can be configured. The AS numbers are separated by spaces. Each group supports the following formats:

  • The value is an integer ranging from 1 to 4294967295.
  • x.y format: x and y are integers. x is an integer ranging from 1 to 65535, and y is an integer ranging from 0 to 65535.

Views

Route-policy view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The AS_Path attribute is a private attribute of BGP. The apply as-path prepend command is valid only for BGP routes. The AS_Path attribute records the numbers of all ASs that a route passes through from the local end to the destination in the vector order. The AS_Path attribute can be used to control route selection and prevent routing loops. If multiple routes are destined for the same address, BGP compares their AS paths and regards the one with the shortest AS path as the optimal route.

By using routing policies to change the AS_Path attribute, you can control BGP route selection and data traffic forwarding paths. After the filtering conditions specified by the if-match clause are met and the matching mode is permit, you can run the apply as-path prepend command to prepend AS numbers to the local AS number for the routes that meet the filtering conditions.

The apply as-path prepend command is not controlled by the apply as-path none command.

Run the route-policy command to enter the route-policy view.

A route-policy can consist of multiple nodes. The relationship between different nodes is OR. The system checks each node according to the node sequence number. If a route matches one node, the route matches the route-policy and is not matched against other nodes.

Each node may consist of a group of if-match and apply clauses. An if-match clause defines matching rules. The matching objects are some attributes of the routing information. The relationship between multiple if-match clauses for different attributes of a node is AND. A node can pass the matching test only when all the matching conditions specified by the if-match clauses are met. The relationship between multiple if-match clauses for the same attribute is OR, and the system checks the if-match clauses in sequence. If a route matches one of the if-match clauses, the route matches the route-policy and is not matched against other if-match clauses. For example, in node 10, the if-match community-filter 1 and if-match as-path-filter 1 commands are used to filter routes based on different attributes. The relationship between the two commands is AND. In node 20, if-match community-filter 1 and if-match community-filter 2 are used to filter routes based on communities. The relationship between if-match community-filter 1 and if-match community-filter 2 is OR. The apply clauses specify actions. That is, the apply clauses set some attributes of the route after the route matches the node.

Prerequisites

A route-policy has been configured using the route-policy command.

Configuration Impact

The apply as-path prepend command prepends AS numbers to the local AS number. The apply as-path command adds or deletes AS numbers after the local AS number and before the original AS_Path attribute. The AS_Path attribute can be overwritten.

After the apply as-path prepend command is run, the AS_Path attributes of the BGP routes that meet the matching rules change. For example:

Assume that the local AS number is 100, the original AS_Path is (65001 600 65002 700), and the apply as-path prepend configuration is (200 300 65004). If the matching conditions are met and apply as-path 400 500 65003 additive is configured:

If the peer public-as-only command is run, the private AS numbers carried in the AS_Path attribute is deleted and the AS_Path attribute is changed to (200 300 65004 100 400 500 600 700).

If the peer public-as-only command is not run, AS_Path is changed to (200 300 65004 100 400 500 65003 65001 600 65002 700).

After the undo apply as-path prepend command is run, AS numbers are not prepended to the AS_Path of the routes that match the routing policy, and the path that the routes pass through is not modified.

In the goto next-node scenario, the combined AS_Path attribute and operation type are passed to BGP routes. Assume that the local AS number of EBGP is 100 and the original AS_Path is (65001 600 65002 700). When the matching conditions are met:

  • If apply as-path prepend 200 300 65003 and goto next-node are configured on node 1 and apply as-path prepend 400 500 65004 is configured on node 2, the AS_Path is changed to (400 500 65004 200 300 65003 100 600 700).
  • If apply as-path prepend 200 300 65003 and goto next-node are configured on node 1 and apply as-path 400 500 65004 additive is configured on node 2, the AS_Path is changed to (200 300 65003 100 400 500 600 700).
  • If apply as-path prepend 65002 200 and goto next-node are configured on node 1, apply as-path 300 additive and goto next-node are configured on node 2, apply as-path 400 additive and goto next-node are configured on node 3, and apply as-path prepend 65003 500 is configured on node 4, the AS_Path is changed to (65003 500 65002 200 400 300 100 600 700).

Precautions

Running this command affects the path through which network traffic passes. Therefore, you must be familiar with the network topology and the impact of running this command.

  • The apply as-path prepend command supports a minimum of one AS number and a maximum of 256 AS numbers.
  • The apply as-path prepend and apply as-path commands can be both configured and take effect together.

By default, BGP checks the first AS number in the AS_Path that is carried in the Update message received from an EBGP peer, and BGP accepts the message only if the first AS number is the AS where the EBGP peer locates. Otherwise, the Update message is denied. Therefore, after using this function to change AS numbers, you need to run the undo check-first-as or peer check-first-as disable command on the receive end.
