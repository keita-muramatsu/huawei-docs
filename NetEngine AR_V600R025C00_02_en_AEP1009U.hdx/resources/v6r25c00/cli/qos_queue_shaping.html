qos queue shaping

Function

The qos queue shaping command enables traffic shaping for a queue on a specified interface and sets traffic shaping parameters.

The undo qos queue shaping command restores the default scheduling parameters of each queue on an interface.

The following table describes the default scheduling parameters on an interface.

Format

qos queue queue-index shaping { percent cir cir-percent-value | cir cir-value [ kbps | mbps | gbps ] [ cbs cbs-value [ bytes | kbytes | mbytes ] ] }

undo qos queue queue-index shaping

Parameters

Parameter Description Value
queue-index

Specifies the queue index.

The value is an integer ranging from 0 to 7.
percent

Specifies the bandwidth rate as the queue information rate.

-
cir cir-value

Specifies the absolute value of the CIR for traffic shaping.

The value is an integer that ranges from 1 to 100000000, in kbit/s by default.
cir cir-percent-value

Specifies the percentage value of the CIR for traffic shaping.

The value is an integer that ranges from 1 to 100. The default value is 100.

In this mode, CBS is calculated using the following formula:

CBS = cir-percent-value x Maximum bandwidth of the interface x 8
kbps

Indicates that the rate is expressed in kbit/s.

-
mbps

Indicates that the rate is expressed in Mbit/s.

-
gbps

Indicates that the rate is expressed in Gbit/s.

-
cbs cbs-value

Specifies the absolute value of the committed burst size (CBS), that is, the average volume of burst traffic that can pass through an interface.

The value is an integer. The value ranges are as follows:

When the value is expressed in bytes, the value ranges from 10000 to 4194304.

When the value is expressed in kbytes, the value ranges from 10 to 1096.

When the value is expressed in mbytes, the value ranges from 1 to 4.
bytes

Indicates that the burst size is expressed in bytes.

-
kbytes

Indicates that the burst size is expressed in kbytes.

-
mbytes

Indicates that the burst size is expressed in Mbytes.

-

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

When the traffic rate of an interface on a downstream device is lower than that of the connected interface on the upstream device, traffic congestion may occur on the interface of the downstream device. You can configure traffic shaping for queues on the outbound interface of the upstream device and adjust the transmit rate of the interface.

The qos queue shaping command configures traffic shaping on packets of a specific service on an interface.

Prerequisites

Priority mapping based on simple traffic classification has been configured to map packet priorities to PHBs and colors, or internal priority re-marking based on complex traffic classification has been configured so that packets of different services enter different queues.

Precautions

  • If traffic shaping is configured both on an interface queue and an interface (using the qos lr command), the CIR of the interface cannot be lower than the sum of CIR values of all the queues on the interface; otherwise, traffic shaping result may be incorrect. For example, the queue with a lower priority may occupy the bandwidth of the queue with a higher priority.
  • If you run the qos queue shaping command multiple times on the same interface, only the latest configuration takes effect.
  • For the AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR5700 series, the command cannot be configured in the Layer 2 interface view.
  • On the AR8000 series, and AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4, AR6700-H, the command cannot be configured in the Layer 2 Eth-Trunk interface view.

Example

# Set percentage values of the CIR for queue 4 on the 10GE0/0/1 to 50%.
<HUAWEI> system-view
[HUAWEI] interface 10GE 0/0/1
[HUAWEI-10GE0/0/1] qos queue 4 shaping percent cir 50
# Set absolute values of the CIR for queue 4 on the 10GE0/0/1 to 10000 kbit/s.
<HUAWEI> system-view
[HUAWEI] interface 10GE 0/0/1
[HUAWEI-10GE0/0/1] qos queue 4 shaping cir 10000 kbps
