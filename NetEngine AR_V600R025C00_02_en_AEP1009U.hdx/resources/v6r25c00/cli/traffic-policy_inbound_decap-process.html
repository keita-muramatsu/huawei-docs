traffic-policy inbound decap-process

Function

The traffic-policy inbound decap-process command configures a hierarchical CAR policy applied after decapsulation in the inbound direction of an interface.

The undo traffic-policy inbound command deletes the hierarchical CAR policy applied to an interface.

By default, no traffic policy is applied to an interface.

Format

traffic-policy policy-name inbound decap-process

undo traffic-policy policy-name inbound

Parameters

Parameter Description Value
policy-name

Specifies the name of a traffic policy.

The value is a string of 1 to 31 case-sensitive characters. It cannot contain spaces.

Views

10GE sub-interface view, 10GE interface view, 25GE sub-interface view, 25GE interface view, 40GE sub-interface view, 40GE interface view, Dialer interface view, GE sub-interface view, GE interface view, Interface group view, Ethernet interface view, Ethernet sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

With the proliferation of users and service types on networks, it becomes ever-more critical to offer differentiated services to users. You can configure hierarchical scheduling in the inbound direction of a tunnel interface to differentiate both services and users, implementing refined QoS. After you specify the decap-process parameter to configure MQC for the decapsulation service on a physical interface that receives traffic and enable a decapsulation traffic policy on the tunnel interface, the decapsulation traffic policy configured on the physical interface is implemented when traffic passes through the tunnel interface. In this way, hierarchical scheduling is implemented on the tunnel interface.

Prerequisites

  • A traffic policy has been created using the traffic policy command, and a traffic classifier and a traffic behavior have been bound to the traffic policy.
  • The qos car inbound decap-process command has been run in the interface view to configure bandwidth limit for decapsulation services in the inbound direction of the interface.

Precautions

  • This command is not supported in the 5G channelized interface, Eth-Trunk, or tunnel interface view.
  • In the traffic behavior of the traffic policy for decapsulation, only the shared CAR can be configured. That is, the share parameter must be configured in the car command so that all rules in the traffic classifier bound to the same traffic behavior share the CAR parameters.
  • In the traffic behavior of the traffic policy for decapsulation, you are advised to set the packet color to green pass yellow pass red discard. Otherwise, hierarchical scheduling may fail to be implemented.
  • When configuring hierarchical scheduling on a tunnel interface, you must run all of the qos car inbound decap-process, traffic-policy inbound decap-process, and traffic-policy decap-process enable commands together. Otherwise, hierarchical scheduling does not take effect.

Example

# Create a traffic policy p1 for decapsulation, associate the created traffic classifier c1 and traffic behavior b1 with the traffic policy, and apply the traffic policy to 10GE0/0/1 in the inbound direction.
<HUAWEI> system-view
[HUAWEI] qos car test cir 1 gbps
[HUAWEI] traffic classifier c1
[HUAWEI-classifier-c1] quit
[HUAWEI] traffic behavior b1
[HUAWEI-behavior-b1] quit
[HUAWEI] traffic policy p1
[HUAWEI-trafficpolicy-p1] classifier c1 behavior b1
[HUAWEI-trafficpolicy-p1] quit
[HUAWEI] interface 10GE 0/0/1
[HUAWEI-10GE0/0/1] qos car inbound test decap-process
[HUAWEI-10GE0/0/1] traffic-policy p1 inbound decap-process
