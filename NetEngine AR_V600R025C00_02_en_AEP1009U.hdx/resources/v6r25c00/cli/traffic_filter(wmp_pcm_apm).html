traffic-filter (AP wired port profile view)

Function

The traffic-filter command configures ACL-based IPv4, IPv6, or Layer 2 packet filtering on AP wired interfaces.

The undo traffic-filter command cancels the ACL-based IPv4, IPv6, or Layer 2 packet filtering configuration on AP wired interfaces.

By default, ACL-based IPv4, IPv6, or Layer 2 packet filtering is not configured on AP wired interfaces.

Format

traffic-filter { inbound | outbound } l2 acl { acl-number-l2 | name acl-name-l2 }

traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name }

traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name } l2 acl { acl-number-l2 | name acl-name-l2 }

undo traffic-filter { inbound | outbound } l2 acl { acl-number-l2 | name acl-name-l2 }

undo traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name }

undo traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name } l2 acl { acl-number-l2 | name acl-name-l2 }

Parameters

Parameter Description Value
inbound

Configures packet filtering in the inbound direction.

-
outbound

Configures packet filtering in the outbound direction.

-
l2

Filters Layer 2 packets.

-
acl acl-number

Specifies the number of an advanced ACL.

The value is an integer that ranges from 3000 to 3031 for IPv4 ACLs.
acl acl-number-l2

Specifies a Layer 2 ACL number.

The value is an integer that ranges from 4000 to 4031 for L2 ACLs.
name acl-name

Filters packets based on a specified named ACL. The parameter acl-name specifies the name of the ACL.

The ACL name must exist.

The value range is the same as that of the numbered ACL.
name acl-name-l2

Filters packets based on a specified named ACL. acl-name specifies the name of the ACL.

The ACL name must exist.

The value range is the same as that of the numbered l2 ACL.
ipv4

Filters IPv4 packets.

-

Views

AP wired port profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

On a wireless network, the administrator wants to provide differentiated services for STAs. The services include but are not limited to the following:

  • Deny or permit access of specified STAs to specified LAN devices.
  • Deny access of specified STAs to specified invalid IP addresses.

You can configure ACL-based packet filtering on an AP's wired interface for providing differentiated services.

The rules for an AP's wired interface to filter packets based on ACLs are as follows:

  • If the action in an ACL rule is deny, the device discards packets matching the rule.
  • If the action in an ACL rule is permit, the device forwards packets matching the rule.
  • If no rule is matched, packets are allowed to pass through.

When multiple ACL-based packet filtering commands in the same direction are configured in the same AP wired port profile view, the system matches packets against ACL rules in the sequence in which the commands are configured. If packets match a rule, the system stops the matching process and executes the specified policy. Otherwise, the system continues to match packets against the next rule. If no rule is matched, packets are allowed to pass through. The following occurs depending on whether packets match ACL rules:

  • If a policy contains only one ACL rule and the ACL rule is matched, the permit or deny action is performed.
  • If a policy contains two ACL rules and the specified action is performed only when the two ACL rules are both matched.

If an ACL contains multiple rules, packets are matched against the rules in the ascending order of rule IDs.

On a Mesh network, some terminals or devices are connected to wired interfaces of MPs. You can run this command to configure ACL-based packet filtering for terminals or devices connected to the network through an AP's Ethernet interface.

Precautions

After the traffic-policy (interface view) command is run on an interface to apply a traffic policy, the traffic policy does not take effect for the packets discarded by the command.

The ACL referenced by this command can be an ACL that has no rule configured. You can configure rules for the referenced ACL after running the command.

A maximum of eight ACL-based packet filtering rules can be configured in the same direction. The sequence in which the rules take effect depends on the configuration sequence. To improve the matching rate, you are advised to configure the packet filtering rule with a high matching probability and set the ID of the rule with a high matching probability to a small value when configuring each ACL. This reduces the number of matching times and resource waste. To change the current packet filtering rule, you need to delete all related configurations and reconfigure ACL-based packet filtering.

Example

# Configure the wired interface on APs in an AP group to filter incoming packets based on ACL 3000.
<HUAWEI> system-view
[HUAWEI] wlan
[HUAWEI-wlan] wired-port-profile name wired
[HUAWEI-wlan-wired-port-wired] traffic-filter inbound ipv4 acl 3000
[HUAWEI-wlan-wired-port-wired] quit
[HUAWEI-wlan] ap-group name ap-group1
[HUAWEI-wlan-ap-group-ap-group1] wired-port-profile wired eth-trunk 0
# Configure the wired interface on APs in an AP group to filter incoming packets based on ACL t1(3000).
<HUAWEI> system-view
[HUAWEI] acl name t1 number 3000
[HUAWEI-acl4-advance-t1] rule 5 permit ip source 192.168.0.2 0
[HUAWEI-acl4-advance-t1] quit
[HUAWEI] wlan
[HUAWEI-wlan] wired-port-profile name wired
[HUAWEI-wlan-wired-port-wired] traffic-filter inbound ipv4 acl name t1
[HUAWEI-wlan-wired-port-wired] quit
[HUAWEI-wlan] ap-group name ap-group1
[HUAWEI-wlan-ap-group-ap-group1] wired-port-profile wired eth-trunk 0
