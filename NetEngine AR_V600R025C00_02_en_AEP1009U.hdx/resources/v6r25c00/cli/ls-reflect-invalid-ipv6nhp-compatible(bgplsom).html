reflect invalid-ipv6-nexthop compatible(BGP-LS address family view)

Function

The reflect invalid-ipv6-nexthop compatible command configures the device to change the invalid next-hop IPv6 address of a BGP-LS route to its own IPv6 address when reflecting the route.

The undo reflect invalid-ipv6-nexthop compatible command configures the device to keep the invalid next-hop IPv6 address of a BGP-LS route unchanged when reflecting the route.

By default, a device does not change the invalid next-hop IPv6 address of a BGP-LS route when reflecting the route.

Format

reflect invalid-ipv6-nexthop compatible

undo reflect invalid-ipv6-nexthop compatible

Parameters

None

Views

BGP-LS address family view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

By default, a device does not change the invalid next hop IPv6 addresses (IPv6 addresses starting with :: excluding the loopback address ::1/128 and unspecified address ::/128) of BGP-LS routes learned from an IBGP peer of the IPv6 address type when reflecting the routes to other IBGP peers of the IPv6 address type. After the reflect invalid-ipv6-nexthop compatible command is run, the device performs compatibility processing when reflecting such routes to other IBGP peers of the IPv6 address type. Specifically, the device changes the next hops of the routes to the IP addresses of the interfaces connecting the device to these IBGP peers.

Precautions

If the device learns BGP-LS routes with invalid next hop IPv6 addresses (IPv6 addresses starting with :: excluding the loopback address ::1/128 and unspecified address ::/128) from an IBGP peer of the IPv6 address type and needs to reflect these routes to other IBGP peers of the IPv6 address type:

  • If the device changes the next hops of the BGP-LS routes to the IP addresses of the interfaces connecting the device to the IBGP peers when reflecting the routes to these IBGP peers by default before the upgrade, you are advised to run this command after the upgrade to ensure next hop attribute consistency.
  • If the device does not change the next hops of the routes when reflecting the routes to the peers by default before the upgrade, you are advised not to run this command after the upgrade. Otherwise, the next hop attributes of the routes will be changed after the upgrade.

Example

# Configure the device to perform compatibility processing when it reflects the BGP-LS routes with invalid next hop IPv6 addresses.
<HUAWEI> system-view
[HUAWEI] bgp 100
[*HUAWE-bgp] link-state-family unicast
[*HUAWE-bgp-af-ls] reflect invalid-ipv6-nexthop compatible
