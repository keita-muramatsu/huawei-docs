test-type (NQA view)

Function

The test-type command specifies the test type for an NQA test instance.

The undo test-type command deletes the test type.

By default, no test type is configured.

Format

test-type { tcp | jitter | icmp | lspping | lsptrace | icmpjitter | trace | dns | http }

undo test-type

Parameters

Parameter Description Value
tcp

Indicates a TCP test, which checks TCP services.

-
jitter

Indicates a UDP jitter test, which checks the jitter in processing UDP packets.

-
icmp

Indicates an ICMP test to test link connectivity. If an ICMP test instance fails, run the ping -detail or ping ipv6 -detail command to locate the fault.

-
lspping

Indicates an LSP ping test, which checks LSP connectivity.

-
lsptrace

Indicates an LSP trace route test, which locates faulty nodes on an LSP.

-
icmpjitter

Indicates an ICMP jitter test, which checks the path jitter by sending ICMP packets.

-
trace

Indicates a trace route test, which detects the faulty node on a link.

-
dns

Indicates a DNS test, which tests DNS service performance.

-
http

Specifies an HTTP test to check whether the device provides the HTTP service and the time taken to set up a connection.

-

Views

NQA view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

NQA test instances measure the performance of various protocols running on the network, allowing carriers to collect network performance counters in real time. This enables effective fault diagnosis and locating if a fault occurs on the network.

NQA test instances of various types help diagnose and locate faults.

Examples:

  • The test-type dns command configures a DNS test. A DNS test is based on UDP packets and measures the speed at which a DNS name is resolved to an IP address.
  • The test-type icmp command configures an ICMP test. You must set test parameters for the ICMP test based on the configured test group parameters. Test parameters include the TTL, ToS, and delay. After that, you can enable the device to send test packets to the destination address and interface.

    When receiving a test packet, the NQA server first determines whether the packet times out. If the packet times out, the NQA server discards it; if not, the NQA server calculates the RTT and records the information to the history table and the result table.
  • The test-type icmpjitter command configures an ICMP jitter test. The test uses ICMP messages to simulate end-to-end jitters of services and measures jitters on paths.
  • The test-type trace command configures a traceroute test. Before packets are sent in a tracert test, you must first set test parameters based on user-defined parameters. The parameters mainly include the TTL and delay. The TTL of the first ICMP Echo Request message sent to the destination is 1. After the TTL times out, the destination sends an ICMP Echo Reply message to the source. This process repeats until all devices along the path return a reply message. Then, the traceroute test is complete. The source obtains the test result based on the received reply messages.
  • The test-type tcp command configures a TCP test. You must configure an NQA TCP server on the peer end. The client then initiates a test to the specified IP address and port of the server. The TCP test measures the time taken to set up a TCP connection.
  • The test-type http command configures an HTTP test. By calculating the DNS resolution time, TCP connection setup time, and HTTP transaction time, an HTTP test checks whether a device provides HTTP services and measures the time taken to set up a connection.
  • The test-type jitter command configures a jitter test. In a jitter test, the source periodically sends packets to the destination. Each packet is marked with a timestamp. After receiving a packet, the destination timestamps the packet based on the local system time and returns the packet to the source. The source then calculates the jitter time based on the timestamp carried in the received packet. A jitter test instance can consecutively send a maximum of 3000 packets and can simulate voice service traffic.
  • The test-type lspping command configures an LSP ping test. In an LSP ping test, a UDP MPLS Echo Request packet is first constructed. The destination IP address in the IP header is filled with an IP address on the network segment 127.0.0.0/8. The source then searches for the corresponding LSP. For a TE LSP, the packet can be sent from a tunnel interface and then forwarded along a specified CR-LSP. Packets are forwarded within the MPLS domain according to the specified LSP. The receive end egress listens to the response packets sent from port 3503. The transmit end obtains the test result based on the received response packets.
  • The test-type lsptrace command configures an LSP traceroute test. In an LSP traceroute test, a UDP MPLS Echo Request packet is first constructed. The destination IP address in the IP header is filled with an IP address on the network segment 127.0.0.0/8. The source then searches for the corresponding LSP. For a TE LSP, the packet can be sent from a tunnel interface and then forwarded along a specified CR-LSP. The Echo Request packet must carry a Downstream Mapping TLV (used to carry information about the downstream devices, including the address of the next hop and the outgoing label).

    The TTL of the first MPLS Echo Request packet is 1. The packet is forwarded along a specified LSP in the MPLS domain. An MPLS Echo Reply packet is returned after the TTL times out. The source continues to send the MPLS Echo Request packet, with the TTL increasing by 1 each time. This process continues until all the LSRs along the LSP return an MPLS Echo Reply packet. Then, the traceroute process is complete. The source obtains the test result based on the received reply messages.

Precautions

  • The type of a test instance cannot be modified once it is configured. That is, if you modify the parameters of a test instance during the running of the test instance, the test instance stops running.
  • Before starting an ICMP jitter or path jitter test instance in timestamp mode, you need to enable the function of sending and receiving ICMP timestamp packets.

Example

# Set the test type of an NQA test instance to HTTP.
<HUAWEI> system-view
[HUAWEI] nqa test-instance user test
[HUAWEI-nqa-user-test] test-type http
# Set the test type of an NQA test instance to icmp.
<HUAWEI> system-view
[HUAWEI] nqa test-instance user test
[HUAWEI-nqa-user-test] test-type icmp
# Set the test type of an NQA test instance to DNS.
<HUAWEI> system-view
[HUAWEI] nqa test-instance user test
[HUAWEI-nqa-user-test] test-type dns
