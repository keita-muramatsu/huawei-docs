qos overhead layer link

Function

The qos overhead layer link command configures the method of calculating the packet length during traffic policing or traffic shaping.

The undo qos overhead layer link command restores the default configuration.

By default, the device includes physical-layer and link-layer compensation information of packets when calculating the packet length during traffic policing or traffic shaping.

This command is supported only on the AR5710-S8TWDSE-LTE4EA, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR5710-S10T1X2, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR6710-L14T2X4, AR8100 series, AR5710-S8P1XDSE-2LTE4EA and AR6700-H series.

Format

qos overhead layer link

undo qos overhead layer link

Parameters

None

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

An inter-frame gap is required between Ethernet frames. The default length of an inter-frame gap is 12 bytes.

The length of an Ethernet frame starts from the destination MAC address and ends with the FCS. A preamble is added before the Ethernet frame is sent. The preamble is used for synchronization. After receiving the preamble, the receiver determines that the received packet is an Ethernet frame. The preamble has eight bytes.

After traffic shaping in the outbound direction or traffic policing for interface-based rate limiting in the inbound direction is configured, the device counts the inter-frame gap and preamble of packets when calculating the traffic shaping rate in the outbound direction or the traffic policing rate for interface-based rate limiting in the inbound direction. As a result, the calculated rate is inaccurate. After this command is configured, the device does not count the inter-frame gap and preamble when calculating the rate. This ensures the accuracy of the traffic shaping rate in the outbound direction or the traffic policing rate for interface-based rate limiting in the inbound direction.

The qos overhead layer link command affects calculation of the traffic policing rate for interface-based rate limiting in the inbound direction. For example, after the car (traffic behavior view) and qos car inbound commands are used to configure traffic policing and inbound rate limit on an interface, the device does not count the inter-frame gap and preamble when calculating the rate.

The qos overhead layer link command affects calculation of the traffic shaping rate in the outbound direction. For example, after the queue (flow queue view) and qos queue queue-index shaping commands are used to configure rate limit for traffic shaping, the device does not count the inter-frame gap and preamble when calculating the rate.

Precautions

  • Before this command is run, the rate limit for outgoing traffic shaping or incoming traffic policing on an interface is calculated using the following formula: Rate limit for outgoing traffic shaping or incoming traffic policing = (Original packet length + Inter-frame gap + Preamble) x Number of forwarded packets per second.
  • After this command is run, the rate limit for outgoing traffic shaping or incoming traffic policing on an interface is calculated using the following formula: Rate limit for outgoing traffic shaping or incoming traffic policing = Original packet length x Number of forwarded packets per second.

    This command is mutually exclusive with the qos car ifg disable command. This is because the inter-frame gap and preamble have been subtracted during traffic policing when this command is used. If the qos car ifg disable command is configured, the inter-frame gap and preamble are subtracted again during traffic policing.
  • Only Ethernet links and PPP links support the qos overhead layer link command.
  • For the AR8700 series, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, and AR6710-L50T2X4-T, the device counts the inter-frame gap and preamble when calculating the traffic shaping rate in the outbound direction or the traffic policing rate for interface-based rate limiting in the inbound direction, which cannot be modified using a command.

Example

# Configure the device to include only link-layer compensation information in packets when calculating the packet length during traffic policing or traffic shaping.
<HUAWEI> system-view
[HUAWEI] qos overhead layer link
