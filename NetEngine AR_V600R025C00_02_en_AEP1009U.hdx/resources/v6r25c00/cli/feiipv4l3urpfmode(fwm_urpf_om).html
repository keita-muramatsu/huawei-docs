ip urpf

Function

The ip urpf command configures the URPF check mode on an interface.

The undo ip urpf command cancels the configured URPF check mode on an interface.

By default, URPF check is disabled on all interfaces.

Format

ip urpf { strict | loose } [ allow-default-route ] [ acl acl-number ]

undo ip urpf

Parameters

Parameter Description Value
strict

Indicates the strict mode.

-
loose

Indicates the loose mode.

-
allow-default-route

Allows the default route.

-
acl acl-number

Specifies an ACL number.

The value is an integer ranging from 2000 to 3999.

Usage Guidelines

Usage Scenario

Using the ip urpf command, you can configure the URPF check mode on an interface. When the strict check mode is configured, the device checks the first packet and subsequent packets to prevent loops and ensure customer network availability.

Using the undo ip urpf command, you can delete the URPF check mode configured on an interface.

By default, URPF check is disabled on an interface.

Configuration Impact

The URPF check can be implemented in strict or loose mode. Additionally, the URPF check also supports checking ACLs and default routes.

The processing flow of the URPF check is as follows:

If the source IP address of a packet exists in the FIB table of the URPF-enabled device:

  • In strict mode, the device reversely searches for the outbound interface of the packet. If only one outbound interface matches the inbound interface of the packet, the packet passes the URPF check. Otherwise, the packet is discarded. If more than one outbound interface matches the inbound interface of the packet, you must use the loose mode. (Reverse search indicates searching for the outbound interface of another packet whose destination IP address is the source IP address of the packet.)
  • In loose mode, when the source IP address of the packet exists in the FIB table of the device and the route is not a blackhole one (regardless of the consistency between the reversely-searched outbound interface and the inbound interface of the packet), the packet passes the URPF check. Otherwise, the packet is discarded.

    If the source IP address of the packet does not exist in the FIB table of the device, check whether the default route and the allow-default-route parameter for URPF are configured.
  • If the default route is configured, but the allow-default-route parameter is not specified:

    As the source IP address of the packet does not exist in the FIB table of the device, the packet is denied regardless of whether the URPF check is in strict or loose mode.
  • If the default route is configured, and the allow-default-route parameter is specified:

    If the strict check is implemented, and the outbound interface of the default route is consistent with the inbound interface of the packet, the packet passes the URPF check and is forwarded normally. Otherwise, the packet is denied.

    If the loose check is implemented, the packet passes the URPF check and is forwarded normally.

    The ACL is matched only when the packet is denied. If the ACL allows the packet through, the packet is forwarded normally. If the ACL denies the packet, the packet is discarded.

Example

# Enable URPF strict check on 10GE0/0/1 and allow special processing and ACL check on the default route.
<HUAWEI> system-view
[HUAWEI] acl number 2000
[HUAWEI-acl4-basic-2000] quit
[HUAWEI] interface 10GE0/0/1
[HUAWEI-10GE0/0/1] ip urpf strict allow-default-route acl 2000
