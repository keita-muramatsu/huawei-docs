ping lsp (General)

Function

The ping lsp command tests whether the LSP connectivity and LSP forwarding are normal.

Format

ping lsp [ -a source-ip | -c count | -exp exp-value | -h ttl-value | -m interval | -r reply-mode | -s packet-size | -t time-out | -v | -g ] * ip destination-iphost mask-length [ ip-address ] [ nexthop nexthopAddr ]

Parameters

Parameter Description Value
-a source-ip

Specifies the source address of MPLS Echo Request packets to be sent.

If no source IP address is specified, the MPLS LSR ID is used as the source IP address of MPLS Echo Request packets.

The value is in dotted decimal notation.
-c count

Specifies the number of MPLS Echo Request packets to be sent.

When the network quality is poor, you can increase the number of sent packets to detect the network quality based on the packet loss rate.

The value is an integer ranging from 1 to 4294967295.
-exp exp-value

Specifies the EXP value of MPLS Echo Request packets to be sent.

The value is an integer ranging from 0 to 7.
-h ttl-value

Specifies the TTL value.

During packet forwarding, if the value of the TTL field is reduced to 0, the router that the packet reaches sends an ICMP timeout packet to the source end, indicating that the remote device is unreachable.

The value is an integer ranging from 1 to 255.
-m interval

Specifies the time to wait before the next MPLS Echo Request packet is sent.

The value is an integer ranging from 1 to 10000, in milliseconds.
-r reply-mode

Specifies a mode in which the peer sends MPLS Echo Reply packets in response.

The value is a decimal integer ranging from 1 to 2. The default value is 2.

  • 1: no reply.
  • 2: responds with IPv4/IPv6 UDP packets.
-s packet-size

Specifies the length of the sent payload packet, that is, the length of the packet excluding the IP header and UDP header.

The value is an integer ranging from 65 to 9600, in bytes.
-t time-out

Specifies the timeout period for waiting for an MPLS Echo Reply packet after an MPLS Echo Request packet is sent.

The value is an integer ranging from 0 to 65535, in milliseconds.
-v

Specifies output details.

-
-g

Specifies MPLS packet fragmentation.

-
ip destination-iphost

Specifies an IPv4 address or host name for the destination.

If the value is an IP address, it is in dotted decimal notation. If the value is a host name, it is a string of 1 to 255 case-sensitive characters, spaces not supported.
mask-length

Specifies a mask length for the destination address.

The value is an integer ranging from 0 to 32.
ip-address

Indicates the destination address in the IP header of an MPLS ping packet with the prefix of 127.0.0.0/8.

The destination address in the IP header can be changed to trace test packets.

By default, the destination IP address carried in the IP header of an MPLS ping packet is 127.0.0.1.
nexthop nexthopAddr

Specifies an IP address for the next hop. This parameter is used when the ingress node has one or more next hops. You can specify this parameter to select one tunnel for connectivity check.

The value is in dotted decimal notation.

Views

All views

Default Level

0: Visit level

Usage Guidelines

Usage Scenario

The ping lsp command can be used to check the connectivity of LSPs on an MPLS network, and the tracert lsp command can be used to locate the faulty node.

LSP ping uses MPLS Echo Request and MPLS Echo Reply messages to check LSP connectivity. Packets are sent in UDP format through port 3503. The receive end identifies MPLS Echo Request and MPLS Echo Reply packets based on the UDP port number. An MPLS Echo Request packet carries the FEC information to be checked and is sent along the same LSP as other packets that belong to this FEC. In this manner, the LSP is checked. MPLS Echo Request packets are forwarded to the destination through MPLS, and MPLS Echo Reply packets are forwarded to the source using IP.

LDP LSP ping: You can run the ping lsp -c count -s packet-size ip destination-iphost mask-length command on the ingress to initiate a ping test to the egress to check the connectivity of an LSP. If multiple tunnels are configured on the ingress for load balancing, you can use the nexthop parameter to specify the next hop for checking the connectivity of a specified LSP.

If the LSP ping test result shows that a fault occurs on an LSP during traffic forwarding and consequently all data traffic on this LSP fails to reach the destination, you can run the tracert lsp command to locate the fault. LSP ping and LSP tracert can efficiently check LSP connectivity and locate faults on LSPs. On a live network, if an MPLS forwarding path is faulty, that is, data traffic on an LSP is interrupted, you can use LSP ping and LSP tracert to locate the faulty LSR.

Prerequisites

Before running the ping lsp command, ensure that the MPLS module has been enabled and is working properly.

Configuration Impact

To prevent the egress from forwarding a received MPLS Echo Request packet to other nodes, you can set the destination address in the IP header of the packet to 127.0.0.1/8 (the local loopback address) and the TTL value to 1.

Precautions

During an L3VPN LSP ping test, if the destination of a ping operation is a CE address, the ping can succeed even when the link between the CE and PE is faulty, because it is the end-to-end link between PEs that is detected.

Table 1 Description of the ping lsp (General) command output
Item Description
FEC: xxxx ping statistics

Ping statistics, including.

  • packet(s) transmitted: number of MPLS echo request packets sent.
  • packet(s) received: number of MPLS echo reply packets received.
  • % packet loss: percentage of the number of MPLS echo request packets with no responses to the total number of MPLS echo request packets sent.
  • round-trip min/avg/max: minimum, average, or maximum response time.
press CTRL_C to break

Stopping the ongoing ping test by pressing CTRL+C.
Reply from x.x.x.x

Response from the destination node to each MPLS echo request packet:

  • bytes: length of an MPLS echo reply packet.
  • sequence: sequence number of an MPLS echo reply packet.
  • time: response time, in milliseconds. If no ICMP echo reply packet is received within the timeout period, the system displays "Request time out".
xx data bytes

Length of a sent packet, in bytes.
