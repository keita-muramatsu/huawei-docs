preference (OSPFv3 view)

Function

The preference command sets a priority for OSPFv3 routes.

The undo preference command restores the default value.

By default, the prefence value of OSPFv3 routes is 10. When ASE is specified, the default value is 150.

Format

preference { preference | route-policy route-policy-name } *

preference ase { preference | route-policy route-policy-name } *

undo preference

undo preference ase

Parameters

Parameter Description Value
preference

Specifies a priority for OSPFv3 routes.

The value is an integer in the range from 1 to 255.
route-policy route-policy-name

Specifies the name of a route-policy.

The value is a string of 1 to 200 case-sensitive characters without spaces. The character string can contain spaces if it is enclosed with double quotation marks (").
ase

Sets a priority for AS external routes or NSSA routes.

-

Views

OSPFv3 view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Multiple dynamic routing protocols may run on a device at the same time. Therefore, routing information needs to be shared and selected among routing protocols. Therefore, a default preference is specified for each routing protocol. When multiple routes to the same destination are discovered by different routing protocols, the route discovered by the protocol with the highest priority is chosen for forwarding IP packets.

The smaller the preference value, the higher the priority.

Precautions

  • On a device running multiple routing protocols, changing the OSPFv3 preference may cause a change in the results of route selection among the routing protocols in the routing table.
  • If route-policy route-policy-nameis specified in the command, the following items can be matched: the route cost, route type, route tag, IPv6 route destination address ACL, IPv6 route destination address prefix list, IPv6 route next hop address ACL, IPv6 route next hop address prefix list, route source IP address prefix list, route source IP address ACL, routing protocol type, prefix modulo, and outbound interface. The route preference can be set.

    If the referenced policy contains unsupported attribute matching or behavior setting, unexpected results may occur.
  • Configuring different protocol preference values for different OSPFv3 processes on the public network may cause routing loops between devices. Configuring different protocol preference values for different OSPFv3 processes in the same VPN instance may cause routing loops between devices.

    If different preference values are configured for different OSPFv3 processes in the same VPN instance or on the public network using the preference [ ase ] preferencecommand, a message is displayed. Such a check is performed in the scenario where only the preferenceparameter is configured. If the route-policy parameter is also configured, such a check is not performed.

Example

# Set a priority for OSPFv3 routes.
<HUAWEI> system-view
[HUAWEI] ospfv3 1
[HUAWEI-ospfv3-1] preference 5
