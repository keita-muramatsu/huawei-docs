set master-key

Function

The set master-key command sets the system master key.

By default, the system uses the default master key.

Format

set master-key

Parameters

None

Views

User view

Default Level

3: Management level

Usage Guidelines

Usage Scenario

  • In the actual network environment, networks and devices are provided and maintained by network providers, and data belongs to tenants. To provide secure data transmission and storage on the network, ensure that keys are under complete control of the specific tenant and cannot be obtained by network providers or other tenants. To be specific, tenants need to have their own key management schemes. Tenants can run this command to manually change the system master key as required to improve data security and reliability.
  • There are three types of system master keys: default master key, automatically generated master key, and user-defined master key.
  • Default master key: a fixed binary number generated by the system. The length is 32 bytes.
  • Automatically generated master key: a random number generated by the system, which may contain letters and special characters. It is secure and does not need to be changed frequently.
  • User-defined master key: a user-defined string of 20 to 32 characters and must contain uppercase letters, lowercase letters, digits, and special characters.
  • When the device is delivered, the system master key is the default master key.

Precautions

  • The interval between two master key settings must be at least 3 minutes.
  • When changing the system master key, note the following points:
    • Enter the password of the current login user for identity authentication.
    • Read the risk warning. If you want to continue the change, enter Y on the terminal. If you do not want to change the master key, enter N on the terminal. The system then exits the master key change.
    • Select the system master key type. If you want to use the user-defined master key, enter Y on the terminal. If you want to use the automatically generated master key, enter N on the terminal. If you want to use the default master key, enter D on the terminal.
    • If you want to use a user-defined master key, you need to enter the new master key twice. The system proceeds to the next step only when the new master keys entered twice are the same.
  • The default system master key has no validity period and is not automatically updated, and no alarm is reported when it expires.
  • Both the master key automatically generated by the system and user-defined master key have a validity period. The value is specified by the set master-key update-days command in the diagnostic view. The default value is 1825, in days. You can also run the display master-key configuration command to view the validity period of the current master key. After the master key automatically generated by the system and user-defined master key expire, the device performs the following operations:
    • If the system master key is automatically generated, it is automatically updated when it expires.
    • If the system master key is user defined, it is not automatically updated when it expires. Instead, an expiration alarm will be reported. In this case, services will not be affected.
  • Configuration files can be shared between devices when the following conditions are met:
    • The two devices use the same system master key (either default or user-defined master key).
    • If the two devices use different system master keys, the historical master keys of the local device contain the system master key currently used by the peer device. In this case, you need to locally save the historical user-defined master keys configured on the two devices.
  • If the master key of the peer device does not exist on the local device, the configuration files of the two devices cannot be shared. In this case, if the configuration file of the peer device is copied to the local device as the configuration file for next startup, the configuration fails. To resolve this issue, use one of the following methods:
    • Change the master key on the local device to be the same as that on the peer device.
    • Change the master key on the peer device to be the same as that on the local device. Run the save configuration-filecommand to save and export the configuration file, upload the configuration file to the local device, and run the startup saved-configuration configuration-filecommand to specify the configuration file for next startup.
  • If an error occurs during the master key change, the system displays a message indicating that the master key fails to be changed. If the failure persists, contact technical support personnel.
  • If you run system diagnostic commands in another window during the execution of this command, the system may experience frame freezing for 3 to 4 seconds.
