bgp-ls identifier

Function

The bgp-ls identifier command configures a BGP-LS identifier for IS-IS.

The undo bgp-ls identifier command deletes a BGP-LS identifier configured for IS-IS.

By default, the BGP-LS identifier of IS-IS is 0.

Format

bgp-ls identifier identifier-value

undo bgp-ls identifier [ identifier-value ]

Parameters

Parameter Description Value
identifier-value

Specifies a BGP-LS identifier.

The value is an integer ranging from 2 to 65535.

Views

IS-IS view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

BGP-LS is a new method of collecting network topology information. After IS-IS topology advertisement is enabled, IS-IS reports topology information, such as node, link, and prefix information, to BGP. A BGP device obtains topology information based on topology IDs and reports the topology information to the controller. To set an IS-IS topology ID, run the bgp-ls identifier command.

The topology information discovered by IGPs is summarized and reported to an upper-layer controller through BGP. The powerful route selection capability of BGP offers the following advantages:

  • The requirements for the computing capability of the upper-layer controller are reduced, and the IGP capability of the controller is no longer required.
  • BGP summarizes topology information of each process or AS and directly sends complete topology information to the controller, facilitating path selection and calculation.
  • All topology information on the network is sent to the controller through BGP, unifying the topology sending protocol.

Devices in the same IS-IS level area have the same topology information. Therefore, you are advised to deploy BGP-LS only on two devices (one device functions as the backup device). If BGP-LS needs to be deployed on multiple devices in the same IS-IS level area, the identifiers of these devices must be the same (indicating that the topology information obtained by BGP devices is from the same IS-IS area) to ensure the accuracy of topology information collected by BGP.

Implementation Procedure

IS-IS topology information can be flooded only within an area. As a result, IS-IS cannot report multi-area topology information to the controller. To address this problem, deploy at least one BGP node in each IS-IS area and establish a BGP-LS peer relationship between each BGP node and the controller so that BGP-LS collects and reports topology information to the controller.

Configuration Impact

  • BGP-LS advertises all topology information (node, link, and prefix information), and the controller needs to save all topology information, consuming a large number of memory resources.
  • Any change in the topology information collected by BGP-LS will trigger IS-IS LSP flooding, which may burden the controller. As a result, the maximum number of IS-IS neighbors supported and the topology size will be affected.
  • BGP-LS requires topology synchronization between IS-IS and BGP, which further consumes CPU resources. As a result, IS-IS convergence is slowed down.

Example

# Set the BGP-LS identifier to 2 for IS-IS.
<HUAWEI> system-view
[HUAWEI] isis 1
[HUAWEI-isis-1] bgp-ls identifier 2
