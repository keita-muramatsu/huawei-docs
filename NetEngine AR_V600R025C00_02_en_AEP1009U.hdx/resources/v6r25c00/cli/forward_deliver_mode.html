forward deliver mode

Function

The forward deliver mode command sets the traffic distribution mode.

For the AR5700 and AR6700 series, the default traffic distribution mode is the port core binding mode. In the factory configuration file, the traffic distribution mode is automatic.

For the AR8100 and AR8700 series, the default traffic distribution mode is per-packet forwarding.

This command is supported only on the AR5710-S8TWDSE-LTE4EA, AR8700 series, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR5710-S10T1X2, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR8100 series and AR5710-S8P1XDSE-2LTE4EA.

Format

For AR8100 series, AR8700 series:

forward deliver mode { flow | packet }

For AR5700-H series, AR5710-S10T1X2, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR5710-S8P1XDSE-2LTE4EA, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5710-S8TWDSE-LTE4EA, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T:

Usage Guidelines

Usage Scenario

Packet application scenario:

When the number of CPU cores is greater than 4 and the number of flows is small, traffic-based 5-tuples or 3-tuples cannot be evenly distributed to multiple cores for processing. As a result, the advantages of multi-core CPUs cannot be brought into full play. You can use the per-packet forwarding mode so that flows are evenly distributed to multiple cores for processing, improving the forwarding performance of the device.

Flow application scenario:

When there are a large number of flows, traffic-based 5-tuples or 3-tuples are evenly distributed to multiple cores for processing, which can give full play to the advantages of multi-core CPUs. You can use this mode to improve the forwarding performance of the device.

Port application scenario:

When the number of CPU cores is less than or equal to 4 and the number of flows is small, traffic-based 5-tuples or 3-tuples cannot be evenly distributed to multiple cores for processing. As a result, the advantages of multi-core CPUs cannot be brought into full play. In this case, you can use the port-core binding mode so that traffic on the LAN and WAN ports is distributed to different cores for processing, improving the forwarding performance of the device.

Auto application scenario:

The number of CPU cores is less than or equal to 4. In the SD-WAN solution, the inner 5-tuple or 3-tuple of IPsec encrypted flows can be evenly distributed to multiple cores for processing, fully utilizing the advantages of multi-core CPUs. You can set the forwarding scheduling mode of the router to the automatic mode to improve the device forwarding performance.

After the flow mode is switched, traffic is unevenly distributed in traditional IPsec, NAT traversal, and UDP packet header encapsulation scenarios.

Precautions

  • The traffic distribution mode configured on the AR6700 and AR5700 series takes effect immediately. The traffic distribution mode configured on the AR8700 and AR8100 series takes effect only after the device is restarted.
  • When the traffic distribution mode needs to be set to the port-core binding mode on the AR6700 and AR5700 series, the inbound and outbound interfaces for traffic forwarding must be a LAN-side interface and a WAN-side interface.
  • Only AR6700 and AR5700 series support SD-WAN IPsec traffic distribution based on inner packets.
  • In SD-WAN scenarios, the AR6700 and AR5700 series negotiate the traffic distribution mode based on the SD-WAN IPsec traffic distribution capability supported by the site. When all sites that establish tunnels support the SD-WAN IPsec traffic distribution capability, the traffic distribution mode of the device is negotiated to the flow-core binding. When one site where a tunnel is established does not support the SD-WAN IPsec traffic distribution capability, the traffic distribution mode of the device is negotiated to the port-core binding.
  • If the traffic distribution mode has not been set for the AR8700 and AR8100 series, the default per-packet forwarding mode is used after the first restart when the configuration file is used for configuration restoration and the traffic distribution mode in the configuration file is flow-core binding. After the second restart, the traffic distribution mode is the flow-core binding mode.
  • After setting the traffic distribution mode on the AR8700 and AR8100 series, you need to save the configuration.

Example

# Set the traffic distribution mode to flow-core binding on the AR8700 and AR8100 series.
<HUAWEI> system-view
[HUAWEI] forward deliver mode flow
Info: Deliver mode is set successfully. Please save current configuration. Restart the device for the setting to take effect.
# Set the traffic distribution mode to flow-core binding on the AR5700 and AR6700 series.
<HUAWEI> system-view
[HUAWEI] forward deliver mode flow
Info: Deliver mode is set successfully.
