service-exclude protocol (NAT policy rule view)

Function

The service-exclude protocol command excludes a TCP/UDP/SCTP ports or IP-layer protocol from a policy rule, so that traffic with the port or IP-layer protocol does not match the policy.

The undo service-exclude protocol command deletes the excluded TCP/UDP/SCTP port or IP-layer protocol from the policy.

By default, this function is not configured.

Format

For AR8700 series, AR6700-H series:

service-exclude protocol { udp | tcp | sctp } [ source-port { source-port | start-source-port to end-source-port } &<1-64> | destination-port { destination-port | start-destination-port to end-destination-port } &<1-64> ] *

service-exclude protocol icmpv6 [ icmpv6-type { icmpv6-name | icmpv6-type-number { icmpv6-code-number [ to icmpv6-code-number ] } &<1-64> } ]

undo service-exclude protocol { udp | tcp | sctp } [ source-port { source-port | start-source-port to end-source-port } &<1-64> | destination-port { destination-port | start-destination-port to end-destination-port } &<1-64> ] *

undo service-exclude protocol icmpv6 [ icmpv6-type { icmpv6-name | icmpv6-type-number { icmpv6-code-number [ to icmpv6-code-number ] } &<1-64> } ]

Views

NAT policy rule view

Default Level

2: Configuration level

Usage Guidelines

If you reference TCP/UDP/SCTP ports or IP-layer protocols in a policy, you can run the service-exclude protocol command to exclude a port or IP-layer protocol. After the configuration, traffic with the port number or IP-layer protocol will not match the policy.

When configuring a nat policy, you can reference the TCP/UDP/SCTP port or IP-layer protocols in the policy to implemented port-based NAT. For example, two services Service1 (TCP, source port 0 to 65535, and destination port 100 to 120) and Service2 (TCP, source port 0 to 65535, and destination port 100 to 200) are available. NAT needs to be disabled for traffic that belongs to Service1 but needs to be implemented for traffic that belongs to Service2, and NATed traffic needs to be permitted. You can use configuration method 1 to assign different actions to different ports. This method increases policies as well as policy maintenance workloads. Alternatively, you can use configuration method 2 to run the service-exclude protocol command to configure the policy. This method has the same effect as method 1 and does not need additional policies.

Method 1:

<huawei> system-view

[HUAWEI] security-policy

[HUAWEI-policy-security] rule name policy_1

[HUAWEI-policy-security-rule-policy_1] service protocol Service1

[HUAWEI-policy-security-rule-policy_1] action no-nat

[HUAWEI-policy-security-rule-policy_1] quit

[HUAWEI-policy-security] rule name policy_permit

[HUAWEI-policy-security-rule-policy_2] service protocol Service2

[HUAWEI-policy-security-rule-policy_2] action source-nat address-group group1

[HUAWEI-policy-security-rule-policy_2] quit

Method 2:

<huawei> system-view

[HUAWEI] security-policy

[HUAWEI-policy-security] rule name policy_sec

[HUAWEI-policy-security-rule-policy_sec] service-exclude protocol Service1

[HUAWEI-policy-security-rule-policy_sec] service protocol Service2

[HUAWEI-policy-security-rule-policy_sec] action source-nat address-group group1

Example

# Exclude UDP source port 1024 in the nat policy as a policy matching condition. 
<HUAWEI> system-view
[HUAWEI] nat-policy
[HUAWEI-policy-nat] rule name policy_nat
[HUAWEI-policy-nat-rule-policy_nat] service-exclude protocol udp source-port 1024
