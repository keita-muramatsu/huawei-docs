bfd (SR Policy template view)

Function

The bfd bypass command enables BFD bypass in an SR Policy attribute template.

The bfd no-bypass command enables BFD no-bypass in an SR Policy attribute template.

The bfd no-bypass preferred command enables BFD packets not to preferentially use a local protection path in an SR Policy attribute template.

The undo bfd bypass command disables BFD bypass in an SR Policy attribute template.

The undo bfd no-bypass command disables BFD no-bypass in an SR Policy attribute template.

The undo bfd no-bypass preferred command disables BFD packets from not preferentially using a local protection path in an SR Policy attribute template.

By default, the BFD bypass function in an SR Policy attribute template is enabled.

Format

bfd { no-bypass [ preferred ] | bypass }

undo bfd { no-bypass [ preferred ] | bypass }

Parameters

Parameter Description Value
no-bypass

Enables BFD no-bypass in an SR Policy attribute template.

If this parameter is selected, BFD packets of an SR Policy are not transmitted over local protection paths such as TI-LFA and TE FRR. If the primary path fails, the BFD session directly reports a Down event, triggering a primary/backup switchover.

-
preferred

Enables BFD packets not to preferentially use a local protection path in an SR Policy attribute template.

If this parameter is selected and an SR Policy has a backup path, BFD packets on the primary path are not transmitted over a local protection path such as TI-LFA or TE FRR. If the primary path fails, the BFD session goes Down, and traffic is transmitted over the backup path. BFD packets on the backup path can be transmitted over the local protection path to ensure service continuity.

-
bypass

Enables BFD bypass in an SR Policy attribute template.

If this parameter is selected, BFD packets of an SR Policy can be transmitted over local protection paths such as TI-LFA and TE FRR. If the primary path fails, the BFD session does not directly report a Down event. As a result, the actual status of the primary path of the SR Policy cannot be detected.

-

Views

SR Policy template view

Default Level

2: Configuration level

Usage Guidelines

The bfd bypass (SR Policy Template view) command enables BFD bypass for an SR Policy attribute template. The srv6-te-policy bfd bypass (segment routing IPv6 view) command enables BFD bypass for all SRv6 TE Policies in the segment routing IPv6 view, to configure BFD bypass for a single SRv6 TE Policy, run the bfd bypass (SRv6 TE Policy view) command.

For the same SRv6 TE Policy, if both the srv6-te-policy bfd bypass (segment routing IPv6 view) and bfd bypass (SRv6 TE Policy view) commands are run and the template referenced by the primary path of the policy has BFD configurations, run the bfd enable (SRv6 TE Policy view) command. The configuration of bfd enable (SRv6 TE Policy view) has the highest priority, the configuration of bfd bypass (SR Policy Template view) has the second highest priority, and the configuration of srv6-te-policy bfd bypass (SR IPv6 view) has the lowest priority.

Example

# Enable the BFD no-bypass function in an SR Policy attribute template.
<HUAWEI> system-view
[HUAWEI] segment-routing policy-template 1
[HUAWEI-sr-policy-template-1] bfd no-bypass
# Enable BFD packets not to preferentially use a local protection path in an SR Policy attribute template.
<HUAWEI> system-view
[HUAWEI] segment-routing policy-template 1
[HUAWEI-sr-policy-template-1] bfd no-bypass preferred
