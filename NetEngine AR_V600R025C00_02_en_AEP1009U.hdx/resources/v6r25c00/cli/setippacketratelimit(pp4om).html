host-packet rate-limit

Function

The host-packet rate-limit command sets the maximum rate at which host packets are processed.

The undo host-packet rate-limit command cancels the configuration.

By default, the maximum rate at which a host processes TTL Exceeded packets and Port Unreachable packets per second during the trace process is 256 pps, and the maximum rate at which a host processes ping request packets per second is 300 pps.

Format

host-packet rate-limit ttl-exceeded rate-value all

host-packet rate-limit port-unreachable rate-value all

host-packet rate-limit icmp-echo rate-value all

undo host-packet rate-limit ttl-exceeded all

undo host-packet rate-limit port-unreachable all

undo host-packet rate-limit icmp-echo all

Parameters

Parameter Description Value
rate-value

Specifies the maximum rate at which host packets of a specified type are processed, in packets per second (pps).

The value is an integer ranging from 1 to 1024.
port-unreachable

Indicates Port Unreachable packets during the trace process.

-
ttl-exceeded

Indicates TTL Exceeded packets during the trace process.

-
all

Indicates all boards.

-
icmp-echo

Indicates ping request packets.

-

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

You can adjust the maximum rate at which a host processes tracert packets based on the actual service scale on the live network. When there are a large number of services and users on the live network and a large number of normal tracert packets exist on the network, you can run this command to increase the maximum packet processing rate so that the host can process more tracert packets. When the service scale on the live network is small or tracert packet attacks exist, you can run this command to reduce the maximum packet processing rate to protect the CPU.

Configuration Impact

If the maximum rate at which host packets are processed is increased to a value greater than the default value, the CPU usage may increase.

Precautions

This command can only adjust the maximum rate at which host packets are processed, but cannot adjust the rate at which packets are sent from the underlying layer to a host. You can run the cpu-defend policy and car commands to adjust the maximum rate at which packets are sent from the underlying layer to a host. The "IPV4 TTL expires" packets in the CAR channel correspond to the "IPv4 ttl-exceeded" packets of the host, and the "IPV4 UDP packet to CPU" packets correspond to the "IPv4 port-unreachable" packets of the host.

You can specify the slot <slotid> parameter to deliver the configuration to the specified board or specify the all parameter to deliver the configuration globally. The board-level configuration and global configuration can coexist. The board-level configuration has a higher priority. That is, if both the global configuration and board-level configuration have been delivered for a board, the board-level configuration takes effect.

Example

# Set the maximum rate at which IPv4 TTL Exceeded packets are processed on all boards to 100 pps.
<HUAWEI> system-view
[HUAWEI] host-packet rate-limit ttl-exceeded 100 all
