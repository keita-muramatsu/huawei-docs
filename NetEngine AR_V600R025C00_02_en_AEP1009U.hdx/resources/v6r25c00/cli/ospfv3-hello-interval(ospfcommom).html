ospfv3 timer hello

Function

The ospfv3 timer hello command sets the interval at which Hello packets are sent on an interface.

The undo ospfv3 timer hello command restores the default value.

By default, for P2P and broadcast interfaces, the interval is 10 seconds, for P2MP and NBMA interfaces, the interval is 30 seconds.

Format

ospfv3 timer hello interval [ conservative ] [ instance instance-id ]

undo ospfv3 timer hello [ interval [ conservative ] ] [ instance instance-id ]

Parameters

Parameter Description Value
interval

Specifies the interval at which the multi-area adjacency interface sends Hello packets.

The value is an integer ranging from 1 to 65535.
conservative

Indicates the conservative mode of the dead timer.

-
instance instance-id

Specifies the interface instance ID.

The value is an integer ranging from 0 to 255. The default value is 0.

Views

10GE interface view, 25GE sub-interface view, 25GE interface view, 40GE interface view, Dialer interface view, Eth-Trunk interface view, Ethernet interface view, GE optical interface view, GE sub-interface view, GE electrical interface view, IP-Trunk interface view, MP-group interface view, POS interface view, VLANIF interface view, 40GE sub-interface view, 10GE sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Hello packets are periodically exchanged by OSPFv3 interfaces to establish and maintain neighbor relationships. A Hello packet contains information about timers, DRs, BDRs, and known neighbors.

The smaller the interval value, the faster a network topology change can be detected, and the larger the route cost. Ensure that the parameters of this interface and the adjacent routers are consistent.

To speed up OSPFv3 convergence in the case of a link failure, configuring BFD For OSPFv3 is recommended. If the remote end does not support BFD for OSPFv3 or you do not want to configure BFD for OSPFv3, specify conservative when you run the ospfv3 timer hello command. If the conservative mode is configured, the value configured for the dead timer using the ospfv3 timer dead command takes effect even when the value is less than 10s; if the value configured for the dead timer is greater than 10s, services may be affected.

Precautions

  • OSPFv3 does not support the configuration on null interfaces.
  • If the configured interval (X) for sending Hello packets is less than 10s, the actual interval for sending Hello packets is calculated using the following formula: Actual interval = X/2 + X%2, where X%2 refers to X mod 2. This prevents neighbor flapping and improves network reliability.
  • If OSPFv3 packets are encapsulated into GRE packets, you are advised to set the interval for sending Hello packets to a large value. As OSPFv3 Hello packets are encapsulated into GRE data packets, which have a low priority and may be easily discarded during network congestion, OSPFv3 may fail to receive Hello packets within the dead time, interrupting the neighbor relationship.
  • If a Hello interval is set but no value is configured for the OSPFv3 dead timer, the OSPFv3 neighbor dead interval is four times the Hello interval. Therefore, if the interval for sending Hello packets is less than or equal to 2s, the OSPFv3 neighbor dead interval is less than 10s. If the OSPFv3 neighbor dead interval is less than 10s and no Hello packets are received within the dead interval, the neighbor relationships are disconnected. To prevent this problem, if the interval for sending Hello packets is set to 1s, the system automatically sets the OSPFv3 neighbor dead interval to 10s. If the interval for sending Hello packets is set to 2s, the system automatically sets the OSPFv3 neighbor dead interval to 16s. This prevents neighbor flapping and improves network reliability. However, if the conservative mode is enabled, the OSPFv3 neighbor dead interval is still four times the hello interval.
  • If a Hello interval is set and the ospfv3 timer dead command is configured, the OSPFv3 neighbor dead interval takes effect based on the configured ospfv3 timer dead value. If the dead timer is too short, neighbor flapping may occur. Therefore, when the configured dead timer is less than 10s, special processing is performed on the value that takes effect. For details, see the description of the ospfv3 timer dead command. To allow the configured dead timer to take effect in this case, configure the conservative parameter.
  • If the dead timer is too short, OSPFv3 neighbor relationships may easily go down due to timeout, affecting services. To prevent this problem, you are advised to keep the default configurations of the ospfv3 timer hello and ospfv3 timer dead commands. Alternatively, set a value that is no less than 40s for the dead timer using the ospfv3 timer dead command.

Example

# Set the interval at which Hello packets are sent on the interface in instance 1 to 20 seconds. 
<HUAWEI> system-view
[HUAWEI] ospfv3 1
[HUAWEI-ospfv3-1] quit
[HUAWEI] interface 10GE 0/0/0
[HUAWEI-10GE0/0/0] undo portswitch
[HUAWEI-10GE0/0/0] ipv6 enable
[HUAWEI-10GE0/0/0] ospfv3 1 area 0 instance 1
[HUAWEI-10GE0/0/0] ospfv3 timer hello 20 instance 1
