apply-label pop-go (VPN instance IPv6 address family view)

Function

The apply-label per-route pop-go command configures a device to assign a unique label to each route (in the VPN instance IPv6 address family) sent to its peer PE. After receiving a data packet encapsulated with such a label, the device removes the label, searches the incoming label map (ILM) for the corresponding outbound interface, and forwards the packet.

The undo apply-label per-route pop-go command restores the default configuration.

The apply-label per-nexthop pop-go command configures a device to assign a unique label to all routes (in the VPN instance IPv6 address family) that share the same next hop to its peer PE. After receiving a data packet encapsulated with such a label, the device removes the label, searches the incoming label map (ILM) for the corresponding outbound interface, and forwards the packet.

The undo apply-label per-nexthop pop-go command restores the default configuration.

By default, after a device receives a labeled data packet, the device removes the label of the data packet and forwards the packet based on a forwarding entry found in its IP forwarding table according to the longest-match rule.

Format

apply-label { per-nexthop | per-route } pop-go

undo apply-label { per-nexthop | per-route } pop-go

Parameters

Parameter Description Value
per-nexthop

Indicates the one-label-per-next-hop label distribution mode.

-
per-route

Indicates the one-label-per-route label distribution mode.

-

Views

VPN instance IPv6 address family view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

By default, in a BGP/MPLS IP VPN scenario, after a local device receives a labeled data packet from a VPN instance IPv6 address family, it removes the label and forwards the packet based on a forwarding entry found in its IP forwarding table according to the longest-match rule.

Before a local device with the apply-label per-route pop-go command configured sends a BGP VPNv6 route to its BGP VPNv6 peer, it records in its ILM the mapping between the label assigned to the route and the outbound interface of the route. After the local device receives a labeled data packet from its BGP VPNv6 peer, it directly searches its ILM for an outbound interface based on the label carried in the packet, instead of searching its IP forwarding table according to the longest-match rule. The device then removes the label and forwards the packet through the found outbound interface. This implementation significantly accelerates packet forwarding.

Before a local device with the apply-label per-nexthop pop-go command configured sends a BGP VPNv6 route to its BGP VPNv6 peer, it records in its ILM the mapping between the label assigned to the route's next hop and the outbound interface corresponding to the next hop. After the local device receives a labeled data packet from a VPN instance peer, it directly searches its ILM for an outbound interface based on the label carried in the packet, instead of searching its IP forwarding table according to the longest-match rule. The device then removes the label and forwards the packet through the found outbound interface. This implementation significantly accelerates packet forwarding.

Prerequisites

An RD has been configured using the route-distinguisher command in the VPN instance IPv6 address family view.

Precautions

The apply-label pop-go command is mutually exclusive with the apply-label command (VPN instance IPv6 address family view). The latest configuration overrides the previous one.

After the apply-label pop-go command is run, the system pops out the label, searches the ILM for the corresponding outbound interface, and forwards the packet without any lookup in the IP forwarding table. The apply-label command, however, requires a lookup in the routing and forwarding table to forward the packet.

If a large number of routes exist, the one-label-per-route label distribution mode may cause the number of labels to exceed the upper limit. Therefore, use this mode on demand.

Example

# Configure vpn1 to assign a unique label to routes with the same next hop and forward received data packets that carry the assigned label through the corresponding outbound interface after removing the label.
<HUAWEI> system-view
[HUAWEI] ip vpn-instance vpn1
[HUAWEI-vpn-instance-vpn1] ipv6-family
[HUAWEI-vpn-instance-vpn1-af-ipv6] route-distinguisher 100:1
[HUAWEI-vpn-instance-vpn1-af-ipv6] apply-label per-nexthop pop-go
# Configure vpn1 to assign a unique label to each route and forward received data packets that carry assigned labels through the corresponding outbound interfaces after removing these labels.
<HUAWEI> system-view
[HUAWEI] ip vpn-instance vpn1
[HUAWEI-vpn-instance-vpn1] ipv6-family
[HUAWEI-vpn-instance-vpn1-af-ipv6] route-distinguisher 100:1
[HUAWEI-vpn-instance-vpn1-af-ipv6] apply-label per-route pop-go
