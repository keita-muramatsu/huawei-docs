hrp tcp link-state check delay

Function

The hrp tcp link-state check delay command sets a delay for TCP session status detection.

The undo hrp tcp link-state check command cancels the delay.

By default, TCP session status detection is not delayed.

Format

hrp tcp link-state check delay delay-time

undo hrp tcp link-state check

Parameters

Parameter Description Value
delay-time

Specifies the delay period.

The value is an integer ranging from 0 to 1800, in seconds. The value 0 indicates no delay, which is the same as the effect of the undo hrp tcp link-state check command.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

When the upstream and downstream service interfaces on the device work in hot standby mode at Layer 2 and TCP session status detection is enabled on the device, run the hrp tcp link-state check delay command on active and standby devices to set a delay for TCP session status detection. Otherwise, the new active device upon a switchover fails to establish sessions because it cannot immediately learn the MAC address table. After a delay is set, TCP session status detection is postponed on the new active device after a switchover, ensuring that the new active device has enough time to learn the MAC address table.

Example

# Set a delay to 60 seconds for TCP session status detection.
<HUAWEI> system-view
[HUAWEI] hrp tcp link-state check delay 60
