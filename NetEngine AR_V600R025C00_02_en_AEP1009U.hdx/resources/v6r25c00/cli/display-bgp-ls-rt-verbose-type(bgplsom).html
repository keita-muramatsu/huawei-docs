display bgp link-state unicast routing-table type verbose (All views)

Function

The display bgp link-state unicast routing-table type verbose command displays detailed information about BGP-LS routes based on the route type.

Format

display bgp link-state unicast routing-table type { node | link | ipv4-prefix | ipv6-prefix | te-policy | srv6-sid } verbose

Parameters

Parameter Description Value
node

Indicates node routes.

-
link

Indicates link routes.

-
ipv4-prefix

Indicates IPv4 prefix routes.

-
ipv6-prefix

Indicates IPv6 prefix routes.

-
te-policy

Indicates TE Policy routes.

-
srv6-sid

Indicates SRv6-SID routes.

-
type

Indicates route type information.

-

Views

All views

Default Level

1: Monitoring level

Usage Guidelines

The display bgp link-state unicast routing-table type verbose command displays detailed information about BGP-LS routes based on the route type. BGP-LS routes carry network topology information and are classified into node routes, link routes, prefix routes, TE Policy routes, SRv6 SID routes, and network slice routes. The preceding routes carry node, link, route prefix, TE Policy, SRv6 SID, and network slice routing information, respectively. The six types of routes work together to transmit topology information.

Flags

TE policy descriptor:

* E-Flag (0x80): If this flag is set, the endpoint address is an IPv6 address. If this flag is cleared, the endpoint address is an IPv4 address.

* O-Flag (0x40): If this flag is set, the initiator address is an IPv6 address. If this flag is cleared, the initiator address is an IPv4 address.

CP State:

* S-Flag (0x8000): If this flag is set, the candidate path is in the administratively closed state.

* A-Flag (0x4000): If this flag is set, the candidate path is an active path (for example, a path deployed on the forwarding plane).

* B-Flag (0x2000): If this flag is set, the candidate path is a backup path of an SR Policy (to protect the primary path).

* E-Flag (0x1000): If this flag is set, validity of the candidate path has been evaluated. (The headend evaluates the validity of the candidate path based on the priority.).

* V-Flag (0x0800): If this flag is set, the candidate path has at least one valid SID-List. When the E-Flag is cleared (for example, the candidate path has not been evaluated), this flag must be set to 0 by the initiator and ignored by the receiver.

* O-Flag (0x0400): If this flag is set, the candidate path has been instantiated based on the on-demand next-hop trigger of the local template. For details, see 8.5 of [I-D.ietf-spring-segment-routing-policy].

* D-Flag (0x0200): If this flag is set, the candidate path is delegated to a PCE or controller for computation.

* C-Flag (0x0100): If this flag is set, the candidate path is provided by the PCE or controller.

* I-Flag (0x0080): If this flag is set, the candidate path is discarded when it is invalid when no other active path is available for the SR Policy and the path is the optimal one among active candidate paths. For details, see 8.2 [I-D.ietf-spring-segment-routing-policy].
