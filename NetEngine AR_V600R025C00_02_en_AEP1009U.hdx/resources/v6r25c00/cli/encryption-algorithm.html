encryption-algorithm

Function

The encryption-algorithm command configures an encryption algorithm for IKE negotiation.

The undo encryption-algorithm command restores the default configuration.

By default, the AES-GCM-256 encryption algorithm is used for IKE negotiation.

Format

encryption-algorithm { des | 3des | aes-128 | aes-192 | aes-256 | sm4 | aes-gcm-128 | aes-gcm-192 | aes-gcm-256 } *

undo encryption-algorithm

Parameters

Parameter Description Value
des

Indicates that the Data Encryption Standard (DES) algorithm in Cipher Block Chaining (CBC) mode is used, and the key length is 56 bits.

-
3des

Indicates that the Triple DES (3DES) algorithm in CBC mode is used and the key length is 168 bits.

-
aes-128

Indicates that the Advanced Encryption Standard (AES) algorithm in CBC mode is used. The key length is 128 bits.

-
aes-192

Indicates that the Advanced Encryption Standard (AES) algorithm in CBC mode is used. The key length is 192 bits.

-
aes-256

Indicates that the Advanced Encryption Standard (AES) algorithm in CBC mode is used and the key length is 256 bits.

-
sm4

Uses the SM4 encryption algorithm defined by China's State Cryptography Administration. It uses a 128-bit key. The attribute value of the SM4 algorithm is 129.

-
aes-gcm-128

Indicates that the GCM Advanced Encryption Standard (AES) algorithm is used and the key length is 128 bits.

-
aes-gcm-192

Indicates that the GCM Advanced Encryption Standard (AES) algorithm is used and the key length is 192 bits.

-
aes-gcm-256

Indicates that the GCM Advanced Encryption Standard (AES) algorithm is used and the key length is 256 bits.

-

Views

IKE proposal view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

To improve the success rate of IKE negotiation, the device supports multiple encryption algorithms. During IKE negotiation, the algorithms are tried from the highest security level to the lowest security level. The encryption algorithms used in an IKE proposal are listed in descending order of security level: sm4 > aes-gcm-256 > aes-gcm-192 > aes-gcm-128 > aes-256 > aes-192 > aes-128 > 3des > des.

Precautions

SM4 can meet high confidentiality and security requirements, but takes a comparatively long time for processing. 3DES, DES, and AES-CBC are not secure enough and therefore are not recommended.

You can specify parameters 3des, des, aes-128, aes-192, and aes-256 in this command only after the weak security algorithm/protocol feature package (WEAKEA) is installed using the install feature-software WEAKEA command.

You can specify the sm4 parameter in this command only after the IKEv1 feature package is installed.

If the IKEv1 feature package has been installed, AES algorithms in CBC mode can also be used.

For IKE peers that support only IKEv1, AES algorithms in GCM mode cannot be configured in IKE proposals. For IKE peers that support only IKEv2, the SM4 algorithm cannot be configured in IKE proposals.

When a GCM algorithm is used for IKE negotiation, the negotiation can succeed even if the two ends use different integrity algorithms.

Example

# Set the AES-GCM-192 algorithm for IKE proposal 10. 
<HUAWEI> system-view
[HUAWEI] ike proposal 10
[HUAWEI-ike-proposal-10] encryption-algorithm aes-gcm-192
