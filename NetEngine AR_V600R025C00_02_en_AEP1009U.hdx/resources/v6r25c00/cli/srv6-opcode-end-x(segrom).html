opcode end-x

Function

The opcode end-x command configures a static SRv6 End.X SID operation code (Opcode).

The undo opcode end-x command deletes a static SRv6 End.X SID operation code.

By default, no opcode is configured for static SRv6 End.X SIDs.

Format

opcode func-opcode end-x interface { interface-name | interface-type interface-number } nexthop nexthop-address { no-flavor | psp | psp-usp-usd }

undo opcode func-opcode end-x interface { interface-name | interface-type interface-number } nexthop nexthop-address [ no-flavor | psp | psp-usp-usd ]

Parameters

Parameter Description Value
func-opcode

Specifies a static SRv6 End.X SID operation code.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.

Specifies an interface name.

-

Specifies the type of an interface.

-
interface-number

Specifies an interface number.

nexthop nexthop-address

Specifies the next-hop address.

The value is a 32-digit hexadecimal number, in the format of X:X:X:X:X:X:X:X.
no-flavor

Cancels the flavor attribute. After this parameter is configured, only the USP flavor is available by default.

-
psp

Specifies the PSP flavor.

-
psp-usp-usd

Specifies the PSP, USP, and USD flavors.

The USD flavor is often used in scenarios where an SRv6 TE Policy does not have a service SID (for example, an IPv4 public network service without any End.DT4 SID is redirected to an SRv6 TE Policy). When packets are forwarded to the device where the last SID resides, they can be properly decapsulated.

Usage Guidelines

Usage Scenario

An SRv6 SID is a 128-bit IPv6 address expressed in the Locator:Function:Args format. The Function field is also called Opcode. Configuring different Opcodes is equivalent to defining different functions. Opcodes can be dynamically allocated using an IGP or statically configured using the opcode command.

Static Opcodes need to be configured in the range of the static segment to prevent conflicts with the Opcodes dynamically allocated by the IGP. The length of the static segment is determined by the static static-length parameter in the locator command, and it is used to specify the range of static Opcodes that can be configured in the locator.

After various types of Opcodes are statically configured using the opcode command, the locator, Opcode, and Args form a unique SRv6 SID. After SRv6 SIDs are generated, they are added to the local SID table and can be advertised using a routing protocol. During forwarding, the locator part in an SRv6 SID helps other nodes on the network perform route addressing, find the node that generates the SRv6 SID, and forward the SRv6 packet to this node. The Opcode part instructs the node that generates the SRv6 SID to perform corresponding functions.

End.X is short for Layer-3 cross-connect. End.X supports the forwarding of packets from a specified link to a Layer 3 adjacency. It can be used in scenarios such as TI-LFA and strict explicit path-based TE scenarios. End.X is essentially a change based on End. The instruction is disassembled into End + X, where X indicates cross-connect (direct packet forwarding to a specified Layer 3 adjacency). Therefore, an End.X SID must be bound to a Layer 3 adjacency or a group of Layer 3 adjacencies. This instruction decrements the SL value by 1, obtains the next SID from the SRH based on the SL value, adds the SID to the destination address field in the IPv6 header, and forwards the IPv6 packet to the Layer 3 adjacency bound to the End.X SID.

S-flag indicates that an End.X SID is associated with a group of adjacencies. Data traffic can be load balanced among these adjacencies.

Precautions

  • To ensure proper forwarding, various static SIDs cannot conflict with IPv6 addresses configured on interfaces. When configuring parallel labels for IS-IS P2P links, you are advised to run the ipv6 advertise link attributes command in the IS-IS process.
  • To ensure that the configured SID takes effect, the specified next-hop address must be the remote interface's global IPv6 address or link-local address and reside on the same network segment as the address of the local outbound interface.
  • If the configured next-hop address is the global IPv6 address of the neighboring interface, OSPFv3 can advertise the corresponding End.X SID only after the neighbor advertises this global IPv6 address in an OSPFv3 E-Router-LSA.

Example

# Configure an opcode for a static SRv6 End.X SID.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] locator test1 ipv6-prefix 2001:DB8:100:: 64 static 32
[HUAWEI-segment-routing-ipv6-locator] opcode ::200 end-x interface 10GE0/0/1 nexthop 2001:DB8:400::100 no-flavor
[HUAWEI-segment-routing-ipv6-locator] opcode ::201 end-x interface 10GE0/0/1 nexthop 2001:DB8:400::100 psp
