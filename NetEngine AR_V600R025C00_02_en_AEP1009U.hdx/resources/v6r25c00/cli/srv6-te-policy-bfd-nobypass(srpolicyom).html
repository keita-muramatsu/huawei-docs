bfd no-bypass

Function

The bfd no-bypass command enables BFD no-bypass for an SRv6 TE Policy.

The bfd bypass command enables BFD bypass for an SRv6 TE Policy.

The bfd no-bypass preferred command enables BFD packets of an SRv6 TE Policy not to preferentially use a local protection path.

The undo bfd no-bypass command deletes the BFD no-bypass configuration and inherits the srv6-te-policy bfd no-bypass configuration.

The undo bfd bypass command deletes the BFD bypass configuration and inherits the srv6-te-policy bfd no-bypass configuration.

The undo bfd no-bypass preferred command deletes the BFD no-bypass preferred configuration and inherits the srv6-te-policy bfd no-bypass configuration.

By default, the srv6-te-policy bfd no-bypass configuration is inherited.

Format

bfd { no-bypass [ preferred ] | bypass }

undo bfd { no-bypass [ preferred ] | bypass }

Parameters

Parameter Description Value
no-bypass

Enables BFD no-bypass for an SRv6 TE Policy.

If this parameter is selected, BFD packets of an SRv6 TE Policy do not pass through a local protection path such as a TI-LFA and TE FRR path. If the primary path fails, the BFD session goes Down directly, triggering an SRv6 TE Policy primary/backup switchover.

-
preferred

Enables BFD packets of an SRv6 TE Policy not to preferentially use a local protection path.

If this parameter is selected and an SRv6 TE Policy has a backup path, BFD packets on the primary path are not transmitted over a local protection path such as TI-LFA or TE FRR. If the primary path fails, the BFD session goes Down, and traffic is transmitted over the backup path. BFD packets on the backup path can be transmitted over the local protection path to ensure service continuity.

-
bypass

Enables BFD bypass for an SRv6 TE Policy.

If this parameter is selected, BFD packets of an SRv6 TE Policy can be transmitted over a local protection path such as TI-LFA or TE FRR. If the primary path fails, the BFD session does not report a Down event. As a result, the actual status of the primary path of the SRv6 TE Policy cannot be detected.

-

Views

SRv6 TE policy view

Default Level

2: Configuration level

Usage Guidelines

In scenarios where BFD for SRv6 TE Policy is deployed, if the segment lists of the primary candidate path all fail and a local protection path (for example, a TI-LFA or TE FRR path) exists, the BFD session remains Up, and data traffic is switched to the TI-LFA or TE FRR path. However, the performance such as the bandwidth/latency of the TI-LFA or TE FRR path may be unstable, preventing the path from meeting the strict SLA requirements of high-value private line services. To resolve this problem, you can enable BFD traffic to bypass local protection paths. In this way, BFD goes Down if the segment lists of the primary candidate path all fail, triggering the candidate path to also go Down. As a result, traffic is switched to a backup candidate path or another SRv6 TE Policy.

The srv6-te-policy bfd no-bypass command globally enables the BFD no-bypass function for all SRv6 TE Policies in the Segment Routing IPv6 view. The bfd { no-bypass [ preferred ] | bypass } command can be used to configure the BFD no-bypass or bypass function for a single SRv6 TE Policy.

If both the srv6-te-policy bfd no-bypass and bfd { no-bypass [ preferred ] | bypass } commands are run for an SRv6 TE Policy, the bfd { no-bypass [ preferred ] | bypass } command takes precedence.

Example

# Enable BFD no-bypass for an SRv6 TE Policy named policy1.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] srv6-te policy policy1 endpoint 2001:DB8:1::1 color 100
[HUAWEI-segment-routing-ipv6-policy-policy1] bfd no-bypass
# Enable the BFD packets of SRv6 TE Policy named policy1 not to preferentially use a local protection path.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] srv6-te policy policy1 endpoint 2001:DB8:1::1 color 100
[HUAWEI-segment-routing-ipv6-policy-policy1] bfd no-bypass preferred
