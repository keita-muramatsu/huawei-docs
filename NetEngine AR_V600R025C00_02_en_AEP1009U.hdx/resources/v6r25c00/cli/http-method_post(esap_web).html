http-method post

Function

The http-method post command configures parameters for parsing and replying to POST/GET request packets of the HTTP or HTTPS protocol.

The undo http-method post command restores the default setting.

By default, parameters for parsing and replying to POST or GET requests of the HTTP or HTTPS protocol have been configured on the device. For details, see "Parameters" in the command.

Format

http-method post { cmd-key cmd-key [ login login-key | logout logout-key ] * | init-url-key init-url-key | login-fail response { err-msg { authenserve-reply-message | msg inFailErrMsg } | redirect-login-url | redirect-url inFailRedirUrl [ append-reply-message inFailRedirMsg ] } | login-success response { msg inSuccMsg | redirect-init-url | redirect-url inSuccRedirUrl } | logout-fail response { msg outFailMsg | redirect-url outFailRedirUrl } | logout-success response { msg outSuccMsg | redirect-url outSuccRedirUrl } | password-key password-key | user-mac-key user-mac-key | userip-key userip-key | username-key username-key } *

http-method post { cmd-key cmd-key [ login login-key | logout logout-key ] * | init-url-key init-url-key | login-fail response { err-msg { authenserve-reply-message | msg inFailErrMsg } | redirect-login-url | redirect-url inFailRedirUrl [ append-reply-message inFailRedirMsg ] | allow-origin inFailOrgUrl } | login-success response { msg inSuccMsg | redirect-init-url | redirect-url inSuccRedirUrl | allow-origin inSuccOrgUrl } | logout-fail response { msg outFailMsg | redirect-url outFailRedirUrl } | logout-success response { msg outSuccMsg | redirect-url outSuccRedirUrl } | password-key password-key | user-mac-key user-mac-key | userip-key userip-key | username-key username-key } *

undo http-method post { all | { cmd-key | init-url-key | login-fail | login-success | logout-fail | logout-success | password-key | user-mac-key | userip-key | username-key } * }

Parameter Description Value
cmd-key cmd-key

Specifies the command identification keyword. The default value is cmd.

The value of this parameter must be the same as that configured on the Portal server.

The value is a string of 1 to 16 case-sensitive characters without spaces, question marks (?), ampersands (&), and equal signs (=).

Specifies the user login identification keyword. The default value is login.

The value of this parameter must be the same as that configured on the Portal server.

The value is a string of 1 to 15 case-sensitive characters without spaces, question marks (?), ampersands (&), and equal signs (=).

Specifies the user logout identification keyword. The default value is logout.

Default Level

2: Configuration level

Usage Guidelines

When the device uses the HTTP or HTTPS protocol to communicate with the Portal server, a user sends POST/GET request packets (carrying parameters such as the user name and MAC address) to the device as required by the Portal server. After receiving the POST/GET request packets, the device parses parameters in the packets. If identification keywords of the parameters differ from those configured on the device, the user authentication fails. Therefore, you need to run the http-method post command to configure the identification keywords based on the Portal server configuration.

After a successful or failed user login or logout, the device sends the login or logout result to the user based on the http-method post command configuration. For example, by default, the device sends the LogoutSuccess! message to a user who logs out successfully.

Example

# Change the command identification keyword to cmd1 on the device when the command identification keyword in POST request packets is cmd1 on the connected Portal server.
<HUAWEI> system-view
[HUAWEI] web-auth-server abc
[HUAWEI-web-auth-server-abc] http-method post cmd-key cmd1
