traffic-filter(Traffic profile view)

Function

The traffic-filter command configures ACL-based packet filtering in a traffic profile.

The undo traffic-filter command cancels configuration of ACL-based packet filtering in a traffic profile.

By default, ACL-based packet filtering is not configured in a traffic profile.

Format

traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name }

traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name } l2 acl { acl-number-l2 | name acl-name-l2 }

traffic-filter { inbound | outbound } l2 acl { acl-number-l2 | name acl-name-l2 }

traffic-filter { inbound | outbound } ipv6 acl ipv6-acl-number

undo traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name }

undo traffic-filter { inbound | outbound } ipv4 acl { acl-number | name acl-name } l2 acl { acl-number-l2 | name acl-name-l2 }

undo traffic-filter { inbound | outbound } l2 acl { acl-number-l2 | name acl-name-l2 }

undo traffic-filter { inbound | outbound } ipv6 acl ipv6-acl-number

Parameters

Parameter Description Value
inbound

Configures packet filtering in the inbound direction.

-
outbound

Configures packet filtering in the outbound direction.

-
ipv4

Filters IPv4 packets.

-
acl ipv6-acl-number

Specifies the number of an advanced ACL.

The value is an integer that ranges from 3000 to 3031 for IPv6 ACLs.
acl acl-number

Specifies the number of the ACL.

The value is an integer that ranges from 3000 to 3031 for IPv4 ACLs.
acl acl-number-l2

Specifies a Layer 2 ACL number.

For Layer 2 ACLs, the value ranges from 4000 to 4031.
name acl-name

Filters packets based on a specified named ACL. The parameter acl-name specifies the name of the ACL.

The ACL name must exist.
name acl-name-l2

Filters packets based on a specified named Layer 2 ACL. The parameter acl-name-l2 specifies the name of an ACL.

The ACL name must exist.
l2

Filters Layer 2 packets.

-
ipv6

Configures ACL-based IPv6 packet filtering.

-

Views

Traffic profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

On a wireless network, administrators want to provide differentiated services for wireless users. The services may include, but are not limited to the following:

  • Deny or permit access of specified wireless users to specified LAN devices.
  • Deny access of specified wireless users to specified invalid IP addresses.

    You can configure ACL-based packet filtering in a traffic profile to provide differentiated services for wireless users based on ACL rules.

    When the traffic-filter command is configured in the traffic profile view, the device first matches packets against ACLs and then performs the action according to the matched policy.

    If multiple ACL-based packet filtering commands in the same direction are configured in a traffic profile, packets are matched against the next rule in the sequence in which the commands are configured. If packets match a rule, the device executes the specified policy and stops the matching process. Otherwise, the device continues to match packets against the next rule. If no rule is matched, the packets are allowed to pass through.

    In particular:
  • If a policy contains only one ACL and the ACL is matched, the permit or deny action is performed.
  • If a policy contains two ACLs, the device considers that the policy is matched only when the packets match both of the ACLs. The device then performs the corresponding action.

    For example, if the two matched ACL rules are both permit, the permit action is performed. Otherwise, the deny action is performed.

    If an ACL contains multiple rules, packets match against the rules in the ascending order of rule IDs. If packets match a rule, the device considers that the ACL is matched and stops the matching process. Otherwise, the device continues to match packets against the next rule. If no rule is matched, the device considers that this ACL is not matched. To improve match efficiency, you are advised to configure an ACL rule with a high match probability first and set a small ID for the rule. This will reduce the number of times ACL rules are matched and save resources.

Prerequisites

Ensure that an ACL rule has been created before this command is run.

  • acl name
  • acl ipv6 name
  • acl number
  • acl ipv6 number

Precautions

The traffic-filter command can reference a numbered ACL rule that is not configured. You can configure the referenced ACL rule after running this command.

You can only configure a maximum of eight ACL rules in the same direction. The sequence in which ACL rules take effect follows the sequence in which the rules are configured. To change the current packet filtering rules, delete all the related configurations and reconfigure the ACL-based packet filtering.

When configuring filtering for IPv6 packets, ensure that the device has been enabled to process STA IPv6 services of STAs using the sta-ipv6-service enable command.

Example

# Create the traffic profile p1 and configure traffic filtering based on the ACL with the name t1 and number 3000.
<HUAWEI> system-view
[HUAWEI] acl name t1 number 3000
[HUAWEI-acl4-advance-t1] rule 5 permit ip source 192.168.0.2 0
[HUAWEI-acl4-advance-t1] quit
[HUAWEI] wlan
[HUAWEI-wlan] traffic-profile name p1
[HUAWEI-wlan-traffic-prof-p1] traffic-filter inbound ipv4 acl name t1
# Create the traffic profile p1 and configure ACL-based IPv4 packet filtering in the inbound direction to permit IPv4 packets with source IP address 192.168.1.1/32.
<HUAWEI> system-view
[HUAWEI] acl 3000
[HUAWEI-acl4-advance-3000] rule 5 permit ip source 192.168.1.1 0
[HUAWEI-acl4-advance-3000] quit
[HUAWEI] wlan
[HUAWEI-wlan] traffic-profile name p1
[HUAWEI-wlan-traffic-prof-p1] traffic-filter inbound ipv4 acl 3000
[HUAWEI-wlan-traffic-prof-p1] quit
