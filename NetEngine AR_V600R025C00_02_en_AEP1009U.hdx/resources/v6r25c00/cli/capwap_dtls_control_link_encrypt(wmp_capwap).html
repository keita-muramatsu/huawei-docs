capwap dtls control-link encrypt (System view)

Function

The capwap dtls control-link encrypt command enables DTLS encryption for CAPWAP control tunnels.

The undo capwap dtls control-link encrypt command disables DTLS encryption for CAPWAP control tunnels.

By default, DTLS encryption for a control tunnel is disabled.

Format

capwap dtls control-link encrypt

undo capwap dtls control-link encrypt

Parameters

None

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

In the Discovery phase of the CAPWAP tunnel establishment between the client and server, the client obtains the server's IP address using the discovery mechanism. Then in the DTLS negotiation phase, a CAPWAP tunnel is established between the client and server based on this IP address. During this process, UDP packets transmitted over the CAPWAP tunnel are encrypted using DTLS.

After DTLS encryption is enabled on the local end, the local end authenticates the peer end using the configured authentication mode. After authentication succeeds, the local end negotiates a DTLS encryption key with the peer end based on the authentication mode to protect packets transmitted over the CAPWAP control tunnel. If the DTLS negotiation fails, the CAPWAP tunnel cannot be established.

Prerequisites

  1. The CAPWAP DTLS PSK has been configured.
  2. Default-certificate authentication or non-authentication access has been enabled so that the CAPWAP client connects to the server and the PSK is delivered.

Configuration Impact

After the configuration is modified, the AP and AC re-establish a CAPWAP tunnel.

Follow-up Procedure

After all clients access the network by means of CAPWAP DTLS, disable the function of establishing CAPWAP DTLS sessions through the initial certificate and in none authentication mode.

Precautions

When HA is enabled or APs are being upgraded, the status of DTLS encryption cannot be changed.

Before enabling this function, run the capwap dtls psk command to configure a PSK.

If this function is enabled on the peer end, authentication and DTLS encryption negotiation are still performed on the local end even if the function is disabled on the local end. If the local end fails the verification of the peer end, the CAPWAP tunnel fails to be established. To temporarily disable DTLS encryption on the local and peer ends, you can configure the function of establishing CAPWAP DTLS sessions in none authentication mode. However, this function brings security risks. Ensure that the peer and local ends are in a secure and trusted network environment. After the CAPWAP link is established, disable the function of establishing CAPWAP DTLS sessions in none authentication mode so that the local and peer ends re-establish a CAPWAP link in secure mode.

Example

# Enable DTLS encryption for CAPWAP control tunnels.
<HUAWEI> system-view
[HUAWEI] capwap dtls control-link encrypt
Warning: This operation may cause devices using CAPWAP connections to reset or go offline. Continue? [Y/N]:y
