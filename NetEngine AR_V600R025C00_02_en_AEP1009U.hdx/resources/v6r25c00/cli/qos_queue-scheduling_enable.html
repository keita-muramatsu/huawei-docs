qos queue-scheduling enable

Function

The qos queue-scheduling enable command enables the queue capability.

The undo qos queue-scheduling enable command disables the queue capability.

By default, the queue capability is disabled on an interface.

Format

qos queue-scheduling enable

undo qos queue-scheduling enable

Parameters

None

Views

10GE interface view, 25GE interface view, 40GE interface view, Cellular interface view, Dialer interface view, Eth-Trunk sub-interface view, Eth-Trunk interface view, GE interface view, Multi-GE interface view, Tunnel interface view, Sub-interface view, Interface group view, Virtual serial interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

By default, no queue resource is allocated to an interface. To use queue resources (such as HQoS) on an interface, you need to run this command to enable the queue capability on the interface so that queue resources can be dynamically allocated to the interface.

Prerequisites

To enable the queue capability on an Eth-Trunk sub-interface, you need to enable the queue capability on its Eth-Trunk main interface first.

To disable the queue capability on an Eth-Trunk main interface, you need to disable the queue capability on all its Eth-Trunk sub-interfaces first.

Configuration Impact

  • After the queue capability is enabled on an Eth-Trunk interface, a dialer interface, or a tunnel interface, the loopback function is enabled by default.
  • When the queue capability is enabled on a cellular interface, it is also enabled on the cellular channel interface of the interface.
  • For other physical interfaces, when the queue capability is enabled on an interface, it is not enabled on sub-interfaces of the interface. If the queue capability also needs to be used on a sub-interface, enable it in the sub-interface view.

Precautions

  • This command can be configured only on Layer 3 interfaces.
  • For the AR5700 series and AR6710-L8T3TS1X2, queue resources are not allocated to physical and logical interfaces by default. Therefore, this command can be configured on physical and logical interfaces.
  • For other models, queue resources are allocated to physical interfaces, but are not allocated to logical interfaces by default. Therefore, this command can be configured only on logical interfaces.
  • Queue resources are allocated to MP-group interfaces and serial interfaces created on E1 cards by default. Therefore, this command cannot be configured on MP-group interfaces and serial interfaces created on E1 cards. If queue resources are insufficient, creating these two types of interfaces will cause queue-related functions on the interfaces to become invalid. In this case, you need to create the interfaces again when queue resources are sufficient.

Example

# Enable the queue capability on an Eth-Trunk interface.
<HUAWEI> system-view
[HUAWEI] interface Eth-Trunk 1
[HUAWEI-Eth-Trunk1] qos queue-scheduling enable
