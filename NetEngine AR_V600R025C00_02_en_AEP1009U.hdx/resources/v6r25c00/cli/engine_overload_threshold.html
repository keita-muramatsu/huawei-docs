engine overload threshold

Function

The engine overload threshold command configures an engine overload threshold.

The undo engine overload threshold command restores the default engine overload threshold.

By default, the lower stacking threshold percentage is 5, the upper stacking threshold percentage is 10, the number of stacked packets is 30, and the single-core CPU usage is 90.

This command is supported only on the AR5710-S8TWDSE-LTE4EA, AR8700 series, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4, AR8100 series, AR5710-S8P1XDSE-2LTE4EA and AR6700-H series.

Format

engine overload threshold { app | stack } backlog low low-value high high-value

engine overload threshold flow backlog flow-value

engine overload threshold cpu-usage cpu-usage-value

undo engine overload threshold { app | stack } backlog

undo engine overload threshold flow backlog

undo engine overload threshold cpu-usage

Parameters

Parameter Description Value
app

Indicates the stacking threshold for determining whether the application layer is overloaded.

-
stack

Indicates the stacking threshold for determining whether the protocol stack is overloaded.

-
backlog

Indicates backlog.

-
low low-value

Sets the lower stacking threshold (percentage).

The value is an integer that ranges from 0 to 100. The default value is 5.
high high-value

Sets the upper stacking threshold (percentage).

The value is an integer that ranges from 0 to 100. The default value is 10.
flow

Indicates backlog packets.

-
flow-value

Sets the number of stacked packets.

The value is an integer that ranges from 1 to 512. The default value is 30.
cpu-usage cpu-usage-value

Sets the CPU usage.

The value is an integer that ranges from 1 to 100. The default value is 90.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

If traffic is stacked in the engine channel and the processing speed is too slow, you can run this command to set a traffic threshold and adjust the conditions for triggering traffic bypass. The detailed scenario is as follows:

  1. Run the engine overload threshold stack backlog low <low-value> high <high-value> command to set the stacking threshold for protocol stack overload.
  2. Run the engine overload threshold app backlog low <low-value> high <high-value> command to configure the stacking threshold for the application layer to process overload determination.
  3. Run the engine overload threshold cpu-usage <cpu-usage-value> command to set a single-core CPU usage threshold.
  4. Run the engine overload threshold flow backlog <flow-value> command to set the number of stacked packets.

Example

# Set the CPU usage threshold of a single core to 80% and the number of packets stacked in a single flow to 10. When the CPU usage of the corresponding engine instance is greater than 80% and the number of packets stacked in a flow exceeds 10, the current flow is bypassed.
<HUAWEI> system-view
[HUAWEI] engine overload threshold cpu-usage 80
[HUAWEI] engine overload threshold flow backlog 10
# Set the upper and lower overload thresholds of the engine to 10% and 20% respectively. When the number of packets backlogged in a channel exceeds 10% of the queue length, the service instance associated with the channel is overloaded and new flows are bypassed. When the number of packets backlogged in a channel exceeds 20% of the queue length, the service instance associated with the channel is overloaded and subsequent packets of the flows that have been sent to the CPU are bypassed.
<HUAWEI> system-view
[HUAWEI] engine overload threshold app backlog low 10 high 20
