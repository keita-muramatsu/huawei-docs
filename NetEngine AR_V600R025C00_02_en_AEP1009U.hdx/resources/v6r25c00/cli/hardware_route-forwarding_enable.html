hardware route-forwarding enable

Function

The hardware route-forwarding enable command enables hardware-based routing and forwarding.

The undo hardware route-forwarding enable command disables hardware-based routing and forwarding.

By default, hardware-based routing and forwarding is disabled.

This command is supported only on the AR5710-S8TWDSE-LTE4EA, AR8700 series, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5700-H series, AR5710-S10T1X2, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4, AR5710-S8P1XDSE-2LTE4EA and AR6700-H series.

Format

For AR5710-S10T1X2, AR5710-S8P2X, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8T2S, AR5710-S8P2XE-NRGL, AR5710-S8T2XE-NRGL, AR5710-S8T2XE, AR5710-S8T2XE-LTE4EA-T, AR5710-S8P1XDSE-2LTE4EA, AR5710-S28T2S2XE4, AR5710-S52T2XE4, AR5710-S8T1XWE, AR5710-S8T1XWE-NRGL, AR5710-S8TWDSE-LTE4EA, AR6700-H series, AR6710-L14T2X4, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR8700 series:

Usage Guidelines

Usage Scenario

For AR8700 series, AR6700-H series, AR5700-S series, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4:

This command is used to improve forwarding performance.

If the hardware-based routing and forwarding function is disabled, the device sends the received packets to the CPU for processing. After processing the packets, the CPU sends them to the specified outbound interface. To reduce the CPU load and improve the forwarding performance of the device, after the hardware-based routing and forwarding function is enabled, the device can accelerate basic forwarding by accelerating hardware and does not send packets to the CPU for processing.

After this function is enabled, only basic Ethernet Layer 3 forwarding services are supported. If other services are configured, this function does not take effect and all traffic is sent to the CPU for processing.

The hardware acceleration forwarding function becomes invalid in the following situations:

  • One of the following services is configured on interfaces: QoS, application identification, NAT, security policies, interface statistics collection, NetStream, multicast protocols, mirroring, TCP MSS, packet obtaining, URPF, and IPsec policies.
  • Services such as MPLS, BFD, SRv6, data compression, SaaS, DNS check, and QoS are globally configured.
  • An E1, MP, IP-Trunk, POS, cellular, dialer, or VDSL interface is up.
  • The protocol status of a GRE, mGRE, IPv4 over IPv6, or IPv6 over IPv4 tunnel is up, or the interface status of an SD-WAN tunnel is up.
  • The MTU configured on an interface is less than 1200.
  • Add the interface to security zones.
  • There is an FRR route.

For AR5700-H series, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T:

  1. Only basic forwarding and hardware forwarding in IPv4 NAT, ACL, and QoS scenarios are supported. Hardware forwarding is not supported in SD-WAN scenarios.

  2. After hardware route-forwarding enable is configured, the following functions are supported in hardware forwarding mode:

  • IPv4 basic forwarding, ECMP, and forcible fragmentation on Ethernet, Ethernet Layer 3 sub-interfaces, VLANIF, Eth-Trunk, Eth-Trunk sub-interfaces, cellular, Dialer (PPPoE Client IPv4), VDSL interfaces, and VDSL sub-interfaces.
  • IPv6 basic forwarding and ECMP on Ethernet, Ethernet Layer 3 sub-interfaces, Eth-Trunk, Eth-Trunk sub-interfaces, VLANIF, VDSL interfaces, and VDSL sub-interfaces
  • NAT on Ethernet interfaces, Layer 3 Ethernet sub-interfaces, Eth-Trunk interfaces, Eth-Trunk sub-interfaces, cellular interfaces, dialer interfaces (PPPoE client IPv4), VDSL interfaces, and VDSL sub-interfaces
  • VRRP on Ethernet, Ethernet Layer 3 sub-interfaces, Eth-Trunk, Eth-Trunk sub-interfaces, VDSL interfaces, and VDSL sub-interfaces
  • Traffic statistics collection on Ethernet Layer 3 sub-interfaces, VLANIF interfaces, Eth-Trunk interfaces, Eth-Trunk sub-interfaces, dialer interfaces (PPPoE client IPv4), and VDSL sub-interfaces; IPv4 traffic statistics collection on Ethernet, cellular, and VDSL interfaces
  • Local port mirroring on Ethernet interfaces, Eth-Trunk interfaces, cellular interfaces, dialer interfaces (PPPoE client IPv4), and VDSL interfaces
  • Packet capture on Ethernet interfaces, cellular interfaces, and VDSL interfaces

  1. After the hardware route-forwarding qos enable command is configured, hardware acceleration is supported for some QoS services, and QoS functions that do not support hardware acceleration cannot be configured.

  2. In hardware acceleration forwarding mode, if TCP-MSS is configured, the system does not switch to software forwarding. All TCP SYN and SYN ACK packets are forwarded by the CPU and TCP-MSS services are performed.

  3. If a service that does not support hardware forwarding is configured, hardware acceleration will not take effect on the service and all traffic of that service is sent to the CPU for processing.

  • Services such as application identification, security policies, NetStream, multicast protocols, URPF, and IPsec policies are configured on interfaces.
  • Services such as MPLS, BFD, SRv6, data compression, SaaS, and DNS check are globally configured.
  • An E1, MP, IP-Trunk, POS interface, or L2TP dialer is up.
  • The protocol status of a GRE, mGRE, IPv4 over IPv6, or IPv6 over IPv4 tunnel is up, or the interface status of an SD-WAN tunnel is up.
  • The MTU configured on an interface is less than 1200.
  • Add the interface to security zones.
  • There is an FRR route.

Precautions

For AR8700 series, AR6700-H series, AR5700-S series, AR6710-L26T2X4, AR6710-L26T2X4-T, AR6710-L50T2X4, AR6710-L50T2X4-T, AR6710-L14T2X4:

The interval between two configuration commands or between a configuration command and an undo command is 30 seconds.

For AR5700-H series, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T:

  1. After hardware-based QoS acceleration is enabled, hardware-based acceleration is supported for some QoS services. QoS services that do not support hardware-based acceleration cannot be configured.
  2. After hardware-based QoS acceleration is enabled, hardware queues, ACLs, and WRED profiles are used. The number of these resources is less than that of software resources. The configuration that require excess hardware resources does not take effect. In addition, software-based forwarding is performed for services that do not support hardware-based routing. HQoS, traffic shaping, congestion avoidance, and congestion management still use hardware resources.
  3. After hardware-based QoS acceleration is enabled, the precision of hardware-based traffic management is 3%.
  4. After hardware-based QoS acceleration is enabled, if an MQC policy based on Layer 4 information (such as the port number and TCP flag) is configured and packets are fragmented on the network, the MQC policy does not take effect. This is because packet fragments other than the first fragment do not carry port information. To apply an MQC policy to all packet fragments, you are advised to configure an IP address-based MQC policy.
  5. When the hardware QoS acceleration function is enabled or disabled, a small number of packets are lost. If queue statistics collection is enabled, the queue statistics will be affected.
  6. If hardware forwarding is configured and then software forwarding is used, the forwarding performance deteriorates. If services that do not support hardware forwarding need to be used, you are advised to disable hardware forwarding.
  7. In hardware forwarding mode, sub-interface mirroring is not supported. If sub-interface mirroring is configured, software forwarding is not used.
  8. In hardware forwarding mode, statistics about multicast and broadcast packets on VLANIF interfaces and Layer 3 sub-interfaces are not supported.
  9. The interval between two configuration commands or between a configuration command and an undo command is 30 seconds.
  10. After hardware-based QoS acceleration is enabled, the following QoS service commands are supported:

Example

# Enable the hardware-based routing and forwarding function.
<HUAWEI> system-view
[HUAWEI] hardware route-forwarding enable
Warning: If the system has a configuration that does not support hardware-based forwarding, traffic will be forwarded through software. [Y/N]:
# Enable hardware-based routing and forwarding and QoS hardware acceleration.
<HUAWEI> system-view
[HUAWEI] hardware route-forwarding qos enable
Warning: Hardware QoS resources (ACL and queue) are less than software resources. If the system has a configuration that does not support hardware-based forwarding, traffic will be forwarded through software, but hardware traffic management is still used. [Y/N]:
