traffic tm-post-processing enable

Function

The traffic tm-post-processing enable command enables the loopback function for shaped traffic.

The undo traffic tm-post-processing enable command disables the loopback function for shaped traffic.

By default, shaped traffic is not looped back.

Format

traffic tm-post-processing enable

undo traffic tm-post-processing enable

Parameters

None

Views

10GE interface view, 25GE interface view, 40GE interface view, Cellular interface view, Eth-Trunk interface view, GE interface view, Multi-GE interface view, Interface group view, Ethernet interface view, Ethernet sub-interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

After traffic shaping is configured on an interface, statistics on some service traffic cannot be collected due to the processing mechanism of the device. As a result, traffic statistics are inaccurate. In scenarios where service faults need to be determined based on traffic statistics, you are advised to configure the loopback function so that the shaped traffic is looped back and then sent out from the physical interface after statistics are collected. This facilitates troubleshooting.

Prerequisites

The qos queue-scheduling enable command has been configured to enable the queue capability, if the traffic tm-post-processing enable command needs to be configured on an Eth-Trunk interface.

Precautions

The traffic tm-post-processing command can be configured only in the Layer 3 interface view.

Example

# Configure the loopback function for shaped traffic.
<HUAWEI> system-view
[HUAWEI] interface 10GE 0/0/1
[HUAWEI-10GE0/0/1] traffic tm-post-processing enable
