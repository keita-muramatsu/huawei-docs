security enhanced-open

Function

The security enhanced-open command configures a security policy of Opportunistic Wireless Encryption (OWE) or OWE transition.

By default, no security policy is configured. To restore the default security policy, run the undo security command.

Format

security enhanced-open aes [ transition-ssid ssid ]

Parameters

Parameter Description Value
transition-ssid ssid

Specifies an SSID to use open authentication in OWE transition mode.

· If the parameter transition-ssid ssid is not specified, OWE authentication is used.

· If the parameter transition-ssid ssid is specified, the OWE transition mode is used.

The value is a string of 1 to 32 case-sensitive characters. It supports Chinese characters and Chinese + English characters, without tab characters.

To start an SSID with a space, you need to encompass the SSID with double quotation marks ("), for example, " hello". The double quotation marks occupy two characters. To start an SSID with a double quotation mark, you need to add a backslash (\) before the double quotation mark, for example, \"hello. The backslash occupies one character.

You can only use a command editor of the UTF-8 encoding format to edit Chinese characters.

SSIDs containing Chinese characters cannot be properly displayed on STAs that do not support the UTF-8 encoding format.
aes

Configures AES encryption.

-

Views

Security profile view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

OWE authentication is an enhanced open network authentication. Users can access a network without entering a password. The device uses the AES encryption algorithm to encrypt data on the network, protecting data exchange between user devices and the Wi-Fi network. Some STAs do not support OWE authentication. To be compatible with such STAs, OWE also supports the transition mode. That is, STAs that do not support OWE authentication access the network in OPEN mode, and STAs that support OWE authentication access the network in OWE mode.

Precautions

If OWE authentication or the OWE transition mode is used, the PMF function must be enabled and in mandatory mode. That is, the configuration of the pmf { optional | mandatory } command does not take effect in OWE authentication or OWE transition mode authentication.

  • OWE authentication depends on the PMF function, but 802.11n APs do not support PMF. Therefore, 802.11n APs do not support OWE authentication.
  • OWE and 802.11r cannot be used at the same time.
  • OWE authentication is not supported in WDS or Mesh scenarios.
  • If a security profile has been bound to another profile, running this command may interrupt services.
  • Some STAs may fail to access the network in OWE authentication or the OWE transition mode due to compatibility issues.
  • Some OWE-capable STAs may still access the network in open mode in OWE transition mode due to compatibility issues.

Example

# Configure the OWE transition mode and set the SSID for open system authentication to wlan-net.
<HUAWEI> system-view
[HUAWEI] wlan
[HUAWEI-wlan] security-profile name p1
[HUAWEI-wlan-sec-prof-p1] security enhanced-open aes transition-ssid wlan-net
