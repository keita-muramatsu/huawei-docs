ppp mru-negotiate

Function

The ppp mru-negotiate command enables maximum receive unit (MRU) negotiation at the PPP link control layer.

The undo ppp mru-negotiate command restores the default negotiation mode.

By default, PPP IPv4 MRU negotiation is performed at the link control layer.

Format

ppp mru-negotiate ipv4

undo ppp mru-negotiate

Parameters

Parameter Description Value
ipv4

Enables the IPv4 MRU negotiation at the PPP link control layer.

-

Views

Dialer interface view, POS interface view, Serial interface view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

The MRU indicates the capability of an interface on receiving packets. By default, the IPv4 MRU negotiation is performed at the link control layer. When the negotiation ends, the MTU of the link adopts the smaller one of the MTUs (the negotiated MRUs) of the two interfaces, and the MRUs of the two interfaces do not change. Therefore, the MTU of an interface cannot be greater than the MRU of the interface, which ensures that both ends are capable of receiving packets from each other.

After a PPP link is set up in the Establish phase, it performs LCP negotiation. If MRU negotiation is enabled, the MRU of the PPP link is negotiated during LCP negotiation.

Prerequisites

PPP is configured as the link layer protocol of the interface.

Configuration Impact

Changing the configuration triggers PPP renegotiation.

Precautions

After the configuration is complete, run the shutdown and undo shutdown commands in the interface view to restart the interface for the configuration to take effect.

Example

# Enable Dialer95 to perform IPv4 MRU negotiation at the link control layer.
<HUAWEI> system-view
[HUAWEI] interface Dialer 95
[HUAWEI-Dialer95] ppp mru-negotiate ipv4
