srv6-te-policy bfd initial-up-delay backup-path

Function

The srv6-te-policy bfd initial-up-delay backup-path command configures a delay after which BFD for the backup path of an SRv6 TE Policy goes up for the first time.

The undo srv6-te-policy bfd initial-up-delay backup-path command disables the function of configuring a delay after which BFD for the backup path of an SRv6 TE Policy goes up for the first time.

By default, the function of configuring a delay after which BFD for the backup path of an SRv6 TE Policy goes up for the first time is disabled.

Format

srv6-te-policy bfd initial-up-delay delay-interval backup-path

undo srv6-te-policy bfd initial-up-delay delay-interval backup-path

Parameters

Parameter Description Value
delay-interval

Specifies a delay after which BFD for the backup path of an SRv6 TE Policy goes up for the first time.

The value is an integer ranging from 1 to 600000, in milliseconds.

Views

Segment routing IPv6 view

Default Level

2: Configuration level

Usage Guidelines

  • Fault scenario:

    Assume that an SRv6 TE Policy contains primary path 1 and backup path 2. If a fault occurs, traffic is switched to backup path 2. In this case, the controller recomputes paths and delivers new primary path 3 and backup path 4. When the BFD Up notification of backup path 4 is received, traffic is switched to backup path 4. Then, when the BFD Up notification of primary path 3 is received, traffic is switched to primary path 3.

    In this scenario, there are three reachable paths, which are classified as optimal, second optimal, or third optimal based on SLA compliance. In normal cases, the policy preferentially selects the optimal and second optimal paths as the primary and backup paths. If the optimal path fails, the controller recomputes paths and updates the primary and backup paths to the second optimal and third optimal paths, respectively. When BFD is enabled, traffic steering is performed immediately after BFD goes up. Due to the time when the BFD Up notification is received, the BFD Up notification of the third optimal path may be first received, causing traffic to be steered to the third optimal path. The new backup path may be the third optimal path, which probably have low bandwidth. This may cause traffic congestion.
  • To solve the preceding problem, run this command to delay the response when the BFD status of the backup path changes from Unknown to Up.

Example

# Set the delay after which BFD for the backup path of an SRv6 TE Policy goes up for the first time to 100 ms.
<HUAWEI> system-view
[HUAWEI] segment-routing ipv6
[HUAWEI-segment-routing-ipv6] srv6-te-policy bfd initial-up-delay 100 backup-path
