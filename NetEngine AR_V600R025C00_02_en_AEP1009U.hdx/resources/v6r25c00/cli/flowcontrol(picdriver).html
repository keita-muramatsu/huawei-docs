flow-control(interface view)

Function

The flow-control command enables flow control on an Ethernet interface.

The undo flow-control command disables flow control on an Ethernet interface.

By default, flow control is disabled on an Ethernet interface.

Format

flow-control

flow-control input

flow-control output

undo flow-control

Parameters

Parameter Description Value
input

Enables flow control in the inbound direction of an Ethernet interface.

-
output

Enables flow control in the outbound direction of an Ethernet interface.

-

Views

Layer 2 10GE interface view, 10GE interface view, 25GE-L2 view, 25GE interface view, Layer 2 40GE interface view, 40GE interface view, GE optical interface view, GE electrical interface view, Layer 2 multi-GE interface view, Multi-GE interface view, Interface group view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Flow control prevents packet loss caused by network congestion. If network congestion occurs on the local device after flow control is configured on both ends of a link, the local device sends a message to the remote device, requesting the remote device to temporarily stop sending packets. After receiving the message, the remote device stops sending packets, regardless of its interface working rate.

You can enable flow control in both the inbound and outbound directions of an interface or enable the function in either direction based on actual requirements. If flow control is enabled in the inbound direction, the interface stops sending data packets when it receives pause frames. Conversely, if flow control is enabled in the outbound direction, the interface sends pause frames to instruct the peer end to stop sending packets. If neither direction is specified, flow control is enabled in both directions.

Precautions

  • If flow control is enabled on an interface, it must also be enabled on the remote interface.
  • Flow control is not supported for broadcast, multicast, and unknown unicast packets.
  • If the input and output parameters are not specified, flow control is enabled in both the inbound and outbound directions.
  • If the input and output parameters are specified in sequence, the later configured parameter takes effect. For example, if you run the flow-control input command to enable flow control in the inbound direction and then run the flow-control output command to enable flow control in the outbound direction, flow control in the inbound direction is disabled.
  • Ensure that no loop exists on the traffic path when enabling flow control. Otherwise, traffic may fail to be forwarded.
  • When the hwFlowControlDeadLockAlarm alarm is generated on a device, the device automatically disables flow control in the inbound direction of its interfaces. When the hwFlowControlDeadLockAlarm alarm is cleared, the device automatically restores flow control in the inbound direction of its interfaces.
  • If the duplex mode of an interface is half-duplex, flow control does not take effect.
  • When an interface is congested, the flow-control or undo flow-control command may fail to be executed. In this case, reconfigure the flow-control or undo flow-control command when the interface is not congested or after the interface is restarted.
  • On the WSIC-4GE-C-V2, WSIC-8GE-T-V2, AR6710-L26T2X4, AR6710-L14T2X4 and AR6710-L50T2X4, flow control can be configured only in the input direction. The AR8700 series does not support flow control.

Example

# Enable flow control in the inbound direction of 10GE0/0/1.
<HUAWEI> system-view
[HUAWEI] interface 10ge 0/0/1
[HUAWEI-10GE0/0/1] flow-control input
