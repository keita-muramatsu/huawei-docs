wait-to-restore-period

Function

The wait-to-restore-period command configures the SPR switchback period.

The undo wait-to-restore-period command deletes the SPR switchback period configuration.

By default, no switchback period is configured in SPR.

Format

wait-to-restore-period period-value

undo wait-to-restore-period [ period-value ]

Parameters

Parameter Description Value
period-value

Specifies the switchback period.

The value is an integer in the range from 1 to 259200, in seconds.

Views

Smart-policy-route view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

After SPR switches traffic from a high-priority link to a low-priority link, SPR will immediately switch traffic from the low-priority link back to the high-priority link when the high-priority link is recovered. If critical services are being transmitted over the low-priority link, traffic loss will occur during the switchback. You can configure a switchback period, in which the device will not switch traffic back to the high-priority link upon detection of recovery of the high-priority link. This ensures reliable transmission of critical services on the low-priority link.

After the SPR switchback period is set, the device starts a timer when it detects that SPR switches traffic to a low-priority link, the flapping suppression period expires, and the high-priority link recovers. If SPR detects that the high-priority link remains normal within the configured switchback period, SPR switches traffic back to the high-priority link after the switchback period expires. If the device detects that the high-priority link does not meet traffic forwarding requirements within the configured switchback period, the device resets the timer. When detecting that the high-priority link recovers next time, the device starts the timer again.

Prerequisites

SPR has been configured using the smart-policy-route command.

Example

# Set the SPR switchback period to 10 seconds.
<HUAWEI> system-view
[HUAWEI] smart-policy-route
[HUAWEI-smart-policy-route] wait-to-restore-period 10
