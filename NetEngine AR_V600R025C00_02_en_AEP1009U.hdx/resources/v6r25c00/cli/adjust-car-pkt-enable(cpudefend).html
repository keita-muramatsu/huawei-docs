cpu-defend dynamic-adjust packet-type enable

Function

The cpu-defend dynamic-adjust packet-type enable command enables adaptive adjustment of the default CPCAR value for protocol packets sent in wired mode.

The undo cpu-defend dynamic-adjust packet-type enable command disables adaptive adjustment of the default CPCAR value for protocol packets sent in wired mode and restores the default CPCAR value.

By default, adaptive adjustment of the default CPCAR value for protocol packets is enabled.

Format

cpu-defend dynamic-adjust packet-type packet-type enable

undo cpu-defend dynamic-adjust packet-type packet-type enable

Parameters

Parameter Description Value
packet-type packet-type

Specifies the packet type.

The value can be arp-reply, arp-request, arp-request-uc, dhcp-discovery, dhcp-reply, dhcp-request or nd.

Views

System view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

To fulfill the dynamic requirements of rate limiting on protocol packets that a fixed default CPCAR value cannot fulfill, you can use this command to enable adaptive adjustment of the default CPCAR value for protocol packets.

If adaptive adjustment of the default CPCAR value is enabled for a specific type of protocol packets, the device checks for packet loss of such protocol packets at a specified interval. When detecting a packet loss, the device dynamically adjusts the CPCAR value for the protocol packets based on the CPU usage. When the CPU usage is low, the device increases the CPCAR value, which however cannot exceed the maximum CPCAR value. When the CPU usage is high, the device reduces the CPCAR value, but the value cannot be smaller than the default one. If packet loss occurs due to congestion in the queue where the detected protocol packets reside, the device restores the default CPCAR value for the protocol packets. You can run the display cpu-defend dynamic-adjust history-record command to view the historical adaptive CPCAR adjustment records.

The following lists the types of protocol packets for which CPCAR values can be dynamically adjusted and the maximum CPCAR values after adjustment.

  • The adjusted maximum CPCAR value for ARP reply packets (arp-reply) is twice the default value.
  • The adjusted maximum CPCAR value for ARP request packets (arp-request) is twice the default value.
  • The adjusted maximum CPCAR value for unicast ARP request packets (arp-request-uc) is twice the default value.
  • The adjusted maximum CPCAR value for DHCP request packets (dhcp-discovery) is 1.5 times the default value.
  • The adjusted maximum CPCAR value for DHCP reply packets (dhcp-reply) is 1.5 times the default value.
  • The adjusted maximum CPCAR value for DHCP request packets (dhcp-request) is 1.5 times the default value.
  • The adjusted maximum CPCAR value for IPv6 ND packets (nd) is twice the default value.

Precautions

This function takes effect only when the default CPCAR values for protocol packets are not manually changed.

If a specific type of protocol packets requires dynamic adjustment of the default CPCAR value, run the cpu-defend dynamic-adjust enable command to enable adaptive adjustment of the default CPCAR value globally first.

Example

# Enable adaptive adjustment of the default CPCAR value for ARP packets.
<HUAWEI> system-view
[HUAWEI] cpu-defend dynamic-adjust packet-type arp-request enable
