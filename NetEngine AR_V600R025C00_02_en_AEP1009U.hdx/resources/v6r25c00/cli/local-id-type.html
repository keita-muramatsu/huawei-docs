local-id-type

Function

The local-id-type command sets the type of the local ID used in IKE negotiation.

The undo local-id-type command restores the default type of the local ID used in IKE negotiation.

By default, the local ID type used by IKE negotiation is an IP address.

Format

local-id-type { dn | ip [ ip-configurable ] | user-fqdn | fqdn | esn }

undo local-id-type

Parameters

Parameter Description Value
dn

Specifies the Distinguished Name (DN) as the local ID.

-
ip

Specifies the IP address as the local ID.

-
ip-configurable

Indicates that the IP address can be configured using the local-id command.

If this parameter is not specified, the IP address is the local address used for IKE negotiation by default.

-
user-fqdn

Specifies the user domain name of the local end as the local ID.

-
fqdn

Specifies the name as the local ID.

-
esn

Specifies the ESN as the local ID.

-

Views

IKE peer view

Default Level

2: Configuration level

Usage Guidelines

Usage Scenario

Identity authentication is a self-protection mechanism of IKE negotiation. It ensures security by confirming the identities of communicating parties. IKE peers can use different types of identities. This command is used to configure the local identity type of an IKE peer, also called the local ID type.

When pre-shared key authentication is used for negotiation and the local ID type is set to IP, the device uses the IP address of the interface used to establish an IPsec tunnel as the local ID by default. If the interface used to establish an IPsec tunnel has multiple IP addresses (for example, primary and secondary IP addresses), the device uses the IP address configured using the tunnel local command as the local ID.

Precautions

  • The local ID type can be different from the peer ID type. You can run the command to specify the local ID type and peer ID type.
  • For IKEv1, the pre-shared key authentication method requires that the local ID configured on the local end be the same as the peer ID configured on the peer end.
  • For IKEv2, the pre-shared key authentication method requires that the local ID type/local ID configured on the local end be the same as the peer ID type/peer ID configured on the peer end.
  • In pre-shared key authentication mode, if both the local ID type and the peer ID type are IP, the local ID configured on the local end does not need to be the same as the peer ID configured on the peer end.
  • RSA signature authentication requires that the peer ID type/peer ID configured on the local end be consistent with the corresponding fields in the local certificate of the peer end.

Example

# Set the local ID type of IKE peer peer1 to FQDN. 
<HUAWEI> system-view
[HUAWEI] ike peer peer1
[HUAWEI-ike-peer-peer1] local-id-type fqdn
