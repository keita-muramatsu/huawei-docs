slow-peer single-group number(BGP-LS address family view)

Function

The slow-peer single-group number command sets the maximum number of slow peers that can be automatically switched to single-peer update peer-groups.

The undo slow-peer single-group number command restores the default maximum number of slow BGP peers that can be automatically switched to single-peer update peer-groups.

By default, a maximum of five slow BGP peers can be automatically switched to single-peer update peer-groups.

Format

slow-peer single-group number number-value

undo slow-peer single-group number number-value

Parameters

Parameter Description Value
number-value

Specifies the maximum number of slow peers that can be automatically switched to single-peer update peer-groups.

Specifies the maximum number of slow peers that can be automatically switched to single-peer update peer-groups.

Views

BGP-LS address family view

Default Level

2: Configuration level

Usage Guidelines

A slow update peer-group may contain multiple slow peers. If a network problem (congestion for example) occurs and slows down the speed at which the local device advertises routes to a slow peer, the speed at which the local device advertises routes to other peers in the slow update peer-group is also affected. To prevent this problem, you can enable hierarchical slow-peer switching, which allows the slowest peer in a slow update peer-group to be automatically switched to a new slow update peer-group. This new slow update peer-group consists of only this peer.

After hierarchical slow-peer switching is enabled, the local device calculates the time taken to send messages to each slow peer in the slow update peer-group. If the time taken to send messages to a peer is greater than or equal to the absolute time threshold for detecting slower peers to implement hierarchical slow-peer switching, the local device considers this peer as a slower peer. If all the other peers in the slow update peer-group have received messages from the device at this time, the device switches the preceding slower peer from the current update peer-group to a single-peer update peer-group, which prevents this slower peer from affecting route advertisement to other peers in the current update peer-group.

A single-peer update peer-group affects device memory. Therefore, you need to set the maximum number of slow peer groups that can be automatically switched to a single-peer update peer-group. When the maximum number is reached, no more slow peers can be automatically switched to single-peer update peer-groups. The SLOW_PEER_SINGLEGROUP log records the information, prompting the user to perform manual intervention.

Example

# Set the maximum number of slow peers that can be automatically switched to single-peer update peer-groups to 8.
<HUAWEI> system-view
[HUAWEI] bgp 100
[HUAWEI-bgp] link-state-family unicast
[HUAWEI-bgp-af-ls] slow-peer single-group number 8
