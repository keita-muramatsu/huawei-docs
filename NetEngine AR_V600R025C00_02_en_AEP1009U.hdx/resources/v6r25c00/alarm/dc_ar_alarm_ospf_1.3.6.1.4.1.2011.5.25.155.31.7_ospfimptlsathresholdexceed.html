OSPF_1.3.6.1.4.1.2011.5.25.155.31.7 hwOspfv2ImportAseRouteThreshold

Trap Buffer Description

The number of AS-external LSAs generated when an OSPF process imports external routes exceeds the configured alarm upper threshold. (hwOspfv2ProcessIdIndex=[hwOspfv2ProcessIdIndex], hwOspfv2Threshold=[hwOspfv2Threshold])

The number of ASE LSAs generated when an OSPF process imported external routes exceeded the upper alarm threshold (in percentage) multiplied by the maximum number allowed.

Impact on the System

The network stability may be adversely affected.

Possible Causes

The number of ASE LSAs generated when an OSPF process imported external routes exceeded the upper alarm threshold (in percentage) multiplied by the maximum number allowed.

Procedure

1. Run the display ospf brief command to check whether the number of ASE LSAs generated when OSPF imports routes exceeds the upper alarm threshold. The Current status field in the display ospf brief command output shows the overload status. Normal indicates that the number is less than the lower alarm threshold. Approach limit indicates that the number reaches 90% of the upper alarm threshold. Exceed limit indicates that the number reaches or exceeds the maximum number.

  • If the threshold is exceeded, this message is informational only, and no action is required.
  • If the threshold is not exceeded yet, go to Step 2.

2. Perform the following operations as required:

  • If a change in the maximum number of ASE LSAs generated when OSPF imports routes is allowed, run the import-route limit <limit-number> [ threshold-alarm upper-limit <upper-limit-value> lower-limit <lower-limit-value> ] command to change the maximum number.
  • If a change in the maximum number of ASE LSAs generated when OSPF imports routes is not allowed, go to Step 3.

3. Contact technical support personnel.

4. End.
