SYSTEM_1.3.6.1.4.1.2011.5.25.19.2.11 hwPatchInstallFail

Trap Buffer Description

Patch operation failed. (SlotIndex=[SlotIndex], PatchIndex=[PatchIndex], PackageName=[PackageName], PackageVersion=[PackageVersion], FailReason=[FailReason], PhysicalName=[PhysicalName])

The patch package fails to be installed.

Impact on the System

Services will not be affected.

Possible Causes

  • Cause 1: Failed to read the configuration information of the patch package.
  • Cause 2: The cause value was not used.
  • Cause 3: The memory space of the memory was not enough.
  • Cause 4: The patch conflicted with the previous one.
  • Cause 5: The patch package version was incorrect.
  • Cause 8: Failed to synchronize the patch package file because of insufficient disk space.
  • Cause 9: The patch configuration is inconsistent.
  • Cause 10: The source file in the patch is abnormal.

Procedure

  • Cause 1: Failed to read the configuration information of the patch package.

    1. Reinstall the patch package. After the installation is complete, run the display patch-information command to check the status of the patch package.

    • If the patch package is in the run state, the patch package is successfully installed. The fault is rectified.
    • If the patch package is not in the run state, go to Step 2.

    2. Collect logs and contact technical support personnel.

  • Cause 2: The cause value was not used.

    Collect logs and contact technical support personnel.

  • Cause 3: The memory space of the memory was not enough.

    1. Run the dir command to check whether the remaining space is sufficient.

    • If yes, go to step 3.
    • If no, go to step 2.

    2. Clear the space and reinstall the patch package. After the patch package is installed, run the display patch-information command to check whether the patch package is in the run state. If the patch package is in the run state, the patch package is successfully installed.

    • If yes, go to step 4.
    • If no, go to step 3.

    3. Collect logs and contact technical support.

    4. End.

  • Cause 4: The patch conflicted with the previous one.

    1. Uninstall the current patch and reinstall the patch package. After the patch package is installed, run the display patch-information command to check whether the patch package is in the run state. If the patch package is in the run state, the patch package is successfully installed.

    • If yes, go to step 4.
    • If no, go to step 2.

    2. Restart the device and install the patch package. After the patch package is installed, run the display patch-information command to check whether the patch package is in the run state. If the patch package is in the run state, the patch package is successfully installed.

    • If yes, go to step 4.
    • If no, go to step 3.

    3. Collect logs and contact technical support.

    4. End.

  • Cause 5: The patch package version was incorrect.

    1. Run the display startup command to query the version of the system software package.

    2. Replace the patch with a patch that matches the system software package version. Then check whether the alarm is cleared.

    • If yes, go to step 4.
    • If no, go to step 3.

    3. Collect alarm and log information, and contact technical support personnel.

    4. End.

  • Cause 8: Failed to synchronize the patch package file because of insufficient disk space.

    1. Run the dir command to check the free disk space of the board in the slot indicated in the alarm information.

    If the remaining space is less than the size of the patch file to be loaded, run the delete /unreserved command to delete unnecessary files and clear the environment to ensure sufficient space. Then, go to step 2.

    If the remaining disk space is greater than the size of the patch file to be loaded, go to step 3.

    2. Load the patch again and restart the board in the corresponding slot.

    3. Collect alarm and log information, and contact technical support personnel.

    4. End.

  • Cause 9: The patch configuration is inconsistent.

    There are three ways to clear the alarm:

    1. After the trap is reported, the active/standby switchover is performed twice. Half an hour after the board is registered, the trap is cleared through the aging mechanism. If the trap cannot be cleared, go to step 4.

    2. After the alarm is reported, restart a single board. After the board is registered for half an hour, the alarm on the corresponding board is cleared through the aging mechanism. If the alarm persists, go to step 4.

    3. After the alarm is reported, restart the device. If the alarm is cleared, go to step 4.

    4. Collect logs and contact technical support.

  • Cause 10: The source file in the patch is abnormal.

    Collect trap, log, and configuration information, and contact technical support personnel.
