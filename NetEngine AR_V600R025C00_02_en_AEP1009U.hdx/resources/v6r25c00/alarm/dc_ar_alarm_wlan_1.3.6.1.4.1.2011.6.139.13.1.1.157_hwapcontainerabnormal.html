Impact on the System

  • Cause 1: The first startup of an application failed.

    The container and applications in the container cannot run properly.

  • Cause 2: The alarm is generated when an application is reset due to a fault during running.

    Basic services are affected.

Possible Causes

  • Cause 1: The first startup of an application failed.
  • Cause 2: The alarm is generated when an application is reset due to a fault during running.

Procedure

  • Cause 1: The first startup of an application failed.

    1. Wait for 30s and check whether the alarm is cleared.

    If so, no further action is required.

    If not, go to Step 2.

    2. Check whether the startup configuration of the application instance is correct. If not, run the uninstall container application-software and install container application-software commands to restart the application instance and then check whether the alarm is cleared.

    If so, no further action is required.

    If not, go to Step 3.

    3. Check whether the resources (memory, CPU, and storage) of the current host machine meet the requirements for starting the application instance. If not, stop or delete the application instance.

    If so, no further action is required.

    If not, go to Step 4.

    4. Collect trap and log information, and contact technical support.

  • Cause 2: The alarm is generated when an application is reset due to a fault during running.

    1. Wait for 90s and check whether the alarm is cleared.

    If so, no further action is required.

    If not, go to Step 2.

    2. Collect trap and log information, and contact technical support.
