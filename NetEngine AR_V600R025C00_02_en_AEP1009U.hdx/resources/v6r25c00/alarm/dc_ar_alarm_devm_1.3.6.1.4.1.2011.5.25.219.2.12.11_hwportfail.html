Possible Causes

  • Cause 1: Port received package with preamble code error.
  • Cause 2: Port cannot go up due to lack of serdes mode.
  • Cause 3: Remote alarm indication on E1 port.
  • Cause 4: An alarm indication of the upstream E1 signals.
  • Cause 5: Loss of frame alignment alarm on E1 port.
  • Cause 6: Loss of Multiframe Alignment on E1 port.
  • Cause 7: Phy instability.
  • Cause 8: The PHY chip is abnormal.

Procedure

  • Cause 1: Port received package with preamble code error.

    Run the port serdes-mode command to configure the Serdes mode of a MultiGE port.

  • Cause 2: Port cannot go up due to lack of serdes mode.

    1. Check whether the device connected to the port where the alarm is generated can be migrated to another port.

    • If yes, go to Step 2.
    • If no, go to Step 3.

    2. Migrate the device connected to the port where the alarm is generated to another port and check whether the alarm persists.

    • If yes, go to Step 1.
    • If no, no further action is required.

    3. Run the port serdes-mode command to configure the Serdes mode of the MultiGE port to ensure that the SerDes mode of the port in the alarm is available.

  • Cause 3: Remote alarm indication on E1 port.

    1. Check whether an alarm exists on the peer E1 port. If so, clear the alarm and check whether the alarm on the local end is cleared.

    • If yes, no further action is required.
    • If no, go to step 2.

    2. Check whether the physical link is interrupted. Rectify the link fault and check whether an alarm is generated.

    • If yes, no further action is required.
    • If no, contact technical support.
  • Cause 4: An alarm indication of the upstream E1 signals.

    1. Check whether the LOS alarm is generated on the peer E1. If so, clear the alarm and check whether an alarm exists on the local end.

    • If yes, go to Step 2.
    • If no, no further action is required.

    2. Check whether the unframed and idle-code configurations exist on the peer port. If yes, restore the configurations and check whether the alarm is cleared.

    • If yes, contact technical support.
    • If no, no further action is required.
  • Cause 5: Loss of frame alignment alarm on E1 port.

    1. Run the display controller command to check whether the frame format of the peer end (Physical layer) is the same as that of the local end.

    • If yes, contact technical support.
    • If no, run the using e1 command to make the service configurations consistent.
  • Cause 6: Loss of Multiframe Alignment on E1 port.

    1. Run the display controller command to check whether the frame format of the peer end (Physical layer) is the same as that of the local end.

    • If yes, contact technical support.
    • If no, run the frame-format { crc4 | no-crc4 } command to make the service configurations consistent.
  • Cause 7: Phy instability.

    1. Run the display device command to check whether the faulty board has registered. If the board has registered and services are running properly, go to Step 3.

    2. Run the power off slot command to power off the board, and then run the power on slot command to power on the board. If the fault persists, go to Step 3.

    3. Collect alarm, log, and configuration information, and contact technical support personnel.

  • Cause 8: The PHY chip is abnormal.

    1. Collect alarm, log, and configuration information, and contact technical support personnel.
