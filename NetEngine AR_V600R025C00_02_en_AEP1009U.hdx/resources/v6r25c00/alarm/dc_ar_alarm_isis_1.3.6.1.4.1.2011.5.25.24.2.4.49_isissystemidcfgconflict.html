ISIS_1.3.6.1.4.1.2011.5.25.24.2.4.49 hwIsisSystemIdCfgConflict

Trap Buffer Description

An IS-IS system ID conflict occurred. The system ID may have been automatically restored, but the conflicting configuration may still exist. To restore the configured system ID, manually delete the network-entity of the local device and reconfigure it. (SysInstance=[hwisisSysInstance], Level=[hwisisSysLevelIndex], ConflictSystemID=[hwIsisConflictSystemID], LocalHostName=[hwIsisHostName], RemoteHostName=[hwIsisAdjSysName])

This alarm is generated when an IS-IS system ID conflict occurs.

Impact on the System

If the system ID conflict self-healing function is disabled, route flapping may occur.

If the system ID conflict self-healing function is enabled, the system ID is automatically restored, and services are not affected. However, the conflict configuration may still exist.

Possible Causes

The same IS-IS system ID is configured on multiple non-directly connected devices in the network.

Procedure

1. Run the undo network-entity command to delete the IS-IS system ID of the local device.

2. Re-plan the IS-IS system ID of the local device to ensure that it is unique on the network.

3. Run the network-entity command to configure a new IS-IS system ID.

4. Run the display isis system-id conflict command to check whether an IS-IS system ID conflict exists.

  • If the conflict persists, go to Step 1 or collect log and configuration information and contact technical support personnel.
  • If the conflict no longer exists, the alarm is cleared, and no further action is required.
