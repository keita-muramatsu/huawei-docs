OSPF_1.3.6.1.2.1.14.16.2.5 ospfVirtIfConfigError

Parameter Description

VirtIfAreaId

Indicates the ID of a transit area.

VirtIfNeighbor

Indicates the IP address of a neighbor.

ProcessId

Indicates the ID of an OSPF process.

RouterId

Indicates the ID of a router.

ConfigErrorType

Error type:

  • 1: OSPF_TRAP_CFGERR_BAD_VER: The OSPF version number is incorrect, that is, it is not 2.
  • 2: OSPF_TRAP_CFGERR_AREA_MISMATCH: The area ID in the received packet does not match the local area ID. (The Vlink can receive packets from area 0. In other cases, if the area IDs are different, it is considered an error.)
  • 3: OSPF_TRAP_CFGERR_UNKNOWN_NBMA_NBR: The NBMA neighbor cannot be identified.
  • 4: OSPF_TRAP_CFGERR_UNKNOWN_VIRT_NBR: The virtual neighbor cannot be identified.
  • 5: OSPF_TRAP_CFGERR_AUTH_TYPE_MISMATCH: The packet authentication type is incorrect.
  • 6: OSPF_TRAP_CFGERR_AUTH_FAILURE: The authentication fails.
  • 7: OSPF_TRAP_CFGERR_NETMASK_MISMATCH: The address mask does not match the local one.
  • 8: OSPF_TRAP_CFGERR_HELLO_INTVL_MISMATCH: The intervals for sending Hello packets are different.
  • 9: OSPF_TRAP_CFGERR_DEAD_INTVL_MISMATCH: The neighbor dead timer values are different.
  • 10: OSPF_TRAP_CFGERR_OPT_MISMATCH: An option field mismatch exists.
  • 11: OSPF_TRAP_CFGERR_MTU_MISMATCH: MTU check is enabled on the OSPF interface, and the MTU of the received DD packet is greater than that of the inbound interface.
  • 12: OSPF_TRAP_CFGERR_DUPLICATEROUTERID: A router ID conflict occurs.
  • 13: OSPF_TRAP_CFGERR_NOERROR: No error is reported.

PacketType

Packet type:

  • 1: Hello packet
  • 2: Database Description: DD packet
  • 3: Link State Request: LSR packet
  • 4: Link State Update: LSU packet
  • 5: Link State Ack: link state acknowledgment packet.

InstanceName

Indicates the VPN name.

Impact on the System

This trap message is generated after the virtual interface receives a packet indicating parameters are incorrectly configured.

Possible Causes

The virtual interface is incorrectly configured.

Procedure

1. Run the display ospf vlink and display current-configuration configuration commands to check whether the configurations of the interfaces at both ends are consistent.

  • If the configurations are consistent, go to Step 3.
  • If the configurations are inconsistent, go to Step 2.

2. Perform either of the following operations based on the networking condition:

  • If the configurations at both ends can be modified to be consistent, modify the configurations to ensure consistency according to the configuration guide. Check whether the alarm is cleared. If the alarm is cleared, go to Step 4. If the alarm persists, go to Step 3.
  • If the configurations on both ends cannot be changed to be consistent, go to Step 3.

3. Collect alarm, log, and configuration information about the device, and contact technical support engineers.

4. End.
