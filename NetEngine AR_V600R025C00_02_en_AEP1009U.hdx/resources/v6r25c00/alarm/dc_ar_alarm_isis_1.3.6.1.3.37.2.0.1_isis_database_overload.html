Impact on the System

1.

If the trap is generated because the IS-IS LSDB entered or exited the overload state, route selection on the IS-IS neighbor will be affected.

2.

If the trap is generated because the memory usage exceeds the upper threshold, the IS-IS LSDB is unreliable.

Possible Causes

Cause 1: The set-overload or undo set-overload command was run in the IS-IS view.

Cause 2: The IS-IS process entered the Overload state and then exited from it.

Cause 3: Failed to apply for memory in the case of memory shortage, causing a system crash.

Procedure

1. Run the display this command in the IS-IS view to check whether the set-overload or undo set-overload command is run in the IS-IS process.

  • If yes, the message is informational only, and no action is required.
  • If no, go to Step 2.

2. Run the display memory command to view the memory usage of the device and check whether the memory usage reaches the threshold.

  • If yes, obtain user logs and go to Step 3.
  • If no, go to Step 3.

3. Collect log and configuration information, and contact technical support personnel.

4. End.
