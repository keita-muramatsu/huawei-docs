LDP_1.3.6.1.4.1.2011.5.25.182.1.54.2 hwmplsldpvirtualtunneldown

Trap Buffer Description

The LDP virtual tunnel went Down. (LdpVirtualTunnelFEC=[LdpVirtualTunnelFEC])

This alarm is generated when the LDP virtual tunnel goes Down.

Impact on the System

If VPN services are iterated to only LDP tunnels, services may be compromised.

Possible Causes

All the Ingress LSPs which are belongs to a LDP tunnel were deleted.

Procedure

1. Run the display ip routing-table <destination-ip-address> command to check whether the route exists. The value of destination-ip-address must be the same as that of LdpVirtualTunnelFEC in the alarm.

  • If routing information is displayed, check whether Interface and NextHop in the command output are the expected outbound interface and next hop. If yes, go to Step 2. Otherwise, go to Step 3.
  • If no route information is displayed, go to Step 3.

2. Run the display mpls ldp peer command to check whether the value of DiscoverySource in the command output is the same as the value of Interface in the routing information. If yes, go to Step 4. Otherwise, go to Step 5.

If the command output does not contain DiscoverySource that is the same as Interface, go to Step 6.

3. Check whether the IGP route configuration is correct. If OSPF is used as the IGP, run the display current-configuration configuration ospf command in the OSPF view to check whether OSPF is used to advertise the routes to the loopback interface and the corresponding interface addresses. If IS-IS is used, run the display this command on the loopback interface and the corresponding interface to check whether IS-IS is enabled.

  • If so, go to Step 12.
  • If not, go to Step 5.

4. Run the display mpls ldp session <PeerID> command with Peer ID set to the peer ID obtained in Step 2.

  • If the status of the peer is Operational, run the display mpls lsp include <destination-ip-address> <mask> command to check whether the LDP LSP is established. If the LDP LSP is not established, go to Step 12.
  • If the status of the peer is not Operational, go to Step 12.

5. Restore the routing protocol configuration and check whether the configuration is correct. If the route is correct, go to Step 4. If the route is incorrect, go to Step 12.

6. Run the display mpls ldp interface command on both ends to check whether the interface status is normal and check the Status field.

If the corresponding interface exists but is not in the Active state, go to Step 9.

If the corresponding interface does not exist, go to Step 7.

7. Run the display this command on the interface to check whether LDP is enabled.

  • If so, go to Step 12.
  • If not, go to Step 8.

8. Enable MPLS LDP on the interface. Go to Step 9.

9. Run the display this command on the interface to check whether the interface is shut down.

  • If so, go to Step 10.
  • If not, go to Step 12.

10. Run the undo shutdown command on the interface. Go to Step 11.

11. Check whether the session is Up.

  • If so, check whether the LDP LSP is successfully established. If the LDP LSP is not successfully established, go to Step 12.
  • If not, go to Step 12.

12. Collect alarm and configuration information, and contact technical support personnel.
