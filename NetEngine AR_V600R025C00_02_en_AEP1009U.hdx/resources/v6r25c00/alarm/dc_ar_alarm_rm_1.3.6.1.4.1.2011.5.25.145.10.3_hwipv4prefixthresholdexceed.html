Impact on the System

The number of IPv4 route prefixes exceeded the alarm threshold, and services may be affected if the number of IPv4 route prefixes keeps increasing.

Possible Causes

The number of IPv4 prefixes exceeded the threshold of the routing table.

Procedure

1. Run the display current-configuration command to check whether the ip prefix-limit system threshold-alarm command is run and the alarm threshold is too small.

  • If yes, go to Step 2.
  • If no, go to Step 3.

2. Run the ip prefix-limit system threshold-alarm upper-limit <upper-limit-value> lower-limit <lower-limit-value> command to increase the value of <upper-limit-value>.

3. Run the display ip routing-table statistics command to check the total number of IPv4 public network route prefixes and run the display ip routing-table all-vpn-instance statistics command to check the total number of VPN route prefixes. In addition, check the number of routes that each routing protocol adds to each IPv4 routing table.

Determine whether the routes are required by services or are generated due to incorrect configurations.

  • If the routes are generated due to incorrect configurations, go to Step 4.
  • If the routes are required by services, go to Step 5.

4. Adjust the configurations to delete unnecessary routes so that the number of route prefixes falls below the lower-limit <lower-limit-value> configured using the ip prefix-limit system threshold-alarm command, and then check whether the RM_1.3.6.1.4.1.2011.5.25.145.10.4 hwIpv4PrefixThresholdExceedClear alarm is generated.

  • If no, go to Step 5.
  • If yes, go to Step 6.

5. Collect alarm and configuration information, and contact technical support personnel.

6. End.
