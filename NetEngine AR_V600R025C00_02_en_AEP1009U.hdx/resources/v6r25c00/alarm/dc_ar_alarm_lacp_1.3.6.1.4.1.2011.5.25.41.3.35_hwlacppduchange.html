LACP_1.3.6.1.4.1.2011.5.25.41.3.35 hwLacpPDUChange

Trap Buffer Description

The LACP member interface's status changed from selected to unselected due to the PDU change. (TrunkIndex=[TrunkIndex], PortIfIndex=[PortIfIndex], TrunkId=[TrunkId], TrunkName=[TrunkName], PortName=[PortName], OldPduInfo=[OldPduInfo], NewPduInfo=[NewPduInfo], ReasonCode=[ReasonString])

The status of an Eth-Trunk's member interface changed from selected to unselected due to an LACPDU change.

Impact on the System

The member link cannot carry services.

Possible Causes

  • Cause 1: Partner system ID changed in the received PDU.
  • Cause 2: Partner system priority changed in the received PDU.
  • Cause 3: Partner key changed in the received PDU.
  • Cause 4: Partner port number changed in the received PDU.
  • Cause 5: Partner port priority changed in the received PDU.
  • Cause 6: Partner state's aggregation bit changed in the received PDU.
  • Cause 7: Actor system ID changed in the received PDU.
  • Cause 8: Actor system priority changed in the received PDU.
  • Cause 9: Actor key changed in the received PDU.
  • Cause 10: Actor port priority changed in the received PDU.
  • Cause 11: Actor port number changed in the received PDU.
  • Cause 12: Actor state's aggregation bit changed in the received PDU.
  • Cause 13: Actor state's synchronization bit changed in the received PDU.
  • Cause 14: Actor aggregation delay changed in the received PDU.

Procedure

  • Cause 1: Partner system ID changed in the received PDU.

    1. Run the display interface brief command to check whether the member interface is Down.

    • If yes, go to Step 2.
    • If not, go to Step 5.

    2. Run the undo shutdown command and check whether the alarm is cleared. If the alarm persists, go to Step 3.

    3. Check whether the physical link is normal (For example, check whether the network cable or optical module is loose or disconnected).

    • If yes, go to Step 5.
    • If not, go to Step 4.

    4. Repair the physical link and check whether the alarm is cleared. If the alarm persists, go to Step 5.

    5. Run the display eth-trunk [ <trunk-id> [ interface <interface-type> <interface-number> | verbose ] ] command to check whether the link aggregation group has member interfaces.

    • If yes, go to Step 7.
    • If not, go to Step 6.

    6. Run the eth-trunk <trunk-id> command in the interface view to add the current Ethernet interface to the Eth-Trunk interface as required. Then, check whether this alarm is cleared. If the alarm persists, go to Step 7.

    7. Run the display eth-trunk <trunk-id> command to check whether the lower threshold for the number of Eth-Trunk member links in the Up state is configured for the Eth-Trunk, which causes the Eth-Trunk member interfaces to fail to negotiate with each other.

    • If yes, go to Step 8.
    • If not, go to Step 9.

    8. Run the least active-linknumber <link-number> command in the Eth-Trunk interface view to correctly configure the minimum number of trunk member links in the Up state. Then, check whether the alarm is cleared. If the alarm persists, go to Step 9.

    9. Collect alarm and configuration information, and contact technical support personnel.
