OSPF_1.3.6.1.2.1.14.16.2.13 ospfMaxAgeLsa

Trap Buffer Description

An LSA is aged. (RouterId=[RouterId], LsdbAreaId=[LsdbAreaId], LsdbType=[LsdbType], LsdbLsid=[LsdbLsid], LsdbRouterId=[LsdbRouterId])

The aging time of LSAs in the LSDB of the device reached the maximum value. The possible cause was that the routes imported by OSPF were deleted or the OSPF interface went Down.

Impact on the System

The route forwarding may be affected. If the network segment where the LSA resides belongs to a service route network segment, the services will be affected.

Possible Causes

Cause 1: The status of the physical interface switched between Up and Down.

Cause 2: The status of the neighbor changed.

Cause 3: The route imported by OSPF changed.

Procedure

1. Check the LsdbRouterId of the LSA in the alarm.

  • If the LSA is generated locally, go to Step 2.
  • If the LSA is not generated locally, log in to the device that generates the LSA and go to Step 2.

2. Check the LSA type.

  • If the LSA type is Type 1 or Type 2, check whether any of the following alarms is generated: 1.3.6.1.2.1.14.16.2.1, 1.3.6.1.2.1.14.16.2.2, 1.3.6.1.2.1.14.16.2.3, and 1.3.6.1.2.1.14.16.2.16. If yes, handle the alarm according to the corresponding alarm handling procedure. If no, go to Step 4.
  • If the LSA type is Type 3, Type 5, or Type 7, go to Step 3.

3. Run the display ip routing-table <ip-address> command to check whether the route exists in the routing table or whether route flapping occurs. The value of <ip-address> is the LsdbRouterId of the LSA in the alarm.

  • If the route exists or route flapping occurs, go to Step 4.
  • If the route does not exist, go to Step 4.

4. Collect alarm, log, and configuration information about the device, and contact technical support engineers.

5. End.
