OSPF_1.3.6.1.2.1.14.16.2.10 ospfTxRetransmit

Trap Buffer Description

An OSPF packet is retransmitted on a non-virtual interface. (RouterId=[RouterId], IfIpAddress=[IfIpAddress], AddressLessIf=[AddressLessIf], NbrIfIpAddress=[NbrIfIpAddress], NbrAddressLessIf=[NbrAddressLessIf], IfNeighbor=[IfNeighbor], PacketType=[PacketType], LsdbAreaId=[LsdbAreaId], LsdbType=[LsdbType], LsdbLsid=[LsdbLsid], LsdbRouterId=[LsdbRouterId])

An OSPF packet was retransmitted on the non-virtual interface. The possible cause was that the physical link of the non-virtual interface was faulty.

Impact on the System

When a packet is retransmitted on a non-virtual interface because the network is busy, this trap message will be generated, which leads to longer route synchronization and convergence.

Possible Causes

Cause 1: The address used to forward the packet could not be pinged.

Cause 2: The peer end considered the packet to be invalid.

Procedure

1. Check the retransmission count of each retransmitted packet.

  • If the retransmission count is 1 or 2 and only a small number of packets are retransmitted, this is normal and no action is required.
  • If a large number of packets are repeatedly retransmitted, go to Step 2.

2. Find the IP address of the neighbor in the alarm information, and ping the address.

  • If the ping fails, go to Step 4.
  • If the ping succeeds, go to Step 3.

3. Check whether the alarm 1.3.6.1.2.1.14.16.2.9 is generated on the local device and its neighbor. If yes, clear the alarm according to the alarm handling procedure. If no, go to Step 4.

4. Collect alarm, log, and configuration information about the device, and contact technical support engineers.

5. End.
