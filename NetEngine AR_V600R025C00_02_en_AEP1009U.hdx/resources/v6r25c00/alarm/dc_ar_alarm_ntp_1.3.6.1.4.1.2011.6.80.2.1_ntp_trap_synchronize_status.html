NTP_1.3.6.1.4.1.2011.6.80.2.1 hwNtpStateChangeTrap

Trap Buffer Description

NTP synchronization state changed. (hwNtpState=[state], hwNtpSource=[source], hwNtpSourceVpnName=[VpnName])

The status of the local NTP clock changes.

Impact on the System

The local time may be inaccurate.

Possible Causes

The NTP status changes from synchronized to unsynchronized due to the following reasons:

Cause 1: The system clock is reset.

Cause 2: The specified peer end is deleted.

Cause 3: The specified peer end is unreachable.

Cause 4: The specified peer end fails authentication.

Cause 5: The specified peer clock is not synchronized.

Cause 6: The last update of the peer clock times out.

Cause 7: The source level is higher than the local level.

Cause 8: The system synchronization source is lost.

Cause 9: The NTP mode does not match the specified peer end.

Procedure

Cause 1: The system clock is reset.

1. Specify a new clock and check whether NTP enters the synchronization state.

  • If so, no further action is required.
  • If not, go to Step 2.

2. Collect alarm and configuration information, and contact technical support personnel.

Cause 2: The specified peer is deleted.

1. Configure a substitute clock source and check whether NTP enters the synchronization state.

  • If so, no further action is required.
  • If not, go to Step 2.

2. Collect alarm and configuration information, and contact technical support personnel.

Cause 3: The specified peer is unreachable.

1. Check the connectivity between the clock and its peer.

  • If the connectivity is normal, go to Step 3.
  • If not, go to Step 2.

2. Specify a new clock source and check whether NTP enters the synchronization state.

  • If so, no further action is required.
  • If not, go to Step 3.

3. Collect alarm and configuration information, and contact technical support personnel.

Cause 4: The specified peer fails to be authenticated.

1. Check whether NTP authentication has been configured for both the local and peer ends.

  • If so, go to Step 2.
  • If not, configure NTP authentication.

2. Check whether the NTP authentication keys configured on the local and peer ends are the same.

  • If yes, go to Step 3.
  • If not, reconfigure the NTP authentication keys.

3. Collect alarm and configuration information, and contact technical support personnel.

Cause 5: The clock of the specified peer is not synchronized.

1. Configure a substitute clock source.

  • If NTP enters the synchronization state, no further action is required.
  • If NTP does not enter the synchronization state, go to Step 2.

2. Collect alarm and configuration information, and contact technical support.

Cause 6: The interval between the current time and the last update time of the peer clock is not within the allowed time range.

1. Configure a substitute clock source.

  • If NTP enters the synchronization state, no further action is required.
  • If NTP does not enter the synchronization state, go to Step 2.

2. Collect alarm and configuration information, and contact technical support.

Cause 7: The source stratum is higher than the local stratum.

1. Run the display ntp status command to check the local NTP stratum.

  • If the local NTP stratum is lower than the peer stratum, go to Step 2.
  • If the local NTP stratum is higher than the peer stratum, go to Step 3.

2. Configure a substitute clock source, ensuring that the stratum of the substitute clock source is lower than the local stratum.

  • If NTP enters the synchronization state, no further action is required.
  • If NTP does not enter the synchronization state, go to Step 3.

3. Collect alarm and configuration information, and contact technical support personnel.

Cause 8: The system synchronization source is lost.

1. Configure a substitute clock source, ensuring that the stratum of the substitute clock source is lower than the local stratum.

  • If NTP enters the synchronization state, no further action is required.
  • If NTP does not enter the synchronization state, go to Step 2.

2. Collect alarm and configuration information, and contact technical support.

Cause 9: The NTP mode on the local end does not match that on the peer end.

1. Run the display ntp sessions command to check the NTP mode.

  • If the NTP mode on the local end matches that on the peer end, go to Step 3.
  • If the NTP mode on the local end does not match that on the peer end, go to Step 2.

2. Configure the NTP mode.

  • If NTP enters the synchronization state, no further action is required.
  • If NTP does not enter the synchronization state, go to Step 3.

3. Collect alarm and configuration information, and contact technical support personnel.

For details, see "NTP Configuration"in Configuration Guide > System Management Configuration.
