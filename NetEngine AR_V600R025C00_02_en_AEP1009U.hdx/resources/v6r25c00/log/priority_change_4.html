HRP/4/PRIORITY_CHANGE

Message

HRP/4/PRIORITY_CHANGE: The priority of the HRP changed. (change_reason=[reason], local_old_fault_indicator=[local-old-fault-indicator], local_new_fault_indicator=[local-new-fault-indicator], local_old_robustness_indicator=[local-old-robustness-indicator], local_new_robustness_indicator=[local-new-robustness-indicator])

Description

The HRP priority of the local device changed and the reason for the change.

Parameters

Parameter Name Parameter Meaning

reason

Cause of the priority change.

local-old-fault-indicator

Old HRP fault coefficient at the local end.

local-new-fault-indicator

New fault coefficient of the local HRP.

local-old-robustness-indicator

Old HRP robustness variable of the local device.

local-new-robustness-indicator

New robustness variable of the local HRP.

Possible Causes

Possible causes for a priority change are as follows:

  • The CPU is faulty.
  • The CPU fault is rectified.
  • A key process is faulty.
  • A key process fault is rectified.
  • The HRP status is manually switched to active.
  • The HRP status is manually switched to standby.
  • The status of the interface monitored by HRP changes from Up to Down.
  • The status of the interface monitored by HRP changes from Down to Up.
  • The status of the VRRP group monitored by HRP changes from Initialize to Master or Standby.
  • The status of the VRRP group monitored by HRP changes from Master or Standby to Initialize.
  • The status of the BFD session monitored by HRP changes from Up to Down.
  • The status of the BFD session monitored by HRP changes from Down to Up.
  • Other unknown causes.

Procedure

The troubleshooting method varies with the reason parameter.

  • If the reason parameter is "The xxx recovered", the system is running properly and no action is required.
  • If the reason parameter is "The xxx failed", contact technical support personnel.
  • If the reason parameter indicates that the status of the VRRP group or BFD session monitored by the device changes, run the display hrp state verbose command on the active and standby devices to check the status of the interfaces or links monitored by the devices. If any exception is found, check whether the corresponding interfaces or links are faulty. If the fault persists, contact technical support personnel.
  • If the reason parameter indicates CPU association, check whether the CPU status is correct.
