ND/4/NDNeighborUserIPv6AddressConflict

Message

ND/4/NDNeighborUserIPv6AddressConflict: Detected an IPv6 address collision. (Ipv6Address=[Ipv6Addr], Local MacAddress=[LocalMacAddr], Local InterfaceName=[LocalIfName], Local WorkInterfaceName=[LocalWorkIfName], Local VLAN=[LocalPVid], Local INNER-VLAN=[LocalCVid], Received MacAddress=[RcvMacAddr], Received InterfaceName=[RcvIfName], Received WorkInterfaceName=[RcvWorkIfName], Received VLAN=[RcvPVid], Received INNER-VLAN=[RcvCVid])

Description

An ND IPv6 address conflict was detected.

Parameters

Parameter Name Parameter Meaning

Ipv6Addr

IPv6 address

LocalMacAddr

Local MAC Address

LocalIfName

Local Interface Name

LocalWorkIfName

Name of the local working interface

LocalPVid

Local outer VLAN ID

LocalCVid

Local inner VLAN ID

RcvMacAddr

MAC address of the received packet

RcvIfName

Name of the interface that receives packets

RcvWorkIfName

Name of the working interface that receives packets

RcvPVid

Outer VLAN ID of the received packet

RcvCVid

Inner VLAN ID of the received packet

Possible Causes

A local NB entry exists on the device. When the device receives an NS/NA message other than an unsolicited multicast NA message, the source IPv6 address of the message is the same as an IPv6 address in the local dynamic NB entry, but the source MAC address is different from the MAC address in the entry.

Procedure

1. Check the devices configured with the same IPv6 address on the network. Change the IPv6 addresses of the interfaces based on the IPv6 address plan to resolve the IPv6 address conflict.

2. Check whether a loop exists on the network. If a loop exists, remove it.
