RUMNG/4/RU_LOG

Message

RUMNG/4/RU_LOG: Receive remote unit log. (ESN=[Esn], Content=[Content])

Description

Logs reported by the remote unit are received.

Parameters

Parameter Name Parameter Meaning

Esn

ESN of the remote unit.

Content

Log content.

Possible Causes

The remote unit reports logs.

Procedure

Check whether the remote unit is faulty based on the log content. If the corresponding restoration content is displayed, the remote unit has been restored. The details are as follows:

Content

The PMBus power supply is faulty.

Restoration Content

The PMBus power supply recovers from a fault.

Cause Analysis

The PMBus IIC is faulty.

Handling Procedure

Collect alarm, log, and configuration information, and contact technical support personnel.

Impact on the System

PoE power supply is unavailable.

Content

High temperature alarm of the PMBus power supply.

Restoration Content

The high temperature alarm of the PMBus power supply is cleared.

Cause Analysis

The ambient temperature is too high or the device power is too high.

Handling Procedure

Reduce the ambient temperature or reduce the device power.

Impact on the System

The PoE power supply may be abnormal.

Content

Failed to upgrade the software package. (expected package version=[SoftwareVersion])

Restoration Content

None.

Cause Analysis

If the software package is rolled back due to an upgrade failure, whether the version of the running software package is consistent with the target version is checked 2 minutes after the rollback starts. If they are inconsistent, an alarm is generated.

Handling Procedure

Upgrade the software package again on the web page.

Impact on the System

None.

Content

Temperature exceeds the alarm threshold. (Threshold=[Threshold], CurrentTemperature=[CurrentTemperature], TempType=[TempType])

Restoration Content

Temperature is lower than the alarm threshold. (Threshold=[Threshold], CurrentTemperature=[CurrentTemperature], TempType=[TempType])

Cause Analysis

1. The temperature of the board or at the air intake vent of the fan is too high.

2. The board temperature is too low.

Handling Procedure

1. Adjust the ambient temperature or the distance between the device and the air conditioner.

2. Collect alarm, log, and configuration information, and contact technical support personnel.

Impact on the System

The device may run abnormally.

Content

Temperature exceeds the reset threshold. (Threshold=[Threshold], CurrentTemperature=[CurrentTemperature], TempType=[TempType])

Restoration Content

Temperature is lower than the reset threshold. (Threshold=[Threshold], CurrentTemperature=[CurrentTemperature], TempType=[TempType])

Cause Analysis

The temperature of the board or at the air intake vent of the fan is too high.

Handling Procedure

1. Check whether the ambient temperature is too high.

  • If so, lower the ambient temperature.
  • If not, go to step 2.

2. Collect alarm, log, and configuration information, and contact technical support personnel.

Impact on the System

If the reset threshold is exceeded, the device will be reset.

Content

The board totally failed. (Reason=[Reason])

Restoration Content

None.

Cause Analysis

The device hardware fails to be verified.

Handling Procedure

Collect alarm, log, and configuration information, and contact technical support personnel.

Impact on the System

The board fails, and services are interrupted. A key component of the board may have been replaced or tampered with, which affects system reliability and security.

Content

The device has been reset. (RebootReason=[RebootReason])

Restoration Content

None.

Cause Analysis

Handling Procedure

This log is informational only, and no action is required.

Impact on the System

The device restarts and the system runs again.

Content

The CPU usage exceeded the pre-set overload threshold. (Usage=[Usage],Threshold=[Threshold])

Restoration Content

The CPU usage falls below the pre-set overload threshold. (Usage=[Usage],Threshold=[Threshold])

Cause Analysis

Services are not differentiated, and the board CPU usage exceeds the predefined overload threshold.

Handling Procedure

  • If the CPU usage is higher than the overload threshold, delete unnecessary services and configurations to reduce the CPU usage. Then, check whether the alarm is cleared.
  • If the alarm is no longer generated, the problem is resolved.
  • If the alarm persists, collect alarm, log, and configuration information, and contact technical support personnel.

Impact on the System

Services are not affected in a short period of time. However, if the CPU usage remains high for a long period of time, services may not be processed in a timely manner, affecting the system performance. For example, the response speed of the GUI, neighbor status, and route convergence performance will be affected.

Content

The CPU usage exceeds the reset threshold. (Usage=[Usage], Threshold=[Threshold])

Restoration Content

The CPU usage is lower than the reset threshold. (Usage=[Usage], Threshold=[Threshold])

Cause Analysis

The CPU usage is high.

Handling Procedure

1. If the board is not reset or powered off and services are running properly, contact technical support.

2. Power off and then power on the faulty board.

3. If the board cannot be registered or the alarm cannot be cleared after the board is registered, contact Huawei technical support personnel.

4. End.

Impact on the System

The device is reset.

Content

The memory usage exceeded the pre-set overload threshold. (Usage=[Usage], Threshold=[Threshold])

Restoration Content

The memory usage falls below the pre-set overload threshold. (Usage=[Usage], Threshold=[Threshold])

Cause Analysis

The board memory usage exceeds the predefined overload threshold.

Handling Procedure

1. Run the display system memory statistics command to check the memory usage (the memory usage is calculated by dividing System Used by System Total), and run the display memory threshold command to check the overload threshold.

  • If the memory usage is higher than the overload threshold, go to step 2.
  • If the memory usage is lower than the overload threshold, go to step 4.

2. Delete unnecessary services and configurations to reduce memory usage, and then check whether the alarm is cleared. When deleting service configurations, submit three to five configurations in a batch.

  • If the alarm is no longer generated, the problem is resolved.
  • If the alarm persists, go to step 3.

3. Run the set memory threshold command to adjust the overload threshold and check whether the alarm is cleared.

  • If the alarm is no longer generated, the problem is resolved.
  • If the alarm persists, go to step 4.

4. Collect alarm, log, and configuration information, and contact technical support personnel.

Impact on the System

If the memory space cannot be applied for services, the system is automatically restarted.

Content

Interface has turned into DOWN state. (PortID=[%u],PortName=[%s],AdminStatus=[%s],OperStatus=[%s])

Restoration Content

None.

Cause Analysis

The physical link where the interface resides becomes Down.

Handling Procedure

1. If the Ethernet cable is removed and then inserted or the port status is configured, this log message is informational only, and no action is required.

2. On the port management page of the web system, check whether the interfaces at both ends are shut down.

  • If so, go to step 3.
  • If not, go to step 4.

3. Enable the interfaces on the port management page of the web system, and check whether the alarm is cleared.

  • If so, go to step 7.
  • If not, go to step 4.

4. Check whether the physical connection is normal (for example, whether the Ethernet cable or optical module is loose or disconnected).

  • If so, go to step 6.
  • If not, go to step 5.

5. Connect the physical link correctly and check whether the alarm is cleared.

  • If so, go to step 7.
  • If not, go to step 6.

6. Collect alarm and configuration information, and contact technical support personnel.

7. End

Impact on the System

The interface cannot forward packets properly.

Content

The interface CRC error count exceeded the trap threshold. (PortID=[%u],PortName=[%s],ErrorCount=[%u],Threshold=[%u],CountInterval=[%u](s))

Restoration Content

The interface CRC error count fell below the trap threshold. (PortID=[%u],PortName=[%s],ErrorCount=[%u],Threshold=[%u],CountInterval=[%u](s))

Cause Analysis

The number of CRC errors exceeds the preset threshold.

Handling Procedure

1. On the interface management page of the web system, check whether the rates and duplex modes of the interfaces at both ends of the link are the same.

  • If so, go to step 2.
  • If not, adjust the duplex mode.

2. If the optical fiber or optical module is faulty, replace the optical module or optical fiber, and then check whether the fault is rectified.

  • If so, no further action is required.
  • If not, go to step 3.

3. Collect alarm and configuration information, and contact technical support personnel.

Impact on the System

Some service data on the interface is lost.

Content

The port duplex mode has changed. (PortID=[%u],PortName=[%s],DuplexMode=[%s])

Restoration Content

None.

Cause Analysis

The interface changes from the full-duplex mode to the half-duplex mode.

The interface changes from the half-duplex mode to the full-duplex mode.

Handling Procedure

1. Check whether the interface is expected to work in the half-duplex mode.

  • If so, go to step 5.
  • If not, go to step 2.

2. On the interface management page of the web system, check whether the half-duplex mode is configured.

  • If so, forcibly set the working mode to full-duplex on the interface management page of the web system.
  • If not, go to step 4.

3. On the interface management page of the web system, check whether one end is configured with auto-negotiation and the other end is configured with non-auto-negotiation.

  • If so, configure both interfaces to use auto-negotiation on the interface management page of the web system.
  • If not, go to step 4.

4. For details, contact technical support.

5. End.

Impact on the System

The half-duplex mode may cause packet loss, bandwidth usage decrease, or even network interruption.

Content

Restoration Content

Cause Analysis

The rate of traffic received by the interface is too large.

Handling Procedure

1. Run the display this interface command in the interface view to check whether the traffic threshold is too low. The threshold range can be specified based on service requirements.

  • If so, go to step 2.
  • If not, go to step 3.

2. Run the trap-threshold input-rate <bandwidth-in-use> command in the interface view to set the alarm threshold to a larger value. Then, check whether the alarm is cleared.

  • If so, go to step 4.
  • If not, go to step 3.

3. Collect alarm and configuration information, and contact technical support personnel.

4. End.

Impact on the System

When the traffic rate approaches 100% of the bandwidth, delay or packet loss may occur.

Content

Interface PHY ID check failed. (Interface=[%u], unit=[%u], port=[%u], phyid1=[%04x], phyid2=[%04x], InterfaceName=[%s])

Restoration Content

Interface PHY ID check ok. (Interface=[%u], unit=[%u], port=[%u], phyid1=[%04x], phyid2=[%04x], InterfaceName=[%s])

Cause Analysis

The PHY chip fails.

Handling Procedure

1. If the interface that uses the abnormal PHY chip is in Up state, the device automatically restarts. After the restart, check whether the interface can send and receive packets properly.

  • If not, the PHY chip is faulty. In this case, replace the device.
  • If so, go to step 4.

2. If the interface that uses the abnormal PHY chip is in Down state, the device will not automatically restart.

  • If you do not use the interface, no action is required.
  • If you want to use the interface, go to step 3.

3. Run the reboot command to restart the device. After the restart, check whether the interface can send and receive packets properly.

  • If not, the PHY chip is faulty. In this case, replace the device.
  • If so, go to step 4.

4. End.

Impact on the System

The traffic on the interface that uses the abnormal PHY chip is interrupted.

Content

PD with invalid IEEE class and power denied. (IfIndex=[IfIndex], Interface=[Interface])

Restoration Content

None.

Cause Analysis

Cause 1:

The PD may be a non-standard PD. The device supports 802.3af and 802.3at, and the detected class value may fail to be identified.

Cause 2:

The PD hardware is faulty.

Cause 3:

The PoE chip on the device is faulty.

Handling Procedure

1. Run the poe legacy enable command on the interface to enable compatibility detection and then check whether the alarm is cleared.

  • If so, no further action is required.
  • If not, go to step 2.

2. Replace the PD with a standard PD and then check whether the alarm is cleared.

  • If so, no further action is required.
  • If not, collect alarm and configuration information and contact technical support personnel.

Impact on the System

Content

PD powered off. (IfIndex=[IfIndex], Interface=[Interface], FaultID=[FaultID])

Restoration Content

None.

Cause Analysis

Cause 1:

The PD is removed.

Cause 2:

The PD is faulty.

Cause 3:

An interface with a higher priority preempts power of the PD due to insufficient power.

Cause 4:

The interface is in the power-off time range.

Cause 5:

The PD is powered off due to overcurrent protection.

Handling Procedure

Check whether the PD is removed.

  • If so, go to step 2.
  • If not, go to step 4.

2. Check whether the PD needs to be removed.

  • If so, no further action is required.
  • If not, go to step 3.

3. Install the PD and check whether it is powered on.

  • If so, no further action is required.
  • If not, go to step 4.

4. Run the display poe power-state <interface-type> <interface-number> command to check whether the maximum output power of the interface is sufficient.

  • If so, go to step 5.
  • If not, connect the PD to another interface or PoE device.

5. Run the display poe power-state <interface-type> <interface-number> command to check whether the power supply priority of the interface is low.

  • If so, go to step 6.
  • If not, go to step 8.

6. Check whether the power supply priority of the interface needs to be reconfigured.

  • If so, go to step 7.
  • If not, go to step 8.

7. Run the poe priority command to configure the power supply priority of the interface. Then check whether the PD is powered on.

  • If so, no further action is required.
  • If not, go to step 8.

8. Run the display poe power-state <interface-type> <interface-number> command to check whether the interface is in the power-off time range.

  • If so, no further action is required.
  • If not, go to step 9.

9. Check whether the PD is faulty.

  • If so, replace the PD.
  • If not, collect alarm and configuration information and contact technical support personnel.

Impact on the System

The PD connected to this interface is powered off and cannot work normally.

Content

PoE power consumption has exceeded the upper limit. (ConsumingPower=[ConsumingPower], PowerThreshold=[PowerThreshold])

Restoration Content

PoE power consumption is below the upper limit. (ConsumingPower=[ConsumingPower], PowerThreshold=[PowerThreshold])

Cause Analysis

The total power consumption of all the PDs is greater than or equal to the alarm threshold.

Handling Procedure

1. Check whether the power consumption of the PDs is within the accepted range.

  • If so, go to step 2.
  • If not, go to step 3.

2. Run the poe power-threshold command to change the alarm threshold for PoE power consumption percentage.

3. Replan the network based on the system's external power supply capability. Run the poe priority command to increase the priority of important PDs to prevent their power from being occupied by other PDs. Power off the PDs that are not required to ensure system reliability.

Impact on the System

If the alarm persists, all the PDs may be powered off because of insufficient power supply.
