NHRP/4/NHRP_HUB_DOWN

Message

NHRP/4/NHRP_HUB_DOWN: NHRP Hub Down. (Protocol Address=[ProtocolAddress], NBMA Address=[NbmaAddress], Interface=[interface], Protocol Address Mask=[ProtAddrMask], Next Hop Address=[NextAddress])

Description

Nhrp Hub Down

Parameters

Parameter Name Parameter Meaning

ProtocolAddress

Protocol address

NbmaAddress

NBMA address

interface

Interface name

ProtAddrMask

Protocol address mask

NextAddress

Next hop address

Possible Causes

Cause 2: The tunnel interface went down.

Cause 3: NBMA addresses cannot communicate with each other.

Cause 4: GRE key configurations of the spokes and hub are different.

Cause 5: An NHRP authentication string is configured on the hub but not on the spokes; or different NHRP authentication strings are configured on the hub and spokes.

Procedure

1. Run the display current-configuration | in nhrp command to check whether the NHRP configuration is correct.

  • If so, go to Step 2.
  • If no, complete the configuration (see the corresponding configuration section) and go to Step 9.

2. Run the display interface interface-type interface-number command to check whether the interface is up.

  • If yes, go to Step 3.
  • If no, go to Step 8.

3. Run the display this command on the mGRE interface to check whether the configurations on the hub and spokes are consistent.

  • If yes, go to Step 4.
  • If no, go to Step 8.

4. Run the display ip routing-table command to check whether there are reachable routes between spokes and between spokes and the hub.

  • If yes, go to Step 5.
  • If no, go to Step 8.

5. Check whether IPsec profiles have been bound to tunnel interfaces on the hub and spokes.

  • If yes, go to Step 6.
  • If no, go to Step 7.

6. Run the display ipsec sa command to check whether IPsec SAs are established on both ends of the tunnel.

  • If yes, go to Step 7.
  • If no, go to Step 8.

7. Run the display nhrp statistics interface interface-type interface-number command to check whether the number of request packets matches the number of response packets.

  • If yes, go to Step 9.
  • If no, go to Step 8.

8. Collect trap, log, and configuration information, and contact technical support.

9. End.
