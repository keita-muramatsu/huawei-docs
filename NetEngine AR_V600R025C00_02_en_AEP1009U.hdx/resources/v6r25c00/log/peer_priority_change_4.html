HRP/4/PEER_PRIORITY_CHANGE

Message

HRP/4/PEER_PRIORITY_CHANGE: The peer priority of the HRP changed. (change_reason=[reason], peer_old_fault_indicator=[peer-old-fault-indicator], peer_new_fault_indicator=[peer-new-fault-indicator], peer_old_robustness_indicator=[peer-old-robustness-indicator], peer_new_robustness_indicator=[peer-new-robustness-indicator])

Description

Change in the priority of the peer HRP and the cause of the change

Parameters

Parameter Name Parameter Meaning

reason

Reason why the peer priority changes.

peer-old-fault-indicator

Old fault coefficient of the peer HRP.

peer-new-fault-indicator

New fault coefficient of the peer HRP.

peer-old-robustness-indicator

Old robustness coefficient of the peer HRP.

peer-new-robustness-indicator

New robustness coefficient of the peer HRP.

Possible Causes

Possible causes for a priority change are as follows:

  • The local HRP is disabled.
  • The peer HRP is disabled.
  • The heartbeat link is faulty.
  • Heartbeat packets times out.
  • A message indicating that the peer priority changes is received.
  • The local device is faulty.

Procedure

The troubleshooting method varies with the reason parameter.

  • If the value of reason is "xxx disabled", the running information is caused by user operations. No action is required.
  • If the value of reason is "The heartbeat link is faulty", check whether the link between the two devices is normal during the fault.
  • If the value of reason is "The heartbeat link is faulty", check whether the link between the two devices is normal during the fault.
  • If the value of reason is "Received peer priority change message", check the HRP running status of the peer device.
  • If the value of reason is "The local device is faulty", check whether the current device can forward packets properly.
