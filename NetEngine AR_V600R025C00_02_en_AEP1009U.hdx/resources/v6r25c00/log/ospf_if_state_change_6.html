OSPF/6/OSPF_IF_STATE_CHANGE

Message

OSPF/6/OSPF_IF_STATE_CHANGE: The status of the non-virtual interface changes. (RouterId=[RouterId], IfIpAddress=[IfIpAddress], AddressLessIf=[AddressLessIf], IfState=[IfState], ProcessId=[ProcessId], AreaId=[AreaId], IfnetIndex=[IfnetIndex], LocalIfIpAddress=[LocalIfIpAddress], IfName=[IfName], InstanceName=[InstanceName], IfChgReason=[IfChgReason])

Description

The status of the non-virtual OSPF interface changed. The possible cause is that the interface working as a physical interface went Down.

Parameters

Parameter Name Parameter Meaning

RouterId

ID of the local router

IfIpAddress

IP address of the interface on the non-virtual link. If IP address unnumbered is configured, the value is 0.0.0.0.

AddressLessIf

If IP address unnumbered is not configured on an interface, the value is 0. In other cases, the value is the same as IfnetIndex.

IfState

Interface status.

  • [0] Down.
  • [1] Waiting.
  • [2] P2P.
  • [3] DR.
  • [4] BDR.
  • [5] DROther.
  • [6] LoopBack.
  • [7] Standby.
  • [8] Max State.

ProcessId

Process ID

AreaId

Area ID

IfnetIndex

Interface index.

LocalIfIpAddress

IP address of the local router interface

IfName

Interface name

InstanceName

The instance name

IfChgReason

The reason of interface status changed.

  • [1] Config reason.
  • [2] Physical reason.
  • [3] Unknown.

Possible Causes

Cause 1: The status of the physical interface alternated between Up and Down. Cause 2: The OSPF neighbor relationship was being established.

Procedure

1. Run the display ospf interface command to check whether the interface is down.

  • If the interface is down, go to Step 2.
  • If the interface is in another state, services are not affected. In this case, go to Step 4.

2. Run the display interface [ <interface-type> [ <interface-number> ] ] command to check whether the current interface is up.

  • If the current interface is up, go to Step 3.
  • If the current interface is in another state, view the log file to check whether the shutdown command has been configured on the interface. If the misoperation exists, run the undo shutdown command on the interface. Otherwise, go to Step 4. If a link is faulty, replace it or go to Step 3.

3. Contact technical support personnel.

4. End.
