SRPOLICY/2/hwSrPolicyCandiPathDeleteHold_active

Message

SRPOLICY/2/hwSrPolicyCandiPathDeleteHold_active: The status of an SR Policy's candidate path changed to delete-hold. (hwSrPolicyEndpoint=[SrPolicyEndpoint], hwSrPolicyColor=[SrPolicyColor], hwProtocolOrigin=[ProtocolOrigin], hwNodeAddress=[NodeAddress], hwASN=[ASN], hwDiscriminator=[Discriminator], hwPreference=[Preference])

Description

The status of the candidate path of an SR Policy changed to delete-hold.

Parameters

Parameter Name Parameter Meaning

SrPolicyEndpoint

Endpoint of an SR Policy.

SrPolicyColor

Color of an SR Policy.

ProtocolOrigin

Protocol origin.

NodeAddress

Node address.

ASN

AS number.

Discriminator

Discriminator.

Preference

Priority.

Possible Causes

If the segment list of the candidate path of the SR Policy triggers the delete-hold state, all new segment lists of the candidate path are in the Down state, and non-new segment lists of the candidate path are in the delete-hold state.

Procedure

1. Run the segment-list command in the candidate path view to add a segment list that can go up.

2. Check whether the segment-list delete-hold enable command is run in the SR Policy view. If yes, run the segment-list delete-hold disable command to disable the delete-hold function.

3. If the delete-hold function is not enabled in the SR Policy view, run the undo srv6-te-policy segment-list delete-hold enable command in the Segment Routing IPv6 view to disable the delete-hold function.

4. If the fault detection function is configured, run the undo srv6-te-policy path verification enable command in the Segment Routing IPv6 view or run the path verification disable command in the SR Policy view to disable this function.

5. If the BFD function is configured, run the display srv6-te policy command to check the BFD type and then run the corresponding command to disable this function.
