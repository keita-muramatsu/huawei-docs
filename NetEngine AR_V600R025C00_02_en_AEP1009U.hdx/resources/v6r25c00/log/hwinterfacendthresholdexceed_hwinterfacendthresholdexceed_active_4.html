ND/4/hwInterfaceNDThresholdExceed_active

Message

ND/4/hwInterfaceNDThresholdExceed_active: The number of ND entries exceeded the threshold of interface. (entPhysicalIndex=[entPhysicalIndex], Slotname=[slotname], InterfaceName=[InterfaceName], Threshold=[Threshold], Number of dynamic ND entries=[DynEntries], Number of static ND entries=[StatEntries], Number of remote ND entries=[RemoteEntries]).

Description

The number of ND entries on the interface exceeded 80% of the alarm threshold.

Parameters

Parameter Name Parameter Meaning

entPhysicalIndex

Index of the board that reports the alarm.

slotname

Name of the board that reports the alarm.

InterfaceName

Name of the interface that reports the alarm.

Threshold

Alarm threshold.

DynEntries

Number of dynamic ND entries on the interface that reports the alarm.

StatEntries

Number of static ND entries on the interface that reports the alarm.

RemoteEntries

Number of remote ND entries on the interface that reports the alarm.

Possible Causes

Many services were deployed, triggering the interface to learn a large number of dynamic ND entries. Or, a large number of static ND entries were configured on the interface. Or, a large number of remote ND entries were received on the interface.

Procedure

1. Check whether ND entries on the interface are valid. Valid entries need to be reserved.

2. If the entries are invalid and dynamic, run the reset ipv6 neighbors command to delete them. If the entries are invalid and static, run the undo ipv6 neighbor command to delete them. Remote entries need to be deleted by the remote device.

3. If invalid entries are still continuously sent to the CPU, run the ipv6 nd neighbor-limit command to limit the number of entries learned by the interface.
