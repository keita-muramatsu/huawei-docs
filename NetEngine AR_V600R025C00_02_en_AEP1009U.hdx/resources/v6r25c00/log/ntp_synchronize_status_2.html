NTP/2/NTP_SYNCHRONIZE_STATUS

Message

NTP/2/NTP_SYNCHRONIZE_STATUS: NTP state changed from synchronized to unsynchronized. (SynchronizationSourceAddress = [Source] , VpnInstance = [VpnName], Reason = [Reason])

Description

NTP synchronization status.

Parameters

Parameter Name Parameter Meaning

Source

IP address of the server for local NTP clock synchronization.

VpnName

VPN instance and remote end for local NTP clock synchronization.

Reason

Reason why the NTP clock status changes to unsynchronized.

Possible Causes

The possible causes are as follows:

Cause 1: A VPN change is detected.

Cause 2: The peer is unreachable.

Cause 3: The authentication fails.

Cause 4: The authentication configuration is changed.

Cause 5: The KOD DENY message is received.

Cause 6: The multicast probe restarts.

Cause 7: The unicast server configuration is deleted.

Cause 8: The unicast peer configuration is deleted.

Cause 9: The reference clock configuration is deleted.

Cause 10: The number of stratums increases.

Cause 11: The peer clock is not synchronized or is not selectable.

Cause 12: The multicast configuration is deleted.

Cause 13: The configuration is changed.

Cause 14: Clock selection fails due to too many fake clocks.

Cause 15: Clock selection fails because no clock can be selected.

Cause 16: A clock change is detected.

Cause 17: The NTP IPv4 service is disabled.

Cause 18: The NTP IPv6 service is disabled.

Cause 19: Peer selection is restricted.

Cause 20: The multicast session is aged.

Cause 21: The peer end can be preempted.

Cause 22: The clock stratum is invalid or the server clock is not synchronized.

Cause 23: The NTP test fails.

Cause 24: A loopback occurs during clock synchronization.

Cause 25: The clock stratum of the peer is better.

Cause 26: The clock synchronization distance is greater than the threshold.

Procedure

Cause 1: A VPN change is detected.

Select another VPN.

Cause 2: The peer is unreachable.

1. Check whether the link to the remote clock source is reachable.

2. If the link is unreachable, rectify the network fault or configure a new remote clock source.

3. If the link is reachable, check whether the source interface is correctly configured.

Cause 3: The authentication fails.

The synchronization fails because authentication failure packets are discarded.

1. Check whether a key is configured. If not, configure a key. If so, check whether the key is correct.

2. Check whether the key is trusted.

3. Check whether the clock source configuration contains a key.

Cause 4: The authentication configuration is changed.

If the authentication configuration is changed, see cause 3.

Cause 5: The KOD DENY message is received.

The client receives the KOD packet with the DENY code. The remote clock source restricts the synchronization time of the client. In this case, configure a new remote clock source.

Cause 6: The multicast probe restarts.

The multicast client restarts the discovery process. No action is required.

Cause 7: The unicast server configuration is deleted.

The unicast server configuration has been deleted. Reconfigure the NTP unicast server.

Cause 8: The unicast peer configuration is deleted.

The unicast peer configuration has been deleted. Reconfigure the NTP unicast peer.

Cause 9: The reference clock configuration is deleted.

The master clock configuration has been deleted. Reconfigure the local NTP clock as the master NTP clock.

Cause 10: The number of stratums increases.

1. The stratum of the remote clock source is increased. Check whether the current clock is in the synchronization state.

2. If the clock is in the synchronization state, check whether the precision meets the requirements. If not, reconfigure a remote clock source with higher precision.

3. If the clock is not in the synchronization state, reconfigure a new remote clock source.

Cause 11: The peer clock is not synchronized or is not selectable.

1. The stratum of the remote clock source is increased. Check whether the current clock is in the synchronization state.

2. If the clock is in the synchronization state, check whether the precision meets the requirements. If not, reconfigure a remote clock source with higher precision.

3. If the clock is not in the synchronization state, reconfigure a new remote clock source.

Cause 12: The multicast configuration is deleted.

The multicast client configuration has been deleted. Reconfigure the NTP multicast client.

Cause 13: The configuration is changed.

Check whether the client configuration is deleted. If so, add the NTP client configuration again.

Cause 14: Clock selection fails due to too many fake clocks.

Clock selection fails due to too many fake clocks. In this case, delete invalid clock sources and reconfigure valid clock sources.

Cause 15: Clock selection fails because no clock can be selected.

Clock selection fails because no clock source is available. Configure a valid clock source.

Cause 16: A clock change is detected.

The time of the clock source undergoes an unexpected change. Check the time of the clock source or reconfigure a new remote clock source.

Cause 17: The NTP IPv4 service is disabled.

The NTP IPv4 service is disabled. Enable the NTP IPv4 service again.

Cause 18: The NTP IPv6 service is disabled.

The NTP IPv6 service is disabled. Enable the NTP IPv6 service again.

Cause 19: Peer selection is restricted.

The peer cannot be selected. Reconfigure the NTP peer.

Cause 20: The multicast session is aged.

The multicast dynamic session is aged, and no action is required.

Cause 21: The peer end can be preempted.

The peer is preempted, and no action is required.

Cause 22: The clock stratum is invalid or the server clock is not synchronized.

1. The stratum of the remote clock source is invalid or not synchronized. Check whether the current clock is in the synchronization state.

2. If the clock is in the synchronization state, check whether the precision meets the requirements. If not, reconfigure a remote clock source with higher precision.

3. If the clock is not in the synchronization state, reconfigure a new remote clock source.

Cause 23: The NTP test fails.

NTP standard verification failed. Reconfigure a new remote clock source.

Cause 24: A loopback occurs during clock synchronization.

An NTP synchronization loop is detected. Check the NTP configuration.

Cause 25: The clock stratum of the peer is better.

The system peer stratum is better, and no action is required.

Cause 26: The clock synchronization distance is greater than the threshold.

If the synchronization distance is greater than the distance threshold, adjust the synchronization distance threshold or reconfigure a better clock source.
