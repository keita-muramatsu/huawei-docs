RUMNG/4/LLDP_INTERFACE_NEIGB_CHANGE

Message

RUMNG/4/LLDP_INTERFACE_NEIGB_CHANGE: Neighbor information of the interface was changed. (RemoteUnitEsn=[remoteUnitEsn], PortName=[portName], RuPortName=[ruPortName], NeighborIndex=[remoteIndex], Action=[eventType], RemoteChassisType=[chassisSubType], RemoteChassisId=[chassisId], RemotePortIdType=[portIdSubType], RemotePortId=[portId], RemoteSystemName=[systemName], RemoteSystemDescription=[systemDescription])

Description

The neighbor information of the interface changes.

Parameters

Parameter Name Parameter Meaning

remoteUnitEsn

ESN of the RU.

portName

Interconnection interface on an RU.

ruPortName

Interface on an RU.

remoteIndex

Index of an LLDP neighbor.

eventType

LLDP neighbor change type:

1: add

2: delete

3: update

chassisSubType

Indicates the chassis type of the LLDP neighbor.

chassisId

Indicates the chassis ID of an LLDP neighbor.

portIdSubType

Interface ID type of an LLDP neighbor.

portId

Interface ID of an LLDP neighbor.

systemName

Indicates the system name of an LLDP neighbor.

systemDescription

Indicates the system description of an LLDP neighbor.

Possible Causes

Cause 1: The interface discovered a new neighbor.

Cause 2: The neighbor of the interface was deleted.

Cause 3: The neighbor of the interface ages out because the aging time expires.

Procedure

Cause 1: A new neighbor was discovered.

1. Run the display remote-unit lldp neighbor command to check whether LLDP is enabled on the new neighbor.

  • If so, the message is informational only, and no action is required.
  • If not, go to Step 2.

2. Collect log and configuration information, and contact technical support.

Cause 2: A neighbor was deleted.

1. Run the display remote-unit lldp neighbor command to check whether LLDP is disabled on the neighbor.

  • If so, run the undo lldp disable command in the remote unit view of the neighbor to enable LLDP.
  • If not, go to Step 2.

2. Run the display remote-unit port brief command to check whether a link fault has occurred between the local and neighboring devices.

  • If so, rectify the link fault.
  • If not, go to Step 3.

3. Collect log and configuration information, and contact technical support.

Cause 3: A neighbor was aged because the aging period expired.

1. Run the display lldp statistics command to check whether neighboring node information saved on the local device has timed out.

  • If so, the message is informational only, and no action is required.
  • If not, go to Step 2.

2. Check whether the interface connecting the local and neighboring devices has been shut down.

  • If so, run the undo shutdown command on the interface to set the interface to up.
  • If not, go to Step 3.

3. Collect log and configuration information, and contact technical support.
