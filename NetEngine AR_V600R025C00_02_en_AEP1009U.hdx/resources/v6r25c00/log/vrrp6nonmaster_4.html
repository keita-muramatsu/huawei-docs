VRRP6/4/vrrp6NonMaster

Message

VRRP6/4/vrrp6NonMaster: The VRRP status changed between backup and initialize. (ifIndex=[ifIndex], VrId=[VrId], MasterIpAddr=[MasterIpAddr], sysName=[sysName], ifName=[ifName], CurrentState=[CurrentState], ChangeReason=[ChangeReason])

Description

The VRRP6 status changed between Backup and Initialize.

Parameters

Parameter Name Parameter Meaning

ifIndex

Index of the interface where VRRP6 is configured

VrId

VRID of the VRRP6 backup group

MasterIpAddr

IP address of the master device in the VRRP6 backup group

sysName

System name

ifName

Name of the interface where VRRP6 is configured

CurrentState

VRRP6 status after the change. Possible values are as follows:

  • Initialize
  • Backup

ChangeReason

VRRP6 status change reason

Possible Causes

Possible Cause s for the VRRP6 status change from Backup to Initialize are as follows:

Cause 1: The device on which the VRRP6 backup group is configured failed.

Cause 2: The interface on which the VRRP6 backup group is configured or its connected link failed.

Possible Cause s for the VRRP6 status change from Initialize to Backup are as follows:

Cause 1: The device on which the VRRP6 backup group is configured recovered.

Cause 2: The interface on which the VRRP6 backup group is configured or its connected link recovered.

Procedure

1. Check the value of CurrentState in the log to determine the status of the VRRP6 group after the change.

  • If the value of CurrentState is Initialize, go to Step 2.
  • If the value of CurrentState is Backup, the status of the VRRP6 group changes from Initialize to Backup, which is normal. In this case, go to Step 6.

2. The original backup device in the VRRP6 group fails. Locate and rectify the fault as follows:

  • If the interface on which the VRRP6 group is configured is Down, go to Step 3.
  • If the link monitored by BFD that is associated with VRRP6 is Down, go to Step 4.

3. Run the display this interface command in the view of the interface where VRRP6 is configured to check the physical status and protocol status of the interface.

  • If the physical status of the interface is Down, the direct link of the interface fails. Locate the cause of the fault and restore the monitored link. Then, check whether the VRRP6 group recovers.
  • If the VRRP6 group has recovered, go to Step 6.
  • If the VRRP6 group has not recovered, go to Step 5.
  • If the physical status of the interface is Up but its protocol status is Down, the IP address of the interface has been deleted. Reassign an IP address to the interface. Then, check whether the VRRP6 group recovers.
  • If the VRRP6 group has recovered, go to Step 6.
  • If the VRRP6 group has not recovered, go to Step 5.
  • If the physical and protocol statuses of the interface are both Up, the IP address of the interface is not on the same network segment as the virtual IP address of the VRRP6 group. Reassign an IP address to the interface and ensure that the IP address is on the same network segment as the virtual IP address of the VRRP6 group. Then, check whether the VRRP6 group recovers.
  • If the VRRP6 group has recovered, go to Step 6.
  • If the VRRP6 group has not recovered, go to Step 5.

4. Run the display vrrp6 command and check whether the value of BFD-session state in the command output is Up.

  • If Down is displayed, the original backup link is faulty. Locate and rectify the fault. Then, check whether the VRRP6 group recovers.
  • If the VRRP6 group has recovered, go to Step 6.
  • If the VRRP6 group has not recovered, go to Step 5.
  • If the value of BFD-session state in the command output is UP, go to Step 5.

5. Collect log and configuration information, and contact technical support personnel.

6. End.
