ISIS/5/IS_ADJ_CHANGE

Message

ISIS/5/IS_ADJ_CHANGE: ISIS-INFO: ISIS adjacency state changed. (IfName=[IfName], AdjLevel=[AdjLevel], NbrSysId=[NbrSysId], AdjState=[AdjState], AddressFamily=[AddressFamily], Reason=[Reason], LastSendHelloTime=[LastSendHelloTime], LastRecvHelloTime=[LastRecvHelloTime], CpuUsage=[CpuUsage]%, LocalIpv4Add=[LocalIpv4Add], LocalIpv6Add=[LocalIpv6Add], PeerIpv4Add=[PeerIpv4Add], PeerIpv6Add=[PeerIpv6Add], VpnName=[VpnName], SysInstId=[SysInstId], OldAdjState=[OldAdjState], IfMtu=[IfMtu], SubReason=[SubReason], SuppressCount=[SuppressCount], SystemInfo=[SystemInfo])

Description

The status of the neighbor changed.

Parameters

Parameter Name Parameter Meaning

IfName

Name of a corresponding interface on a neighbor.

AdjLevel

Level of the neighbor whose status changes.

NbrSysId

ID of an LSP.

AdjState

Former status of a neighbor:

  • 1: Down.
  • 2: Init.
  • 3: Up.

AddressFamily

Address family of a neighbor.

Reason

Cause of the neighbor status change.

LastSendHelloTime

Time when the Hello packet was last sent.

LastRecvHelloTime

Time when the Hello packet was last received.

CpuUsage

CPU usage.

LocalIpv4Add

IPv4 address of the local interface.

LocalIpv6Add

IPv6 address of the local interface.

PeerIpv4Add

IPv4 address of the peer neighbor.

PeerIpv6Add

IPv6 address of the peer neighbor.

VpnName

VPN instance name.

SysInstId

IS-IS process ID.

OldAdjState

Former status of the neighbor.

IfMtu

Interface MTU.

SubReason

The neighbor went Up.

  • The neighbor is deleted.
  • Deleting an Interface
  • Interface Suppression
  • Incorrect packets are received.
  • Authentication failed.
  • A system ID conflict occurs on the network.
  • The maximum number of area addresses does not match.
  • Indicates that the Level-1 area addresses do not match.
  • No Hello packet is received.
  • The physical interface is Down.
  • The protocol type does not match.
  • Insufficient Memory
  • BFD Down
  • IS-IS shutdown
  • The handshake mode is changed.
  • The neighbor is reset.
  • The interface type is changed.
  • IS-IS reset
  • undo last network
  • undo IS-IS
  • The level does not match.
  • IIH packets do not contain the local SNPA address.
  • The interface is not Up after three-way handshake.
  • No matching MT ID.
  • CircuitID change
  • Hello packets received from the peer end during three-way handshake do not contain the local neighbor.
  • Other errors.
  • The checksum is incorrect.
  • Multicast Association
  • Topology Suppression
  • Alarm Timeout
  • Configuration Changes

SuppressCount

Number of times that suppression is performed

SystemInfo

System information

Possible Causes

1. The hold timer of the IS-IS neighbor expired.(The neighbor HoldTimer expires.)

2. The physical interface went Down.(The interface is Down.)

3. Protocols are incorrectly configured.(protocol cause).

4. BFD detected that the neighbor went Down.(BFD detects that the neighbor is Down.)

5. The IS-IS configuration changed.(configuration change).

6. The problem is caused by the remote device.(The peer device is faulty.)

Cause 100: The alarm was cleared.(The alarm is cleared.)

Procedure

  • Cause 1: The adjacency HoldTimer expired.

1. Run the ping command to ping the remote device.

  • If the remote device can be pinged, go to Step 2.
  • If the remote device cannot be pinged, go to Step 4.

2. Run the display this command in the IS-IS process view and interface view on the peer device to check whether IS-IS configurations are correct.

  • If IS-IS configurations are correct, go to Step 3.
  • If IS-IS configurations are incorrect, go to Step 5.

3. Check whether the CPU usage is excessively high.

  • If the CPU usage is high, go to Step 5.
  • If the CPU usage is not high, go to Step 6.

4. Run the display this command in the interface view to check whether the link configuration is correct. If the link configuration is incorrect, modify it. Then, run the display isis peer command to check whether the neighbor relationship is up.

  • If the neighbor relationship is down, go to Step 5.
  • If the neighbor relationship is up, the fault is rectified.

5. In the system view, run the display current-configuration command to check whether the configuration on the device is correct. If the configuration is incorrect, modify it. Then, run the display isis peer command to check whether the neighbor relationship is up.

  • If the neighbor relationship is down, go to Step 6.
  • If the neighbor relationship is up, the fault is rectified.

6. Collect log and configuration information, and contact technical support personnel.

  • Cause 2: The physical interface went Down.

1. Run the display isis interface or the display interface brief command to check whether the interface is down.

  • If the interface is down, go to Step 2.
  • If the interface is up, go to Step 3.

2. Modify the configuration, and then check whether the interface goes up.

  • If the interface is up, go to Step 3.
  • If the interface is down, go to Step 4.

3. Run the display isis peer command to check whether the neighbor relationship is up.

  • If the neighbor relationship is down, go to Step 4.
  • If the neighbor relationship is up, the fault is rectified.

4. Collect log and configuration information, and contact technical support personnel.

  • Cause 3: Protocol reason.

1. Run the display memory command to check whether the memory usage of the system is too high.

  • If the memory usage is not high, go to Step 2.
  • If the memory usage is too high, no further action is required.

2. Collect log and configuration information, and contact technical support personnel.

  • Cause 4: BFD detected that the neighbor went Down.

1. Run the ping command to ping the remote device.

  • If the remote device can be pinged, go to Step 3.
  • If the remote device cannot be pinged, go to Step 2.

2. Run the display this command in the interface view to check whether the link configuration is correct. If the link configuration is incorrect, modify it. Then, run the display isis peer command to check whether the neighbor relationship is up.

  • If the neighbor relationship is down, go to Step 3.
  • If the neighbor relationship is up, the fault is rectified.

3. Collect log and configuration information, and contact technical support personnel.

  • Cause 5: Configurations changed.

1. Check whether some recently changed configurations affect the establishment of the neighbor relationship.

  • If yes, go to Step 2.
  • If no, go to Step 4.

2. Check whether configurations are changed as expected.

  • If yes, no further action is required.
  • If no, go to Step 3.

3. Restore the original configuration and then check whether the neighbor relationship is up.

  • If the neighbor relationship is down, go to Step 4.
  • If the neighbor relationship is up, the fault is rectified.

4. Collect log and configuration information, and contact technical support personnel.

  • Cause 6: Peer router reason.

1. Check whether the configuration on the remote device is correct.

  • If the configuration of the remote device is incorrect, go to Step 2.
  • If the configuration of the remote device is correct, go to Step 3.

2. Correct the configuration of the remote remote and then check whether the neighbor relationship is up.

  • If the neighbor relationship is down, go to Step 3.
  • If the neighbor relationship is up, the fault is rectified.

3. Collect log and configuration information, and contact technical support personnel.
