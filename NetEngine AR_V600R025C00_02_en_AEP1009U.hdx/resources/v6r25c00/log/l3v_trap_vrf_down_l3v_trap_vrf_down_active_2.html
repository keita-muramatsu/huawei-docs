L3VPN/2/L3V_TRAP_VRF_DOWN_active

Message

L3VPN/2/L3V_TRAP_VRF_DOWN_active: The interface bound to the VPN instance went Down. (VpnInstanceName=[VpnInstanceName], IfName=[IfName], IfCurRowStatus=[IfCurRowStatus], VRFOperationStatus=[VRFOperationStatus])

Description

Of the interfaces that are bound to VPN instance, the last interface in the Up state goes Down.

Parameters

Parameter Name Parameter Meaning

VpnInstanceName

Indicates the name of the VPN.

IfName

The name of interface.

IfCurRowStatus

Indicates the row status of the interface. Including:

  • 1: Active
  • 2: Not in Service
  • 3: Not Ready
  • 4: Create and Go
  • 5: Create and Wait
  • 6: Destroy

VRFOperationStatus

Indicates the status of the VRF. Including:

  • 1: Up
  • 2: Down

Possible Causes

Cause 1: One interface was bound with the VPN instance, and the interface status changed from Up to Down.

Cause 2: Multiple interfaces were bound with the VPN instance; the status of all the interfaces changed from Up to Down; the last interface in the Up state went Down.

Cause 3: The last interface with Up state is disassociated from the VPN instance.

Procedure

1. Run the display ip vpn-instance verbose <vpn-instance-name> command to view the Interfaces field and check the interfaces bound to the specified VPN instance.

  • If no interface is bound, check whether a log that contains the keyword undo ip binding vpn-instance is generated together with the alarm.
  • If yes and the VPN instance needs to be unbound, run the transit-vpn command to set the VPN status to Up to clear the alarm. If the VPN instance is not used, delete the VPN instance to clear the alarm. Otherwise, run the ip binding vpn-instance <vpn-instance-name> command in the interface view to bind the VPN instance to the interface, and run the ip address command to configure an IP address for the interface.

If the L3VPN_1.3.6.1.2.1.10.166.11.0.1 L3VPN_MIB_TRAP_VRF_UP alarm of the VPN instance is displayed, the fault is rectified.

Otherwise, go to Step 5.

If no, go to Step 5.

  • If there are interfaces bound to the VPN instance, go to Step 2.

2. Run the display ip interface brief command to check whether the interfaces bound to the VPN instance are up.

  • If yes, go to Step 5.
  • If no, go to Step 3.

3. Check whether the interfaces bound to the VPN instance have IP addresses configured.

  • If yes, go to Step 4.
  • Configure IP addresses for the interfaces bound to the VPN instance using the ip address command.

If the L3VPN_1.3.6.1.2.1.10.166.11.0.1 L3VPN_MIB_TRAP_VRF_UP alarm of the VPN instance is displayed, the fault is rectified.

If no, go to Step 4.

4. Run the display this command in the view of the interface bound to the VPN instance to check whether the shutdown command was run.

  • If yes, run the undo shutdown command to enable the interface as required.

If the L3VPN_1.3.6.1.2.1.10.166.11.0.1 L3VPN_MIB_TRAP_VRF_UP alarm of the VPN instance is displayed, the fault is rectified.

If no, go to Step 5.

  • If no, go to Step 5.

5. Collect alarm and configuration information, and contact technical support.

6. End.
