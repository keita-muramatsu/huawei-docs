ISIS/2/isisSystemIdCfgConflict_active

Message

ISIS/2/isisSystemIdCfgConflict_active: An IS-IS system ID conflict occurred. The system ID may have been automatically restored, but the conflicting configuration may still exist. To restore the configured system ID, manually delete the network-entity of the local device and reconfigure it. (SysInstance=[hwisisSysInstance], Level=[hwisisSysLevelIndex], ConflictSystemID=[hwIsisConflictSystemID], LocalHostName=[hwIsisHostName], RemoteHostName=[hwIsisAdjSysName])

Description

This alarm is generated when an IS-IS system ID conflict occurs.

Parameters

Parameter Name Parameter Meaning

hwisisSysInstance

ID of an IS-IS process.

hwisisSysLevelIndex

IS-IS Level.

hwIsisConflictSystemID

Conflicting IS-IS system ID.

hwIsisHostName

Dynamic hostname of the local IS-IS end.

hwIsisAdjSysName

Dynamic hostname of the IS-IS remote end.

Possible Causes

The same IS-IS system ID is configured on multiple non-directly connected devices in the network.

Procedure

1. Run the undo network-entity command to delete the IS-IS system ID of the local device.

2. Re-plan the IS-IS system ID of the local device to ensure that it is unique on the network.

3. Run the network-entity command to configure a new IS-IS system ID.

4. Run the display isis system-id conflict command to check whether an IS-IS system ID conflict exists.

  • If the conflict persists, go to Step 1 or collect log and configuration information and contact technical support personnel.
  • If the conflict no longer exists, the alarm is cleared, and no further action is required.
