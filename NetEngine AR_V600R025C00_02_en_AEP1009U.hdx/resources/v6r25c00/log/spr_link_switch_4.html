SPR/4/SPR_LINK_SWITCH

Message

SPR/4/SPR_LINK_SWITCH: The path of SPR instance changed. (DestSiteIndex=[DestSiteIndex], PolicyName=[PolicyName], PreviousLink=[PreviousLink], PreviousLinkLoss=[PreviousLinkLoss], PreviousLinkDelay=[PreviousLinkDelay], PreviousLinkJitter=[PreviousLinkJitter], PreviousLinkCMI=[PreviousLinkCMI], PreviousLinkOutputRate=[PreviousLinkOutputRate], PreviousLinkApplicationRate=[PreviousLinkApplicationRate], CurrentLink=[CurrentLink], CurrentLinkLoss=[CurrentLinkLoss], CurrentLinkDelay=[CurrentLinkDelay], CurrentLinkJitter=[CurrentLinkJitter], CurrentLinkCMI=[CurrentLinkCMI], CurrentLinkOutputRate=[CurrentLinkOutputRate], CurrentLinkApplicationRate=[CurrentLinkApplicationRate], ChangedReason=[ChangedReason])

Description

The link selected by the SPR instance changes.

Parameters

DestSiteIndex

Index of the destination site.

SPR policy name.

ChangedReason

Cause of the link switchover.

When a link is unavailable, the device may report an alarm indicating that the packet loss rate on the link exceeds the threshold or the link status changes.

Possible Causes

1. The delay of the link exceeds the threshold configured in the policy.

2. The packet loss rate of the link exceeds the threshold configured in the policy.

3. The jitter of the link exceeds the threshold configured in the policy.

4. The comprehensive metric value of the link exceeds the threshold configured in the policy.

5. The real-time rate of the link exceeds the configured link bandwidth threshold.

6. The link status changes.

7. The link detection result is down.

8. Traffic is switched back from a low-priority link to a high-priority link.

9. The optimal link is selected.

10. Traffic steering is performed for the first time.

11. The real-time rate of the link exceeds the configured application bandwidth threshold of the link.

Procedure

1. Run the display spr-policy command to check whether the thresholds configured in the SPR policy are correct.

  • If the delay threshold is incorrect, run the delay threshold command to set a proper threshold for the policy.
  • If the jitter threshold is incorrect, run the jitter threshold command to set a proper threshold for the policy.
  • If the packet loss rate threshold is incorrect, run the loss threshold command to set a proper threshold for the policy.
  • If the CMI threshold is incorrect, run the cmi threshold command to configure a proper threshold for the policy.
  • If the configuration is correct, go to step 2.

2. Check the status of the transport network.

  • If the network quality is poor during the switchover, the link switchover is normal.
  • If the status of the transport network is normal, go to step 3.

3. Collect alarm, log, and configuration information, and contact technical support personnel.
