IPSEC/5/IPSEC_TUNNEL_TEARED_DOWN

Message

IPSEC/5/IPSEC_TUNNEL_TEARED_DOWN: Vsys [vsys-name]: An IPSec tunnel is teared down. (IfName=[if-name], PolicyName=[policy-name], PolicyId=[policy-id], PolicyAlias=[policy-alias], TunnelVpnName=[tunnel-vpn-name], FlowVpnName=[flow-vpn-name], PeerAddress=[peer-address], PeerPort=[peer-port], LocalAddress=[local-address], LocalPort=[local-port], FlowInfo=[flow-info], Reason=[reason], Status=[status])

Description

An IPsec tunnel has been torn down.

Parameters

Parameter Name Parameter Meaning

vsys-name

The value is fixed to Public.

if-name

Interface name.

policy-name

Name of an IPsec policy.

policy-id

Sequence number of the IPsec policy.

policy-alias

Alias of the IPsec policy.

tunnel-vpn-name

VPN instance name.

flow-vpn-name

VPN instance name of data packets.

peer-address

Peer IP address.

peer-port

Peer UDP port number.

local-address

Local IP address.

local-port

Local UDP port number.

flow-info

Flow information.

reason

Cause for a tunnel Down event.

status

Tunnel status.

  • 1: The tunnel goes online.
  • 2: The tunnel goes offline.

Possible Causes

Reason why a tunnel goes offline:

  • dpd timeout: DPD detection times out.
  • peer request: The peer end sends a deletion message.
  • config modify or manual offline: The SA is deleted or the SA is manually cleared due to configuration modification.
  • phase1 hard expiry: A hard timeout occurs in phase 1 (no new SA negotiation succeeds).
  • phase2 hard expiry: A hard timeout occurs in phase 2.
  • heartbeat timeout: The heartbeat detection times out.
  • re-auth timeout: The SA is deleted because re-authentication times out.
  • aaa cut user: The AAA module logs out the user, causing the SA to be deleted.
  • ip address syn failed: IP address synchronization fails.
  • hard expiry triggered by port mismatch: A hard timeout occurs due to NAT port mismatch.
  • kick old sa with same flow: The old SA is deleted when the same flow accesses the network.
  • cpu table updated: The SAs of other CPUs are deleted when the SPU is removed and then inserted.
  • flow overlap: The IP address in the encrypted flow conflicts with the peer IP address.
  • spi conflict: An SPI conflict occurs.
  • phase1 sa replace: The new IKE SA replaces the old IKE SA.
  • phase2 sa replace: The new IPsec SA replaces the old IPsec SA.
  • nhrp notify: NHRP instructs the device to delete the SA.
  • receive backup delete info: The standby device receives SA backup deletion messages from the active device.
  • eap delete old sa: The local device deletes the old SA when the remote device performs EAP authentication repeatedly.
  • receive invalid spi notify: An invalid SPI notification is received.
  • dns resolution status change: The DNS resolution status changes.
  • ikev1 phase1-phase2 sa dependent offline: The device deletes the associated IPsec SA when deleting an IKEv1 SA.
  • exchange timeout: Packet exchange times out.
  • hash gene adjusted: The IPsec tunnel is deleted due to hash factor adjustment.
  • ipsec tunnel recover: Tunnel self-healing and reestablishment
  • hash except: The IPsec tunnel is deleted because the hash traffic distribution algorithm is adjusted.

Procedure

  • Cause: DPD timed out.

Perform the ping operation to check whether the link is reachable. If the link is unreachable, check whether the link and network configuration are correct.

  • Cause: heartbeat timeout

1. Perform a ping to check link reachability. If a link is unreachable, verify the link configuration.

2. Check the heartbeat configurations on both ends. If the configuration is incorrect, correct it.

  • Reason: config modify or manual offline

1. Check whether an SA is reset manually. If so, no further action is required.

2. Check whether the IPsec configuration modified on the local end is correct. If not, correct the configuration.

3. Check whether the IPsec policy is properly deleted. If not, re-apply the IPsec policy to the interface.

  • Cause: phase1 hard expiry

Check whether the IKE SA lifetime is proper. If not, modify the IKE SA lifetime.

  • Cause: phase2 hard expiry

Check whether the IPsec SA lifetime is proper. If not, modify the IPsec SA lifetime.

  • Cause: flow overlap

Check the security ACL information configured on both ends and modify the ACL rules that conflict with each other.

  • Reason: hard triggered by port mismatch

Check whether the NAT ports on both ends match. If not, modify the NAT ports.

  • Cause: peer request

Check the log information of the remote device and determine the cause of the IPSec tunnel fault based on the log information.

  • Cause: receive invalid spi notify

If the fault occurs frequently, check whether the status and configuration of the peer device are normal.

  • Cause: dns resolution status change

1. Ensure that the link between the device and DNS server is normal.

2. Ensure that the DNS server is working properly.

3. Ensure that the domain name configured using the remote-address host-name command is correct.

  • Reason: ikev1 phase1-phase2 sa dependent offline

If new IKE SAs and IPsec SAs can be established through renegotiation, no action is required. If the two devices cannot renegotiate new IKE SA and IPsec SA, you are advised to run the undo ikev1 phase1-phase2 sa dependent command on the local device to configure dependency between IPsec SA and IKE SA during IKEv1 negotiation.

  • Cause: ip address syn failed

Ensure that the link is normal and the IPsec configuration is correct.

  • Cause: Exchange timed out.

Ensure that the link is normal and the IPsec configuration is correct.

  • Reason: kick old sa with same flow

Run the ipsec remote traffic-identical accept command to enable new users with the same data flow to access the headquarters.

  • Possible causes: aaa cut user, receive backup delete info, eap delete old sa, re-auth timeout, phase1 sa replace, phase2 sa replace, cpu table updated, spi conflict, nhrp notify and ipsec tunnel recover.

No action is required.
