SDWAN-EVPN/2/hwConnectionDownReport_active

Message

SDWAN-EVPN/2/hwConnectionDownReport_active: The connection has entered the down state. (ConnectionID=[ConnectionID], DestSiteID=[DestSiteID], SrcSiteID=[SrcSiteID], DestTNPID=[DestTNPID], SrcTNPID=[SrcTNPID], DownReason=[DownReason], ReasonCode=[ReasonCode])

Description

The SD-WAN EVPN link is unavailable.

Parameters

Parameter Name Parameter Meaning

ConnectionID

Indicates the link index.

DestSiteID

ID of the destination site.

SrcSiteID

Indicates the ID of the source site.

DestTNPID

Destination TNP ID.

SrcTNPID

Indicates the source TNP ID.

DownReason

Reason why the link goes Down.

ReasonCode

Reason code.

Possible Causes

  • Cause 1: The site tunnel route is deleted.
  • Cause 2: The DH group does not match.
  • Cause 3: The DH group is changed.
  • Cause 4: The TNP is deleted.
  • Cause 5: The TNP status changes to down.
  • Cause 6: The TNP weight is changed.
  • Cause 7: KA detection fails.
  • Cause 8: Reset by user.

Procedure

  • Cause 1: The site tunnel route is deleted.

    1. Check whether the service route to the corresponding site is deleted.

    Run the display tunnel all command to check information about all tunnels.

    Run the display tunnel tunnel-id command to check SD-WAN tunnel information one by one and check whether the corresponding service route exists.

    If no, configure the corresponding site route.

    If yes, collect alarm and configuration information, and contact technical support personnel.

  • Cause 2: The DH group does not match.

    1. Check whether the DH group of the local device matches that of the peer device.

    Run the display ipsec p2mp-policy command to check IPSec Key-Exchange information on both ends.

    If the DH groups of the two communication parties are different and one party uses the strict mode, the DH groups cannot match.

    Configure the same DH group or disable the strict mode.

  • Cause 3: The DH group is changed.

    1. Run the display ipsec p2mp-policy command to check IPSec Key-Exchange information on the peer device.

    Check whether the DH group is changed.

  • Cause 4: The TNP is deleted.

    1. Run the display evpn site-tnp site-id command to check whether the TNP of the peer device is deleted.

    If yes, configure TNP information.

    If not, collect alarm and configuration information, and contact technical support personnel.

  • Cause 5: The TNP status changes to down.

    1. Run the display evpn site-tnp site-id verbose command to check whether the TNP on the local device is bound to an interface.

    If so, go to Step 3.

    If not, go to Step 2.

    2. Configure the source interface of the TNP.

    3. Check whether the protocol status of the physical interface bound to the TNP is Up.

    4. Check whether the shutdown command is run on the interface.

  • Cause 6: The TNP weight is changed.

    1. Run the display evpn site-tnp site-id verbose command to check whether the TNP weight is changed.

  • Cause 7: KA detection fails.

    1. Check whether the interfaces bound to the TNP can ping each other.

    If so, go to Step 3.

    If not, go to Step 2.

    2. Check whether the intermediate transmission network is faulty.

    3. Collect alarm and configuration information, and contact technical support personnel.

  • Cause 8: Reset by user.

    1. Check whether the reset BGP or reset evpn connection command is run on the local device.
