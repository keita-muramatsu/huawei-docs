L3VPN/2/TNL_EVENT

Message

L3VPN/2/TNL_EVENT: The tunnel up/down state or tunnel recursion state is changed. (VpnIndex=[VpnIndex], NextHop=[NextHop], Ckey=[Ckey], TrapType=[TrapType])

Description

The tunnel used by the VPN service goes up or down, or whether the VPN service can be recursed to a tunnel changes during tunnel switching.

Parameters

Parameter Name Parameter Meaning

VpnIndex

Index of a VPN instance.

The value is the same as the value of the VPN-Instance Name and ID field in the display ip vpn-instance verbose command output.

NextHop

Next-hop address on the public network.

Ckey

Ckey value, which can be used to obtain recursion tunnel information. The value is the same as the value of the IID field in the display ip vpn-instance tunnel-info command output.

TrapType

Alarm event type:

  • 0x0001: The tunnel used by the VPN service goes up, or the VPN service can be recursed to a tunnel during tunnel switching.
  • 0x0002: The tunnel used by the VPN service goes down.
  • 0x0003: The tunnel is no longer used by the VPN service.

Possible Causes

Cause 1: The tunnel used by VPN services went up or down.

Cause 2: During the switchover of VPN services to a tunnel, the result of tunnel iteration changed from success (a tunnel is iterated) to failure (a tunnel fails to be iterated); or the opposite.

Procedure

1. Run the display ip vpn-instance verbose vpn-instance-name command to check if the tnl-policy field exists.

  • If yes, go to Step 2.
  • If no, go to Step 4.

2. Run the display tunnel-policy tunnel-policy-name command to check the tunnel policy configuration.

  • In the case of a tunnel type prioritizing policy, run the display tunnel-info all verbose command to check whether a tunnel that meets the requirements exists.
  • If yes, go to Step 5.
  • If no, go to Step 3.
  • In the case of a tunnel binding policy, run the display interface tunnel command to check whether the tunnel interface defined in the policy is up.
  • If yes, go to Step 5.
  • If no, go to Step 6.

3. Configure LSPs according to the networking scenario or change the VPN tunnel policy. Then check whether the following log is generated: L3VPNBASE/2/TNL_EVENT: The tunnel up event is occurred.

  • If yes, go to Step 6.
  • If no, go to Step 5.

4. Check the LDP LSP configuration. Locate and rectify the fault according to LSP-related alarms. Then check whether the following log is generated: L3VPNBASE/2/TNL_EVENT: The tunnel up event is occurred.

  • If yes, go to Step 6.
  • If no, go to Step 5.

5. Collect log and configuration information, and contact technical support.

6. End.
