HRP/4/CORE_STATE

Message

HRP/4/CORE_STATE: The HRP core state changed due to [reason]. (old_state=[old-state], new_state=[new-state], local_fault_indicator=[local-fault-indicator], peer_fault_indicator=[peer-fault-indicator], local_robustness_indicator=[local-robustness-indicator], peer_robustness_indicator=[peer-robustness-indicator])

Description

The HRP status changes.

Parameters

Parameter Name Parameter Meaning

reason

Cause of the HRP status change. The options are as follows:

  • HRP is enabled
  • HRP is disabled
  • HRP hello packet negotiation succeeded
  • HRP hello packet negotiation failed
  • Local priority changed
  • Peer priority changed
  • Preferred role changed

old-state

Old HRP status. The values are as follows:

  • initial
  • active
  • standby
  • load sharing (primary)
  • load sharing (secondary)

new-state

Current HRP status. The values are as follows:

  • initial
  • active
  • standby
  • load sharing (primary)
  • load sharing (secondary)

local-fault-indicator

Local HRP fault coefficient.

peer-fault-indicator

Peer HRP fault coefficient.

local-robustness-indicator

Robustness variable of the local HRP.

peer-robustness-indicator

Robustness variable of the peer HRP.

Possible Causes

In a hot standby scenario, the priority of the local or peer device changes because the device meets the reason parameter.

Procedure

The troubleshooting method varies with the reason parameter.

  • If the value of reason is "HRP is enabled" or "HRP is disabled", check whether the command for enabling or disabling HRP has been executed.
  • If the reason parameter is set to other values, run the display hrp state verbose command on the device to check the status of the interface or link monitored by HRP. If any exception is found, troubleshoot the faulty interfaces or links. If the fault persists, contact technical support engineers.
