PKI/4/CERT_REPLACE_ERR

Message

PKI/4/CERT_REPLACE_ERR: Failed to replace certificate. (Type=[type],Realm=[realm],OldName=[old_name],NewName=[new_name],Reason=[reason])

Description

Failed to replace the certificate.

Parameters

Parameter Name Parameter Meaning

type

Certificate type.

realm

Domain name.

old_name

Name of the old certificate.

new_name

Name of the new certificate.

reason

Cause of the certificate replacement failure.

Possible Causes

Cause 1: An unknown error occurred. (Replacing failed because of unknown reason.)

Cause 2: The certificate name was invalid. (The cert name is invalid.)

Cause 3: The key pair name was invalid. (The key name is invalid.)

Cause 4: The certificate cannot be loaded from the file. (Failed to load cert from file.)

Cause 5: The number of certificates reached the upper limit. (The number of cert reaches the maximum.)

Cause 6: The certificate name already exists. (The same name cert already exists.)

Cause 7: A certificate with the same issuer and subject already exists. (The same issuer and subject cert already exists.)

Cause 8: An error occurred during the replacement. (Error occurred when replacing cert or key.)

Cause 9: Invalid parameter. (Param is invalid.)

Cause 10: The key pair in the file did not match the certificate. (The key in file doesn't match the cert in file.)

Cause 11: The number of key pairs reached the upper limit. (The number of key pairs reaches the maximum.)

Cause 12: The key pair name already exists. (The same name key already exists.)

Cause 13: Failed to load the key pair from the file. (Failed to load key from file.)

Cause 14: The local certificate in the file was not unique. (Exactly one cert is expected from the input file.)

Cause 15: The key pair to be replaced has been referenced by a PKI realm. (The key pair to be replaced is being used by PKI realm.)

Cause 16: The key pair to be replaced has been referenced by PKI cmp. (The key pair to be replaced is being used by PKI cmp session.)

Procedure

1. Contact technical support engineers.

2. Change the certificate file name and try again.

3. Change the certificate file name and try again. (The file name must have an extension.)

4. Check the certificate file and certificate validity period.

5. Delete the certificates on some devices and then replace the certificates.

6. Delete the certificate with the same name and then replace it, or change the certificate file name.

7. Delete the duplicate certificate and replace the original one.

8. Contact technical support engineers.

9. Check whether the northbound packet parameters are correct.

10. Check whether the key pair in the certificate file matches the certificate.

11. Delete some key pairs on the device and then replace them.

12. Delete the key pair with the same name and replace it, or change the certificate file name.

13. Check the key pair file.

14. Check the certificate file and delete unnecessary certificates from the file.

15. Delete the reference in the domain and then replace the original reference.

16. Delete the reference in cmp and replace the original one.

If the fault persists, collect alarm and configuration information, and contact technical support personnel.
