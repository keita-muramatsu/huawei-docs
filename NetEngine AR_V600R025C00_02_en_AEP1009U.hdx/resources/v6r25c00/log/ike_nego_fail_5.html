IKE/5/IKE_NEGO_FAIL

Message

IKE/5/IKE_NEGO_FAIL: Vsys [vsys-name]: IPSec tunnel negotiation fails. (IfIndex=[IfIndex], SeqNum=[SeqNum], PeerAddress=[PeerAddress], PeerPort=[PeerPort], Reason=[Reason])

Description

IPsec tunnel establishment failed.

Parameters

Parameter Name Parameter Meaning

vsys-name

The value is fixed to Public.

IfIndex

Index of the interface to which the IPsec policy is applied.

SeqNum

Sequence number of the IPsec policy.

PeerAddress

Remote IP address.

PeerPort

Remote port number.

Reason

Cause of the IPsec tunnel establishment failure.

Possible Causes

Common causes of IPsec tunnel establishment failures are as follows:

  • phase1 proposal mismatch: IKE proposal parameters on both ends do not match. Visible only to the tunnel initiator.
  • phase1 proposal encryption algorithm mismatch: The encryption algorithms in IKE proposals at both ends do not match. Visible only to the receive end of the tunnel.
  • phase1 proposal authentication method mismatch: The IKE proposal authentication methods at both ends do not match. Visible only to the receive end of the tunnel.
  • phase1 proposal authentication algorithm mismatch: The IKE proposal authentication algorithms at both ends do not match. Visible only to the receive end of the tunnel.
  • phase1 proposal dh mismatch: IKE proposal DH group parameters on both ends do not match. Visible only to the receive end of the tunnel.
  • phase1 proposal integrity algorithm mismatch: The integrity algorithm parameters of IKE proposals at both ends do not match. Visible only to the receive end of the tunnel.
  • phase1 proposal prf mismatch: IKE proposal PRF algorithm parameters on both ends do not match. Visible only to the receive end of the tunnel.
  • phase2 proposal or pfs mismatch: IPsec proposal parameters or PFS algorithms at both ends do not match.
  • responder dh mismatch: The DH algorithm of the responder does not match.
  • initiator dh mismatch: The DH algorithm of the initiator does not match.
  • encapsulation mode mismatch: The encapsulation mode does not match.
  • flow or peer mismatch: The security ACLs or IKE peer addresses on both ends do not match.
  • version mismatch: The IKE versions on both ends do not match.
  • peer address mismatch: The IKE peer addresses on both ends do not match.
  • config ID mismatch: No matching IKE peer is found based on the ID.
  • exchange mode mismatch: The negotiation modes on both ends do not match.
  • authentication fail: Identity authentication fails.
  • construct local ID fail: The local ID fails to be constructed.
  • rekey no find old sa: The old SA cannot be found during renegotiation.
  • rekey fail: The old SA is going offline during renegotiation.
  • first packet limited: The rate of the first packet is limited.
  • unsupported version: The IKE version is not supported.
  • malformed message: malformed message.
  • malformed payload: malformed payload.
  • malformed payload or psk mismatch: The payload is malformed or the pre-shared keys at both ends are inconsistent.
  • critical drop: unidentified critical payload.
  • cookie mismatch: The cookie does not match.
  • invalid cookie: invalid cookie.
  • invalid length: The packet length is invalid.
  • unknown exchange type: unknown negotiation mode.
  • uncritical drop: unidentified non-critical payload.
  • route limit: The number of injected routes reaches the upper limit.
  • ip assigned fail: IP address allocation fails.
  • eap authentication timeout: EAP authentication times out.
  • eap authentication fail: EAP authentication fails.
  • xauth authentication fail: XAUTH authentication fails.
  • xauth authentication timeout: XAUTH authentication times out.
  • license or specification limited: The license is restricted.
  • local address mismatch: The local IP address does not match the interface IP address during IKE negotiation.
  • dynamic peers number reaches limitation: The number of IKE peers reaches the upper limit.
  • ipsec tunnel number reaches limitation: The number of IPsec tunnels has reached the upper limit.
  • netmask mismatch: After IPsec mask filtering is enabled, masks do not match.
  • flow conflict: A data flow conflict occurs.
  • proposal mismatch or use sm in ikev2: IPsec proposals do not match or IKEv2 uses the SM algorithm.
  • ikev2 not support sm in ipsec proposal ikev2: IKEv2 does not support the SM algorithm of IPsec proposals.
  • no policy applied on interface: No policy is applied to the interface.
  • nat detection fail: NAT detection fails.
  • fragment packet limit: The number of fragmented packets exceeds the upper limit.
  • fragment packet reassemble timeout: Fragment reassembly times out.

Procedure

  • Cause: phase1 proposal xx mismatch

Check the IKE proposal parameters on both ends and run the corresponding command to change the parameters to be the same.

  • Cause: phase2 proposal or pfs mismatch

Check the IPsec proposal parameters or PFS algorithms on both ends and run the corresponding commands to change the inconsistent parameters to be the same.

  • Cause: responder dh mismatch, initiator dh mismatch

Check the DH algorithms on both ends and run the corresponding command to change the DH algorithms to be the same.

  • Cause: encapsulation mode mismatch

Check the encapsulation modes of the two ends and run the corresponding command to change the encapsulation modes to be the same.

  • Cause: eap authentication timeout, eap authentication fail, xauth authentication fail, xauth authentication timeout

Ensure that the user name and password of the client are correct and that the user access configuration is correct.

  • Cause: ip assigned fail

Ensure that AAA and IPsec configurations are correct, such as the IP pool, AAA service scheme, and IP address assigned to IKE users.

  • Cause: peer address mismatch

Check the IKE peer addresses on both ends and run the corresponding command to change the IKE peer addresses that do not match.

  • Cause: config ID mismatch

Check the identity authentication parameters, such as the ID type and ID value, and run the corresponding command to modify the parameters that do not match.

  • Cause: authentication fail

Check the IKE proposal parameters or IKE peer parameters on both ends, and run corresponding commands to change the parameters to be the same on both ends.

  • Cause: license or specification limited

Apply for a license or expand the capacity as required.

  • Cause: exchange mode mismatch

Check the IKEv1 phase 1 negotiation modes on both ends and run the corresponding command to change the negotiation modes to be the same.

  • Cause: route limit

Replace the device with a device with higher route injection specifications and properly plan the network.

  • Cause: local address mismatch

Check the local IP address and interface IP address during IKE negotiation, and run the corresponding command to change them to be the same.

  • Cause: IPsec tunnel number reaches limitation

Delete unnecessary IPsec tunnels or expand the device capacity.

  • Cause: dynamic peers number reaches limitation

Expand the device capacity and properly plan the network.

  • Cause: in disconnect state

Check whether the link or device is normal based on the IPsec link detection result.

  • Cause: proposal mismatch or use sm in ikev2, ikev2 not support sm in IPsec proposal

Check the algorithm used by IKEv2 in the IPsec proposal and run the corresponding command to correct the algorithm.

  • Cause: flow conflict

Check the ACL rules on both ends and run the corresponding command to correct the ACL rules.

  • Cause: netmask mismatch

Modify the range of IPsec data flows protected by the branch or headquarters to ensure that the data flows negotiated between the branch and headquarters do not overlap.

  • Cause: no policy applied on interface

Apply the corresponding IPsec policy to the interface.

  • Cause: fragment packet limit

The number of received fragmented packets exceeds the upper limit. Adjust the MTU of the peer device properly.

  • Cause: fragment packet reassemble timeout

Ensure that the link and device status at both ends are normal.

  • If the fault persists, collect related information and contact technical support personnel.
