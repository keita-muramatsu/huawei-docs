3-Tuple NAT

Definition

3-tuple NAT translates both source addresses and ports of packets, allowing multiple private addresses to be translated into the same public address. It also enables users on the Internet to proactively access private network users for P2P services such as file sharing, audio communication, and video transmission.

Implementation

When 5-tuple NAT (NAPT) is used for intranet PCs to access the Internet, extranet devices cannot proactively access intranet PCs through the post-NAT public IP addresses and ports.

3-tuple NAT can be used to resolve this problem due to its following characteristics:

  1. A post-NAT port number cannot be reused by different intranet PCs, ensuring their port consistency but resulting in low public address utilization.
  2. Extranet devices can proactively access intranet PCs through post-NAT IP addresses and ports, even in scenarios where security policies are not configured for such packets.

    When the endpoint-independent filtering function is enabled, the device searches for a destination server mapping entry matching the packet sent by an Internet user to communicate with an intranet user. If a match is found, the device translates the destination address of the packet based on the matching entry and forwards the packet, without matching the packet against any security policy. If this function is disabled, the device searches for a matching security policy and determines whether to forward or discard the packet accordingly. By default, the endpoint-independent filtering function is enabled.

Figure 1 3-tuple NAT process

When HostA on the intranet accesses HostB on the Internet, the 3-tuple NAT process on DeviceA is as follows:

  1. When receiving a packet from HostA, DeviceA discovers that the packet needs to travel from the Trust zone to the Untrust zone based on the destination IP address, so it searches for a matching security policy. If the security policy allows the packet to pass through, DeviceA searches for a matching NAT policy and discovers that the packet requires NAT translation.
  2. DeviceA replaces the source IP address of the packet with a public IP address (1.1.1.10 in this example) from the NAT address pool and the source port number with 2296, creates a session entry and server mapping entry accordingly, and sends the packet to HostB.
  3. When receiving a response packet from HostB, DeviceA searches the session table for the entry created in step 2, replaces the destination IP address of the packet with 192.168.1.2 (private IP address of HostA) and the port number with 6363 accordingly, and then forwards the packet to HostA.
  4. If DeviceA receives a request packet from HostC to access HostA before the server mapping entry created in step 2 ages, DeviceA can also perform address translation according to this entry and forward the packet to HostA correctly.

The server mapping table stores the mappings between the private and public IP addresses of hosts.

Forward server mapping entries ensure that the post-NAT addresses and ports of intranet PCs remain unchanged. Return server mapping entries allow extranet devices to proactively access intranet PCs.

Classification

3-tuple NAT includes local and global 3-tuple NAT.

In local 3-tuple NAT mode, the server mapping table contains the security zone parameter, and only hosts in this security zone can access intranet hosts. As shown in Figure 1, if HostB and HostC are in different security zones and a 3-tuple NAT relationship has been created between HostA and HostB, HostC cannot access HostA through the created server mapping entry.

In global 3-tuple NAT mode, the server mapping table does not contain the security zone parameter, and hosts in all security zones can access intranet hosts. As shown in Figure 1, if HostB and HostC are in different security zones and a 3-tuple NAT relationship has been created between HostA and HostB, HostC can access HostA through the created server mapping entry.

The device supports smart 3-tuple NAT and determines the port allocation mode based on destination ports of packets, allowing some public IP addresses to be reused. If the destination port number of a packet is in the configured port range, NAPT is used for port allocation and address translation; otherwise, 3-tuple NAT is used.
