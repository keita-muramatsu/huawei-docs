Failed to Log In to the SSH Server Using STelnet

Fault Description

A user fails to log in to the SSH server using STelnet.

Procedure

  1. Log in to the SSH server through the console port or Telnet. Enter the system view.

    system-view

  2. Check STelnet server parameters.

    1. Check whether the source interface and listening port number of the STelnet server are correct, and whether the STelnet function is enabled.
      display current-configuration configuration ssh include-default

      If the source interface and listening port are correct and the STelnet function is enabled, go to step 3.

      If the source interface and listening port are incorrect or the STelnet function is disabled, go to step b.

    2. Enable the STelnet server function and configure the source interface and port number.

      # Enable the STelnet server function.

      stelnet [ ipv4 | ipv6 ] server enable
      # Configure the port number of the STelnet server.
      ssh [ ipv4 | ipv6 ] server port port-number
      # Configure the source interface of the STelnet server.
      ssh server-source -i interface-type interface-number
ssh server-source -a ip-address [ -vpn-instance vpnName ]
ssh ipv6 server-source -a ipv6-address [ -vpn-instance vpn-instance-name ]
ssh server-source all-interface
ssh ipv6 server-source all-interface

  3. Check whether the SSH service is enabled on the SSH server.

    1. Check the configuration of the SSH server.
      display ssh server status
      • If STelnet is not enabled, go to step b.
      • If STelnet is enabled, go to step 4.
    2. Enable the STelnet service on the SSH server.
      stelnet server enable

  4. Check the protocol configuration in the VTY user interface view of the SSH server.

    1. Check whether the protocol supported by the VTY user interface is SSH or all.
      user-interface vty first-ui-number [ last-ui-number ]
display this
      • If not, go to step b.
      • If so, go to step 5.
    2. Set the protocol supported by the user interface to SSH.
      protocol inbound { ssh | all }
quit

  5. Check whether an SSH user is configured on the SSH server.

    1. Check the configuration of the SSH user.
      display ssh user-information
      • If no configuration information exists, go to step b.
      • If configuration information exists, go to step 6.
    2. Create an SSH user, and configure the authentication mode and service type for the SSH user.
      ssh user user-name   //Create an SSH user.
ssh user user-name authentication-type { password | rsa | password-rsa | all | dsa | password-dsa | ecc | password-ecc | sm2 | password-sm2 | password-x509v3-rsa | x509v3-rsa | password-x509v3-ecdsa-sha2 | x509v3-ecdsa-sha2 | sm2-sm3 | password-sm2-sm3 } // Configure the authentication mode for the SSH user.
ssh user user-name service-type { all |  stelnet }  //Configure the service type for the SSH user.

  6. Check whether the number of users who are logged in to the SSH server has reached the upper limit.

    1. Check whether all VTY channels are occupied.
      display users
      • If all VTY channels are occupied, go to step b.
      • If not all VTY channels are occupied, go to step 7.
    2. Check the maximum number of users allowed by the current VTY channel.
      display user-interface maximum-vty
      • If the configured maximum number of VTY user interfaces does not reach 21, go to step c.
      • If the configured maximum number of VTY user interfaces reaches 21, go to step 7.
    3. Set the maximum number of users allowed by the VTY channel to 21.
      user-interface maximum-vty 21

  7. Check whether an ACL is bound to the VTY user interface of the SSH server.

    1. Check whether an ACL is configured on the VTY user interface.
      user-interface vty first-ui-number [ last-ui-number ]
display this
quit
      • If an ACL is configured, record the ACL number and go to step b.
      • If no ACL is configured, go to step 8.
    2. Check whether ACL denies the IP address of the STelnet client.
      display acl acl-number
      • If so, go to step c.
      • If not, go to step 8.
    3. Delete the deny rule.
      undo rule rule-id
    4. Modify the ACL to allow access from the IP address of the client.
      rule permit source source-ip-address source-wildcard

  8. Check whether the SSH version on the SSH server matches that on the SSH client.

    display ssh server status

    Only SSH2.0 is supported. Ensure that the SSH version on the SSH client is the same as that on the SSH server.

  9. Check whether the first login function is enabled for the SSH client.

    If the first login function is not enabled on an SSH client, the first login from the STelnet client to the SSH server fails because validity check on the RSA public key of the SSH server fails.

    1. Check whether the first login function is enabled for the SSH client.
      display this
    2. Enable first login for the SSH client.
      ssh client first-time enable
