Configuring the IKE SA Lifetime

Prerequisites

The IKE SA lifetime takes effect only for the following IPsec types:

  • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
  • Route-based IPsec (involving IPsec profiles)

Context

You can configure the IKE SA lifetime to update IKE SAs in real time, reducing the risk of cracking IKE SAs and improving security.

The configured IKE SA lifetime applies only to new IKE SAs. Before an IKE SA is about to expire, IKE negotiates a new IKE SA for the remote end. The remote end uses the new IKE SA to protect IPsec communication immediately after the new IKE SA has been negotiated. The original IKE SA is cleared after 10s or the hard lifetime expires.

The IKE SA lifetime is classified into hard lifetime and soft lifetime.

  • Hard lifetime (hard timeout period): indicates the lifetime of an IKE SA. When two devices negotiate an IKE SA, the actual IKE SA hard lifetime is the smaller of the two hard lifetime values configured on the two devices.
  • Soft lifetime (soft timeout period): indicates the time after which a new IKE SA is negotiated to replace the existing IKE SA before the hard lifetime of the existing IKE SA is about to expire.

Procedure

  • Set the IKE SA hard lifetime.
    1. Enter the system view.

      system-view

    2. Enter the IKE proposal view.

      ike proposal { proposal-number | default }

    3. Set the IKE SA hard lifetime.

      sa duration seconds

      For the default settings, see Table 4.

      If the hard lifetime of an IKE SA expires, the IKE SA will be updated automatically. IKE negotiation involves Diffie-Hellman (DH) calculation, which takes a long period of time. To ensure that IKE SA update does not affect secure communication, you are advised to set the IKE SA lifetime to a value greater than 600s.

  • Set the IKE SA soft lifetime.
    1. Enter the system view.

      system-view

    2. Enter the IKE peer view.

      ike peer peer-name

    3. Set the IKE SA soft timeout buffer time.

      sa soft-duration time-based buffer seconds

      By default, no IKE SA soft timeout buffer time is configured.

      If the value that equals the IKE SA hard lifetime minus the configured IKE SA soft timeout buffer time is larger than 10s, this value is used as the actual IKE SA soft lifetime. Otherwise, the default IKE SA soft lifetime is used.

    4. Optional: Enable the local device to send IKE SA lifetime notification messages to the peer end.

      lifetime-notification-message enable

      By default, the device does not send IKE SA lifetime notification messages.

      IKEv1 peers negotiate the lifetime, and a smaller SA lifetime at the two ends is used. When a Huawei device and a non-Huawei device establish an IPsec tunnel and they use different IKE SA lifetimes, run this command to enable the local device to send IKE SA lifetime notification messages to the peer end. By doing this, two ends can successfully perform IKE negotiation.
