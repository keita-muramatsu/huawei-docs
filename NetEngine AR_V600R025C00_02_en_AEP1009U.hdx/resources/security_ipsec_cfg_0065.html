Configuring the Maximum Number of Half-Open Connections Allowed by IKEv2

Prerequisites

  • The maximum number of half-open connections allowed by IKEv2 takes effect only for IKEv2 negotiation.
  • The maximum number of half-open connections allowed by IKEv2 takes effect only for the following IPsec types:
    • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
    • Route-based IPsec (involving IPsec profiles)

Context

IKEv2 initial exchange messages are transmitted in clear text. If an attacker forges mass IKE_INIT_SA requests, the resources of the responder will be exhausted, causing DoS attacks on the responder.

Cookie exchange is defined in IKEv2 to defend against such attacks. That is, after receiving the first message from the initiator, the responder replies an unprotected Notify payload. In subsequent communication, the responder accepts only the IKE negotiation initiated by the initiator that sends a Notify payload containing a cookie. By setting the maximum number of half-open connections allowed by IKEv2, you can enable the preceding attack defense mechanism when the number of half-open IKEv2 connections exceeds the maximum value.

Procedure

  1. Enter the system view.

    system-view

  2. Set the maximum number of half-open connections allowed by IKEv2.

    ikev2 cookie-challenge number

    By default, the maximum number of half-open connections allowed by IKEv2 is 25,000.
