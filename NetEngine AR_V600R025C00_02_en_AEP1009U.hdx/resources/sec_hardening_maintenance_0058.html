CPU Attack Defense

Overview

CPU attack defense limits the rate of packets sent to the CPU so that only a limited number of packets are sent to the CPU within a certain period of time. This ensures that the CPU can properly process services.

Control Plane Committed Access Rate (CPCAR) is the core of CPU attack defense. CPCAR limits the rate at which protocol packets are sent to the management and control planes to protect the two planes.

You can reduce the CPCAR value or set the CPCAR to deny to prevent the packets that do not need to be processed or have low priorities from being sent to the CPU, ensuring normal system operation.

Impact on the System

To prevent an improper CPCAR value from affecting services, set a proper CPCAR value as required.

Procedure

  1. Enter the system view.

    system-view

  2. Create an attack defense policy and enter the attack defense policy view.

    cpu-defend policy policy-name

  3. Configure the method used to limit the packets to be sent to the CPU.

    • Set a CPCAR value for protocol packets of a specified type. 
      car packet-type packet-type pps pps-value
    • Set a CPCAR value for all packets to be sent to the CPU.
      car all-packets pps pps-value
    • Configure rate limiting based on protocol association.
      1. Enable protocol association.
        application-apperceive packet-type enable
      2. Set a CPCAR value for packets of a specific protocol upon the establishment of the protocol connection.
        linkup-car packet-type packet-type pps pps-value
      3. Configure the penalty ratio threshold for protocol association.
        linkup session anti-attack ratio-threshold rate-value-percent

        By default, the threshold is 50%.

      4. (Optional) Enable the session CAR function for rate limiting by session.
        session-car packet-type enable

        By default, session CAR is disabled.

        The session CAR function relies on the protocol association function, so you must run the application-apperceive enable command to enable protocol association first. Otherwise, session CAR cannot be enabled.

      5. (Optional) Configure the CIR and PIR for protocol packets of each session upon the establishment of the protocol connection.
        session-car packet-type cir cir-value [ pir pir-value ]

        It is recommended that the PIR (specified by pir) for the session CAR function do not exceed the CPCAR value (specified by pps) for protocol association in Step b.

  4. (Optional) Configure the device to discard packets to be sent to the CPU. 

    deny packet-type packet-type

    By default, the device does not discard the packets to be sent to the CPU.

  5. Return to the system view.

    quit

  6. Apply the attack defense policy.

    • Configure attack defense policies in batches.
      cpu-defend-policy policy-name batch slot { start-slot [ to end-slot ] } &<1-12>

      You cannot batch configure attack defense policies on the AR8700 series and AR6700-H.

    • Configure an attack defense policy separately.

      For the AR5700, AR6700-L, and AR8100 series:

      cpu-defend-policy policy-name [ slot slot-id ]

      For the AR8700 series and AR6700-H:

      cpu-defend-policy policy-name [ mcu ]

    After an attack defense policy is created, you must apply the policy in the system view. Otherwise, the policy does not take effect.

Verifying the Security Hardening Result

  • Run the display cpu-defend policy [ policy-name ] command to check the attack defense policy configuration.
  • Run the display cpu-defend configuration [ packet-type packet-type ] { all | slot slot-id } command to check the rate configuration for protocol packets sent to the CPU.
  • Run the display cpu-defend rate [ packet-type packet-type ] { all | slot slot-id } command to check the CPCAR value configured for protocol packets.
  • Run the display cpu-defend statistics [ packet-type packet-type ] { all | slot slot-id } command to check statistics on the packets sent to the CPU.
