HDLC Fundamentals

HDLC can transparently transmit any type of bit stream, not requiring data to be character sets. This sets HDLC apart from other data link layer protocols.

Data link control protocols focus on the logical transmission of data that is segmented into physical blocks or packages. These blocks or packages are also called frames, each of which is identified by a start flag and an end flag. HDLC transmits data and control information in a unified frame format. Each frame starts and ends with a special delimiter (01111110) that signals the start and end of the frame, as well as frame synchronization. To prevent confusion, the frame delimiter cannot appear inside the frame.

To make the frame delimiter unique and keep data in a frame transparent, the zero-bit insertion function can be used. With this function, the transmit end monitors all fields except the frame delimiter. When detecting five consecutive 1s, it adds a 0 and keeps sending subsequent bits. The receive end also monitors all fields except the frame delimiter. When five consecutive 1s are detected and the following bit is 0, the receive end automatically deletes the 0 to restore the former bit stream. However, when five consecutive 1s are detected but the following bit is also 1, the receive end determines that a 0 is incorrectly inserted or an end delimiter is received based on the frame check sequence field. A further action can then be taken accordingly.

HDLC Operation Modes

On a network using HDLC, nodes are classified as primary, secondary, or combined nodes.

The primary node organizes data flows and fixes data errors. The secondary node receives information from the primary node and sends back acknowledgment information. Frames transferred by the primary node to a secondary node are called commands, and frames transferred by a secondary node to the primary node are called responses. A combined node provides the functions of both a primary node and a secondary node.

On a point-to-multipoint (P2MP) link, there is a primary node and several secondary nodes. The primary node polls the secondary nodes to determine whether they have data to transmit, and then chooses one to transmit its data to. On a point-to-point (P2P) link, the nodes at both ends can be primary nodes. If a node is connected to multiple links, the node can be the primary node for some links and a secondary node for other links.

HDLC can run in the following modes:

  • NRM

    Normal response mode (NRM): an unbalanced data link operation mode, also called unbalanced normal response mode.

    NRM is generally used on terminal-oriented P2P links and P2MP links.

    In NRM, a primary node initiates a transmission process, and a secondary node will respond only after receiving a command from the primary node.

    The response information consists of one or more frames. If multiple frames are carried, the secondary node must mark the final frame.

    The primary node is responsible for managing the entire link, including polling, choosing a secondary node, sending commands to the secondary node, and controlling timeout, retransmission, and error recovery.

  • ARM

    Asynchronous response mode (ARM): an unbalanced data link operation mode.

    In contrast to NRM, ARM allows a secondary node to independently send frames to the primary node, without needing commands from the primary node.

    In this mode, the secondary node controls timeout and retransmission.

    This mode is essential for multi-node links that utilize polling.

  • ABM

    Asynchronous balanced mode (ABM): an operation mode that allows any node to initiate a transmission process.

    In ABM operation mode, all nodes are combined nodes. All nodes can transmit information, send and receive commands, send responses, and correct errors without requiring permission from other nodes. This enhances the efficiency of link transmission.

HDLC Frame Format

HDLC transmits both data and control information in frames using a standardized format.

HDLC frames resemble BSC character blocks but are not transmitted as independent entities.

HDLC Frame Types

The Control field in an HDLC frame determines the type of the frame.

The HDLC frame types are as follows:

  • Information frame (I-frame): used to transmit valid data. An I-frame contains a receive sequence number N(R) and a sequence number of the sent frame N(S) in the Control field.
  • Supervisory frame (S-frame): used for flow and error control. An S-frame contains only N(R) in the Control field. S-frames do not have the Information field.
  • Unnumbered frames (U-frames): used to set up, tear down, and control links. A U-frame does not contain N(R) or N(S) in the Control field.

HDLC Flapping Dampening

If the physical status of a network's underlying layer is unstable, HDLC interfaces may frequently engage in negotiation, leading to HDLC link flapping. This may further cause repeated flapping of other protocols such as routing protocols and Multiprotocol Label Switching (MPLS). Consequently, the network and devices will be significantly impacted, in some cases crashing completely.

To prevent the preceding issues, HDLC flapping dampening can be implemented. This feature limits the frequency of HDLC protocol status changes on an interface. By doing so, it reduces the negative effects of flapping on the network and devices.

HDLC flapping dampening encompasses the following concepts:

  • Penalty value: This value is calculated by a suppression algorithm that takes into account the HDLC protocol status of an interface. The penalty value increases linearly and decreases exponentially as the frequency of interface status changes.
  • Suppress threshold: When the penalty value exceeds the suppress threshold, HDLC negotiation is suppressed. In this case, the HDLC protocol status is down.
  • Reuse threshold: When the penalty value drops below the reuse threshold, the HDLC protocol status of an interface is no longer suppressed, and negotiation starts.
  • Ceiling threshold: When the penalty value reaches the ceiling threshold, it stops increasing. This prevents HDLC negotiation failures from occurring due to prolonged suppression. The ceiling threshold can be calculated using the following formula: Ceiling threshold = Reuse threshold x 2(Maximum suppress time/Half-life period).
  • Half-life period: the time it takes for the penalty value to decrease by half. A half-life period starts to be calculated when the HDLC protocol status changes to down for the first time. When the half-life period elapses, the penalty value decreases by half, and another half-life period starts.
  • Maximum suppress time: the maximum period during which the HDLC protocol status of an interface is suppressed. After the maximum suppress time elapses, the HDLC protocol status of the interface is renegotiated, and the new status is reported.
