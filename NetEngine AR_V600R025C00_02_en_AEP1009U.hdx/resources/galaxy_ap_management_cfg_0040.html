Configuring AP Patch Loading

Context

Similar to the in-service AP upgrade, in-service patch loading allows you to load the patch to a single AP, APs of a specified type, or APs in a specified AP group.

For an AR with the built-in AP, the built-in AP patch is released independently. To install the patch for a built-in AP, perform this configuration.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Configure in-service patch loading.

    The AP ID of the built-in AP is fixed to 0. In factory settings, the built-in AP is added to the AP group built_in_ap by default.

    • Perform in-service patch loading for a single AP.
      ap-patch update load { ap-mac ap-mac | ap-id ap-id } update-filename update-file-name [ next-startup ]
    • Load the patch for APs of the same AP type.
      1. Configure a patch file for APs of a specified type.
        ap-patch update update-filename filename ap-type type-id [ ap-group ap-group-name ]

        By default, no patch file is specified.

      2. Load the patch for APs of the same type in batches.
        ap-patch update multi-load ap-type type-id [ ap-group group-name | { ap-id ap-id } &<1-10> ] [ next-startup ]
    • Load the patch for APs in the same AP group.
      1. Configure a patch file for APs in a specified AP group.
        ap-patch update update-filename filename ap-type type-id [ ap-group ap-group-name ]

        By default, no patch file is specified.

      2. Load the patch to APs in the same group in batches.
        ap-patch update multi-load ap-group group-name [ { ap-id ap-id } &<1-10> ] [ next-startup ]

    To cancel a patch upgrade, run the undo command of the preceding commands.

    To uninstall a patch, run the ap-patch delete [ next-startup ] { ap-type type-id [ ap-group group-name ] | ap-group group-name | ap-id ap-id-value } command.
