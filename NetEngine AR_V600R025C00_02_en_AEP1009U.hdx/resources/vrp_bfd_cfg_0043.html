Understanding BFD for Perlink

BFD for Perlink is used to detect inter-board Eth-Trunk member link faults in a VLAN. Two devices are directly connected through Eth-Trunk interfaces that are added to the same VLAN, and a VLANIF interface is created for the VLAN on each device. If a single-hop BFD for IP session is bound to the VLANIF interface to detect Eth-Trunk link faults, BFD selects one of the Eth-Trunk member links as the detection path and monitors this member link only. Once BFD detects that the selected member link is down, it assumes that the Eth-Trunk link is down even if the other Eth-Trunk member links are up.

To resolve this problem, configure a BFD for Perlink session to monitor Eth-Trunk member links. After a BFD for Perlink session is bound to a VLANIF interface, BFD creates a dynamic unicast BFD sub-session for each Eth-Trunk member interface as well as a management session. The BFD sub-sessions perform negotiation and detection independently and report their statuses to the management session, which does not perform negotiation or detection and instead only manages the reported sub-session status. The management session goes down only when all sub-sessions are down.

Currently, BFD sub-sessions can be configured to detect link faults in one-arm BFD Echo mode. The following describes how BFD for Perlink works on the network shown in Figure 1.

Figure 1 Network diagram of BFD for Perlink
RB1 is connected to RB2 through Device1. GW1 and RB1 as well as GW2 and RB2 are directly connected through Eth-Trunk interfaces. The Eth-Trunk interfaces on GW1 and GW2 are added to the same VLAN, and a VLANIF interface is created for that VLAN. BFD is deployed to detect faults on the link between GW1 and GW2. After a BFD for Perlink session is configured on GW1, the following occurs:
  1. GW1 creates a BFD sub-session for each Eth-Trunk member interface, and these sub-sessions send BFD Echo packets. Each BFD Echo packet carries the IP address of the local VLANIF interface as the destination IP address, GW2's MAC address as the destination MAC address, and dynamically created local and remote discriminators. In addition, each BFD Echo packet is sent out through a specified member interface.
  2. After receiving a BFD Echo packet, RB1 forwards it through Device1.
  3. Upon receipt, RB2 uses a hash algorithm to select a member link to forward the BFD Echo packet.
  4. After receiving the BFD Echo packet, GW2 finds that the destination IP address of the packet is the IP address of the VLANIF interface on GW1, and immediately loops back the packet on the forwarding plane.
  5. Upon receipt, RB2 forwards the packet through Device1.
  6. When the BFD Echo packet arrives at RB1, RB1 also uses a hash algorithm to select an Eth-Trunk member link and forwards the packet to GW1.

If Eth-Trunk member link 1 between GW1 and RB1 fails, sub-session 1 of the BFD for Perlink session goes down. However, as sub-session 2 remains up, the management session is also up, preventing BFD from incorrectly reporting link faults.
