Example for Using URL Categories to Control Website Access

Networking Requirements

On the network shown in Figure 1, DeviceA is deployed as a gateway at the border of an enterprise network. This device is used to implement URL filtering on users' requests for Internet access.

The enterprise has the following network access requirements for R&D and marketing employees:

  • R&D employees can access only education/science and search engine/portal websites from 09:00 to 17:00, and cannot access other websites.
  • Marketing employees can access only education/science, search engine/portal, and social issues websites from 09:00 to 17:00, and cannot access other websites.
Figure 1 Network diagram for using URL categories to control website access

In this example, interface 1 and interface 2 represent 10GE0/0/1, and 10GE0/0/2, respectively.


Configuration Roadmap

  1. Configure an IP address for each interface and add interfaces to security zones.
  2. Configure a security policy to block encrypted DNS traffic and ensure that the browser uses non-encrypted DNS to perform the DNS query.

    When employees use browsers to access web pages, secure DNS may be enabled by default on some browsers. By default, URL filtering is not performed on encrypted DNS traffic. Therefore, you need to configure a security policy to block encrypted DNS traffic. After the encrypted DNS traffic is blocked, the browser attempts to use non-encrypted DNS to perform the DNS query again. In this process, users can access the Internet properly.

  3. Configure the remote query server to obtain the mappings between URLs and predefined URL categories. In this example, education/science, search engine/portal, and social issues websites are predefined URL categories, based on which the device filters URLs. To use the remote query function, perform the following operations:
    1. Activate the remote URL query license and ensure that the license is within the validity period.
    2. Configure a DNS server to ensure that DeviceA can correctly parse sec.huawei.com.
    3. Set the parameters for the remote query server, including the query mode, country name, and timeout interval.
    4. Configure a security policy to allow DeviceA to access the scheduling center sec.huawei.com.
  4. Configure two URL filtering profiles — profile_url_research and profile_url_marketing — for the R&D and marketing departments, respectively. Specify control actions for predefined URL categories.

  5. Configure a time range.

  6. Configure two security policies, and reference the corresponding time range and URL filtering profile in each security policy to control URL access from employees in different departments.

Procedure

  1. Configure an IP address for each interface and add interfaces to security zones.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ip address 1.1.1.1 24
[DeviceA-10GE0/0/1] quit
[DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] ip address 10.1.1.1 255.255.255.0
[DeviceA-10GE0/0/2] ip address 10.1.2.1 255.255.255.0 sub
[DeviceA-10GE0/0/2] quit
[DeviceA] firewall zone untrust
[DeviceA-zone-untrust] add interface 10ge 0/0/1
[DeviceA-zone-untrust] quit
[DeviceA] firewall zone trust
[DeviceA-zone-trust] add interface 10ge 0/0/2
[DeviceA-zone-trust] quit

  2. Configure a security policy to block encrypted DNS traffic and ensure that the user browser uses non-encrypted DNS to perform the DNS query. By default, URL filtering is not performed on encrypted DNS traffic.

    # Block traffic of encryption protocols, including QUIC (service: UDP; destination port number: 443), HTTPS (service: TCP; destination port number: 443), and DNS_over_TLS (service: TCP; destination port number: 853), and IP addresses of well-known DNS servers (1.0.0.3, 1.1.1.3, 8.8.4.4, and 8.8.8.8).

    [DeviceA] security-policy
[DeviceA-policy-security] rule name policy_deny_dot
[DeviceA-policy-security-rule-policy_deny_dot] destination-address 1.0.0.3 mask 255.255.255.255
[DeviceA-policy-security-rule-policy_deny_dot] destination-address 1.1.1.3 mask 255.255.255.255
[DeviceA-policy-security-rule-policy_deny_dot] destination-address 8.8.4.4 mask 255.255.255.255
[DeviceA-policy-security-rule-policy_deny_dot] destination-address 8.8.8.8 mask 255.255.255.255
[DeviceA-policy-security-rule-policy_deny_dot] service protocol tcp source-port 0 to 65535 destination-port 443
[DeviceA-policy-security-rule-policy_deny_dot] service protocol tcp source-port 0 to 65535 destination-port 853
[DeviceA-policy-security-rule-policy_deny_dot] service protocol udp source-port 0 to 65535 destination-port 443
[DeviceA-policy-security-rule-policy_deny_dot] action deny
[DeviceA-policy-security-rule-policy_deny_dot] quit
    # Block traffic of encrypted DNS applications, including DNS_ECH and DNS_Over_HTTPS.
    [DeviceA-policy-security] rule name policy_deny_ech
[DeviceA-policy-security-rule-policy_deny_ech] application app DNS_ECH
[DeviceA-policy-security-rule-policy_deny_ech] application app DNS_Over_HTTPS
[DeviceA-policy-security-rule-policy_deny_ech] action deny
[DeviceA-policy-security-rule-policy_deny_ech] quit
[DeviceA-policy-security] quit

  3. Configure the remote query server to obtain the mappings between URLs and predefined URL categories.
    1. Activate the remote URL query license and ensure that the license is within the validity period.
    2. Configure a DNS server.

      [DeviceA] dns resolve
[DeviceA] dns server 10.2.0.70

    3. Set the parameters of the remote query server, including the country name, timeout interval, and timeout action.

      [DeviceA] country CN
[DeviceA] url-filter query timeout time 3 action allow

    4. Configure a security policy to allow DeviceA to access the scheduling center.

      [DeviceA] security-policy
[DeviceA-policy-security] rule name policy_sec_huawei_com
[DeviceA-policy-security-rule-policy_sec_huawei_com] source-zone local
[DeviceA-policy-security-rule-policy_sec_huawei_com] destination-zone untrust
[DeviceA-policy-security-rule-policy_sec_huawei_com] action permit
[DeviceA-policy-security-rule-policy_sec_huawei_com] quit
[DeviceA-policy-security] quit

  4. Configure URL filtering profiles.

    You can run the display url-filter category pre-defined command to query the mappings between the following predefined categories and IDs:

    • 17: Education/Science
    • 15: Search Engines/Portals
    • 5: Social Focus (social issues)

    1. Configure a URL filtering profile for the R&D department.

      [DeviceA] profile type url-filter name profile_url_research 
[DeviceA-profile-url-filter-profile_url_research] category pre-defined action block
[DeviceA-profile-url-filter-profile_url_research] category pre-defined category-id 15 action allow
[DeviceA-profile-url-filter-profile_url_research] category pre-defined category-id 17 action allow
[DeviceA-profile-url-filter-profile_url_research] https-filter enable
[DeviceA-profile-url-filter-profile_url_research] quit

    2. Configure a URL filtering profile for the marketing department.

      [DeviceA] profile type url-filter name profile_url_marketing 
[DeviceA-profile-url-filter-profile_url_marketing] category pre-defined action block
[DeviceA-profile-url-filter-profile_url_marketing] category pre-defined category-id 5 action allow
[DeviceA-profile-url-filter-profile_url_marketing] category pre-defined category-id 15 action allow
[DeviceA-profile-url-filter-profile_url_marketing] category pre-defined category-id 17 action allow
[DeviceA-profile-url-filter-profile_url_marketing] https-filter enable
[DeviceA-profile-url-filter-profile_url_marketing] quit

  5. Configure a time range.

    [DeviceA] time-range time_range 09:00 to 17:00 daily

  6. Reference URL filtering profiles in security policies.
    1. Configure a security policy for the R&D department.

      [DeviceA] security-policy
[DeviceA-policy-security] rule name policy_sec_research
[DeviceA-policy-security-rule-policy_sec_research] description Security policy of web access protect for research.
[DeviceA-policy-security-rule-policy_sec_research] source-zone trust
[DeviceA-policy-security-rule-policy_sec_research] destination-zone untrust
[DeviceA-policy-security-rule-policy_sec_research] source-address 10.1.2.0 mask 255.255.255.0
[DeviceA-policy-security-rule-policy_sec_research] time-range time_range
[DeviceA-policy-security-rule-policy_sec_research] action permit
[DeviceA-policy-security-rule-policy_sec_research] profile url-filter profile_url_research
[DeviceA-policy-security-rule-policy_sec_research] quit

    2. Configure a security policy for the marketing department.

      [DeviceA-policy-security] rule name policy_sec_marketing
[DeviceA-policy-security-rule-policy_sec_marketing] description Security policy of web access protect for marketing.
[DeviceA-policy-security-rule-policy_sec_marketing] source-zone trust
[DeviceA-policy-security-rule-policy_sec_marketing] destination-zone untrust
[DeviceA-policy-security-rule-policy_sec_marketing] source-address 10.1.1.0 mask 255.255.255.0
[DeviceA-policy-security-rule-policy_sec_marketing] time-range time_range
[DeviceA-policy-security-rule-policy_sec_marketing] action permit
[DeviceA-policy-security-rule-policy_sec_marketing] profile url-filter profile_url_marketing
[DeviceA-policy-security-rule-policy_sec_marketing] quit
[DeviceA-policy-security] quit

  7. Commit the content security profiles.

    [DeviceA] engine configuration commit
Info: The operation may last several minutes, please wait. Try "display engine information" for detail. 
[DeviceA] 
Info: URL submitted configurations successfully.  
Info: Engine configuration is compiled successfully.

Verifying the Configuration

  • All R&D employees can access only websites that belong to the education/science and search engine/portal categories from 09:00 to 17:00, but they cannot access other websites including websites that belong to the social focus category.

    If an R&D employee attempts to access other websites (including those belonging to the Social Focus category), the device generates a URL log (URL/4/FILTER), in which Type (indicates the filtering type) is Pre-defined and Action is Block.

  • All marketing employees can access only websites that belong to the Education/Science, Search Engines/Portals, and Social Focus categories from 09:00 to 17:00, but they cannot access other websites.

    If a marketing employee attempts to access other websites, the device generates a URL log (URL/4/FILTER), in which Type (indicates the filtering type) is Pre-defined and Action is Block.
