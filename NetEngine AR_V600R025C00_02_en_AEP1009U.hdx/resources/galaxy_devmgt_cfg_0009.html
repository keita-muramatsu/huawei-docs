Pre-Configuring Boards Not in Position

Context

When the device needs to have new components installed or its capacity expanded but the target physical components are not available, you can create logical boards and deploy service configurations in advance. In this way, the service configurations can be automatically activated as soon as the target physical components are installed properly. If a physical component is removed, the service configurations of the component are automatically deactivated and displayed as offline configurations, which you can modify.

Pre-configuration allows you to create logical components and configure services for them before the corresponding physical components are installed properly on a device. If a physical component is installed incorrectly or in the wrong position, the pre-configured services will be retained and activated only when the physical component is correctly installed.

A logical component, such as a logical board or subcard, is created and pre-configured with services before the corresponding physical component is available. In contrast, a physical component refers to the hardware component that actually runs on a device.

Pre-configuring services brings the following benefits:
  • Service planning: You can plan services to be configured in idle slots so that the pre-configured services will be automatically activated as soon as the target boards are installed in these slots.
  • Service pre-deployment: To expand a device's capacity, you can deploy service configurations on the device in advance when the target hardware is not available. In this way, the pre-deployed services will be activated as soon as the corresponding hardware is properly installed. This helps improve capacity expansion efficiency and reduce the risk of errors during service configuration.
  • Mis-insertion prevention: If a physical component is installed incorrectly or in the wrong position, the pre-configured services will be retained and activated only when the physical component is correctly installed.

Currently, the device supports board pre-configuration.

  • The type of logical boards to be created must be supported by devices.

  • Only one logical board can be pre-configured in a slot. To replace an existing logical board, before performing the following steps to create a logical board, first run the undo device board command to delete the logical board or run the clear inactive-configuration command to clear offline configurations.

Procedure

  1. Enter the system view.

    system-view

  2. Create a logical board of a specified type in a specified slot.

    device board slot-id board-type type

Verifying the Configuration

After pre-configuring services, verify the configurations.
  • Run the display device all command to check whether the information about physical boards and the corresponding logical boards is the same. If there are differences, identify the corresponding boards. Logical boards will be marked by an asterisk (*).
  • Run the display current-configuration [ all ] command to check the configurations of all boards, including online and logical boards.
