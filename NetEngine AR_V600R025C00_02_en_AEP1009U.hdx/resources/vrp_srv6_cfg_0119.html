(Optional) Configuring the Delete-Hold Function for SRv6 TE Policies

Configuring the Delete-Hold function for SRv6 TE Policies improves SRv6 reliability.

Context

In a scenario where the controller updates the segment list of an SRv6 TE Policy, if the involved device checks the validity of the new path before performing a path switchover, SRv6 reliability can be improved.

The Delete-Hold function enables the device to check the status of the new segment list before an existing segment list is deleted from the same candidate path. If the new segment list is Down, the segment list to be deleted is still in the candidate path.

Procedure

  1. Enter the system view.

    system-view

  2. Enable SRv6 and enter its view.

    segment-routing ipv6

  3. Enable the Delete-Hold function for SRv6 TE Policies.

    The Delete-Hold function for SRv6 TE Policies supports both global configuration and single-policy configuration. You can select either of the two modes as required. If both global and single-policy configurations exist, the single-policy configuration takes precedence.

    • Global configuration
      Enable the Delete-Hold function for all SRv6 TE Policies.
      srv6-te-policy segment-list delete-hold enable
    • Single-policy configuration
      1. Enter the SRv6 TE Policy view.
        srv6-te policy name-value
      2. Configure the Delete-Hold function for a specified SRv6 TE Policy.
        segment-list delete-hold { enable | disable }

        In global configuration, you can use the disable parameter to disable the Delete-Hold function for the specified SRv6 TE Policy.
