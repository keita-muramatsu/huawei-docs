Description of an Intermediate File in Python Format

In Table 1, the bold content in the Script Content column can be modified based on the actual running environment.

Table 1 Script description

Script Content

Description

 
#sha256="cb203b72b6070f535eaff14c7c7d984cf28c58052fadf1b484f80258b07fc8c9"

SHA256 verification code of the script file, which is used to check the integrity of the script file.

You can use either of the following methods to generate a SHA256 verification code for a script file:

  1. Use the SHA256 calculation tool, such as HashMyFiles.
  2. Run the certutil -hashfile filename SHA256 command supported by the Windows operating system.
NOTE:

Before a SHA256 verification code is generated, do not add the #sha256= field to the script. Instead, #sha256= should be added to the beginning of the script after the SHA256 verification code is generated.

A script without a SHA256 verification code can still be executed.

 
REMOTE_IMAGE = {
    'product-name': {
        'AR8000' : {
            'path': '/image/software_file_name.cc',
            'sha256': '',
        },
    },
    'esn': {},
    'mac': {},
    'uname': {}
}

Path, file name, and SHA256 verification code of the system software.

  • path: If this field is left empty, no system software needs to be loaded. The file name of the system software is a string of 4 to 120 characters suffixed with .cc.
  • sha256: SHA256 verification code, which can be left empty.
NOTE:

Only one of product-name, esn, mac, and uname can be specified and these fields cannot be all empty.

  • When product-name is used for deployment, the value of product-name can be queried using the display version command. In the command output, AR8000 in "Version xxx (AR8000 xxx)" is the value of product-name.
  • When esn is used for deployment, the value of esn can be queried using the display device esn command.
  • When mac is used for deployment, the value of mac can be queried using the display bridge mac-address command. The value of mac, which is case sensitive, must be the same as that queried on the device, for example, 00e0-fc12-3456.
  • When uname is used for deployment, the value of uname can be queried using the display version command. In the command output, AR8140-12G10XG in "HUAWEI AR8140-12G10XG uptime is X day, X hours, X minutes" is the value of uname.
 
REMOTE_CONFIG = {
    'product-name': {},
    'esn': {
        'BARCODETEST20200620' : {
            'path': '/config/conf_file_name.cfg',
            'effective_mode': EFFECTIVE_MODE_NO_REBOOT,
            'sha256': '',
            'save_after_success': ''
        },
        'COMMON': {
            'path': '/config/conf_%s.cfg',
            'effective_mode': EFFECTIVE_MODE_NO_REBOOT,
            'sha256': '',
            'save_after_success': ''
        }
    },
    'mac': {},
    'uname': {}
}

If the path, name, activation mode, and SHA256 verification code of a configuration file are specified as follows:

        'BARCODETEST20200620' : {
            'path': '/config/conf_file_name.cfg',
            'effective_mode': EFFECTIVE_MODE_NO_REBOOT,
            'sha256': '',
            'save_after_success': ''
        }
  • path: If this field is left empty, no configuration file needs to be loaded. The name of the configuration file is a string of 5 to 64 characters suffixed with .zip or .cfg.
  • sha256: SHA256 verification code, which can be left empty.
  • effective_mode: activation mode. If this field is left empty, the file is activated without the need of device restart.
    • EFFECTIVE_MODE_NO_REBOOT: The file is activated without the need of device restart.
    • EFFECTIVE_MODE_REBOOT: The file is activated upon restart.
  • save_after_success: whether to save current configurations to the configuration file after successful deployment. If this field is left empty, the value 1 is used. A device does not verify this field if the configuration file activation mode is set to activation without restart. After being successfully deployed, the device does not save the current configurations to the configuration file. (This field is not supported for USB-based deployment.)
    • 0: A device does not save current configurations to the configuration file after successful deployment.
    • 1: A device restarts and saves current configurations to the configuration file after successful deployment.

If the path, name, activation mode, and SHA256 verification code of a configuration file are specified as follows:

        'COMMON': {
            'path': '/config/conf_%s.cfg',
            'effective_mode': EFFECTIVE_MODE_NO_REBOOT,
            'sha256': '',
            'save_after_success': ''
        }
  • path: %s cannot be edited. If this parameter is set to esn, %s indicates the serial number of the device. If this parameter is set to mac, %s indicates the MAC address of the device. You can obtain the configuration file based on the device serial number or MAC address. If the corresponding conf_ %s.cfg file does not exist on the file server, an error message is displayed, indicating that the configuration file fails to be downloaded. For example, if the serial number of the device is 2102351HLD10J2000012 and the conf_2102351HLD10J2000012.cfg file does not exist on the file server, an error message is displayed.
  • sha256: SHA256 verification code, which can be left empty.
  • effective_mode: activation mode. If this field is left empty, the file is activated without the need of device restart.
    • EFFECTIVE_MODE_NO_REBOOT: The file is activated without the need of device restart.
    • EFFECTIVE_MODE_REBOOT: The file is activated upon restart.
  • save_after_success: whether to save current configurations to the configuration file after successful deployment. If this field is left empty, the value 1 is used. A device does not verify this field if the configuration file activation mode is set to activation without restart. After being successfully deployed, the device does not save the current configurations to the configuration file. (This field is not supported for USB-based deployment.)
    • 0: A device does not save current configurations to the configuration file after successful deployment.
    • 1: A device restarts and saves current configurations to the configuration file after successful deployment.
NOTE:

Only one of product-name, esn, mac, and uname can be specified and these fields cannot be all empty.

  • When product-name is used for deployment, the value of product-name can be queried using the display version command. In the command output, AR8000 in "Version xxx (AR8000 xxx)" is the value of product-name.

Path, file name, activation mode, and SHA256 verification code of the batch processing file.

  • path: If this field is left empty, no batch processing file needs to be loaded.

    pki import-certificate default_ca realm default
  • effective_mode: activation mode. If this field is left empty, the file is activated without the need of device restart.

REMOTE_LICLIST = {
    'path': '/license/ztp_license_list.xml',
    'sha256': 'a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c',
}

Path and SHA256 verification code of the license list file.

  • path: If this field is left empty, a license file does not need to be loaded.

    The path contains the license list file name, which is a string of 5 to 120 characters suffixed with .xml, for example, ztp_license_list.xml.

    If license files are stored in a separate directory, their names in the license list file must contain paths. For example, if the license files LIC_file1.xml and LIC_file2.dat are stored in /license/, the license list file is as follows:

    <?xml version="1.0" encoding="utf-8" standalone="yes"?>
<Index formatVersion="1.0">
	<Lic name="/license/LIC_file1.xml" sha256="d27305447dbb1e76ea9c6f27e19be2986503b91d8240612f9ebde708e7d1019e">
		<LSN>LIC202005183TCG5M</LSN>
		<Esn>102050157695</Esn>
	</Lic>
	<Lic name="/license/LIC_file2.dat" sha256="6a2690e7a08e3df844ba86e1f48dc3c504af3b760dd0e38134771e1024fe1a5f">
		<LSN>LIC202005183TCI50</LSN>
		<Esn>2102311LDL0000000805</Esn>
	</Lic>
</Index>
    NOTE:

    Devices can automatically load license files through a license list file, which contains mappings between licenses and device ESNs. A device first downloads the license list file and then downloads and loads the corresponding license file based on the ESN of the master device.

  • sha256: SHA256 verification code, which can be left empty.

Customized deployment files are supported. Up to nine files can be used for deployment, so there can only be a limited number of customized deployment files. For example, if the system software, configuration file, patch file, and customized files are involved in a deployment, a maximum of six customized files can be added. The format of multiple customized files is as follows:

        'BARCODETEST20200620' : [
            {
                'path': '/user/ztp_user.txt',
                'sha256': '',
            },
            {
                'path': '/user/ztp_user1.txt',
                'sha256': '',
            },
        ],

FILE_SERVER          = 'sftp://sftp_user:sftp_pwd@10.1.3.2'

Deployment files are downloaded from the USB flash drive for USB-based deployment.

The value is in file:// format.

File server information for intermediate file-based deployment.

  • Obtaining deployment files from an SFTP server: The address is in sftp://username:password@hostname:port or sftp-sha1://username:password@hostname:port format.
  • Obtaining deployment files from an HTTP server: The address is in http://hostname:port format if no username or password is available and is in http://username:password@hostname:port format if a username and password are available.
  • Obtaining deployment files from a TFTP server: The address is in tftp://hostname format.
  • Obtaining deployment files from an FTP server: The address is in ftp://username:password@hostname:port format.

In the format, port is optional, and the value of hostname can be a domain name or an IP address.

NOTE:

SFTP is recommended because it is more secure than TFTP, FTP, and HTTP.

 
TIME_SN             = '20200526120159'

Uniquely identifies a deployment in order to prevent repeated deployments. The value format is yyyymmddhhmmss.

For example, this field can be set to 20200526120159, indicating 12:01:59 on 2020-05-26.

 
SYSLOG_INFO          = 'UDP'

Transport protocol used by the Syslog server.

  • TCP: Logs are transmitted using TCP.
  • UDP: Logs are transmitted using UDP.
 
SPACE_CLEAR         = ZTP_SPACE_CLEAR_NO_NEED

Whether to automatically clean up the system storage space in the case of insufficient space.

  • ZTP_SPACE_CLEAR_NO_NEED: The system storage space is not cleaned up.
  • ZTP_SPACE_CLEAR_NORMAL: Only system software is deleted.
  • ZTP_SPACE_CLEAR_DEEP: In-depth cleanup is performed. System software is deleted first. If there is still not enough space, all unnecessary files are deleted from the flash directory.
NOTE:
  • In-depth cleanup involves some inherent risks. As such, you are advised to back up required files locally before performing in-depth cleanup.
  • No matter which cleanup policy is used, temporary files with the file name extension .cc.tmp will be deleted during device deployment.
 
ACTIVE_DELAYTIME    = '60'

Delay for deployment to be performed. The value is an integer that ranges from 0 to 86400, in seconds. For example, if the value is 60, the device starts deployment 60 seconds after it is powered on. If the value is greater than 86400, the value 86400 is used.

 
ACTIVE_INTIME       = None
NOTE:

If both ACTIVE_DELAYTIME and ACTIVE_INTIME are set, ACTIVE_DELAYTIME takes effect.

Scheduled time for deployment to be performed within 24 hours. The value format is HH:MM, where HH indicates the 24-hour format, and MM indicates the 60-minute format. For example, the value 20:10 indicates that the deployment will be performed at 20:10.

NOTE:

If the configured time is earlier than the system time of the device, the actual deployment time is the configured time plus 24 hours minus the current system time. For example, if the configured time is 10:00 and the device system time is 11:00, the deployment will be performed at 23:00.

 
VRPVER       = None

System software version number.

If the current system software version of the device is the same as the value specified here, the device does not download the system software from the deployment file server.

To use the current system software package for deployment, set this field to the version number of the current system software package.

 
INSTALL_WEAK        = None

Whether to install the weak security algorithm or protocol feature package. The options are as follows:

  • 1: The weak security algorithm or protocol feature package is installed during ZTP deployment, and will not be uninstalled after the deployment.
  • 0: The weak security algorithm or protocol feature package may be installed during ZTP deployment (for example, when deployment files are obtained through FTP or TFTP), and will be uninstalled after the deployment.

If this parameter is not set or is set to a value that is not 1, the value 0 is used.

NOTE:

If the value of INSTALL_WEAK is not 1 and the configuration file contains a weak security algorithm or protocol, the weak security algorithm or protocol feature package will fail to be uninstalled.

For security purposes, you are not advised to use FTP or TFTP to obtain deployment files.

 
is_set_master = None

System master key of a deployment configuration file. The value is a string of 20 to 32 characters and must contain uppercase letters, lowercase letters, digits, and special characters.

NOTE:
  • This field takes effect only when there is a deployment configuration file.
  • The configuration file is exported from a device, which has a system master key configured. This system master key is used as the value of this field.
  • When this field is configured, the intermediate file contains the key in plaintext. Therefore, you need to ensure the security of the intermediate file.
 
is_clear_master = False

Whether to clear the system master key configured in the intermediate file.

  • True: After ZTP is complete, the device clears the system master key configured in the intermediate file and restores it to a random master key.
  • False: After ZTP is complete, the device continues to use the master key configured in the intermediate file.
 
master_exportcfg = None

When the configuration file is saved from another device:

  • If the password parameter is not specified when the save shareable-configuration command is executed to save the configuration file, set master_exportcfg to None.
  • If the password parameter is specified when the save shareable-configuration command is executed to save the configuration file, set master_exportcfg to a value that is the same as the password entered in interactive mode.
NOTE:

The master_exportcfg field takes effect only when both is_set_master and master_exportcfg exist in the intermediate file and takes effect only for the configuration file.
