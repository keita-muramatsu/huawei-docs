Example for Configuring SPT Switchover Conditions in a PIM-SM Domain

Networking Requirements

Receivers can receive multicast Video On Demand (VOD) information. The PIM-SM single-BSR administrative domain is adopted in the entire PIM network. By default, the receiver DR and the RP perform the SPT switchover immediately after receiving the first multicast data packet, and choose the optimal path to receive information from the source. If the receiver expects an SPT switchover to be performed after the traffic rate reaches a threshold, configure conditions for the switchover.

On the network shown in Figure 1, HostA on the leaf network needs to receive multicast data from the RP (GE1/0/0 of DeviceA). When the transmission rate of multicast packets reaches 1024 kbit/s, the SPT switchover is performed. After the SPT switchover, HostA receives multicast packets through the path Source -> DeviceB -> DeviceC -> HostA.

In this example, interface1, interface2, and interface3 represent 10GE0/0/1, 10GE0/0/2, and 10GE0/0/3, respectively.

Figure 1 Networking diagram for SPT switchover in a PIM-SM domain

To complete the configuration, you need the following data:

  • Multicast source (S) address: 10.110.5.100/24

  • Multicast group (G) address: 225.1.1.1/24

Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure IP addresses and a unicast routing protocol for interfaces on each device.

  2. Enable multicast on all devices that provide multicast services, enable PIM-SM on each interface, and enable IGMP on the interface connected to the host.

  3. Configure the same static RP on each device.

  4. Configure SPT switchover conditions on DeviceC.

Procedure

  1. Assign an IP address to each device interface and configure a unicast routing protocol. For detailed configurations, see Configuration Scripts.
  2. # Enable multicast on each device, PIM-SM on each interface, and IGMP on the interfaces that connect DeviceC to the leaf network.

    # Configure DeviceC. The configurations of DeviceA and DeviceB are similar to the configuration of DeviceC. For detailed configurations, see Configuration Scripts.

    [DeviceC] multicast routing-enable
[DeviceC] interface 10GE 0/0/2
[DeviceC-10GE0/0/2] pim sm
[DeviceC-10GE0/0/2] igmp enable
[DeviceC-10GE0/0/2] quit
[DeviceC] interface 10GE 0/0/1
[DeviceC-10GE0/0/1] pim sm
[DeviceC-10GE0/0/1] quit
[DeviceC] interface 10GE 0/0/3
[DeviceC-10GE] pim sm
[DeviceC-10GE] quit

  3. Configure a static RP.

    # Configure a static RP on DeviceA, DeviceB, and DeviceC. The configurations of DeviceB and DeviceC are similar to the configuration of DeviceA. For detailed configurations, see Configuration Scripts.

    [DeviceA] pim
[DeviceA-pim] static-rp 192.168.1.1
[DeviceA-pim] quit

  4. Set the threshold for an SPT switchover.

    # Configure a threshold of 1024 kbit/s for performing an SPT switchover on DeviceC.

    [DeviceC] pim
[DeviceC-pim] spt-switch-threshold 1024
[DeviceC-pim] quit

Configuration Scripts

  • DeviceA

    #
sysname DeviceA
#
multicast routing-enable
#
interface 10GE0/0/1
 ip address 192.168.1.1 255.255.255.0
 pim sm
#
interface 10GE0/0/2
 ip address 192.168.3.1 255.255.255.0
 pim sm
#
pim
 static-rp 192.168.1.1
#
ospf 1
 area 0.0.0.0
  network 192.168.1.0 0.0.0.255
  network 192.168.3.0 0.0.0.255
#
return

  • DeviceB

    #
sysname DeviceB
#
multicast routing-enable
#
interface 10GE0/0/1
 ip address 192.168.2.1 255.255.255.0
 pim sm
#
interface 10GE0/0/2
 ip address 192.168.3.2 255.255.255.0
 pim sm
#
interface 10GE0/0/3
 ip address 10.110.5.1 255.255.255.0
 pim sm
#
pim
 static-rp 192.168.1.1
#
ospf 1
 area 0.0.0.0
  network 10.110.5.0 0.0.0.255
  network 192.168.2.0 0.0.0.255
  network 192.168.3.0 0.0.0.255 
#
return

  • DeviceC

    #
sysname DeviceC
#
multicast routing-enable
#
interface 10GE0/0/1
 ip address 192.168.1.2 255.255.255.0
 pim sm
#
interface 10GE0/0/2
 ip address 10.110.2.1 255.255.255.0
 pim sm
 igmp enable
#
interface 10GE0/0/3
 ip address 192.168.2.2 255.255.255.0
 pim sm
#
pim
 spt-switch-threshold 1024
 static-rp 192.168.1.1
#
ospf 1
 area 0.0.0.0
  network 10.110.2.0 0.0.0.255
  network 192.168.1.0 0.0.0.255
  network 192.168.2.0 0.0.0.255 
#
return
