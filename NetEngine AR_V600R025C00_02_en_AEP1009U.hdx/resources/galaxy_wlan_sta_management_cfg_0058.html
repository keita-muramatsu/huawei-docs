(Optional) Configuring the VAP Type

Context

You can configure VAP types as required. The application scenarios of VAP types are as follows:
  • If the type of a VAP is set to service, STAs connected to the VAP can access only network resources but not APs. Service VAPs are used in common WLAN deployment scenarios.

  • If the type of a VAP is set to service-backup ap-offline, STAs can access the network through the backup VAP after the AP goes offline. For example, on a headquarters-branch network where APs at branches connect to the WAC at the headquarters through the WAN, APs may go offline due to the WAN instability. In this case, you can configure a VAP of the service-backup ap-offline type to allow new STAs to access the network after the APs go offline.

  • If the VAP type is set to service-backup auth-server-down, the backup VAP is automatically enabled for STAs to access the network when the authentication server is unreachable. After the authentication server recovers, this backup VAP cannot be automatically disabled. In this case, you can manually disable it. If the authentication server is reachable but rejects user access, the backup VAP cannot be automatically enabled. In this case, you can manually enable it. To manually enable or disable a VAP, run the vap-service-backup auth-server-down command.

  • If the VAP type is set to service-backup distribute, the backup VAP continuously detects the signal output of the distributed VAP with the same SSID. If the signal from the distributed VAP with the same SSID is not detected within 25 Beacon intervals, the backup VAP considers the DAP faulty and automatically releases a signal for STAs to access the network. After the distributed VAP recovers, the signal of the backup VAP is disabled, and STAs are switched back to the distributed VAP.
Note the following during the configuration:

  • After the VAP type is configured in the VAP profile view, the VAPs generated by the VAP profile use the configured VAP type. The new VAP type will overwrite the old one.

  • For an AP-offline backup service VAP:

    • Only the WPA3 SAE, WPA2-WPA3 PSK-SAE, open, WPA+PSK, WPA2+PSK and WPA-WPA2+PSK authentication modes are supported.

    • The data forwarding mode must be direct forwarding.

    • When the number of configured AP-offline backup service VAPs reaches the maximum specifications on the AP, if the offline management VAP function is enabled, the offline management VAP does not take effect when the AP goes offline.

    • This VAP type is mutually exclusive with service holding upon link disconnection and tunnel forwarding for mDNS packets.

  • For an authentication-server-down backup service VAP:

    • Only the WPA3 SAE, WPA2-WPA3 PSK-SAE, open, WEP, WPA+PSK, WPA2+PSK and WPA-WPA2+PSK authentication modes are supported.

    • This VAP type is exclusive with the AP-offline backup service VAP.

  • For a distributed-AP backup service VAP:
    • Before configuring the DAP backup function, run the distribute-mode enable command to enable the DAP network collaboration function.
    • When a STA switches between the distributed VAP and backup VAP, the process is similar to WLAN roaming, during which a few packets may be lost.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Create a VAP profile and enter its view.

    vap-profile name profile-name

  4. Configure the VAP type.

    • Set the VAP type to AP-offline backup service.
      type service-backup ap-offline
    • Set the VAP type to authentication-server-down backup service.
      type service-backup auth-server-down [ vap-auto-off delay-time ] radius-server template template-name [ reject-new-access ]
    • Set the VAP type to distributed-AP backup service.
      type service-backup distribute

    The default type of a VAP is service.
