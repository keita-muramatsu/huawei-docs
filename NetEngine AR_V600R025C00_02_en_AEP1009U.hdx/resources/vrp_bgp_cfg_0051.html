Understanding the BGP Default Route

On large or medium-sized BGP networks, the BGP routing table of a device contains a large number of routing entries, consuming a large number of memory resources. In addition, the transmission and processing of routing information consumes many network resources. In scenarios where a BGP peer's routing table contains multiple routes advertised by the local device, you can configure the device to advertise the default route with the local address as the next hop address to this peer, regardless of whether the default route exists in the local routing table. This significantly reduces the number of routes transmitted on the network and minimizes consumption of network resources and the peer's memory resources.

Figure 1 Network diagram of advertising the default route to a peer

On the network shown in Figure 1, DeviceA and DeviceB establish a BGP peer relationship, and DeviceB imports routes 10.1.1.0/24, 10.2.1.0/24, and 10.3.1.0/24 into its BGP routing table. DeviceA learns these routes from DeviceB. In this case, DeviceA retains the three BGP routes. To reduce the memory consumption on DeviceA and the bandwidth consumption that occurs when DeviceB sends routing information to DeviceA, configure DeviceB to advertise the default route to its peer (DeviceA) and use a routing policy to prevent DeviceB from advertising the routes (10.1.1.0/24, 10.2.1.0/24, and 10.3.1.0/24) to DeviceA. After configuration, DeviceA stores only the default route but can still send traffic to the three network segments.
