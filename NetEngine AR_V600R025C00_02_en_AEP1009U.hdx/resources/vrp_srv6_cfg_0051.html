Understanding SRv6 Network Slicing

SRv6 network slicing enables one physical network to meet the differentiated requirements of various services.

Slice IDs are core elements of network slicing. Before planning network slices, you need to create network slice instances and allocate slice IDs. After forwarding resources are divided on interfaces, a physical network is divided into multiple network slices.

Network Slice-based Service Forwarding

In an SRv6 scenario, End SIDs are allocated only to nodes on the physical network, and End.X SIDs are allocated to physical links. No SID is allocated to logical nodes or links in network slices, as they use the SIDs of the physical network.

This section uses L3VPNv4 over SRv6 TE Policy, shown in Figure 3, as an example to describe the route advertisement process in the control plane of a network slice.

In the route advertisement phase, PE2 advertises a VPN route to PE1 through the MP-BGP/BGP EVPN peer relationship. This route carries information such as the color, next hop, and VPN SID.

This example assumes that an SRv6 TE Policy is created on PE1 and that a slice ID is configured for the SRv6 TE Policy to associate the two. PE1 recurses the VPN route 10.2.2.2/32 to the SRv6 TE Policy based on the color and next hop information. This route is then associated with the network slice whose slice ID is associated with the SRv6 TE Policy. In this way, the route can use the forwarding resources of this network slice.

Figure 3 Route advertisement in the control plane of a network slice

Figure 4 shows the data forwarding process of a network slice in an L3VPNv4 over SRv6 TE Policy scenario.

Figure 4 Data forwarding process of a network slice

In the data forwarding phase:

  1. CE1 sends a common IPv4 unicast packet to PE1.

  2. After receiving the packet from CE1, PE1 searches the routing table of the corresponding VPN instance and finds that the outbound interface of the route is an SRv6 TE Policy. PE1 then inserts an SRH that contains the SID list of the SRv6 TE Policy, the HBH header that contains the slice ID of the SRv6 TE Policy, and the IPv6 basic header into the packet in sequence. PE1 then finds the network slice interface based on the slice ID and forwards the packet to P1 over this interface.

  3. P1 forwards the packet based on the SRH information, using the slice ID in the HBH header to associate the packet with the specified network slice interface. The forwarding process on P3 and P5 is similar to that on P1.

  4. After the packet arrives at the egress PE2, PE2 searches My Local SID Table based on the IPv6 destination address in the packet and finds a matching End SID. According to the instruction bound to the SID, PE2 decrements the SL value of the packet by 1 and updates the IPv6 DA field to the VPN SID.

    Based on the VPN SID, PE2 searches My Local SID Table and finds a matching End.DT4 SID. According to the instruction bound to the SID, PE2 decapsulates the packet, removes the SRH, HBH header, and IPv6 header, searches the routing table of the VPN instance corresponding to the VPN SID based on the destination address 10.2.2.2 in the inner IPv4 packet, and forwards the packet to CE2.

It can be learned from the foregoing process that a slice ID is essential for connecting the control and forwarding planes. This network slicing solution is also referred to as slice ID-based network slicing. For details, see Figure 5.
