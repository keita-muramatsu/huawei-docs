NE Topology Collection

After the master device authenticates and manages member devices, it initiates topology information collection to each member device. Member devices report interface and LLDP neighbor information to the master device, which then updates the topology in real time and displays the topology on WebMaster.

The device supports automatic and manual topology refreshing.
  • Automatic topology refreshing: After the topology refresh interval is set on WebMaster, the master device automatically refreshes the network topology at the specified interval.
  • Manual topology refreshing: You can run commands on the device to trigger information collection on member devices and update the network topology.

The implementation process is as follows:

  1. After a member device is discovered by the master device, its information is displayed in the device approval list on WebMaster. For details, see Automatic NE Discovery.
  2. You can select member devices to be managed from this list.
  3. The master device sends topology collection packets to the member device to subscribe to its interface information and LLDP neighbor information.

    After an NE is managed, LLDP is automatically enabled for the NE. If you manually disable LLDP, the topology may be incorrectly displayed. To avoid this issue, you need to re-enable LLDP.

  4. The member device sends a unicast response packet to the master device. The packet carries information about all the device's physical main interfaces and Eth-Trunk interfaces (such as interface names and interface status) and LLDP neighbor information.
  5. After receiving the response from the member device, the master device calculates the network topology and displays it on WebMaster.
  6. The user runs the reset ual topo-info command on the device or delivers configurations on WebMaster to trigger topology re-collection.
  7. The master device clears the device approval list. Topology information of managed devices is re-collected, and unmanaged devices are re-discovered.
