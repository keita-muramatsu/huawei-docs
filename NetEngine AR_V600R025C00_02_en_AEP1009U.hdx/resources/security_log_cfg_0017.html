Understanding System Logs

The device can output the information generated when each function module is running to the log server or other storage paths through the information center. You can refer to the Log Reference to find system log information generated by the function modules on the device. The information center is where you can find information about all system software modules on the device. The device outputs system information in a refined manner to effectively filter information.

System logs include the administrator login or logout log, blacklist log, and operation log of command lines. The logs in syslog format are sent to a third-party log server through the information center.

Information Categorization

There are eight severity levels, each identified by a number. A smaller number indicates a higher severity level, as shown in Table 1.

Table 1 Information severity levels

Log Level

Severity Level

Description

0

Emergency

A fault that makes the device unable to run normally unless it is restarted. For example, the device restarts due to a program exception or an error during memory usage.

1

Alert

A fault that needs to be rectified immediately. For example, the device memory usage reaches the upper limit.

2

Critical

A fault that needs to be analyzed and processed. For example, the memory usage drops below the lower limit, the temperature drops below the lower limit, BFD detects that a device is unreachable, or an error message sourced from the device is detected.

3

Error

An improper operation that is performed or exceptions that occur during service processing. The fault does not affect services but needs to be analyzed. For example, users enter incorrect commands or passwords, or error protocol packets are received.

4

Warning

An exception that occurs when the device is operating and requires attention because it may cause service failures. For example, a routing process is disabled, packet loss is detected using BFD, or error protocol packets are detected.

5

Notice

A key operation that is performed to ensure normal operation of the device. For example, the shutdown command is used, a neighbor is discovered, or the protocol status changes.

6

Informational

A common operation that is performed when the device is running properly.

7

Debug

Common information that is generated during normal operation of the device, which requires no attention.

When you filter information based on the severity level, the device only outputs logs with severity levels numerically lower than or equal to the configured severity level.

For example, if the severity level is set to Informational, the device only outputs logs with severity levels from 0 to 6.

When multiple log hosts are configured, you can enable the device to output system logs from one or more channels to different logs hosts. For example, the device can output some system logs from channel 2 (loghost) to one log host and other logs from channel 6 to another log host. You can also change the name of channel 6 for easier information channel management.

When channel 9 is disabled, logs cannot be written to the memory database; therefore, you are advised to enable channel 9.

Log Format

The format of system logs is as follows:

<Int_16>TIMESTAMP HOSTNAME %%ddAAA/B/CCC(l):CID=ZZZ; YYYY

Table 3 describes the details of each field.

Table 3 Description of system log formats

Field

Meaning

Description

<Int_16>

Preamble

The device adds a preamble before sending logs to a log host.

If logs are saved on the device, the preamble is not saved.

TIMESTAMP

Timestamp, indicating the information output time.
Five timestamp formats are available:

  • Boot: relative time.

  • Date: system time. System logs use the date timestamp by default.

  • Short-date: same as the date format except that the short-date timestamp does not include the year.

  • Format-date: another system time format.

  • None: The information does not contain any timestamp.

The timestamp and host name are separated by a space.

HOSTNAME

Host name

The default value is HUAWEI.

%%

Huawei identifier

Indicates that a log is output by a Huawei device.

dd

Version

Indicates the version of the log format.

AAA

Module name

Indicates the name of the module that outputs information to the information center.

B

Log level

Indicates the level of the log information.

CCC

Brief description

Further describes the type of the information.

(l)

Information category

l: Log identifier

CID=ZZZ

Internal component ID

Identifies the internal component to which the log belongs. The parameter is as follows:

ZZZ: ID of an internal component.

YYYY

Description

Details about the information that each module outputs to the information center. Each module adds a description before sending a log to describe log details.
