Testing the Server Connectivity

Context

When configuring remote server authentication, you can run the test-aaa command to manually test the connectivity between a single user and the authentication or accounting server. This facilitates fault location.

Procedure

  • Run the test-aaa command in any view to test the connectivity between the device and server.

    Table 1 Testing the server connectivity

    Operation

    Command

    Test the connectivity between the device and the RADIUS authentication or accounting server.

    test-aaa user-name user-password radius-template template-name [ chap | pap | accounting [ start | realtime | stop ] ] [ called-station-id [ ssid ssid-value ] ]

    Test the connectivity between the device and the HWTACACS authentication or accounting server.

    test-aaa user-name user-password hwtacacs-template template-name [ accounting [ start | realtime | stop ] ]

    Test the connectivity between the device and the AD authentication server.

    test-aaa user-name user-password ad-template template-name

    Test the connectivity between the device and the LDAP authentication server.

    test-aaa user-name user-password ldap-template template-name

Follow-up Procedure

The Info messages of the test-aaa command do not distinguish between the server types. Table 2 describes the Info messages.

Table 2 Info messages of the test-aaa command

Info Message

Description

Troubleshooting Method

Info: Authentication may fail due to incorrect name or password.

The device can communicate with the server. However, the user name and password used in the test are different from those configured on the server.

Run the test-aaa command to check whether the user name and password are correct. If this Info message is displayed, the user name and password are incorrect. Ensure that the user name and password are correct during user authentication.

Info: Authentication may fail due to incorrect shared key.

The shared key of the server configured on the device is different from that configured on the server.

Reconfigure the shared key on the device and server.

Info: The server template does not exist.

The server template used for the test is not configured on the device.

Configure a server template for the test on the device.

Info: One more user doing this operation is not permitted. Please wait for a while to do this operation again.

Multiple users are running the test-aaa command at the same time.

Ensure that the test-aaa command is run by only one user at a time.

  • Info: Account test time out.

    During the test of the RADIUS server:

    The following describes possible causes:
    • There are no reachable routes between the device and the server.
    • The NAS IP address configured in the RADIUS server template is different from that on the RADIUS server.
    • The RADIUS server address in the RADIUS server template is incorrect.
    • The authentication port number configured in the RADIUS server template is incorrect.
    • The authentication port number on the RADIUS server is used by another program.
    • The IP address of the access control device is incorrect or the RADIUS server is not started.
    Procedure
    • Run the ping command to check whether there are reachable routes between the device and the server.
    • Run the display radius-server configuration [ template template-name] command in any view to check whether the port number, NAS IP address, and RADIUS server IP address configured in the RADIUS server template are the same as those configured on the RADIUS server.
    • When the controller functions as the RADIUS server, run the netstat -nao | findstr 1812 and netstat -nao | findstr 1813 commands on the server to check whether the authentication port number is used by another program. If another program uses this port number, close the program.
    • Check whether the IP address of the access control device is correct on the RADIUS server.

    During the test of the HWTACACS server:

    The following describes possible causes:
    • There are no reachable routes between the device and the server.
    • The HWTACACS server address in the HWTACACS server template is incorrect.
    • The authentication port number configured in the HWTACACS server template is incorrect.
    • The authentication port number on the HWTACACS server is used by another program.
    • The IP address of the access control device is incorrect or the HWTACACS server is not started.
    Procedure
    • Run the ping command to check whether there are reachable routes between the device and the server.
    • Run the display hwtacacs-server template [ template template-name ] command in any view to check whether the port number and IP address of the HWTACACS server configured in the HWTACACS server template are the same as those configured on the HWTACACS server.
    • Check whether the IP address of the access control device on the HWTACACS server is correct. If the IP address is correct, analyze packets on both the device and HWTACACS server to check whether the intermediate link is operational. The possible link failure is that a firewall deployed on the network between the HWTACACS server and device blocks the port number (49 by default) of the HWTACACS server.
    • Run the hwtacacs-server shared-key cipher key-string command in the HWTACACS server template view to configure a shared key on the device, and reconfigure a shared key on the HWTACACS server to ensure that the shared keys configured on the HWTACACS server and device are the same.
    • Check whether the IP address of the device is added to the HWTACACS server or whether the added IP address is correct. The added IP address must be the source IP address of the authentication request packets sent by the device. The source IP address can be configured using a command in the HWTACACS server template view. If the source IP address is not configured, the default one is used. That is, the IP address of the outbound interface for authentication request packets is used as the source IP address. To check the source IP address, perform the following operations:

      Run the display hwtacacs-server template [ template template-name] command to check whether the source IP address is configured. The Source-IP-address field in the command output indicates the source IP address. If the source IP address is displayed, the source IP address has been configured using a command. The source IP address configured on the HWTACACS server must be the same as that displayed in the command output. If no source IP address is displayed, the default source IP address is used. You can view the NextHop field in the corresponding route to obtain the source IP address of authentication request packets. The source IP address configured on the HWTACACS server must be the same as the obtained IP address.

  • Info: Account test failed.

    The following describes possible causes:

    The RADIUS or HWTACACS server IP address is not configured.

    Procedure

    • When testing the RADIUS server, run the display radius-server configuration [ template template-name ] command in any view to check whether the IP address of the RADIUS server is configured in the RADIUS server template.
    • When testing the HWTACACS server, run the display hwtacacs-server template [ template template-name ] command in any view to check whether the IP address of the HWTACACS server is configured in the HWTACACS server template.
  • Info: Account test succeeded. The device is connected to the server, but the user cannot pass the authentication during login.

    The following describes possible causes:

    Check whether the domain used for user authentication is the same as the domain configured for RADIUS or HWTACACS authentication on the device.

    Procedure

    • Run the display this command in the AAA view to check whether the domain used for user authentication is the same as the domain configured for RADIUS authentication on the device.

      • If the user name entered by the user contains a domain name, check whether RADIUS or HWTACACS authentication is configured in the domain with the domain name.
      • If the user name entered by the user does not contain a domain name, check whether RADIUS or HWTACACS authentication is configured in the global default domain.
    • Run the display this command in the AAA view to check whether the AAA authentication scheme and RADIUS or HWTACACS server template are applied to the domain.
