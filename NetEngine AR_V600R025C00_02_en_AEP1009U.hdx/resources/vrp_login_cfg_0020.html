Failed to Log In to the Telnet Server Using Telnet

Fault Description

A user fails to log in to the Telnet server using Telnet.

Procedure

  1. Log in to the device through the console port. Enter the system view.

    system-view

  2. Check Telnet server parameters.

    1. Check whether the source interface and listening port number of the Telnet server are correct, and whether the Telnet function is enabled.
      display current-configuration configuration telnet include-default

      If the source interface and listening port are correct and the Telnet function is enabled, go to step 3.

      If the source interface and listening port are incorrect or the Telnet function is disabled, go to step b.

    2. Enable the Telnet server function and configure the source interface and port number.

      # Enable the Telnet server function. This command can be used only after the weak security algorithm/protocol feature package (WEAKEA) is installed using the install feature-software WEAKEA command.

      telnet [ ipv6 ] server enable
      # Configure the port number of the Telnet server.
      telnet [ ipv6 ] server port port-number
      # Configure the source interface of the Telnet server.
      telnet server-source -i { interface-type interface-number | interface-name }
telnet ipv6 server-source -a ipv6-address [ -vpn-instance vpn-instance-name ]
telnet [ ipv6 ] server-source all-interface

  3. Check whether the number of users who are logged in to the Telnet server has reached the upper limit.

    1. Check whether all VTY channels are occupied.
      display users [ all ]
      • If all VTY channels are occupied, go to step b.
      • If not all VTY channels are occupied, go to step 4.
    2. Check the maximum number of users allowed by the current VTY channel.
      display user-interface maximum-vty
      • If the configured maximum number of VTY user interfaces does not reach 21, go to step c.
      • If the configured maximum number of VTY user interfaces reaches 21, go to step 4.
    3. Set the maximum number of users allowed by the VTY channel to 21.
      user-interface maximum-vty 21

  4. Check whether an ACL has been configured on the VTY user interface of the Telnet server.

    1. Check whether an ACL is configured on the VTY user interface.
      user-interface vty first-ui-number [ last-ui-number ]
display this
quit
      • If an ACL is configured, record the ACL number and go to step b.
      • If no ACL is configured, go to step 5.
    2. Check whether the IP address of the Telnet client is denied in the ACL.
      display acl acl-number
      • If the IP address of the Telnet client is denied, go to step c.
      • If the IP address of the Telnet client is not denied, go to step 5.
    3. Delete the deny rule.
      undo rule rule-id
    4. Modify the ACL to allow access from the IP address of the client.
      rule permit source source-ip-address source-wildcard

  5. Check the protocol configuration in the VTY user interface view of the Telnet server.

    1. Check whether the protocol supported by the VTY user interface is Telnet or all.
      user-interface vty first-ui-number [ last-ui-number ]
display this
      • If not, go to step b.
      • If so, go to step 6.
    2. Set the protocol supported by the user interface to Telnet.
      protocol inbound { telnet | all }
quit

  6. Check whether the login authentication mode is configured in the user interface view of the Telnet server.

    user-interface vty first-ui-number [ last-ui-number ]
display this
quit

    If AAA authentication is configured using the authentication-mode aaa command, you must run the local-user user-name password command to create a local AAA user and set the user service type to Telnet.
