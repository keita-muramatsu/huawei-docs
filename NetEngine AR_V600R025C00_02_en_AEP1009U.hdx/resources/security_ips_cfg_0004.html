Intrusion Prevention Process

As shown in Figure 1, the intrusion prevention process consists of signature matching-based attack detection and attack response.

Figure 1 Intrusion prevention process

  1. Packet reassembly

    Some attacks attempt to evade intrusion prevention by fragmenting packets. To prevent such attacks, after receiving traffic, the device reassembles IP fragments and TCP flows before detection. This helps to ensure the continuity of application-layer data and effectively detect the attacks that evade intrusion prevention.

    IPS detection is based on flows. The device reassembles, identifies, and detects all packets (regardless of their sizes) of a flow.

  2. Application protocol identification and parsing

    The device identifies the application-layer protocol based on the packet content and performs in-depth parsing on the protocol to extract packet features.

    Compared with the conventional method that identifies protocols only by IP address and port number, intrusion prevention significantly increases the detection rate of application-layer attacks.

  3. Signature matching

    The device compares the extracted packet features with Intrusion Prevention Signatures. If a match is found, the packets are processed according to the configured action.

    The device can periodically download the latest IPS signature database from the Huawei security center (isecurity.huawei.com) to effectively defend against network intrusions in a timely manner.

  4. Attack response

    After a packet matches a signature, the device determines whether and how to respond to (alert or block) the packet according to Intrusion Prevention Profile. An IPS profile consists of two elements: exception signature and signature filter.

    1. The device checks whether the matched signature is an exception signature. If so, the device performs the action set for the exception signature. Otherwise, the device proceeds with the next step.
    2. The device checks whether the matched signature is that filtered out by the signature filter. If so, the device performs the action set for the signature filter. Otherwise, the device directly permits the packet.

    You can configure a signature filter, a set of conditions for filtering signatures, based on the network and service status. The device can defend against only attacks corresponding to the signatures filtered out by the signature filter. This prevents key attacks from being overwhelmed by large numbers of attack logs.

    In addition, the device provides the exception signature function. When the action set for the signature filter does not meet requirements, you can modify the action for a single signature. The action set for an exception signature takes precedence over that for a signature filter.

    As for TCP traffic, if the handling action of the content security service is block, the device sends RST packets to the client or server through the ASE to disconnect TCP connections to block the traffic.
