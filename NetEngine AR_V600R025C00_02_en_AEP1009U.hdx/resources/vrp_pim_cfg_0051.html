Understanding PIM Security Policies

In addition to basic PIM functions, PIM security management functions (such as limiting, filtering, and checking) are provided to ensure the normal running of multicast services on networks. Table 1 provides details about these functions.

Limit on the BSR address range

PIM-SM

On a PIM-SM network that uses the bootstrap router (BSR) mechanism, any multicast device can be configured as a candidate-BSR (C-BSR) to participate in a BSR election. The winner is responsible for advertising RP information on the network.

This function guarantees BSR security by preventing BSR spoofing and malicious hosts from replacing authorized BSRs.

An ACL and filtering rules are configured to limit the range of permitted BSR addresses. BSR messages that are not from this address range are discarded by devices.

Limit on the C-RP address range

PIM-SM

On a PIM-SM network that uses the BSR mechanism, any multicast device can be configured as a candidate-rendezvous point (C-RP) to serve the multicast group within a specified address range. After each C-RP unicasts a C-RP Advertisement message to the BSR, the BSR summarizes all collected C-RP information as an RP-Set and floods it network wide through Bootstrap messages. Then, each multicast device locally calculates an RP corresponding to the specific group address range according to the RP-Set.

This function guarantees C-RP security by preventing C-RP spoofing and malicious hosts from replacing authorized C-RPs. With this function, an RP can be correctly elected.

An ACL and filtering rules are configured to limit the range of permitted C-RP addresses and the range of multicast groups that the C-RPs serve. Advertisement messages carrying the C-RP addresses out of the permitted address range are discarded by the BSR.

Register message filtering

PIM-SM

Before multicast data is sent to group members, any new multicast source on a PIM-SM network must first register with an RP by using the source DR to send a Register message to the RP.

This function protects the network against unauthorized Register messages from malicious devices, thus preventing MDT setup and data forwarding failures caused by those messages.

An ACL and filtering rules are configured to enable the RP to filter Register messages received from the multicast source DR.

Defense against malicious host attacks (through PIM Silent)

PIM-SM

A device's interface directly connected to a user host can set up a PIM neighbor relationship and process PIM messages once PIM-SM is enabled on the interface. This, however, brings security risks. When a host maliciously sends PIM Hello messages as a forged PIM device, its peer device may break down.

This function protects PIM-SM interfaces against attacks from forged PIM neighbors.

The interface is disabled from accepting or forwarding any PIM messages, and all PIM neighbor relationships on the interface are deleted.

Device that has an interface directly connected to the subnet of user hosts. Note that the subnet can have only one PIM device connected.

PIM devices directly connected to the subnet of user hosts

Denying the Hello messages without the Generation ID option

PIM-SM

After PIM-SM is enabled on an interface, the device generates a random number as the Generation ID of a Hello message. If the device status is updated, a new Generation ID is generated.

This function prevents a multicast device from setting up a neighbor relationship with a device that does not support the Generation ID parameter, improving PIM security.

The device checks whether each received Hello message contains the Generation ID. The device processes the Hello messages that carry the Generation ID and discards those without the Generation ID.

PIM neighbor filtering

PIM-SM

Some unknown devices on a network may run PIM to prevent a multicast device from becoming the DR.

This function prevents a multicast device from setting up PIM neighbor relationships with unknown devices and prevents an unknown device from becoming a DR.

An ACL and filtering rules are configured to enable interfaces to set up neighbor relationships only with the permitted addresses and delete those without permitted addresses.

Join information filtering

PIM-SM

A Join/Prune message received by an interface contains both join and prune information.

This function filters join information to prevent unauthorized users from joining multicast groups.

An ACL and filtering rules are configured to filter join information. Devices create PIM entries only based on permitted join information.

Source address-based filtering

PIM-SM

This function enables a device to filter multicast data packets based on source or source-group addresses, ensuring the security of multicast data packets.

An ACL and filtering rules are configured to enable devices to forward only multicast packets whose source or both source and group addresses are within the permitted address range.

PIM neighbor check

PIM-SM

This function guarantees the security of Join/Prune and Assert messages received or sent by devices.

When receiving or sending Join/Prune or Assert messages, a device checks whether the messages are sent to or received from a PIM neighbor. If yes, the messages are processed; otherwise, the messages are discarded.
