Enabling the Net Assistant Function

Context

If you want to centrally manage and maintain devices on the network through one device, you can do so after enabling the net assistant function and then logging in to WebMaster.

Procedure

  1. Configure the DHCPv4 server function. Perform this step on the device that provides the DHCP server function, which is usually the master device.

    1. Enable DHCPv4.
      system-view
dhcp enable [ ipv4 | ipv6 ]
    2. Configure the DHCPv4 server function.
      interface Vlanif1 //It must be configured on VLANIF1.
ip address ip-address { mask | mask-length }
dhcp select interface
dhcp server gateway-list ip-address &<1-8>
    3. (Optional) Bind an IP address in the interface address pool to the MAC address of a DHCP client.
      dhcp server static-bind ip-address ip-address mac-address mac-address [ description description ]

      If the master device does not function as the DHCP server, you need to bind IP addresses in the address pool to the MAC addresses of hosts when approving existing devices or configuring approved devices as WACs.

      By default, no IP address in the interface address pool is bound to the MAC address of a DHCP client.

    4. Exit the interface view.
      quit

  2. Configure the master device. Perform this step on the master device.

    1. Create a local AAA account for logging in to WebMaster.
      system-view
aaa
local-user user-name password irreversible-cipher irreversible-cipher-password
local-user user-name service-type http
local-user user-name privilege level 3 
quit
    2. (Optional) Enable the DHCP client function on an interface.

      If the master device also functions as the DHCPv4 server or the device is started with the default configuration, skip this step.

      interface Vlanif1 //It must be configured on VLANIF1.
ip address dhcp-alloc [ unicast ]
quit
    3. Configure the specified NE as the master device.
      ual role controller

      By default, no master role is configured, and the device functions as a member device.

      After the command is run:

      • The master device automatically delivers the net-assistant enable command to enable the net assistant function.
      • The master device automatically generates a default SSL policy (named netasstpolicy) and binds it to the PKI realm named default (no PKI certificate is automatically loaded to this realm).
      • The master device automatically configures the SSL policy for the net assistant function and automatically enables the SSL peer verification function.
      • The master device automatically generates a virtual IP address 10.231.10.253.
      • The master device automatically runs the undo web-manager captcha enable command to disable the verification code-based authentication function on the authentication page of the web server.
      • The master device automatically runs the web-manager server-source -i Vlanif1 command to specify Vlanif1 as the source interface of the web server.

  3. (Optional) Enable the DHCP client function on an interface. Perform this step on the member device.

    If the device is started with the default configuration, skip this step.

    system-view
interface Vlanif1 //It must be configured on VLANIF1.
ip address dhcp-alloc [ unicast ]
quit

  4. Log in to WebMaster through a virtual IP address.

    1. Connect the network interface of the administrator PC to any interface of any device on the network.
    2. Set the IP address of the PC to be on the same network segment as the virtual IP address (10.231.10.253).
    3. Enter https://10.231.10.253:port in the address box of the browser. port indicates the port number for web login. The default value is 443. For details, see Specifying the Master Device and Logging In to WebMaster.
