Intermediate File in the INI Format

The intermediate file in .ini format is used to save information about the device and its deployment files. The file name must be ***.ini, such as ztp_script.ini, and the following is an example of such a file. For details about the fields included in this file, see Table 1.

#sha256="676a306a0c22d46ed975633de9d05af4b1ebb94879ed1dd1d1e34de2a72c4e7e"
;BEGIN ZTP CONFIG
[GLOBAL CONFIG]
*FILESERVER=sftp://sftp_user:Hyx_Hy1234@10.1.3.2
*TIME_SN=20200526120159
*DEVICE_TYPE_NUM=1
SET_MASTER=Root@123456789123456
CLEAR_MASTER=1
EXPORTCFG=
INSTALL_WEAK=

[DEVICE_TYPE_1 DESCRIPTION]
DEVICE_TYPE=AR8000
ESN=
MAC=
UNAME=
VRPVER=
SYSLOG_INFO=UDP
SPACE_CLEAR=1
DIRECTORY=folder/
ACTIVE_DELAYTIME=60
ACTIVE_INTIME=
*FILETYPENUM=7
*FILENAME_1=software_file1.cc
*TYPE_1=SOFTWARE
*EFFECTIVE_MODE_1=0
ISBATCHPROCESS_1=0
SHA256_1=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c
*FILENAME_2=cfg_file1.cfg
*TYPE_2=CFG
*EFFECTIVE_MODE_2=0
SAVE_AFTER_SUCCESS=0
ISBATCHPROCESS_2=0
SHA256_2=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c
*FILENAME_3=pat_file1.pat
*TYPE_3=PAT
*EFFECTIVE_MODE_3=1
ISBATCHPROCESS_3=0
SHA256_3=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c
*FILENAME_4=lic_file1.xml
*TYPE_4=LIC
*EFFECTIVE_MODE_4=1
ISBATCHPROCESS_4=0
SHA256_4=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c
*FILENAME_5=user_file1.txt
*TYPE_5=USER
*EFFECTIVE_MODE_5=2
ISBATCHPROCESS_5=0
SHA256_5=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c
*FILENAME_6=mod1.MOD
*TYPE_6=MOD
*EFFECTIVE_MODE_6=1
ISBATCHPROCESS_6=0
SHA256_6=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c
*FILENAME_7=feature_plugin1.ccx
*TYPE_7=FEATURE-PLUGIN
*EFFECTIVE_MODE_7=1
ISBATCHPROCESS_7=0
SHA256_7=a7638ea0a69933ac20df66ea9bf6ea301de8155684d81fbcdf00f6ca07261d7c

;END ZTP CONFIG
Table 1 Fields in an INI file

Field

Mandatory or Not

Description

sha256

No

SHA256 verification code of the intermediate file, which is used to check the integrity of the intermediate file.

You can use either of the following methods to generate a SHA256 verification code for a script file:

  1. Use the SHA256 calculation tool, such as HashMyFiles.
  2. Run the certutil -hashfile filename SHA256 command supported by the Windows operating system.
NOTE:

Before a SHA256 verification code is generated, do not add the #sha256= field to the script. Instead, #sha256= should be added to the beginning of the script after the SHA256 verification code is generated.

A script without a SHA256 verification code can still be executed.

;BEGIN ZTP CONFIG

Yes

Start flag of a file. This field cannot be modified.

[GLOBAL CONFIG]

Yes

Start flag of the global configuration. This field cannot be modified.

*FILESERVER

Yes

Address of the deployment file server.

  • Obtaining deployment files from an SFTP server: The address is in sftp://username:password@hostname:port/path or sftp-sha1://username:password@hostname:port format.
  • Obtaining deployment files from an HTTP server: The address is in http://hostname:port/path format if no user name or password is available and is in http://username:password@hostname:port/path format if a user name and a password are available.
  • Obtaining deployment files from a TFTP server: The address is in tftp://hostname/path format.
  • Obtaining deployment files from an FTP server: The address is in ftp://username:password@hostname:port/path format.

In the format, port is optional, and the value of hostname can be a domain name or an IP address. path specifies the directory where deployment files are stored on the file server. If /path is not specified, deployment files are stored in the root directory of the file server.

NOTE:

SFTP is recommended because it is more secure than TFTP, FTP, and HTTP.

*TIME_SN

Yes

Uniquely identifies a deployment in order to prevent repeated deployments. The value format is yyyymmddhhmmss.

For example, this field can be set to 20200526120159, indicating 12:01:59 on 2020-05-26.

*DEVICE_TYPE_NUM

Yes

Number of device types. For example, the value 1 indicates that only one type of device can be deployed.

SET_MASTER

No

System master key of a configuration file. The value is a string of 20 to 32 characters. It must contain uppercase letters, lowercase letters, digits, and special characters.

NOTE:
  • This field takes effect only when the deployment configuration file exists.
  • The configuration file is exported from a device, which has a system master key configured. This system master key is used as the value of this field.
  • When this field is configured, the intermediate file contains the key in plaintext. Therefore, you need to ensure the security of the intermediate file.

CLEAR_MASTER

No

Whether to clear the system master key configured in the intermediate file for deployment. This field is available only when the SET_MASTER field exists.

  • 1: After ZTP is complete, the device clears the system master key configured in the intermediate file, and restores the master key to the random master key.
  • 0: After ZTP deployment, the device continues to use the master key configured in the intermediate file. This value is used by default.

If the CLEAR_MASTER field is not set or is not set to 1, the value 0 is used.

EXPORTCFG

No

Password entered when the configuration file is saved from another device. When the configuration file is saved from another device:

  • If the password parameter is not specified when the save shareable-configuration command is executed to save the configuration file, leave EXPORTCFG empty.
  • If the password parameter is specified when the save shareable-configuration command is executed to save the configuration file, set EXPORTCFG to a value that is the same as the password entered in interactive mode.
NOTE:

EXPORTCFG is available and takes effect only for the configuration file only when both SET_MASTER and EXPORTCFG are set in the .ini intermediate file.

INSTALL_WEAK

No

Whether to install the weak security algorithm or protocol feature package.

  • 1: The weak security algorithm or protocol feature package is installed during ZTP deployment, and will not be uninstalled after the deployment.
  • 0: The weak security algorithm or protocol feature package may be installed during ZTP deployment (for example, when deployment files are obtained through FTP or TFTP), and will be uninstalled after the deployment.

If this parameter is not set or is set to a value that is not 1, the value 0 is used.

NOTE:

If the value of INSTALL_WEAK is not 1 and the configuration file contains weak security algorithms or protocols, the weak security algorithm or protocol feature package will fail to be uninstalled.

For security purposes, you are not advised to use FTP or TFTP to obtain deployment files.

[DEVICE_TYPE_n DESCRIPTION]

Yes

Start tag of the device description. n indicates the device number. The value is an integer starting from 1.

DEVICE_TYPE

When DEVICE_TYPE_NUM is set to 1, DEVICE_TYPE, ESN, MAC, and UNAME can all be set to DEFAULT or left empty.

When DEVICE_TYPE_NUM is greater than 1, at least one of DEVICE_TYPE, ESN, MAC, and UNAME must be specified.

NOTE:
  • To upgrade devices in batches, set DEVICE_TYPE or UNAME.
  • To upgrade a single device, set ESN or MAC.

Device type.

The value of DEVICE_TYPE can be queried using the display version command. In the command output, AR8000 in "Version xxx (AR8000 xxx)" is the value of DEVICE_TYPE.

If this field is left empty or set to DEFAULT, the device type does not need to be matched. The default value is DEFAULT.

ESN

Master device ESN, which can be queried using the display device esn command.

If this field is left empty or set to DEFAULT, the device ESN does not need to be matched. Otherwise, the device ESN needs to be matched. The default value is DEFAULT.

MAC

MAC address of a device, in the XXXX-XXXX-XXXX format, in which X is a hexadecimal number. You can run the display bridge mac-address command to query the MAC address.

If this field is left empty or set to DEFAULT, the MAC address does not need to be matched. Otherwise, the MAC address needs to be matched. The default value is DEFAULT.

UNAME

Specific device model.

The value of UNAME can be queried using the display version command. In the command output, AR8140-12G10XG in "HUAWEI AR8140-12G10XG uptime is X day, X hours, X minutes" is the value of UNAME. The default value is DEFAULT.

VRPVER

No

System software version number.

If the current system software version of the device is the same as the value specified here, the device does not download the system software from the deployment file server.

To use the current system software package for deployment, set this field to the version number of the current system software package.

SYSLOG_INFO

No

Transport protocol used by the Syslog server.

  • TCP: Logs are transmitted using TCP.
  • UDP: Logs are transmitted using UDP.

SPACE_CLEAR

No

Whether to automatically clean up the system storage space in the case of insufficient space. The value is of the enumerated type.

  • 0: The system storage space is not cleaned up.
  • 1: Only system software is deleted.
  • 2: In-depth cleanup is performed. System software is deleted first. If the available space is still insufficient, all unnecessary files are deleted from the flash directory.

If this field is left empty or set to DEFAULT, the space is not cleaned up. The default value is DEFAULT.

NOTE:
  • In-depth cleanup involves some inherent risks. As such, you are advised to back up required files locally before performing in-depth cleanup.
  • No matter which cleanup policy is used, temporary files with the file name extension .cc.tmp will be deleted during device deployment.

DIRECTORY

No

Relative directory where deployment files are stored on the file server.

If this field is left empty or set to DEFAULT, deployment files are stored in the root directory. The default value is DEFAULT.

NOTE:

The relative directory must start with a folder name and cannot start with a slash (/).

ACTIVE_DELAYTIME

No

NOTE:

If both ACTIVE_DELAYTIME and ACTIVE_INTIME are set, ACTIVE_DELAYTIME takes effect.

Delay for deployment to be performed. The value is an integer that ranges from 0 to 86400, in seconds. For example, if the value is 60, the device starts deployment 60 seconds after it is powered on. If the value is greater than 86400 seconds (that is, more than one day), the system regards the value as one day.

ACTIVE_INTIME

Scheduled time for deployment to be performed within 24 hours. The value format is HH:MM, where HH indicates the 24-hour format, and MM indicates the 60-minute format. For example, the value 20:10 indicates that the deployment will be performed at 20:10.

NOTE:

If the configured time is earlier than the system time of the device, the actual deployment time is the configured time plus 24 hours minus the current system time. For example, if the configured time is 10:00 and the device system time is 11:00, the deployment will be performed at 23:00.

*FILETYPENUM

Yes

Number of deployment files to be loaded.

NOTE:

The total number of deployment files must not exceed 9.

The value of this field must be the same as the actual number of deployment files, and the value is the same as n in FILENAME_n.

*FILENAME_n

Yes

Name of a deployment file, which can be the name of a system software file, configuration file, license file, patch file, module file, customized file, batch processing file, or feature package file. The value format is path/filename.

  • path: indicates the relative directory of the deployment file on the file server. The directory cannot start with a slash (/). The file storage path is specified by the combination of FILESERVER, DIRECTORY, and FILENAME_n.
  • filename: indicates the deployment file name.

If an initial CA certificate needs to be activated during device deployment, you can use a batch processing file to import a command, for example:

pki import-certificate default_ca realm default
NOTE:

If the length of a deployment file name exceeds the limit, the file will fail to be downloaded. The length limits for different deployment files are as follows:

  • System software: The name is a string of 4 to 120 characters suffixed with .cc.
  • Configuration file: The name is a string of 5 to 64 characters suffixed with .zip or .cfg.
  • License file: The name is a string of 5 to 120 characters suffixed with .dat, .xml, or .zip. The suffix depends on the license file you apply for.
  • PAT patch file: The name is a string of 5 to 63 characters suffixed with .pat.
  • MOD patch file: The name is a string of 5 to 63 characters suffixed with .MOD.
  • Customized file: The name is a string of 3 to 64 characters.
  • Feature package file: The name is a string of 4 to 120 characters suffixed with .ccx.
  • Batch processing file: The name is a string of 5 to 64 characters suffixed with .bat.

*TYPE_n

Yes

Type of a deployment file. The value is of the enumerated type.

  • SOFTWARE: system software.
  • CFG: configuration file.
  • LIC: license file.
  • PAT: PAT patch file.
  • MOD: MOD patch file.
  • USER: customized file.
  • FEATURE-PLUGIN: feature package file.
  • SCRIPT: batch processing file.

*EFFECTIVE_MODE_n

Yes

Activation mode. The value is of the enumerated type.

  • 0: activated upon restart, which applies to the system software, configuration file, patch file, module file, batch processing file, and feature package file.
  • 1: activated immediately, which applies to the license file, configuration file, patch file, module file, batch processing file, and feature package file.
  • 2: Activation is not required, which applies to the customized file.

The default activation modes of various deployment files are as follows:

  • The default activation mode of the system software and configuration file is that specified by the value 0 (activated upon a restart).
  • The default activation mode of the patch file, module file, license file, batch processing file, and feature package file is that specified by the value 1 (activated immediately).
  • The default activation mode of the customized file is that specified by the value 2 (activation not required).

If EFFECTIVE_MODE_n is not an enumerated value supported by each type of file and not empty, the default activation mode of each type of file is used.

SAVE_AFTER_SUCCESS

No
Whether to save current configurations to the configuration file after successful deployment. The value is of the enumerated type.
  • 0: A device does not save current configurations to the configuration file after successful deployment.
  • 1: A device restarts and saves current configurations to the configuration file after successful deployment.

The default value is 1.

A device does not check this field if the configuration file activation mode is set to 1 (activated immediately). After being successfully deployed, the device does not save the current configurations to the configuration file.

ISBATCHPROCESS_n

No

Whether to perform batch processing for the license list file. The value is of the enumerated type.

  • 0: no
  • 1: yes

If this field is left empty or set to DEFAULT or a value not 1, batch processing is not performed. The default value is DEFAULT.

NOTE:

Devices can automatically load license files through a license list file, which contains mappings between licenses and device ESNs. A device first downloads the license list file and then downloads and loads the corresponding license file based on the ESN of the master device. The license list file is in XML format and its name must be ztp_license_list. An example of such a file is as follows:

<?xml version="1.0" encoding="utf-8" standalone="yes"?>
<Index formatVersion="1.0">
	<Lic name="LIC_file1.xml" sha256="d27305447dbb1e76ea9c6f27e19be2986503b91d8240612f9ebde708e7d1019e">	
		<LSN>LIC202005183TCG5M</LSN>
		<Esn>102050157695</Esn>
	</Lic>
	<Lic name="LIC_file2.dat" sha256="6a2690e7a08e3df844ba86e1f48dc3c504af3b760dd0e38134771e1024fe1a5f">
		<LSN>LIC202005183TCI50</LSN>
		<Esn>2102311LDL0000000805</Esn>
	</Lic>
</Index>

SHA256_n

No

Verification code corresponding to the SHA256 encryption algorithm, which is used to verify the integrity of a deployment file.

If this field is left empty, the deployment file integrity is not verified.

You can use either of the following methods to generate a SHA256 verification code for a deployment file:

  1. Use the SHA256 calculation tool, such as HashMyFiles.
  2. Run the certutil -hashfile filename SHA256 command supported by the Windows operating system.

;END ZTP CONFIG

Yes

End flag of a file. This field cannot be modified.
