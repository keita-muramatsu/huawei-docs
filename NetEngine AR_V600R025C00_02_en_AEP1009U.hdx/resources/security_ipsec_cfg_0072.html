Configuring PKI Certificate Whitelist Check

Prerequisites

  • PKI certificate whitelist check takes effect only for RSA-based digital signature certificate authentication.
  • PKI certificate whitelist check takes effect only for the following IPsec types:
    • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
    • Route-based IPsec (involving IPsec profiles)
  • Ensure that the certificate whitelist file exists in the device storage medium and has been imported to the device memory. For details, see "Configuring a Certificate Whitelist to Implement Access Control" in CLI Configuration Guide > Security Configuration > PKI Configuration > Authenticating The Peer Entity's Certificate.

Context

In LTE scenarios, when the device uses RSA signature authentication to establish IPsec tunnels with multiple base stations, you can configure a certificate whitelist and enable PKI certificate whitelist check to centrally manage the certificates of base stations. That is, you can specify which base stations are allowed to establish IPsec tunnels with the device.

A certificate whitelist contains a set of common names (CNs) in the certificate subject of base stations. The certificate whitelist file is in XML format and uses 7-bit ASCII encoding. The following example is a certificate whitelist file, which contains two CNs:

<SerialnumberList> 
<Serialnumber>CN-on-Certificate_of-RBS-1</Serialnumber> 
<Serialnumber>CN-on-Certificate_of-RBS-2</Serialnumber> 
</SerialnumberList>

After PKI certificate whitelist check is enabled, the local device checks whether the CN in the certificate subject of the remote device carried in the received certificate authentication packet is the same as that in the local certificate whitelist. If not, authentication fails and no IPsec tunnel can be established between the two devices.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the IKE peer view.

    ike peer peer-name

  3. Enable PKI certificate whitelist check.

    pki validate-certificate whitelist enable

    By default, PKI certificate whitelist check is disabled.

  4. Optional: Enable fuzzy match for the PKI certificate whitelist.

    pki whitelist-fuzzy-match enable

    By default, the PKI certificate whitelist supports exact match. That is, the local device checks whether the CN in the certificate subject of the remote device carried in the received certificate authentication packet is the same as that in the local certificate whitelist. If not, authentication fails.

    In some scenarios, however, the CN in a certificate subject contains dots (.), such as 123.huawei.com, but the CN in the certificate whitelist does not, such as 123. In this case, the CN in the certificate subject of the remote device does not exactly match that in the local certificate whitelist, leading to an authentication failure. To prevent this problem, run this command to enable fuzzy match for the PKI certificate whitelist. The local device then matches the content before the first dot in the received CN against that in the local certificate whitelist. If they match, authentication is successful.
