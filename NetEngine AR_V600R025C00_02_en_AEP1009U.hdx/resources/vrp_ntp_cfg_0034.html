Configuring KOD on the Server

Context

Kiss-o'-Death (KOD) is a modern access control technology implemented in NTPv4 and is used by the server to provide information, such as status reports and access control, to the client.

After the KOD function is enabled on the server, the server sends the kiss code DENY or RATE to the client according to the operating status of the system.

  • When receiving the kiss code DENY, the client terminates all connections to the server, and stops sending packets to the server.
  • When receiving the kiss code RATE, the client immediately reduces its polling interval to the server. The client will continue to reduce the interval if it receives subsequent RATE kiss codes.

KOD cannot be used in broadcast or multicast mode.

KOD applies only to NTPv4.

The following configuration is performed on the server.

Procedure

  1. Enter the system view.

    system-view

  2. Enable KOD.

    ntp kod-enable

    By default, KOD is disabled.

  3. (Optional) Configure access control authority.

    ntp access { peer | query | server | synchronization | limited } { { acl-number | acl-name aclname } [ ipv6 { acl6-number | acl6-name acl6name } ] | ipv6 { acl6-number | acl6-name acl6name } [ { acl-number | acl-name aclname } ] }

    By default, no access control authority is configured.

    Before enabling control on the rate of incoming NTP packets, check the ACL rule configuration. When the ACL rule is configured as deny, the server sends the kiss code DENY. When the ACL rule is configured as permit and the number of NTP packets received reaches the upper limit, the server sends the kiss code RATE.

  4. (Optional) Configure the minimum and average intervals for receiving NTP packets.

    ntp discard { min-interval min-interval-val | avg-interval avg-interval-val } *

    By default, the minimum interval for sending NTP packets is 2 (2 to the power of 1) seconds, and the average interval is 32 (2 to the power of 5) seconds.
