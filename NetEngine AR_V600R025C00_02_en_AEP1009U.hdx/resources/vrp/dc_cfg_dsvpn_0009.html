Configuring DSVPN over IPsec

Prerequisites

Before configuring DSVPN over IPsec, you have completed the following task:

  • Configure basic DSVPN functions. For details, see Configuring Basic DSVPN Functions.

Context

Data transmitted between the hub and spokes, as well as between spokes, needs to be encrypted to increase data security. To meet this requirement, consider binding an IPsec profile to DSVPN during DSVPN deployment, so that mGRE and IPsec tunnels are dynamically established between spokes.

For security purposes, you are advised not to use weak security algorithms in this feature.

In a DSVPN over IPsec scenario, if a NAT device is deployed, you are advised to set the IPsec encapsulation mode to transport. If two spokes are situated behind different NAT devices or the hub is situated behind a NAT device, the IPsec encapsulation mode can only be transport.

Procedure

  1. Configure an IKE proposal. For details, see "Configuring an IKE Proposal" in CLI Configuration Guide > VPN Configuration > IPsec Configuration > Configuring IKE Negotiation.
  2. Configure an IKE peer. For details, see "Configuring an IKE Peer" in CLI Configuration Guide > VPN Configuration > IPsec Configuration > Configuring IKE Negotiation.

    There is no need to configure a peer ID or peer IP address in DSVPN.

  3. Configure an IPsec proposal. For details, see "Configuring an IPsec Proposal" in CLI Configuration Guide > VPN Configuration > IPsec Configuration.
  4. Configure an IPsec profile.
    1. Enter the system view.

      system-view

    2. Create an IPsec profile and enter the IPsec profile view.

      ipsec profile profile-name

    3. Reference an IPsec proposal.

      proposal proposal-name

    4. Reference an IKE peer.

      ike-peer peer-name

    5. (Optional) Configure the perfect forward secrecy (PFS) feature to be used when the local end initiates negotiation.

      pfs { dh-group1 | dh-group2 | dh-group5 | dh-group14 | dh-group15 | dh-group16 | dh-group18 | dh-group19 | dh-group20 | dh-group21 | dh-group24 }

      By default, PFS is not used when the local end initiates IPsec tunnel negotiation.

      If PFS is specified at the local end, you also need to specify PFS at the peer end. The Diffie-Hellman (DH) groups specified on the two ends must be the same. Otherwise, the negotiation fails.

    6. Exit the IPsec profile view.

      quit

  5. Apply the IPsec profile.
    1. Enter the tunnel interface view.

      interface tunnel interface-number

    2. Apply the IPsec profile to the tunnel interface.

      ipsec profile profile-name [ shared ]

      • A tunnel interface can have only one IPsec profile applied. Before applying another IPsec profile to the tunnel interface, run the undo ipsec profile command to unbind the existing IPsec profile from the tunnel interface.
      • If the parameter shared is not specified, an IPsec profile can be applied to only one tunnel interface. Before applying the IPsec profile to another interface, unbind the IPsec profile from the tunnel interface.
      • If the parameter shared is specified, an IPsec profile can be applied to a maximum of 64 tunnel interfaces.

        If multiple tunnel interfaces share the same outbound interface, you must apply the same IPsec profile to and specify the parameter shared for all these tunnel interfaces. Otherwise, the two ends cannot establish an IPsec tunnel.
