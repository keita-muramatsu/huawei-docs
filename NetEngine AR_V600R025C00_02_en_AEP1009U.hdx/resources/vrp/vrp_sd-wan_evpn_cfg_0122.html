Configuring DTLS

Context

In an SD-WAN EVPN scenario, a DTLS connection needs to be established between a CPE and an RR so that a management channel can be established for their information exchange. In Figure 1, the RR functions as the DTLS server, and the CPEs functions as DTLS clients.

Figure 1 DTLS management channel

For security purpose,you are not advised to use the weak security algorithm or weak security protocols provided by this feature. If you need to use the weak security algorithm or protocols, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA. By default, the device provides the weak security algorithm or protocol feature package WEAKEA. For details about how to install or uninstall the feature package, see "Upgrade Maintenance Configuration" in CLI Configuration Guide > System Management Configuration.

Procedure

  • Configure the RR as the DTLS server.

    1. Enter the system view.
      system-view
    2. Enter the DTLS server view.
      dtls server
    3. Enable the DTLS server function.
      dtls server enable

      By default, the DTLS server function is disabled.

    4. Configure an IP address checked by the DTLS server.
      listening-ip ip-address [ vpn-instance vpn-instance-name ]
listening-ipv6 ipv6-address [ vpn-instance vpn-instance-name ]

      By default, no IP address is checked by the DTLS server.

    5. Configure a port number checked by the DTLS server.
      listening-port port

      By default, no port number is checked by the DTLS server.

    6. (Optional) Configure a PKI realm for the DTLS server.
      pki-realm pki-realm-name

      By default, there is a PKI realm named default on the device. This realm can be modified, but not deleted.

    7. (Optional) Configure the cipher suite used by the DTLS server.
      cipher-suite { ecdhe_rsa_aes128_gcm_sha256 | ecdhe_rsa_aes256_gcm_sha384 | rsa_aes_128_sha256 } *

      By default, the DTLS server uses cipher suites of ecdhe_rsa_aes128_gcm_sha256 and ecdhe_rsa_aes256_gcm_sha384.

      The rsa_aes_128_sha256 parameter can be used only after the weak security algorithm or protocol plug-in is installed.

    8. (Optional) Configure the packet fragment size of the DTLS server.
      packet-length length

      By default, the packet fragment size of the DTLS server is not configured.

  • Configure the CPEs as DTLS clients.

    1. Enter the system view.
      system-view
    2. Enter the DTLS client view.
      dtls client
    3. Configure a connection between the DTLS client and DTLS server.
      peer system-id system-id [ vpn-instance vpn-instance-name ] { ip ip-address | ipv6 ipv6-address } port port

      By default, no connection is configured between the DTLS client and DTLS server.

    4. (Optional) Configure a PKI realm for the DTLS client.
      pki-realm pki-realm-name

      By default, there is a PKI realm named default on the device. This realm can be modified, but not deleted.

    5. (Optional) Configure the cipher suite used by the DTLS client.
      cipher-suite { ecdhe_rsa_aes128_gcm_sha256 | ecdhe_rsa_aes256_gcm_sha384 | rsa_aes_128_sha256 } *

      By default, the DTLS client uses cipher suites of ecdhe_rsa_aes128_gcm_sha256 and ecdhe_rsa_aes256_gcm_sha384.

    6. (Optional) Configure the packet fragment size of the DTLS client.
      packet-length length

      By default, the packet fragment size of the DTLS client is not configured.
