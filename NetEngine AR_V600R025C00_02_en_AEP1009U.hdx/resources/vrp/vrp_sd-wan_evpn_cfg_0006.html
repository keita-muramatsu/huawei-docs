Establishment of an SD-WAN Data Channel

Channel Establishment Process

In Establishment of a BGP SD-WAN Control Channel, an RR reflects BGP SD-WAN routes between CPEs so that CPEs can obtain necessary information such as TNPs and SA parameters required to establish SD-WAN data channels from each other. The following describes the process of establishing an SD-WAN data channel to transmit service traffic, as shown in Figure 1.

  1. Each CPE establishes a BGP EVPN peer relationship with the RR.
  2. Each CPE generates an EVPN IP prefix route (Type 5 route) based on the route of the VPN instance for the local user service. This IP prefix route contains the NLRI, SD-WAN encapsulation extended community attribute, and color extended community attribute (containing Site ID).
  3. Each CPE sends the IP prefix route to the RR, which then reflects the route to other CPEs.
  4. After receiving a reflected IP prefix route, a CPE obtains the SD-WAN encapsulation extended community attribute and color extended community attribute (containing Site ID) carried in the route and triggers the establishment of an SD-WAN data channel with the peer CPE. Information such as the TNP and SA parameters is used for channel encapsulation. In addition, the IP prefix route recurses to the SD-WAN data channel based on Site ID to establish the service traffic forwarding path.
Figure 1 Process of establishing an SD-WAN data channel

EVPN Routes

In the SD-WAN EVPN Solution, service routes are EVPN IP prefix routes. These routes contain the NLRI, SD-WAN encapsulation extended community attribute, and color extended community attribute. The VN ID that identifies the VPN instance to which an EVPN IP prefix route belongs is carried in NLRI. Figure 2 shows the NLRI format of an EVPN IP prefix route.

Other Functions

In an SD-WAN EVPN scenario, a routing policy can be used to adjust information including the color extended community attribute and next hop carried in EVPN routes so as to control and orchestrate service paths. Currently, the following application scenarios are supported:

Isolating Tenants

Carriers provide SD-WAN EVPN services for different enterprises, each considered as a tenant. In Figure 5, CPE1 and CPE2 belong to tenant 1, CPE3 and CPE4 belong to tenant 2, and the RR is shared by multiple tenants. In this example, you need to configure a routing policy on the RR so it can reflect EVPN routes of a specific CPE of a tenant to other CPEs of the same tenant. This policy implements service communication between CPEs of the same tenant and service isolation between CPEs of different tenants. The following describes the routing policy configuration on the RR:

  1. Add CPE1 and CPE2 to the BGP EVPN peer group Group1, and add CPE3 and CPE4 to the BGP EVPN peer group Group2.
  2. Configure the import policy Group1_in and export policy Group1_out for the peer group Group1 on the RR. The Group1_in policy sets the community attribute 100:1 for EVPN routes that are received by the RR. The Group1_out policy allows the RR to advertise only EVPN routes carrying the community attribute 100:1.
  3. Configure the import policy Group2_in and export policy Group2_out for the peer group Group2 on the RR. The Group2_in policy sets the community attribute 200:2 for EVPN routes that are received by the RR. The Group2_out policy allows the RR to advertise only EVPN routes carrying the community attribute 200:2.
Figure 5 Tenant isolation scenario

Adding a Redirect Site

A redirect site can be added between two sites to improve reliability. When the SD-WAN tunnel between the two sites is not operational, service traffic can be directed to the redirect site to prevent service interruptions. In Figure 6, redirect site 100 is added between site 1 and site 2. CPE3 establishes two SD-WAN tunnels, one with CPE1 and one with CPE2. The following describes the routing policy configuration on the RR:

  1. Configure the export policy Evpn_export_policy.
  2. Set the matching condition for the export policy: EVPN routes carry the route target (RT) value of the VPN instance for the user service on CPE2 and carry the color value of site 2.
  3. Add the color value of the redirect site 100 to the matching EVPN route. The priority of the color value of the redirect site is lower than that of the primary path.
Figure 6 Redirect site scenario

After CPE2 sends the local EVPN route to the RR, the RR adds the color value of the redirect site 100 to the route based on the routing policy before reflecting the route to CPE1. When the primary path between CPE1 and CPE2 is operational, the EVPN route on CPE1 recurses to the SD-WAN tunnel on the primary path based on the color value of site 2. When the primary path is not operational, the EVPN route recurses to the SD-WAN tunnel of the best-effort path based on the color value of the redirect site 100.

Directing Traffic to a Hub Site

If you want all service traffic on the network to pass through a specific hub site, you can configure a routing policy on the RR. On the network shown in Figure 7, service traffic on CPE1 and CPE2 needs to be forwarded through the HUB-CPE. The following describes the routing policy configuration on the RR:

  1. Configure the export policy Evpn_export_policy.
  2. Set the matching condition for the export policy: EVPN routes carry the RT values of the VPN instances for the user services on CPE1 and CPE2 and carry the color value of site 1 or 2.
  3. Enable the RR to change the next hops of the matching EVPN routes to the system IP of the HUB-CPE and change the color value carried in the routes to the color value of the hub site.
