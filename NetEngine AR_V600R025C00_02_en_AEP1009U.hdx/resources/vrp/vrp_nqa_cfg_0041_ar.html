Example for Configuring an NQA Test to Check MPLS Network Connectivity

Networking Requirements

On the MPLS network shown in Figure 1, PE1 and PE2 are edge devices. An NQA test can be configured to periodically check the connectivity between PE1 and PE2.

Figure 1 Networking diagram of configuring an NQA test to check MPLS network connectivity

In this example, interface 1 and interface 2 represent 10GE 0/0/1 and 10GE 0/0/2, respectively.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Create an LSP ping test instance on PE1.

  2. Start the test instance.

Data Preparation

To complete the configuration, you need the following data:

  • IP addresses of PEs and P

Procedure

  1. Create an LSP ping test instance.

    <HUAWEI> system-view
[HUAWEI] sysname PE1
[PE1] nqa test-instance admin lspping
[PE1-nqa-admin-lspping] test-type lspping
[PE1-nqa-admin-lspping] lsp-type ipv4
[PE1-nqa-admin-lspping] destination-address ipv4 3.3.3.9 lsp-masklen 32
[PE1-nqa-admin-lspping] frequency 20

  2. Start the test instance.

    [PE1-nqa-admin-lspping] start now

Verifying the Configuration

Check the LSP ping test result.
[PE1-nqa-admin-lspping] display nqa results test-instance admin lspping

Configuration Scripts

  • PE1
    #
sysname PE1
#
vlan batch 100
#
mpls lsr-id 1.1.1.9
#
mpls
#
mpls ldp
#
interface Vlanif100
 ip address 10.1.1.1 255.255.255.0
 mpls
 mpls ldp
#
interface 10GE0/0/1
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 100
#
interface LoopBack1
 ip address 1.1.1.9 255.255.255.255
#
ospf 1
 area 0.0.0.0
  network 10.1.1.0 0.0.0.255
  network 1.1.1.9 0.0.0.0
#
nqa test-instance admin lspping
 test-type lspping
 destination-address ipv4 3.3.3.9 lsp-masklen 32
 frequency 20
#
return
