DSVPN in Hierarchical Hub Networking

Figure 1 shows the DSVPN topology of an enterprise with hierarchical organizations. On such a hierarchical DSVPN network, some intermediate nodes act as both spokes and hubs. For example, Hub1 and Hub2 act as hubs for downstream spokes and as spokes for Hub in the HQ. According to the service plan, some spokes communicate with Hub1 whereas some with Hub2.

The principle of establishing a dynamic mGRE tunnel between spokes of the same hub (Hub1 or Hub2) is the same as that in DSVPN Fundamentals. When a spoke of Hub1 needs to set up a dynamic mGRE tunnel with a spoke of Hub2, the source spoke sends an NHRP Resolution Request message to Hub1. Hub1 sends the NHRP Resolution Request message to Hub2 through Hub in the HQ, and Hub2 forwards this message to the destination spoke. As such, a dynamic mGRE tunnel is set up between the spokes.

On a DSVPN network with hierarchical hubs, spokes can learn routes from each other in shortcut mode only.

During DSVPN deployment, two tunnel interfaces need to be created on Hub1 and Hub2, one for building a static mGRE tunnel with Hub in the HQ and the other for building static mGRE tunnels with their respective spokes. Hub1 and Hub2 function as spokes for Hub in the HQ.
