Configure a BGP EVPN Peer

Prerequisites

Before configuring a BGP EVPN peer on an RR, create a route-policy to change the next-hop address of the EVPN routes (reflected by the RR to a CPE) to the RR's IP address so that the route-policy can be applied to the outbound direction during BGP EVPN peer configuration.

system-view
route-policy route-policy-name matchMode node node
apply ip-address next-hop address

In an SD-WAN EVPN scenario, no direct public network routes exist between CPEs. If the RR directly reflects an EVPN route to a CPE, the route will be inactive because no reachable next hop is available. To prevent this, configure a route-policy on the RR to change the next-hop address of the EVPN route to the RR's address. In this case, there are public network static routes between the CPE and RR (meeting the prerequisite for configuring a BGP SD-WAN peer), and the EVPN route is active after reaching the CPE.

Context

As shown in Figure 1, after the CPE at each site obtains TNP information of the peer end, you need to configure a BGP EVPN peer relationship between the CPE and RR. In this way, the local IP prefix routes (VPN routes of user services) of each CPE are reflected by the RR to other CPEs, which triggers the establishment of an SD-WAN tunnel for forwarding service data between CPEs and establishes the data channel of the underlay network. In addition, the IP prefix routes finally recurse to the SD-WAN tunnel, establishing service paths on the overlay network.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the BGP view.

    bgp as-number

  3. Enable the BGP EVPN address family and enter its view.

    l2vpn-family evpn

  4. Enable the capability of exchanging routing information with a specified peer in the BGP EVPN address family view.

    peer ipv4-address enable

    In this example, you need to enable the capability of exchanging BGP EVPN routes with the peer end in the BGP EVPN address family view of the CPE and RR.

    By default, the ability to exchange EVPN routes with a peer or peer group is automatically enabled only in the BGP-IPv4 unicast address family.

  5. Set the encapsulation attribute carried in the IP prefix routes advertised to a BGP EVPN peer to SD-WAN.

    peer ipv4-address advertise encap-type { sd-wan }

    By default, the EVPN routes advertised by the local device to a peer carry the VXLAN encapsulation attribute.

    Set the encapsulation attribute carried in the IP prefix routes advertised to a BGP EVPN peer to SD-WAN in the BGP-EVPN address family on both the CPE and RR.

  6. Configure the local device as an RR and specify the CPE as the RR client.

    peer peerIpv4Addr reflect-client

    Perform this step on the RR. This step is not required on the CPE.

    By default, the RR and its clients are not configured.

  7. Disable VPN target filtering for EVPN routes on the RR.

    undo policy vpn-target

    The RR does not need to be configured with VPN instances for user services. To prevent the RR from discarding EVPN routes due to RT mismatch, you need to perform this step on the RR.

    By default, VPN target-based filtering is enabled for VPN routes.

  8. Configure an export policy on the RR.

    peer peerIpv4Addr route-policy policy-name export

    Configure the route-policy created in the prerequisites as the export policy, and change the next-hop address of the EVPN routes reflected by the RR to the CPE to the RR's IP address. For details about how to use an export policy to modify other route attributes, see the optional functions in Step 10.

    By default, no route-policy is specified for a peer. That is, no route-policy is applied to the routes to be advertised to a peer.

  9. Enable the RR to modify the path attributes of BGP routes using an export policy.

    reflect change-path-attribute

    By default, an RR cannot modify path attributes of BGP routes using an export policy. To enable the RR to change the next-hop address of the EVPN routes reflected to the CPE to the RR's IP address using an export policy, perform this step on the RR.

  10. Configure optional functions in the BGP EVPN address family as required.

    Table 1 Optional functions supported by the BGP EVPN address family

    Function

    Command

    Remarks

    Enable next hop recursion of EVPN routes to default routes.

    nexthop recursive-lookup default-route

    This function is applicable only to CPEs.

    Due to a fault or configuration error, EVPN routes may fail to recurse to SD-WAN tunnels because the routes are unreachable, resulting in service interruptions. To prevent this, configure this function on the local CPE and configure the remote CPE to send a default route to the local CPE. In this way, if the next hop of a specific route on the local CPE is unreachable, services can recurse to the default route and then to an SD-WAN path for forwarding, ensuring service continuity.

    By default, next hop-based recursion to the default route is disabled.

    Add a specified BGP EVPN peer to a peer group.

    peer ipv4-address group group-name

    peer group-name enable

    To improve configuration efficiency, you can add multiple BGP EVPN peers that have the same policy applied to a peer group. Then, you only need to configure BGP EVPN peers based on the peer group.

    Set the encapsulation attribute carried in the IP prefix routes advertised to a BGP EVPN peer group to SD-WAN.

    peer group-name advertise encap-type { sd-wan }

    -

    Configure a specified BGP EVPN peer group as an RR client.

    peer peerGroupName reflect-client

    This function is applicable only to RRs.

    Apply a specified route-policy to the routes to be advertised to a BGP EVPN peer or peer group.

    peer peerIpv4Addr route-policy route-policy-name export

    peer peerGroupName route-policy route-policy-name export

    Before configuring this function, you need to create a route-policy using policy-name and modify route attributes in the route-policy.

    Apply a specified route-policy to the routes received from a BGP EVPN peer or peer group.

    peer peerIpv4Addr route-policy route-policy-name import

    peer peerGroupName route-policy route-policy-name import

    Before configuring this function, you need to create a route-policy using policy-name and modify route attributes in the route-policy.

    Allow advertising community attributes to a BGP EVPN peer or peer group.

    peer peerIpv4Addr advertise-community

    peer peerGroupName advertise-community

    Before configuring this function, you need to create a route-policy, set the community attributes of routes, and apply the route-policy when configuring route advertisement.

    By default, a device does not advertise community attributes to any peer or peer group.

    Set the preferred value for a BGP EVPN peer or peer group.

    peer peerIpv4Addr preferred-value preferredvalue

    peer peerGroupName preferred-value preferredvalue

    -

    Set a cluster ID for the RR.

    reflector cluster-id { cluster-id-value | cluster-id-ipv4 }

    This function is applicable only to RRs.

    When multiple RRs are configured in a cluster, you need to set the same cluster ID for all of the RRs to identify the cluster and prevent routing loops.

    By default, each RR uses its own router ID as the cluster ID.

    Set the maximum hold-off time for the local device to wait for GR recovery on the peer end.

    peer ipv4-address graceful-restart static-timer restart-time
    Two methods are available to set the hold-off time for re-establishing BGP EVPN peer relationships:

    • Run the graceful-restart timer restart command in the BGP view. The maximum hold-off time supported by this command is 3600s.

    • Run the peer graceful-restart static-timer command in the BGP EVPN address family view. This command allows you to set a hold-off time greater than 3600s.

    By default, the maximum duration from the time when the local end detects the restart of the peer end to the time when the local end reestablishes the BGP EVPN session is 150 seconds.

    If both methods are used, the latter takes precedence.

    NOTE:

    This function can be configured only after GR has been enabled in the BGP view.

    Configure the device to lower the priorities of routes received from a peer in GR state.

    route-lowest-priority graceful-restart

    When GR is enabled on the local device and the peer from which the optimal route is received restarts, the peer enters the GR state and the local device retains the routes received from that peer. In this situation, by default, the traffic steering rules remain unchanged and the retained routes continue to be preferred. As a result, traffic is not switched to other paths, leading to packet loss. To solve this problem, you can run the route-lowest-priority graceful-restart command on the local device to lower the priorities of routes received from a peer in GR state. When this command is configured and routes are imported from the EVPN address family into a BGP VPN instance, the priorities of those imported routes are also reduced accordingly.

    NOTE:

    This function takes effect only when GR is enabled on the local device and the peer is in the GR state. For details about how to enable GR, see Enabling GR for BGP Peers.

    Set the maximum number of routes that can be accepted from a BGP EVPN peer or peer group.

    peer peerIpv4Addr route-limit limit [ percentage ] [ alert-only | idle-forever | idle-timeout times ]

    peer peerGroupName route-limit limit [ percentage ] [ alert-only | idle-forever | idle-timeout times ]

    By default, there is no limit on the number of routes that can be received from a peer or peer group.

    Set the interval for sending Update packets with the same route prefix to a BGP EVPN peer or peer group.

    peer peerIpv4Addr route-update-interval interval

    peer peerGroupName route-update-interval interval

    By default, a device sends Update messages to IBGP peers at an interval of 15s and to EBGP peers at an interval of 30s.

    Disable BGP EVPN slow peer detection.

    slow-peer absolute-detection disable

    By default, BGP EVPN slow peer detection is enabled.

    Set the BGP EVPN slow peer detection threshold.

    slow-peer absolute-detection threshold absolute-threshold-value

    By default, the BGP EVPN slow peer detection threshold is 60s.

    Set the delay in responding to next hop recursion changes of BGP EVPN routes.

    nexthop recursive-lookup delay [ delay-time ]

    nexthop recursive-lookup non-critical-event delay [ nonCrit-delay-time ]

    If the next hop recursion of BGP EVPN routes changes frequently, you can set the delay in responding to the change, which reduces unnecessary route re-selection and re-advertisement.

    Allow the local AS number to be contained in the AS_Path attribute of the route sent by a BGP EVPN peer or peer group. You can also set the number of times that the local AS number can be repeated in the AS_Path attribute.

    peer ipv4-address allow-as-loop [ number ]

    peer peerGroupName allow-as-loop [ number ]

    By default, local AS number repetition is not allowed.
