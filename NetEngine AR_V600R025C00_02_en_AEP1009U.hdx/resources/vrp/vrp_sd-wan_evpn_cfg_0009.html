Configuring a VPN Instance

Prerequisites

Before configuring a VPN instance, you need to create a route-policy and set the color value and priority for EVPN routes to apply the route-policy to the outbound direction when configuring the VPN instance.

system-view
route-policy route-policy-name matchMode node node
apply extcommunity priority-color { extCmntyValue } &<1-16>

Context

SD-WAN EVPN is a VPN solution that separates the overlay service network from the underlay transport network. On the overlay network, you need to configure VPN instances for user services on CPEs at sites and enable the VPN instances to advertise EVPN IP prefix routes so that the IP prefix routes become VPN routes for user services.

Procedure

  1. Enter the system view.

    system-view

  2. Create a VPN instance and enter the VPN instance view.

    ip vpn-instance vpn-instance-name

  3. Bind a VN ID to the VPN instance.

    vn-id vn-identifier

    For the same VPN instance, ensure that different CPEs have the same VN ID so that services of the same user can be forwarded properly.

    By default, no VN ID is bound to a VPN instance.

  4. Enable the VPN instance IPv4 or IPv6 address family and enter its view.

    • Enter the IPv4 address family view.
      ipv4-family
    • Enter the IPv6 address family view.
      ipv6-family

  5. Configure an RD.

    route-distinguisher route-distinguisher

    By default, no RD is configured for a VPN instance.

  6. Configure VPN targets for EVPN routes.

    vpn-target { vpn-target } &<1-8> [ vrfRtType ] evpn

    When the local CPE advertises EVPN IP prefix routes to other CPEs, all VPN targets in the export VPN target list configured in this step must be carried in the routes. IP prefix routes received by the local CPE can be leaked to the routing table of the local VPN instance only when the VPN targets carried in the routes overlap with those in the import VPN target list configured in this step.

    By default, no VPN targets for EVPN routes are configured for the IPv4/IPv6 address family of a VPN instance.

  7. Configure an export policy for the VPN instance and apply the policy to the EVPN routes advertised by the VPN instance.

    export route-policy policy-name [ add-ert-first ] evpn

    If you want to set the color attribute for EVPN routes on the CPE, perform this step and set the route-policy configured in the prerequisites as the export policy of the VPN instance.

    By default, export VPN targets are added to VPN routes after these routes are matched against an export route-policy. If the export route-policy contains VPN target-related filtering rules, it cannot apply to VPN routes. If you want to apply the VPN target-related filtering rules defined in an export route-policy to VPN routes, configure the add-ert-first parameter for the device to add export VPN targets to VPN routes before matching these routes against the export route-policy.

  8. Return to the VPN instance view.

    quit

  9. Return to the system view.

    quit

  10. Enter the view of the interface to be bound to the VPN instance.

    interface interface-type interface-number

  11. Bind the interface to the VPN instance.

    ip binding vpn-instance vpn-instance-name

    After this step is performed, Layer 3 features (including IPv4 and IPv6 features) configured on the interface, such as the IP address and routing protocol, will be deleted. If necessary, reconfigure them.

  12. Return to the system view.

    quit

  13. Enter the BGP view.

    bgp as-number

  14. Enter the BGP-VPN instance IPv4 or IPv6 address family view.

    • Enter the IPv4 address family view.
      ipv4-family vpn-instance vpn-instance-name
    • Enter the IPv6 address family view.
      ipv6-family vpn-instance vpn-instance-name

  15. Import direct routes into the BGP-VPN instance IPv4 address family.

    import-route direct [ med med | route-policy route-policy-name ] *

    User-side devices are directly connected to the CPE. To generate VPN routes for user services, direct routes need to be imported into the BGP-VPN instance IPv6 address family.

  16. Enable the function of advertising EVPN IP prefix routes of the VPN instance.

    advertise l2vpn evpn [ best-route | valid-routes ]

    After the advertise l2vpn evpn command is run, the CPE advertises all VPN routes (including invalid and non-optimal routes) of the VPN instance for user services to the BGP EVPN peer in the format of IP prefix routes. To prevent invalid routes from being advertised, specify the valid-routes parameter. If you want to advertise only the optimal VPN routes, specify the best-route parameter.

    By default, a VPN instance is disabled from advertising EVPN IP prefix routes.
