SD-WAN EVPN Fundamentals

Key Components and Channels

In Figure 1, SD-WAN EVPN involves the following key components:

  • Route reflector (RR): distributes BGP EVPN routes and SD-WAN tunnel information between customer-premises equipment (CPE) devices. In the current solution, an RR is usually used as a regional controller.
  • CPE: establishes an SD-WAN data channel based on the routes reflected by the RR and tunnel information carried in the routes, and forwards service traffic.
Figure 1 SD-WAN EVPN architecture

In the SD-WAN EVPN architecture, each pair of RR and CPE establish a Datagram Transport Layer Security (DTLS) management channel with each other. Then, the RR and CPE establish a BGP SD-WAN control channel. Finally, CPEs establish an SD-WAN data channel with each other. The following describes these channels:

  • DTLS management channel: established between each pair of CPE and RR to notify each other of the parameters required for establishing an SD-WAN tunnel.
  • SD-WAN tunnel: is an SD-WAN overlay tunnel that uses the dedicated SD-WAN tunneling protocol. For two sites to be able to communicate with each other, a tunnel needs to be established between them. At both ends of the tunnel are the WAN interfaces of the CPEs at the two sites, and these WAN interfaces can communicate at the underlay network layer. The two sites can be interconnected through networks of different carriers, allowing them to establish multiple tunnels with each other. Packets of BGP SD-WAN control channels and SD-WAN data channels are forwarded through SD-WAN tunnels.
  • BGP SD-WAN control channel: established between the CPE and RR to exchange BGP packets. The CPE uses the BGP SD-WAN control channel to advertise local network information and service routes to the RR, which then reflects the network information and service routes to other CPEs.
  • SD-WAN data channel: established between CPEs to forward Layer 3 service traffic after the CPEs learn network information and service routes from each other through the RR.

Basic Concepts

The SD-WAN EVPN Solution involves the following basic concepts:

  • Transport network (TN): a WAN network provided by carriers, including MPLS networks and the Internet. TN is the network foundation for the SD-WAN EVPN Solution.

  • Transport network port (TNP): a special WAN interface for a CPE to access a TN. Key TNP information includes the Site ID, Transport Network-ID, Public IP, Private IP, and Tunnel Encapsulation.

  • Site ID: a globally unique identifier of a site on an SD-WAN EVPN network. Generally, a site ID is a string of digits.

  • Site system ID: a globally unique identifier of a site device on an SD-WAN EVPN network. A site usually contains one or two devices. Generally, a site system ID is a device's loopback IP address.

  • Security association (SA): An SA defines elements for secure communication between two IPsec peers using security services (such as encryption). The elements include security protocols, characteristics of data flows to be protected, encapsulation modes of data transmitted between peers, encryption and authentication algorithms, and lifetimes of keys (used for secure data conversion and transmission) and SAs.

  • Routing domain: defines whether reachable routes exist between physical links for different TNs. In most cases, if the TNs that are of the same type and provided by different carriers can communicate with each other, these TNs are in the same routing domain.

SD-WAN EVPN Implementation

The following uses CPE1 as an example to describe SD-WAN EVPN implementation shown in Figure 2:

  1. CPE1 initiates DTLS registration with the RR to establish a DTLS management channel with the RR. Through this channel, CPE1 notifies the RR of its TNP and SA information to establish an SD-WAN tunnel with the RR.
  2. The RR notifies CPE1 of its TNP and SA information through the DTLS management channel to establish an SD-WAN tunnel with CPE1.
  3. CPE1 and the RR exchange BGP messages through the SD-WAN tunnel to establish a BGP SD-WAN peer relationship using their site system IDs (system-ip-1 of CPE1 and system-ip-rr of the RR).
  4. CPE1 generates a BGP SD-WAN route based on its TNP information (including the TNP IP address used as the interface address of the SD-WAN data channel) and SA parameters required to establish an SD-WAN data channel, and sends the route to the RR. In addition, CPE1 generates a BGP EVPN IP prefix route based on a user-side service route it has learned, and sends the IP prefix route to the RR. The IP prefix route has the site system ID of CPE1 (system-ip-1) as its next-hop address and carries the priority-color extended community attribute.
  5. The RR reflects the received BGP SD-WAN route to CPE2 and CPE3. Through this route, CPE2 and CPE3 obtain the TNP information of CPE1 and SA parameters required to establish the SD-WAN data channel. Additionally, the RR reflects the received IP prefix route to CPE2 and CPE3. Through this route, CPE2 and CPE3 obtain the site information of CPE1 and trigger the establishment of an SD-WAN data channel with CPE1.
