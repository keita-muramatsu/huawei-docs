Configuring an HTTP Test

Prerequisites

  • Before configuring an HTTP test, you need to configure the DNS client function, including enabling dynamic domain name resolution and configuring the IP address of the DNS server to be accessed. For details, see "Configuring a DNS Test".
  • If HTTPS is used for an HTTP test, ensure that an SSL policy has been created. For details, see "SSL Configuration" in CLI Configuration Guide > Security Configuration.

Context

An HTTP test checks whether a client can set up a connection with a specified HTTP server and measures the time taken to set up such a connection.

Figure 1 shows a network on which an HTTP test is performed. The HTTP test obtains the respond speed in three phases:

  • DNS resolution time: indicates the duration between the time when DeviceA sends a DNS packet to the DNS server and the time when the DNS server sends back to DeviceA a DNS resolution packet containing an IP address resolved from the HTTP server domain name.
  • TCP connection setup time: indicates the time that DeviceA takes to set up a TCP connection with the HTTP server through three-way handshake.
  • HTTP transaction time: indicates the duration between the time when DeviceA sends a Get or Post packet to the HTTP server and the time when a response packet reaches DeviceA.
Figure 1 HTTP test networking

Through an HTTP test, the following information can be calculated based on the packets from the client:

  • Minimum, maximum, and total time of DNS resolution
  • Minimum, maximum, and total time taken to set up a TCP connection
  • Minimum, maximum, and total HTTP transaction time

The HTTP test results and historical records are collected in test instances, which can be checked using commands.

Currently, only the HTTP operation of the Get type is supported.

Procedure

  1. Enter the system view.

    system-view

  2. Create an NQA test instance and set the test instance type to HTTP.
    1. Create an NQA test instance and enter its view.

      nqa test-instance admin-name test-name

    2. Set the test instance type to HTTP.

      test-type http

    3. Set the protocol type for the HTTP test.

      protocol { http | https }

      By default, HTTPS is used. HTTPS is highly recommended because it is more secure.

    4. (Optional) Configure a description for the test instance.

      description description

  3. Specify a destination URL for the NQA test instance.

    http-url ipv4 url [ proxy { ipv4 ipv4Address [ port port ] | url url } ]

  4. (Optional) Specify an SSL policy to be applied in the NQA test instance.

    ssl-policy policyName

    This step is mandatory when HTTPS is used and is not required when HTTP is used.

  5. (Optional) Configure the SD-WAN tunnel to be detected by the NQA test instance.
    • Configure the site ID and device ID of the SD-WAN tunnel to be detected.
      sd-wan site-id site-id-value system-id system-id-value
    • Enable the function of recording outbound interface and SD-WAN site information in the NQA test instance result table.
      record out-interface
  6. (Optional) Set parameters as required for the NQA test instance to simulate packet transmission.
    1. Configure the aging time for the test instance.

      agetime ageTimeValue

    2. Set the number of probes in a test.

      probe-count countValue

    3. Set the interval at which test packets are sent.

      interval seconds interval

    4. Set the source interface for test packets.

      source-interface { ifName | ifType ifNum }

    5. Set the ToS value of test packets.

      tos tos-value

  7. (Optional) Configure test failure conditions.
    1. Set the timeout interval for response packets.

      timeout timeout-Value

    2. Set the percentage of failed probes, exceeding which the test is considered failed.

      fail-percent percent

  8. (Optional) Set the maximum numbers of historical test records and test results that can be saved for the NQA test instance.

    records { history history-number | result result-number }

  9. (Optional) Configure the VPN instance name for the NQA test instance.

    vpn-instance vrfName

  10. Schedule the NQA test instance.
    1. (Optional) Set the interval for performing NQA tests.

      frequency frequencyValue

    2. Start the NQA test instance.

      You can start an NQA test instance immediately, at a specified time, after a delay, or periodically.

      • Start the test instance immediately.
        start now [ end { at [ yyyy/mm/dd ] hh:mm:ss | delay { seconds second | hh:mm:ss } | lifetime { seconds second | hh:mm:ss } } ]
      • Start the test instance at a specified time.
        start at [ yyyy/mm/dd ] hh:mm:ss [ end { at [ yyyy/mm/dd ] hh:mm:ss | delay { seconds second | hh:mm:ss } | lifetime { seconds second | hh:mm:ss } } ]

      • Start the test instance after a specified delay.

        start delay { seconds second | hh:mm:ss } [ end { at [ yyyy/mm/dd ] hh:mm:ss | delay { seconds second | hh:mm:ss } | lifetime { seconds second | hh:mm:ss } } ]

      • Start the test instance at a specified time every day.

        start daily hh:mm:ss to hh:mm:ss [ begin yyyy/mm/dd ] [ end yyyy/mm/dd ]
