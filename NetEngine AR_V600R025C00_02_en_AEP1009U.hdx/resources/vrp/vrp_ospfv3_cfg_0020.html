Understanding the Network Types Supported by OSPFv3

As shown in Table 1, OSPFv3 classifies networks into four types based on the types of link layer protocols.

Table 1 Network types supported by OSPFv3

Network Type

Description

Broadcast

If the link layer protocol is either Ethernet or Fiber Distributed Data Interface (FDDI), OSPFv3 considers the network as a broadcast network by default.

On a broadcast network:

  • Hello, LSU, and LSAck packets are multicast. FF02::5 is an IPv6 multicast address reserved for an OSPFv3 device. FF02::6 is an IPv6 multicast address reserved for an OSPFv3 DR or BDR.

  • DD and LSR packets are unicast.

NBMA

OSPFv3 considers networks with X.25 as the link layer protocol to be NBMA networks by default.

On NBMA networks, protocol packets, such as Hello, DD, LSR, LSU, and LSAck packets, are transmitted in unicast mode.

Point-to-multipoint (P2MP)

Regardless of the link layer protocol, OSPFv3 does not set the network type to P2MP by default. Instead, P2MP is forcibly changed from another type of network, which in most cases is from a non-fully meshed NBMA network to a P2MP network.

On a P2MP network:

  • Hello packets are transmitted to the multicast address FF02::5.

  • Other protocol packets, such as DD, LSR, LSU, and LSAck packets, are transmitted in unicast mode.

Point-to-point (P2P)

If the link layer protocol is either Point-to-Point Protocol (PPP) or Link Access Procedure Balanced (LAPB), OSPFv3 considers the network as a P2P network by default.

On a P2P network, protocol packets, such as Hello, DD, LSR, LSU, and LSAck packets, are transmitted to the multicast address FF02::5.

As shown in the preceding table, OSPFv3 sends packets in different ways depending on the specific type of network. Therefore, the difference between OSPFv3 configurations on different networks lies in the different packet sending configurations. By setting the network type of an interface, you can forcibly change the network type of the interface. Generally, the network types on both interfaces of a link must be the same; otherwise, an OSPFv3 neighbor relationship cannot be established.

OSPFv3 does not support the network type configuration for a Null interface.
