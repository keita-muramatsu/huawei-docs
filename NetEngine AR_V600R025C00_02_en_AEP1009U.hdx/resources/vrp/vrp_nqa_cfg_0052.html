Example for Configuring an NQA Trace Test to Check the Forwarding Path on an IP Network

Networking Requirements

On the network shown in Figure 1, DeviceA functions as an NQA client to check the forwarding path between DeviceA and DeviceC.

Figure 1 Networking diagram of configuring an NQA trace test to check the forwarding path on an IP network

In this example, interface1 and interface2 represent 10GE 0/0/1 and 10GE 0/0/2, respectively.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure DeviceA as an NQA client and DeviceC as an NQA server, and configure a trace test instance on DeviceA.

  2. Start the test instance.

Data Preparation

To complete the configuration, you need the following data:

  • IP addresses of DeviceA and DeviceC

Procedure

  1. Configure DeviceA as the NQA client, create a trace test instance, and set the destination IP address to the IP address of DeviceC.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] nqa test-instance admin trace
[DeviceA-nqa-admin-trace] test-type trace
[DeviceA-nqa-admin-trace] destination-address ipv4 10.2.1.2
[DeviceA-nqa-admin-trace] frequency 60

  2. Start the test instance immediately.

    [DeviceA-nqa-admin-trace] start now

Verifying the Configuration

Verify the test result. The command output shows information about each hop between DeviceA and DeviceC.

[DeviceA-nqa-admin-trace] display nqa results test-instance admin trace

Configuration Scripts

  • DeviceA

    #
sysname DeviceA
#
vlan batch 100
#
interface Vlanif100
 ip address 10.1.1.1 255.255.255.0
#
interface 10GE0/0/1
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 100
#
ip route-static 10.2.1.0 255.255.255.0 10.1.1.2
# 
nqa test-instance admin trace
 test-type trace
 destination-address ipv4 10.2.1.2
 frequency 60
#
return

  • DeviceB

    #
sysname DeviceB
#
vlan batch 100 200
#
interface Vlanif100
 ip address 10.1.1.2 255.255.255.0
#
interface Vlanif200
 ip address 10.2.1.1 255.255.255.0
#
interface 10GE0/0/1
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 100
#
interface 10GE0/0/2
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 200
#
return

  • DeviceC

    #
sysname DeviceC
#
vlan batch 200
#
interface Vlanif200
 ip address 10.2.1.2 255.255.255.0
#
interface 10GE0/0/1
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 200
#
ip route-static 10.1.1.0 255.255.255.0 10.2.1.1
#
return
