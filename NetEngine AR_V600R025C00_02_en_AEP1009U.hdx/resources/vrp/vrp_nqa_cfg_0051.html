Example for Configuring an NQA ICMP Test to Check IP Network Reachability

Networking Requirements

On the network shown in Figure 1, DeviceA functions as an NQA client to check whether DeviceB is reachable.

Figure 1 Networking diagram of configuring an NQA ICMP test to check IP network reachability

In this example, interface1 represents 10GE 0/0/1.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure DeviceA as an NQA client and DeviceB as an NQA server, and configure an ICMP test instance on DeviceA.

  2. Start the test instance.

Data Preparation

To complete the configuration, you need the following data:

  • IP addresses of DeviceA and DeviceB

Procedure

  1. Configure DeviceA as the NQA client, create an ICMP test instance, and set the destination IP address to the IP address of DeviceB.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] nqa test-instance admin icmp
[DeviceA-nqa-admin-icmp] test-type icmp
[DeviceA-nqa-admin-icmp] destination-address ipv4 10.1.1.2
[DeviceA-nqa-admin-icmp] frequency 20

  2. Start the test instance immediately.

    [DeviceA-nqa-admin-icmp] start now

Verifying the Configuration

Verify the test result. The command output shows that there is a reachable route between DeviceA and DeviceB.

[DeviceA-nqa-admin-icmp] display nqa results test-instance admin icmp

Configuration Scripts

  • DeviceA

    #
sysname DeviceA
#
vlan batch 100
#
interface Vlanif100
 ip address 10.1.1.1 255.255.255.0
#
interface 10GE0/0/1
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 100
# 
nqa test-instance admin icmp
 test-type icmp
 destination-address ipv4 10.1.1.2
 frequency 20
#
return

  • DeviceB

    #
sysname DeviceB
#
vlan batch 100
#
interface Vlanif100
 ip address 10.1.1.2 255.255.255.0
#
interface 10GE0/0/1
 portswitch
 port link-type trunk
 port trunk allow-pass vlan 100
#
return
