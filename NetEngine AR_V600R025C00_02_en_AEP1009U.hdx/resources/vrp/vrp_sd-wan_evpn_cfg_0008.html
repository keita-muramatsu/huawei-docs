Configuring a BGP SD-WAN Peer

Prerequisites

Before configuring a BGP SD-WAN peer, ensure that a CPE at a site and the RR on the TN are reachable to each other through public network routes. To improve security, an SD-WAN tunnel needs to be established to forward BGP packets used to establish a BGP SD-WAN peer relationship between the CPE and RR. Therefore, you need to configure a static route on the CPE and RR and specify the color attribute of the peer end for the route so that the CPE and RR are reachable to each other through public network routes and trigger the establishment of an SD-WAN tunnel between the CPE and RR.

system-view
ip route-static ip-address { mask | mask-length } color color-value [ preference preference | tag tag ] * [ description text ]

Context

In the SD-WAN EVPN Solution, CPEs at different sites need to advertise local TNP information to each other so that an SD-WAN tunnel can be established. Local TNP information includes the site ID, TN ID, WAN-side public IP address, WAN-side private IP address, and tunnel encapsulation type. That is, a CPE sends local TNP information to an RR, which then reflects the information to other CPEs. TNP information transmission depends on the BGP SD-WAN control channel established between the CPE and RR, as shown in Figure 1. To establish the control channel between the CPE and RR, configure a BGP SD-WAN peer relationship between the CPE and RR as follows.

Procedure

  1. Enter the system view.

    system-view

  2. Enable BGP (with a specified local AS number) and enter the BGP view.

    bgp as-number

  3. (Optional) Configure a BGP router ID.

    router-id ipv4-address

    By default, BGP automatically selects a router ID configured in the system view as its router ID. If the IP address of a physical interface is used as the BGP router ID, route flapping occurs when this IP address changes. To enhance network stability, configure the IP address of a loopback interface as the BGP router ID.

    Configuring a new BGP router ID or changing the existing one will reset the BGP peer relationship between devices.

  4. Specify the IP address of a peer and the number of the AS where the peer resides.

    peer ipv4-address as-number as-number

    By default, no peer is specified.

    The peer IP address can be one of the following:

    • IP address of the peer's interface that is directly connected to the local device

    • IP address of a sub-interface on the peer's interface that is directly connected to the local device

    • IP address of a reachable loopback interface on the peer

    You need to specify the CPE and RR as each other's BGP peer.

  5. (Optional) Specify the source interface and source IP address for TCP connection establishment.

    peer ipv4-address connect-interface interface-type interface-number [ ipv4-source-address ]

    By default, a BGP device uses the physical interface directly connected to the peer as the local interface of a TCP connection.

    If the IP address of a loopback interface or sub-interface is used to establish a BGP connection, you are advised to run the peer connect-interface command at both ends of the connection to ensure that the connection has been correctly established. If this command is run on only one end, the BGP connection may not be established.

  6. (Optional) Set the maximum number of hops allowed for an EBGP connection.

    peer ipv4-address ebgp-max-hop [ hop-count ]

    By default, the value of hop-count is 255.

    In most cases, there should be a direct physical link between EBGP peers. If this requirement is not met, run the peer ebgp-max-hop command to allow EBGP connections to be established over multiple hops.

  7. Enable the BGP IPv4 SD-WAN address family and enter the BGP IPv4 SD-WAN address family view.

    ipv4-family sd-wan

    By default, the BGP IPv4 SD-WAN address family is not enabled.

  8. Enable the capability of exchanging routing information with a specified peer in the BGP IPv4 SD-WAN address family view.

    peer peerIpv4Addr enable

    By default, no peer is enabled in the BGP IPv4 SD-WAN address family view.

    You need to enable the capability of exchanging BGP SD-WAN routes with the peer end in the BGP IPv4 SD-WAN address family view of the CPE and RR.

  9. Configure the local device as an RR and specify the CPE as the RR client.

    peer peerIpv4Addr reflect-client

    By default, no RR and its client are configured.

    Perform this step on the RR. This step is not required on the CPE.

  10. Configure optional functions in the BGP IPv4 SD-WAN address family view as required.

    Add a specified BGP SD-WAN peer to a peer group.

    peer peerIpv4Addr group peerGroupName

    peer peerGroupName enable

    To improve configuration efficiency, you can add multiple BGP SD-WAN peers to which the same policy is applied to a peer group. Then, you only need to configure BGP SD-WAN peers based on the peer group.

    Configure a specified BGP SD-WAN peer group as an RR client.

    peer peerGroupName reflect-client

    This function is applicable only to RRs.

    Apply a specified route-policy to the routes to be advertised to a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr route-policy policy-name export

    peer peerGroupName route-policy policy-name export

    Before configuring this function, you need to create a route-policy using policy-name and modify route attributes in the route-policy.

    Apply a specified route-policy to the routes received from a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr route-policy policy-name import

    peer peerGroupName route-policy policy-name import

    Before configuring this function, you need to create a route-policy using policy-name and modify route attributes in the route-policy.

    Allow advertising community attributes to a BGP SD-WAN peer or peer group.

    peer ipv4-address advertise-community

    peer group-name advertise-community

    Before configuring this function, you need to create a route-policy, set the community attributes of routes, and apply the route-policy when configuring route advertisement.

    Allow advertising extended community attributes to a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr advertise-ext-community

    peer group-name advertise-ext-community

    Before configuring this function, you need to create a route-policy, set the extended community attributes of routes, and apply the route-policy when configuring route advertisement.

    Enable the RR to modify the path attributes of routes using an export policy.

    reflect change-path-attribute

    This function is applicable only to RRs.

    Before configuring this function, you need to create a route-policy, set the next hop attributes of routes, and apply the route-policy when configuring route advertisement.

    Set a cluster ID for the RR.

    reflector cluster-id { cluster-id-value | cluster-id-ipv4 }

    This function is applicable only to RRs.

    When multiple RRs are configured in a cluster, you need to set the same cluster ID for all of the RRs to identify the cluster and prevent routing loops.

    Configure BGP SD-WAN not to compare the AS_Path attributes contained in routes during optimal route selection.

    bestroute as-path-ignore

    Configure BGP SD-WAN not to compare the router IDs contained in routes during optimal route selection.

    bestroute router-id-ignore

    When creating a route-policy, configure BGP SD-WAN not to compare the router IDs contained in routes during optimal route selection, which reduces unnecessary route switching.

    Allow the local AS number to be contained in the AS_Path attribute of the route sent by a BGP SD-WAN peer or peer group. You can also set the number of times that the local AS number can be repeated in the AS_Path attribute.

    peer peerIpv4Addr allow-as-loop [ num ]

    peer peerGroupName allow-as-loop [ num ]

    -

    Configure an AS_Path-based route filtering policy for the routes to be advertised to a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr as-path-filter { number | name } export

    peer peerGroupName as-path-filter { number | name } export

    Before configuring this function, you need to create an AS_Path filter.

    Configure an AS_Path-based route filtering policy for the routes received from a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr as-path-filter { number | name } import

    peer peerGroupName as-path-filter { number | name } import

    Before configuring this function, you need to create an AS_Path filter.

    Configure the function of discarding the extended community attributes in the routing information of a specific BGP SD-WAN peer or peer group.

    peer peerIpv4Addr discard-ext-community

    peer peerGroupName discard-ext-community

    -

    Set the maximum hold-off time for the local device to wait for GR recovery on the peer end.

    peer peerIpv4Addr graceful-restart static-timer restart-time
    Two methods are available to set the maximum hold-off time for the local device to wait for GR recovery on the peer end:

    • To set the maximum hold-off time for re-establishing all BGP peer relationships, run the graceful-restart timer restart command in the BGP view. The maximum hold-off time supported by this command is 3600s.

    • To set the maximum hold-off time for re-establishing a specified BGP SD-WAN peer relationship, run the peer graceful-restart static-timer command in the BGP IPv4 SD-WAN address family view. This command allows you to set a hold-off time greater than 3600s.

    If both methods are used, the latter takes precedence.

    NOTE:

    This function can be configured only after GR has been enabled in the BGP view.

    Configure the device to preferentially select a route received from a peer not in GR state as the optimal route.

    bestroute non-gr-prior

    By default, the function of preferentially selecting a route received from a peer not in GR state as the optimal route is not configured. When GR is enabled on the local device and the peer from which the optimal route is received restarts, the peer enters the GR state and the local device continues to prefer the route received from this peer. As a result, traffic is not switched to other paths, leading to packet loss. To solve this problem, you can run the bestroute non-gr-prior command on the local device to preferentially select a route received from a peer not in GR state as the optimal route.

    NOTE:

    This function takes effect only when GR is enabled on the local device and the peer is in the GR state. For details about how to enable GR, see Enabling GR for BGP Peers.

    Set the maximum number of routes that can be accepted from a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr route-limit limit [ percentage ] [ alert-only | idle-forever | idle-timeout times ]

    peer peerGroupName route-limit limit [ percentage ] [ alert-only | idle-forever | idle-timeout times ]

    -

    Set the interval for sending Update packets with the same route prefix to a BGP SD-WAN peer or peer group.

    peer peerIpv4Addr route-update-interval interval

    peer peerGroupName route-update-interval interval

    -

    Disable BGP SD-WAN slow peer detection.

    slow-peer absolute-detection disable

    By default, BGP SD-WAN slow peer detection is enabled.

    Set the BGP SD-WAN slow peer detection threshold.

    slow-peer absolute-detection threshold absolute-threshold-value

    By default, the BGP SD-WAN slow peer detection threshold is 60s.

    Disable SAFI compatibility with non-standard BGP peer groups.

    peer peerIpv4Addr capability-advertise safi non-standard-compatible disable

    peer peerGroupName capability-advertise safi non-standard-compatible disable

    By default, SAFI compatibility with non-standard BGP peers is enabled.

    Enabling or disabling SAFI compatibility for a peer causes the BGP peer relationship to be disconnected and re-established. If two devices are configured with different compatibility modes, one device will not perform negotiation with the other device and the other device will enter the established state. Given this, the two devices must be configured with the same compatibility mode. Otherwise, they may fail to establish a peer relationship.
