Example for Configuring DSVPN NAT Traversal

Networking Requirements

The HQ (Hub) and branches (Spoke1 and Spoke2) of an enterprise are located in different areas and their subnet environments change frequently. Spoke1 and Spoke2 connect to Hub over the public network using post-NAT addresses, but they do not know each other's post-NAT address. The enterprise wants to use a VPN for communication between spokes. To meet this requirement, configure a dynamic routing protocol (OSPF) based on enterprise network planning and deploy NAT traversal on the DSVPN network to achieve direct communication between Spoke1 and Spoke2. Figure 1 shows the related networking.

Figure 1 Network diagram of NAT traversal on a DSVPN network

In this example, interface1 and interface2 represent 10GE0/0/1 and 10GE0/0/2, respectively.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure DSVPN NAT traversal to enable communication between branches. This is because branches access the public network using post-NAT addresses and are unaware of each other's post-NAT address.

  2. Considering the large number of branches, configure DSVPN in shortcut mode.

  3. Due to frequent changes in subnet environments of the HQ and branches, deploy OSPF based on enterprise network planning for communication between the HQ and branches, which simplifies maintenance.

Procedure

  1. Configure interface IP addresses.

    Configure interface IP addresses on each device.

    # Configure interface IP addresses on Hub.
    <HUAWEI> system-view
[HUAWEI] sysname Hub
[Hub] interface 10ge0/0/1
[Hub-10GE0/0/1] ip address 10.10.1.10 255.255.255.0
[Hub-10GE0/0/1] quit
[Hub] interface tunnel 0
[Hub-Tunnel0] ip address 172.16.1.1 255.255.255.0
[Hub-Tunnel0] quit
[Hub] interface loopback 0
[Hub-LoopBack0] ip address 192.168.0.1 255.255.255.255
[Hub-LoopBack0] quit

    Configure IP addresses for interfaces on Spoke1, Spoke2, NAT1, and NAT2 according to Figure 1. The configurations of the spokes and NAT devices are similar to the configuration of Hub.

  2. Configure devices to be reachable through public network routes.

    Configure OSPF on each device to ensure that public network routes are available.

    # Configure OSPF on Hub.

    [Hub] ospf 2 router-id 10.10.1.10
[Hub-ospf-2] area 0.0.0.1
[Hub-ospf-2-area-0.0.0.1] network 10.10.1.0 0.0.0.255
[Hub-ospf-2-area-0.0.0.1] quit
[Hub-ospf-2] quit

    # Configure OSPF on NAT1.

    [NAT1] ospf 2 router-id 10.1.2.1
[NAT1-ospf-2] import-route op-route
[NAT1-ospf-2] area 0.0.0.1
[NAT1-ospf-2-area-0.0.0.1] network 10.1.2.0 0.0.0.255
[NAT1-ospf-2-area-0.0.0.1] network 10.1.1.0 0.0.0.255
[NAT1-ospf-2-area-0.0.0.1] quit
[NAT1-ospf-2] quit

    # Configure OSPF on NAT2.

    [NAT2] ospf 2 router-id 10.1.3.1
[NAT2-ospf-2] import-route op-route
[NAT2-ospf-2] area 0.0.0.1
[NAT2-ospf-2-area-0.0.0.1] network 10.1.3.0 0.0.0.255
[NAT2-ospf-2-area-0.0.0.1] network 10.2.2.0 0.0.0.255
[NAT2-ospf-2-area-0.0.0.1] quit
[NAT2-ospf-2] quit

    # Configure OSPF on Spoke1.

    [Spoke1] ospf 2 router-id 10.1.1.1
[Spoke1-ospf-2] area 0.0.0.1
[Spoke1-ospf-2-area-0.0.0.1] network 10.1.1.0 0.0.0.255
[Spoke1-ospf-2-area-0.0.0.1] quit
[Spoke1-ospf-2] quit

    # Configure OSPF on Spoke2.

    [Spoke2] ospf 2 router-id 10.2.2.2
[Spoke2-ospf-2] area 0.0.0.1
[Spoke2-ospf-2-area-0.0.0.1] network 10.2.2.0 0.0.0.255
[Spoke2-ospf-2-area-0.0.0.1] quit
[Spoke2-ospf-2] quit

  3. Enable the NAT function on interfaces.

    # Configure NAT1.

    [NAT1] interface 10ge0/0/1
[NAT1-10GE0/0/1] nat enable
[NAT1-10GE0/0/1] quit

    # Configure NAT2.

    [NAT2] interface 10ge0/0/1
[NAT2-10GE0/0/1] nat enable
[NAT2-10GE0/0/1] quit

  4. Configure NAT Server.

    # Configure NAT1.

    [NAT1] nat server nat1 global 10.10.2.10 inside 10.1.1.1 route

    # Configure NAT2.

    [NAT2] nat server nat1 global 10.10.3.10 inside 10.2.2.2 route

    The NAT devices must have NAT Server configured. NAT traversal cannot be implemented on a DSVPN network if source NAT policy-based dynamic NAT is configured on the NAT devices.

  5. Configure basic OSPF functions.

    # Configure Hub.

    [Hub] ospf 1 router-id 172.16.1.1
[Hub-ospf-1] area 0.0.0.0
[Hub-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Hub-ospf-1-area-0.0.0.0] network 192.168.0.0 0.0.0.255
[Hub-ospf-1-area-0.0.0.0] quit
[Hub-ospf-1] quit

    # Configure Spoke1.

    [Spoke1] ospf 1 router-id 172.16.1.2
[Spoke1-ospf-1] area 0.0.0.0
[Spoke1-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Spoke1-ospf-1-area-0.0.0.0] network 192.168.1.0 0.0.0.255
[Spoke1-ospf-1-area-0.0.0.0] quit
[Spoke1-ospf-1] quit

    # Configure Spoke2.

    [Spoke2] ospf 1 router-id 172.16.1.3
[Spoke2-ospf-1] area 0.0.0.0
[Spoke2-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Spoke2-ospf-1-area-0.0.0.0] network 192.168.2.0 0.0.0.255
[Spoke2-ospf-1-area-0.0.0.0] quit
[Spoke2-ospf-1] quit

    The configuration on one spoke subnet is given as an example. Configure other spoke subnets similarly. If a spoke's subnet changes, you only need to configure dynamic routing attributes at that spoke.

  6. Enable NHRP globally.

    # Configure Hub.

    [Hub] nhrp enable

    The configurations of the spokes are similar to the configuration of Hub.

  7. Configure tunnel interfaces.

    On Hub and the spokes, set the OSPF network type to P2MP. On Hub, enable the NHRP redirect function. On Spoke1 and Spoke2, configure a static NHRP mapping entry for Hub and enable the NHRP shortcut function.

    # On Hub, configure a tunnel interface and OSPF route attributes, and enable the NHRP redirect function.
    [Hub] interface tunnel 0
[Hub-Tunnel0] tunnel-protocol gre p2mp
[Hub-Tunnel0] nhrp enable
[Hub-Tunnel0] source 10ge0/0/1
[Hub-Tunnel0] nhrp entry multicast dynamic
[Hub-Tunnel0] ospf network-type p2mp
[Hub-Tunnel0] nhrp redirect
[Hub-Tunnel0] quit
    # On Spoke1, configure a tunnel interface, OSPF route attributes, and a static NHRP mapping entry for Hub, and enable the NHRP shortcut function.
    [Spoke1] interface tunnel 0
[Spoke1-Tunnel0] tunnel-protocol gre p2mp
[Spoke1-Tunnel0] nhrp enable
[Spoke1-Tunnel0] source 10ge0/0/1
[Spoke1-Tunnel0] nhrp entry 172.16.1.1 10.10.1.10 register
[Spoke1-Tunnel0] ospf network-type p2mp
[Spoke1-Tunnel0] nhrp shortcut
[Spoke1-Tunnel0] quit
    # On Spoke2, configure a tunnel interface, OSPF route attributes, and a static NHRP mapping entry for Hub, and enable the NHRP shortcut function.
    [Spoke2] interface tunnel 0
[Spoke2-Tunnel0] tunnel-protocol gre p2mp
[Spoke1-Tunnel0] nhrp enable
[Spoke2-Tunnel0] source 10ge0/0/1
[Spoke2-Tunnel0] nhrp entry 172.16.1.1 10.10.1.10 register
[Spoke2-Tunnel0] ospf network-type p2mp
[Spoke2-Tunnel0] nhrp shortcut
[Spoke2-Tunnel0] quit

Configuration Scripts

  • Hub

    #
sysname Hub
# 
nhrp enable
#
interface 10GE0/0/1
 ip address 10.10.1.10 255.255.255.0
#
interface LoopBack0
 ip address 192.168.0.1 255.255.255.255
# 
interface Tunnel0
 ip address 172.16.1.1 255.255.255.0
 tunnel-protocol gre p2mp
 source 10GE0/0/1
 ospf network-type p2mp
 nhrp enable
 nhrp redirect
 nhrp entry multicast dynamic
# 
ospf 1 router-id 172.16.1.1
 area 0.0.0.0
  network 172.16.1.0 0.0.0.255
  network 192.168.0.0 0.0.0.255
# 
ospf 2 router-id 10.10.1.10
 area 0.0.0.1
  network 10.10.1.0 0.0.0.255
# 
return

  • Spoke1

    #
sysname Spoke1
# 
nhrp enable
#
interface 10GE0/0/1
 ip address 10.1.1.1 255.255.255.0
#
interface LoopBack0
 ip address 192.168.1.1 255.255.255.255
# 
interface Tunnel0
 ip address 172.16.1.2 255.255.255.0
 tunnel-protocol gre p2mp
 source 10GE0/0/1
 ospf network-type p2mp
 nhrp enable
 nhrp shortcut
 nhrp entry 172.16.1.1 10.10.1.10 register
# 
ospf 1 router-id 172.16.1.2
 area 0.0.0.0
  network 172.16.1.0 0.0.0.255
  network 192.168.1.0 0.0.0.255
# 
ospf 2 router-id 10.1.1.1
 area 0.0.0.1
  network 10.1.1.0 0.0.0.255
#
return

  • NAT1
    #
sysname NAT1
# 
interface 10GE0/0/1
 ip address 10.1.2.1 255.255.255.0

# 
interface 10GE0/0/2

#
