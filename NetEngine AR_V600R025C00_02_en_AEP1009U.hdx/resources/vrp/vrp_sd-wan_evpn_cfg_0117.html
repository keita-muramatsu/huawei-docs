SD-WAN EVPN Data Forwarding

Data can be exchanged between sites after an SD-WAN EVPN network is deployed. The following describes the encapsulation and forwarding process of IP data from CPE1 to CPE2 during communication between Site 1 and Site 3, as shown in Figure 1.

Figure 1 SD-WAN EVPN data forwarding and encapsulation process

The SD-WAN EVPN data forwarding process is as follows:

  1. CPE1 receives an ordinary unicast packet from user A, searches the routing table of the SD-WAN EVPN instance, and forwards the packet based on the next-hop site of the matching SD-WAN EVPN route. CPE1 adds GRE information to the packet, encapsulates the packet with an IPv4 tunnel header, and forwards the packet to CPE2.
  2. CPE2 receives the packet, searches the SD-WAN tunnel decapsulation table based on the IPv4 source address (CPE1) and destination address (CPE2) of the packet, decapsulates the packet, removes the IPv4 header, searches the routing table of the SD-WAN EVPN instance based on the GRE Key value and destination address of the inner packet, and then forwards the packet to user B.

An identifier needs to be added to data packets of different service VPNs to differentiate traffic in the same tunnel. The traffic is GRE encapsulated, so a GRE key extension is used to identify traffic of different service VPNs.

Figure 2 shows the GRE header format.

Figure 2 GRE header format

The Key field is used by the receive end to authenticate received packets. This field identifies traffic in a tunnel. Packets of the same traffic flow use the same key. During packet decapsulation, GRE identifies data packets of the same traffic flow based on the key. The authentication is successful only if the Key field settings on both endpoints of the tunnel are consistent. Otherwise, the packets are dropped. Both endpoints must either be configured with the same Key field or not configured with the Key field for successful authentication to take place.

In an SD-WAN EVPN scenario, the value of the Key field is the VN ID. During packet encapsulation, the local end obtains the VN ID based on the VPN, encapsulates the extended GRE header of a packet with the VN ID, and sends the packet to the peer end. The peer end then maps the VN ID to the local VPN for route isolation.
