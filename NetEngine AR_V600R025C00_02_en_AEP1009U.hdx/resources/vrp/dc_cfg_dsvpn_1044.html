Spoke Registration Fails

Fault Symptom

The display nhrp peer command output on the hub does not show an NHRP mapping entry that records the mapping between a spoke's tunnel address and public address.

Procedure

  1. Check whether the hub and spoke have reachable routes to each other.

    Run the display ip routing-table command on the spoke and hub to check whether there is a reachable route to each other.

    • If not, check the route configuration. For details, see CLI Configuration Guide > IP Routing Configuration.
    • If there is such a route, go to step 2.

  2. Check the configurations of the spoke and hub.

    Run the display nhrp peer command on the hub and spoke to check NHRP mapping entries.

    If the hub does not have a dynamic NHRP mapping entry for the spoke, run the display this command in the mGRE interface view to check whether the configurations on the hub and spoke are the same. Table 1 lists the fields in the command output that you need to check and follow-up operations.
    Table 1 Check items

    Check Item

    Check Criteria and Follow-up Operations

    nhrp authentication

    Check whether NHRP authentication strings configured on the spoke and hub are the same. If they are different, run the nhrp authentication command to change them to the same string.

    nhrp entry

    Check whether the static NHRP mapping entry configured on the spoke records correct hub interface information. If not, run the nhrp entry command to reconfigure a correct NHRP mapping entry.
