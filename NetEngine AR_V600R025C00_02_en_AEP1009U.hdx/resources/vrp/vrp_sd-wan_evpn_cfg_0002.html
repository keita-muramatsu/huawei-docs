Overview of SD-WAN EVPN

Definition

Software-defined Wide Area Network (SD-WAN) Ethernet Virtual Private Network (EVPN) is a VPN solution that extends the existing EVPN technology to separate the overlay service network from the underlay transport network.

SD-WAN EVPN extends network layer reachability information (NLRI) based on BGP. That is, it defines a new type of routes, BGP SD-WAN routes, through which sites exchange transport network port (TNP) information, including key information used to establish SD-WAN tunnels between sites. Then sites use Border Gateway Protocol Ethernet Virtual Private Network (BGP EVPN) IP prefix routes (Type 5 routes) to advertise service routes to each other. After receiving these BGP EVPN routes from the peer site, the local site triggers the establishment of an SD-WAN tunnel with the peer site, based on which the data channel of the underlay network is established. In addition, EVPN routes recurse to the SD-WAN tunnel to establish service paths on the overlay network.

Purpose

The SD-WAN EVPN Solution enables communication between the enterprise headquarters and branches as well as between branches. An enterprise often uses hub-spoke architecture to connect its headquarters' network and multiple branch networks, enhancing communication security. Generally, the headquarters uses static public IP addresses to access carrier networks, whereas branches use dynamic public IP addresses to access carrier networks. If a traditional IP security (IPsec) or Generic Routing Encapsulation (GRE) over IPsec technology is used to construct a VPN, branches (spokes) cannot communicate with each other because they cannot obtain each other's public IP address. Data then needs to be forwarded through the headquarters (hub) when being transmitted between the branches, resulting in the following problems:

  • The headquarters is forced to withstand substantial performance pressure, and a significant amount of CPU and memory resources will be consumed.

  • Additional encapsulation and decapsulation need to be performed on data, resulting in a longer network delay.

  • As the IPsec network expands, dynamic routing protocols need to be deployed on the network. Dynamic routing protocols need to use multicast and broadcast packets to update routes; however, IPsec does not support the transmission of such packets.

To address these problems, the SD-WAN EVPN Solution is introduced: On the control plane, sites use the BGP route reflector (RR) mechanism to exchange BGP SD-WAN and EVPN routes, greatly reducing the configuration workload. In addition, each site only needs to have routes to the RR, which can be static routes, removing the need to deploy dynamic routing protocols. After SD-WAN tunnels are established between branch sites and EVPN service routes are advertised between these sites, services can be directly transmitted between these sites without being forwarded by the headquarters site. This prevents the headquarters site from becoming a bottleneck.

Benefits

The SD-WAN EVPN Solution provides the following benefits for enterprise branch interconnection:

  • SD-WAN tunnels between sites (including the headquarters and branches) are fully connected to ensure the fast and secure transmission of service traffic and prevent service traffic between branch sites from being forwarded by the headquarters, improving enterprise network performance.
  • The BGP RR mechanism is introduced so that each site only needs to establish a BGP connection with the RR, avoiding full-mesh connections between sites, reducing the configuration workload and number of links, and improving O&M efficiency.
  • Because EVPN routes can carry extended community attributes, routing policies can be used to flexibly control service paths, thereby isolating tenants, providing redirect sites, and directing traffic to hub devices.
