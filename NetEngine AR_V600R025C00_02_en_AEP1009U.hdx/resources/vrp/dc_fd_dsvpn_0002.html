Overview of DSVPN

Definition

Dynamic Smart Virtual Private Network (DSVPN) is a dynamic VPN technology that connects branches to the headquarters (HQ) and to each other on a hub-spoke network.

Purpose

To keep network construction costs low by fully utilizing public network resources, enterprises want to connect branches (spokes) to the HQ (hub) and to each other, irrespective of their locations, through VPNs over a public network.

Figure 1 shows a typical hub-spoke network, where the HQ and branches set up hub-spoke tunnels and the branches have to go through the HQ to communicate with each other. Such a network has the following problems:

  • When a new spoke joins the network, the hub needs to add and maintain the VPN configuration for this spoke. In this case, having a large number of spokes on a network complicates the configuration on the hub. Additionally, each time the network topology changes, the configuration on the hub must be modified.
  • If spoke-spoke traffic traverses the hub, the traffic consumes resources of the hub and results in an additional delay (especially when IPsec is used for encryption). This is because the hub needs to decrypt and encrypt the traffic from the source spoke before sending it to the destination spoke.
  • If spokes communicate directly without going through the hub and their egresses use dynamic addresses, the spokes cannot obtain the peer end's address in advance. As a result, they cannot set up a tunnel between them.

To resolve the address-related issue, DSVPN works in conjunction with Next Hop Resolution Protocol (NHRP) to collect and maintain site information, such as dynamic public addresses. When a site wants to reach another, it uses NHRP to determine the public address of the destination.

Figure 1 Typical hub-spoke networking without DSVPN deployed

On a DSVPN network, as shown in Figure 2, branches use dynamic addresses for public network access and establish dynamic mGRE tunnels between each other for direct communication. Besides, this DSVPN network uses multipoint Generic Routing Encapsulation (mGRE) technology to allow one mGRE tunnel interface to have multiple GRE tunnels. This simplifies subnet traffic management and configurations of GRE and IPsec.

Figure 2 Hub-spoke networking with DSVPN deployed

Benefits

  • Reduced VPN construction costs

    DSVPN establishes fully-meshed dynamic connections between sites on a hub-spoke network. There is no need for spokes to purchase static public addresses.

  • Simplified configuration of the hub and spokes

    DSVPN works in conjunction with mGRE to group many point-to-point GRE tunnel interfaces into a single mGRE tunnel interface at the hub and spokes. Additionally, adding spokes to a DSVPN network requires no configuration changes at the hub or existing spokes. Only the new spokes need to be configured, after which they automatically register with the hub.

  • Reduced data transmission delay between spokes

    Dynamic tunnels between spokes eliminate the need for spoke-spoke traffic to traverse the hub. This reduces the forwarding delay and improves forwarding performance and efficiency.
