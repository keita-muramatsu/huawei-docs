Example for Configuring DSVPN over IPsec

Networking Requirements

For security purposes, you are advised not to use weak security algorithms in this feature.

The HQ (Hub) and branches (Spoke1 and Spoke2) of an enterprise are located in different areas and their subnet environments change frequently. The branches connect to the HQ and to each other over the public network, and use dynamic addresses to access the public network. Data transmitted between the HQ and branches, as well as between branches, needs to be protected through encryption. The enterprise wants to use a VPN for communication between branches and encrypt data exchanged between the HQ and branches and between branches. To meet this requirement, configure a dynamic routing protocol (OSPF) based on enterprise network planning and deploy DSVPN over IPsec to achieve direct communication between Spoke1 and Spoke2 as well as data encryption. Figure 1 shows the related networking.

Figure 1 Network diagram for configuring DSVPN over IPsec

In this example, interface1 represents 10GE0/0/1.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure DSVPN to enable communication between branches. This is because branches access the public network using dynamic addresses and are unaware of each other's public address.

  2. Considering the large number of branches, configure DSVPN in shortcut mode.

  3. Due to frequent changes in subnet environments of the HQ and branches, deploy OSPF based on enterprise network planning for communication between the HQ and branches, which simplifies maintenance.

  4. Configure DSVPN over IPsec to encrypt data transmitted between organizations. Use SHA2-256 as the authentication algorithm in the IKE proposal, AH, and ESP.

    In a DSVPN over IPsec scenario, if a NAT device is deployed, you are advised to set the IPsec encapsulation mode to transport. If two spokes are situated behind different NAT devices or the hub is situated behind a NAT device, the IPsec encapsulation mode can only be transport.

Procedure

  1. Configure interface IP addresses.

    Configure interface IP addresses on each device.

    # Configure interface IP addresses on Hub.

    <HUAWEI> system-view
[HUAWEI] sysname Hub
[Hub] interface 10ge0/0/1
[Hub-10GE0/0/1] ip address 10.1.1.10 255.255.255.0
[Hub-10GE0/0/1] quit
[Hub] interface tunnel 0
[Hub-Tunnel0] ip address 172.16.1.1 255.255.255.0
[Hub-Tunnel0] quit
[Hub] interface loopback 0
[Hub-LoopBack0] ip address 192.168.0.1 255.255.255.255
[Hub-LoopBack0] quit

    Assign an IP address to each interface of Spoke1 and Spoke2 according to Figure 1. The configurations of the spokes are similar to the configuration of Hub.

  2. Configure devices to be reachable through public network routes.

    Configure OSPF on each device to ensure that public network routes are available.

    # Configure OSPF on Hub.

    [Hub] ospf 2 router-id 10.1.1.10
[Hub-ospf-2] area 0.0.0.1
[Hub-ospf-2-area-0.0.0.1] network 10.1.1.0 0.0.0.255
[Hub-ospf-2-area-0.0.0.1] quit
[Hub-ospf-2] quit

    # Configure OSPF on Spoke1.

    [Spoke1] ospf 2 router-id 10.1.2.10
[Spoke1-ospf-2] area 0.0.0.1
[Spoke1-ospf-2-area-0.0.0.1] network 10.1.2.0 0.0.0.255
[Spoke1-ospf-2-area-0.0.0.1] quit
[Spoke1-ospf-2] quit

    # Configure OSPF on Spoke2.

    [Spoke2] ospf 2 router-id 10.1.3.10
[Spoke2-ospf-2] area 0.0.0.1
[Spoke2-ospf-2-area-0.0.0.1] network 10.1.3.0 0.0.0.255
[Spoke2-ospf-2-area-0.0.0.1] quit
[Spoke2-ospf-2] quit

  3. Configure basic OSPF functions.

    # Configure Hub.

    [Hub] ospf 1 router-id 172.16.1.1
[Hub-ospf-1] area 0.0.0.0
[Hub-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Hub-ospf-1-area-0.0.0.0] network 192.168.0.0 0.0.0.255
[Hub-ospf-1-area-0.0.0.0] quit
[Hub-ospf-1] quit

    # Configure Spoke1.

    [Spoke1] ospf 1 router-id 172.16.1.2
[Spoke1-ospf-1] area 0.0.0.0
[Spoke1-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Spoke1-ospf-1-area-0.0.0.0] network 192.168.1.0 0.0.0.255
[Spoke1-ospf-1-area-0.0.0.0] quit
[Spoke1-ospf-1] quit

    # Configure Spoke2.

    [Spoke2] ospf 1 router-id 172.16.1.3
[Spoke2-ospf-1] area 0.0.0.0
[Spoke2-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Spoke2-ospf-1-area-0.0.0.0] network 192.168.2.0 0.0.0.255
[Spoke2-ospf-1-area-0.0.0.0] quit
[Spoke2-ospf-1] quit

  4. Enable NHRP globally.

    # Configure Hub.

    [Hub] nhrp enable

    The configurations of the spokes are similar to the configuration of Hub.

  5. Configure an IKE proposal.

    Configure an IKE proposal on Hub and the spokes and select the same authentication mode on both.

    # Configure Hub.

    [Hub] ike proposal 1
[Hub-ike-proposal-1] encryption-algorithm aes-256
[Hub-ike-proposal-1] dh group14
[Hub-ike-proposal-1] authentication-algorithm sha2-256
[Hub-ike-proposal-1] quit

    The configurations of Spoke1 and Spoke2 are similar to the configuration of Hub. For configuration details, see Configuration Scripts in this section.

  6. Configure an IKE peer.

    Configure the IKE peer required for IKE negotiation on Hub and the spokes.

    # Configure Hub.

    [Hub] ike peer hub
[Hub-ike-peer-hub] ike-proposal 1
[Hub-ike-peer-hub] pre-shared-key YsHsjx_202206
[Hub-ike-peer-hub] quit

    The configurations of Spoke1 and Spoke2 are similar to the configuration of Hub. For configuration details, see Configuration Scripts in this section.

  7. Create an IPsec proposal.

    Create an IPsec proposal on Hub and the spokes.

    # Configure Hub.

    [Hub] ipsec proposal pro1
[Hub-ipsec-proposal-pro1] transform ah-esp
[Hub-ipsec-proposal-pro1] ah authentication-algorithm sha2-256
[Hub-ipsec-proposal-pro1] esp authentication-algorithm sha2-256
[Hub-ipsec-proposal-pro1] esp encryption-algorithm aes-192
[Hub-ipsec-proposal-pro1] quit

    The configurations of Spoke1 and Spoke2 are similar to the configuration of Hub. For configuration details, see Configuration Scripts in this section.

  8. Configure an IPsec profile.

    Configure an IPsec profile on Hub and the spokes.

    # Configure Hub.

    [Hub] ipsec profile profile1
[Hub-ipsec-profile-profile1] ike-peer hub
[Hub-ipsec-profile-profile1] proposal pro1
[Hub-ipsec-profile-profile1] quit

    The configurations of Spoke1 and Spoke2 are similar to the configuration of Hub. For configuration details, see Configuration Scripts in this section.

  9. Configure tunnel interfaces.

    # On Hub, configure a tunnel interface and OSPF attributes and apply the IPsec profile.
    [Hub] interface tunnel 0
[Hub-Tunnel0] tunnel-protocol gre p2mp
[Hub-Tunnel0] nhrp enable
[Hub-Tunnel0] source 10.1.1.10
[Hub-Tunnel0] nhrp entry multicast dynamic
[Hub-Tunnel0] ospf network-type p2mp
[Hub-Tunnel0] nhrp redirect
[Hub-Tunnel0] ipsec profile profile1
[Hub-Tunnel0] quit
    # On Spoke1, configure a tunnel interface, OSPF route attributes, and a static NHRP mapping entry for Hub, and apply the IPsec profile.
    [Spoke1] interface tunnel 0
[Spoke1-Tunnel0] tunnel-protocol gre p2mp
[Spoke1-Tunnel0] nhrp enable
[Spoke1-Tunnel0] source 10.1.2.10
[Spoke1-Tunnel0] nhrp entry 172.16.1.1 10.1.1.10 register
[Spoke1-Tunnel0] ospf network-type p2mp
[Spoke1-Tunnel0] nhrp shortcut
[Spoke1-Tunnel0] ipsec profile profile1
[Spoke1-Tunnel0] quit
    # On Spoke2, configure a tunnel interface, OSPF route attributes, and a static NHRP mapping entry for Hub, and apply the IPsec profile.
    [Spoke2] interface tunnel 0
[Spoke2-Tunnel0] tunnel-protocol gre p2mp
[Spoke2-Tunnel0] nhrp enable
[Spoke2-Tunnel0] source 10.1.3.10
[Spoke2-Tunnel0] nhrp entry 172.16.1.1 10.1.1.10 register
[Spoke2-Tunnel0] ospf network-type p2mp
[Spoke2-Tunnel0] nhrp shortcut
[Spoke2-Tunnel0] ipsec profile profile1
[Spoke2-Tunnel0] quit

Configuration Scripts

  • Hub

    #
sysname Hub
# 
ike dpd idle-time 100
#
ike proposal 1
 encryption-algorithm aes-256                                                   
 dh group14                                                                      
 authentication-algorithm sha2-256                                       
 authentication-method pre-share                                                
 integrity-algorithm hmac-sha2-256                                              
# 
ike peer hub
 pre-shared-key %^%#6n%Y;[:>0T\w~V2nMW//EnxY@k;[q0/x~`.gjZ>#%^%#
 ike-proposal 1
#
ipsec proposal pro1
 transform ah-esp
 ah authentication-algorithm sha2-256
 esp authentication-algorithm sha2-256
 esp encryption-algorithm aes-192
# 
ipsec profile profile1
 ike-peer hub
 proposal pro1
# 
nhrp enable
#
interface 10GE0/0/1
 ip address 10.1.1.10 255.255.255.0
# 
interface LoopBack0
 ip address 192.168.0.1 255.255.255.255
# 
interface Tunnel0
 ip address 172.16.1.1 255.255.255.0
 tunnel-protocol gre p2mp
 source 10.1.1.10
 ospf network-type p2mp
 nhrp enable
 nhrp redirect
 nhrp entry multicast dynamic
 ipsec profile profile1
# 
ospf 1 router-id 172.16.1.1
 area 0.0.0.0
  network 172.16.1.0 0.0.0.255
  network 192.168.0.0 0.0.0.255
# 
ospf 2 router-id 10.1.1.10
 area 0.0.0.1
  network 10.1.1.0 0.0.0.255
# 
return
