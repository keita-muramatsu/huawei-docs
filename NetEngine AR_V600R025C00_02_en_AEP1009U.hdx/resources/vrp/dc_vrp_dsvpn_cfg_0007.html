Configuring Dual-Hub DSVPN

Prerequisites

Before configuring dual hubs for a DSVPN network, you have completed the following task:

  • Configure each involved interface and assign IP addresses to them.

Context

On a DSVPN network, all spokes connect to a hub. If the hub fails, spokes cannot establish tunnels for direct communication. To improve DSVPN reliability, consider deploying two hubs (for example, Hub1 and Hub2) that can serve as backups for each other. Specifically, Hub1 functions as the active hub and Hub2 as the standby hub. If Hub1 fails, Hub2 takes over protocol packet forwarding. After Hub1 recovers, Hub2 reverts back to serving as the standby hub.

Procedure

  1. Configure mGRE. For details, see Configuring mGRE.
  2. Configure routes. For details, see Configuring Routes.
  3. Configure route preferences.

    • If static routes are used, configure route preferences to determine the active and standby hubs.

      Specify the preference of a static route.

      ip route-static ip-address { mask | mask-length }nexthop-address preference preference

      By default, the preference of a static route is 60.

    • If OSPF is used, set different OSPF interface costs for tunnel interfaces on the hubs to determine their active and standby roles.

      Set a cost for the OSPF interface.

      ospf cost value

      By default, the OSPF interface cost is calculated using the following formula:

      Interface cost = Bandwidth reference value/Interface bandwidth

      In this formula, the bandwidth reference value can be changed using the bandwidth-reference command.

    • If another routing protocol is used, configure route preferences by referring to CLI Configuration Guide > IP Routing Configuration.

    After the configuration is complete, configure the active Hub1 as the next hop of private network routes between spokes.

  4. Configure NHRP. For details, see Configuring NHRP.

    Configure static NHRP mapping entries for active and standby hubs on the spokes.
