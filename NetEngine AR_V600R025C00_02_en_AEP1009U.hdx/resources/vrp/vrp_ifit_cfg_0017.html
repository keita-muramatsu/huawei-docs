Configuring Performance Measurement Based on Static IFIT Flows

Prerequisites

Before configuring performance measurement based on static IFIT flows, you have completed the following tasks:

  • Configure static routes or dynamic routing protocols to ensure network connectivity between devices.
  • Configure the network time protocol by referring to NTP Configuration.

Context

Figure 1 shows the typical networking of performance measurement based on a static IFIT flow. The target flow enters the transport network through PE1, traverses P, and leaves the transport network through PE2.

  • End-to-end measurement: To monitor transport network performance in real time or diagnose faults, configure IFIT end-to-end measurement on both PE1 and PE2.
  • Hop-by-hop measurement: To measure packet loss and delay hop by hop for fault locating when network performance deteriorates, configure hop-by-hop measurement on PE1, P, and PE2.
    Figure 1 Performance measurement based on static IFIT flows

Procedure

  1. Enter the system view.

    system-view

  2. Enable IFIT globally and enter the IFIT view.

    ifit

  3. Configure the IFIT NE ID.

    node-id node-id

    Typically, only steps 1 to 3 need to be configured on P and PE2 that function as the transit node and egress node, respectively, to implement measurement based on static IFIT flows.

  4. (Optional) Set the timing mode for the IFIT measurement interval and sampling timestamp.

    period-clock-mode { ptp current-leap current-leap-value [ { leap59 | leap61 } date utc-date ] | ntp }

  5. Create an IFIT instance and enter the IFIT instance view.

    instance instance-id

  6. Set the IFIT measurement mode to end-to-end or hop-by-hop.

    measure-mode { e2e | trace }

  7. (Optional) Configure the measurement interval for the IFIT instance.

    interval interval-value

  8. Run any of the following commands to create a static IFIT flow according to the service scenario.

    • In EVPN L3VPNv4 over SRv6 scenarios:
      flow unidirectional source source-ip [ source-mask ] destination destination-ip [ destination-mask ] [ protocol { { tcp | udp | protocol-number4 | protocol-number5 } [ source-port source-port ] [ destination-port destination-port ] | { protocol-number | protocol-number2 | protocol-number3 } } ] [ dscp dscp-value ] [ vpn-instance vpn-instance-name ]
    • In EVPN L3VPNv6 over SRv6 scenarios:
      flow unidirectional source-ipv6 src-ipv6-address [ src6-mask-length ] destination-ipv6 dest-ipv6-address [ dest6-mask-length ] [ protocol { { tcp | udp | protocol-number4 | protocol-number5 } [ source-port source-port ] [ destination-port destination-port ] | { protocol-number | protocol-number2 | protocol-number3 } } ] [ dscp dscp-value ] [ vpn-instance vpn-instance-name ]
    • In public network IPv4 over SRv6 tunnel scenarios:
      flow unidirectional source source-ip [ source-mask ] destination destination-ip [ destination-mask ] [ protocol { { tcp | udp | protocol-number4 | protocol-number5 } [ source-port source-port ] [ destination-port destination-port ] | { protocol-number | protocol-number2 | protocol-number3 } } ] [ dscp dscp-value ]
    • In public network IPv6 over SRv6 tunnel scenarios:
      flow unidirectional source-ipv6 src-ipv6-address [ src6-mask-length ] destination-ipv6 dest-ipv6-address [ dest6-mask-length ] [ protocol { { tcp | udp | protocol-number4 | protocol-number5 } [ source-port source-port ] [ destination-port destination-port ] | { protocol-number | protocol-number2 | protocol-number3 } } ] [ dscp dscp-value ]

  9. Bind the IFIT flow to a specified interface.

    binding interface { interface-type interface-number | interface-name }

    Different IFIT instances can be configured with the same flow characteristics, but cannot be bound to the same interface.

  10. (Optional) Disable packet loss measurement for the IFIT instance.

    loss-measure disable

  11. (Optional) Disable delay measurement for the IFIT instance.

    delay-measure disable
