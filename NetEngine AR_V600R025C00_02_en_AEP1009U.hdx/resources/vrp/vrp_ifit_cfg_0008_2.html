Understanding IFIT Tunnel-Level Quality Measurement

Related Concepts

IFIT tunnel-level quality measurement collects statistics on performance indicators of tunnels on a network. On the network shown in Figure 1, the ingress and egress nodes of a forwarding path function as a Measurement Control Point (MCP) and Data Collecting Point (DCP), respectively. IFIT instances can be created to calculate the quality of each segment list of an SRv6 TE Policy, helping implement intelligent path selection based on measurement results.

Figure 1 IFIT tunnel-level quality measurement

IFIT tunnel-level quality measurement collects statistics on performance indicators of tunnels on a network. As shown in Figure 2, the IFIT measurement model consists of the FEI, IFITMCP, IFIT, and SRPOLICY components.

  • FEI component: collects original IFIT measurement data.
  • IFITMCP component: consists of DCP and MCP. The DCP collects measurement data and reports the data to the MCP. The MCP summarizes the collected data, calculates the result, and sends the result to the SRPOLICY module through the ingress node.
  • IFIT component: creates IFIT measurement instances.
  • SRPOLICY component: triggers IFIT measurement and implements tunnel switching based on the measurement result.
    Figure 2 IFIT measurement model
The working process of the components is as follows:
  1. After IFIT packet loss measurement and delay measurement are enabled on the SRPOLICY component, the SRPOLICY component instructs the IFIT component to create an IFIT measurement instance when creating a segment list. The instance carries the list, measurement parameters, and peer IPv6 address.
  2. The IFIT component assigns a flow ID to an IFIT measurement flow in the corresponding list, creates an IFIT measurement instance, and sends the creation result to the SRPOLICY component. The IFIT header is added to the IFIT measurement instance on the ingress node and is removed on the inbound interface of the egress node.
  3. After receiving the creation success feedback, the SRPOLICY component starts to subscribe to measurement data from the IFITMCP component with a specified threshold.
  4. After the IFITMCP component receives the subscription request, the DCP collects original measurement data from the FEI component.
  5. The DCP sends the collected data to the MCP. The MCP summarizes the data and performs calculation.
  6. If the IFITMCP component determines that the measurement result is greater than the threshold, it advertises the measurement result to the SRPOLICY component.
  7. The Smart Policy Routing (SPR) module of the SRPOLICY component selects routes based on the IFIT measurement result.

Application Scenario

A bank access network connects tier-1 banks to tier-2 banks, branches, subsidiaries, and external organizations. Tier-2 banks, branches, subsidiaries, and external organizations first connect to tier-1 banks, which aggregate service traffic and then connect to the bank core network to implement access between them and the head office data center. With the development of banking services, branch services become diversified. In addition to traditional production and office services, branch services also include security protection, IoT, mixed operation, and public cloud services. These services bring the following changes:

  • The traffic transmission paths are changing. For example, for security protection traffic, tier-2 banks need to access each branch, forming a semi-full-mesh network.
  • The traffic bandwidth is increasing. It is estimated that the bandwidth of a branch will increase to 200 Mbit/s to 300 Mbit/s in the future, and the total bandwidth will increase by 10 times. In addition to using traditional private lines, banks are proactively looking for a substitute for traditional private lines.
  • There are few O&M personnel in branches, and the traditional command-based maintenance mode cannot meet the requirements of growing services.

Based on the preceding changes, it has become a consensus that SD-WAN is used on the access network of banks. In this way, the intelligent O&M solution for one WAN is formed. This solution orchestrates different networks to provide cross-domain network services. In this solution, SRv6 technology is used on the bank access network to simply and quickly establish basic network connections between the cloud and various access points, ensuring efficient service provisioning. The financial industry has high requirements on SLA assurance. The IFIT tunnel-level quality measurement solution can help customers implement intelligent traffic steering, simplify the O&M process, and optimize O&M experience. Figure 3 Network diagram of IFIT tunnel-level quality measurement
This solution has the following characteristics:
  • IFIT can be used to measure the quality of each SRv6 segment list. SPR selects the optimal link based on the measurement result and periodically compares the current link with the optimal link to optimize route selection, implementing intelligent traffic steering.
  • One core controller is deployed on the entire network to implement centralized O&M for the entire bank access network and implement end-to-end visualized management and scheduling.

In this solution, the device is generally used as a branch-side device, and provides the capability of summarizing and calculating measurement data.
