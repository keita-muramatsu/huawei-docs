Configuring Performance Measurement Based on Dynamic IFIT Flows

Prerequisites

Before configuring performance measurement based on dynamic IFIT flows, you have completed the following tasks:

  • Configure static routes or dynamic routing protocols to ensure network connectivity between devices.
  • Configure the network time protocol by referring to NTP Configuration.

Context

IFIT supports automatic learning of dynamic flows on the ingress node. In addition, IFIT can flexibly monitor service quality in real time by configuring a learning whitelist. The generation of dynamic flows on transit and egress nodes is triggered by packets with the IFIT header.

Procedure

  1. Enter the system view.
    system-view
  2. Enable IFIT globally and enter the IFIT view.
    ifit
  3. Configure the IFIT NE ID.
    node-id node-id

    Only steps 1 to 3 need to be performed on transit and egress nodes to implement measurement based on dynamic IFIT flows.

  4. Perform the following steps to configure automatic IFIT flow learning on the ingress node to implement flexible performance measurement based on dynamic IFIT flows:
    1. (Optional) Create an IFIT whitelist group and enter the IFIT whitelist group view.
      whitelist-group whitelist-group-name
    2. (Optional) Run either of the following commands to configure a whitelist rule according to the service scenario:
      • In IPv4 scenarios:
        rule rule-name ipv4 { source { src-ip-address [ src-mask-length ] } | destination { dest-ip-address [ dest-mask-length ] } | protocol { { tcp | udp | protocol-number4 | protocol-number5 } [ source-port src-port-number [ to src-port-number2 ] ] [ destination-port dest-port-number [ to dest-port-number2 ] ] | { protocol-number | protocol-number2 | protocol-number3 } } } *
      • In IPv6 scenarios:
        rule rule-name ipv6 { source-ipv6 { src-ipv6-address [ src6-mask-length ] } | destination-ipv6 { dest-ipv6-address [ dest6-mask-length ] } | protocol { { tcp | udp | protocol-number4 | protocol-number5 } [ source-port src-port-number [ to src-port-number2 ] ] [ destination-port dest-port-number [ to dest-port-number2 ] ] | { protocol-number | protocol-number2 | protocol-number3 } } } *
    3. Create an IFIT VPN instance and enter the IFIT VPN instance view.
      flow-learning vpn-instance vpn-name
    4. Set the measurement mode for IFIT flow learning to end-to-end or hop-by-hop.
      measure-mode { e2e | trace }
    5. (Optional) Configure the measurement interval of IFIT flow learning.
      interval interval-value
    6. Bind IFIT flow learning to a specified interface.
      flow-learning interface { ifType ifNum | ifName } [ whitelist-group whitelist-group-name ]
    7. Return to the IFIT view.
      quit
  5. Run any of the following commands to modify the learned dynamic IFIT flows according to the service scenario:
    • In IPv4 scenarios:
      dynamic flow source src-ip-address [ src-mask-length ] destination dest-ip-address [ dest-mask-length ] vpn-instance vpn-name interface { ifType ifNum | ifName } { protocol { { tcp | udp | protocol-tcp | protocol-udp } [ source-port src-port-number ] [ destination-port dest-port-number ] | { protocol-number | protocol-number2 | protocol-number3 } } } { measure-mode { e2e | trace } | delay-measure { enable | disable } | interval interval-value | { loss-measure-enable | loss-measure-disable } } *
      To clear the learned dynamic IFIT flows, run the following command:
      reset dynamic flow source src-ip-address [ src-mask-length ] destination dest-ip-address [ dest-mask-length ] vpn-instance vpn-name interface { ifType ifNum | ifName } { protocol { { tcp | udp | protocol-tcp | protocol-udp } [ source-port src-port-number ] [ destination-port dest-port-number ] | { protocol-number | protocol-number2 | protocol-number3 } } }
    • In IPv6 scenarios:
      dynamic flow source-ipv6 src-ipv6-address [ src6-mask-length ] destination-ipv6 dest-ipv6-address [ dest6-mask-length ] vpn-instance vpn-name interface { ifType ifNum | ifName } { protocol { { tcp | udp | protocol-tcp | protocol-udp } [ source-port src-port-number ] [ destination-port dest-port-number ] | { protocol-number | protocol-number2 | protocol-number3 } } } { measure-mode { e2e | trace } | delay-measure { enable | disable } | interval interval-value | { loss-measure-enable | loss-measure-disable } } *
      To clear the learned dynamic IFIT flows, run the following command:
      reset dynamic flow source-ipv6 src-ipv6-address [ src6-mask-length ] destination-ipv6 dest-ipv6-address [ dest6-mask-length ] vpn-instance vpn-name interface { ifType ifNum | ifName } [ protocol { { tcp | udp | protocol-tcp | protocol-udp } [ source-port src-port-number ] [ destination-port dest-port-number ] | { protocol-number | protocol-number2 | protocol-number3 } } ]
  6. (Optional) Set the aging time of IFIT dynamic flows to a multiple of the measurement interval.
    dynamic-flow age interval-multiplier multi-value
  7. (Optional) Delete a learned dynamic flow instance.
    reset dynamic flow { flowId | all }
In addition to the preceding configurations, you also need to perform the following steps in a scenario where native-IP IFIT and application-level IFIT measurement domains are interconnected:
  1. In the IFIT view:
    1. Enable native IP flow learning and enter the native-IP IFIT view.
      flow-learning native-ip
    2. (Optional) Configure the color bit for packet loss and delay measurement.
      color-flag { tos-bit { bit3 | bit4 | bit5 | bit6 | bit7 } | flags-bit0 }
  2. Perform the following configurations based on the device role in different scenarios:
    • When the device functions as the ingress node (for application-level IFIT) for switching from native-IP IFIT to application-level IFIT, configure the function of reserving or clearing the color bit in the inbound direction of the device based on the instance in the IFIT VPN instance view.
      mapping-color-flag { keep-color | clear-color }
    • When the device functions as the egress node (for application-level IFIT) for switching from application-level IFIT to native-IP IFIT:
      1. Enter the interface view from the system view.
        interface { interface-name | interface-type interface-number }
      2. Enable color bit switching in the outbound direction.
        ifit egress mapping-color-flag enable
