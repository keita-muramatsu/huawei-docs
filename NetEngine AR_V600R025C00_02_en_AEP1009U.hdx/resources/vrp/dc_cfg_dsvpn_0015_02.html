Example for Configuring DSVPN in Non-Shortcut Mode (OSPF)

Networking Requirements

The HQ (Hub) and branches (Spoke1 and Spoke2) of an SME are located in different areas and their subnet environments change frequently. The branches connect to the HQ and to each other over the public network, and use dynamic addresses to access the public network. The enterprise wants to use a VPN for communication between spokes. To meet this requirement, configure a dynamic routing protocol (OSPF) based on enterprise network planning and deploy DSVPN in non-shortcut mode to achieve direct communication between Spoke1 and Spoke2. Figure 1 shows the related networking.

Figure 1 Network diagram for configuring DSVPN in non-shortcut mode

In this example, interface1 represents 10GE0/0/1.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure DSVPN to enable communication between branches. This is because branches access the public network using dynamic addresses and are unaware of each other's public address.

  2. Considering the small number of branches, configure DSVPN in non-shortcut mode.

  3. Due to frequent changes in subnet environments of the HQ and branches, deploy OSPF based on enterprise network planning for communication between the HQ and branches, which simplifies maintenance.

Procedure

  1. Configure interface IP addresses.

    Configure interface IP addresses on each device.

    # Configure interface IP addresses on Hub.
    <HUAWEI> system-view
[HUAWEI] sysname Hub
[Hub] interface 10ge0/0/1
[Hub-10GE0/0/1] ip address 10.1.1.10 255.255.255.0
[Hub-10GE0/0/1] quit
[Hub] interface tunnel 0
[Hub-Tunnel0] ip address 172.16.1.1 255.255.255.0
[Hub-Tunnel0] quit
[Hub] interface loopback 0
[Hub-LoopBack0] ip address 192.168.0.1 255.255.255.255
[Hub-LoopBack0] quit

    Assign an IP address to each interface on Spoke1 and Spoke2 according to Figure 1. The configurations of the spokes are similar to the configuration of Hub.

  2. Configure devices to be reachable through public network routes.

    Configure OSPF on each device to ensure that public network routes are available.

    # Configure OSPF on Hub.

    [Hub] ospf 2 router-id 10.1.1.10 
[Hub-ospf-2] area 0.0.0.1
[Hub-ospf-2-area-0.0.0.1] network 10.1.1.0 0.0.0.255
[Hub-ospf-2-area-0.0.0.1] quit
[Hub-ospf-2] quit

    # Configure OSPF on Spoke1.

    [Spoke1] ospf 2 router-id 10.1.2.10 
[Spoke1-ospf-2] area 0.0.0.1
[Spoke1-ospf-2-area-0.0.0.1] network 10.1.2.0 0.0.0.255
[Spoke1-ospf-2-area-0.0.0.1] quit
[Spoke1-ospf-2] quit

    # Configure OSPF on Spoke2.

    [Spoke2] ospf 2 router-id 10.1.3.10 
[Spoke2-ospf-2] area 0.0.0.1
[Spoke2-ospf-2-area-0.0.0.1] network 10.1.3.0 0.0.0.255
[Spoke2-ospf-2-area-0.0.0.1] quit
[Spoke2-ospf-2] quit

  3. Configure basic OSPF functions.

    # Configure Hub.

    [Hub] ospf 1 router-id 172.16.1.1
[Hub-ospf-1] area 0.0.0.0
[Hub-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Hub-ospf-1-area-0.0.0.0] network 192.168.0.0 0.0.0.255
[Hub-ospf-1-area-0.0.0.0] quit
[Hub-ospf-1] quit

    # Configure Spoke1.

    [Spoke1] ospf 1 router-id 172.16.1.2
[Spoke1-ospf-1] area 0.0.0.0
[Spoke1-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Spoke1-ospf-1-area-0.0.0.0] network 192.168.1.0 0.0.0.255
[Spoke1-ospf-1-area-0.0.0.0] quit
[Spoke1-ospf-1] quit

    # Configure Spoke2.

    [Spoke2] ospf 1 router-id 172.16.1.3
[Spoke2-ospf-1] area 0.0.0.0
[Spoke2-ospf-1-area-0.0.0.0] network 172.16.1.0 0.0.0.255
[Spoke2-ospf-1-area-0.0.0.0] network 192.168.2.0 0.0.0.255
[Spoke2-ospf-1-area-0.0.0.0] quit
[Spoke2-ospf-1] quit

    The configuration on one spoke subnet is given as an example. Configure other spoke subnets similarly. If a spoke's subnet changes, you only need to configure dynamic routing attributes at that spoke.

  4. Enable NHRP globally.

    # Configure Hub.

    [Hub] nhrp enable

    The configurations of the spokes are similar to the configuration of Hub.

  5. Configure tunnel interfaces.

    Configure a tunnel interface on the hub and each spoke, and configure a static NHRP mapping entry for Hub on Spoke1 and Spoke2.

    # Configure a tunnel interface on Hub.
    [Hub] interface tunnel 0
[Hub-Tunnel0] tunnel-protocol gre p2mp
[Hub-Tunnel0] nhrp enable
[Hub-Tunnel0] source 10ge0/0/1
[Hub-Tunnel0] nhrp entry multicast dynamic
[Hub-Tunnel0] ospf network-type broadcast
[Hub-Tunnel0] quit
    # Configure a tunnel interface and a static NHRP mapping entry for Hub on Spoke1.
    [Spoke1] interface tunnel 0
[Spoke1-Tunnel0] tunnel-protocol gre p2mp
[Spoke1-Tunnel0] nhrp enable
[Spoke1-Tunnel0] source 10ge0/0/1
[Spoke1-Tunnel0] nhrp entry 172.16.1.1 10.1.1.10 register
[Spoke1-Tunnel0] ospf network-type broadcast
[Spoke1-Tunnel0] ospf dr-priority 0
[Spoke1-Tunnel0] quit
    # Configure a tunnel interface and a static NHRP mapping entry for Hub on Spoke2.
    [Spoke2] interface tunnel 0
[Spoke2-Tunnel0] tunnel-protocol gre p2mp
[Spoke2-Tunnel0] nhrp enable
[Spoke2-Tunnel0] source 10ge0/0/1
[Spoke2-Tunnel0] nhrp entry 172.16.1.1 10.1.1.10 register
[Spoke2-Tunnel0] ospf network-type broadcast
[Spoke2-Tunnel0] ospf dr-priority 0
[Spoke2-Tunnel0] quit

Configuration Scripts

  • Hub

    #
sysname Hub
# 
nhrp enable
#
interface 10GE0/0/1
 ip address 10.1.1.10 255.255.255.0
#
interface LoopBack0
 ip address 192.168.0.1 255.255.255.255
# 
interface Tunnel0
 ip address 172.16.1.1 255.255.255.0
 tunnel-protocol gre p2mp
 source 10GE0/0/1
 ospf network-type broadcast
 nhrp enable
 nhrp entry multicast dynamic
# 
ospf 1 router-id 172.16.1.1
 area 0.0.0.0
  network 172.16.1.0 0.0.0.255
  network 192.168.0.0 0.0.0.255
# 
ospf 2 router-id 10.1.1.10
 area 0.0.0.1
  network 10.1.1.0 0.0.0.255
#
return

  • Spoke1

    #
sysname Spoke1
# 
nhrp enable
#
interface 10GE0/0/1
 ip address 10.1.2.10 255.255.255.0
#
interface LoopBack0
 ip address 192.168.1.1 255.255.255.255
#
interface Tunnel0
 ip address 172.16.1.2 255.255.255.0
 tunnel-protocol gre p2mp
 source 10GE0/0/1
 ospf network-type broadcast
 ospf dr-priority 0
 nhrp enable
 nhrp entry 172.16.1.1 10.1.1.10 register
# 
ospf 1 router-id 172.16.1.2
 area 0.0.0.0
  network 172.16.1.0 0.0.0.255
  network 192.168.1.0 0.0.0.255
# 
ospf 2 router-id 10.1.2.10
 area 0.0.0.1
  network 10.1.2.0 0.0.0.255
#
return
