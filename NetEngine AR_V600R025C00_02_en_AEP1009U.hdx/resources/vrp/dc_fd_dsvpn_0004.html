In Figure 1, public addresses refer to Non-Broadcast Multiple Access (NBMA) addresses and tunnel addresses refer to protocol addresses.

DSVPN Node

A DSVPN node is a DSVPN-deployed device, which can be a hub or spoke.

  • Spoke

    A spoke is usually a gateway of an enterprise branch. Generally, a spoke uses a dynamic public address.

  • Hub

    A hub is typically located at an enterprise's HQ and serves as a central device on a DSVPN network, receiving registration messages from spokes. On a DSVPN network, it can use either a fixed or dynamic public address. A fixed public address is recommended. If a hub uses a dynamic public address, spokes must update the destination address for registration whenever the hub's IP changes.

mGRE and mGRE Tunnel Interface

mGRE is a technology developed from GRE and extends point-to-point (P2P) GRE tunnel interfaces to point-to-multipoint (P2MP) mGRE tunnel interfaces. By using a single mGRE tunnel interface, a hub or spoke can connect to multiple remote devices, greatly reducing the configuration workload for GRE tunnels.

An mGRE tunnel interface has the following attributes:
  • Tunnel source address: the source address of a GRE-encapsulated packet. In Figure 1, this is the public address of one tunnel end.
  • Tunnel destination address: the destination address of a GRE-encapsulated packet. In Figure 1, this is the public address of the other end of a tunnel. Unlike the destination address of a GRE tunnel, which is manually specified, the destination address of an mGRE tunnel is determined by NHRP.
  • Tunnel interface IP address: Similar to an IP address of a physical interface, it is used for communication between devices, for example, obtaining routing information. In Figure 1, these addresses are the tunnel addresses (protocol addresses).
  • mGRE tunnel interfaces do not support keepalive detection provided by GRE tunnels.
A GRE tunnel established using mGRE tunnel interfaces is called mGRE tunnel. mGRE tunnels can be classified as static or dynamic:
  • Static mGRE tunnel: connects a hub and spoke and is permanent.
  • Dynamic mGRE tunnel: connects spokes. If a dynamic tunnel has no traffic to forward within a certain period, it is automatically torn down.

NHRP and NHRP Mapping Table

On a DSVPN network, NHRP associates a protocol address (tunnel or subnet address in Figure 1) with an NBMA address (public address in Figure 1). By doing so, it helps a spoke obtain the dynamic public address of another spoke.

An NHRP mapping table contains entries that associate protocol addresses with NBMA addresses. These entries can be classified as static or dynamic:
  • Static entry: manually configured by an administrator. When a spoke needs to establish a static mGRE tunnel with the hub, an administrator needs to specify the hub's tunnel and public addresses on that spoke. This association forms a static NHRP mapping entry.
  • Dynamic entry: dynamically generated by NHRP. After receiving an NHRP Registration Request message from a spoke, the hub extracts the spoke's tunnel and public address from the message and then generates a dynamic NHRP mapping entry for that spoke. Similarly, each spoke generates dynamic NHRP mapping entries for other spokes after receiving NHRP Resolution Request messages from them.
