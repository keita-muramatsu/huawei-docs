Removing the PAF Restriction on the Number of Received BGP Routes

Context

By default, the PAF restriction is enabled on the number of routes received from peers in a BGP address family. With the PAF restriction, if the number of received routes exceeds 80% of the specification, a threshold alarm is generated. If the number of routes received from peers in the BGP address family exceeds 100% of the specification, a limit-crossing alarm is reported, and routes are discarded. To enable the local device to keep accepting routes even after the number of received BGP routes in a BGP address family exceeds the specification, run the bgp paf feature off command to remove the PAF restriction.

Currently, only the PAF restriction on the number of routes received from peers in a BGP address family can be removed. If the PAF restriction is removed, the device can still learn routes after the specification is exceeded. This may consume excessive memory and affect other services. In addition, memory exhaustion may cause the device to reset. Therefore, removing the PAF restriction is not recommended.

Procedure

  1. Enter the system view.

    system-view

  2. Remove the PAF restriction on a specified BGP feature.

    bgp paf feature featureName off
