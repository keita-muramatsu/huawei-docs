Understanding Static BFD for IPv6 Static Routes

Unlike dynamic routes, static routes do not have a dedicated fault detection mechanism. If a link fault occurs on a network, the fault must be manually rectified. BFD for IPv6 static route allows an IPv6 static route to be bound to a BFD session so that the BFD session monitors the status of the link related to the IPv6 static route.

In BFD for IPv6 static route, each IPv6 static route can be bound to a BFD session. If an IPv6 static route is eligible for route selection, whether the static route participates in route selection is also affected by the BFD session status.

  • If the BFD session that monitors an IPv6 static route detects a link fault (the BFD session status is down), the BFD session reports the fault to the system. Then, the system removes the static route from the IP routing table.

  • After the BFD session finds that the link is re-established successfully (the BFD session is up), the BFD session reports the event to the system. Then, the system adds the IPv6 static route to the IP routing table.

  • By default, when a BFD session is in the AdminDown state (triggered using the shutdown command) or a BFD peer is in the AdminDown state, the IPv6 static route bound to the BFD session can participate in route selection. However, if the system is restarted, the BFD session needs to be re-negotiated. Whether the IPv6 static route can participate in route selection depends on the re-negotiated BFD status.

    In static BFD for IPv6 static route, static BFD sessions are established to monitor the link status for IPv6 static routes. When the link related to an IPv6 static route is disconnected, the IPv6 static route that depends on the BFD session is withdrawn from the forwarding table and the active route is re-calculated.

BFD for IPv6 static route works in single-hop detection or multi-hop detection mode.

  • Single-hop detection: Single-hop BFD monitors an IPv6 static route with the configured outbound interface and IP address of a directly connected next hop. The outbound interface name associated with a single-hop BFD session is the outbound interface name carried in the static route, and the peer address is the next-hop address carried in the static route.

  • Multi-hop detection: Multi-hop BFD monitors a static route in which only a next-hop IP address is specified. Such a route needs to recurse to a directly connected next hop, and then a corresponding outbound interface is found. In this case, the peer address of the BFD session is set to the original next-hop address of the route, regardless of which outbound interface is used. Generally, the original next hop to which an IPv6 static route recurses is an indirect next hop. In this situation, multi-hop detection can be used to monitor the recursive static route.
