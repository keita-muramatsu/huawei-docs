Understanding IPsec Link Redundancy

To improve network reliability, a branch needs to establish an IPsec connection with the headquarters through two or more links. This implements IPsec link redundancy so that traffic can be switched to another link if one link fails, ensuring normal service operation. The device supports two IPsec link redundancy modes: IPsec active/standby link redundancy and IPsec multi-link redundancy.

IPsec Link Redundancy Based on a Branch's Tunnel Interfaces

In Figure 1, DeviceA connects to DeviceB through the active and standby links. Two tunnel interfaces (Tunnel 1 and Tunnel 2) are created on DeviceA in the branch using the IP address of the same physical interface and different IPsec policies are applied to the two tunnel interfaces. Different IPsec policies are also applied to the two physical interfaces on DeviceB at the headquarters. In this way, the active and standby IPsec tunnels can be established between DeviceA and DeviceB. In normal situations, traffic is transmitted through the IPsec tunnel established on Tunnel 1 and the active link. If the active link fails, traffic is transmitted through the IPsec tunnel established on Tunnel 2 and the standby link, and the old IPsec tunnel is deleted.

Figure 1 IPsec link redundancy based on a branch's tunnel interfaces

IPsec link redundancy based on the headquarters' tunnel interface

In Figure 2, DeviceA connects to DeviceB through the active and standby links. An IPsec tunnel is established between the physical interface of DeviceA and tunnel interface (Tunnel 1) of DeviceB. Traffic between the branch and headquarters is IPsec-protected through the tunnel interface and sent out by a physical interface according to the routing table. If the active link fails, traffic is switched to the standby link.

IPsec link redundancy based on the headquarters' tunnel interface is easier to configure and does not require IPsec tunnel renegotiation when compared with IPsec link redundancy based on a branch's tunnel interfaces. Therefore, traffic can be quickly switched.

Figure 2 IPsec link redundancy based on the headquarters' tunnel interface

When multiple IPsec gateways are connected to different ISP networks or the same ISP network but the active and standby links are connected to different access routers of the same ISP network across LANs or areas, if the active link becomes faulty, the device on the standby link may discard the IPsec packets whose source address belongs to a different ISP network or access router. Therefore, before configuring link redundancy, check whether active/standby link switchover is allowed in the actual network environment.
