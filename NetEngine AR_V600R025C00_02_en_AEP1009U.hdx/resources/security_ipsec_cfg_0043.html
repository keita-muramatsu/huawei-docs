Configuring IPsec Packet Fragmentation

Prerequisites

IPsec packet fragmentation takes effect for the following IPsec types:
  • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
  • Route-based IPsec (involving IPsec profiles)

Fragmentation before encryption is not supported when the IPsec encapsulation mode is transport. You need to run the encapsulation-mode tunnel command to set the encapsulation mode to tunnel mode.

Context

After packets are encapsulated with IPsec headers, the packet length may exceed the MTU allowed by the outbound interface of the device. You need to fragment the packets to prevent packet loss. Two methods are available for packet fragmentation:

  • Fragmentation after encryption: If the length of an IPsec-encapsulated packet exceeds the MTU of the outbound interface, an encryption device encrypts the packet and then fragments it based on the MTU of the outbound interface. In this case, the remote device needs to reassemble and decrypt the packet. Therefore, the remote device must support packet fragmentation and reassembly. If the remote device does not support packet fragmentation and reassembly, the packet will be discarded or incorrectly processed, affecting packet transmission.

  • Fragmentation before encryption: Before encapsulating a packet, an encryption device calculates the estimated length of the encapsulated packet. If the calculated length exceeds the MTU of the outbound interface, the encryption device fragments the packet and then encrypts the fragmented packet. In this case, the remote device can decapsulate the packet without reassembling the fragments, and the destination host reassembles the packet. This ensures that the decapsulated packet can be forwarded normally, reducing the CPU usage of the decryption device.

The device supports the configuration of global IPsec packet fragmentation and the configuration of IPsec packet fragmentation for a single IPsec policy or IPsec profile. If both configurations are performed, the configuration of IPsec packet fragmentation for a single IPsec policy or IPsec profile takes precedence over the global configuration.

Procedure

  • Configure global IPsec packet fragmentation before encryption.
    1. Enter the system view.

      system-view

    2. Configure global IPsec packet fragmentation before encryption.

      ipsec fragmentation before-encryption

      By default, IPsec packets are encrypted before being fragmented.

    3. Optional: Set the don't fragment (DF) bit for IPsec packets.

      ipsec df-bit { clear | set | copy }

      By default, the DF bit of IPsec packets is copied. That is, the DF bit of encapsulated IPsec packets is the same as that of original packets.

      If IPsec packets are fragmented after being encrypted, whether IPsec packets can be fragmented depends on the DF bit of encapsulated IPsec packets. If the DF bit of original IPsec packets is 1 (indicating that IPsec packets cannot be fragmented), you need to run the ipsec df-bit clear command in the system view to set the DF bit of encapsulated IPsec packets to 0 so that encapsulated IPsec packets can be fragmented.

    4. Optional: Configure the function of ignoring the DF bit in original packets.

      ipsec fragmentation ignore df-bit

      By default, the function of ignoring the DF bit in original packets is disabled.

      After IPsec fragmentation before encryption is enabled, whether original packets can be fragmented depends on the DF bit in original packets. If the DF bit is 1, original packets cannot be fragmented. If the DF bit is set to 0, original packets can be fragmented. You can run this command to enable the function of ignoring the DF bit in original packets. Then the device fragments the packets before encrypting them, without checking the DF bit in the packets.

  • Configure IPsec packet fragmentation before encryption in a specified IPsec policy or IPsec profile.
    1. Enter the system view.

      system-view

    2. Enter the IPsec policy view or IPsec profile view.

      # Enter the ISAKMP IPsec policy view.

      ipsec policy policy-name seq-number [ isakmp ]

      # Enter the template IPsec policy view.

      ipsec policy-template template-name seq-number

      # Enter the IPsec profile view.

      ipsec profile profile-name

    3. Configure IPsec packet fragmentation before encryption in an IPsec policy.

      fragmentation before-encryption

      By default, IPsec packets are encrypted before being fragmented in an IPsec policy.

    4. Optional: Return to the system view and configure the DF bit of IPsec packets.

      quit
ipsec df-bit { clear | set | copy }

      By default, the DF bit of IPsec packets is copied. That is, the DF bit of encapsulated IPsec packets is the same as that of original packets.

      If IPsec packets are fragmented after being encrypted, whether IPsec packets can be fragmented depends on the DF bit of encapsulated IPsec packets. If the DF bit of original IPsec packets is 1 (indicating that IPsec packets cannot be fragmented), you need to run the ipsec df-bit clear command in the system view to set the DF bit of encapsulated IPsec packets to 0 so that encapsulated IPsec packets can be fragmented.

    5. Optional: Configure the function of ignoring the DF bit in original packets.

      ipsec fragmentation ignore df-bit

      By default, the function of ignoring the DF bit in original packets is disabled.

      After IPsec fragmentation before encryption is enabled, whether original packets can be fragmented depends on the DF bit in original packets. If the DF bit is 1, original packets cannot be fragmented. If the DF bit is set to 0, original packets can be fragmented. You can run this command to enable the function of ignoring the DF bit in original packets. Then the device fragments the packets before encrypting them, without checking the DF bit in the packets.
