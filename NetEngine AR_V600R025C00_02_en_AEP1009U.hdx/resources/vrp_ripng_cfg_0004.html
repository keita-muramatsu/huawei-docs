RIPng Message Format

A RIPng message consists of a header and multiple route table entries (RTEs). In a RIPng message, the maximum number of RTEs depends on the MTU of an interface.

Figure 1 shows the RIPng message format.

Figure 1 RIPng message format

The fields in a RIPng message are described as follows:

  • Command: identifies the type of the RIPng message. The value 1 indicates a Request message, and the value 2 indicates a Response message.
  • Version: specifies the RIPng version. The value of this field is 1.
  • Must be zero: In RIPng, the value of this field is 1.
  • RTE: specifies a routing entry.
A RIPng message contains two types of RTEs:

  • Next hop RTE: Located before the IPv6-prefix RTEs that have the same next hop, a next hop RTE defines the next hop IPv6 address. Generally, the value of a next hop RTE is 0xFF.

  • IPv6-prefix RTE: Located after a next-hop RTE, an IPv6-prefix RTE describes the destination IPv6 address and the cost in the RIPng routing table. Several different IPv6-prefix RTEs can exist after a next-hop RTE.

Figure 2 shows the format of a next hop RTE.

Figure 2 Format of a next hop RTE

The fields of a next hop RTE are described as follows:

  • IPv6 next hop address: specifies the IPv6 address of the next hop.

Figure 3 shows the format of an IPv6-prefix RTE.

Figure 3 Format of an IPv6-prefix RTE

The fields of an IPv6-prefix RTE are described as follows:

  • IPv6 prefix: specifies the prefix of the destination IPv6 address.
  • Route tag: indicates the tag of a route. It is used to distinguish external routes.
  • Prefix len: specifies the prefix length of an IPv6 address.
  • Metric: specifies the metric of a route.
