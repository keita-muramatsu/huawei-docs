Configuring Network Slice Instances

Configuring network slice instances is the first step for implementing network slicing. Interfaces can be added to network slices only after network slice instances are configured.

Procedure

  1. Enter the system view.

    system-view

  2. (Optional) Configure a protocol number for network slices in an IPv6 packet header.

    network-slice protocol-number number

    protocol-number number determines the value of the Next Header field in an IPv6 header. This field indicates that the next header is the HBH header.

    • When all devices support network slicing, you can skip this step and use the default protocol number of 0. In this way, all the devices can identify the HBH header and steer packets to specified slice interfaces.
    • If transit nodes does not support network slicing, you need to configure the protocol number on the other devices. The transit nodes then transparently transmit IPv6 packets rather than transmitting them over a network slice. This command is mandatory in this scenario. Otherwise, the transit nodes fail to forward packets.

  3. Create a network slice instance.

    network-slice instance netSliceInstId

    You can repeat this step to create multiple network slice instances.

  4. (Optional) Configure a description for the network slice instance.

    description instDescrip
