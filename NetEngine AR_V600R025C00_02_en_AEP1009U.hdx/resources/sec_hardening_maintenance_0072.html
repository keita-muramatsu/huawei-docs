DHCP Security

Overview

When a device functioning as a DHCP server or relay agent receives a large number of DHCP messages from a malicious user, the device's processing capability is wasted on such invalid messages, which in turn prevents it from processing valid DHCP messages. This ultimately prevents clients from obtaining or renewing IP addresses.

To defend against this kind of attack, configure the following security policies on a device:

  • DHCP user-level protection

    The device uses attack source tracing to monitor the rate of DHCP messages sent to the control plane from each user based on their MAC or IP addresses. If a user's rate exceeds a specified threshold, the device discards DHCP messages sent from this user for a period of time.

    Attack source tracing is enabled by default. Attack source tracing allows you to modify information such as the check threshold, sampling ratio, punishment action, and whitelist.

Impact on the System

None

Procedure

  1. Configure attack source tracing. To prevent valid DHCP messages from being filtered out, add the interface (for example, 10GE0/0/1) connected to a valid DHCP server to the whitelist for attack source tracing.

    <Huawei> system-view 
[Huawei] cpu-defend policy antiatk 
[Huawei-cpu-defend-policy-antiatk] auto-defend enable 
[Huawei-cpu-defend-policy-antiatk] auto-defend threshold 30 
[Huawei-cpu-defend-policy-antiatk] auto-defend attack-packet sample 5 
[Huawei-cpu-defend-policy-antiatk] auto-defend action deny timeout 300 
[Huawei-cpu-defend-policy-antiatk] auto-defend whitelist 1 interface 10ge 0/0/1  
[Huawei-cpu-defend-policy-antiatk] quit 
[Huawei] cpu-defend-policy antiatk

Verifying the Security Hardening Result

Run the display auto-defend configuration command to check the configuration of attack source tracing.
