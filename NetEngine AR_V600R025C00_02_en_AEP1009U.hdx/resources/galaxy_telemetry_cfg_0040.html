gRPC Service Modes

The RPC service specifies the methods that can be remotely called using parameters and return values. gRPC uses the Protocol Buffers language to define the methods, parameters, and return values of services. The methods are defined in a .proto file. The format is as follows:

service Service name {

rpc Method name(stream Parameter name) returns(stream Return value) {};

}

Example:

service gRPCDataservice {

rpc dataPublish(stream serviceArgs) returns(stream serviceArgs) {} ;

}

Table 1 describes the gRPC service modes according to the location of the keyword stream.

Table 1 gRPC service modes

Service Mode

Description and Example

Simple mode

Simple interaction in request-response mode.

Example: rpc Cancel(CancelArgs) returns(CancelReply) {};

Server streaming mode

The client sends a request, and the server continuously returns data to the client.

Example: rpc Subscribe(SubsArgs) returns(stream SubsReply) {};

Client streaming mode

The client continuously pushes data to the server and waits for a response from the server.

Example: rpc LotsOfGreetings(stream HelloRequest) returns (HelloResponse) {};

Bidirectional streaming mode

Both the client and server can send a series of messages using a read/write data stream. The two data streams sent by the client and server are independent of each other. The communication parties can further control interaction based on the content of data streams, maximizing flexibility.

Example: rpc dataPublish(stream serviceArgs) returns(stream serviceArgs) {};
