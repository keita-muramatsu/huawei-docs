Configuring an IKE Proposal

Context

An IKE proposal defines IKE negotiation parameters, including the encryption algorithm, authentication method, authentication algorithm, Diffie-Hellman (DH) group, and security association (SA) lifetime.

During IKE negotiation, the initiator sends its IKE proposal to the responder. The responder starts from the highest priority IKE proposal to match its IKE proposals against the received IKE proposal and uses the first matched one to establish an IKE SA. The priority of an IKE proposal is determined by its sequence number. A smaller sequence number indicates a higher priority.

Two matching IKE proposals define the same encryption algorithm, authentication method, authentication algorithm, and DH group. If both ends have a different IKE SA lifetime, the two ends use the smaller IKE SA lifetime for IKE negotiation.

By default, there is an IKE proposal Default with the lowest priority and default parameter values. If only the sequence number is specified during the creation of an IKE proposal, the parameters in the IKE proposal use the default values. Default Settings for IPsec describes the default settings for an IKE proposal.

Procedure

  1. Enter the system view.

    system-view

  2. Create an IKE proposal and enter the IKE proposal view.

    ike proposal { proposal-number | default }

  3. Configure an identity authentication method.

    authentication-method { pre-share | rsa-signature | sm2 digital-envelope }

    By default, an IKE proposal uses pre-shared key (PSK) authentication.

    In IKE negotiation, the authentication methods in the IKE proposals used by the IKE peers on both ends must be the same. Otherwise, IKE negotiation fails.

    SM digital envelope authentication is supported only in IKEv1 negotiation scenarios. The sm2 digital-envelope parameter can be configured only after the IKEv1 feature package is installed.

  4. Configure the identity authentication algorithm used for IKEv1 negotiation.

    authentication-algorithm { md5 | sha1 | sha2-256 | sha2-384 | sha2-512 | sm3 }*

    By default, the SHA2-256 authentication algorithm is used for IKEv1 negotiation.

    An authentication algorithm must be configured for IKEv1 negotiation. The following authentication algorithms are listed in descending order of security level: SM3, SHA2-512, SHA2-384, SHA2-256, SHA1, and MD5. Of these, SHA1 and MD5 are not recommended because they cannot meet security requirements.

  5. Configure the identity encryption algorithm used for IKE negotiation.

    encryption-algorithm { des | 3des | aes-128 | aes-192 | aes-256 | sm4 | aes-gcm-128 | aes-gcm-192 | aes-gcm-256 }*

    By default, the AES-GCM-256 encryption algorithm is used for IKE negotiation.

    The following encryption algorithms are listed in descending order of security level: SM4, AES-GCM-256, AES-GCM-192, AES-GCM-128, AES-256, AES-192, AES-128, 3DES, and DES. DES, 3DES, and AES in CBC mode are not recommended because they cannot meet security requirements.

  6. Configure the DH group used for IKE negotiation.

    dh { group1 | group2 | group5 | group14 | group15 | group16 | group18 | group19 | group20 | group21 | group24 }*

    By default, the DH group used for IKE negotiation is Group 14.

    The following DH groups are listed in descending order of security level: Group 24, Group 21, Group 20, Group 19, Group 18, Group 16, Group 15, Group 14, Group 5, Group 2, and Group 1. Group 1, Group 2, and Group 5 are not recommended because they cannot meet security requirements.

  7. Configure the pseudo-random function (PRF) algorithm used for IKEv2 negotiation.

    prf { aes-xcbc-128 | hmac-md5 | hmac-sha1 | hmac-sha2-256 | hmac-sha2-384 | hmac-sha2-512 }*

    By default, the HMAC-SHA2-256 PRF algorithm is used for IKEv2 negotiation.

    AES-XCBC-128, HMAC-MD5 and HMAC-SHA1 are not recommended because they cannot meet security requirements.

  8. Configure the identity authentication algorithm used for IKEv2 negotiation.

    integrity-algorithm { aes-xcbc-96 | hmac-md5-96 | hmac-sha1-96 | hmac-sha2-256 | hmac-sha2-384 | hmac-sha2-512 }*

    By default, the HMAC-SHA2-256 authentication algorithm is used for IKEv2 negotiation.

Verifying the Configuration

Run the display ike proposal [ number proposal-number | default ] [ slot slot-id cpu cpu-id ] command in the user view to check the IKE proposal configuration.

Follow-up Procedure

The configured IKE proposal can be referenced by IKE peers. For details, see Configuring an IKE Peer.
