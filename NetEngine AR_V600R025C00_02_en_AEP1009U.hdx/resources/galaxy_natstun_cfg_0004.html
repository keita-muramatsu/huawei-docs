STUN Message Structure

All STUN messages start with a 20-byte header, followed by zero or more STUN attributes.

Message Header

As shown in Figure 1, a STUN message header contains four fields: STUN Message Type, Message Length, Magic Cookie, and Transaction ID. The most significant two bits of every STUN message must be 0s so that STUN messages can be differentiated from messages of other protocols when STUN is multiplexed with other protocols on the same UDP port.

Figure 1 STUN message header

STUN Message Type

This field is 14 bits in length. Currently, only two STUN message types are supported: STUN binding request messages and STUN binding response messages. Their STUN Message Type field values are 0x0001 and 0x0101, respectively.

Message Length

This field indicates the length of a message, excluding that of the message header. This field is 16 bits in length.

Magic Cookie

This field is 32 bits in length and fixed at 0x2112A442. It allows a STUN server to detect if a STUN client can understand certain attributes. Furthermore, it helps distinguish STUN messages from messages of other protocols when STUN is multiplexed with other protocols on the same UDP port.

Transaction ID

This field is 96 bits in length and uniquely identifies STUN transactions. For request/response transactions, the transaction ID is chosen by the STUN client for the request and echoed by the server in the response. The STUN server also uses the transaction ID to identify each transaction uniquely across all clients.

STUN Attribute

Following the STUN message header are zero or more STUN attributes. Each attribute must be Type-Length-Value (TLV) encoded, with a 16-bit Type field, a 16-bit Length field, and a variable length Value field. Figure 2 shows the STUN attribute format.

Figure 2 STUN attribute format

Table 1 lists the supported STUN attributes.

Table 1 STUN attributes

Attribute (Type)

Value

Description

MAPPED-ADDRESS

0x0001

Post-NAT IP address and port number of a STUN client. This attribute is used by STUN servers for backwards compatibility with STUN clients.

USERNAME

0x0006

Used for authentication and message integrity check. It identifies the username used in the authentication and message integrity check. The STUN server and STUN client can use the username carried in the message to retrieve the password associated with this username and use the password as the key for calculating the Hash-based Message Authentication Code (HMAC) value.

MESSAGE-INTEGRITY

0x0008

Contains the HMAC value of the STUN message. The MESSAGE-INTEGRITY attribute can be present in any STUN message type. The STUN server and STUN client can calculate the HMAC value of a STUN message (including the message header and attributes preceding the MESSAGE-INTEGRITY attribute), and compare the calculated HMAC value with the HMAC value carried in the MESSAGE-INTEGRITY field to perform authentication and message integrity check.

XOR-MAPPED-ADDRESS

0x0020

Post-NAT IP address and port number of a STUN client. This attribute is identical to the MAPPED-ADDRESS attribute, except that IP addresses are obfuscated through the exclusive or (XOR) function.

RESPONSE-ORIGIN

0x802b

IP address and port number used by the STUN server. This attribute helps determine whether a NAT device is in front of the server.

SOFTWARE

0x8022

Software version.

PATHSET

0xb001

Huawei extended attribute, which uniquely identifies a Software-Defined WAN (SD-WAN) tunnel.
