Configuring Heartbeat Detection

Prerequisites

  • Heartbeat detection takes effect only for IKEv1 negotiation.
  • Heartbeat detection can be configured only for the following types of IPsec:
    • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
    • Route-based IPsec (involving IPsec profiles)

Context

The IKE protocol does not provide the peer status detection mechanism. If one IKE peer does not respond to the other IKE peer, the other IKE peer continues to send IPsec traffic until the SA lifetime expires because it cannot detect the change of the peer. An SA between two IKE peers exists until its lifetime expires. If an IKE peer becomes unreachable, an IPsec black hole will occur and data flows will be discarded. IPsec communication can be restored rapidly only when black holes are identified and detected in a timely manner. To solve this issue, the device provides the heartbeat detection mechanism.

Heartbeat detection enables the local end to periodically send heartbeat packets to the remote end. If the local end does not receive heartbeat packets from the remote end within the timeout interval, the local end considers the remote end as unreachable and deletes the IKE SA or IPsec SA between IKE peers.

Heartbeat detection has the following limitations:
  • Enabling heartbeat detection will consume CPU resources to process IKE keepalive messages, limiting the number of IPsec sessions to be established.
  • There are no uniform technical standards for heartbeat detection, so devices from different vendors may be unable to communicate with each other.

To address these limitations, the device also supports dead peer detection (DPD). For details, see Configuring DPD. When both heartbeat detection and DPD are enabled on the device, only DPD takes effect.

Procedure

  1. Enter the system view.

    system-view

  2. Configure heartbeat packet parameters.

    ike heartbeat { seq-num { new | old } | spi-list }

    By default, a heartbeat packet uses old type sequence number mechanism and does not carry the SPI list.

  3. Configure the heartbeat interval in an IKE SA.

    ike heartbeat-timer interval interval

    By default, the heartbeat interval in an IKE SA is not configured.

  4. Configure the heartbeat timeout period.

    ike heartbeat-timer timeout seconds

    By default, the heartbeat timeout period is not configured.

    If the ike heartbeat-timer timeout command is configured on one end, the ike heartbeat-timer interval command must be configured on the other end. The heartbeat timeout period is often longer than the interval at which heartbeat packets are sent. Generally, packets will not be lost for more than three consecutive times on the network. Therefore, you can set the value of seconds to three times the value of interval.
