Configuring Fast Access for New Branches

Prerequisites

  • Fast access for new branches takes effect only when the headquarters functions as the responder in IPsec negotiation and a template IPsec policy is used.
  • The ACL rules configured for a new branch are the same as those configured for an existing branch.
  • The interface through which a new branch accesses the headquarters is the same as that through which an existing branch accesses the headquarters.

Context

After the branch establishes an IPsec tunnel with the headquarters, the IP address of the interface to which an IPsec policy group is applied changes due to the link status change. Because the headquarters already has an IPsec tunnel to protect the traffic transmitted between the headquarters and branch, protected data flows will conflict with each other. The branch and headquarters cannot quickly establish a new IPsec tunnel before IPsec SAs are aged out. You can configure fast access for the new branch so that the IPsec SAs established between the existing branch and headquarters can be aged out quickly and a new IPsec tunnel can be established between the new branch and headquarters.

Procedure

  1. Enter the system view.

    system-view

  2. Configure fast access for new branches.

    ipsec remote traffic-identical accept

    By default, fast access is enabled for new branches.
