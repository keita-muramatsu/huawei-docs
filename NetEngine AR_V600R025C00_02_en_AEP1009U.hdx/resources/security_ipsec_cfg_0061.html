Configuring IPsec Check

Prerequisites

IPsec check takes effect only for the following IPsec types:

  • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
  • Route-based IPsec (involving IPsec profiles)

Context

For security purposes, do not disable IPsec check. After IPsec check is disabled, the device permits unencrypted packets and cannot prevent internal attackers.

IPsec check ensures that data flows are correctly encrypted. After IPsec check is enabled, the device checks decrypted cleartext packets and discards the encrypted packet if the packet is supposed to be unencrypted.
  • In an ACL-based IPsec scenario, if the IPsec encapsulation mode is set to tunnel mode, the internal IP header of the decapsulated IPsec packets in the inbound direction of an SA may not be in the range defined in the ACL referenced by the current IPsec policy, for example, the header of maliciously constructed attack packets on the network. If post-IPsec check is configured, the device checks whether the internal IP header of packets is in the range defined in the ACL. If not, the device discards the packets, improving network security.
  • In a route-based IPsec scenario, after an IPsec profile is applied to a tunnel interface, the device generates an ACL based on the encapsulation mode of the tunnel interface. The generated ACL varies depending on the encapsulation mode of the tunnel interface. When the encapsulation mode is set to IPsec, the source and destination addresses in the generated ACL can be any addresses, indicating that all data flows to the tunnel interface will be protected. When the encapsulation mode is set to GRE, the source and destination addresses in the generated ACL are the source and destination addresses of the tunnel interface. The internal IP header of the decapsulated IPsec packets in the inbound direction of an SA may not be in the range defined in the generated ACL, for example, the header of maliciously constructed attack packets on the network. If post-IPsec check is configured, the device checks whether the internal IP header of packets is in the range defined in the generated ACL. If not, the device discards the packets, improving network security.

Procedure

  1. Enter the system view.

    system-view

  2. Enable IPsec check.

    ipsec decrypt check

    By default, IPsec check is enabled.
