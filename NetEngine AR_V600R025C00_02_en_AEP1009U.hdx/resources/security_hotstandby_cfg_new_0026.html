Example for Configuring Hot Standby in an SD-WAN EVPN Dual-Gateway Site Scenario

Networking Requirements

As shown in Figure 1, DeviceA and DeviceB form an SD-WAN EVPN branch site, which runs in dual-gateway mode. To transmit the information that must be synchronized and the status entry information required by dual-gateway, the two devices need to establish a hot standby channel. In addition, the devices need to support application identification if packets are sent and received over different paths.

This section describes only the hot standby configuration. For details about the SD-WAN EVPN service configuration, see the corresponding scenario example.

Figure 1 Network diagram of an SD-WAN EVPN dual-gateway site

In this example, interface1, interface2, interface3, and interface4 represent 10GE 0/0/1, 10GE 0/0/2, 10GE 0/0/3, and 10GE 0/0/4, respectively.


Procedure

  1. Configure IP addresses for heartbeat interfaces.

    DeviceA

    DeviceB

    		 
    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10ge 0/0/4
[DeviceA-10GE0/0/4] ip address 10.10.0.1 24
[DeviceA-10GE0/0/4] quit 
    <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10ge 0/0/4
[DeviceB-10GE0/0/4] ip address 10.10.0.2 24
[DeviceB-10GE0/0/4] quit

  2. Specify the heartbeat interface, configure the authentication key, and enable hot standby.

    DeviceA

    DeviceB

    		 
    [DeviceA] hrp interface 10ge 0/0/4 remote 10.10.0.2 
[DeviceA] hrp authentication-key YsHsjx_202206
[DeviceA] hrp enable 
    [DeviceB] hrp interface 10ge 0/0/4 remote 10.10.0.1 
[DeviceB] hrp authentication-key YsHsjx_202206
[DeviceB] hrp enable

  3. Set the gateway type of the site to dual-gateway. Assume that the site system ID is 1.1.1.1 for DeviceA and 2.2.2.2 for DeviceB.

    DeviceA

    DeviceB

    		 
    [DeviceA] evpn site 1 
[DeviceA-site-1] gateway dual peer-system-id 2.2.2.2
[DeviceA-site-1] quit
    		 
    [DeviceB] evpn site 1 
[DeviceB-site-1] gateway dual peer-system-id 1.1.1.1
[DeviceB-site-1] quit

  4. Configure an interface type.

    DeviceA

    DeviceB

    		 
    [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] port-type nni
[DeviceA-10GE0/0/1] quit 
[DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] port-type ini
[DeviceA-10GE0/0/2] quit
[DeviceA] interface 10ge 0/0/3
[DeviceA-10GE0/0/3] port-type uni
[DeviceA-10GE0/0/3] quit
    		 
    [DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] port-type nni
[DeviceB-10GE0/0/1] quit 
[DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] port-type ini
[DeviceB-10GE0/0/2] quit
[DeviceB] interface 10ge 0/0/3
[DeviceB-10GE0/0/3] port-type uni
[DeviceB-10GE0/0/3] quit
