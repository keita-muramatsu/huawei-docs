Storing, Sending, and Viewing Logs

When packets pass through a device and corresponding log generation and recording conditions are met, the log module of the device assembles packets according to the configured log format. Then, the device sends logs to the log server or other storage paths to allow end users to view the logs in the storage paths.

The device provides multiple log storage paths:

  • Log buffer: A portion of memory space in the system. If the number of logs in the log buffer reaches the upper limit, new logs will replace the existing logs, starting with the oldest logs, until all the new logs are stored. It can be used to store a small number of service logs and system logs in syslog format.
  • Log file: The log information is saved in the log.log format on the device. A small number of service logs and system logs can be stored in syslog format. Log files are usually used for troubleshooting.
  • Log server: After receiving the log information from the device, the log server processes the data and displays it in various logs. Administrators can conveniently check these logs. The log server has a large storage space and can store log data for a long period of time. Therefore, the log server is recommended.

Some logs cannot be stored on the device and need to be sent directly to the log server, and some logs are sent to the log server through the information center. Table 1 describes the methods of storing, sending, and viewing logs of each type.

Log Type

Log Format

Storage and Sending Method

Viewing Method

Session log
  • Binary
  • Syslog

Session logs are not stored on the device. Instead, the device directly sends session logs to the log server through an independent channel.
  • You can view session logs in binary format on SecoManager.
  • You can view session logs in syslog format on SecoManager or a third-party log server.

System log

Syslog
  • System logs are stored in the log buffers or log files through the information center and can be sent to the log server, console (console user interfaces), or terminals (VTY user interfaces).
  • For system logs stored in log files, you can run the display logfile flash:/logfile/log.log command to view detailed contents in log files.
  • To view system logs stored in the log buffer, you can run the display logbuffer command.
  • You can log in to the device through the console port, Telnet, or STelnet, and run the terminal monitor and terminal logging commands on the CLI to enable the function of displaying logs on the terminal.
  • System logs can be viewed on the log server.

Service log

Syslog
  • Service logs in syslog format can be stored in the log buffers or log files through the information center, or sent to the console (console user interfaces) or terminals (VTY user interfaces). In addition, the device can send service logs in syslog format to the log server.
  • For service logs in syslog format stored in log files, you can run the display logfile flash:/logfile/service/service.log command to view detailed contents in log files.
  • To view service logs stored in the log buffer, you can run the display logbuffer service-log command.
  • You can log in to the device through the console port, Telnet, or STelnet, and run the terminal monitor and terminal logging commands on the CLI to enable the function of displaying logs on the terminal.
  • The logs can be viewed on the log server.
