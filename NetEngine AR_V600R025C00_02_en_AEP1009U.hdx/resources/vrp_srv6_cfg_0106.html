Configuring an SRv6 TE Policy

Context

SRv6 TE Policies are used to guide traffic over an SRv6 TE network. Each SRv6 TE Policy can have multiple candidate paths with different preferences. From the valid candidate paths, the one with the highest preference is selected as the primary path, and the one with the second highest preference is selected as the backup path.

An SRv6 TE Policy can either be configured manually or be delivered by a controller. This section describes how to configure an SRv6 TE Policy manually.

Procedure

  1. Configure a segment list.
    1. Enter the system view.

      system-view

    2. Enable SRv6 and enter the SRv6 view.

      segment-routing ipv6

    3. Create a segment list for the SRv6 TE Policy candidate path and enter the segment list view.

      segment-list list-name

    4. Specify the next-hop SID in the segment list.

      index index sid ipv6 ipv6address

      You can run the command multiple times to specify multiple SIDs. According to index index, the system generates a SID stack in ascending order. If a candidate path in the SRv6 TE Policy is preferentially selected, traffic is forwarded using the segment list of the candidate path. A maximum of 10 SIDs can be configured for each segment list.

  2. Configure an SRv6 TE Policy.
    1. Enter the system view.

      system-view

    2. Enable SRv6 and enter the SRv6 view.

      segment-routing ipv6

    3. (Optional) Configure switching and deletion delays for all SRv6 TE Policies.

      srv6-te-policy switch-delay switchDelay delete-delay deleteDelay

    4. Configure a locator to specify a binding SID for the SRv6 TE Policy to be created.

      srv6-te-policy locator locator-name

    5. Create an SRv6 TE Policy and enter the SRv6 TE Policy view.

      srv6-te policy name-value endpoint endpoint-ip color color-value

    6. (Optional) Specify a binding SID for the SRv6 TE Policy.

      binding-sid binding-sid

      The value of binding-sid must be within the static range defined using the locator locator-name [ ipv6-prefix ipv6-address mask-length [ static static-length | args args-length ] * ] command.

    7. Configure a candidate path and its preference for the SRv6 TE Policy.

      candidate-path preference pref-value

      Each SRv6 TE Policy supports multiple candidate paths. A larger preference value indicates a higher candidate path preference. If multiple candidate paths are configured, the one with the highest preference takes effect.

    8. Configure a segment list for the candidate path of the SRv6 TE Policy.

      segment-list list-name [ weight weight-value | path-mtu mtu-value | binding-sid binding-sid-value | reverse-binding-sid reverse-binding-sid-value ] *

      The segment list must have been created using the segment-list (Segment-routing IPv6 view) command.

      In unaffiliated BFD (U-BFD) for SRv6 TE Policy scenarios, return packets are forwarded through IPv6 routes by default, which may cause the U-BFD status to be incorrect. To enable U-BFD return packets to be forwarded through an SRv6 TE Policy, use the reverse-binding-sid reverse-binding-sid-value parameter to specify a binding SID (BSID) for the reverse segment list. Alternatively, use the binding-sid binding-sid-value parameter to specify a BSID for the local segment list so that the peer end can reference this BSID.

    9. (Optional) Configure the switching delay for the reverse binding SID of an SRv6 TE Policy's segment list and the deletion delay for the forward binding SID of the SRv6 TE Policy's segment list.

      srv6-te-policy segment-list reverse-binding-sid switch-delay switchDelay binding-sid delete-delay deleteDelay
