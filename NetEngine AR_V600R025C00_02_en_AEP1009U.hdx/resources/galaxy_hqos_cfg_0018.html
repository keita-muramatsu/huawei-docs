CBQ Configuration Model

The class-based queuing (CBQ) configuration model simplifies the parent and child traffic policy configuration model and allows you to configure queue scheduling without nesting traffic policies. The CBQ configuration model provides user-defined scheduling for a type of queues. When user-defined scheduling does not need to be performed for SQs and FQs at the same time, the CBQ configuration model is recommended because it is easier and faster to configure and occupies less system resources.

In the CBQ configuration model, you only need to define the QoS parameters of SQs or FQs through MQC. The device will automatically deliver the other type of default queues to establish the queue association relationships with the configured queues, implementing hierarchical scheduling. Figure 1 shows the CBQ configuration model.

The CBQ configuration model supports only queue scheduling HQoS.

Figure 1 CBQ configuration model

After a CBQ traffic policy is applied to an outbound interface, the system establishes the association relationships between FQs and SQs based on the queues defined in the CBQ configuration model.

  • If SQs are defined in the CBQ configuration model, the device automatically delivers a default FQ for each SQ, as shown in Figure 2.
  • If FQs are defined in the CBQ configuration model, the device automatically delivers a default SQ for all FQs, as shown in Figure 3.

In addition, the device automatically delivers the default FQ and default SQ to ensure that the packets that do not match the CBQ traffic policy can be forwarded normally.
