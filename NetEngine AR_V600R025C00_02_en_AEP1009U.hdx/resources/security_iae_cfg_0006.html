Adjusting ASE Configurations

Context

In normal cases, the ASE does not require any configuration to run. Temporary configuration is necessary only if the ASE is used in fault locating or certain test scenarios.

Procedure

  • Configure the working mode of the ASE.

    Table 1 Configuring the working mode of the ASE

    Operation

    Command

    Description

    Set the ASE threat handling action to warning.

    engine action-mode warning

    By default, the ASE threat handling action is not set to warning.

    After this command is executed, the ASE threat handling action is set to warning. That is, even if the content security service detects threats in traffic, it cannot block the threats, but can only generate related logs.

    Enable the automatic bypass function of the ASE when the CPU load is high.

    engine throttle on cpu-high

    By default, the bypass mechanism is enabled for content security services when the CPU usage is high. After this mechanism is enabled, the device processes the packets sent to the ASE based on the current CPU usage.

    • When the CPU usage is greater than 85%, the device suppresses the ratio of packets sent to the ASE.
    • When the CPU usage ranges from 75% to 85%, the device does not adjust the ratio of packets sent to the ASE.
    • When the CPU usage falls below 75%, the device increases the ratio of packets sent to the ASE.

    Manually set the ASE to bypass or stop state.

    engine { bypass | stop } [ slot slot-id cpu cpu-id ]
    Normally, if you do not need to use ASE-related service features, cancel the configurations of these features. This command is used only in specific troubleshooting scenarios. You are advised not to run this command in normal scenarios.
    • bypass: Traffic that requires content security detection is directly forwarded instead of being sent to the ASE for processing.
    • stop: All packets will not be processed by the ASE, and services carried on the ASE will become unavailable.

    Configure the action to be taken when the ASE is overloaded.

    engine overload action { block | bypass }

    This command takes effect only for content security services.

    Select a packet processing action to be taken when the ASE is overloaded based on the site requirements.

    • block: discards packets. This action applies to service scenarios with high security requirements.
    • bypass: forwards packets. This action applies to scenarios where service transmission is prioritized but security requirements are not high.

    Configure the ASE to work in enhanced detection mode.

    engine enhanced-detection

    You can enable the enhanced detection mode if the service traffic is heavy, the device's security detection capability needs to be improved, and if the detection rate can be reduced to a certain extent.

    Configure the traffic distribution mode for the content security service of the ASE.

    engine deliver mode { round-robin | source-ip-hash }

    Adjust the traffic distribution mode based on the traffic model on the live network and ASE status.

    Enable the hardware acceleration mode.

    gpm hardware-acceleration enable

    Enable the hardware acceleration mode and restart the ASE.

    NOTE:

    For the AR5700, this command is supported only on the AR5700-H series devices.

    The AR6700 series devices except the AR6700-H support this command.

  • Configure packet reassembly.

    Table 2 Configuring packet reassembly

    Operation

    Command

    Description

    Configure the maximum buffer size for a single stream during stream reassembly in scenarios where TCP out-of-order packets exist.

    stream-reassemble session-cache session-cache-value

    This command is used to configure the caching specification for a single stream during stream reassembly in scenarios where severe packet out-of-order occurs or the incoming and outgoing paths are inconsistent.

    Configure a timeout duration for TCP out-of-order packet detection.

    stream-reassemble session-timeout session-timeout

    The ASE will attempt to reassemble traffic only when the TCP out-of-order time is less than or equal to session-timeout. If the TCP out-of-order time is greater than session-timeout and the action to be taken when the ASE is overloaded is set to forward, the ASE will preferentially ensure service transmission without performing traffic detection.

    Enable the enhanced traffic reassembly mode.

    stream-reassemble enhanced-mode

    The enhanced traffic reassembly mode generally applies to the off-path deployment scenario. After this mode is enabled, sequence number reassembly is supported when TCP data packets and three-way handshake packets are out of order.

    Configure the action for cache overflow during TCP stream reassembly.

    stream-reassemble overflow-mode { forward | discard }
    When reassembling TCP packets, the ASE processes the packets that overflow the cache in either of the following ways:
    • forward
    • discard

    Configure the action for overlapping packets during TCP stream reassembly.

    stream-reassemble overlap-mode { overwrite | preserve }
    When reassembling TCP packets, the ASE processes the overlapping packets in either of the following ways:
    • overwrite: Overwrite overlapping packets.
    • preserve: Preserve overlapping packets.

  • Others

    Table 3 Others

    Operation

    Command

    Description

    Configure the resumable data transfer blocking function.

    engine breakpoint-resume-blocking protocol { all | http | ftp | smb }

    engine breakpoint-resume-blocking timeout seconds

    To perform content security detection on files, the ASE needs to obtain complete files from network traffic. The resumable data transfer mechanism may cause the ASE to fail to extract complete files for detection, resulting in missing detection.

    You can configure the resumable data transfer blocking function to block resumable data transfer for HTTP, FTP, and SMB files.

Follow-up Procedure

  • Run the display engine state command to check the ASE status.
  • Run the display debugging command to check the debugging status of each ASE service module.
