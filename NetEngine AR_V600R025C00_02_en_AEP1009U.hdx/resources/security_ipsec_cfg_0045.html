Configuring IPsec Route Injection

Prerequisites

  • IPsec route injection takes effect only for the following IPsec policies:
    • ISAKMP IPsec policies
    • Template IPsec policies
  • The device does not support IPsec route injection when an IPsec policy group is applied to a Layer 2 interface.

Context

When an enterprise headquarters and its branch establish an IPsec tunnel, a route to the branch subnet needs to be configured at the headquarters. If there are a large number of branch subnets, a lot of routes need to be configured at the headquarters. When a branch subnet changes, the route configuration needs to be manually modified at the headquarters, complicating network maintenance. After the IPsec route injection function is configured, the device injects the route to the branch subnet into the routing table based on the destination network segment in the flow information of the IPsec SA established by the local end. The next hop of the route defaults to the IP address of the local interface to which an IPsec policy is applied. The IPsec route injection function reduces the costs of configuring and maintaining routing information at the headquarters and improves configuration accuracy. This function can also be configured in branches to inject routes to the headquarters gateway.

In Figure 1, the branch establishes an IPsec tunnel with the headquarters. Hosta1 resides on the branch subnet, and Hostb1 resides on the headquarters subnet. An ACL rule is configured on the headquarters and branch to define IPsec-protected data flows from Hostb1 to Hosta1 and data flows from Hosta1 to Hostb1. Before the IPsec route injection function is enabled, a route to the branch subnet needs to be configured at the headquarters. After this function is enabled on a headquarters device, the device automatically generates a routing entry with the destination IP address on the destination network segment in the flow information of the IPsec SA established by the local end and the next hop being the IP address of the local interface to which an IPsec policy is applied.

Figure 1 Configuring IPsec route injection

IPsec route injection includes static route injection and dynamic route injection.

  • Static route injection: The automatically generated route is immediately added to the routing table of the local device, and is independent of IPsec tunnel status changes.

  • Dynamic route injection: If the IPsec tunnel is Up, the automatically generated route is immediately added to the routing table of the local device. If the IPsec tunnel is Down, the automatically generated route is immediately removed from the routing table of the local device. In dynamic route injection, the automatically generated route is associated with the IPsec tunnel status to prevent IPsec peers from sending IPsec packets over the IPsec tunnel in Down state, reducing packet loss.

In addition, the device supports the configuration of priorities for the routes injected by the IPsec route injection function to flexibly control routes. For example, if routes to the same destination are configured on the device and the same priority is specified for these routes, load balancing can be implemented among these routes. If different priorities are specified for these routes, route backup can be implemented among these routes.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the ISAKMP or template IPsec policy view.

    # Enter the ISAKMP IPsec policy view.

    ipsec policy policy-name seq-number isakmp

    # Enter the template IPsec policy view.

    ipsec policy-template template-name seq-number

  3. Configure IPsec route injection.

    route inject { static | dynamic } [ preference preference ]

    By default, IPsec route injection is not configured.

  4. Optional: Configure the next-hop address of the route to be injected by the IPsec route injection function.

    route inject nexthop { { ipv4-address | ipv6-address } | auto }

    The specified next-hop address will replace the automatically generated next-hop address.

    This command applies to the following situations:

    If the destination address of an IPsec-protected data flow is the same as the remote address of the IPsec tunnel (for example, the IPsec-protected data flow from the web system to the device), you need to run the route inject nexthop ip-address command to specify the next-hop address to the remote end. Only one next-hop address can be specified in this command. As such, if an IPsec interface has multiple next hops, you need to manually modify the configuration when the next hop changes. This method cannot well adapt to network changes. To address this, you can run the route inject nexthop auto command to configure the device to search its IP routing table for routes of packets based on packets' destination addresses and specify the next-hop address of the optimal route as the next-hop address to the remote end.

  5. Optional: Enable route injection protection.

    route inject protection enable

    By default, route injection protection is disabled.

    After IPsec route injection is enabled, the device injects the route to the branch subnet into the routing table based on the destination network segment in the flow information of the IPsec SA established by the local end. If the destination network segment is 0.0.0.0, the automatically generated route may affect other services. In this case, you are advised to enable route injection protection to prevent the device from generating a default route with 0.0.0.0 as the destination address.
