Example for Configuring Association Between LDP and Static Routes

Networking Requirements

On an MPLS network with primary and secondary LSPs established between devices using static routes, if association between LDP and static routes is not enabled, traffic is interrupted for a short period of time during traffic switchover from the primary LSP to the secondary LSP when the LDP session on the primary link fails (not because of a link fault) or during traffic switchback when the primary link recovers from a fault.

On the network shown in Figure 1, DeviceA has two static routes to DeviceD, with one passing through DeviceB and the other through DeviceC. LDP sessions are established based on the static routes. LinkA is the primary link, and LinkB is the backup link. It is required that association between LDP and static routes be configured to prevent MPLS traffic from being interrupted if the LDP session on LinkA fails or LinkA recovers from a fault.

Figure 1 Configuring association between LDP and static routes

In this example, interface1 and interface2 represent 10GE0/0/1 and 10GE0/0/2, respectively.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure static routes to other devices on each device to ensure network reachability.

  2. Enable MPLS and MPLS LDP globally and on interfaces of devices.

  3. Configure association between LDP and static routes and check configurations.

Procedure

  1. Assign an IP address to each interface.

    Configure an IP address for each interface based on Figure 1. The configuration details are not mentioned here.

  2. Configure static routes for the devices to ensure network reachability.

    # On DeviceA, configure two static routes to DeviceD with different priorities. On DeviceD, configure two static routes to DeviceA with different priorities.

    # Configure DeviceA.

    [DeviceA] ip route-static 2.2.2.2 32 10ge 0/0/1 10.1.1.2
[DeviceA] ip route-static 3.3.3.3 32 10ge 0/0/2 10.2.1.2
[DeviceA] ip route-static 10.3.1.1 30 10ge 0/0/1
[DeviceA] ip route-static 10.4.1.1 30 10ge 0/0/2
[DeviceA] ip route-static 4.4.4.4 32 10ge 0/0/1 10.1.1.2 preference 40
[DeviceA] ip route-static 4.4.4.4 32 10ge 0/0/2 10.2.1.2 preference 60

    # Configure DeviceB.

    [DeviceB] ip route-static 1.1.1.1 32 10ge 0/0/1 10.1.1.1
[DeviceB] ip route-static 4.4.4.4 32 10ge 0/0/2 10.3.1.2

    # Configure DeviceC.

    [DeviceC] ip route-static 1.1.1.1 32 10ge 0/0/1 10.2.1.1
[DeviceC] ip route-static 4.4.4.4 32 10ge 0/0/2 10.4.1.2

    # Configure DeviceD.

    [DeviceD] ip route-static 2.2.2.2 32 10ge 0/0/1 10.3.1.1
[DeviceD] ip route-static 3.3.3.3 32 10ge 0/0/2 10.4.1.1
[DeviceD] ip route-static 10.1.1.2 30 10ge 0/0/1
[DeviceD] ip route-static 10.2.1.2 30 10ge 0/0/2
[DeviceD] ip route-static 1.1.1.1 32 10ge 0/0/1 10.3.1.1 preference 40
[DeviceD] ip route-static 1.1.1.1 32 10ge 0/0/2 10.4.1.1 preference 60

    # After completing the configurations, run the display ip routing-table protocol static command on each node to check the static route configurations. DeviceA is used as an example.

  3. Enable MPLS LDP on each device to set up LDP LSPs.

    # Configure DeviceA.

    [DeviceA] mpls lsr-id 1.1.1.1
[DeviceA] mpls
[DeviceA-mpls] quit
[DeviceA] mpls ldp
[DeviceA-mpls-ldp] quit
[DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] mpls
[DeviceA-10GE0/0/1] mpls ldp
[DeviceA-10GE0/0/1] quit
[DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] mpls
[DeviceA-10GE0/0/2] mpls ldp
[DeviceA-10GE0/0/2] quit

    The configurations of DeviceB, DeviceC, and DeviceD are similar to the configuration of DeviceA. For detailed configurations, see Configuration Scripts.

    [DeviceA] display mpls ldp session

  4. Configure association between LDP and static routes on DeviceA and DeviceD.

    # Configure DeviceA.

    [DeviceA] ip route-static 4.4.4.4 32 Vlanif100 10.1.1.2 preference 40 ldp-sync
[DeviceA] interface Vlanif100
[DeviceA-10GE0/0/1] static-route timer ldp-sync hold-down 20
[DeviceA-10GE0/0/1] quit

    # Configure DeviceD.

    [DeviceD] ip route-static 1.1.1.1 32 10ge 0/0/1 10.3.1.1 preference 40 ldp-sync
[DeviceD] interface 10ge 0/0/1
[DeviceD-10GE0/0/1] static-route timer ldp-sync hold-down 20
[DeviceD-10GE0/0/1] quit

Verifying the Configuration

# Display outbound interface status of the static routes that are associated with LDP on DeviceA.

[DeviceA] display static-route ldp-sync
Total number of routes enable Ldp-Sync: 1
-----------------------------------------------------
Interface 10GE0/0/1
Enable ldp-sync static routes number: 1
Static-route ldp-sync holddown timer: 20s
Sync state: Normal
Dest = 4.4.4.4, Mask = 32, NextHop = 10.1.1.2.
-----------------------------------------------------

The command output shows that association between LDP and static routes has been configured (in Normal state).

  • When the LDP session on the primary link is interrupted, traffic is immediately switched to the backup link (LinkB) to ensure association between the static route and LDP.

  • When the primary link (LinkA) recovers from a fault, the static route with next hop 10.1.1.2 is not selected immediately. The static route with next hop 10.1.1.2 becomes active and traffic is switched to the primary link only after the hold-down timer (20s) expires and an LDP session is established on the primary link. In this manner, the static route is associated with LDP, ensuring uninterrupted MPLS traffic forwarding.

#

#

interface 10ge 0/0/1

 mpls ldp
#
interface 10ge 0/0/2
 ip address 10.2.1.1 255.255.255.252
 mpls
 mpls ldp
#
interface LoopBack0
 ip address 1.1.1.1 255.255.255.255
#
