Data Fails to Be Forwarded Along the SPT on a PIM-SM Network

Symptom

After PIM-SM is configured and an SPT is set up, user hosts cannot receive multicast data.

Possible Causes

Possible causes are as follows:

  • The downstream interfaces of multicast devices do not receive any (S, G) Join messages.
  • PIM-SM is not enabled on interfaces.
  • The RPF route to the multicast source is incorrect (for example, the unicast route has a loop).
  • Configurations are improper (for example, the configuration of the MTU, switching threshold, or multicast boundary is improper).

Procedure

  1. Run the display pim routing-table command in any view to check whether the PIM routing table contains correct (S, G) entries.

    • If the entry exists, but the flag is RPT, the multicast group is in the ASM group address range, and the upstream interface is the RPF interface toward the RP but not the SPT interface toward the multicast source, the SPT fails to be established. In this case, run the display current-configuration configuration pim command on the receiver DR to check the current configuration in the PIM view. If the command output displays spt-switch-threshold traffic-rate or spt-switch-threshold infinity, run the undo spt-switch-threshold command to delete the configuration or run the spt-switch-threshold traffic-rate command to configure a proper traffic rate.
    • If the (S, G) entry exists and the flag is SPT, run the display multicast ip fib command to check the (S, G) entry in the forwarding table and check whether the value of the Matched field increases. You need to wait several minutes after running the display multicast ip fib command as the count is updated slowly.
      • If the value of the Matched field keeps increasing, multicast data is properly forwarded from the upstream device to the current device. However, multicast data cannot be forwarded to the downstream device due to certain reasons.
      • If the value of the Matched field does not increase and the current device is not the source DR, the current device does not receive multicast data. In this case, the fault may occur on the upstream device, and you need to check whether the correct (S, G) entry exists in the PIM routing table of the upstream device.
    • If no correct (S, G) entry exists in the PIM routing table, go to Step 2.

  2. Run the display pim control-message counters interface interface-type interface-number message-type join-prune command in any view to check whether the downstream interface receives Join messages.

    If the current device is the receiver DR, skip this step.

    A downstream interface fails to receive (S, G) Join messages if a fault occurs on it or PIM-SM is not enabled.
    • If the number of Join/Prune messages received by the downstream interface does not increase, run the display pim control-message counters interface interface-type interface-number message-type join-prune command on the downstream device connected to the interface to check whether the downstream device has sent Join/Prune messages to the upstream device.
      • If the number of Join/Prune messages increases, the downstream device has sent Join/Prune messages. In this case, communication between the upstream and downstream PIM neighbors is abnormal.
      • If the number does not increase, the downstream device is not working properly. In this case, troubleshoot the downstream device.
    • If the number of Join/Prune messages received by the downstream interface increases, go to Step 3.

  3. Run the display pim interface verbose command in any view to check whether PIM-SM is enabled on the interface.

    The common cause for the fault is that PIM-SM is not enabled on the RPF interface toward the multicast source. When deploying a PIM-SM network, you are advised to enable multicast on all devices and PIM-SM on all interfaces.

    Especially check whether PIM-SM is configured on the RPF interface.
    • If the command output does not contain interface information or the PIM mode of an interface is dense, run the pim sm command on the interface. If the message "Error: Please enable multicast in the system view first." is displayed when you enable PIM-SM on an interface, run the multicast routing-enable command in the system view to enable the multicast function first. Then run the pim sm command in the interface view to enable PIM-SM.
    • If PIM-SM has been enabled on all the involved interfaces of the device, go to Step 4.

  4. Run the display multicast rpf-info source-address command in any view to check whether there is an RPF route to the multicast source.

    • If the command output does not contain an RPF route to the multicast source, check the unicast route configuration: Run the ping command on both the device and multicast source to check connectivity between them.
    • If the command output contains an RPF route to the multicast source:
      • If the RPF route is a multicast static route in the command output, run the display current-configuration command to check whether the multicast static route configuration is correct.
      • If the RPF route is a unicast route in the command output, run the display ip routing-table command to check whether the unicast route is consistent with the RPF route.
    • If the command output contains an RPF route to the multicast source and the route configuration is correct, go to Step 5.

  5. Run the display pim interface interface-type interface-number command in any view to check whether the interface forwarding multicast data is the receiver DR.

    • If the command output does not contain the local flag, the interface is not the receiver DR. In this case, perform Step 6 on the DR according to the DR address in the command output.
    • If the command output contains the local flag, the interface is the receiver DR. In this case, go to Step 6.

  6. Run the display current-configuration interface interface-type interface-number command in the user view to check whether the multicast boundary is configured on the interface.

    • If multicast boundary is displayed in the configuration of the interface, multicast boundary is configured on the interface. In this case, you are advised to run the undo multicast boundary { group-address { mask | mask-length } | all } command to delete the configuration or replan the network to ensure that no multicast boundary is configured on the RPF interface or the RPF neighbor interface.
    • If multicast boundary is not configured on the interface, go to Step 7.

  7. Run the display current-configuration configuration pim command in the PIM view to check whether the source-policy is configured.

    If the command output contains source-policy acl-number or source-policy acl-name, a source-based filtering policy is configured. Any multicast data that is not permitted by the ACL is then discarded. In this case, run the undo source-policy command to delete the configuration or reconfigure ACL rules to ensure that the multicast data required by users can be forwarded normally.
