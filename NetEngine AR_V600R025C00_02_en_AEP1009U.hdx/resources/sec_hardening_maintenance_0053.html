RADIUS User Management

Overview

RADIUS is the most commonly used protocol for implementing AAA on remote dial-up users. RADIUS runs atop UDP, and its authentication and accounting port numbers are 1812 and 1813, respectively. RADIUS uses the client/server model for communication between the RADIUS client and server to provide AAA functions.

RADIUS supports the following security hardening modes:
  • Performs authentication using a shared key. This mode is recommended in scenarios that require a high user access rate.

    RADIUS uses UDP as a transport protocol. The RADIUS server and client authenticate each other using a shared key, which is not transmitted over the network. In addition, to prevent user passwords from being disclosed on an insecure network, the passwords transmitted between the RADIUS server and client are encrypted using the shared key. The device allows you to configure a shared key for packet encryption to improve transmission security. For security purposes, it is recommended that the shared key contain at least 16 characters and at least two types of the following characters: uppercase letters, lowercase letters, digits, and special characters. You are advised to periodically change the shared key.

  • Supports the DTLS service. This method is recommended in scenarios that have high security requirements.

    RADIUS over DTLS supports DTLS certificate authentication.

Impact on the System

None

Procedure

  • Configure a shared key for the RADIUS server.
    1. Enter the system view.

      system-view

    2. Create a RADIUS server template and enter its view.

      radius-server template template-name

    3. Configure the RADIUS server and its shared key.

      radius-server authentication ip-address port shared-key cipher share-key

  • Configure RADIUS over DTLS.
    1. Enter the system view.

      system-view

    2. Configure a DTLS policy.

      Ensure that the PKI realm realm-name bound to the DTLS policy has a certificate loaded. The certificate can be an initial device certificate or a digital certificate applied by a user. For details about how to load a certificate using PKI, see PKI Configuration under CLI Configuration Guide > Security Configuration.

      pki realm realm-name 
quit 
pki import-certificate ca realm realm-name pem filename file-name 
dtls policy policy-name
pki-domain realm-name 
quit

    3. Create a RADIUS server template and enter its view.

      radius-server template template-name

    4. Configure the RADIUS server and the DTLS policy to be used by the RADIUS server.

      radius-server authentication ip-address port dtls-policy dtlspolicyname

Checking the Security Hardening Result

Run the display radius-server configuration command to check the RADIUS server configuration.
