Applying Queue Scheduling HQoS to an Outbound Interface

Context

  • A parent traffic policy in the parent and child traffic policy mode or a traffic policy in CBQ mode can be applied to an interface.
  • Queue scheduling HQoS must be applied to the outbound direction of an interface. Currently, queue scheduling HQoS can be configured only on Layer 3 Ethernet interfaces and their sub-interfaces, Eth-Trunk interfaces and their sub-interfaces, tunnel interfaces, and cellular channel interfaces.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the interface view.

    interface { interface-type interface-number | interface-name }

  3. Enable the queue capability of the interface.

    qos queue-scheduling enable

    By default, the queue capability is disabled on physical and logical interfaces for the AR5700 series, AR6710-L14T2X4, AR6710-L8T3TS1X2, and AR6710-L8T3TS1X2-T. Therefore, this step needs to be performed on all interfaces.

    For all other devices, the queue capability is enabled on physical interfaces but is disabled on logical interfaces by default. Therefore, this step needs to be performed on logical interfaces.

  4. Apply a parent traffic policy or CBQ traffic policy in the outbound direction of the interface.

    traffic-policy policy-name outbound

  5. (Optional) Configure interface-based traffic shaping to implement interface-based rate limiting.

    qos lr cir cir-value [ kbps | mbps | gbps ] [ cbs cbs-value [ bytes | kbytes | mbytes ] ] outbound

    By default, the traffic shaping rate of an interface is the maximum bandwidth of the interface. Determine whether to perform this step based on actual network traffic.
