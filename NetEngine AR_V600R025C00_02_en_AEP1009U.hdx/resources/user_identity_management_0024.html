Understanding TSM SSO

TSM SSO is an authentication mode in which a device interworks with a TSM SSO-capable server to obtain user login information. The enterprise has deployed the TSM identity authentication mechanism and enabled TSM SSO. In this case, the device obtains the mappings among users, security groups, and IP addresses so that the administrator can configure policies on the device to control network access behaviors of different users or security groups.

iMaster NCE-Campus running V300R022C10 or later versions can function as the TSM SSO server.

Application scenario of TSM SSO

As shown in Figure 1, access devices such as access switches and APs are usually used as authentication points on a campus network. The authentication points work with the controller to perform 802.1X authentication, MAC address authentication, and Portal authentication on users. After a user is authenticated, the user goes online on the controller.

Figure 1 Diagram of campus network

The gateway at the network egress is not an authentication point and also requires user-based permission control. In this case, TSM SSO is required. The controller sends user login messages to the device, and the user-based permission control can be implemented without secondary authentication on the user gateway.

Fundamentals of TSM SSO

As shown in Figure 2, the TSM SSO server authenticates users. The administrator needs to set communication parameters on the TSM SSO server and the device. Thereafter, the TSM SSO server sends user login and logout messages to the device through the UDP channel, allowing the device to obtain the mappings between users, security groups, and IP addresses. After being authenticated by the TSM SSO server, users can directly access network resources without being authenticated by the device.

Figure 2 TSM SSO

After authenticating a user, the TSM SSO server obtains the user's IP address and sends the IP address to the device so that the user can go online on the device. After a user is authenticated, they can go online using a maximum of 11 IP addresses (one IPv4 address and a maximum of 10 IPv6 addresses).

TSM Online User Synchronization

In TSM SSO, online users on the device are synchronized with those on the TSM SSO server, which is a key factor for normal user permission control. However, in actual applications, online users on both ends are not synchronized in the following situations:

  • Problem 1: After a user passes the authentication on the TSM SSO server, the user login message sent by the TSM SSO server to the device is lost. As a result, the user cannot go online on the device, and therefore cannot access the network.
  • Problem 2: In some networking scenarios, the TSM SSO server does not proactively send user login messages to the device. Service traffic needs to be used to trigger the device to proactively bring users online.
  • Problem 3: The device has an online user aging mechanism. That is, if no traffic from an online user passes through the device within a specified period, the user goes offline. In this case, the user may not go offline from the TSM SSO server, but from the device in advance. As a result, the user cannot access the network.
  • Problem 4: A user goes offline from the TSM SSO server. The user logout message sent from the TSM SSO server to the device is lost, but the device still retains the user. The user may be spoofed.

To solve these problems, the device provides the online user aging mechanism and TSM online user synchronization function to ensure synchronization between the device and TSM SSO server.

  • For the preceding problems: When the traffic passing through the device does not have the corresponding online user entry, the device proactively queries the TSM SSO server for the online user corresponding to the source IP address. If an online user corresponding to the IP address exists on the TSM SSO server, the TSM SSO server returns the user login information to the device.

    To prevent traffic that does not require TSM SSO from being queried on the TSM SSO server, you can specify the range of the traffic to be queried. Only the traffic in that range triggers the device to initiate a query to the TSM SSO server.

  • For problem 4: The online user aging mechanism of the device can solve this problem. If an online user has no traffic for a certain period of time, the device disconnects the user.
