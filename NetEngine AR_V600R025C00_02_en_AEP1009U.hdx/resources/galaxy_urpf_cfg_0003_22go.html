Understanding URPF

Working Mode

On a complex network, the routing paths recorded on a remote device may be different from those recorded on the local device. A URPF-enabled device on such a network may discard packets received from valid paths. To solve this problem, the device provides two URPF modes:

  • Strict mode

    In strict mode, the device allows a packet to pass through only when there is a route to the source IP address of the packet in its FIB table and the inbound interface of the packet is the same as the outbound interface of the route.

    You are advised to use the strict mode when you are sure that the routing paths recorded on the local and remote devices are the same. For example, if there is only one path between two network edge devices, strict mode can be used to ensure network security.

  • Loose mode

    In loose mode, the device allows a packet to pass through as long as there is a route to the source IP address of the packet in its FIB table. In contrast to strict mode, the inbound interface of the packet does not need to be the same as the outbound interface of the route.

    You are advised to use the loose mode when the routing paths recorded on the local and remote devices may be different. For example, if there are multiple paths between two network edge devices, the loose mode can be used to effectively protect the device against network attacks while preventing valid packets from being discarded.

Implementation

URPF obtains the source address and inbound interface of a packet, retrieves the interface corresponding to the source address in the FIB table, and checks whether the retrieved interface is the same as the obtained inbound interface. If they are different, the device considers the source address to be spoofed and discards the packet. In this manner, URPF can effectively protect the device against malicious attacks that modify source addresses of packets.

Figure 1 URPF implementation

As shown in Figure 1, RouterA forges request packets with the source address 20.10.10.10 and sends the packets to RouterB. After receiving the packets, RouterB sends response packets to RouterC with the IP address 20.10.10.10. As a result, both RouterB and RouterC are attacked by such packets.

To prevent such attacks, we can enable URPF strict check on RouterB. In this way, once RouterB receives packets with the source address 20.10.10.10, it discards the packets because the interface corresponding to the source address does not match the interface that receives the packets.

Application Scenario

  • URPF strict check

    In Figure 2, there is one link between AS1 and AS3 and another link between AS2 and AS3. URPF is enabled on Interface1 and Interface2 of RouterC to protect AS3 from source address spoofing attacks from AS1 and AS2.

    In this example, PC A in AS1 forges a packet with the source address 20.20.20.20 and sends the packet to Server in AS3. After receiving the packet, RouterC checks the inbound interface of the packet and finds that packets with the source address 20.20.20.20 must reach RouterC through Interface2. RouterC considers the packet to be a spoofed one and discards it.

    Packets from AS2 to Server, in contrast, are allowed to pass through after passing URPF check.

    Figure 2 URPF strict check application
  • URPF loose check

    URPF is often used when multiples connections are set up between two network edge devices.

    • Single-homed client connected to one ISP

      Figure 3 URPF enabled on a single-homed client connected to one ISP

      As shown in Figure 3, two connections are set up between an enterprise network and an ISP network to ensure high reliability. In this case, the symmetry of routes between the two networks cannot be ensured, and loose URPF must be used.

    • Multi-homed client connected to several ISPs

      Figure 4 URPF enabled on a multi-homed client connected to several ISPs

      In Figure 4, the enterprise network is connected to two ISP networks. It is difficult to ensure the symmetry of routes between the enterprise network and two ISP networks. As such, loose URPF must be used.

      URPF applications in the scenario where a client is connected to multiple ISPs:

      To allow special packets to pass URPF check in any situation, you can specify the source addresses of these packets in an ACL.

      In some cases, the devices connected to users only have one default route to the ISP. Therefore, matching the default routing entry needs to be supported.
