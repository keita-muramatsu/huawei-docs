Enabling the Route Prefix Conflict Check

Context

When a static or direct route is added and its prefix is the same as that of another route that belongs to a different routing protocol in the routing table, only one of the routes (the one with the highest priority) takes effect. This may affect existing configurations. To prevent this problem, the system performs the prefix conflict check by default. This can identify risks.

Procedure

  1. Enter the system view.

    system-view

  2. Enable the prefix conflict check for static and direct routes.

    undo route duplicate check disable

    By default, the device performs the prefix conflict check for static and direct routes.

    To disable this function, run the route duplicate check disable command. Disabling this function may affect existing configurations. Therefore, exercise caution when performing this operation.

Verifying the Configuration

Run the display current-configuration command to check the configuration.
