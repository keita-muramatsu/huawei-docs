Extranet Hosts Fail to Access an Intranet Server (NAT Server Fault)

Fault Symptom

When the NAT Server function is configured on the device, extranet hosts cannot access an intranet server.

Possible Causes

  • The NAT function is not enabled on the inbound interface through which extranet hosts access the intranet.
  • The NAT Server configuration is incorrect.
  • A security policy is configured on the device to control packets.

Procedure

  1. Check whether services on the intranet server are running properly.

    You can use an intranet host to access the intranet server. If the access succeeds, services are running properly on the intranet server. If services are not enabled on the intranet server, enable the services.

  2. Check whether the NAT function is enabled on the inbound interface through which extranet hosts access the intranet.

    Run the display this command on the inbound interface through which extranet hosts access the intranet to check whether the NAT function is enabled. If not, run the nat enable command to enable NAT on the inbound interface.

  3. Check whether NAT Server is correctly configured.

    Run the display nat server command on the device to check whether the NAT Server configuration (such as the protocol, port, and address) is correct.

    Ensure that the private IP address and port number configured in NAT Server are correct. When data packets of some services such as FTP and TFTP are transmitted, several interfaces may be used. Therefore, when configuring NAT Server for providing such services, cancel the limitation on interfaces so that the intranet server can provide services normally. If the NAT Server configuration is incorrect, modify it.

  4. Check whether the security policy is correctly configured.

    Run the display security-policy rule all command on the device to check the security policy configuration. If the configuration is incorrect, modify it.

  5. Check the connectivity between the extranet hosts and the device's WAN interface, as well as the configuration of this interface.

    Check whether the IP address of the device's WAN interface and the public IP address configured in NAT Server are correct. For example, check whether an IP address conflict exists. Ping the device's WAN interface from an extranet host. If the ping fails, resolve the connectivity problem.

  6. Check the route and gateway configurations of the intranet server.

    Check whether the intranet server is configured with the correct route and gateway address so that packets destined for extranet hosts can be sent to the device. If the gateway address or route on the intranet server is incorrectly configured, modify it.
