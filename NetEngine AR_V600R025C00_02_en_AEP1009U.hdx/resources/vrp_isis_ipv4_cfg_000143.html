Disabling IS-IS Memory Overload Control

IS-IS memory overload control is enabled by default and can be disabled.

Context

If the system memory is overloaded, each module needs to take necessary measures to control the memory usage increase or even reduce the memory usage. In this case, the IS-IS module takes the following measures to improve IS-IS resilience: restrict the establishment of new neighbor relationships, enter the Overload state and reject new LSPs, restrict the installation of newly imported routes, or delete imported routes.

Procedure

  1. Enter the system view.

    system-view

  2. (Optional) Enable IS-IS to enter the Overload state and discard new LSPs if the system memory is overloaded and the memory usage of the IS-IS LSDB component is not among the top 3.

    isis memory-overload exception-threshold discard new-lsp

    If the system memory is overloaded and the memory usage of the IS-IS LSDB component is among the top 3, IS-IS enters the Overload state and discards new LSPs by default to improve IS-IS resilience. However, if the memory usage of the IS-IS LSDB component is not among the top 3 and new IS-IS services are added, the IS-IS LSDB component will consume more memory resources, aggravating the system memory overload issue. To prevent this issue, enable IS-IS to enter the Overload state and discard new LSPs in this case. Of course, you can disable this function as required.

    IS-IS memory overload control is enabled by default. If you disable this function by performing the next step, the configuration in this step will become invalid.

  3. Disable IS-IS memory overload control.

    isis memory-overload control disable

    To minimize the impact of memory overload on services, you are advised to keep IS-IS memory overload control enabled.
