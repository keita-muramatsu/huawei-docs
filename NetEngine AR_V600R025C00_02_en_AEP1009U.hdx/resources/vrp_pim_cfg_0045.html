Understanding BFD for IPv4 PIM

To minimize the impact of device faults on services and improve network reliability, a network device needs to quickly detect faults when communicating with adjacent devices. Measures can then be promptly taken to ensure service continuity.

Bidirectional Forwarding Detection (BFD) provides unified detection for all media and protocol layers on the entire network within milliseconds. Two systems set up a BFD session and periodically send BFD control packets along the path between them. If one system does not receive BFD control packets within a detection period, the system considers that a fault has occurred on the path.

If the current DR or assert winner on a shared network segment is faulty in a multicast scenario, other PIM neighbors start a new DR election or assert election after the neighbor relationship or assert timer expires. Multicast data transmission is interrupted for no less than the neighbor relationship or assert timer timeout period (usually several seconds).

BFD can detect changes in the status of a link on a shared network segment within milliseconds, enabling a device to rapidly respond to PIM neighbor faults. If an interface enabled with BFD does not receive BFD control packets from the DR or assert winner within a detection period, it considers the DR or assert winner faulty. The BFD module quickly notifies the RM of the session status, and the RM notifies the PIM module. Then, the PIM module triggers a new DR election or assert election without waiting for the neighbor relationship or assert timer to expire. This shortens the interruption time of multicast data transmission and improves the reliability of multicast data transmission.

Figure 1 Networking diagram of BFD for IPv4 PIM

In Figure 1, on the shared network segment connected to user hosts, the downstream interface Interface1 on DeviceB and downstream interface Interface2 on DeviceC establish a BFD session and send BFD control packets to monitor the link status.

DeviceB functions as the DR and its downstream interface Interface1 is responsible for forwarding multicast data. If Interface1 fails, BFD rapidly notifies the RM of the session status, and the RM then notifies PIM of the session status. The PIM module triggers a new DR election. DeviceC functions as the new DR and its downstream interface Interface2 forwards multicast data to the Receiver in a short period of time. This shortens the interruption time of multicast data transmission.
