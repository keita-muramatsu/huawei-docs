Developing Data Subscription on the Collector (Python)

After receiving a data packet sent from the device, the collector removes the protocol header and then parses the content layer.

  • For UDP-based transport, the UDP packet header and message header need to be removed. For gRPC-based transport, the protocol layer is removed automatically by the open-source gRPC framework developed by Google.
  • The content layer consists of two sublayers: The telemetry layer describes the sampling interval and sampling path, and the service data layer contains the actual sampled data. Regardless of whether UDP or gRPC is used, the content layer is identical after the protocol layer is removed.

The open-source gRPC framework developed by Google uses the client/server model.

  • When a static subscription is configured, the device acts as a gRPC client and pushes data to the collector. In this case, secondary development is required to configure the collector as a gRPC server.
  • When a dynamic subscription is configured, the collector operates as a gRPC client and establishes a connection with the device, which acts as the gRPC server. The device then samples and pushes data to the collector.

The gRPC server can remove the protocol layer, so you only need to focus on content layer parsing.
