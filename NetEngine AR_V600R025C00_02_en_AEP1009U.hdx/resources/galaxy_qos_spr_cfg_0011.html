Configuring a Policy and Binding It to a Service Profile

Context

Service traffic identified using SPR must be associated with a policy. To do this, you need to create a policy profile and bind it to the corresponding service profile. The device matches service traffic based on the bound service profile and implements intelligent traffic steering for different service traffic based on the parameters set in the policy profile.

A policy can be bound to multiple services, and a service can match multiple policies.

  • If a policy is bound to multiple services and a service matches one or more rules in the policy, the service matches the policy.
  • If a service is bound to and matches multiple policies, only the policy with the highest priority takes effect.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the SPR configuration view.

    smart-policy-route

  3. Create a policy profile, and enter the policy profile view.

    spr-policy node node-index

  4. Configure the policy priority.

    priority priority-value

    By default, the priority of a policy is the same as the node index of the policy. A policy with a higher priority takes effect preferentially.

  5. Bind the policy profile to a service profile.

    binding service-map name

    A service profile can be bound to multiple policies, but only the policy with the highest priority takes effect.

  6. (Optional) Enable the switchback function.

    switch-back enable

    By default, the switchback function is enabled.

  7. (Optional) Configure the time range in which the policy takes effect.

    time-range name

    By default, no time range is specified for an SPR policy, indicating that the SPR policy takes effect immediately.

  8. (Optional) Configure the action to be taken on packets when no link meets the conditions in the policy.

    default-action { discard | forward }

    By default, service packets are forwarded through the link with the optimal CMI among all links in the current policy.
