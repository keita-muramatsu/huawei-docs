Example for Establishing a GRE over IPsec Tunnel Using an IPsec Profile

Networking Requirements

As shown in Figure 1, Network A and Network B are connected through DeviceA and DeviceB. Users on Network A need to securely access resources on Network B through a GRE tunnel. GRE cannot authenticate or encrypt packets. Therefore, IPsec needs to be configured to protect traffic from Network A to Network B.

The networking requirements are as follows:

  • Network A is in the network segment 10.1.1.0/24 and connects to DeviceA through interface 2.

  • Network B is in the network segment 10.1.2.0/24 and connects to DeviceB through interface 2.

  • DeviceA and DeviceB have reachable routes to each other.

Figure 1 GRE over IPsec networking

In this example, interface 1 and interface 2 represent 10GE 0/0/1 and 10GE 0/0/2, respectively.

Configuration Roadmap

This example uses default security algorithms of IPsec.

For security purposes, you are advised not to use the weak security algorithm or weak security protocol of this feature. If you must use such a weak security algorithm or protocol, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA.

The roadmap for configuring DeviceA is the same as that for configuring DeviceB.
  1. Perform basic interface configurations.
  2. Configure static routes to ensure that there are reachable routes between both ends.
  3. Configure a GRE tunnel interface and a forwarding route for the tunnel interface to direct the data flows to be protected by IPsec to the interface.
  4. Configure an IPsec profile.

Procedure

  1. Perform basic interface configurations on DeviceA.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] ip address 10.1.1.1 24
[DeviceA-10GE0/0/2] quit
[DeviceA] interface 10ge 0/0/1 
[DeviceA-10GE0/0/1] ip address 1.1.3.1 24 
[DeviceA-10GE0/0/1] quit

  2. Configure a GRE tunnel interface on DeviceA.

    [DeviceA] interface tunnel 1
[DeviceA-Tunnel1] tunnel-protocol gre
[DeviceA-Tunnel1] ip address 2.1.1.1 24
[DeviceA-Tunnel1] source 1.1.3.1
[DeviceA-Tunnel1] destination 1.1.5.1
[DeviceA-Tunnel1] quit

    The IP address of the tunnel interface can be any idle IP address. When routes with the tunnel interface as the next hop need to be generated through dynamic routing protocols, the IP addresses of the interfaces at both ends of the GRE tunnel must belong to the same network segment.

  3. Configure a static route from DeviceA to Network B. The following assumes that the next hop of the route with the outbound interface 10GE 0/0/1 is 1.1.3.2. Configure a forwarding route for the tunnel interface to direct the data flows to be protected by IPsec to the interface.

    [DeviceA] ip route-static 1.1.5.0 255.255.255.0 10ge 0/0/1 1.1.3.2
[DeviceA] ip route-static 10.1.2.0 255.255.255.0 tunnel 1

  4. Configure an IPsec profile and apply it to the tunnel interface.
    1. Configure an IPsec proposal. You do not need to set default parameters.

      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] quit

    2. Configure an IKE proposal. You do not need to set default parameters.

      [DeviceA] ike proposal 10
[DeviceA-ike-proposal-10] authentication-method pre-share 
[DeviceA-ike-proposal-10] quit

    3. Configure an IKE peer.

      [DeviceA] ike peer b
[DeviceA-ike-peer-b] ike-proposal 10
[DeviceA-ike-peer-b] pre-shared-key YsHsjx_202206
[DeviceA-ike-peer-b] quit

    4. Configure an IPsec profile.

      [DeviceA] ipsec profile pro1
[DeviceA-ipsec-profile-pro1] proposal tran1
[DeviceA-ipsec-profile-pro1] ike-peer b
[DeviceA-ipsec-profile-pro1] quit

    5. Apply the IPsec profile pro1 to the tunnel interface.

      [DeviceA] interface tunnel 1
[DeviceA-Tunnel1] ipsec profile pro1
[DeviceA-Tunnel1] quit
[DeviceA] quit

  5. Perform basic interface configurations on DeviceB.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] ip address 10.1.2.1 24
[DeviceB-10GE0/0/2] quit
[DeviceB] interface 10ge 0/0/1 
[DeviceB-10GE0/0/1] ip address 1.1.5.1 24 
[DeviceB-10GE0/0/1] quit

  6. Configure a GRE tunnel interface on DeviceB.

    [DeviceB] interface tunnel 1
[DeviceB-Tunnel1] tunnel-protocol gre
[DeviceB-Tunnel1] ip address 2.1.1.2 24
[DeviceB-Tunnel1] source 1.1.5.1
[DeviceB-Tunnel1] destination 1.1.3.1
[DeviceB-Tunnel1] quit

    The IP address of the tunnel interface can be any idle IP address. When routes with the tunnel interface as the next hop need to be generated through dynamic routing protocols, the IP addresses of the interfaces at both ends of the GRE tunnel must belong to the same network segment.

  7. Configure a static route from DeviceB to Network A. The following assumes that the next hop of the route with the outbound interface 10GE 0/0/1 is 1.1.5.2. Configure a forwarding route for the tunnel interface to direct the data flows to be protected by IPsec to the interface.

    [DeviceB] ip route-static 1.1.3.0 255.255.255.0 10ge 0/0/1 1.1.5.2
[DeviceB] ip route-static 10.1.1.0 255.255.255.0 Tunnel1

  8. Configure an IPsec profile and apply it to the tunnel interface.
    1. Configure an IPsec proposal. You do not need to set default parameters.

      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] quit

    2. Configure an IKE proposal. You do not need to set default parameters.

      [DeviceB] ike proposal 10
[DeviceB-ike-proposal-10] authentication-method pre-share
[DeviceB-ike-proposal-10] quit

    3. Configure an IKE peer.

      [DeviceB] ike peer a
[DeviceB-ike-peer-b] ike-proposal 10
[DeviceB-ike-peer-b] pre-shared-key YsHsjx_202206
[DeviceB-ike-peer-b] quit

    4. Configure an IPsec profile.

      [DeviceB] ipsec profile pro1
[DeviceB-ipsec-profile-pro1] proposal tran1
[DeviceB-ipsec-profile-pro1] ike-peer a
[DeviceB-ipsec-profile-pro1] quit

    5. Apply the IPsec profile pro1 to the tunnel interface.

      [DeviceB] interface tunnel 1
[DeviceB-Tunnel1] ipsec profile pro1
[DeviceB-Tunnel1] quit
[DeviceB] quit
