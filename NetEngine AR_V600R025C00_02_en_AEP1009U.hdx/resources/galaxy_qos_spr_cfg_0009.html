Configuring an SPR Service Profile

Prerequisites

  • ACLs have been configured (if packets need to be matched based on ACLs).

  • When application identification needs to be used to match service traffic:
    • The application identification function has been enabled for traffic entering an interface.
    • The latest service awareness (SA) signature database has been loaded (if applications need to be matched).
    • An application group has been configured (if traffic needs to be matched by application group).

Context

To use SPR to intelligently steer traffic of services matching an ACL, application, or application group, you must create a service profile and bind the ACL, application, or application group to the service profile.

Procedure

  1. Enter the system view.

    system-view

  2. Enable the SPR function and enter the SPR configuration view.

    smart-policy-route

  3. Create a service profile and enter the service profile view.

    service-map name

  4. Bind services to the SPR service profile based on your site requirements.

    Table 1 Binding services to a service profile

    Operation

    Command

    Description

    Bind an ACL to the service profile.

    match acl { acl-number | acl-name }

    match ipv6 acl { acl-number | acl-name }

    By default, no service is bound to a service profile.

    One or more rules can be bound based on service requirements.

    A service matches a service profile if it matches one or more rules specified in the profile. If a packet does not match any rule, the routing table is queried to forward the packet according to its destination IP addresses.

    NOTE:

    A service profile differentiates service flows by matching them against ACL rules. The ACL number is in the range from 2000 to 3999.

    • 2000 to 2999: basic ACLs

    • 3000 to 3999: advanced ACLs

    • If an ACL rule defines permit, the device selects routes for the packets matching the ACL rule according to link quality.

    • If an ACL rule defines deny, the device searches the routing table for a route based on the destination address of the packets matching the ACL rule.

    Bind an application to the service profile.

    match application application-name

    Bind an application group to the service profile.

    match application-group application-group-name

    Bind an ACL and application to the service profile.

    match acl { acl-number | acl-name } application application-name

    match ipv6 acl { acl-number | acl-name } application application-name

    Bind an ACL and application group to the service profile.

    match acl { acl-number | acl-name } application-group application-group-name

    match ipv6 acl { acl-number | acl-name } application-group application-group-name
