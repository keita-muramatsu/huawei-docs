Feature Requirements

NAT Server

If the IP address of an interface on the device is configured as the public IP address in NAT Server, you cannot use this interface address to manage or ping the device. To resolve this problem, enable port translation and specify a protocol and port number when you configure NAT Server.

NAT Server

When configuring NAT Server in the scenario where an intranet server uses multiple public IP addresses to provide services to external network users, you must specify the no-reverse parameter if links to these public IP addresses belong to the same security zone. This prevents proactive access from the intranet server to external networks.

NAT Server

Ensure that a public IP address is not used by both a NAT address pool and NAT Server. If this situation cannot be avoided, configure both a public IP address and port number in NAT Server and exclude the port number from the NAT address pool. Otherwise, server mapping entries or session entries may conflict, causing address translation failures.

NAT Server

The public IP address configured in NAT Server must not be excluded from the address pool. Otherwise, proxy ARP cannot be performed, affecting the use of NAT Server.

Source NAT

NAT session entries are not updated in the following scenarios:

1. The configuration or route information on an interface is changed, but the outbound interface remains unchanged.

2. The NAT address pool is changed. For example, an address segment is dynamically added, an excluded IP address is dynamically deleted, or an excluded port is dynamically added or deleted.

3. A 5-tuple or No-PAT NAT address pool is changed. For example, an address segment is dynamically deleted, or an excluded IP address is dynamically added.

Source NAT

NAT processing only for IPv4 packets

Source NAT

IP addresses in an address pool can overlap with the public IP addresses configured in NAT Server or interface IP addresses. However, when configuring NAT No-PAT or 3-tuple NAT that can generate dynamic server mapping entries, ensure that interface IP addresses on the device are not included in the NAT address pool. Otherwise, access to the device will be affected because the device preferentially matches the received packets against server mapping entries.

Source NAT

For SCTP packets, only IP address translation can be performed.

Source NAT

In hot standby scenarios, ensure that NAT address pools do not include IP addresses of interfaces on the active and standby devices. If an interface IP address is included in a NAT address pool, both the active and standby devices respond to the ARP request for this IP address sent from the upstream device, causing an ARP conflict.

Source NAT

In a non-mirroring hot standby scenario, do not configure Easy IP NAT that uses the public IP address of an outbound interface as the post-NAT address. Otherwise, if an active/standby switchover is performed, traffic from the Internet to the intranet cannot be switched to the new active device, causing service interruption. This is because the MAC address corresponding to the public IP address learned by the upstream device is the MAC address of the original active device.

Source NAT

The device cannot perform NAPT on GRE and AH packets. The reason is as follows: When receiving a GRE or AH packet, the device sets the protocol port number in the packet to 0 based on the NAPT configuration. However, the return packet received by the device has no port information. As a result, the forward and return packets have different port information, affecting service traffic forwarding.

Source NAT

A NAT conflict will occur if source NAT is configured on the outbound interface together with MQC-based redirection to a NAT-enabled interface. To prevent conflicts, you are advised to configure redirection on a LAN-side inbound interface.

Source NAT

When using both a VPN and NAT, specify proper matching conditions in a NAT policy to prevent NAT translation from being performed on data flows that are to be encapsulated in the VPN.

Source NAT

In hot standby scenarios, ensure that the source or destination IP addresses configured in a NAT policy do not include the IP addresses of heartbeat interfaces. Otherwise, NAT will be performed on heartbeat packets, causing an exception of heartbeat link communication.

Source NAT

The device does not support NAT for GRE inner packets. When NAT is enabled for GRE on the device, do not enable the keepalive function of the GRE tunnel. Otherwise, the tunnel status is abnormal.

Source NAT

In an Easy IP scenario, you are advised to use a loopback interface as the source interface for host protocol services (such as NQA).

When Easy IP is configured, the post-NAT port number or ICMP ID of the traffic destined for other devices may conflict with the port number or ICMP ID of a service on the local device. As a result, traffic of this service cannot be forwarded. In this case, you are advised to configure the local service address to match the NAT policy so that NAT is also performed for this service.

Source NAT

For NAPT address pools (excluding port pre-allocation and CAR-NAT), public IP address assignment is performed based on the hash calculation results of intranet users' IP addresses. Each intranet user is assigned a unique public IP address. If there are a small number of private source IP addresses on the live network, some public IP addresses may not be used.

Source NAT

After server mapping entries are generated for an address pool, they will be immediately aged out if subsequent packets match these entries but the address pool ID is not the original one. As such, when replacing public IP addresses for the original service or changing the NAT type for the original address pool, you are advised to create a new address pool.

Source NAT

NAPT allows for port multiplexing. When different intranet users access different destination servers, the users may be assigned the same public IP address and port number. However, when multiple intranet users access a special server (the server provides multiple public IP addresses for load balancing) and are assigned the same public IP address and port number, the user packets may be discarded due to conflict detection inside the server.
