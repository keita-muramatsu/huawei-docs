Configuration Precautions for IPS

Licensing Requirements

The update service of the IPS signature database is controlled by the IPS license control item. If the license control items are not activated, the device does not support the preset signature database, and cannot manually load or update the signature database. In this case, only the IPS function based on user-defined signatures is available. After the license control items are activated, you can load and update the signature database. After the license control items expire, the signature database cannot be manually loaded or upgraded. The intrusion prevention function is available, but the signature database may not be up-to-date, and the intrusion detection and defense capabilities are limited.

For SMB, the device can detect only SMB1 and SMB2 files, but cannot detect files of SMB3 or later. For NFS and SMB, if the client and server use some new technologies, the device cannot completely restore files. In this case, the device cannot detect the NFS and SMB files. Such situations include, but are not limited to, the following:

- A file is transmitted through multiple sessions (multi-channel transmission).

- File fragments are transmitted out of order.

- During file transmission, the Windows system uses file caching. As a result, files may not be completely transmitted.

- The resumable transfer function is enabled for SMB.

When the intrusion prevention function is deployed on the security device between two routers that use BFD to detect each other, BFD flapping occurs if occasional congestion occurs on the network. You are advised to set the BFD detection interval to a larger value (greater than 100 ms) on the routers to prevent BFD flapping caused by occasional network congestion.

On a network where the forward and return paths of packets are different, the device cannot receive all packets of a data flow. Therefore, the device may fail to detect network intrusions.

The IPS correlation detection function delivers a dynamic blacklist. You need to run the firewall blacklist enable command to enable the blacklist function so that the dynamic blacklist entries can take effect and the device can block attack flows based on the blacklist.

If a signature has been removed from the latest IPS signature database after an update, all configurations related to this signature become invalid.

When the device uses the intrusion prevention function to perform content security detection on traffic, the device performance will be affected. Therefore, you need to configure this function as required.

To prevent log storms, the content security detection engine merges IPS threat logs by default. Information such as the source port number in the merged logs may be 0.

In the resumable transmission scenario, the IPS function blocks the threat file that is transmitted for the first time. If the threat file is transferred multiple times, the resumable transfer blocking function blocks the file. For details about the restrictions on the resumable transfer blocking function, see Configuration Precautions for ASE in the product documentation.

IPS supports only domain names that comply with RFC 1035 standards. For domain names that do not comply with RFC 1035 standards, the IPS effect cannot be guaranteed. The domain name requirements specified in RFC standards include but are not limited to the following:

- According to section 2.3.4 in RFC 1035, the length of a domain name must be less than or equal to 255 bytes, and that of a single label must be less than or equal to 63 bytes.

- According to section 2.3.1 in RFC 1035, a domain name can contain uppercase letters, lowercase letters, digits (0–9), periods (.), and hyphens (-); other characters are invalid.

Multicast and broadcast traffic is not sent to the ASE. Therefore, IPS is not performed on the traffic.

ASE processes only TCP/UDP traffic. Therefore, traffic of non-TCP/UDP protocols such as ICMP cannot be detected.
