Feature Requirements

USB-based deployment

When using a USB flash drive for deployment, ensure that the read and write protection functions of the USB flash drive are disabled.

USB-based deployment

If the source file is compressed, the HMAC value in the index file is the HMAC value calculated for the source file.

USB-based deployment

1. To ensure data security, it is recommended that the device administrator use a keystroke encrypted or fingerprint encrypted USB flash drive and keep the USB flash drive with the deployment configuration file properly. After the deployment is complete, delete the deployment configuration file in a timely manner.

2. No security measures are available for unconfigured devices. Therefore, if a deployment task is performed by a non-professional onsite engineer, ensure that the engineer does not perform unauthorized operations on the device, USB flash drive, or deployment files.

3. If a configured device needs to be deployed using a USB flash drive, you are advised to use compression encryption and HMAC integrity check to ensure file security.

4. Do not remove the USB flash drive before the USB-based deployment is complete. Otherwise, data in the USB flash drive may be damaged.

5. Do not power off the device during USB-based deployment. Otherwise, the upgrade fails.

6. During USB-based deployment, if the deployment file contains the system software, the CPU usage may be high temporarily. The CPU usage will automatically return to the normal range, and no action is required.

USB-based deployment

Streamlined USB-based deployment is used only in solution scenarios.

Ensure that the devices are placed based on the mappings between the ESNs and sites. Otherwise, the devices may not be able to communicate with the controller.

USB-based deployment

Configuration labels are saved during streamlined USB-based deployment. After configurations are rolled back to a deployment label, the console port login configuration will be cleared. To log in to the device, you need to deliver the configuration again on the controller.

DHCP-based deployment

Only Python 3 scripts are supported.

DHCP-based deployment

1. During the deployment of a device, device configurations are modified. When logging in to the device to save configurations, you need to check whether the configurations modified during the deployment are saved by mistake.

2. During ZTP, you cannot log in to the device to deliver configurations that are the same as or conflict with the ZTP configurations.

The following configurations are delivered during ZTP:

ip address dhcp-alloc

undo portswitch

dhcp client request option-list (Options 7, 43, 66, 67, and 148 are involved.)

dns server (The DNS server information obtained by the user can be distinguished from that obtained from the DHCP server during ZTP, unless the DNS server information configured by the user is the same as that obtained from the DHCP server.)

ip route-static 0.0.0.0 0 (fixed at 0.0.0.0 0.) gateway ifname (DHCP server configuration and deployment port)

info-center loghost [ipv6] x.x.x.x port xxx (The information obtained by the user can be distinguished from that obtained from the DHCP server during ZTP, unless the information configured by the user is the same as that obtained from the DHCP server.)

port description ztp (fixed at ztp)

ssl policy (fixed at sztp_policy)

DHCP-based deployment

The Syslog server address is obtained through the Options field configured on the DHCP server, but not through the intermediate file.

DHCP-based deployment

ZTP needs to be deployed on a private network because using a non-private network to deploy ZTP has security risks. For example, if a service port is used to deploy the device, the service plane, management plane, and control plane need to be isolated for security purposes. If security risks are uncontrollable, use SZTP for deployment.

DHCP-based deployment

The Python script file must be in the Windows or Unix format.

DHCP-based deployment

The devices to be deployed must meet the following requirements:

1. The device runs with an empty configuration file. That is, the Startup saved-configuration file and Next startup saved-configuration file fields in the display startup command output are empty.

2. ZTP is not disabled, that is, the set ztp disable command is not executed.

DHCP-based deployment

1. ZTP temporarily exits (that is, the deployment is suspended): During the deployment, a user logs in to the device and configures an IP address for the device. ZTP is suspended for 2 hours and then attempts to start again.

2. ZTP permanently exits: During the deployment, a user logs in to the device and sets the configuration file for the next startup or runs the set ztp disable command.

After a user logs in to the device, the device waits for 2 hours and then attempts to perform ZTP.

DHCP-based deployment

-URI: /restconf/data/huawei-sztp:sztp/usb-deployment: used to configure USB-based deployment and query USB-based deployment configurations.

When the interface request information is <usb-deployment><source-destination-compress-path>"{src_path};{dest_path}"</source-destination-compress-path></usb-deployment>, the device uses the password configured in theztp usb-deployment file-compress password command to decompress the src_path file to the dest_path directory. The value of src_path must be a USB path, and the value of dest_path must be a flash path.

If the interface request information is <usb-deployment><source-destination-integrity-path>$filepath</source-destination-integrity-path></usb-deployment>, the device calculates the SHA256 value of the file in the file path and records the value in flash:/ztp_hmac.txt.

-URI: /restconf/data?fields=/huawei-sztp:sztp/get-ztp-usb-status-flag(statusflag): used to check whether USB-based deployment is in progress.

-URI: /restconf/data?fields=/huawei-sztp:sztp/get-register-domain: used to query the domain name of the registration center configured on the device.

-URI: /restconf/operations/huawei-sztp:set-usb-enable-status: used to check whether USB-based deployment is in progress.

-URI: /restconf/operations/huawei-sztp:set-register-center-interactions: used to query the registration center of a specified IP address, and the controller information corresponding to the device ESN and MAC address.

The request format is <input><ip>$ip</ip><device-esn>$esn</device-esn><device-mac>$mac</device-mac><ssl-policy>$policy</ssl-policy></input>, in which ip indicates the IP address of the registration center, esn and mac indicate the ESN and MAC address of the device respectively, and policy indicates the name of the SSL policy created on the device.

- URI: /restconf/data?fields=/huawei-sztp:sztp/get-ztp-status-flag(statusflag): used to check whether ZTP is enabled.

- URI: /restconf/data/huawei-sztp:sztp/ztp-bootstraps: used to obtain information about the bootstrap server, including the bootstrap server address, port number, and certificate authentication mode.

- URI: /restconf/data/huawei-sztp:sztp/parse-ztp-config: used to obtain information about ZTP capabilities supported by the device, such as whether USB-based deployment and email-based deployment are supported and the supported file transfer protocols.

- URI: /restconf/operations/huawei-sztp:set-sztp-interactions: used to query interaction information between the server and bootstrap server.

If the interface request information is <input><host-addr-ipv4>$ip</host-addr-ipv4><server-port>$port</server-port><load-cafile>$has_caFile</load-cafile><dev-esn>$esn</dev-esn><redirect-num>$pin</redirect-num></input>, the device obtains the conveyed-info information from the bootstrap server. In the preceding information, ip and port indicate the IP address and port number of the bootstrap server respectively, has_caFile indicates whether the device has the trust certificate loaded, esn indicates the ESN of the device, and pin indicates the number of bootstrap servers to which the device is redirected.

If the interface request information is <input><host-addr-ipv4>$ip</host-addr-ipv4><server-port>$port</server-port><sztp-progress>$progress</sztp-progress></input>, the device sends the SZTP deployment progress to the bootstrap server. In the preceding information, ip and port indicate the IP address and port number of the bootstrap server respectively, the value of progress is a character string and can be customized, for example, bootstrap-initiated, parsing-initiated, parsing-complete, boot-image-initiated, or bootstrap-complete.

If the interface request information is <input><delete-cert>$certName</delete-cert></input>, the device deletes the trust certificate downloaded from the bootstrap server. In the preceding information, certName indicates the certificate name.

The request format is <input><fileurl>$file_url</fileurl><filepath>$file_path</filepath></input>, in which the value of file_url is a character string in the format of http://1.1.1.1/ztp.ini, and file_path indicates the file storage path, for example, flash:/.

- URI: /restconf/operations/huawei-sztp:set-running-status: used to set the current ZTP status.

The request format is <input><runningstatus>$enableStatus</runningstatus></input>, in which the value of enableStatus is true or false.

-URI: /restconf/operations/huawei-sztp:set-bootstrap-interactions: used to set information for downloading files from the bootstrap server.

The request format is <input><host-addr-ip>$ip</host-addr-ip><server-port>$port</server-port><trust-state>$trust_state</trust-state><voucher>$voucher</voucher><vpn-instance>$vpn</vpn-instance><ssl-policy>$policy</ssl-policy></input>, which is equivalent to the ztp certificate-remote command. For details about the parameters, see the command description.

-URI: /restconf/operations/huawei-sztp:operate-files: used to create a file, delete a file, or check whether a file exists based on operate_type.

The request format is <input><operate-type>$operate_type</operate-type><file-name>$file_name</file-name></input>, in which the value of operate_type is a character string that contains create, delete, and exist, and file_name indicates the file name in the flash directory.

-URI: /restconf/operations/huawei-sztp:get-capability: used to query a capability set value on the device.

The request format is <input><item-name>$item_name</item-name></input>, in which item_name indicates the capability set name.

-URI: /restconf/operations/huawei-sztp:operate-environment-variable: used to read, write, or clear environment variables. The environment variable name can only be set to usb_time_sn, ztp_enableFlag, ztp_statusFlag, or actoken.

The request format is <input><item-name>$item_name</item-name><item-value>$item_value</item-value><operate-type>type</operate-type></input>, in which item_name indicates the name of the environment variable to be queried or set, item_value indicates the value of the environment variable to be set, and the value of type ranges from 1 to 3, indicating that the read, write, and clear operations respectively.

DHCP-based deployment

You are advised to use SFTP for ZTP deployment.

HTTP, TFTP, and FTP have security risks. You are advised to use SFTP for ZTP deployment.

DHCP-based deployment

During file download for ZTP, if a file with the same name exists on the device, the original file will be deleted and the new file will be downloaded to the device.

DHCP-based deployment

During ZTP deployment, you need to add the login configuration of the console port or management network port to the configuration file. Otherwise, the login and deployment will fail. The device records user logs and attempts to perform the ZTP deployment process again.

DHCP-based deployment

The option fields in the downloaded intermediate file and the user name, password, and version file name configured in the intermediate file cannot contain the following special characters: & > < " ' | · $ ; ( ) [ ] { } ~ * ? ! \n # % , /.

DHCP-based deployment

For a voucher certificate, only the serial-number field (indicating the device ESN) is verified. The created-on, expires-on, assertion, idevid-issuer, domain-cert-revocation-checks, nonce, and last-renewal-date fields are not verified.

The onboarding information does not use the configuration-handling (merge/replace) object. The configuration file takes effect after the system is restarted.

The pre-configuration-script and post-configuration-script objects are not used in the onboarding information.

DHCP-based deployment

1. Before SZTP deployment, a device identity certificate must be loaded before delivery. The certificate is used for authentication between the device and server and for establishing a TLS connection.

2. The bootstrap data sent by the server may be encrypted using the public key of the device identity certificate. The device needs to decrypt the bootstrap data using the private key of the device identity certificate.

DHCP-based deployment

The option 148 field configured on the DHCP server must comply with the following rules: agilemanage-domain and agilemanage-port must be used in pairs, and the number of IP addresses must be the same as the number of ports.
