If the destination address of a GRE tunnel recurses to a ToTable route (static route whose next hop is a VPN) or Vlink route, the GRE tunnel cannot go up.

Basic GRE functions

The routes to GREv4 tunnel destination addresses can recurse only to IPsec tunnels and cannot recurse to other tunnels.

Basic GRE functions

After the pathMTU function is enabled, the device cannot fragment or reassemble GRE keepalive detection packets. If the size of a Keepalive detection packet encapsulated in a GRE tunnel exceeds the MTU of the interface, the packet can be forwarded out of the device without being fragmented. If the device functioning as the destination end of the tunnel receives fragmented packets, the packet is incorrectly decapsulated and discarded.

Basic GRE functions

When the Keepalive function is enabled for a GRE tunnel, the tunnel interface may frequently alternate between up and down due to insufficient ACL resources. When configuring the Keepalive function, you are advised to configure flapping control to reduce the impact on device and network stability.

Basic GRE functions

GRE tunnels bound to different VPNs cannot have the same source IP addresses and same destination IP addresses.

Traffic statistics on a logical interface do not contain bandwidth usage information.

Basic GRE functions

After the device receives GRE packets that are fragmented based on the GRE header, the device cannot identify other segments except the first one because the GRE header is followed by a data packet but not the inner IP header. In this case, the device hashes received fragments among ECMP or LAG members based on data packet information. As a result, the forwarding paths of these GRE packets may be different, causing packet mis-sequencing on the destination device.

Basic GRE functions

When an IP packet enters a GRE tunnel and is encapsulated:

1. The DSCP value in the original IP header is mapped to an internal priority based on the DiffServ default profile. The internal priority is obtained based on the DiffServ domain profile bound to a Layer 3 inbound interface.

2. The DSCP value in the newly encapsulated IP header is mapped to an internal priority based on the DiffServ domain profile bound to the outbound interface. The internal priority is obtained based on the new DSCP value in the original IP header and the DiffServ default profile.

3. The qos phb marking dscp enable command must be run in the system view to ensure the correct priority mapping of packets. Otherwise, the queue that packets on the outbound interface enter is determined based on the DSCP value of the original packet defined in the default DiffServ domain profile. The DSCP value of the packets sent from the device may not be the priority specified in pipe mode, because priority mapping is performed twice.

When an IP packet leaves a GRE tunnel and is decapsulated:

The DSCP value in the inner IP header is mapped based on the internal priority and the DiffServ domain profile bound to the outbound interface. The internal priority is obtained based on the DSCP value in the outer IP header and the DiffServ default profile.

Basic GRE functions

Different types of tunnel interfaces cannot be configured with the same tunnel source address and destination address. For example, an IPv6 over IPv4 tunnel interface and a GRE tunnel interface cannot be configured with the same tunnel source address and destination address.
