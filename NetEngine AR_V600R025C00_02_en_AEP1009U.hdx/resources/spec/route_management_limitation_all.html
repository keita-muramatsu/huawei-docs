IPv6 FIB

In an inter-VPN communication scenario, when the DIP is used to search the IPv6 routing table, the result is a new VPN. Because the new VPN and DIP are used to search the routing table again, the forwarding performance deteriorates.

1. Next-Table routes can recurse twice at most.

2. Next-Table routes do not support load balancing or FRR.

IPv6 FIB

Default routes and common routes share IPv6 forwarding entries. If the number of common routes exceeds the upper limit, the default routes fail to be delivered. For details about IPv6 forwarding entry specifications, see "IPv6 FIB table specification."

IPv6 FIB

1. The peer device cannot ping the address of a local interface across VPNs based on the static route information.

2. When ECMP or FRR is configured for a static route, packet loss occurs for a short period of time for the inter-VPN traffic that is transmitted over the static route.

3. When an inter-VPN static route with the destination address with a 128-bit mask is configured and the next hop of this static route is an interface, the static route does not take effect.

4. When a route with a non-128-bit mask is configured for the source VPN and an ND entry with the same mask already exists in the destination VPN, the newly configured route does not take effect. You can reset the ND entry corresponding to the destination VPN to make the new route take effect.

IPv4 FIB

IP forwarding is performed (ignoring MAC addresses) only for network segment routes. This function does not take effect if ARP entries are queried.

IPv4 FIB

Default routes and common routes share IPv4 forwarding entries. If the number of common routes exceeds the upper limit, the default routes fail to be delivered. For details about IPv4 forwarding entry specifications, see "IPv4 FIB table specification."

IPv4 FIB

1. The peer device cannot ping the address of a local interface across VPNs based on such a static route.

2. When ECMP or FRR is configured for a static route, packet loss occurs for a short period of time for the inter-VPN traffic that is transmitted based on this static route.

3. When an inter-VPN static route with the destination address with a 32-bit mask is configured and the next hop of this static route is an interface, the static route does not take effect.

4. When a route with a non-32-bit mask is configured for the source VPN and an ARP entry with the same mask already exists in the destination VPN, the newly configured route does not take effect. You can reset the ARP entry corresponding to the destination VPN to make the new route take effect.

IPv6 Route Management

For the AR5700 series, AR6700 series, AR8700-8:

After the hardware route-forwarding enable is configured, the IPv6 load balancing command does not take effect. You can configure the IPv4 load balancing command to implement the corresponding function.

IPv6 Route Management

For the AR5700 series, AR8700-8, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR6710-H4T4X2Y7:

After hardware route-forwarding enable is configured, IPv6 per-packet load balancing does not take effect, and elephant and ant flows cannot be effectively adjusted.

IPv4 Route Management

ECMP load balancing consistency does not take effect in asymmetric route deployment scenarios. Different routes must use the same or different ECMP group members. Some member paths cannot overlap. That is, a link cannot be a member of both ECMP1 and ECMP2, ECMP1 and ECMP2 have different member links.

IPv4 Route Management

When the outbound interface of an ECMP member link alternates between Up and Down, ECMP fast update can detect the interface flapping and hash the traffic on the interface to other links. When the interface goes Up, the traffic is switched back; however, ECMP convergence on the control plane does not detect intermittent disconnections. Therefore, when an interface alternates between Up and Down states, ECMP hash consistency cannot be ensured.

IPv4 Route Management

After ECMP consistency hash is enabled, the FIB entry delivery rate decreases by about 10%.

IPv4 Route Management

1. For ordinary IPv4 fragmented packets, when 5-tuple load balancing is performed for TCP or UDP packets, the first fragment of a packet is automatically load balanced based on only source and destination IP addresses.

2. For the first fragment of a GRE/IP-encapsulated packet fragmented based on the outer IP header, its inner IP/IPv6 header can participate in hash-based load balancing. As a result, the routes selected for the first fragment and subsequent fragments will be different.

IPv4 Route Management

For the AR8000 series, AR5700 series, AR6710-L8T3TS1X2, AR6710-L50T2X4, AR6710-L8T3TS1X2-T, AR6710-H4T4X2Y7, AR6710-L26T2X4, AR6710-L50T2X4-T, AR6710-L26T2X4-T:

To ensure that ECMP hash consistency takes precedence, load balancing is compromised. After ECMP consistency hash is enabled, traffic may not be evenly load balanced among ECMP member paths.

IPv4 Route Management

After ECMP load balancing consistency is enabled, more next-hop resources will be consumed. As the total number of member paths in each ECMP group is fixed to 128, the number of supported ECMP groups will reduce. The number of supported ECMP groups depends on the total number of ECMP paths supported by the specific board. Some boards may successfully apply for and obtain 128 NHP member resources, whereas other boards cannot. If boards cannot apply for 128 NHP member resources, they apply for NHP resources in common mode.

Example:

If the total number of ECMP paths on a board is 128K, the maximum number of ECMP groups is 1K (128K/128) after ECMP load balancing consistency is enabled. (128K ECMP paths are shared by all services. K = 1024)

IPv4 Route Management

After ECMP consistency hash is enabled, the ECMP member delivery sequence on different boards or devices is different. As a result, when the same traffic is received from different boards or devices, the outbound interfaces of the traffic may be different.

IPv4 Route Management

For the AR5700 series, AR8700-8, AR6710-L8T3TS1X2, AR6710-L8T3TS1X2-T, AR6710-H4T4X2Y7:

After hardware route-forwarding enable is configured, per-packet load balancing in IPv4 load balancing does not take effect, and elephant and ant flows cannot be effectively adjusted.
