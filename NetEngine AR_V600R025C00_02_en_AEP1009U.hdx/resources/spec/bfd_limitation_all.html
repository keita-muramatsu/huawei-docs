Configuration Precautions for BFD

Licensing Requirements

BFD is not under license control.

Precautions

  • Deploying QoS in multi-hop BFD scenarios is not recommended, as it may cause BFD flapping.
  • When a network is in poor quality or overloaded, increase the BFD detection interval as required.
  • When a BFD session is configured between two devices, you are advised to increase the BFD detection interval if an NE along the link between the two devices uses low-speed interfaces or has QoS configured for rate limiting.
  • If a device is deployed on the link between two routing devices which detect one another through BFD, you are advised to set a larger BFD detection interval (longer than 100 ms is recommended) to prevent BFD flapping resulting from occasional network congestion.

Basic BFD Functions

The local discriminator of the local device must be the same as the remote discriminator of the remote device, and the remote discriminator of the local device must be the same as the local discriminator of the remote device. Otherwise, the static BFD session cannot be established.

Basic BFD Functions

If the WTR time is used, you need to manually set the same WTR time at both ends. Otherwise, when the session status changes at one end, the BFD session status detected by the applications at both ends is different.

Basic BFD Functions

Strict URPF or poison reverse cannot be configured on the interface where a U-BFD session is established.

When information is filled in the Echo packet, the source and destination fields are filled with the IP address of the outbound interface on the local end. After receiving a packet, strict URPF checks the source address and interface and discards the packet. As a result, flapping occurs.

Basic BFD Functions

The BFD detection interval of the inner-layer link must be less than that of the outer-layer link.

Basic BFD Functions

Static BFD sessions (excluding static automatically negotiated BFD sessions) cannot interwork with dynamic BFD sessions or static automatically negotiated BFD sessions.

BFD does not guarantee the interworking between static and dynamic BFD sessions. If a session does not flap, it may go up through negotiation.

Basic BFD Functions

When PST is enabled for the BFD session bound to the main interface, only one session can trigger fast switching if the interface is enabled with IPv4 and IPv6 dual stacks.

BFD Service Scenario

When BFD for default IP sessions are configured on two indirectly connected devices, you are advised to disable BFD on the intermediate device or configure a default IP address different from that of the two devices. Otherwise, the BFD session fails to go up through negotiation.

BFD Service Scenario

When BFD for Perlink is configured, VLANIF member interfaces can only be access interfaces.

BFD Service Scenario

PerLink session response packets are forwarded based on routing information. As a result, the sending path may be different from the response path.

When a single-ended fault occurs on a trunk interface, for example, a member interface on one end is removed from the trunk interface or a member interface on the other end is faulty, BFD response packets may fail to detect the peer interface fault in a timely manner. As a result, BFD response packets are still routed to the faulty interface based on the hash algorithm, and BFD response packets are received properly. As a result, BFD goes Down, affecting service functions.

Workaround

1. You are advised to run the mode lacp-static command on a trunk interface so that the devices at both ends can quickly detect the peer interface exception and prevent BFD packets from being forwarded through the abnormal link.

2. Set the detection period of the PerLink BFD session to a larger value. You are advised to set the detection period based on the recommended value in the minimum detection period that can be configured for PerLink one-arm echo BFD to ensure that LAG member faults are not falsely reported as Down.

BFD Service Scenario

In multi-hop BFD scenarios, the QoS function is not recommended because it may cause BFD flapping.

BFD Service Scenario

When a multi-hop BFD session is configured and the bound peer IP address belongs to the network segment of the management network interface, the BFD session cannot be established.

The type delivered in the routing table of the management network port is not DROP. BFD packets sent through Ethernet match the routing table and cannot be forwarded. As a result, the BFD packets are discarded. Currently, the management interface cannot be detected. Currently, the detection function is unavailable for scenarios with management network ports.

BFD Service Scenario

The next hop of a BFD session cannot be the outbound interface of an SD-WAN tunnel.

BFD Service Scenario

In the BFD for IP link scenario, a public network route cannot iterate to an IPv4 over IPv6 or IPv6 over IPv4 tunnel.

BFD Service Scenario

If a single-hop BFD session is directly bound to an Eth-Trunk interface or a member interface of a VLANIF interface is an Eth-Trunk interface, the BFD session incorrectly goes down when the member interface of the Eth-Trunk interface goes down or the board where the Eth-Trunk interface resides goes offline.

BFD detection is not triggered to go down only when the Eth-Trunk interface is normally updated and the abnormal interface is removed from the member interface within N detection periods.

BFD detection packets are forwarded by an Eth-Trunk member interface selected through hash calculation. If the faulty member interface is the one hashed, BFD detection is triggered to go down. Otherwise, BFD detection is not triggered to go down.

BFD Service Scenario

When configuring BFD for IPv6 sessions, you can configure IPv6 addresses as link-local addresses only for single-hop BFD sessions.

BFD Service Scenario

For a static multicast BFD session with automatically negotiated discriminators, if no source IP address is configured, a secure IP address is used by default. If this parameter is specified, the source IP addresses configured on both ends must be the same. If they are different, the multicast BFD session cannot go up.

BFD Service Scenario

When a link-local address is specified for OSPFv3 or IS-ISv6 to deliver routes and a static BFD session is associated with FRR, the peer-ipv6 parameter in the bfd bind peer-ipv6 command must be set to the link-local address of the peer interface.

BFD Service Scenario

It is recommended that the BFD detection interval be greater than the fault convergence time of an Eth-Trunk member interface or the recovery time of a physical interface that alternates between up and down states.

It is recommended that the BFD detection period be greater than the fault convergence time of an Eth-Trunk member interface or the recovery time of a physical interface that alternates between up and down states.

Minimum BFD detection period of LAG interfaces: ≥ 6 x 100 ms

BFD Service Scenario

After a BFD session is configured on a device, if the device receives a BFD packet indicating a down event and the remote discriminator carried in the packet is the same as the local discriminator configured on the device, the BFD session incorrectly reports a down event.

BFD Service Scenario

The inbound interface is not checked for single-hop BFD sessions. When a device receives a BFD packet indicating a down event, if the remote discriminator carried in the packet matches the local discriminator configured on the device, the BFD session may incorrectly report a down event. For example, upon receipt of a BFD packet indicating a down event, a BFD session with a multicast address specified as the peer address incorrectly reports a down event.

BFD Service Scenario

Except one-arm BFD Echo sessions, BFD for link-bundle sessions, and multicast BFD sessions, BFD packets of other types of BFD sessions are sent and received on only one board. A BFD session may go down when a port, board, or device fault occurs.

It is recommended that the BFD detection time be greater than the fault convergence time of LAG member interfaces or the time taken to rectify an intermittent disconnection fault of a physical port.

BFD Service Scenario

When the default CPCAR value is used, the number of BFD sessions supported by each board includes the number of BFD sessions established on the board and the number of BFD sessions that are established on other boards but whose BFD packets are forwarded by this board. If BFD packets are forwarded by a board whose BFD sessions reach the maximum allowable number of the board, run the car command in the attack defense policy view to increase the CPCAR value for BFD packets.

BFD Service Scenario

BFD sessions cannot be configured on GRE tunnels or IPv6 tunnel-encapsulated links.

BFD Service Scenario

The device's timeout mechanism for the first BFD packet prevents a BFD session down event from being incorrectly reported. This mechanism enables the device to start BFD timeout detection upon receipt of the packet carrying the Up state from the peer after a BFD session is established. If no BFD packet is received from the peer, the device reports a BFD session down event only after the timeout period of the first BFD packet expires.

The timeout period of the first BFD packet is as follows:

Software-based BFD: 50s

Forwarding NP deployed on the state machine: 50s

No forwarding NP deployed on the state machine: 200s

BFD Service Scenario

If BFD sessions bound to Eth-Trunk or VLANIF member interfaces are enabled to modify the port state table (PST), you must configure a wait to restore (WTR) time for the BFD session bound to the Eth-Trunk or VLANIF interface. This prevents the BFD session on the Eth-Trunk or VLANIF interface from flapping when its member interface joins or leaves the interface.

BFD Service Scenario

If the minimum BFD detection period is set to 10 ms x 3, flow table-based services (intelligent traffic steering, application identification, URL filtering, IPS/AV, NAT, ASPF, TCP FPM, and network traffic monitoring) cannot be enabled. For services that use flow tables, you are advised to set the minimum BFD detection period to a value greater than 100 ms x 3.

BFD Service Scenario

Because the interface bandwidth is too low, BFD session detection packets occupy most of the bandwidth, potentially affecting normal service traffic.

BFD Service Scenario

When matching BFD packets, the service matches only the YD field in the packets. If a detection Down packet with the same YD is sent, other normal YD discriminator packets go Down.

BFD Service Scenario

1. When the outbound interface of a BFD session is a VLANIF interface and the VLANIF interface is bound to a VGE interface, the BFD session goes down.

2. When the outbound interface of a BFD session is a VGE interface, the BFD session goes down.

BFD Service Scenario

The outbound interface of a BFD session cannot be iterated to a QinQ interface, and BFD packets cannot be sent or received on a QinQ interface.

If a BFD session is generated but the session status is abnormal, the following situations may occur:

1. BFD session negotiation fails.

2. The BFD session flaps.

BFD Service Scenario

Due to the limitation of cellular interfaces, BFD sessions may flap when the network fluctuates or the delay is long. If the outbound interface of a multi-hop BFD session is a cellular interface, you are advised to set the detection interval to a value greater than or equal to 3 x 100 ms. In addition, the total number of BFD instances cannot exceed 128.

BFD Service Scenario

The BFD peer IP address cannot be the outbound interface of an SRv6 TE Policy.

BFD Service Scenario

When one-arm BFD Echo is configured, Layer 3 interface isolation cannot be configured on the interface of the BFD-incapable peer. Otherwise, the BFD session goes down.

BFD Basics

When the card where the BFD session state machine resides resets, the BFD session goes down.

BFD Basics

If BFD is enabled globally and the product of the BFD packet sending interval multiplied by the difference between the session detection multiplier minus 1 is less than the OSU DDR online isolation blackout period, DDR isolation is not allowed.
