Configuration Precautions for Antivirus

Licensing Requirements

The update service of the antivirus signature database is controlled by the antivirus license control item. If the license control item is not activated, the signature database cannot be manually loaded or updated. After the license control item is activated, you can load and update the signature database. After the license control item expires, the signature database cannot be manually loaded or upgraded. The antivirus function is available, but the signature database may not be up-to-date. As a result, the virus detection and defense capabilities are limited.

Feature Requirements

When the antivirus function is deployed on the security device between two routing devices and the two routing devices detect each other through BFD, BFD flapping occurs if network congestion occurs occasionally. BFD flapping consumes link resources. You are advised to increase the BFD detection time on the routing device to a value greater than 100 ms.

The response action of antivirus detection cannot be configured for NFS. The default response action of antivirus detection for NFS is alert.

The response action of antivirus detection cannot be set to block for SMTP, POP3, and IMAP. The default response action of antivirus detection is alert for these protocols. You can change the action to declare or delete attachments.

The device can detect compressed files of the 7ZIP, TAR, ZIP, GZIP, RAR5, BZIP2, and XZ types. Compressed files of other types are directly permitted in the antivirus process.

The files with three compression layers can be inspected by default. Currently, the number of decompression layers can be configured. The maximum number of decompression layers is 100. Compressed files with the compression layers exceeding the configured upper limit are directly permitted in the antivirus process.

Only the first 50 MB of each decompressed file is inspected. If no malware is detected in all files, the compressed package is directly permitted in the antivirus process.

The device cannot perform antivirus detection over the traffic on the network where the forward and return paths of packets are inconsistent. On a network where the forward and return paths of packets are inconsistent, traffic will be directly permitted in the antivirus process.

In flow mode, virus blocking is implemented by blocking the last packet to damage the virus file structure. Incomplete virus files can still be viewed locally, but cannot be executed.

By default, the engine works in flow detection mode. In this mode, the device checks and forwards packets one by one in real time, and retains only the last packet until the antivirus result is returned. If the malware is detected, the last data packet is discarded to block the malware transmission.

For FTP, the engine discards the last data packet as it cannot predict the file size. Therefore, the device blocks the connection only by discarding the TCP FIN packet. When the FIN packets do not contain data packets:

The device detects the malware and discards FIN packets to block connections. However, because all data packets have been transmitted to the peer end, the device can only report an alarm and cannot block the malware file transmission. In this case, you can configure the proxy detection mode (ftp-detect scan-mode proxy) for FTP to block the malware.

In proxy mode, the device retains most data packets of a flow and performs malware detection. If detecting the malware, the device discards all retained data packets. If no malware is detected, the device forwards packets. The proxy mode consumes more performance than the flow detection mode. Select a detection mode based on the actual network situation.

When file type detection other than the default file type is enabled (such as web page files, picture files, and video files). This affects the performance of the entire system. Therefore, you need to set this parameter based on the site requirements.

In the resumable transmission scenario, the antivirus function blocks the virus-infected file that is transmitted for the first time. If the virus-infected file is transferred for multiple times, the resumable transfer blocking function blocks the file. For details about the restrictions on the resumable transfer blocking function, see Configuration Precautions for ASE in the product documentation.

To prevent log storms, the content security detection engine merges antivirus detection logs by default. Information such as the source port number in the merged logs may be 0.

The dynamic blacklist generated based on virus exceptions takes effect only when the blacklist function is enabled (using the firewall blacklist enable command).
