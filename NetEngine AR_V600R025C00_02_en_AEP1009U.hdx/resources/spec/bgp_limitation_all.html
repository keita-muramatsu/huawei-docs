BGP Basics

If the AS-SET parameter is configured during route summarization, the same sequence in the AS_Path attributes of all specific routes forms an AS_SEQUENCE, and all the other ASs form an AS_SET. The AS_SET is used as the AS_Path attribute of the summary route. The number of AS_Path numbers in the AS_Path attribute of a summary route cannot exceed 2000. Otherwise, the AS_Path attribute is set to null.

BGP Basics

After a route is imported between VPN and public network instances, the next hop or color extended community attribute of the route cannot be changed through a route-policy.

You are advised to properly plan the route-policy to be used during the route import between VPN and public network instances.

BGP Basics

Before enabling the Add-Path function, you need to set the number of paths for use according to the actual requirement. The maximum number of paths cannot be set; otherwise, memory resources may be exhausted.

BGP Basics

The peer allow-as-loop command does not take effect for the routes received from common IBGP peers or confederation IBGP peers. That is, even if this command is run, the device does not perform local AS number repetition check on these routes.

The peer allow-as-loop command enables the device to perform local AS number repetition check on the routes received from common EBGP peers or confederation EBGP peers.

If the peer allow-as-loop command is not configured, the local AS number cannot be repeated, and the implementation is equivalent to the peer allow-as-loop 0 configuration.

BGP Basics

EBGP peers do not support the following functions: route reflector, Best-external, Add-Path.

IBGP peers do not support the following functions: ebgp-max-hop and fake-as.

ebgp-max-hop and valid-ttl-hops are mutually exclusive.

BGP Basics

Scenario 1: The as-number command is run in the BGP-VPN instance IPv4 or IPv6 address family view to configure a VPN AS number, and the bgp yang-mode enable command is run to enable the YANG management mode for the BGP VPN instance.

Limitations:

1. After the bgp yang-mode enable command is run, the sequence of the peer as-number and as-number commands in the configuration file changes. As a result, configurations in the configuration file fail to be pasted. To resolve this problem, configure a VPN AS number using the as-number command first and then run other commands.

2. Do not configure BGP peer relationships in the BGP-Flow VPN instance IPv4 address family view, BGP-Flow VPN instance IPv6 address family view, or BGP-labeled-VPN instance IPv4 address family view. VPN IPv4 peers cannot be configured in the BGP-VPN instance IPv6 address family view.

3. Before deleting the VPN AS number, delete all the peers and peer groups in the BGP-VPN instance IPv4 or IPv6 address family as well as all the peers in the BGP VPN instance view.

4. Before running the undo bgp yang-mode enable command, delete the VPN AS number.

Scenario 2: A VPN AS number is configured in both the BGP-VPN instance IPv4 address family view and BGP-VPN instance IPv6 address family view, and the YANG management mode is enabled for the BGP VPN instance and then disabled.

Limitations:

1. After the bgp yang-mode enable command is run, the sequence of the peer as-number and as-number commands in the configuration file changes. As a result, configurations in the configuration file fail to be pasted. To solve this problem, run the peer as-number command in both the BGP-VPN instance IPv4 address family view and BGP-VPN instance IPv6 address family view to configure a new peer or peer group. However, do not configure a new peer in the BGP-VPN instance view.

2. Do not configure BGP peer relationships in the BGP-Flow VPN instance IPv4 address family view, BGP-Flow VPN instance IPv6 address family view, or BGP-labeled-VPN instance IPv4 address family view. VPN IPv4 peers cannot be configured in the BGP-VPN instance IPv6 address family view.

3. Before deleting the VPN AS number, delete all the peers and peer groups in the BGP-VPN instance IPv4 or IPv6 address family as well as all the peers in the BGP VPN instance view.

Note: The address families listed in this restriction are all restricted BGP address families. The actual address families supported by the device prevail.

BGP Basics

If the import-route command is used to advertise default routes, the default-route imported command must also be configured. Otherwise, even if the default routes exist in the routing table, existing local default routes cannot be advertised.

BGP Basics

(1) Regional validation depends on the trustworthiness of the original AS in each route. In actual application, the RPKI ROA function must also be deployed to ensure the correctness of the original AS.

(2) The regional validation configuration is a global configuration. Currently, the scenario where the public and private ASs overlap is not considered.

(3) Regional validation can be enabled only in the address family view. Regional validation cannot be enabled or disabled for a single peer. Currently, the following address families are supported: the IPv4 unicast address family, IPv6 unicast address family, VPN instance IPv4 address family, VPN instance IPv6 address family, and VPN instance IPv4 address family in BGP multi-instance. Labeled routes in the IPv4/IPv6 unicast address family support regional validation.

(4) Regional validation must be configured on a border router that is directly connected to a router in an external region. Risky internal routes that already exist cannot be identified.

(5) When both an import policy (for example, to modify AS numbers) and regional validation are configured, regional validation is performed before the import policy takes effect (after ROA).

(6) Regional validation affects the route learning performance of EBGP peers (the learning performance cannot decrease by more than 5% after regional validation is configured). Regional validation does not affect the convergence performance, RR reflection performance, or IBGP peers' route learning performance.

Configuration Restriction

A maximum of 100 regions can be configured. A maximum of 100 ASs can be configured in a region (regardless of 4-byte or 2-byte ASs).

A maximum of 100 regional confederations can be configured. A maximum of 100 regions can be configured in a regional confederation.

An AS cannot be added to different regions. (The display format is not affected. For example, 1.0 and 65536 are the same AS.)

A region cannot be added to different regional confederations. When a region is added to a regional confederation, the region must exist.

If a region has been added to a regional confederation, the region information in the regional confederation is also deleted when the region is deleted.

BGP Basics

If a feature is not configured for a peer or the default value is configured for the peer, and then the peer is added to a peer group which has a non-default value of the feature configured, the peer inherits the feature configuration from the peer group.

If a peer in a peer group has the same configuration of a feature with the peer group, and then the feature is modified for the peer group, the feature configuration of the peer changes accordingly.

If a peer in a peer group and the peer group have different configurations of a feature, and then the feature is modified for the peer group, the feature configuration of the peer remains inconsistent with that of the peer group.

BGP Basics

If the listening network segments configured for a single instance and multiple instances are different but overlap, the configurations are not mutually exclusive. The device randomly selects one from the single instance and multiple instances to establish a dynamic peer relationship.

If the listening network segments of a single instance and multiple instances overlap, the local end randomly establishes a dynamic neighbor relationship with the peer end in a single instance or multiple instances after detecting a neighbor in the overlapping network segment. Do not configure a single instance or multiple instances to listen to overlapping network segments.

BGP Basics

In the scenario where an authentication configuration change causes an authentication failure (MD5, keychain, or TCP AO authentication failure), the peer disconnection is delayed for 1 minute.

1. The MD5 authentication configuration is modified.

2. The keychain authentication configuration is modified.
