Due to limited ARP encapsulation table resources, traffic forwarding may be abnormal when the number of ARP entries learned by the device exceeds the upper limit. In addition, ARP entries on different cards may be different.

MAC address-triggered ARP entry update and the MAC address learning priority are mutually exclusive. If both of them are configured, ARP attack packets will cause the MAC address learning priority to become invalid. To solve this problem, you need to configure ARP attack defense.

A Virtual-MEth interface does not process received gratuitous ARP packets whose destination address is not the virtual IP address. If the login interface or MAC address is changed, you need to manually delete the corresponding ARP entry.

If a terminal needs to access a Virtual-MEth interface, you need to manually change the IP address of the terminal to an IP address on the same network segment as the virtual IP address.

(1) If proxy ARP anyway is enabled on an intermediate device, broadcast packets passing through the intermediate device are terminated, and users cannot log in to the virtual gateway. In this case, you need to delete proxy ARP anyway on the intermediate device.

(2) If Layer 2 security functions, such as ARP snooping, BD DAI, and NAC, are also enabled on the active LC and intermediate device, packets cannot be sent to the ARP component and ARP entries cannot be learned. As such, related security functions must permit normally learned ARP packets, for example, by configuring a DHCP binding table on the access device.

Intra-VLAN proxy ARP determines whether VLAN information meets proxy requirements based on the ARP entries of the source and destination IP addresses. Therefore, if the ARP entry of a destination IP address does not exist, the device broadcasts ARP request packets in the VLAN to learn the ARP entry of the destination IP address. If proxy ARP is enabled on multiple devices on the network but the destination IP address does not exist, the ARP broadcast triggers the same proxy process on other devices. This process repeats, causing a severe broadcast storm.

Proxy ARP does not take effect on gratuitous ARP packets.

Proxy ARP anyway is mutually exclusive with routed proxy ARP, intra-VLAN proxy ARP, inter-VLAN proxy ARP, and local proxy ARP.

In a VRRP scenario, the virtual IP address configured for the VRRP group, real IP address of the interface, and IP address of the access end must be on the same network segment.

1. The IP addresses of the VBDIF interface, VLANIF interface, and Layer 3 sub-interface must be on the same network segment. These interfaces do not support inter-network segment learning.

2. It is recommended that the IP addresses of other types of interfaces be on the same network segment. If the IP addresses are on different network segments, run the undo arp learning on-different-segment disable command to enable ARP learning for both the virtual IP address and the address of the access end on different network segments.

Proxy ARP does not take effect if the VRRP group is in Backup state in VBDIF interface and VLANIF interface views.
