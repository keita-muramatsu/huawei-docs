Do not configure application identification in the networking environment where the forward and return paths of packets are inconsistent. If the forward and return paths of packets are inconsistent, the application identification function may be unavailable.

After a user-defined application rule is added, modified, or deleted, you need to run the engine configuration commit command in the system view to commit the configuration for the rule to take effect. The new rule takes effect only for new flows.

To ensure the optimal application identification performance and rate, you are advised to use the default maximum number of detection packets sent to the application identification module for a single session. Adjusting the maximum number of detection packets affects the application identification performance and rate.

For the packets that match the well-known port rule, the smaller value between the detect max-packets command and the port-identification packet-number-threshold command is used as the maximum number of detection packets.

On actual networks, some applications are no longer used because they stop providing services. Therefore, there is no traffic related to these applications on the networks. To prevent useless applications from using space, the applications that stop providing services are in the obsolete state in the SA-SDB. An application that has been in the obsolete state for one year will be deleted from the SA-SDB. If the SA-SDB is upgraded after an application is deleted, the policy of the deleted application cannot be referenced and the application cannot be viewed through original logs because the new SA-SDB does not contain the deleted application. Therefore, delete the configuration of the obsolete application in time.

Identification of predefined applications depends on the SA-SDB. Before configuring application-based policies, ensure that the SA-SDB of the latest version has been loaded to the desired device. If a device does not have an SA-SDB loaded or the loaded SA-SDB version is outdated, the application identification function may become unavailable, or applications cannot be accurately identified.

To use the application identification function, you need to load an SA-SDB. Otherwise, commands related to application identification cannot be delivered.

After the engine is restarted and its status changes to ready (the Engine Status field in the display engine information command output is Ready) or the application identification configuration is successfully committed, you need to wait for at least 12 seconds before running the engine configuration commit command to commit the configuration again. Otherwise, the configuration may fail to be committed.

The identification priority of user-defined applications is higher than that of predefined applications in the SA signature database. After the SA signature database is updated, user-defined applications still take precedence.

Third-party VPN software, such as XVPN, features short iteration periods and fast traffic feature changes and defense capabilities (such as Viber). In addition, such applications evade traffic detection by switching communication channels. Therefore, the application awareness signature database cannot accurately match such applications of the latest version, and the device cannot implement accurate traffic control.

When configuring user-defined applications to use IP addresses or ports as the identification conditions, you are advised to configure two rules for each IP address or port and specify the source and destination parameters. Otherwise, an application may be identified as another application.

After an application identification result is obtained for a packet in a flow, the application identification for the flow ends and will not be performed for subsequent packets, for example, application identification in DNS persistent connection scenarios.

Due to the complexity of network traffic and the continuous emergence of unknown applications, the SA signature database may be lagging in covering unknown applications. If the predefined applications in the SA signature database cannot meet the actual management and control requirements, you can define new applications based on application features and reference them in policies for management and control. For details about how to configure user-defined applications, see the application identification section in the product documentation. However, the traffic on the live network is complex, and technical problems may occur during application feature extraction. If the user-defined application configuration cannot be completed by following the instructions provided in the product documentation, contact Huawei technical support.

- QUIC applications can be identified only based on the SNI. In this case, applications cannot be identified if the corresponding packets do not contain SNIs.

- Enabling the QUIC first-packet parsing function will deteriorate device performance. Determine whether to enable this function based on site requirements.

1. Some applications are integrated with public services or third-party applications. In application permitting scenarios, the integrated public services or third-party applications must be permitted.

2. The behavior of blocked or permitted web pages or software may change continuously. As a result, the web pages or software may fail to be loaded completely or the blocking may fail. You need to continuously monitor the control effect.

3. The traffic generated by the same software varies according to the software version, region, networking, and endpoint. The control effect varies accordingly.

Application identification analyzes traffic on the Internet. Point-to-point communication traffic generated in LAN scenarios is not within the application identification scope and cannot be identified by the application identification function.
