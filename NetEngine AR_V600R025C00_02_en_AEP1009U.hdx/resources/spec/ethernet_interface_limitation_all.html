Loopback on an interface

When testing some special functions such as locating an Ethernet fault, you need to enable loopback detection on an Ethernet interface to check whether the interface is working properly. If the Ethernet interface is working properly, its physical status and protocol status are always up after loopback detection is enabled. If a fault occurs on the Ethernet interface, the interface is down.

After an interface is configured as a loopback interface or added to an external loopback interface, the interface rate is the maximum bandwidth of the interface, regardless of the type of the optical module installed on the interface.

When an interface is shutdown or enters the error-down state, maintenance commands cannot be used to test loopback on the interface.

Port

1. If the medium on an interface is replaced in the interface view, some features supported by the new medium cannot be configured in the interface view. To resolve this issue, exit the interface view and run the interface interface-type interface-number command to enter the interface view again.

2. If the module of an interface is replaced and the new module does not support the functions (including the rate configuration and auto-negotiation configuration) that have taken effect on the interface, the conflict policy of the device depends on the installed medium type.

Port

When the auto-negotiation enabling status of two directly connected ports is set to different values, the port may go up unexpectedly. If the port goes up in this case, it may work abnormally, for example, packet loss or error packets occur. It is recommended that the auto-negotiation enabling status of the two interconnected ports be set to the same value.

Port

For the AR5710-S8P2XE-NRGL, AR5710-S8T2S, AR5710-S8T2XE-NRGL:

10GE electrical ports must use Category 6A or higher shielded network cables. Unshielded network cables cannot be used.

Port

There is a possibility that various types of error packets are generated on a port when the port status changes between down and up instantaneously, for example, the physical configuration (including negotiation, FEC, and speed) of the port is changed, the working mode of the port is changed, or the port starts registration with traffic.

Port

In the interconnection scenario, the negotiation modes, duplex modes, and rates of the two ends of a link must be the same. Otherwise, the interconnection may fail.

Port

For the AR5710-S52T2XE4, AR5710-S8TWDSE-LTE4EA, AR5710-S8T1XWE-NRGL, AR5710-S8T1XWE:

1. An interface that supports jumbo frame configuration and an interface that does not support jumbo frame configuration cannot be added to the same Eth-Trunk.

2. After an interface that does not support jumbo frame configuration is added to an Eth-Trunk, the Eth-Trunk does not support jumbo frame configuration.

3. If the jumbo frame range of an Eth-Trunk is changed, interfaces that do not support jumbo frame configuration cannot be added to the Eth-Trunk.

Port

The default FEC mode on an interface varies according to the device model or connection medium. You can run the display interface command to check the FEC mode of an interface. The FEC modes of interfaces on both ends of a link must be the same; otherwise, the interfaces do not go up. If the FEC modes of the two interfaces are different, change the FEC mode of one interface in non-auto-negotiation mode to ensure that the FEC modes of the two interfaces are the same.

To reduce the transmission bit error rate of a physical link and reduce error packets, enable FEC on both ends of the link.

The FEC function is mutually exclusive with auto-negotiation and the speed command. If FEC has been configured, enabling auto-negotiation or running the speed command will automatically delete the FEC configuration.

Note the following while ensuring that the negotiation status of interfaces at both ends of a link is not affected:

When QSFP28-100G-LR4 optical modules are used, FEC is disabled by default according to IEEE 802.3.

When QSFP28 optical modules except QSFP28-100G-LR4 are used, FEC is enabled by default. You are advised not to disable FEC; otherwise, error packets may be generated.

Port

The device works in duplex mode and does not support the half-duplex mode.

Port

Low-speed sampling of port information. The sampling path is huawei-devm:devm/ports/port/huawei-pic:ethernet.

If the device is unconfigured and has a single sampling node, you are advised to adjust the sampling period.

If the number of ports is greater than 100, you are advised to set the sampling period to 60 seconds.

If the number of ports is greater than 300, you are advised to set the sampling period to 180 seconds.

If the number of ports is greater than 500, you are advised to set the sampling period to 300 seconds.

If the CPU usage is high, you are advised to increase the sampling period.

Port

Low-speed sampling of optical module information. The sampling path is huawei-devm:devm/ports/port/huawei-pic:optical-module/channels/channel.

If there are a large number of ports, the actual sampling duration will exceed the minimum sampling period. You are advised to adjust the sampling period.

If the number of ports is greater than 100, you are advised to set the sampling period to 30 seconds.

If the number of ports is greater than 200, you are advised to set the sampling period to 1 minute.

If the number of ports is greater than 400, you are advised to change the sampling period to 2 minutes.

Maintainability

1. During the QL firmware upgrade, active/standby switchover of main control boards is not supported. If an active/standby switchover is performed, the QL firmware upgrade process is interrupted. As a result, the QL chip becomes unavailable and the corresponding port goes down.

2. If a hardware fault occurs during the QL firmware upgrade, the upgrade fails, and the QL chip becomes unavailable.

3. During the QL firmware upgrade, operations such as powering on or off boards or subcards, resetting boards or subcards, and configuring loopback cannot be performed.

4. During the QL firmware upgrade, the configuration is locked and cannot be committed.

5. If the same optical module is removed and then installed during the upgrade, the corresponding port goes down.

6. If an optical fiber is removed and then installed during the upgrade, the corresponding port goes down.

7. If the signal sent by the remote end is abnormal during the upgrade, the SNR eye pattern is poor, and the corresponding port goes down.

Rate reduction auto-negotiation

Electrical interfaces at both ends of a link do not support rate decrease auto-negotiation. For example, if the two interfaces are GE electrical interfaces and connected using an Ethernet cable that supports only the rate of 100 Mbit/s, the interfaces cannot negotiate their rate to 1000 Mbit/s and become down.
