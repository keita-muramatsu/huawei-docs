Basic CAPWAP Parameter Settings

In the WAC + AP networking, the MTU of each interface along the CAPWAP packet forwarding path from the CAPWAP source interface on the WAC to the VLANIF interface corresponding to the management VLAN on the APs must be greater than or equal to the MTU configured in the AP system profile. Otherwise, CAPWAP packet fragmentation deteriorates forwarding performance.

DTLS Negotiation

When the device connects to APs running versions earlier than V200R021C00, note the following:

1. APs running earlier versions do not support initial access using the default certificate, and therefore will fail to go online if DTLS encryption is enabled. In this case, enable the function of establishing CAPWAP DTLS sessions in none authentication mode (by using the capwap dtls no-auth enable command) so that the APs can obtain security credentials. After the APs go online, disable this function immediately to prevent unauthorized APs from going online.

2. APs running earlier versions support only the CBC cipher suite and DTLS 1.0. Therefore, you need to run the capwap dtls cbc enable and capwap dtls version1.0 commands to enable compatibility with the CBC cipher suite and DTLS 1.0. However, this configuration poses security risks.

DTLS Negotiation

For security purposes, it is not recommended that the weak security algorithms or protocols provided in CAPWAP be used. If required, run the install feature-software WEAKEA command to install the weak security algorithm/protocol feature package WEAKEA. By default, the device is equipped with the weak security algorithm/protocol feature package WEAKEA. For details about how to install or uninstall the feature package, see "Upgrade and Maintenance" in the Configuration Guide > System Management Configuration.
