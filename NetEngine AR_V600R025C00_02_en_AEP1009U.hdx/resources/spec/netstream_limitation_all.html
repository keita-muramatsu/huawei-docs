Feature Requirements

Table 2 Feature requirements

Feature

Feature Requirements

Original flow

Original flows cannot be created for packets with more than two VLAN tags.

Flow Sampling

If the sampled traffic is forwarded through multiple Layer 3 interfaces, only traffic on the first Layer 3 interface enabled with sampling can be sampled in the inbound direction, and traffic on the last Layer 3 interface enabled with sampling can be sampled in the outbound direction.

Flow Sampling

NetStream packets cannot be sent through the management interface.

Flow Sampling

For packet fragmentation, NetStream can sample only the first fragment of packets.

Flow Sampling

When the sampling rate is configured based on IPv4/IPv6, packet types are distinguished during sampling, and unmatched packets are discarded based on the flow entry creation configuration during flow entry creation.

Flow Sampling

When performing NetStream sampling, the device does not parse the option fields in IPv4 packets or the extension headers in IPv6 packets.

Flow Sampling

Sampling restrictions when MQC is also used

Co-deployment with MQC:

If the CAR action is configured for inbound MQC, the device performs NetStream sampling on packets after MQC CAR is performed.

If the CAR action is configured for outbound MQC, the device performs NetStream sampling on packets before MQC CAR is performed.

If the discard action is configured for outbound MQC, the device performs outbound NetStream sampling on packets discarded by MQC.

If the discard action is configured for inbound MQC, the device performs inbound NetStream sampling on packets discarded by MQC.

Flow Sampling

Flow creation is supported only for Layer 3 unicast packets.

Flow Sampling

NetStream sampling is not performed for packets discarded in VLAN check.

Flow Sampling

1. For packets carrying two tags, the device creates flows based on the outer VLAN ID.

2. For packets carrying more than two tags, the device does not perform flow creation and analysis.

Flow Sampling

The packets discarded during forwarding are not sampled.

Flow Sampling

1. Only IPv4 flow tables can be stored locally.

2. When the memory of storing NetStream logs locally reaches the upper limit, the earliest logs are overwritten with the latest logs.

3. The device has a limit on the flow rate. A maximum of 8000 aged flows can be recorded within the aging period. When the number of aged flows exceeds 8000, some flow records may be lost to preferentially protect CPU resources.

4. The path for storing logs can only be a USB flash drive path instead of a flash memory path. Currently, logs can be stored only in USB flash drives.

5. The digit in the name of a NetStream log is in the range from 1 to 9999. That is, when the log name is netstreamdata9999.db, no new storage data file can be generated, logs cannot be updated, and storage logs will be lost.

6. The maximum size of a single data file stored in the USB flash drive is about 10 MB and cannot exceed 11 MB (MB = 1024 x 1024).

7. If the remaining space of the USB flash drive is less than 200000 bytes, no more data will be written to the USB flash drive.

Statistics export

When sampling is configured in the inbound or outbound direction of an interface, only the inbound or outbound interface information is included in the statistics, respectively.

Statistics export

Inbound NetStream sampling does not record outbound VLAN information, and outbound NetStream sampling does not record inbound VLAN information.
