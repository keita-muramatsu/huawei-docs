Security Policies

The device matches traffic against a security policy only when the inbound and outbound interfaces of the traffic are both Layer 3 interfaces added to security zones. Layer 2 packets are not matched against a security policy. Multicast and broadcast packets (such as IS-IS and OSPF packets) and unicast protocol packets that are not forwarded through the CPU are not matched against a security policy.

Security Policies

When the address of the policy rule uses the domain-set parameter, you need to understand the implementation mechanism of the device. When an IP address corresponds to multiple domain names, a maximum of 128 domain names can be queried for the IP address. If the domain name in the policy rule is not among the 128 queried domain names, the policy cannot be matched. You are advised to configure multiple domain names with the same IP address in the same policy rule.

After the device is restarted, the mapping between domain names and IP addresses stored on the device is deleted. If no DNS server is configured on the device, the device does not proactively obtain the IP address corresponding to the domain name. However, the DNS record of the user does not age out and no DNS request is initiated. The user directly accesses the destination address using the IP address, and the device does not learn the IP address corresponding to the domain name. In this case, the domain group does not take effect, and the policy rule that references the domain group may not be matched. You are advised to configure the same DNS server as that of the customer on the device.

If the traffic between the client and DNS server does not pass through the device, the device cannot obtain the IP address corresponding to the domain name by parsing DNS response packets. In this case, the same DNS server needs to be configured on the device so that the device can initiate DNS request packets to obtain the information. In addition, the domain group can parse only DNS response packets received from service interfaces and learn IP addresses.

Policy object

1. Configuration restrictions on the domain group name: The maximum total length of the domain group name and virtual system name is 156 characters due to the length limitations of the view. That is, if the virtual system name contains 31 characters, the maximum length of the domain group name is 125 characters.

2. Restrictions on domain group name association: If the length of a domain group name is greater than 59 characters, the existing domain group list is truncated when being associated. In addition, the name cannot be supplemented by tab. You need to enter the complete name.

Policy object

If the TTL (aging time of the mapping between domain names and IP addresses) is less than 1800 seconds, set the TTL to 1800 seconds. In addition, you are advised to configure a DNS server on the device to prevent policies referencing the domain group from becoming invalid due to the aging of the mapping between domain names and IP addresses. After a DNS server is configured and domain names are added to a domain group, the device proactively requests the IP addresses of the domain names from the DNS server and binds the IP addresses to the domain names. If the TTL is less than 7 minutes, the device sends an IP address update request every 3 minutes to update the IP address of the domain name in a timely manner.
