Limitations on the views of configuring mirrored and observing ports:

- An Eth-Trunk interface and its member interfaces cannot be configured as mirrored ports or observing ports at the same time.

- A mirrored port can be an Ethernet interface, an Eth-Trunk interface, or an Eth-Trunk member interface.

- An observing port can be an Ethernet interface.

When an Eth-Trunk member interface functions as a mirrored port, the following restrictions apply:

The function takes effect on Layer 2 Eth-Trunk member interfaces but does not take effect on Layer 3 Eth-Trunk member interfaces.

Packet fragments are processed in different ways in port mirroring and flow mirroring:

- In port mirroring, the device mirrors the unreassembled fragments received from the port.

- In flow mirroring, the device mirrors the reassembled packets.

Traffic received by an observing port cannot be mirrored to the observing port itself. The scenarios are as follows:

- In inbound port mirroring, traffic received by an inbound port cannot be mirrored to this port.

- In outbound port mirroring, traffic received by an observing port will not be mirrored. For example, if outbound port mirroring is configured on GEX/0/2 that mirrors packets to GEX/0/1, packets received by GEX/0/1 will not be mirrored to itself after being forwarded to GEX/0/2.

- Inbound flow mirroring has similar scenarios. For example, if a traffic policy is configured globally to mirror packets to the observing port GEX/0/1, packets received by GEX/0/1 will not be mirrored to itself.

Mirrored packets sent from an observing port always occupy queue 0.

Mirrored traffic occupies the forwarding bandwidth of the device. In the case of full-load traffic forwarding, enabling the mirroring function may cause packet loss due to insufficient forwarding capability.

Outbound mirroring has the following limitations:

- The mirrored outgoing packets may be different from the original packets. This is because the mirroring operation is performed before other forwarding operations on the original packets. For example, if the DSCP value of the original packets needs to be changed, the mirrored packets are different from the original packets because they have been mirrored to the observing port before the change.

- Outbound port mirroring is implemented through internal loopback interfaces. Enabling this function may degrade the forwarding performance of cards.

- When both port mirroring and traffic shaping are configured on an interface, mirroring is performed before traffic shaping. If some packets on the interface are discarded due to traffic shaping, the mirrored packets still contain the discarded packets.

One interface cannot function as both a mirrored port and an observing port.

The mirroring function consumes bandwidth resources of the device, degrading service processing performance and even affecting services. Therefore, disable this function if this function is no longer required. When using the flow mirroring function, reference an ACL to limit the range of traffic to be mirrored, so as to prevent the mirrored traffic from affecting other services.

If an MQC-based traffic policy is applied to the outbound direction, the traffic policy cannot match mirrored traffic.
