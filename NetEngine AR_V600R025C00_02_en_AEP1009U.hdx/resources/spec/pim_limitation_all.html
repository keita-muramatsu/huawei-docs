Feature Requirements

Table 2 Feature requirements

Feature

Feature Requirements

PIM SSM

MSDP is not required if PIM-SSM is used.

PIM SSM

In a multicast scenario with equal-cost links or primary and secondary links, PIM is enabled only for the link in use, but not enabled on the other links. After a link switchover occurs due to a configuration, route, or link change, multicast services will be interrupted, because PIM is not enabled on the newly selected link.

If multicast services are required, PIM must also be enabled on the optimal route of unequal-cost links.

It is recommended that you enable PIM in the view of the interface that lacks the configuration.

PIM SSM

Ensure that all the devices in the network have the same SSM group address range. Otherwise, network faults may occur.

PIM SSM

After the device is restarted, if the BFD session of the device or its neighbor is in the Admin Down state, the PIM status is not affected. If the BFD session is renegotiated, the PIM status is not affected.

PIM SM

The period during which a C-BSR retains the Bootstrap message received from the BSR must be longer than the interval at which the C-BSR sends Bootstrap messages. Otherwise, BSR election is frequently performed.

PIM SM

The period during which the BSR retains the Advertisement messages received from the C-RP must be longer than the interval at which the C-RP sends Advertisement messages.

PIM SM

The interval at which the device sends Hello messages must be shorter than the neighbor holdtime.

PIM SM

In a PIM-SM domain, MSDP and PIM cannot be used together to configure the same Anycast-RP. If Anycast-RP is implemented through PIM, you can configure the device to advertise the source information obtained from MSDP peers in another domain to peers in the local domain.

PIM SM

To enable a device to communicate with a device that supports auto-RP, enable auto-RP listening on the device. After auto-RP listening is enabled, the device can receive auto-RP announcement and discovery messages, parse the messages to obtain source addresses, and perform RPF checks based on the source addresses.

Currently, only IPv4 is supported.

PIM SM

1. The register-suppression-timeout and probe-interval commands must be configured on the source DR.

The source DR can randomly send Register messages within the range from (0.5 x register-suppression-timeout - probe-interval) to (1.5 x register-suppression-timeout - probe-interval), preventing a large number of Register messages from being sent to the CPU in a short period of time.

2. The source-lifetime parameter must be set on the RP.

It is recommended that the source-lifetime of the RP be greater than or equal to (3 x probe-interval + 1.5 x register-suppression-timeout).

PIM SM

For PIM IPv4 services, the RPT and SPT do not overlap. After an RPT-SPT switchover is complete, the device periodically sends a PIM Join-Prune message to the RP. The message carries a multicast source address that is not required to be received from the RP. When a multicast group has multiple multicast sources and the number of PIM Join-Prune messages exceeds the MTU of the upstream interface, some multicast sources are not added to the PIM Join-Prune messages. As a result, those multicast sources cannot be pruned, and the RP forwards the received packets to receivers. After receiving the traffic, the receiver discards the traffic because the RPF check fails.

PIM SM

If the PIM neighbor is lost and the relationship is not re-established, the alarm persists and needs to be manually cleared.

Run the display alarm active command in the diagnostic view to check the serial number of the alarm. Run the clear alarm active sequence-number command with the serial number of the alarm specified in the alarm view to clear the alarm.
