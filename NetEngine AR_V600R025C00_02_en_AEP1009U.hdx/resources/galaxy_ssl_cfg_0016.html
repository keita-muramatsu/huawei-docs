Configuring a DTLS Policy

Prerequisites

A certificate has been loaded to the PKI realm to be bound. The loaded certificate can be an initial device certificate or a digital certificate applied by a user. For details about how to load a certificate using PKI, see "PKI Configuration" in CLI Configuration Guide > Security.

Context

DTLS uses data encryption, identity authentication, and message integrity check mechanisms to ensure security of UDP-based application layer protocols. A DTLS policy can be applied to application layer protocols to provide secure connections.

Procedure

  1. Enter the system view.

    system-view

  2. Configure a DTLS policy and enter the DTLS policy view.

    dtls policy policyName

    By default, no DTLS policy is configured.

  3. (Optional) Configure the minimum path length of the digital certificate chain.

    ssl verify certificate-chain minimum-path-length path-length

    By default, the minimum path length of a digital certificate chain is 1.

  4. (Optional) Configure the digital certificate verification function.

    • Configure the enhanced key usage field for verifying the peer digital certificate.
      ssl verify key-usage enable
    • Configure the hash algorithm and signature algorithm for verifying the peer certificate.
      ssl verify certificate-signature-algorithm enable
    • Configure the basic constraint field for verifying the CA certificate sent by the peer end.
      ssl verify basic-constrain enable

    By default, the digital certificate verification function is disabled.

  5. (Optional) Configure the modulus of the Diffie-Hellman key exchange algorithm.

    diffie-hellman modulus modulus-val

    By default, the modulus of the Diffie-Hellman key exchange algorithm is 3072.

  6. (Optional) Configure signature algorithms.

    signature algorithm-list { ecdsa-secp256r1-sha256 | ecdsa-secp384r1-sha384 | ecdsa-secp521r1-sha512 | ed25519 | ed448 | rsa-pss-pss-sha256 | rsa-pss-pss-sha384 | rsa-pss-pss-sha512 | rsa-pss-rsae-sha256 | rsa-pss-rsae-sha384 | rsa-pss-rsae-sha512 | rsa-pkcs1-sha256 | rsa-pkcs1-sha384 | rsa-pkcs1-sha512 | ecdsa-sha1 | ecdsa-sha224 | rsa-sha1 | rsa-sha224 | dsa-sha1 | dsa-sha224 | dsa-sha256 | dsa-sha384 | dsa-sha512 } *

    By default, the following signature algorithms are configured: ed25519, ed448, ecdsa-secp256r1-sha256, ecdsa-secp384r1-sha384, ecdsa-secp521r1-sha512, rsa-pss-pss-sha256, rsa-pss-pss-sha384, rsa-pss-pss-sha512, rsa-pss-rsae-sha256, rsa-pss-rsae-sha384, and rsa-pss-rsae-sha512.

  7. Bind a PKI realm to the DTLS policy. After a PKI realm is bound, the DTLS policy uses the local certificates, CA certificates, and CRLs in the PKI realm.

    pki-domain pki-domain

    By default, no PKI realm is bound to a DTLS policy.

  8. (Optional) Bind a cipher suite to the DTLS policy.

    binding cipher-suite-customization customization-name

    By default, no cipher suite is bound to a DTLS policy. In this case, all encryption algorithms can be used.

    The cipher suite to be bound to the DTLS policy must have been configured. For details, see (Optional) Configuring a Cipher Suite for an SSL Policy.
