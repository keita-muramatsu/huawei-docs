DHCPv6 Options

The options field in a DHCPv6 message carries control information and parameters that are not defined in common protocols. When a DHCPv6 client requests an IPv6 address from a DHCPv6 server that has been configured to encapsulate the options field, the server returns a DHCPv6 message containing the options field. Table 2 Description of DHCPv6 options

option-code Value

Option Name

Function

1

Client Identifier

Carries a DUID that identifies a client, through which a DHCPv6 server identifies the client.

2

Server Identifier

Carries a DUID that identifies a server, through which a DHCPv6 client identifies the server.

3

Identity Association for Non-temporary Addresses (IA_NA)

Carries an IA_NA, the parameters associated with the IA_NA, and the non-temporary addresses associated with the IA_NA. The IA_NA option includes the IAID, T1, and T2 fields.

  • IAID: unique identifier for the IA_NA.

  • T1: time interval after which a client contacts the server from which the addresses in the IA_NA were obtained to extend the lifetimes of the addresses assigned to the IA_NA.

  • T2: time interval after which a client contacts any available server to extend the lifetimes of the addresses assigned to the IA_NA.

5

IA Address

Specifies an IPv6 address associated with an IA_NA.

This option must be encapsulated in the options field of an IA_NA option.

The IA Address option contains an IPv6 address and its preferred and valid lifetimes. Exercise caution when setting the valid lifetime of an address to 0xffffffff ("infinity"), which equals a permanent assignment of an address to a client.

6

Option Request

Identifies a list of options in a message between a client and a server.

A client may include an Option Request option in a Solicit, Request, Renew, Rebind, or Information-request message to inform the server about options the client wants the server to send to the client.

A server may include an Option Request option in a Reconfigure message to indicate which options the client should request from the server.

7

Preference

Carries the preference value for an Advertise message to control the selection of a server by the client.

9

Relay Message

Carries a DHCPv6 message in a Relay-forward or Relay-reply message.

12

Server Unicast

Allows a client to unicast messages to a server.

13

Status Code

Returns a status indication related to the DHCPv6 message or option in which it appears.

14

Rapid Commit

Signals the use of the two-message exchange for address assignment. A client may include this option in a Solicit message if the client is prepared to perform the Solicit/Reply message exchange.

A server must include this option in a Reply message sent in response to a Solicit message when completing the Solicit/Reply message exchange.

15

User Class

Carries user class information in a request message sent from a DHCPv6 client to a DHCPv6 server. It is a vendor-specific identifier and can carry the enterprise code, device name, and version number.

18

Interface-Id

May be sent by a DHCPv6 relay agent to identify the interface on which the client message was received. If the relay agent receives a Relay-reply message with an Interface-Id option, it relays the message to the client through the interface identified by the option.

The server must copy the Interface-Id option from the Relay-forward message into the Relay-reply message the server sends to the relay agent in response to the Relay-forward message.

Servers may use the Interface-Id option for parameter assignment policies. The Interface-Id value for an interface should be stable and remain unchanged. For example, if the Interface-Id value changes after the relay agent is restarted, a server will not be able to use it reliably in parameter assignment policies.

37

Remote-Id

May be sent by a DHCPv6 relay agent to carry information, such as the DUID, port identifier, and VLAN ID.

79

Client-lla

May be sent by a DHCPv6 relay agent to carry the client's link-layer address information.

68

VSS-Control

May be sent by a DHCPv6 relay agent to carry information about the VPN to which the client belongs.
