Configuring Users and Security Groups

Context

Users and security groups on the device reflect the organizational structure of an enterprise. You can reference policies based on users or security groups to implement user-based access control and permission management.

Procedure

  1. Enter the system view.

    system-view

  2. Create a security group.

    ucl-group name group-name [ index group-index ]

  3. Configure a local user.

    Local users in identity management refer to local access users in AAA. This section provides only the basic procedure for creating a local access user. For more configurations such as the user password policy, user access type, and user status, see CLI Configuration Guide > User Access and Authentication Configuration > AAA Configuration > Configuring a Local Access User.

    After the permissions (such as the password and access type) of a local access user are changed, the online users are not affected, and the latest configuration takes effect for new online users.

    For the configuration requirements of a specific authentication mode for local users, see the description of specific authentication modes in this section.

    1. Enter the AAA view.
      aaa
    2. Create a local user.
      local-access-user user-name

      By default, a user belongs to the default domain. To use another domain, add @domain name to the end of the user name to associate the user with the domain.

    3. Configure the password for the local access user.

      password cipher password
    4. Optional: Configure the security group to which the access user belongs.
      ucl-group name group-name
    5. Configure attributes and password policies for a local access user by referring to CLI Configuration Guide > User Access and Authentication Configuration > AAA Configuration > Configuring a Local Access User.

      By default, the functions of changing the password upon the first login (password alert original), changing the password upon password expiration (password expire), and locking a user upon consecutive login failures (local-aaa-user wrong-password) are enabled.
