ACL6 Configuration Guidelines

When configuring ACL6 rules, follow these guidelines:

  1. Some rules in an ACL6 may overlap, and matching stops for a packet once the packet matches a rule in an ACL6. To prevent a packet from matching a rule with loose conditions earlier than a rule with strict conditions in the same ACL6, ensure that rules with strict conditions are arranged above those with loose conditions.

  2. The ACL6 configuration guidelines vary according to the default ACL6 actions taken by service modules. Take a service module whose default action is permit as an example. If the module must deny packets from only some IPv6 addresses, you can configure a deny rule only for these IPv6 addresses. Because the default action is permit, you do not need to add a permit rule for other IPv6 addresses as the last rule in the ACL6. The opposite is true for a service module whose default action is deny. Table 1 describes the ACL6 configuration guidelines.

    The following rules are for reference only. The command line syntax shall prevail when you configure ACL6 rules.

    The rule permit and rule deny commands permit and deny packets, respectively. In Table 1, a and b indicate packet attributes, with b covering a wider range of packets than a.
