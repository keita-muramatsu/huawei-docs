Configuring an AP PKI Realm Profile

Prerequisites

Prepare a certification authority (CA) certificate, certificate revocation list (CRL) file, local certificate, and private key file, and upload them to the root directory of the flash memory on the WAC.

If multiple CA certificates are required, use the OpenSSL tool to combine them into one.

Context

A public key infrastructure (PKI) realm is a set of identity information required by a PKI entity to enroll a certificate. An AP PKI realm profile allows you to configure the CA certificate, local certificate, certificate revocation list (CRL) file, and private key file for APs. After the configuration is complete, the certificate files need to be delivered to the APs by using the load-file command.

A certificate may need to be revoked for the reasons such as entity name changing, private key leaking, or service termination. Revoking a certificate is to unbind the public key from PKI entity identity information. The PKI uses the CRL to revoke certificates.

After a certificate is revoked, the CA issues a CRL to declare that the certificate is invalid and lists the serial numbers of revoked certificates. The CRL provides a method to verify certificate validity.

The PKI system uses certificate authentication technology to verify the validity of access devices, improving system security. PKI certificates can be used for authentication when APs go online, access the web system, or be upgraded through the Huawei Online Upgrade Repository (HOUP). By default, an AP provides three PKI realms named default, defaultPki_houp, and user-define. Initial certificates are configured in the default and defaultPki_houp realms to support the authentication scenarios listed in Table 1. There is no default configuration in the user-define realm, which can be used for other authentication scenarios. In addition, you can define two default AP PKI realms for other authentication functions.
Table 1 PKI realms in AP certificate authentication scenarios

Certificate Usage Scenario

AP PKI Realm

DTLS authentication during AP onboarding

default, containing the initial certificate

Device authentication for accessing the web system

default, containing the initial certificate

Device authentication for accessing the HOUP for smart upgrade

defaultPki_houp, where the CA certificate is Actalis_CA.cer

An AP PKI realm profile on the WAC allows you to configure an AP PKI realm and the CA certificate, local certificate, CRL file, and private key file in the PKI realm to uniformly manage and maintain certificates on APs.

A maximum of five PKI realms can be configured in an AP PKI realm profile, and a maximum of three PKI realms support the private key configuration (specified by the parameter private-key). One private key must be reserved in both the default and defaultPki_houp realms, and the remaining private key can be configured in the user-define realm or a user-defined realm. To check the configuration of an AP PKI realm profile, run the display ap-pki-profile command. If automatic AP certificate renewal is configured, a default private key is automatically created for the PKI realm used to renew the AP certificate. The private key also occupies the remaining quota of the private key. However, information about the private key is not displayed in the display ap-pki-profile command output.

When APs can access the CA server that supports the CMPv2 or SCEP protocol, you can configure the automatic certificate renewal function for the APs. Then the APs can automatically obtain the local certificate and private key file from the CA server. This reduces the workload of maintenance personnel and reduces the risk of delayed certificate renewal.

An AP PKI realm profile defines information used for automatic certificate renewal, including the PKI entity common name, CA server information, automatic renewal time, and authentication code. After the configuration is complete on the WAC, APs automatically obtain and replace certificates based on the certificate status in each PKI realm and information in the corresponding profile.

  • If a certificate exists in the PKI realm of an AP, the AP continuously checks whether the automatic renewal time is reached. When the automatic renewal time is reached, the AP automatically sends a certificate renewal request to the CA server to replace the certificate.
  • If no certificate is available in the PKI realm of an AP, the AP applies for a certificate from the CA server and periodically replaces the certificate based on the automatic renewal time.

The initial certificate exists in the AP PKI realm default. After the certificate is automatically renewed, related functions may be abnormal. Therefore, you are not advised to enable the automatic certificate renewal function in the default realm.

When an AP applies for a local certificate for the first time, the CA certificate in the default realm is used. Therefore, you need to configure the CA certificate in the AP PKI realm default before configuring automatic certificate renewal for the AP.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Create an AP PKI realm profile and enter its view.

    ap-pki-profile name profile-name

    By default, no AP PKI realm profile is created on the device.

  4. Configure a name for the AP PKI realm and bind the CA certificate, local certificate, and private key file to the realm.

    pki realm realm-name { { ca format { der | pkcs12 | pem } ca-file-name } | { local format { der | pkcs12 | pem } local-file-name [ private-key format { der | pkcs12 | pem } private-key-file-name password password ] } } *

    By default, the name of an AP PKI realm is not configured on the device, and an AP PKI realm is not bound with any CA certificate, local certificate, or private key file.

  5. Configure a name for the AP PKI realm and import a CRL file to the realm.

    pki realm realm-name crl-filename crl-filename

    By default, the name of an AP PKI realm is not configured on the device, and no CRL file is configured to be imported to the AP PKI realm.

  6. Configure an AP PKI realm name. Configure the parameters for automatic certificate renewal, including the PKI entity common name, CA server URL and name, percentage of the certificate's validity period for automatic renewal, and reference and secret values of the message authentication code.

    pki realm real-name auto-enroll { common-name name | url url ca-id id | percent percent message-authentication-code reference-value secret-value } *

    By default, no AP PKI realm name is configured, and no parameters for automatic certificate renewal are configured. The parameters include the PKI entity common name, CA server URL and name, percentage of the certificate's validity period for automatic renewal, and reference and secret values of the message authentication code.

  7. (Optional) Configure automatic certificate renewal for APs.
    1. Configure the protocol used to automatically renew AP certificates.

      pki realm realm-name auto-enroll type { cmpv2 | scep }

      By default, the CMPv2 protocol is used to automatically renew AP certificates.

    2. Configure the digital CA certificate fingerprint used in CA certificate authentication.

      pki realm realm-name auto-enroll fingerprint { md5 | sha1 | sha256 } fingerprint

      By default, no digital CA certificate fingerprint used in CA certificate authentication is configured.

    3. Configure the RSA or ECC key pair and modulus used in SCEP certificate request.

      pki realm realm-name auto-enroll { rsa local-key-pair rsa-modulus-size | ecc local-key-pair ecc-hostkey-length }

      By default, no key pair used in SCEP certificate request is configured.

    4. Configure the challenge password used in SCEP certificate request, which is also used to revoke a certificate.

      pki realm realm-name auto-enroll password password

      By default, no challenge password used in SCEP certificate request is configured.

    5. Configure the percentage threshold for the validity period of SCEP certificate renewal.

      pki realm realm-name auto-enroll percent percent

      The default value of percent is 100, indicating that the system automatically requests a new certificate when the existing one is about to expire.

  8. Return to the WLAN view.

    quit

  9. Enter the AP view or AP group view.
    • Enter the AP group view.
      ap-group name group-name
    • Enter the AP view.
      ap-id ap-id
  10. Bind the AP PKI realm profile to the AP group or a single AP.

    ap-pki-profile profile-name

    By default, no AP PKI realm profile is bound to an AP group or AP.

  11. Return to the WLAN view.

    quit

  12. Manually deliver the certificate file to APs.

    load-file { ap-id ap-id | ap-group group-name | all }

    By default, manual loading of certificate files to APs is not configured.

Verifying the Configuration

  • Run the display ap-pki-profile { all | name profile-name } command to check the configuration of an AP PKI realm profile.
  • Run the display references ap-pki-profile name profile-name command to check reference information about an AP PKI realm profile.
  • Run the display ap pki status [ ap-id ap-id ] command to check the status of an AP PKI realm and certificates.
  • Run the display ap file status all [ succeed | fail ] or display ap file status { ap-id ap-id | ap-mac ap-mac } command to check certificate loading information on APs.
  • Run the display ap pki certificate ap-id ap-id { ca | local } realm realm-name command to check information about the CA and local certificates in a specified AP PKI realm.
