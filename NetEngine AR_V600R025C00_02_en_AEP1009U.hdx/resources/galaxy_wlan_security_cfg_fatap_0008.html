WAPI

WLAN Authentication and Privacy Infrastructure (WAPI) is a Chinese national standard for WLANs, which was developed based on IEEE 802.11. WAPI provides higher security than WEP and WPA, and consists of the following parts:

  • WLAN Authentication Infrastructure (WAI): authenticates user identities and manages keys on WLANs.
  • WLAN Privacy Infrastructure (WPI): protects data transmitted on WLANs and provides the data encryption, data verification, and anti-replay functions.

WAPI uses the elliptic curve cryptography (ECC) algorithm based on the public key cryptography and the block key algorithm based on the symmetric-key cryptography. The ECC algorithm is used for digital certificate authentication and key negotiation between wireless devices. The block key algorithm is used to encrypt and decrypt data transmitted between wireless devices. The two algorithms implement identity authentication, link authentication, access control, and user information encryption.

WAPI has the following advantages:

  • Bidirectional identity authentication

    This mechanism prevents access from unauthorized STAs and protects a WLAN against attacks from unauthorized WLAN devices.

  • Digital certificates as identity credentials

    A WAPI system has an independent certificate server. STAs and WLAN devices use digital certificates to prove their identities, improving network security. When a STA requests to join or leave a network, the administrator only needs to issue a certificate to the STA or revoke the certificate of the STA.

  • Well-developed authentication protocol

    WAPI uses digital certificates to identify STAs. During identity authentication, the Elliptic Curve Digital Signature Algorithm (ECDSA) is used to verify digital certificates. In addition, the secure message hash algorithm is used to ensure message integrity, preventing attackers from tampering with or forging information transmitted during identity authentication.

Identity Authentication

WAPI provides two identity authentication modes: certificate-based mode (WAPI-CERT) and PSK-based mode (WAPI-PSK).

  • WAPI-CERT: A STA and a WAC authenticate each other based on their certificates. The certificates must be loaded on the STA and WAC and verified by an authentication service unit (ASU). After certificate authentication is complete, the STA and WAC use the temporal public key and private key to generate a base key (BK) for key negotiation.

    The WAPI-CERT mode is applicable to large-scale enterprise networks or carrier networks that can deploy and maintain an expensive certificate system.

    Figure 2 WAPI-CERT authentication flowchart

    As shown in Figure 2, the WAPI-CERT authentication process is as follows:

    1. Authentication activation: When a STA associates or re-associates with a WAC and the WAC determines that the STA is a WAPI user, the WAC sends an authentication activation packet to the STA to start the authentication process.
    2. Access authentication request: The STA sends an access authentication request carrying the STA certificate and current system time to the WAC. The system time is called the access authentication request time.
    3. Certificate authentication request: After receiving the access authentication request from the STA, the WAC records the access authentication request time and sends a certificate authentication request to the ASU. The certificate authentication request contains the STA certificate, access authentication request time, WAC certificate, and signature generated using the private key of the WAC.
    4. Certificate authentication response: After receiving the certificate authentication request from the WAC, the ASU verifies the WAC signature and STA certificate validity. If the WAC signature or STA certificate is invalid, the authentication fails. If they are valid, the ASU authenticates the STA's certificate. After the authentication process is complete, the ASU constructs a certificate authentication response with the STA certificate authentication result, WAC certificate authentication result, and signature signed by the ASU, and then sends the response to the WAC.
    5. Access authentication response: The WAC verifies the signature of the certificate authentication response returned by the ASU, obtains the STA certificate authentication result, and performs access control on the STA based on the result. The WAC sends the received certificate authentication response to the STA. After verifying the signature of the ASU, the STA obtains the authentication result of the WAC certificate and determines whether to connect to the WLAN based on the authentication result. If the authentication succeeds, the WAC allows the STA to access the network. If the authentication fails, the WAC disassociates the STA from the network.

  • WAPI-PSK: The STA and WAC authenticate each other based on the PSK. Before authentication, the STA and WAC must be configured with the same PSK. The PSK is converted into a BK during authentication.

    The WAPI-PSK mode does not require an expensive certificate system, so it is applicable to individual users or small-scale enterprise networks.

Key Negotiation

After the WAC is authenticated by the ASU, the WAC initiates key negotiation with the STA. Key negotiation consists of unicast key negotiation and group key negotiation.

  • Unicast key negotiation

    The STA and WAC use the unicast encryption key and unicast integrity key obtained during unicast key negotiation to ensure security of unicast data exchanged between them. During unicast key negotiation, the STA and WAC use the KD-HMAC-SHA256 algorithm to calculate a unicast session key (USK) based on the BK. During unicast key negotiation, the STA and WAC negotiate not only the encryption key for unicast data, but also the protection key and authentication key for the group key used in the session.

    Figure 3 WAPI unicast key negotiation

    As shown in Figure 3, the unicast key negotiation process is as follows:

    1. Unicast key negotiation request

      After a valid BK association is established, the WAC sends a unicast key negotiation request packet to the STA to negotiate a unicast key with the STA.

    2. Unicast key negotiation response

      After receiving the unicast key negotiation request packet from the WAC, the STA performs the following operations:

      1. Checks whether this negotiation process is triggered to update the unicast key.
        • If so, the STA proceeds to step b.
        • If not, the STA proceeds to step c.

        WAPI allows a STA to directly send a unicast key negotiation response packet to the WAC to initiate unicast key update.

      2. Checks whether the WAC challenge is the same as the locally saved challenge used in the last unicast key negotiation. If not, the STA discards the packet.
      3. The STA generates a random challenge, and uses the BK, WAC challenge, STA challenge, and key derivation algorithm KD-HMAC-SHA256 to generate a unicast session key and the WAC challenge for the next unicast key negotiation.
      4. Uses the message authentication key and HMAC-SHA256 algorithm to calculate a local message authentication code (MAC), constructs a unicast key negotiation response packet, and sends the packet to the WAC.

    3. Unicast key negotiation ACK

      After receiving the unicast key negotiation response packet, the WAC performs the following operations:

      1. Checks whether the WAC challenge is correct. If not, the WAC discards the packet.
      2. Uses the BK, WAC challenge, STA challenge, and key derivation algorithm KD-HMAC-SHA256 to generate a unicast session key and the WAC challenge for the next unicast session key negotiation, uses the message authentication key and HMAC-SHA256 algorithm to calculate the local MAC, and compares the local MAC with that in the packet. If not, the WAC discards the packet.
      3. Checks the WAPI information element in the response packet if this is the first unicast key negotiation after the BK is generated. If the network type is BSS, the WAC checks whether the WAPI information element in the response packet is the same as that in the association request packet it received before. If not, the WAC sends a Deauthentication frame to disassociate the STA. If the network type is IBSS (ad-hoc network), the WAC checks whether the unicast key algorithm supports the information element in the response packet. If not, the WAC sends a Deauthentication frame to disassociate the STA.
      4. Uses the message authentication key and HMAC-SHA256 algorithm to calculate the local MAC, constructs a unicast key negotiation ACK packet, and sends the packet to the STA.

  • Group key negotiation

    Group key negotiation is based on unicast key negotiation. The WAC group key is advertised.

    The WAC uses the group encryption key and group integrity check key that are advertised by itself and derived from the group master key (GMK) to ensure security of broadcast/multicast data to be sent, the STA uses the group encryption key and multicast integrity check key (derived from the GMK) advertised by the WAC to decrypt the received broadcast/multicast data.

    Figure 4 WAPI group key negotiation

    As shown in Figure 4, the group key negotiation process is as follows:

    1. Group key advertisement

      After unicast key negotiation succeeds, the WAC uses the random number algorithm to generate a GMK, encrypts the GMK using the negotiated unicast key, and sends an advertisement packet to notify the STA of the GMK.

    2. Group key response

      After receiving the group key advertisement packet, the STA performs the following steps:

      1. Calculates the checksum using the message authentication key identified by the unicast key identifier, and compares the checksum with the MAC field. If they are different, the STA discards the packet.
      2. Checks whether the key advertisement identifier is increasing. If not, the STA discards the packet.
      3. Decrypts the key data to obtain the 16-byte master key and uses the KD-HMAC-SHA256 algorithm to extend it to 32 bytes. The first 16 bytes indicate the encryption key, and the last 16 bytes indicate the integrity key.
      4. Saves the key advertisement identifier, generates a group key response packet, and sends the packet to the WAC.
      5. After receiving the group key response packet, the WAC performs the following steps:
        1. Calculates the checksum using the message authentication key identified by the unicast key identifier, and compares the checksum with the MAC field. If they are different, the WAC discards the packet.
        2. Compares fields (such as key advertisement identifier) in the group key response packet with corresponding fields in the group key advertisement packet it has sent. If all the fields are the same, the group key negotiation is successful. Otherwise, the WAC discards the packet.

Key update mode

WAPI defines a dynamic key negotiation mechanism, but there are still security risks if a STA uses the same encryption key for a long time. WAPI provides a time-based key update mechanism.
