Configuring Basic Functions of Security Policies

Procedure

  1. Enter the system view.

    system-view

  2. Optional: Enable the mandatory condition verification function of a security policy.

    security-policy required-object check enable

    When the mandatory condition verification function of a security policy is disabled, the validity of the policy rules is not affected by whether the source IP address, destination IP address, and service matching conditions are configured.

    After the mandatory condition verification function of a security policy is enabled:

    • The configured security policy rules are not affected.
    • If any one of the source IP address, destination IP address, and service is not configured, a newly configured security policy does not take effect. However, if the three conditions are all set to any, the policy stills take effect.

  3. Enter the security policy view.

    security-policy

  4. Optional: Configure the action of the default security policy.

    default action { permit | deny }

    The matching condition of the default security policy is any and the default action is permit. If the traffic does not match any security policy defined by the administrator, the traffic will match the default security policy.

  5. Optional: Configure the default security policy to control traffic in the same security zone.

    default packet-filter intrazone enable

    By default, if traffic in the same security zone does not match any security policy defined by the administrator, the traffic is not affected by the default security policy and is allowed to pass through. To avoid security risks caused by this default setting, configure the default security policy to control traffic in the same security zone.

  6. Create a security policy rule and enter the security policy rule view.

    • Manually create a security policy. The policy name can be customized.
      rule name rule-name

    In commands, security policies exist by means of rules; therefore, security policy rules and security policies mean the same.

  7. Optional: Configure the description of the security policy rule.

    description description

    The description helps an administrator correctly understand functions of a security policy rule, facilitating query and maintenance.

  8. Define the matching conditions of the security policy rule.

    Run...

    Configure a source security zone

    source-zone { zone-name &<1-6> | any }

    Configure a destination security zone

    destination-zone { zone-name &<1-6> | any }

    Configure the source address/region/domain group
    • source-address address-set address-set-name &<1-6>
    • source-address { ipv4-address { ipv4-mask-length | mask mask-address | wildcard wildcard } | ipv6-address ipv6-prefix-length | range { ipv4-start-address ipv4-end-address | ipv6-start-address ipv6-end-address } | any }
    • source-address geo-location geo-location-name
    • source-address domain-set domain-set-name &<1-6>
    • source-address-exclude address-set address-set-name &<1-6>
    • source-address-exclude { ipv4-address { ipv4-mask-length | mask mask-address | wildcard wildcard } | ipv6-address ipv6-prefix-length | range { ipv4-start-address ipv4-end-address | ipv6-start-address ipv6-end-address } }
    • source-address none

    You can directly configure an address or reference an existing address object, address group, region, or domain group.

    If the source address condition is set to none, the rule does not take effect.

    When the mandatory condition verification function of a security policy is enabled (by running the security-policy required-object check enable command), a new rule does not take effect if any one of the source address, destination address, and service is not configured or is set to none. For a created rule, after any condition (source address, destination address, or service) is deleted, the specific condition is set to none. As a result, the rule becomes invalid.

    NOTE:

    Do not reference only empty address objects, address groups, regions, or domain groups. Otherwise, the matching condition cannot be matched.

    Configure the destination address/region/domain group
    • destination-address address-set address-set-name &<1-6>
    • destination-address { ipv4-address { ipv4-mask-length | mask mask-address | wildcard wildcard } | ipv6-address ipv6-prefix-length | range { ipv4-start-address ipv4-end-address | ipv6-start-address ipv6-end-address } | any }
    • destination-address geo-location geo-location-name
    • destination-address domain-set domain-set-name &<1-6>
    • destination-address-exclude address-set address-set-name &<1-6>
    • destination-address-exclude { ipv4-address { ipv4-mask-length | mask mask-address | wildcard wildcard } | ipv6-address ipv6-prefix-length | range { ipv4-start-address ipv4-end-address | ipv6-start-address ipv6-end-address } }

    You can directly configure an address or reference an existing address object, address group, region, or domain group.

    If the destination address condition is set to none, the rule does not take effect.

    When the mandatory condition verification function of a security policy is enabled (by running the security-policy required-object check enable command), a new rule does not take effect if any one of the source address, destination address, and service is not configured or is set to none. For a created rule, after any condition (source address, destination address, or service) is deleted, the specific condition is set to none. As a result, the rule becomes invalid.

    NOTE:

    Do not reference only empty address objects, address groups, regions, or domain groups. Otherwise, the matching condition cannot be matched.

    Configure a security group or a user

    user { ucl-group ucl-group-name | username username }

    A locally created security group or user can be referenced. In this case, you need to create a security group or user before referencing it in a security policy rule.

    NOTE:

    Currently, only the AR5700 and AR6700 series devices support this function.

    Configure an application

    application { any | app app-name | app-group app-group-name }

    If the policy has application identification configured, the performance of the device may be affected. Configure applications as required.

    NOTE:

    If applications are configured in security policy rules, run the sa enable command in the interface view to enable application identification for traffic. Otherwise, the device cannot identify applications in the traffic. As a result, the security policy rules with applications configured cannot be matched.

    Configure a service
    • service protocol { udp | tcp } [ source-port { source-port | start-source-port to end-source-port } &<1-64> | destination-port { destination-port | start-destination-port to end-destination-port } &<1-64> ] *
    • service protocol sctp

    • service protocol icmp [ icmp-type { icmp-name | icmp-type-number { icmp-code-number [ to icmp-code-number ] } &<1-64> } ]

    • service protocol icmpv6 [ icmpv6-type { icmpv6-name | icmpv6-type-number { icmpv6-code-number [ to icmpv6-code-number ] } &<1-64> } ]

    • service protocol protocol-number

    • service-exclude protocol { udp | tcp } [ source-port { source-port | start-source-port to end-source-port } &<1-64> | destination-port { destination-port | start-destination-port to end-destination-port } &<1-64> ] *
    • service-exclude protocol sctp

    • service-exclude protocol icmp [ icmp-type { icmp-name | icmp-type-number { icmp-code-number [ to icmp-code-number ] } &<1-64> } ]

    • service-exclude protocol icmpv6 [ icmpv6-type { icmpv6-name | icmpv6-type-number { icmpv6-code-number [ to icmpv6-code-number ] } &<1-64> } ]

    • service-exclude protocol protocol-number

    • service any
    • service none

    You can configure the protocol and port number.

    If the service condition is set to none, the rule does not take effect.

    When the mandatory condition verification function of a security policy is enabled (by running the security-policy required-object check enable command), a new rule does not take effect if any one of the source address, destination address, and service is not configured or is set to none. For a created rule, after any condition (source address, destination address, or service) is deleted, the specific condition is set to none. As a result, the rule becomes invalid.

    Configure the time range during which the security policy rule takes effect

    time-range time-range

    -

  9. Specify an action for the security policy rule.

    action { permit | deny }

  10. Configure the security policy rule to reference a content security profile.

    profile { av | ips | url-filter } profile-name
    • Integrated content security check affects the performance of the device. Therefore, configure this function as required.
    • The profile takes effect only when the action of the security policy rule is permit.
    • When you perform the creation, modification, or deletion operation on the content security profile, you need to run the engine configuration commit command in the system view for the profile configuration and the security policy that references the profile to take effect.

Verifying the Configuration

  • Run the display this command in the security policy view to check the configuration of the security policy.
  • Run the display security-policy rule all command in any view to check the configuration and matching status of the security policy.
