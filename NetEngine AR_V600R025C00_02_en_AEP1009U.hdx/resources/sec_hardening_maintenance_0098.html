Defense Against ARP Spoofing Attacks

Overview

ARP spoofing involves an attacker sending forged ARP messages to create incorrect ARP entries on gateways or hosts, resulting in forwarding errors for user or network packets. A network may be attacked using the following methods:

  • Forged ARP messages are sent by an attacker spoofing as an authorized user to a gateway, causing the gateway to learn incorrect user ARP entries.

  • Forged ARP messages are sent by spoofing as a valid gateway, causing users to learn incorrect gateway ARP entries.

  • Malformed ARP messages are sent by an attacker spoofing as an authorized user to a device, causing the device to learn incorrect ARP entries.

To defend against the preceding attacks, configure the following security hardening policies on a device:

  • Fixed ARP

    Devices support three fixed ARP modes: fixed-mac, fixed-all, and send-ack. These three modes are applicable to different scenarios and are mutually exclusive.

    • The fixed-mac mode applies to networks where user MAC addresses do not change but user access locations do. When the access interface of a user changes, the device promptly updates interface information in the user's ARP entry.
    • The fixed-all mode applies to networks where both user MAC addresses and user access locations do not change.
    • The send-ack mode applies to networks where both user MAC addresses and user access locations change.

  • ARP gateway anti-collision

    To defend against attacks from bogus gateways, enable ARP gateway anti-collision on the device functioning as a gateway if user hosts directly connect to the gateway. A device considers an ARP gateway collision to have occurred if it receives an ARP message meeting either of the following conditions:

    • The source IP address of the ARP message is the same as the IP address of the inbound interface.
    • The source IP address of the ARP message is the virtual IP address of the inbound interface, but the source MAC address is not the VRRP virtual MAC address.

    The device generates an ARP anti-collision entry and discards the received ARP messages with the same source MAC address and VLAN ID as those of the ARP message within a specified period of time. This function prevents ARP messages with a bogus gateway address from being broadcast in a VLAN.

  • Gratuitous ARP message sending

    Gratuitous ARP message sending can be enabled on a device that functions as a gateway. The device then periodically sends gratuitous ARP messages to update the ARP entries for authorized users, ensuring that the ARP entries contain the correct MAC address of the gateway.

  • MAC address consistency check in an ARP message

    After receiving an ARP message, a device checks whether the source and destination MAC addresses in the Ethernet frame header match those in the ARP message. If the source and destination MAC addresses in an ARP message are different from those in the Ethernet frame header, the device considers the message as an attack and discards it. If the source and destination MAC addresses in an ARP message are the same as those in the Ethernet frame header, the device performs ARP learning. Checking the consistency of MAC addresses in ARP messages helps protect the network and devices against malformed ARP message attacks.

  • Strict ARP learning

    Once strict ARP learning is enabled, the device learns ARP entries only for ARP reply messages in response to ARP request messages sent by itself. In this way, the device can defend against most ARP attacks.

Impact on the System

None

Procedure

  • Configure fixed ARP.

    Enable fixed ARP in fixed-mac mode.

    <HUAWEI> system-view
[HUAWEI] arp anti-attack entry-check fixed-mac enable  //This command can be run globally or on an interface as required.

  • Configure ARP gateway anti-collision.

    Enable ARP gateway anti-collision.

    <HUAWEI> system-view
[HUAWEI] arp anti-attack gateway-duplicate enable

  • Configure gratuitous ARP message sending.

    Enable gratuitous ARP message sending on VLANIF 10.

    <HUAWEI> system-view
[HUAWEI] interface vlanif 10
[HUAWEI-Vlanif10] arp gratuitous-arp send enable  //This command can be run globally or on an interface as required.
[HUAWEI-Vlanif10] quit

  • Configure MAC address consistency check in an ARP message.

    Enable MAC address consistency check in an ARP message on a specified interface.
    <HUAWEI> system-view
[HUAWEI] interface 10ge 0/0/1
[HUAWEI-10GE] arp validate source-mac destination-mac
[HUAWEI-10GE] quit

  • Configure strict ARP learning.

    Enable strict ARP learning on a specified interface.
    <HUAWEI> system-view
[HUAWEI] interface vlanif 10
[HUAWEI-Vlanif10] arp learning strict force-enable  //This command can be run globally or on an interface as required.
[HUAWEI-Vlanif10] quit

Verifying the Security Hardening Result

  • Run the display arp statistics [ interface { interface-name | interface-type interface-number } ] command to check ARP entry statistics.
  • Run the display arp anti-attack gateway-duplicate item command to check ARP gateway anti-collision entries.
  • Run the display arp packet statistics [ interface [ interface-name | interface-type interface-number ] ] command to check statistics about ARP messages sent and received by the device.
  • Run the display arp learning strict command to check the configuration of strict ARP learning on all interfaces.
