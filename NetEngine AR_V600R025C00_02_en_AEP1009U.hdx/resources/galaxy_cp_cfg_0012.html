Example for Configuring the Device to Obtain CPU-Forwarded Packets

Networking Requirements

In Figure 1, DeviceA connects to the Internet through interface 1. When some services whose packets need to be forwarded by the CPU on DeviceA are not running as normal, the network administrator needs to obtain CPU-forwarded packets originated from 192.168.1.2 and destined for 192.168.2.1 on interface 1 and save the obtained packets to the capture.cap file. In this way, the network administrator can process invalid packets promptly to ensure stable running of services.

Figure 1 Network diagram for obtaining CPU-forwarded packets

In this example, interface 1 represents 10GE 0/0/1.


Procedure

  1. Configure DeviceA to obtain CPU-forwarded packets on 10GE 0/0/1 and save the obtained packets to the capture.cap file.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] acl 3000
[DeviceA-acl4-advance-3000] rule permit ip source 192.168.1.2 24 destination 192.168.2.1 24
[DeviceA-acl4-advance-3000] quit
[DeviceA] quit
<DeviceA> capture-packet soft-forward acl 3000 interface 10ge 0/0/1 inbound destination file capture.cap

Verifying the Configuration

# Run the display capture-packet file flash:/logfile/capture.cap command on DeviceA to view the content of the capture.cap file.

<DeviceA> display capture-packet file flash:/logfile/capture.cap
a1 b2 c3 d4 00 02 00 04 00 00 00 00 00 00 00 00
00 00 ff ff 00 00 00 09 4d 10 36 db 00 0a d5 81
00 00 00 0c 00 00 00 0c ff 03 c0 21 09 9d 00 08
8a 8c bc c3 4d 10 36 db 00 0a d6 ae

Configuration Scripts

DeviceA

#
sysname DeviceA
#
acl 3000
   rule permit ip source 192.168.1.2 0.0.0.255 destination 192.168.2.1 0.0.0.255
#
return
