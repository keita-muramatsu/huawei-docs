Configuring Certificate Validity Check

Prerequisites

  • Certificate validity check takes effect only for RSA-based digital signature certificate authentication.
  • Certificate validity check takes effect only for the following IPsec types:
    • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
    • Route-based IPsec (involving IPsec profiles)

Context

In some scenarios, tunnel negotiation may fail because the certificate on the remote device is unavailable or the local device cannot validate the remote certificate.

The device can use the Online Certificate Status Protocol (OCSP) verification result or Certificate Revocation List (CRL) sent by the remote end to validate the remote certificate. To ensure that an invalid certificate can still be used for tunnel negotiation, the device can have certificate validity check disabled.

Procedure

  • Configure the local end to use the OCSP verification result sent by the remote end to validate the remote certificate.

    When IPsec uses RSA signature authentication for IKEv2 negotiation and uses OCSP for certificate validity check, if the OCSP server is located in the private network of the headquarters, a branch cannot directly communicate with the OCSP server to validate the certificate at the headquarters. You can configure the local end to use IKEv2 to obtain the OCSP verification result from the headquarters to validate the certificate at the headquarters. If the OCSP verification result is valid, the certificate is valid and identity authentication is successful. An IPsec tunnel can then be established between the branch and headquarters through negotiation.

    1. Enter the system view.

      system-view

    2. Enter the IKE peer view.

      ike peer peer-name

    3. Configure the local end to use the OCSP verification result sent by the remote end to validate the remote certificate.

      inband ocsp

      By default, the local end is not configured to use the OCSP verification result sent by the remote end to validate the remote certificate.

  • Configure the local end to use the CRL sent by the remote end to verify the validity of the remote certificate.

    When IPsec uses RSA signature authentication for IKEv2 negotiation and the CRL is used for certificate validity check, if the CA server is located in the private network of the headquarters, a branch cannot directly communicate with the CA server to obtain the latest CRL to validate the certificate at the headquarters. You can configure the local end to use IKEv2 to obtain the CRL from the headquarters to validate the certificate at the headquarters. If the certificate is not in the CRL, the certificate is valid and identity authentication is successful. An IPsec tunnel can then be established between the branch and headquarters through negotiation.

    1. Enter the system view.

      system-view

    2. Enter the IKE peer view.

      ike peer peer-name

    3. Configure the local end to use the CRL sent by the remote end to validate the remote certificate.

      inband crl

      By default, the local end is not configured to use the CRL sent by the remote end to validate the remote certificate.

  • Disable certificate validity check.

    Security risks exist if certificate validity check is not performed.

    When IPsec uses RSA signature authentication for IKE negotiation, the remote device cannot update its certificate if the certificate becomes invalid. As a result, the certificate becomes unavailable and IPsec authentication fails. If the remote device wants to continue to use an invalid certificate, you need to disable certificate validity check. Certificate validity check can be configured globally in the public system or configured for a specific IKE peer.

    Disable certificate validity check globally.

    1. Enter the system view.

      system-view

    2. Disable certificate validity check globally.

      ike certificate-check disable

      By default, the device validates all IKE peers' certificates.

    Disable certificate validity check for a single IKE peer.

    1. Enter the system view.

      system-view

    2. Enter the IKE peer view.

      ike peer peer-name

    3. Disable certificate validity check for the IKE peer.

      certificate-check disable

      By default, the device validates an IKE peer's certificate.
