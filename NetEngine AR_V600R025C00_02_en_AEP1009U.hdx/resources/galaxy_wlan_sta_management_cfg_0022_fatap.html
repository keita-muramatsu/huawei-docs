Configuring Strict STA IP Address Learning Through DHCP

Prerequisites

Before configuring strict STA IP address learning through DHCPv6, enable IP source guard (IPSG).

Context

To prevent STAs with bogus IP addresses from associating with an AP, you can enable strict STA IP address learning through DHCP. Then the following situations may occur when a STA associates with an AP:

  • If the STA dynamically obtains an IP address through DHCP, the AP automatically reports the STA's IP address to the WAC so that the IP and MAC address binding of the STA is correctly maintained.
  • If the STA uses a static IP address and the function of blacklisting STAs with bogus IP addresses is enabled, the STA is added to the dynamic blacklist of the AP. Before the blacklist entry of the STA ages out, the STA cannot associate with the AP. If the function of blacklisting STAs with bogus IP addresses is disabled, the STA is allowed to associate with the AP, but the AP does not learn the STA's IP address.

After strict STA IP address learning through DHCP is enabled, it is recommended that IPSG and dynamic ARP inspection (DAI) be enabled to prevent STAs from communicating with the network before they obtain IP addresses through DHCP.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Create a VAP profile view and enter its view.

    vap-profile name profile-name

  4. Enable STA IP address learning.

    undo learn-client-address { ipv4 | ipv6 } disable

    By default, STA IP address learning is enabled.

  5. Enable strict STA IP address learning through DHCP.

    • If STAs obtain IPv4 addresses, enable strict STA IPv4 address learning through DHCP.
      learn-client-address dhcp-strict [ blacklist enable ]

      By default, strict STA IPv4 address learning through DHCP is disabled.

    • If STAs obtain IPv6 addresses, enable strict STA IPv6 address learning.
      learn-client-address { dhcpv6-strict | dhcpv6-slaac } [ blacklist enable ]

      By default, strict STA IPv6 address learning is disabled.

    For a STA using a static IP address:
    • If blacklist enable is specified, the STA will be added to the dynamic blacklist on the AP and cannot associate with the AP until the blacklist entry ages out.
    • If blacklist enable is not specified, the STA is allowed to associate with the AP, but the AP does not learn the STA's IP address. In this case, you need to enable the IPSG function to block services of STAs with bogus IP addresses.

    • If strict STA IP address learning through DHCP is disabled, users can manually configure static IP addresses for STAs. However, if a STA obtains an IP address dynamically through DHCP, goes online, and then is configured with a static IP address, the administrator cannot detect the IP address change of this STA.

    • After strict STA IP address learning through DHCP is enabled, if the WAC has learned IP addresses through DHCP or static binding, STAs with bogus IP addresses will not be added to the blacklist. In this case, you need to enable the IPSG function to block services of STAs with bogus IP addresses.

    • After strict STA IP address learning through DHCP is enabled, you are advised to run the ip source check user-bind enable and arp anti-attack check user-bind enable commands to enable IPSG and DAI so that STAs cannot communicate with the network before obtaining IP addresses through DHCP.

    • Blacklisted users are forbidden to associate with APs for 2 minutes after they go online.

Verifying the Configuration

Run the display station dynamic-blacklist ap-id ap-id command to check the dynamic blacklist on an AP.
