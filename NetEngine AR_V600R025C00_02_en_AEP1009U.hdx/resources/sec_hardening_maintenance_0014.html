Login Through STelnet

Overview

Attack Methods

  • Brute force cracking

    After obtaining an SSH port number, an attacker attempts to access a device using the SSH port. When the device requests authentication information, the attacker may crack the password, pass the authentication, and obtain the access permission.

  • DoS attack

    An SSH server supports only a limited number of users. If the number of login users reaches a specified upper limit, subsequent users cannot access the server. This situation may occur when the server is attacked.

Security Hardening Policy

  • Authentication

    The SSH server supports password authentication and public-key authentication. Only authenticated users can log in to a device and enter the CLI.

  • Disabling services

    When the SSH service is enabled, the socket service is also automatically enabled. This means that the device is prone to scanning by attackers. To prevent such a risk, disable the SSH service and its port when the SSH service is not required.

  • Changing the port number

    By default, the SSH server uses port 22, which is a well-known port number and is prone to scanning and attacks. You can modify the SSH server port number to an unknown port number, reducing the probability of being scanned.

  • Configuring a security channel

    By default, each VTY supports login through Telnet and STelnet. You can configure each VTY channel to support only STelnet channels in the user interface view.

  • ACL

    ACLs can be configured for VTY user interfaces to control the login of clients with a specified IP address or in a specified IP address segment.

Impact on the System

None

Procedure

  • Configure password or Rivest-Shamir-Adelman (RSA) authentication.

    • Password authentication: Set the authentication mode of a user named testuser to password authentication.

      1. Enter the system view.
        system-view
      2. Create an SSH user.
        ssh user testuser
      3. Configure an authentication mode for the SSH user.
        ssh user testuser authentication-type password

    • RSA authentication: Set the authentication mode of a user named testuser to RSA authentication (using keys each of 3072 bits or more).

      1. Enter the system view.
        system-view
      2. Create an SSH user.
        ssh user testuser
      3. Configure an authentication mode for the SSH user.
        ssh user testuser authentication-type rsa
  • Disable the SSH service. The SSH service is disabled by default.
    1. Enter the system view.
      system-view
    2. Disable the SSH service.
      undo stelnet server enable
  • Specify the source interface for a user to log in to the SSH server.
    1. Enter the system view.
      system-view
    2. Configure the source interface on the SSH server.
      ssh server-source -i { interface-type interface-number | interface-name }
  • Specify the source IPv6 address for a user to log in to the SSH server.
    1. Enter the system view.
      system-view
    2. Configure a source IPv6 address for the SSH server.
      ssh ipv6 server-source -a ipv6-address [ -vpn-instance vpn-instance-name ]
  • Change the SSH server port to 53555.
    1. Enter the system view.
      system-view
    2. Set the port number to 53555.
      ssh server port 53555
  • Configure a security channel.
    1. Enter the system view.
      system-view
    2. Enter the VTY user interface view.
      user-interface vty first-ui-number [ last-ui-number ]
    3. Configure AAA authentication for the channel.
      authentication-mode aaa
    4. Configure an STelnet channel.
      protocol inbound ssh
  • Configure ACL-based access control.
    1. Enter the system view.
      system-view
    2. Create a numbered basic ACL and enter the basic ACL view.
      acl [ number ] acl-number
    3. Configure an ACL rule.
      rule [ rule-id ] [ name <rule-name> ] { permit | deny } [ fragment-type fragment | source { source-ip-address { source-wildcard | 0 | src-netmask } | any } | time-range time-name | [ vpn-instance vpn-instance-name | vpn-instance-public ] ] *
    4. Exit the ACL view.
      quit
    5. Enter the VTY user interface view.
      user-interface vty first-ui-number [ last-ui-number ]

      All VTY user interfaces involved in SSH login must be covered in the user-interface vty first-ui-number [ last-ui-number ] command.

    6. Configure ACL-based access control.
      acl { acl4name | acl4num } { inbound | outbound }
acl ipv6 { acl6name | acl6num } { inbound | outbound }

      To prevent users from using a specified IP address or an IP address in a specified network segment to access a device, specify inbound.

      To prevent users who have already logged in to a device from logging in to other devices, specify outbound.

Verifying the Security Hardening Result

  • Run the display current-configuration configuration aaa command to check the AAA configuration.
  • Run the display ssh server status command to check the current connection information of the SSH server.
