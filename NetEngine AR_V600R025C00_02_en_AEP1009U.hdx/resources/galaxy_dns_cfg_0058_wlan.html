Example for Configuring a Device as an IPv4 DNS Relay Agent

Networking Requirements

In Figure 1, a user host needs to use a domain name to access the network, and the domain name needs to be resolved by the DNS server (with the IPv4 address 10.1.1.2). Configure DeviceA as a DNS relay agent. In this way, the user host is unaware of the change of the DNS server address, reducing maintenance costs.

Figure 1 Network diagram of configuring a DNS relay agent

Procedure

  1. Configure DNS relay.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] dns relay enable
[DeviceA] dns resolve
[DeviceA] dns server 10.1.1.2

  2. Configure an IPv4 address for the DNS relay agent to communicate with a user host. The IPv4 address 10.1.1.1 is an address on DeviceA, and there are reachable routes between this address and the DNS server and between this address and the user host.

    [DeviceA] dns server bind local-ip 10.1.1.1

  3. On a user host, set the IPv4 address of the DNS server to 10.1.1.1 (IPv4 address of the DNS relay agent).

Verifying the Configuration

# Run the display current-configuration command on DeviceA to check the DNS relay configuration.

[DeviceA] display current-configuration | include dns 
 dns resolve                                                                    
 dns server 10.1.1.2                                                            
 dns relay enable
 dns server bind local-ip 10.1.1.1
