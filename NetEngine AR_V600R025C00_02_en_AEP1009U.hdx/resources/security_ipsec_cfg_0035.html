Configuring a Tunnel Interface and Applying an IPsec Profile

Prerequisites

An IPsec proposal has been configured.

Context

A tunnel interface is a Layer 3 logical interface that supports GRE, mGRE, and IPsec protocols. Devices can use these interfaces to provide IPsec protection. An IPsec profile can be applied to a tunnel interface only after the interface's encapsulation mode has been configured.

Based on IKE negotiation, you can configure a tunnel interface and apply an IPsec profile to the interface to establish an IPsec tunnel on the interface. This provides IPsec protection for all the data flows routed to the interface. An IPsec tunnel interface can have an IP address manually configured or dynamically request an IP address through IKEv2 negotiation. Dynamically requesting an IP address reduces the configuration and maintenance workload of branch devices when many branches connect to the headquarters.

In an IPsec profile, you do not need to use ACLs to define data flows. This is because all the data flows routed to an IPsec tunnel interface will be protected. For details, see 8. After an IPsec profile is applied to an IPsec tunnel interface, only one IPsec tunnel will be created. This tunnel will protect all the data flows routed to the tunnel interface, simplifying IPsec policy management.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the tunnel interface view.

    interface tunnel interface-number

  3. Set the encapsulation mode for the tunnel interface.

    tunnel-protocol { gre [ p2mp ] | ipsec }

    An IPsec profile can be applied to a tunnel interface only if the interface's encapsulation mode is set to IPsec, GRE, or mGRE.
    • If the encapsulation mode is set to IPsec, the tunnel interface is used to establish an IPsec tunnel to secure unicast data transmitted on the Internet.
    • If the encapsulation mode is set to GRE, the tunnel interface is used to implement GRE over IPsec and can transmit both unicast and multicast data. The tunnel interface first adds a GRE header to packets, and then adds an IPsec header to the GRE-encapsulated packets so that the packets can be securely and reliably transmitted.
    • If the encapsulation mode is set to mGRE (by specifying p2mp after gre), the tunnel interface is used to implement DSVPN. For detailed configurations, see CLI Configuration Guide > VPN Configuration > DSVPN Configuration.

  4. Configure a private IP address for the tunnel interface.

    ip address ip-address { mask | mask-length } [ sub ]

  5. Configure a source IP address or source interface for the tunnel interface.

    source { [ vpn-instance vpn-instance-name ] source-ip | interface-type interface-number  }

    The vpn-instance vpn-instance-name parameter is available only when the encapsulation mode of a tunnel interface is set to IPsec or mGRE.

    The source tunnel interface must be a Layer 3 interface. If the source address of a tunnel interface is an IP address dynamically obtained by another interface, you are advised to specify the source interface using the source command to prevent the change of the dynamic IP address from affecting IPsec configuration.

  6. Optional: Configure a destination IP address for the tunnel interface.

    destination destination-ip

    If the encapsulation mode of the tunnel interface is set to IPsec, you do not need to configure the destination IP address on both ends. The configuration on one end is enough. When no destination address is configured for an IPsec tunnel interface, the remote address of the IKE peer referenced in an IPsec profile can be used to initiate negotiation. When no destination address is configured for an IPsec tunnel interface and no remote address is configured for the IKE peer, the local end can only accept the negotiation request initiated by the remote end. If the encapsulation mode of the tunnel interface is set to GRE, you need to configure the destination IP address on both ends.

  7. Apply the IPsec profile to the tunnel interface.

    ipsec profile profile-name [ shared ]

    By default, no IPsec profile is applied to a tunnel interface.

    One tunnel interface can have only one IPsec profile applied. If the shared parameter is not specified, an IPsec profile can be applied to only one tunnel interface. If the shared parameter is specified, an IPsec profile can be applied to a maximum of 64 tunnel interfaces.

    The shared parameter can be configured only on mGRE tunnel interfaces. If multiple mGRE tunnel interfaces use the same outbound interface, apply the same IPsec profile to and specify the shared parameter for all these tunnel interfaces. Otherwise, the two ends cannot establish an IPsec tunnel.

  8. Return to the system view, and configure routes to divert the data flows to be encrypted to the IPsec tunnel interface.

    quit
ip route-static ip-address { mask | mask-length } interface-type interface-number

    Routes can be configured to direct the data flows to be protected to the tunnel interface to which an IPsec profile is applied so that all the packets routed to the tunnel interface will be protected by IPsec. interface-type interface-number specifies the tunnel interface used to establish an IPsec tunnel.
