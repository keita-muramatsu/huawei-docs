Intrusion Prevention Profile

The core of the intrusion prevention function is an intrusion prevention profile, which can be used to determine the attacks to be defended against and how to defend against the attacks.

Elements of an Intrusion Prevention Profile

Signature Filter

An intrusion prevention signature database contains a large number of signatures for various attacks. However, in the actual network environment, service types may be centralized, and not all signatures are required. If the device defends against all signatures, a large number of logs will be generated, affecting processing of key attack events and device commissioning. In this case, you need to configure a signature filter to filter out the signatures that need to be concerned and configure the attack response action. The device defends against only the filtered signatures.

A signature filter is a set of conditions for filtering signatures, such as the threat type, target, protocol, severity, and operating system of a signature. The device defends against only the signatures that meet all the filtering conditions. Multiple values can be configured for a filtering condition and these values are ORed. That is, a signature matches a condition as long as the signature matches any value of this condition.

In most cases, the default actions for signatures are used for the filtered signatures in the signature filter. You can also set actions for all signatures in the filter. The action of a signature filter has a higher priority than the default actions of signatures in the filter.

Signature filters configured earlier have higher priorities. If multiple signature filters in one security profile contain the same signature, packets matching the signature are processed according to the signature filter configured earlier.

Exception Signature

A unified action is configured for signatures in a signature filter and you are not allowed to modify the action for a single signature, which cannot fulfill the requirements in some exceptions. To address this issue, the device provides the exception signature function, enabling you to specify a specific signature as an exception signature in an intrusion prevention profile and set an action for the signature. If a log indicates that an application running properly matches a signature in the signature filter and is incorrectly blocked, you can specify the signature as an exception signature and set the action to allow.

The action set for an exception signature can be block, alert, allow, or blacklist. blacklist means adding the source or destination address of related packets to the blacklist when traffic is blocked.

The action for an exception signature has a higher priority than that for a signature filter. If a signature matches both an exception signature and a signature filter, the action for the exception signature prevails.

Determining the Final Response Action for a Signature

In an intrusion prevention profile, multiple signature filters and exception signatures can be configured, which together determine the final response action for a signature. The action for an exception signature, action for a signature filter, and the default action for a signature are listed in descending order of priority.

In Figure 2, two signature filters and an exception signature are configured in an intrusion prevention profile. The final response actions for signatures a01, a02, and a03 are as follows:

  • a01: When multiple signature filters are configured in an intrusion prevention profile, the signature filters are listed in descending order of priority. The signature matches the signature filters based on the descending order of priority. Once a signature filter is matched, the matching process stops. Therefore, in Figure 2, a01 matches only signature filter 1 and the action for a01 is alert.
  • a02: The priority of the exception signature is higher than that of signature filter 1. Therefore, the action for a02 is alert.
  • a03: The signature matches signature filter 2 and the action for a03 is block. The action for the signature filter takes precedence over the default action for the signature.
Figure 2 Response action for a signature

When a packet matches multiple signatures, the actual action for the packet is as follows:

  • If the actions for all the matched signatures are alert, the action for the packet is alert.

  • If the action for any matched signature is block, the action for the packet is block.

Applying an Intrusion Prevention Profile

The intrusion prevention function takes effect only after an intrusion prevention profile is referenced in a security policy. That is, the device performs intrusion prevention on the traffic that matches the security policy.

If a security policy references an intrusion prevention profile, the direction in the security policy is determined by the node that initiates the access, not the node that sends attack packets. For example, to protect intranet PCs against malicious attacks when accessing external servers, the intrusion prevention profile must be applied to the security policy for accessing the external network from intranet, which is consistent with the direction in which access is initiated, even though the attack is initiated from the external network to intranet.
