Configuring NAT Server

Procedure

  1. Enter the system view.

    system-view

  2. Enter the view of the inbound interface of packets.

    interface interface-type interface-number

  3. Change the interface working mode to Layer 3.

    undo portswitch

    Determine whether to perform this step based on the current interface working mode.

  4. Enable the NAT function on the interface.

    nat enable

  5. Return to the system view.

    quit

  6. Configure NAT Server.

    • Configure the same public IP address or WAN interface for all security zones so that all users can request access to an intranet server by sending request packets to the same public IP address or WAN interface.

      Whether a Protocol Type Is Specified

      Command

      Description

      No protocol type is specified.

      nat server name global interface { interface-name | interface-type interface-num } inside host-address host-port [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ nat-disable ] [ description description ]

      nat server name [ vpn-instance vpn-instance-name1 ] global global-address [ global-address-end ] inside host-address [ host-address-end ] [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ route ] [ description description ]

      The intranet server provides services to Internet users through a specified public IP address or the public IP address of a specified WAN interface.

      A protocol type is specified.

      nat server name protocol protocol-type global interface { interface-name | interface-type interface-num } global-port [ global-port-end ] inside host-address host-port [ host-port-end ] [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ nat-disable ] [ description description ]

      nat server name [ vpn-instance vpn-instance-name1 ] protocol protocol-type global global-address [ global-address-end ] global-port [ global-port-end ] inside host-address [ host-address-end ] host-port [ host-port-end ] [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ route ] [ description description ]

      After a protocol type is specified, the device performs port translation only for port numbers used to forward packets of the specified protocol. This ensures that NAT security is improved, but packet forwarding of the protocols that use unfixed ports may be impacted. To minimize these impacts, configure NAT ALG.
    • Configure a different public IP address or WAN interface for each security zone so that users in different security zones can request access to an intranet server by sending request packets to different public IP addresses or WAN interfaces.

      Whether a Protocol Type Is Specified

      Command

      Description

      No protocol type is specified.

      nat server name zone zone-name global interface { interface-name | interface-type interface-num } inside host-address [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ nat-disable ] [ description description ]

      nat server name [ vpn-instance vpn-instance-name1 ] zone zone-name global global-address [ global-address-end ] inside host-address [ host-address-end ] [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ route ] [ description description ]

      In scenarios where an intranet server provides services to Internet users through multiple public IP addresses or WAN interfaces, if the interfaces with these public IP addresses or the WAN interfaces reside in different security zones, you can configure NAT Server to advertise a different public IP address or WAN interface for each security zone.

      If the interfaces with these IP addresses or the WAN interfaces reside in the same security zone, you can configure NAT Server with no-reverse specified. When the no-reverse parameter is specified, you can configure mappings between multiple public IP addresses specified by global and one private IP address specified by inside. In this case, however, the intranet server cannot access the Internet proactively. To rectify this, you can configure a source NAT policy between the security zone of the intranet server and that of the Internet to translate the private IP address of the intranet server into a public IP address. The source NAT policy can reference an address specified by global or another public IP address.

      A protocol type is specified.

      nat server name zone zone-name protocol protocol-type global interface { interface-name | interface-type interface-num } global-port [ global-port-end ] inside host-address host-port [ host-port-end ] [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ nat-disable ] [ description description ]

      nat server name [ vpn-instance vpn-instance-name1 ] zone zone-name protocol protocol-type global global-address [ global-address-end ] global-port [ global-port-end ] inside host-address [ host-address-end ] host-port [ host-port-end ] [ no-reverse ] [ vpn-instance vpn-instance-name2 ] [ route ] [ description description ]
    • If the public address configured in NAT Server and the WAN interface address are on different network segments, a blackhole route is required.
    • If the public address configured in NAT Server and the WAN interface address are on the same network segment, a blackhole route is recommended.
    • If the public address configured in NAT Server is consistent with the WAN interface address, a routing loop will not occur. In this case, a blackhole route is not required.

    If the nat server command has been configured but no open programming route (OPR) is specified, you only need to run the nat server name name route command without the need to change the existing configuration. This command satisfies the requirements of flexible OPR configuration. This OPR has the same functions as a blackhole route.

  7. Configure a route to the Internet on the intranet server or configure the IP address of the interface connecting DeviceA to the intranet server as the default gateway address. This allows the intranet server to send packets to DeviceA by default, after which DeviceA forwards them to Internet users.

Verifying the Configuration

Run the display nat server command to check the NAT Server information.

Follow-up Procedure

After a range of contiguous public IP addresses are assigned to a private server, the device can dynamically modify the mappings of NAT Server to assign some of the public IP addresses to other private servers.

For example, an NAT Server command is configured to map private server IP addresses 192.168.0.1–192.168.0.100 to public IP addresses 192.0.2.1–192.0.2.100 in one-to-one mode.

nat server nat1 global 192.0.2.1 192.0.2.100 inside 192.168.0.1 192.168.0.100

Due to network topology changes, public IP addresses 192.0.2.10–192.0.2.11 need to be mapped to other private server IP addresses 192.168.1.10–192.168.1.11 in one-to-one mode. To implement this, add two independent NAT Server commands.

nat server nat2 global 192.0.2.10 inside 192.168.1.10
nat server nat3 global 192.0.2.11 inside 192.168.1.11

After the configuration is complete, the device automatically adjusts the IP address mappings. During NAT, the device preferentially matches a single mapped IP address and then the mapped IP address range.

Note the following when using the preceding functions:

  • Mappings can be dynamically adjusted only when one-to-one mappings are configured between public and private IP addresses without port numbers specified. The mappings with port translation cannot be dynamically adjusted.
  • A single IP address in NAT Server can replace a mapping of NAT Server with a large IP address range. However, a small IP address range in NAT Server cannot replace some mappings of NAT Server with a large IP address range. For example, if the mappings of the public IP addresses 192.0.2.10–192.0.2.11 in nat1 are changed, you need to configure two single IP address mappings nat2 and nat3, and cannot just configure the nat server nat4 global 192.0.2.10 192.0.2.11 inside 192.168.0.10 192.168.0.11 command.
  • During NAT matching, for the same public or private IP addresses, the priority of single-IP NAT Server is higher than that of IP-range NAT Server, regardless of the configuration sequence.
  • NAT Server with the same private server IP addresses can be configured. That is, after nat1 is configured, 192.168.0.3 in the private server IP addresses can be mapped to a new public IP address 192.0.2.105.
  • A public IP address can be mapped to another private server IP address in an IP-range NAT Server. For example, in nat1, 192.0.2.11 can be mapped to a new IP address 192.168.0.21. After the adjustment, no public IP address is available for the original private server IP address 192.168.0.11 mapped from 192.0.2.11. Therefore, you can use public IP addresses 192.0.2.11 and 192.0.2.21 to access the server at 192.168.0.21, but the server can access the external network through only public IP address 192.0.2.11.
  • After single-IP NAT Server mapping is disabled (using the nat server name name nat-disable command), the device automatically restores the server mapping entries of the IP addresses in the original IP-range NAT Server. After single-IP NAT Server mapping is restored (using the undo nat server name name nat-disable command), the device deletes the server mapping entries of the IP addresses in the original IP-range NAT Server.
