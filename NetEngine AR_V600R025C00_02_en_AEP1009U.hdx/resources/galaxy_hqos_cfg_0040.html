(Optional) Configuring Intelligent Traffic Policing

Context

During peak hours, the available bandwidth fluctuates within a certain range, which may affect the experience of high-priority applications. In this case, you can configure intelligent traffic policing to preferentially guarantee the bandwidth of high-priority service traffic. You need to create an intelligent traffic policing policy, configure the bandwidth threshold for enabling intelligent traffic policing, and apply the policy to the traffic behavior of the parent traffic policy. In this way, the bandwidth of high-priority service traffic is preferentially guaranteed, and the remaining bandwidth is allocated to low-priority service traffic.

Intelligent traffic policing is under license control. For details, see Configuration Precautions for HQoS.

Procedure

  1. Enter the system view.

    system-view

  2. Configure an intelligent traffic policing policy.
    1. Create an intelligent traffic policing policy and enter the intelligent traffic policing view.

      itp policy policy-name

      By default, no intelligent traffic policing policy is created.

    2. Configure the bandwidth threshold for enabling the intelligent traffic policing algorithm.

      bandwidth-threshold { bandwidth | pct percentage }

      By default, the threshold is not configured.

    3. (Optional) Configure the bandwidth detection period.

      detection-period period-value

      By default, the bandwidth detection period is 5 seconds.

    4. (Optional) Configure the lower bandwidth threshold for low-priority services.

      service-lower-threshold { bandwidth | pct percentage }

      By default, the threshold in percentage is 10%.

    5. (Optional) Configure the additive detection bandwidth.

      up-bandwidth bandwidth-value

      By default, the additive detection bandwidth is 1000 kbit/s.

    6. (Optional) Configure the bandwidth suppression period of low-priority services.

      suppression-period period-value

      By default, the bandwidth suppression period is 60 seconds.

    7. Exit the intelligent traffic policing view.

      quit

  3. Apply the intelligent traffic policing policy to the traffic behavior of the parent traffic policy.

    For details, see Configuring Parent and Child Traffic Policies.

Verifying the Configuration

  • Run the display itp adjustment-history interface { interface-name | interface-type interface-number } command to check the dynamic rate limiting adjustment history of an intelligent traffic policing policy.
  • Run the display itp statistics interface { interface-name | interface-type interface-number } command to check statistics about the traffic rate of an interface, CAR of the parent traffic policy, and CAR of the child traffic policy for high-priority services during each detection, and the number of lost packets for CAR of the child traffic policy for high-priority services and CAR of the child traffic policy for low-priority services.
