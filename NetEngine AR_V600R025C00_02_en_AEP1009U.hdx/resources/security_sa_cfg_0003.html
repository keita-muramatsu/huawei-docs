Understanding Application Identification

Application Identification Technologies

Application identification technologies have traditionally used protocols and port numbers as a way to identify applications. However, as applications become more complex, these technologies cannot meet refined control requirements. To address this issue, service awareness (SA) is introduced. Currently, SA application identification technologies are mainly classified into the following types:

  • Signature identification: This is the most basic technology for SA application identification. It identifies applications by parsing the application signatures carried in packets. Different applications typically use different protocols, and each protocol has its own signatures. These signatures may be specific ports, character strings, or bit sequences. In addition to parsing the traditional 5-tuple information of packets, signature identification also parses the application-layer information of packets for greater accuracy.

    Some application protocol signatures are spread over multiple packets rather than only a single packet. In such cases, you need to collect and analyze the signatures of multiple packets to identify applications.

  • Correlation identification: This technology is mainly used to identify applications based on multi-channel protocols, which are used by more and more applications to transmit voice, video, and files. These protocols, such as FTP and SIP, use separate control and data channels. Specifically, they use control channels to negotiate communication parameters (such as port information) for establishing data channels, and use data channels to transmit service data.

    Correlation identification is dependent on signature identification, which is used to identify the applications carried by control channel packets. In addition, the data channel information is extracted from control channel packets and recorded in an application identification association table. Subsequently, data channel packets are identified according to the association table and marked as the corresponding applications. In this way, applications can be identified from multi-channel protocol packets.

  • Behavior identification: This is more complex than the preceding two technologies. It is mainly used to identify the applications of encrypted traffic. Signature identification fails to identify the pattern signatures of encrypted data because they are obscured. Additionally, the encryption of some applications starts from the first packet, meaning that these applications cannot be distinguished based on the correlation between control and data channels. As such, behavior identification requires more extensive information to assist identification. Usually, this is achieved by analyzing the number of connections for a single IP address, proportion of upstream and downstream traffic, packet sending frequency, packet length change rules, and more.

    Huawei SA uses heuristic identification to accurately identify protocols such as encrypted BT, encrypted eDonkey/eMule, and encrypted Thunder based on the multi-dimensional signatures and correlations of data traffic.

Different identification technologies apply to different types of protocols and cannot replace each other. Typically, devices use multiple technologies to identify applications based on non-encrypted protocols (such as HTTP/FTP) or encrypted protocols (such as HTTPS/SFTP), achieving optimal identification.

Service Awareness Signature Database and Predefined Applications

Because different applications have different signatures, obtaining the unique signatures of application protocols is the key for devices to accurately identify various applications. Huawei periodically analyzes the signatures of common applications on networks and stores the signatures in a service awareness signature database. After being loaded on a device, a service awareness signature database exists as a predefined application. It can be referenced by other signatures as a matching condition, but cannot be modified or deleted.

Due to the rapid development of application software, Huawei continuously updates application signatures. By periodically updating a service awareness signature database to the latest version, you can ensure that devices are fully capable of identifying applications in traffic.

User-defined Application

The built-in service awareness signature database is typically sufficient for identifying various common applications. For those that are not included in the predefined applications, you can create such applications based on their signatures.

Currently, a device allows you to create rules for a user-defined application based on the 5-tuple (source IP address, destination IP address, protocol type, source port number, and destination port number), keyword (signature of data packets or flows of the application), or 5-tuple+keyword. The signature can uniquely identify the application.

If the source IP address, destination IP address, protocol type, source port number, and destination port number are fixed, you can create rules based on the 5-tuple; otherwise, create rules based on the keyword. If application traffic has the same 5-tuple but different signatures, you can create rules based on 5-tuple+keyword.

The device extracts information about the multi-tuple or specified fields from a service packet and matches the information with the rules created for the user-defined application. If the matching is successful, the application information of the packet is obtained.

The priority of a user-defined application is higher than that of a predefined application.

Domain name-based user-defined applications are identified by associating application identification with the DNS function to generate entries that associate DNS with applications. A user-defined application rule describes the mapping between domain names and applications, and a DNS reply packet contains the mapping between domain names and IP addresses. These two types of mappings enable a device to obtain the mapping between applications and IP addresses in order to establish DNS association entries. The device can then search for DNS association entries based on the destination IP address carried in application protocol packets in order to identify the corresponding application.

Usage of Application Identification in Features

An application is only a signature of service traffic and must be referenced by other features to implement traffic management and control. After a feature references an application, service flows enter the application identification process for matching application signatures. The matched service flows are processed based on the action configured in the feature. Currently, the following features can reference applications:
  • Modular QoS Command-Line Interface (MQC) traffic classification
  • Smart policy routing (SPR)

Applications use one or more protocols to establish connections. Those that use only one protocol are called single-protocol applications. For example, FTPPro uses only the FTP protocol. Those that use multiple protocols are called multi-protocol applications. For example, Google Play uses HTTP, HTTPS, QUIC and other protocols as well as many services in the Google family (such as Google API and Google service). An application may use one or more protocols to establish one or more connections based on requirements or protocol standards. To permit an application, you need to configure related applications accordingly.
