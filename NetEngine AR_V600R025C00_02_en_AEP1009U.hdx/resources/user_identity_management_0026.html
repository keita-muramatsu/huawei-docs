Configuring TSM SSO Parameters

Context

After the device is connected to the TSM SSO server, enable TSM SSO and configure optional functions.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the identity management view.

    identity-management

  3. Enter the TSM SSO view.

    sso-tsm

  4. Enable TSM SSO.

    tsm-sso enable

  5. Optional: Configure the aging time of online users.

    online-user aging-time aging-time

    Each device parses TSM SSO messages, brings the user online, and creates an online user entry. Within the aging time, the device updates the online user table based on the actual situation to save space resources for the online user table.

    • If a device does not receive user service traffic or TSM SSO messages, the entry corresponding to the user is deleted.
    • If a device receives user service traffic, the device updates the aging time of the online user entry (default value: 1440 minutes).

  6. Optional: Configure IPv6 address prefix parsing.

    ipv6prefix length

    You can run this command when the device needs to parse the IPv6 address prefixes in the packets sent from the TSM SSO server to the device based on the configured IPv6 address prefix length. The parsed IPv6 address prefixes are used as users' IPv6 addresses so that users on an IPv6 address range can go online.

  7. Configure the TSM online user synchronization function.

    1. Enable online user information synchronization.
      server-sync enable

      After this function is enabled, the device proactively sends online user synchronization requests to the TSM SSO server to synchronize online user information.

    2. Synchronize the IP address range of users.
      sync-address address-set address-set-name

      Generally, the IP address range configured in the Terminal IP address list is used when the device is added to the TSM SSO server as the online behavior management device. A maximum of six address set objects can be configured. Address groups cannot be configured.

    3. Optional: Configure the synchronization rate.
      sync-rate rate

      However, if the rate is set to a small value, users go online slowly, and user experience is affected. Therefore, exercise caution when setting the rate. Generally, retain the default value.

    4. Optional: Configure the query interval for the same IP address.
      ip-sync-interval interval

      After configuring the IP address range for online user synchronization on the TSM SSO server, you can run this command to set the query interval for each IP address. This prevents the device from querying numerous invalid IP addresses (IP addresses that do not go online on the TSM SSO server) from the TSM SSO server, which deteriorates the TSM SSO performance of the server.

    5. Optional: Set the maximum number of IP addresses contained in each query packet.
      ip-sync-num number
quit

      You can run this command to effectively control the number of IP addresses in each query packet and adjust the rate at which the TSM SSO server receives online user synchronization query messages from the device, preventing slow query or message queue congestion on the server.

  8. Optional: Configure the security group priority.

    security-group priority-type { local-first | server-first }

    The user login information received by the device contains the security group to which the user belongs on the server. If the information conflicts with the local security group to which the user belongs, you can run this command to control the device to obtain the priority of the security group to which the user belongs. By default, the device preferentially uses the information on the server.

    • local-first: The device preferentially uses the local security group to which the user belongs. If no security group is found, the device uses the security group to which the user belongs on the server.
    • server-first: The device preferentially searches for the security group to which the user belongs on the server. If not found, the device continues to search for the local security group to which the user belongs.

    For example, in the server-first mode, user A on the device belongs to security group A, and user A on the server belongs to security group B. When a user passes authentication and goes online on the device, the user belongs to security group B. However, if the user does not belong to any security group on the server, the device still uses security group A as the security group to which the user belongs.

  9. Optional: Configure the user escape function.

    temporary-access username user-name ucl-group group-name

    If the communication between the device and TSM SSO server is abnormal and the device cannot obtain the mapping between users and IP addresses, you can enable the user escape function to temporarily use the permissions of the security group named ucl-group. When traffic of a user passes through the device and the device cannot find the user name corresponding to the user's IP address in the online user table, the device uses the configured temporary user name and security group to bring the user online.

    When the communication recovers and the device can properly obtain the mapping between users and IP addresses, the device updates the user names and security groups in the online user table. The device performs permission control based on the new user names and security groups.

    In this step, group-name must be specified as the name of an existing security group on the device, while user-name can be directly specified.

    If a local user (local-access-user) whose name is the same as the value of user-name exists on the device, the device uses the security group to which the user corresponding to the value of user-name belongs during the escape and does not query the security group to which the local user belongs.

  10. Optional: Configure user login and logout logs.

    undo userlog login-out enable

    When the TSM SSO function is enabled and there are too many users, you are advised to run this command to disable user login and logout logs to prevent device performance deterioration.
