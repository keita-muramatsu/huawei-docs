Configuring an IPsec Proposal

Context

An IPsec proposal, as a part of an IPsec policy or IPsec profile, defines security parameters for IPsec SA negotiation, including the security protocol, encryption and authentication algorithms, and data encapsulation mode. Devices on both ends of an IPsec tunnel need to have the same security parameters configured.

Procedure

  1. Enter the system view.

    system-view

  2. Create an IPsec proposal and enter the IPsec proposal view.

    ipsec proposal proposal-name

  3. Configure an IPsec security protocol.

    transform { ah | esp | ah-esp }

    By default, IPsec uses ESP as the security protocol.

  4. Configure data encryption and authentication algorithms for the IPsec security protocol.

    • When IPsec uses AH, you can configure only the authentication algorithm used by AH, because AH supports only authentication, not encryption.
    • When IPsec uses ESP, you can configure the encryption and authentication algorithms for ESP as required because ESP supports both authentication and encryption.
    • If IPsec uses both AH and ESP, you can configure the authentication algorithm used by AH and the encryption and authentication algorithms used by ESP. In this case, devices first encapsulate an ESP header and then an AH header to packets.

    1. Configure the data authentication algorithm for AH.

      ah authentication-algorithm { md5 | sha1 | sha2-256 | sha2-384 | sha2-512 | sm3 }*

      By default, AH uses the SHA2-256 authentication algorithm.

      SM3 can meet the high confidentiality and security requirements, but it takes a comparatively long time for processing. For general security requirements, authentication algorithms SHA2-256, SHA2-384, and SHA2-512 are recommended, and authentication algorithms MD5 and SHA1 are not recommended.

    2. Configure the data encryption algorithm for ESP.

      esp encryption-algorithm { des | 3des | aes-128 | aes-192 | aes-256 | aes-128-gcm-128 | aes-192-gcm-128 | aes-256-gcm-128 | aes-128-gmac | aes-192-gmac | aes-256-gmac | sm4 }*

      By default, ESP uses the AES-256-GCM-128 encryption algorithm.

      SM4 can meet high confidentiality and security requirements, but it takes a relatively long processing time. For general security requirements, encryption algorithms AES-256-GCM-128, AES-192-GCM-128, AES-128-GCM-128, AES-256-GMAC, AES-192-GMAC, and AES-128-GMAC are recommended, and encryption algorithms 3DES, DES, and AES in CBC mode are not recommended.

    3. Configure the data authentication algorithm for ESP.

      esp authentication-algorithm { md5 | sha1 | sha2-256 | sha2-384 | sha2-512 | sm3 }*

      By default, ESP uses the SHA2-256 authentication algorithm.

      SM3 can meet the high confidentiality and security requirements, but it takes a comparatively long time for processing. For general security requirements, authentication algorithms SHA2-256, SHA2-384, and SHA2-512 are recommended, and authentication algorithms MD5 and SHA1 are not recommended.

  5. Configure the data encapsulation mode for the IPsec security protocol.

    encapsulation-mode { transport | tunnel | auto }

    By default, an IPsec security protocol uses the tunnel mode.

    auto indicates that the data encapsulation mode is auto-sensing mode. In auto-sensing mode, the device uses the tunnel mode if it serves as the IKE initiator. If it serves as the responder, it can use either the tunnel or transport mode.

    • When configuring an IPsec policy on both ends of an IPsec tunnel, ensure that the referenced proposals use the same packet encapsulation mode.
    • If route-based IPsec is configured, the encapsulation mode of an IPsec security protocol can only be set to tunnel mode in the IPsec proposal referenced by the tunnel interface whose encapsulation protocol is IPsec.
    • When IKEv2 is used, the encapsulation modes in all the IPsec proposals configured on the IKE initiator must be the same; otherwise, IKE negotiation fails.
    • The modified encapsulation mode applies only to new tunnels; it does not affect established tunnels because the existing SAs are not reset.

Verifying the Configuration

Run the display ipsec proposal [ brief | name proposal-name ] [ slot slot-id cpu cpu-id ] command in the user view to check the IPsec proposal configuration.

Follow-up Procedure

The configured IPsec proposal can be referenced in an IPsec policy or IPsec profile. For details, see Configuring an IPsec Policy or Configuring an IPsec Profile.
