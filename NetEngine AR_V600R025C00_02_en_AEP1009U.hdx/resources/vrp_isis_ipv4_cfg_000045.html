Configuring IS-IS Route Leaking

Prerequisites

Before configuring IS-IS route leaking, you have completed the following task:

  • Configure basic IS-IS functions.

Context

When both Level-1 and Level-2 areas are deployed on an IS-IS network, routes in the Level-1 areas leak to the Level-2 areas. Therefore, Level-1-2 devices and Level-2 devices learn the topology of the entire network. By default, a Level-2 device does not advertise the learned routing information of other Level-1 areas and backbone area to the local Level-1 area. In this case, Level-1 devices do not know the routing information outside the local area and forward traffic to the nearest Level-1-2 device. Then, the Level-1-2 device forwards the traffic to the Level-2 area. However, the used route may not be optimal.

With route leaking, Level-1-2 devices can select routes of other Level-1 areas and the backbone area using routing policies or tags and advertise the selected routes to the local Level-1 area. Figure 1 shows the typical networking for route leaking.

  • Devices A, B, C, and D belong to area 10. DeviceA and DeviceB are Level-1 devices, and DeviceC and DeviceD are Level-1-2 devices.

  • DeviceE and DeviceF belong to area 20 and are Level-2 devices.

Figure 1 Network diagram of route leaking

The optimal route of packets from DeviceA to DeviceF is DeviceA -> DeviceB -> DeviceD -> DeviceE -> DeviceF, as its cost is 40 (10 + 10 + 10 + 10), which is less than that (10 + 50 + 10 = 70) of the other route (DeviceA -> DeviceC -> DeviceE -> DeviceF). However, if you check routes on DeviceA, you can find that the selected route is the latter.

This is due to DeviceA being unaware of routes beyond the local area, and sending the packets beyond the local area to the nearest Level-1-2 device.

If route leaking is enabled on the Level-1-2 devices (DeviceC and DeviceD), the selected path is DeviceA -> DeviceB -> DeviceD -> DeviceE -> DeviceF, which is the optimal route from DeviceA to DeviceF.

If route leaking from a Level-1 area to a Level-2 area is enabled (enabled by default) and route importing from the Level-2 area to the Level-1 area is also enabled, the routes imported from the Level-2 area leak back to the Level-2 area, causing routing loops. To prevent this issue, IS-IS sets the Distribution bit to 1 (Down) for the routes that are imported from the Level-2 area to the Level-1 area, so that the Level-2 area does not advertise those routes. For other ordinary routes in the Level-1 area, IS-IS sets the Distribution bit to 0 (Up).

In addition, some services deployed on the network may run only in the local Level-1 area. Therefore, these routes do not need to be leaked to the Level-2 area. In this case, you can configure a policy to leak only desired routes from the Level-1 area to the Level-2 area.

Procedure

  • Configure route leaking from a Level-2 area to the local Level-1 area.
    1. Enter the system view.

      system-view

    2. Enter the IS-IS view.

      isis [ process-id ]

    3. Configure IS-IS to leak only some routing information from a Level-2 area and other Level-1 areas to the local Level-1 area.

      • For IPv4 IS-IS:
        import-route isis level-2 into level-1 [ tag tag | filter-policy { acl-number | acl-name acl-name | ip-prefix ip-prefix-name | { route-policy route-policy-name } } | direct { allow-filter-policy | allow-up-down-bit } * ] *
      • For IPv6 IS-IS:
        ipv6 import-route isis level-2 into level-1 [ tag tag | filter-policy { acl6-number | acl6-name acl6-name-string | ipv6-prefix ipv6-prefix-name | route-policy route-policy-name } | direct { allow-filter-policy | allow-up-down-bit } * ] *

      By default, IS-IS routing information in the Level-2 area is not leaked to Level-1 areas.

      This command can be run only on Level-1-2 devices connected to an external area.

  • Configure route leaking from the local Level-1 area to the Level-2 area.
    1. Enter the system view.

      system-view

    2. Enter the IS-IS view.

      isis [ process-id ]

    3. Configure the device to leak some IS-IS routes from the Level-1 area to the Level-2 area.

      • For IPv4 IS-IS:
        import-route isis level-1 into level-2 [ tag tag-value | filter-policy { acl-number | acl-name acl-name-value | ip-prefix ip-prefix-name | { route-policy route-policy-name } } | direct allow-filter-policy ] *
      • For IPv6 IS-IS:
        ipv6 import-route isis level-1 into level-2 [ tag tag | filter-policy { acl6-number | acl6-name acl6-name-string | ipv6-prefix ipv6-prefix-name | route-policy route-policy-name } | direct allow-filter-policy ] *

      By default, all IS-IS routes (except default routes) in a Level-1 area leak to a Level-2 area. You can specify parameters as required in the command so that only information about the routes that meet specified conditions is leaked to the Level-2 area.

      This command can be run only on Level-1-2 devices connected to an external area.

Verifying the Configuration

  • Run the display isis route [ process-id | vpn-instance vpn-instance-name ] ipv4 [ verbose | [ level-1 | level-2 ] | ip-address [ mask | mask-length ] ] * command to check IPv4 IS-IS route leaking information.
  • Run the display isis route [ process-id | vpn-instance vpn-instance-name ] ipv6 [ verbose | [ level-1 | level-2 ] | ipv6-address [ prefix-length ] ] * command to check IPv6 IS-IS route leaking information.
