NTP Fundamentals

Figure 1 shows the NTP packet exchange process.

Figure 1 NTP packet exchange process

The NTP packet exchange process is as follows:

  1. The NTP client sends an NTP request packet to the NTP server. The NTP request packet is timestamped as T1 when it leaves the NTP client.
  2. The NTP server receives the NTP request packet and adds the timestamp T2 to this packet.
  3. The NTP server sends an NTP response packet to the NTP client. The NTP response packet is timestamped as T3 when it leaves the NTP server.
  4. The NTP client receives the NTP response packet and adds the timestamp T4 to this packet.

Following this packet exchange, the NTP client has four timestamps: T1, T2, T3, and T4.

An example assumes that the one-way delay of a link is Delay and the time difference between the NTP client and NTP server is Offset (the current time of the NTP server minus the time of the NTP client). The calculation formulas are as follows:

T2 - T1 = Delay + Offset

T4 - T3 = Delay - Offset

Therefore, Offset is calculated as follows: Offset = [(T2 - T1) - (T4 - T3)]/2. The NTP client adjusts its clock based on the Offset value to achieve synchronization with the NTP server.

The preceding is a brief introduction of how NTP works. RFC 1305 defines a complex algorithm for NTP to ensure the precision of clock synchronization.
