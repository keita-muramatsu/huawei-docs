MIB Tree Structure

The MIB stores information using a tree structure where the leaf nodes indicate managed objects. A managed object is identified by a path from the root to the leaf node. Such a path is called an object identifier (OID).

Figure 1 shows the MIB tree structure.

Figure 1 MIB tree structure

An OID is a string of non-negative integers and uniquely identifies the location of a managed object in the MIB tree.

Once a MIB file is released, OIDs are bound to managed objects. The bindings cannot be modified. A MIB object cannot be deleted, but it can be labeled "obsolete", indicating that the object is no longer used.

In the tree structure shown in Figure 1, a managed object can be identified as { iso(1) org(3) dod(6) internet(1) mgmt(2) } or simply as 1.3.6.1.2 (known as an OID). The NMS accesses objects in the agent through OIDs.
