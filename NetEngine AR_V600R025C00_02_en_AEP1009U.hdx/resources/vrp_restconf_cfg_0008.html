OPTIONS

The OPTIONS method is used by the client to discover which methods are supported by the server for a specific resource.

The following example shows how the client discovers the methods supported by the server.

  • Request

    OPTIONS /restconf/data/huawei-aaa:aaa/domains/domain HTTP/1.1
Content-Length: 0
Authorization: Basic YXBpLWFkbWluOkFkbWluQDEyMw==

  • Response

    HTTP/1.1 200 OK
Date: Wed, 18 Apr 2022 12:00:00 GMT
Accept-Patch: application/yang-data+xml, application/yang-data+json
Allow: POST, DELETE, GET, HEAD, PATCH, OPTIONS
Content-Length:0
    The meanings of the fields in the message are as follows:
    • HTTP/1.1 200 OK: indicates that the OPTIONS operation succeeds.
    • Accept-Patch: indicates the data formats supported by the PATCH method.
    • Allow: indicates the RESTCONF method supported by the server.
    • Content-Length: indicates the length of the message-body. Value 0 indicates that no message-body exists.

In this example, the RESTCONF methods supported by the server are POST, DELETE, GET, HEAD, PATCH, and OPTIONS.
