MSDP Messages

MSDP messages are encapsulated in TCP data packets and use the standard-compliant type-length-value (TLV) format, as shown in Figure 1.

Figure 1 MSDP message format

The fields in an MSDP message are described as follows:

  • Type: indicates the message type. For details about major message types, see Table 1.
  • Length: indicates the message length.
  • Value: indicates the message content, which varies depending on the message type.

SA messages are sent periodically. This means that when joining a group in a domain, a user must wait for the SA message sent from the MSDP peer in the next period to obtain valid (S, G) information. To reduce the time required for the user to join the source SPT, MSDP supports both Type 2 and Type 3 SA-Req and SA-Resp messages, enabling active source information to be updated faster.

MSDP peers share (S, G) information by exchanging SA messages. As described in Table 1, SA messages can carry (S, G) information and encapsulate multicast data packets. If (S, G) entries in SA messages time out, remote users cannot receive data from the multicast source. To prevent this problem, the source RP can be configured to encapsulate multicast data packets into SA messages and send the messages to the remote RP. After receiving the SA messages, the remote RP decapsulates them and transmits the multicast data packets to users in the local domain along the RPT.
