Configuring IPsec Anti-Replay

Prerequisites

IPsec anti-replay takes effect only for the following IPsec types:

  • ACL-based IPsec (involving ISAKMP IPsec policies, template IPsec policies, and manual IPsec policies)
  • Route-based IPsec (involving IPsec profiles)

Context

Replayed packets are packets that have been processed. IPsec uses the sliding window (anti-replay window) mechanism to check replayed packets. Headers of the AH and ESP protocol packets carry 32-bit serial numbers. In the same SA, the serial numbers of the packets increase in ascending order. If the device receives an authenticated packet and the serial number of the packet is the same as that of the decapsulated packet, or the serial number of the packet is small and out of the sliding window, the packet is considered as a replayed packet.

Decapsulation of replayed packets has no actual significance and may consume a great number of resources of the device, deteriorating service availability. In this case, replayed packets actually result in Denial of Service (DoS) attacks. After the IPsec anti-replay function is enabled, the system discards replayed packets and does not decapsulate them, saving system resources.

The IPsec anti-replay function can be configured globally or in an IPsec policy, IPsec policy template, or IPsec profile.
  • Global configuration

    The global IPsec anti-replay function is valid for all created IPsec policies, IPsec policy templates, and IPsec profiles. If a large number of the same anti-replay window parameters need to be configured, you do not need to configure the parameters in each IPsec policy, IPsec policy template, or IPsec profile. Instead, you only need to configure global parameters, improving configuration efficiency.

  • Configuration in an IPsec policy, IPsec policy template, or IPsec profile

    You can configure the IPsec anti-replay function for a specific IPsec policy, IPsec policy template, or IPsec profile separately. In this case, the anti-replay function of the IPsec policy, IPsec policy template, or IPsec profile will not be affected by the global configuration.

To ensure normal service forwarding, the configured IPsec anti-replay window is valid only for new or renegotiated IPsec SAs but not for existing IPsec SAs.

Procedure

  • Configure the IPsec anti-replay function globally.
    1. Enter the system view.

      system-view

    2. Enable the IPsec anti-replay function globally.

      ipsec anti-replay enable

      By default, the IPsec anti-replay function is enabled globally.

    3. Set the global IPsec anti-replay window size.

      ipsec anti-replay window window-size

      By default, the global IPsec anti-replay window size is 1024 bits.

  • Configure the IPsec anti-replay function in a specific IPsec policy or IPsec profile.
    1. Enter the system view.

      system-view

    2. Enter the IPsec policy view or IPsec profile view.

      # Enter the ISAKMP IPsec policy view.

      ipsec policy policy-name seq-number [ isakmp ]

      # Enter the template IPsec policy view.

      ipsec policy-template template-name seq-number

      # Enter the IPsec profile view.

      ipsec profile profile-name

    3. Enable the IPsec anti-replay function in the IPsec policy.

      anti-replay enable

      By default, the IPsec anti-replay function is disabled in an IPsec policy, and a newly created IPsec policy uses the global IPsec anti-replay configuration.

    4. Set the IPsec anti-replay window size in the IPsec policy.

      anti-replay window window-size

      By default, the IPsec anti-replay window size is not configured in an IPsec policy, and a newly created IPsec policy uses the global IPsec anti-replay window size.
