Configuring BGP Graceful Degradation

On a live network, the memory usage of a device may be high when the service traffic is heavy or the configuration is incorrect. If BGP keeps accepting new routes in this case, the device memory may be exhausted. As a result, the process or board is reset, or even the device is restarted. When the memory usage increases rapidly, BGP graceful degradation can take hierarchical policies, such as reducing the route learning speed, stopping route learning, and disconnecting peer relationships, to proactively cope with the situation. This ensures that the memory usage of the device is within a proper range while reducing the impact on services, ensuring normal service running and preventing serious events such as device restarts.

Prerequisites

Before configuring BGP graceful degradation, you have completed the following task:

  • Configure basic BGP functions.

  • Run the memory-usage reliability switch on command to enable memory overload reliability.

Context

Based on the device memory usage, the device memory states are classified as follows:

  1. Warning state: state when the device memory usage exceeds the warning threshold (also called the notification threshold). The default warning threshold is 70%, indicating that the device enters the warning state when the device memory usage exceeds 70%. You can set this threshold using the notice-threshold notice-threshold-value in the memory-usage reliability command.
  2. Danger state: state when the device memory usage exceeds the danger threshold (also called the overload threshold). The default danger threshold is 85%, indicating that the device enters the danger state when the device memory usage exceeds 85%. You can set this threshold using the overload-threshold overload-threshold-value in the memory-usage reliability command.
  3. Exception state: state when the device memory usage exceeds the exception threshold. The default exception threshold is 90%, indicating that the device enters the exception state when the device memory usage exceeds 90%. You can set this threshold using the exception-threshold exception-threshold-value in the memory-usage reliability command.

Procedure

  1. Enter the system view.

    system-view

  2. Configure BGP to discard received routes when the device memory is in the danger state.
    • Configure BGP to discard the following routes when the device memory is in the danger state: the routes newly received from peers, the routes newly leaked from the VPNv4, VPNv6, and EVPN address families to VPN instances, and the routes advertised by VPN instances to the VPNv4, VPNv6, and EVPN address families.
      bgp memory-usage danger-threshold discard new-route include { vrf-import-route | vrf-export-route }*
    • Configure BGP to discard newly received routes when the device memory is in the danger state.
      bgp memory-usage danger-threshold discard new-route

    Configuring the bgp memory-usage danger-threshold discard new-route command may affect route learning and compromise services. Therefore, exercise caution when running this command.

  3. Configure the device to tear down peer relationships if the device memory remains in the danger state for a specified period and the memory usage of the BGP component ranks in the top 3, and to reset the BGP process if the danger state persists and the memory usage of the BGP component still ranks in the top 3 after the peer relationships are torn down.

    bgp memory-usage danger-threshold escape timeout time [ minute ]

    Configuring the bgp memory-usage danger-threshold escape timeout time [ minute ] command may interrupt services such as IGP and route management services. Therefore, exercise caution when running this command. You can run the bgp memory-usage danger-threshold escape disable command to disable BGP from attempting to escape from the danger state when the device memory is in the danger state.

  4. (Optional) Configure the device not to establish peer relationships with the BGP peers that fail to go up in a specified period when the device memory is in the danger state.

    bgp memory-usage danger-threshold not-allow-connect [ escape time time-value ]

    By default, when the device memory is in the danger state and the memory usage of the BGP component ranks in the top 3, the device does not establish peer relationships with the BGP peers that fail to go up within 72 hours.

  5. (Optional) Configure the device not to disconnect a specified peer when the device memory is in the danger state.
    1. Enter the BGP view.

      bgp as-number

    2. Configure the device not to disconnect a specified peer when the device memory is in danger state. This prevents key services from being affected.

      peer { peerIpv4Addr | peerIpv6Addr | groupName } low-memory exempt

    3. Enter the system view.

      quit

  6. (Optional) Configure the device to exempt rejected routes when the device memory is in the danger state.
    1. Enter the BGP view.

      bgp as-number

    2. Enter the BGP-IPv4 unicast address family view.

      ipv4-family unicast

    3. Configure the device to accept only the routes that match the specified IP prefix list when the device memory is in the danger state.

      prefix low-memory exempt ip-prefix prefix-filter-name

      When the device memory is in the danger state, the routes received from BGP peers are rejected. To restore the rejected routes after the prefix low-memory exempt ip-prefix command is run, run the refresh bgp command.

    4. Enter the BGP view.

      quit

    5. Enter the system view.

      quit
