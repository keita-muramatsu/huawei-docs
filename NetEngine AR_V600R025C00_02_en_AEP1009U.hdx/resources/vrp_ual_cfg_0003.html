UAL Fundamentals

UAL Architecture

The UAL protocol enables discovery, organization, and management of NEs. It allows for centralized management of the entire network through login to any connected device.

Figure 1 shows the network architecture.

Figure 1 Network architecture with UAL deployed

In the network architecture, NEs have two roles: master and member.

  • Master: a device on which the UAL protocol is deployed. It provides automatic management capabilities for the entire network.
  • Member: an NE managed by the master device.

UAL Packet Format

UAL packets are encapsulated into CoAP packets. Therefore, the UAL packet format, as shown in Figure 2, is the same as the CoAP packet format.

Figure 2 UAL packet format
Table 1 Fields in a UAL packet

Field

Length

Description

Ver

2 bits

CoAP protocol version. Currently, this field can only be set to 1. Other values are reserved for later versions.

Type

2 bits

CoAP message type: CON(0), NON(1), ACK(2), and RST(3).

TKL

4 bits

Length of the variable-length token field. The value ranges from 0 to 8. Values 9 to 15 are reserved, and are processed as a message format error if set.

Code

8 bits

Function/response code.

Message ID

16 bits

Message ID, which is used to detect message duplication and to match ACK/RST messages with CON/NON messages.

Token

0–32 bits

Used to correlate requests and responses. The length of a token ranges from 0 to 8 bytes.

Options

Variable

Can contain zero or more options. A UAL packet contains the URI-Host and URI-Path options.

Payload Marker

8 bits

Payload identifier. The value is fixed to 0xFF.

Payload

Variable

Data carried in the packet. It contains the following fields:

  • deviceModel: device model. The value contains a maximum of 64 characters.
  • deviceLogo: device brand.
  • deviceSn: device serial number.
  • deviceMac: device MAC address.
  • deviceIp: device IP address.
  • deviceTypeId: device type.
  • isSupportMaster: whether the device can be elected as the master device. 0 indicates that the device cannot be elected as the master device. 1 indicates that the device can be elected as the master device.
  • deviceLevel: device location. This field is valid only when isSupportmaster is set to 1. The value can be 0x80 (gateway layer), 0x60 (AC), 0x40 (aggregation layer), or 0x20 (access layer).
  • devicePriority: device priority.
  • softwareversion: software version.
  • dynaCapability: dynamic capability of the device, indicating the current device status.
  • capability: static capability of the device, which is specified by the administrator.
  • httpPort: port number of the management channel. The default value is 8443 in the WebMaster scenario.
  • serviceCap: CoAP capability of the device.
  • networkName: reserved field.

Basic Working Process

All NEs are physically connected and powered on. Figure 3 shows the basic working process.

Figure 3 UAL basic working process
  1. IP address assignment

    Create VLANIF1 on each NE and configure an IPv4 address for VLANIF1. You can use DHCP to dynamically assign IPv4 addresses or manually configure them. Ensure that the IP addresses of all NEs are in the same network segment.

  2. Master role election

    The master device is manually specified among NEs that have the master election capability. If multiple NEs compete for the master role, the master device is elected by comparing the priority fields carried in UAL packets.

    After the master device is elected, users at any location can access it using the specified virtual IP address (10.231.10.253).

  3. Automatic NE discovery
    1. The master device periodically sends broadcast packets to check whether other NEs exist.
    2. Upon receiving such a broadcast packet, an NE records the master device information and sends a unicast response packet to the master device.
    3. After receiving the response packet, the master device adds the NE to the device approval list. The NE becomes a member device of the master device.
  4. Network topology information collection
    1. You can select member devices to be managed from the device approval list.
    2. The master device sends topology collection packets to a member device to subscribe to its interface information and LLDP neighbor information.
    3. The member device replies with a unicast response packet carrying its interface information and LLDP neighbor information.
    4. After receiving the response from the member device, the master device calculates the network topology and displays it on WebMaster (WebMaster is an integrated network management platform).
