IPsec Framework

The IPsec framework standards are defined in the Internet Engineering Task Force (IETF) Request for Comments (RFC), as shown in Figure 1.

Figure 1 IPsec framework
  • Authentication Header (AH) and Encapsulating Security Payload (ESP) are the two IP-based transport-layer protocols used by IPsec to provide security services such as authentication and encryption. AH provides data source authentication, data integrity check, and anti-replay functions, but does not provide the encryption function. ESP provides encryption, data source authentication, data integrity check, and anti-replay functions. For details, see Understanding IPsec Security Protocols and Understanding IPsec Encapsulation Modes.
  • The security functions provided by AH and ESP depend on the authentication and encryption algorithms used by IPsec. While only ESP can encrypt original IP packets using symmetric encryption algorithms, both AH and ESP provide data source authentication and data integrity checks. For details, see Understanding IPsec Encryption and Authentication.
  • The keys used by encryption and authentication algorithms can be dynamically negotiated. To improve key security and reduce management complexity, an Internet Key Exchange (IKE) protocol is introduced into the IPsec framework to implement dynamic negotiation and key management of SAs. In the Internet Security Association and Key Management Protocol (ISAKMP) framework, IKE uses Diffie-Hellman (DH) algorithms to securely deliver keys and authenticate identities over insecure networks, ensuring data transmission security. For details, see Understanding Key Exchange.
