(Optional) Configuring IS-IS to Ignore Checking of Specific TLVs in LSPs (IPv4)

Context

By default, a device discards LSPs received from a peer device that follows a different TLV specification, leading to service interruptions. With the default configuration:

  • If the local device receives an IS-IS LSP that contains a protocol-incompliant main TLV, it discards the entire LSP and therefore fails to calculate routes based on the routing information in the LSP.
  • If the local device receives an IS-IS LSP that contains a protocol-incompliant sub-TLV, it discards the entire TLV of the sub-TLV and therefore fails to parse other sub-TLVs in the TLV.
  • If the local device receives an IS-IS LSP that contains a protocol-incompliant sub-sub-TLV, the local device discards the entire sub-TLV of the sub-sub-TLV and therefore fails to parse other sub-sub-TLVs in the sub-TLV.

To prevent preceding issues, you can configure the device to ignore checking of specified TLVs, sub-TLVs, or sub-sub-TLVs.

Procedure

  1. Enter the system view.

    system-view

  2. Create an IS-IS process and enter its view.

    isis [ process-id ] [ vpn-instance vpn-instance-name ]

  3. Configure IS-IS to ignore checking of specific TLVs in LSPs. Run the following commands as required:

    • Configure IS-IS to ignore checking of a specified TLV.
      ignore-check-tlv lsp [ system-id lspIdStr | lsp-id lspIdStr ] tlv tlv-type1
    • Configure IS-IS to ignore checking of a specified sub-TLV in a TLV.
      ignore-check-tlv lsp [ system-id lspIdStr | lsp-id lspIdStr ] tlv tlv-type2 sub-tlv sub-tlv-type2
    • Configure IS-IS to ignore checking of a specified sub-sub-TLVs in a sub-TLV.
      ignore-check-tlv lsp [ system-id lspIdStr | lsp-id lspIdStr ] tlv tlv-type3 sub-tlv sub-tlv-type3 sub-sub-tlv sub-sub-tlv-type3 [ force-ignore ]
