Configuring MACsec for an RU

Context

When data is transmitted in plaintext, there are many security risks, for example, bank account information is stolen and tampered with, or malicious network attacks occur. MACsec is a Layer 2 encryption technology that provides hop-by-hop secure data transmission. It protects transmitted Ethernet frames to reduce the risk of information leakage and malicious network attacks. MACsec is suitable for meeting high requirements on data confidentiality.

Before enabling MACsec for an RU, you need to enable MACsec on the RU ports and set the static CKN and CAK.

After the MACsec function is enabled on interfaces of two connected devices, they elect a key server based on their priorities. A smaller priority value indicates a higher priority. The device with a higher priority is elected as the key server. If the two devices have the same priority, their Secure Channel Identifiers (SCIs) are compared. An SCI consists of the MAC address of an interface and the last two bytes of the interface index. The device with a smaller SCI value is elected as the key server.

For the S5751-L and S5731I-L series RUs, MACsec is supported on all ports but can be enabled on a maximum of 16 ports.

Procedure

  • Configure MACsec for RUs in batches in the global RU view.
    1. Enter the system view.
      system-view
    2. Enter the global RU view.
      remote-unit
    3. Enable MACsec on the RU ports and set the static CKN and CAK.
      remote-unit { ru-id1 [ to ru-id2 ] } &<1-8> macsec enable ckn string-name cak string-key port { port-id1 [ to port-id2 ] } &<1-34>

      By default, MACsec is disabled on an RU port, and no static CKN or CAK is set.

      A CKN is the name of a CAK. To ensure that an MKA session can be successfully established between two devices, configure the same CKN and CAK on their connected interfaces.

      port-id indicates the port ID of an RU, which may be different from the physical port number printed on the panel. For example, if the downlink port numbers are 1 to 8 and the uplink port numbers are 9 to 10 on the panel, set port-id to an integer in the range from 1 to 10 according to the actual port for connection. If the downlink port numbers are 1 to 8 and the uplink port numbers are 1 to 2 on the panel, set port-id to an integer in the range from 1 to 10 (1 to 8: downlink ports; 9: uplink port 1; 10: uplink port 2).

    4. (Optional) Configure the MACsec encryption mode on RU ports.
      remote-unit { ru-id1 [ to ru-id2 ] } &<1-8> macsec mode { none | normal | integrity-only } port { port-id1 [ to port-id2 ] } &<1-34>

      By default, the MACsec encryption mode of an RU port is normal.

      To ensure secure transmission of service data on the network, MACsec provides the data encryption and integrity check functions. You can specify an encryption mode to selectively enable data encryption and integrity check. Three encryption modes are available:
      • None: Neither data encryption nor integrity check is performed.
      • Normal: Both data encryption and integrity check are performed.
      • Integrity-only: Integrity check is performed, and data encryption is not performed.

      When configuring MACsec on a network where data traffic is being transmitted, you can set the encryption mode on both ends to none. After MKA session negotiation is successful, change the encryption mode on both ends to normal. This shortens the traffic interruption time.

    5. (Optional) Set MACsec parameters.
      • Configure the MKA session timeout period.
        remote-unit { ru-id1 [ to ru-id2 ] } &<1-8> macsec mka life-time life-time-value port { port-id1 [ to port-id2 ] } &<1-34>

        By default, the MKA session timeout period on an RU port is 6 seconds. For S5731I-L series RUs, it is recommended that MACsec be enabled on a maximum of 10 ports. If MACsec needs to be enabled on more than 10 ports, it is recommended that the timeout period be set to a value greater than or equal to 15 seconds on both ends.

        After session negotiation is complete and a secure channel is established, the two devices exchange MKA protocol packets to ensure that the session is alive. The MKA protocol defines an MKA session keepalive timer that specifies the timeout period of an MKA session. The local device starts the timer when receiving MKA protocol packets from the remote device.

        • If the local device receives subsequent MKA protocol packets within the timeout period, it restarts the timer.
        • If the local device does not receive subsequent MKA protocol packets within the timeout period, it considers the session insecure, deletes the session, and performs MKA session negotiation again.
      • Configure a MACsec security policy.
        remote-unit { ru-id1 [ to ru-id2 ] } &<1-8> macsec policy { must-secure | should-secure } port { port-id1 [ to port-id2 ] } &<1-34>

        By default, the MACsec security policy is must-secure.

        The MACsec security policies are described as follows:

        • must-secure: All plaintext packets are discarded after MKA session negotiation starts. After the negotiation succeeds, packets are encrypted and decrypted normally.
        • should-secure: Plaintext packets are permitted before MKA session negotiation succeeds. After the negotiation succeeds, plaintext packets are discarded and packets are encrypted and decrypted normally.

        When an RU is connected to an AP, you need to set the security policy to should-secure. Otherwise, the AP will work abnormally when it is restarted.

      • Other MACsec parameters cannot be set for RUs. For details about the default settings, see Table 1.
        Table 1 MACsec parameter settings

        Operation

        Command

        Description

        Configure the MKA key server priority.

        This parameter cannot be configured using commands.

        By default, the MACsec MKA key server priority is 16 for an RU.

        Configure an MKA key generation algorithm.

        This parameter cannot be configured using commands.

        The MKA key generation algorithm used by RUs is AES-CMAC-128.

        After generating the SAK, the key server sends the encrypted SAK to the peer device through an MKA packet. Upon receipt of the MKA packet, the peer device checks the integrity of the packet. If the check fails, the peer device drops the packet. If the check succeeds, the peer device decrypts the packet to obtain the original SAK. In addition, ensure that the key generation algorithms configured on both ends are the same. Otherwise, the negotiation may fail. The AES-CMAC-128 algorithm must be used on the device connected to the RU.

        Configure an encryption algorithm for MACsec data packets.

        This parameter cannot be configured using commands.

        After session negotiation is complete, the devices at both ends use the SAK to encrypt and decrypt data packets for encrypted communication.

        The actually used algorithm is automatically negotiated by the devices at both ends in descending order of encryption strength.

        Configure the MACsec encryption offset.

        This parameter cannot be configured using commands.

        The MACsec encryption offset indicates from which byte behind the MACsec tag field a data frame is encrypted.

        The MACsec encryption offset is 0 bytes for RUs.

        Configure the MACsec replay protection window size.

        This parameter cannot be configured using commands.

        To prevent malicious users from repeatedly sending obtained data packets, the receiver discards duplicate or out-of-order data packets by default. In some cases, however, data packets are reordered during transmission because their sending priorities are different. As a result, the data packets are out of order when they reach the receiver. To ensure that these out-of-order data packets can be received normally, configure the replay protection window size.

        Assume that the replay protection window size configured on the device is a. If the device receives a packet with the sequence number x, the sequence number of the next packet that is allowed to be received must be greater than or equal to (x + 1 - a). Set an appropriate replay protection window size based on the data packet forwarding path on the network. If data packets may be forwarded multiple times, there is a high probability that many of them become out of order. To address this issue, you are advised to increase the replay protection window size. Otherwise, decrease the window size.

        By default, the MACsec replay protection window size is 1024 for RUs. The replay protection window size must be greater than 1024 on the device connected to the RU. Otherwise, packet loss may occur.

        Configure the device to add an SCI to the MACsec frame header.

        This parameter cannot be configured using commands.

        An SCI identifies the source of a packet. It consists of the MAC address of an interface and the last two bytes of the interface index. When the device is connected to a non-Huawei device and MACsec is configured on them, the MACsec frame header may need to contain the SCI to identify the source of packets because the implementation of MACsec on the device is different from that on the non-Huawei device.

        On RUs, the MACsec frame header contains an SCI.

        The settings of whether the MACsec frame header contains an SCI must be the same at both ends. That is, the MACsec frame header must also contain an SCI on the device connected to the RU.

        Configure the SAK timeout period.

        This parameter cannot be configured using commands.

        When MACsec is used for secure communication, an SAK is used to encrypt and decrypt data packets. To improve the security of data packets, an SAK needs to be replaced when the number of data packets encrypted using the SAK reaches a certain value or the time for using the SAK exceeds a certain period. In this case, the key server generates and advertises a new SAK.

        The SAK timeout period is fixed at 3600 seconds for RUs.

        Configure the MACsec capability value.

        This parameter cannot be configured using commands.

        The MACsec capability value is fixed at 3 for RUs. You need to set the MACsec capability value of the RU to be the same as that of the remote device.

        The MACsec capability values are as follows:

        • 2: Both integrity check and confidentiality check are supported. Encryption can only start from the packet header.
        • 3: Both integrity check and confidentiality check are supported. The encryption offset can be 0 bytes (encryption starting from the packet header), 30 bytes, or 50 bytes.
    6. Deliver the configuration to all RUs or a single RU.
      commit { all | name remote-unit-name | interface interface-type interface-number }
