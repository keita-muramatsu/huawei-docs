Configuring the CBQ Mode

Context

The CBQ mode provides user-defined scheduling for a type of queue. Compared with the parent and child traffic policy mode, the CBQ mode is easier and faster to configure and occupies less system resources when user-defined scheduling does not need to be performed for both SQs and FQs. For details about the CBQ mode, see CBQ Configuration Model.

In SD-WAN scenarios, AR8000 series and AR6700-H series devices support the configuration of site connection-based QoS policies in CBQ mode. However, only FQ profiles, but not SQ profiles, can be referenced in traffic behaviors in CBQ mode. For details, see Example for Configuring Queue Scheduling HQoS (Configuring a Connection-based QoS Policy in CBQ Mode).

Procedure

  1. Enter the system view.

    system-view

  2. Configure a traffic classifier to differentiate services.
    1. Create a traffic classifier and enter the traffic classifier view.

      traffic classifier classifier-name [ type { and | or } ]

    2. Select proper traffic classification rules as required. For details, see "Configuring a Traffic Classifier" in MQC Configuration.
    3. Exit the traffic classifier view.

      quit

  3. Configure a traffic behavior.

    1. Create a traffic behavior and enter the traffic behavior view.
      traffic behavior behavior-name
    2. Reference an FQ or SQ profile in the traffic behavior and configure traffic scheduling as required. In the same traffic policy, traffic behaviors can reference only one type of queue profiles.
      • Reference an FQ profile.
        flow-queue flow-queue-name queue queue-name

        When configuring this command, set flow-queue-name to the name of the FQ profile configured in Configuring an FQ or SQ Profile.

      • Reference an SQ profile.
        qos-user-profile profile-name user-queue user-name

        When configuring this command, set profile-name to the name of the SQ profile configured in Configuring an FQ or SQ Profile.

    3. (Optional) Configure the CAR action.
      The CIR and PIR of the CAR action can be set to absolute values or values in percentage, but only one value format can be configured. Use either of the following methods to perform the configuration:
      • Set the absolute values of the CIR and PIR.
        car { cir cir-value [ kbps | mbps | gbps ] [ pir pir-value [ kbps | mbps | gbps ] ] } [ cbs cbs-value [ bytes | kbytes | mbytes ] pbs pbs-value [ bytes | kbytes | mbytes ] ] [ share ] [ mode color-blind ] [ green pass [ remark-8021p 8021p-value | remark-dscp dscp-value ] | yellow { discard | pass [ remark-8021p 8021p-value | remark-dscp dscp-value ] } | red { discard | pass [ remark-8021p 8021p-value | remark-dscp dscp-value ] } ]*
      • Set the values of the CIR and PIR in percentage.
        car cir pct cir-percentage [ pir pct pir-percentage ] hierarchical-bandwidth [ cbs cbs-value pbs pbs-value | share | mode color-blind ]*

        cir-percentage and pir-percentage specify the CIR bandwidth percentage and PIR bandwidth percentage, respectively. Their base value is the traffic shaping bandwidth value (configured using the qos lr command) defined on an interface. If this bandwidth value is not configured, the base value is the interface bandwidth value.

    4. Exit the traffic behavior view.
      quit

  4. Configure a traffic policy in CBQ mode.
    1. Create a traffic policy and enter the traffic policy view.

      traffic policy policy-name

    2. Bind a traffic classifier to a traffic behavior in the traffic policy.

      classifier classifier-name behavior behavior-name [ precedence precedence-value ]

Example

# Configure HQoS in CBQ mode and set user-defined scheduling parameters for an FQ.

  1. Create traffic classifiers data and voice to classify services based on DSCP values (DSCP values 15 and 46 for data and voice services, respectively).
    <HUAWEI> system-view
[HUAWEI] traffic classifier data
[HUAWEI-classifier-data] if-match dscp 15
[HUAWEI-classifier-data] quit
[HUAWEI] traffic classifier voice
[HUAWEI-classifier-voice] if-match dscp 46
[HUAWEI-classifier-voice] quit
  2. Create traffic behaviors data and voice and reference the FQ profile fq1 in the traffic behaviors.
    [HUAWEI] traffic behavior data
[HUAWEI-behavior-data] flow-queue fq1 queue data
[HUAWEI-behavior-data] quit
[HUAWEI] traffic behavior voice
[HUAWEI-behavior-voice] flow-queue fq1 queue voice
[HUAWEI-behavior-voice] quit
  3. Create a CBQ traffic policy named policy-cbq and bind traffic classifiers to traffic behaviors in the traffic policy.
    [HUAWEI] traffic policy policy-cbq
[HUAWEI-trafficpolicy-policy-cbq] classifier data behavior data
[HUAWEI-trafficpolicy-policy-cbq] classifier voice behavior voice

# Configure HQoS in CBQ mode and set user-defined scheduling parameters for an SQ.

  1. Create traffic classifiers user1 and user2 to classify traffic by VLAN.
    <HUAWEI> system-view
[HUAWEI] traffic classifier user1
[HUAWEI-classifier-user1] if-match vlan 10
[HUAWEI-classifier-user1] quit
[HUAWEI] traffic classifier user2
[HUAWEI-classifier-user2] if-match vlan 20
[HUAWEI-classifier-user2] quit
  2. Create traffic behaviors user1 and user2 and reference the SQ uq1 in the traffic behaviors.
    [HUAWEI] traffic behavior user1
[HUAWEI-behavior-user1] qos-user-profile uq1 user-queue user1
[HUAWEI-behavior-user1] quit
[HUAWEI] traffic behavior user2
[HUAWEI-behavior-user2] qos-user-profile uq1 user-queue user2
[HUAWEI-behavior-user2] quit
  3. Create a CBQ traffic policy named policy-cbq and bind traffic classifiers to traffic behaviors in the traffic policy.
    [HUAWEI] traffic policy policy-cbq
[HUAWEI-trafficpolicy-policy-cbq] classifier user1 behavior user1
[HUAWEI-trafficpolicy-policy-cbq] classifier user2 behavior user2
