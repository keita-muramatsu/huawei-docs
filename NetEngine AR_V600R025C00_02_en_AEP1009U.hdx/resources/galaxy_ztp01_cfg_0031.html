Understanding USB-based Deployment

Deployment Process

USB-based deployment requires engineers merely to save all deployment files to a USB flash drive in advance. Deployment personnel then only need to insert the USB flash drive into devices for deployment, which greatly reduces deployment costs. Figure 1 shows the deployment process.

Figure 1 USB-based deployment process
  1. Preparing deployment files and making an intermediate file

    Before USB-based deployment, an engineer prepares deployment files and makes the intermediate file usb.ini on a terminal such as a PC. The intermediate file stores information about the device to be deployed and its deployment files. The intermediate file can be an .ini file (Intermediate File in the INI Format) or Python script (Intermediate File in Python Format).

    The file system format of a USB flash drive must be FAT32 or EXT4, and its port must support USB 2.0 or later. The device does not support Solid State Disk (SSDs) with USB ports.

    The intermediate file in Python format applies only to USB-based deployment of unconfigured devices.

  2. Saving the deployment files and intermediate file to a USB flash drive

    The engineer saves the intermediate file to the root directory of a USB flash drive and saves the deployment files to the specified directory.

  3. Powering on the device and inserting the USB flash drive into the device to start deployment (After the USB flash drive is inserted, you do not need to restart the device. A started device can automatically detect the USB flash drive.)
    After the device is powered on and started, a deployment person inserts the USB flash drive into the device, which then automatically loads the deployment files based on the intermediate file and starts the deployment.
    1. After the device is powered on and starts, it detects the USB flash drive. If the device starts with empty configuration, it directly enters the USB-based deployment process. If the device has a configuration file, it checks whether the USB-based deployment function is enabled and enters the USB-based deployment process only if this function is enabled.
    2. The device reads the intermediate file in the root directory of the USB flash drive and obtains deployment files from the directory specified in the intermediate file.
    3. The device determines the effective mode of each deployment file based on activation modes defined in the intermediate file. If a deployment file is specified as a system startup file, it is activated when the device restarts regardless of the configured activation mode.
  4. Removing the USB flash drive after the deployment is complete

    After the deployment is complete, the deployment person removes the USB flash drive.

  • When deploying an unconfigured device, you are advised not to manually deliver the same configurations as those delivered during ZTP. Doing so will cause the configurations to be deleted if the deployment fails.
  • ZTP depends on OPS. You can run the display ops process current command to obtain the task ID, which indicates the ZTP process ID, and then run the ops stop process process-id command to stop the ongoing ZTP process. This operation, however, may cause the configurations that have been delivered during ZTP to be retained on the device.
