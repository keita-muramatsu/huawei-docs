Enabling Slow Peer Detection

After slow peer detection is configured on a device, the device identifies the slow BGP peer (if any) and removes it from the update peer-group to prevent this slow peer from affecting route advertisement to other peers in this update peer-group. Slow peer detection speeds up BGP network convergence.

Context

An update peer-group may consist of multiple peers. If a network problem (congestion for example) occurs and slows down the speed at which the local device advertises routes to a peer in the update peer-group, the speed at which the local device advertises routes to other peers in the update peer-group is affected. To prevent this impact, enable slow peer detection on the device.

After slow peer detection is enabled, the local device calculates the difference between the time taken to send messages to each peer in the update peer-group and the shortest time taken to send messages to each peer in the group. If the difference between the time taken to send messages to a peer and the shortest time is greater than the threshold specified for slow peer detection, the local device considers this peer as a slow peer and removes it from the update peer-group, which prevents this slow peer from affecting route advertisement to other peers in the group.

If BGP Update messages fail to be advertised, slow peers cannot be detected using the original slow peer detection mode. To address this problem, configure the absolute mode for slow peer detection. If the delay in sending messages to a peer is greater than the absolute time threshold, the peer is considered a slow peer.

A slow update peer-group may contain multiple slow peers. If a network problem (congestion for example) occurs and slows down the speed at which the local device advertises routes to a slow peer, the speed at which the local device advertises routes to other peers in the slow update peer-group is also affected. To prevent this problem, you can enable hierarchical slow-peer switching, which allows the slowest peer in a slow update peer-group to be automatically switched to a new slow update peer-group. This new slow update peer-group consists of only this peer.

After hierarchical slow-peer switching is enabled, the local device calculates the time taken to send messages to each slow peer in the slow update peer-group. If the time taken to send messages to a peer is greater than or equal to the absolute time threshold for detecting slower peers to implement hierarchical slow-peer switching, the local device considers this peer as a slower peer. If all the other peers in the slow update peer-group have received messages from the device at this time, the device switches the preceding slower peer from the current update peer-group to a new update peer-group, which prevents this slower peer from affecting route advertisement to other peers in the current update peer-group. For example, there are three slow peers A, B, and C in a slow update peer-group on the local device, and the absolute time threshold for detecting slower peers in the slow update peer-group is 300s. The local device calculates the time taken to send messages to each slow peer in the slow update peer-group in sequence. If the time taken to send messages to slow peer A is 400s and slow peers B and C have received messages from the device, slow peer A is removed from the current slow update peer-group and added to a single-peer update peer-group. If slow peers B and C have not received messages from the device, slow peer A is not removed from the current slow update peer-group. Instead, the device continues to calculate the time taken to send messages to slow peer B or C and repeats the comparison rule for slow peer A.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the BGP view.

    bgp as-number

  3. Enable slow peer detection.

    slow-peer detection threshold threshold-value

    The threshold threshold-value parameter specifies a threshold for slow peer detection. If the difference between the time taken to send messages to a BGP peer and the time taken to send messages to the fastest peer in the group exceeds the threshold-value, the local device identifies the former peer to be a slow one and removes it from the update peer-group. If this parameter is not specified, the default threshold (300s) is used.

    By default, slow peer detection is enabled. To disable slow peer detection, run the slow-peer detection disable command.

  4. (Optional) Enable slow peer detection in absolute mode.

    slow-peer absolute-detection threshold threshold

  5. (Optional) Configure hierarchical slow-peer switching.
    1. Enable hierarchical slow-peer switching.

      slow-peer single-group { enable | disable | auto-process }

      By default, BGP automatically determines whether to enable hierarchical slow-peer switching based on the device memory. By default, the device automatically checks whether a slower peer exists in the update peer-group, regardless of whether hierarchical slow-peer switching is enabled. If hierarchical slow-peer switching does not take effect and the device detects a slower peer, it records the SLOW_PEER_SINGLEGROUP log.

    2. Set the maximum number of slow peers that can be automatically switched to single-peer update peer-groups.

      slow-peer single-group number number-value

      By default, a maximum of five slow peers can be automatically switched to single-peer update peer-groups.

    3. Configure an absolute time threshold for detection of slower peers in a slow update peer-group.

      slow-peer single-group detection threshold threshold-value

      The threshold threshold-value parameter specifies the absolute time threshold for detection of slower peers in a slow update peer-group. After hierarchical slow-peer switching is enabled, the local device calculates the time taken to send messages to each slow peer in the slow update peer-group. If the time taken to send messages to a peer is greater than or equal to the absolute time threshold for detecting slower peers to implement hierarchical slow-peer switching, the local device considers this peer as a slower peer. If all the other peers in the slow update peer-group have received messages from the device at this time, the device switches the preceding slower peer from the current update peer-group to a new slow update peer-group. If this parameter is not specified, the default threshold (300s) is used.

  6. (Optional) Disable automatic switchback of BGP slow peers.

    slow-peer auto-recover-disable

    By default, automatic switchback of slow BGP peers is enabled. A slow BGP peer automatically switches back to a normal peer every 24 hours. If a peer is identified as a slow peer again after the switchback, message sending to other peers in the update peer-group is affected during the switchover. To prevent this problem, you can disable automatic switchback of slow peers.
