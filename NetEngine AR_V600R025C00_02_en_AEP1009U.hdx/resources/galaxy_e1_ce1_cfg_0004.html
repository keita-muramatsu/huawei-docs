General Concepts of E1/CE1

Context

As pulse code modulation (PCM) technology appeared in 1960s, time division multiplexing (TDM) technology was widely used in digital communication systems. At present, there are two types of TDM systems in digital communication systems: one is the E1 system recommended by ITU-T, which is widely used in Europe and China; the other is the T1 system recommended by ANSI, which is mainly used in North America and Japan (Japan actually uses the J1 system, which is similar to the T1 system).

Serial Interface

After the working mode of an E1/CE1 interface is configured, the link-layer protocol of the generated logical interface is PPP.

  • When the E1/CE1 interface works in E1 mode, only one serial interface is generated.
  • When the E1/CE1 interface works in CE1 mode, all other timeslots except timeslot 0 are randomly divided into several groups. After timeslots in each group are bundled, a serial interface is generated.

Clock Modes

To exchange data successfully, communicating parties must work in clock synchronization state.

An E1/CE1 interface supports the following two clock modes:

  • Master clock mode (internal clock mode): When the interface works in master clock mode, it uses the clock generated inside the chip as the reference clock.
  • Slave clock mode (line clock mode): When the interface works in slave clock mode, it uses the clock recovered from the line as the reference clock.

When two devices are connected using two interfaces, one interface must work in master clock mode and the other interface must work in slave clock mode. The device working in master clock mode provides clock signals, and the device working in slave clock mode uses the clock recovered from the line. This ensures that the two devices can correctly identify received data.

Line Idle Codes

The length of an E1 frame is 256 bits, and an E1/CE1 interface has 32 timeslots. As such, a timeslot has 8 bits. 8000 E1 frames pass through the interface every second (8000/s x 256 bits = 2 Mbit/s).

A line idle code is the code sent over a timeslot that is not bundled into a serial interface. A device supports two types of line idle codes: 0x7e and 0xff.

Interframe Filling Tags

An interframe filling tag is the code sent when no service data is sent through the timeslot bundled to a serial interface.

A device supports two types of interframe filling tags: 0x7e and 0xff. You can set the number of interframe filling tags.
