File System Management Modes Supported by the Device

During file management, a device may work as either a server or a client with the following functions:

  • If the device works as a server, you can access the device using a terminal.
  • If the device works as a client, you can use the device to access another device that works as a server.

In TFTP mode, the device can function only as a client. In SFTP, FTP, and SCP modes, the device can function as both a server and a client.

Based on whether files are uploaded or downloaded when a connection to the device is being set up, the transfer protocols may work in the following modes:

  • One-click mode: You can upload and download files when the connection is being set up.
  • Interactive mode: After the device is connected, you can perform operations on directories and files on the device, and view the help of commands on the device.

There are advantages and disadvantages to each file system management mode, making them applicable to varying scenarios. Details are provided in Table 1. You can select an appropriate mode based on your specific requirements.

Table 1 File system management modes

File System Management Mode

Application Scenario

Advantage

Disadvantage

Local

This mode applies to the scenario of managing directories and files in the storage media after device login through the console port, Telnet, or STelnet.

This mode facilitates storage medium, directory, and file management, and improves management efficiency.

Only files on the logged-in device can be managed. File transfer is not supported.

FTP

This mode applies to the file transfer scenario with low network security requirements, and is widely used in version upgrade.
  • FTP is easy to configure and supports file transfer and file directory operations.
  • FTP supports file transfer between two file systems.
  • The authorization and authentication functions are provided.
  • The interactive mode is supported.

Data is transmitted in plain text, resulting in potential security risks.

TFTP

On a lab local area network (LAN), you can perform online system software load or upgrade using TFTP. This mode applies to the environment without complex interactions between a client and a server.

TFTP requires less memory than FTP.
  • The device can function as a TFTP client only.
  • TFTP supports only file transfer and does not support the interactive mode.
  • TFTP does not provide authorization and authentication functions and transmits data in plain text, posing security risks and making the device vulnerable to network viruses and attacks.

SFTP

This mode applies to scenarios demanding high network security, such as log download and configuration file backup scenarios.
  • Encryption and integrity check are performed on data to ensure high security.
  • File transfer and file directory operations are supported.
  • The interactive mode is supported.

The configuration is complex.

SCP

This mode applies to scenarios demanding high network security and efficient file upload/download.
  • Encryption and integrity check are performed on data to ensure high security.
  • File upload/download is efficient, requiring a single command that also sets up the client-server connection.

The configuration is complex (similar to the configuration in SFTP mode) and the interactive mode is not supported.

The local/FTP/TFTP file management mode is easy to configure and therefore not detailed here. The following only details the SFTP and SCP modes.

  • SFTP mode: As an extension of SSH, SFTP provides a secure channel through which remote users can log in to a device to manage and transfer files. In addition, the device can function as a client, from which users can securely log in to an SSH server for file transfer.
  • SCP mode: SCP is used to copy, upload, and download files based on the SSH remote copy function. The SCP file copy command is easy to use, improving network maintenance efficiency.
