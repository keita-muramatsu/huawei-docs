Configuring the Device to Send ARP/ND Packets on Behalf of Associated STAs

Context

Before a STA succeeds in authentication or key negotiation, if the device sends ARP/ND packets on behalf of the STA, the Layer 2 device connected to the AP will learn the MAC address of the STA. If an attacker floods thousands of STAs' MAC addresses on the network, a large number of MAC address entries of switches on the network are generated, which poses security risks. To prevent this security risk, run the undo sta arp-nd-proxy before-assoc command to configure the device to send ARP/ND packets only after STA authentication or key negotiation succeeds.

In scenarios that do not require high security, you can run the sta arp-nd-proxy before-assoc command to enable the device to send ARP/ND packets on behalf of STAs before they are associated, thereby improving link update efficiency.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Create an AP system profile and enter its view.

    ap-system-profile name profile-name

    By default, the AP system profile default exists on the device.

  4. Configure the device to send ARP/ND packets on behalf of associated STAs.

    undo sta arp-nd-proxy before-assoc

    By default, the device does not send ARP/ND packets on behalf of STAs before they are successfully associated.

  5. Return to the WLAN view.

    quit

  6. Enter the AP view or AP group view.
    • Enter the AP group view.
      ap-group name group-name
    • Enter the AP view.
      ap-id ap-id
  7. Bind the AP system profile to an AP group or a single AP.

    ap-system-profile profile-name

    By default, the AP system profile default is bound to an AP group, but no AP system profile is bound to an AP.
