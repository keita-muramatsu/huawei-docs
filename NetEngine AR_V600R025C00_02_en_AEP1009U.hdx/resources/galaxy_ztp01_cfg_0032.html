For details about the fields in the file, see Table 1. For details about the intermediate file for USB-based deployment in different scenarios, see Intermediate File Examples for USB-based Deployment.

Table 1 Fields in the intermediate file

Field

Mandatory or Not

Description

sha256

No

SHA256 verification code of the script file, which is used to check the integrity of the script file.

You can use either of the following methods to generate a SHA256 verification code for a script file:

  1. Use the SHA256 calculation tool, such as HashMyFiles.
  2. Run the certutil -hashfile filename SHA256 command supported by the Windows operating system.
NOTE:

Before a SHA256 verification code is generated, do not add the #sha256= field to the script. Instead, #sha256= should be added to the beginning of the script after the SHA256 verification code is generated.

A script without a SHA256 verification code can still be executed.

;BEGIN USB

Yes

Start flag of a file. This field cannot be modified.

[GLOBAL CONFIG]

Yes

Start flag of the global configuration. This field cannot be modified.

*TIME_SN

Yes

ID that uniquely identifies a deployment in order to prevent repeated deployments of a device. The value format is yyyymmddhhmmss.

For example, this field can be set to 20200526120159, indicating 12:01:59 on 2020-05-26.

*DEVICE_TYPE_NUM

Yes

Number of device types. The value 1 indicates that only one type of device can be deployed.

[DEVICE_TYPE_n DESCRIPTION]

Yes

Start tag of the device description. n indicates the device number. The value is an integer starting from 1.

DEVICE_TYPE

When DEVICE_TYPE_NUM is set to 1, DEVICE_TYPE, ESN, MAC, and UNAME can all be set to DEFAULT or left empty.

When DEVICE_TYPE_NUM is greater than 1, at least one of DEVICE_TYPE, ESN, MAC, and UNAME must be specified.

NOTE:

In the batch upgrade scenario:

  • You can set DEVICE_TYPE or UNAME to match devices of the same type. For details, see Example 2.
  • You can set ESN or MAC to accurately match a single device. For details, see Example 3.

Device type.

The value of DEVICE_TYPE can be queried using the display version command. In the command output, AR8000 in "Version xxx (AR8000 xxx)" is the value of DEVICE_TYPE.

If this field is left empty or set to DEFAULT, the device type does not need to be matched. The default value is DEFAULT.

ESN

Master device ESN, which can be queried using the display device esn command.

If this field is left empty or set to DEFAULT, the device ESN does not need to be matched. Otherwise, the device ESN needs to be matched. The default value is DEFAULT.

MAC

MAC address of a device, in the XXXX-XXXX-XXXX format, in which X is a hexadecimal number. You can run the display bridge mac-address command to query the MAC address.

If this field is left empty or set to DEFAULT, the MAC address does not need to be matched. Otherwise, the MAC address needs to be matched. The default value is DEFAULT.

UNAME

Specific device model.

The value of UNAME can be queried using the display version command. In the command output, AR8140-12G10XG in "HUAWEI AR8140-12G10XG uptime is X day, X hours, X minutes" is the value of UNAME. The default value is DEFAULT.

VRPVER

No

System software version number.

If the current system software version of the device is the same as the value specified here, the device does not download the system software from the USB flash drive.

To use the current system software package for deployment, set this field to the version number of the current system software package.

SPACE_CLEAR

No

Whether to automatically clean up the system storage space in the case of insufficient space. The value is of the enumerated type.

  • 0: The system storage space is not cleaned up.
  • 1: Only system software is deleted.
  • 2: In-depth cleanup is performed. System software is deleted first. If the available space is still insufficient, all unnecessary files are deleted from the flash directory.

If this field is left empty or set to DEFAULT, the space is not cleaned up. The default value is DEFAULT.

NOTE:

In-depth cleanup involves some inherent risks. As such, you are advised to back up required files locally before performing in-depth cleanup.

DIRECTORY

No

Relative directory of a deployment file on the USB flash drive. The maximum length of the path and file name is 110 characters.

If this field is left empty or set to DEFAULT, deployment files are stored in the root directory. The default value is DEFAULT.

NOTE:

The relative directory must start with a folder name and cannot start with a slash (/).

ACTIVE_DELAYTIME

No

NOTE:

If both ACTIVE_DELAYTIME and ACTIVE_INTIME are set, ACTIVE_DELAYTIME takes effect.

Delay for deployment to be performed. The value is an integer that ranges from 0 to 86400, in seconds. For example, if the value is 60, a powered-on device starts deployment 60s after it has a USB flash drive inserted. If the value is greater than 86400, the value 86400 is used.

ACTIVE_INTIME

Scheduled time for deployment to be performed within 24 hours. The value format is HH:MM, where HH indicates the 24-hour format, and MM indicates the 60-minute format. For example, the value 20:10 indicates that the deployment will be performed at 20:10.

NOTE:

If the configured time is earlier than the system time of the device, the actual deployment time is the configured time plus 24 hours minus the current system time. For example, if the configured time is 10:00 and the device system time is 11:00, the deployment will be performed at 23:00.

*FILETYPENUM

Yes

Number of deployment files to be loaded.

NOTE:

The total number of deployment files must not exceed 9.

The value of this field must be the same as the actual number of deployment files, and the value is the same as n in FILENAME_n.

*FILENAME_n

Yes

Name of a deployment file, which can be the system software, configuration file, license file, patch file, feature package file, default configuration file, batch processing file, Python file, or customized file. The maximum length of the path and file name is 110 characters. The value format is path/filename.

  • path: indicates the relative directory of the deployment file on the USB flash drive. The directory cannot start with a slash (/). The file storage path is specified by the combination of DIRECTORY and FILENAME_n.
  • filename: indicates the deployment file name. If the ztp usb-deployment file-compress password command is executed to compress and encrypt the deployment file, you need to set this parameter to the name of the compressed file.

If an initial CA certificate needs to be activated during device deployment, you can use a batch processing file to import a command, for example:

pki import-certificate default_ca realm default
NOTE:

You are advised to run the save shareable-configuration command without entering a password to export a configuration file.

If the length of a deployment file name exceeds the limit, the file may fail to be downloaded from the USB flash drive. The length limits for different deployment files are as follows:

  • System software: The name is a string of 4 to 110 characters suffixed with .cc.
  • Configuration file: The name is a string of 5 to 64 characters suffixed with .zip or .cfg.
  • License file: The name is a string of 5 to 110 characters suffixed with .dat, .xml, or .zip. The suffix depends on the license file you apply for.
  • PAT patch file: The name is a string of 5 to 63 characters suffixed with .pat.
  • MOD patch file: The name is a string of 5 to 63 characters suffixed with .MOD.
  • Customized file: The name is a string of 3 to 64 characters.
  • Feature package file: The name is a string of 4 to 110 characters suffixed with .ccx.
  • Batch processing file: The name is a string of 5 to 64 characters suffixed with .bat.
  • Default configuration file: The name is a string of 8 to 100 characters suffixed with .defcfg.
  • Python file: The name is a string of 5 to 110 characters suffixed with .py.

*TYPE_n

Yes

Type of a deployment file. The value is of the enumerated type.

  • SOFTWARE: system software.
  • CFG: configuration file.
  • LIC: license file.
  • PAT: PAT patch file or MOD patch file.
  • USER: customized file.
  • FEATURE-PLUGIN: feature package file.
  • SCRIPT: batch processing file.
  • DEFCFG: default configuration file.

    The configurations in the default configuration file will overwrite the factory configurations. For example, to perform DHCP-based deployment through a Layer 3 sub-interface (configured with a termination VLAN tag), you need to configure the Layer 3 sub-interface and configure the sub-interface to terminate single-tagged packets in this configuration file.

  • PYTHON_SCRIPT: Python file.

*EFFECTIVE_MODE_n

Yes

Activation mode. The value is of the enumerated type.

  • 0: activated upon restart, which applies to the system software, configuration file, patch file, feature package file, default configuration file, and batch processing file.
  • 1: activated immediately, which applies to the license file, configuration file, feature package file, batch processing file, Python file, and patch file.
  • 2: Activation is not required, which applies to the customized file.

The default activation modes of various deployment files are as follows:

  • The default activation mode of the system software, default configuration file, and configuration file is 0.
  • The default activation mode of the patch file, license file, batch processing file, Python file, and feature package file is 1.
  • The default activation mode of the customized file is that specified by the value 2 (activation not required).

If EFFECTIVE_MODE_n is set to a value beyond the value range, the default activation mode of each type of file is used.

ISBATCHPROCESS_n

No

Whether to perform batch processing for the license list file. The value is of the enumerated type.

  • 0: no
  • 1: yes

If this field is left empty or set to a value beyond the value range, batch processing is not performed.

NOTE:

Devices can automatically load license files through a license list file, which contains mappings between licenses and device ESNs. A device first downloads the license list file and then downloads and loads the corresponding license file based on the ESN of the master device. The license list file is in XML format and its name must be ztp_license_list. An example of such a file is as follows:

<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<Index formatVersion="1.0">
<Lic Esn="2102353UNW1234567890">
<LSN>LIC202005183TCG5M</LSN>
<name>LIC_file1.xml</name>
<sha256>eb75e8456b049e2406fe61925499080a083bd91319c50f59551cc3ea113a35f2</sha256>
<hamc_sha256/>
<compress_encrytion/>
</Lic>
<Lic Esn="BARCODETEST20200620">
<LSN>LIC202005183TCI50</LSN>
<name>LIC_file2.zip</name>
<sha256>6a2690e7a08e3df844ba86e1f48dc3c504af3b760dd0e38134771e1024fe1a5f</sha256>
<hamc_sha256>6a2690e7a08e3df844ba86e1f48dc3c504af3b760dd0e3813477</hamc_sha256>
<compress_encrytion>1</compress_encrytion>
</Lic>
</Index>

sha256, hamc_sha256, and compress_encrytion in the file are used for integrity verification and compression of a loaded license file, and their functions are the same as those of SHA256_n, HMAC_n, and COMPRESS_ENCRYTION_n in the intermediate file in .ini format.

SHA256_n

No

NOTE:

If neither SHA256 nor HMAC is selected, the deployment file integrity is not verified.

If either SHA256 or HMAC is configured, the configured one takes effect.

If both SHA256 and HMAC are configured, only HMAC verification is performed.

Verification code corresponding to the SHA256 encryption algorithm, which is used to verify the integrity of a deployment file.

If this field is left empty, the deployment file integrity is not verified.

You can use either of the following methods to generate a SHA256 verification code for a script file:

  1. Use the SHA256 calculation tool, such as HashMyFiles.
  2. Run the certutil -hashfile filename SHA256 command supported by the Windows operating system.

HMAC_n

Verification code corresponding to the HMAC_SHA256 encryption algorithm, which is used to verify the integrity of a deployment file.

If this field is left empty, the file integrity is not verified.

This field applies only to USB-based deployment of a device with a configuration file. For details about how to generate a verification code, see (Optional) Configuring Deployment File Security Verification.

COMPRESS_ENCRYTION_n

No

Whether to compress a deployment file.

If the value is 1, a deployment file is compressed with a password. In this case, the device needs to use the password to decompress the deployment file.

If the value is left empty or is not 1, a deployment file is not compressed. In this case, the device does not need to decompress the deployment file.

This field applies only to USB-based deployment of a device with a configuration file.

;END USB CONFIG

Yes

End flag of a file. This field cannot be modified.

Intermediate File Examples for USB-based Deployment

The following provides several intermediate file examples for USB-based deployment in different scenarios.

Example 1

An intermediate file needs to be created for upgrading a single device. The requirements are as follows:

  • An upgrade needs to be performed.
  • The system software package software_file.cc is stored in the root directory of the USB flash drive, and the HMAC string is c3caaee8f4f6bd1389f438801e40dad9af30f2fbbe7e8f55121b39c6c16ba488.

The corresponding intermediate file is as follows:

;BEGIN USB
[GLOBAL CONFIG]
*TIME_SN=20200526120159
*DEVICE_TYPE_NUM=1
[DEVICE_TYPE_1 DESCRIPTION]
DEVICE_TYPE=
ESN=
MAC=
UNAME=
VRPVER=
SPACE_CLEAR=
DIRECTORY=
ACTIVE_DELAYTIME=
ACTIVE_INTIME=
*FILETYPENUM=1
*FILENAME_1=software_file.cc
*TYPE_1=SOFTWARE
*EFFECTIVE_MODE_1=0
ISBATCHPROCESS_1=
SHA256_1=
HMAC_1=c3caaee8f4f6bd1389f438801e40dad9af30f2fbbe7e8f55121b39c6c16ba488
COMPRESS_ENCRYTION_1=
;END USB CONFIG

Create an intermediate file for upgrading multiple devices of the same series to the same software version. The requirements are as follows:

  • An upgrade needs to be performed.

;END USB CONFIG
