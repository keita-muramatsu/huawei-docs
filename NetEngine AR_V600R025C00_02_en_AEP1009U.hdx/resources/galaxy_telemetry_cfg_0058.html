Developing Code

This section only provides the code that you need to pay attention to, which is for reference only.

Except the automatically generated code, you need to develop other code by yourself.

Add the automatically generated Java code to the Java project you have created, and use the data push RPC service to receive data sent from the device. Parse the telemetry header data, and then parse the subsequent data according to the corresponding Java class structure based on the sensor-path field value.

  1. Overwrite the automatically generated RPC service dataPublish, and develop code to obtain corresponding fields.

    The following example describes how to obtain traffic data of 10GE0/0/1.

    public class GBP_Decode {
  private static void gbp_decode() throws IOException, InterruptedException,FileNotFoundException, DescriptorValidationException,InvalidProtocolBufferException { 
    System.out.println("------init msg------");
    byte[] byteArray = initMsg();
    System.out.println("------generate descriptor------");
    // Generate a descriptor file.
    String protocCMD = "protoc --descriptor_set_out=D://cinema1.description D://cinema1.proto --proto_path=D://";
        Process process = Runtime.getRuntime().exec(protocCMD);
        process.waitFor();
        int exitValue = process.exitValue();
        if (exitValue != 0) {
            System.out.println("protoc execute failed");
            return;
        }
    System.out.println("------customer msg------");
    Descriptors.Descriptor pbDescritpor = null;
    DescriptorProtos.FileDescriptorSet descriptorSet = DescriptorProtos.FileDescriptorSet
        .parseFrom(new FileInputStream("D://cinema1.description"));
    for (DescriptorProtos.FileDescriptorProto fdp : descriptorSet.getFileList()) {
      Descriptors.FileDescriptor fileDescriptor = Descriptors.FileDescriptor.buildFrom(fdp, new Descriptors.FileDescriptor[] {});
      for (Descriptors.Descriptor descriptor : fileDescriptor.getMessageTypes()) {
        String className = fdp.getOptions().getJavaPackage() + "."
            + fdp.getOptions().getJavaOuterClassname() + "$"
            + descriptor.getName();
        System.out.println(descriptor.getFullName() + " -> "+ className);

        if (descriptor.getName().equals("Ticket")) {
          System.out.println("Movie descriptor found");
          pbDescritpor = descriptor;
          break;
        }
      }
    }

    if (pbDescritpor == null) {
      System.out.println("No matched descriptor");
      return;
    }
    DynamicMessage.Builder pbBuilder = DynamicMessage.newBuilder(pbDescritpor);
    Message pbMessage = pbBuilder.mergeFrom(byteArray).build();
    System.out.println(pbMessage);
  }

    The method of parsing the third layer is controlled by the value of the sensor-path field. Therefore, before parsing the third layer, select different classes based on the sensor-path field. The following is an example of Java code.

    private TelemetryRowGPBData copyTelemetryRowGPB(TelemetryRowGPB rowGpb, String sensorPath) {
TelemetryRowGPBData rowGPBData = new TelemetryRowGPBData();
if (rowGpb != null) {
long timestamp = rowGpb.getTimestamp();
String collectionTimestamp = "0";
try {
collectionTimestamp = timestamp > 0 ? timestampToString(timestamp) : String.valueOf(timestamp);
} catch (Exception e) {
Log.error("copyTelemetryRowGPB timestampToString Exception : " + e.getMessage());
}

rowGPBData.timestamp = collectionTimestamp;
rowGPBData.content = getObject(sensorPath, rowGpb);
}
return rowGPBData;
}

    For the getObject method, data is decapsulated to obtain service data according to the corresponding Java class based on the sensor-path field value. The following is an example of Java code.

    private Object getObject(String sensorPath, TelemetryRowGPB rowGpb) {
Object object = null;
try {
switch (sensorPath) {
case "huawei-ifm:ifm/interfaces/interface":
object = Ifm.parseFrom(rowGpb.getContent());
break;

case "huawei-devm:devm/cpuinfos/cpuinf":
object = Qos.parseFrom(rowGpb.getContent());
break;
...
default:
Log.error("sensorPath : " + sensorPath + ", TelemetryRowGPB :" + rowGpb);
break;
}
} catch (InvalidProtocolBufferException e) {
Log.error("getObject InvalidProtocolBufferException : " + e.getMessage());
}

return object;
}

  2. Register the created class with the gRPC service framework.

    After the RPC service code is developed, register the created class with the gRPC service framework. When the device requests the RPC to push data, the gRPC service framework automatically calls the registered function to implement decoding.

    For example, use Netty to start the listening port. The following is an example of Java code.

    Java Code

    Description

    public void start(int port) throws IOException {

    NettyServerBuilder builder = NettyServerBuilder.forPort(port).flowControlWindow(500);

    server = builder.addService(dataServiceImpl).build().start();

    }

    Netty is used to listen on the port and bind services. dataServiceImpl is generated through dataServiceImpl = new GrpcDataServiceImpl (). The dataServiceImpl class is the class created in the first step.

After the preceding operations are complete, the collector is interconnected. The .proto files of other services are processed in similar ways.

The overall development roadmap is the same if the collector software is developed using Python or C++.
