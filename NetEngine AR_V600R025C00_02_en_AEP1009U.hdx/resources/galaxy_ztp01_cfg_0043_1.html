Understanding Streamlined USB-based Deployment

For details about the supported models, see "Version Requirements" in SD-WAN Solution & iMaster NCE-Campus Product Documentation.

Deployment Process

Traditional USB-based deployment requires engineers to make deployment files. Streamlined USB-based deployment requires only ZTP parameters to be configured on iMaster NCE-Campus, and then deployment files will be automatically generated, simplifying the USB-based deployment process. Figure 1 shows the deployment process.

Figure 1 Streamlined USB-based deployment process
  1. Configuring and deploying the network

    The network administrator logs in to iMaster NCE-Campus, enters the device ESN, and configures network deployment parameters.

  2. Sending the intermediate file and deployment configuration file automatically generated by iMaster NCE-Campus to the deployment person
    The network administrator configures parameters for streamlined USB-based deployment on iMaster NCE-Campus to generate the intermediate file USB_AR_V600.INI and deployment configuration file ZTP_V600.INI. For details about the fields in the intermediate file, see Understanding an Intermediate File. For details about the fields in the deployment configuration file, see Understanding the Deployment Configuration File.

    The file system format of a USB flash drive must be FAT32 or EXT4, and its port must support USB 2.0 or later. The device does not support Solid State Disk (SSDs) with USB ports.

  3. Saving the intermediate file and deployment configuration file to the USB flash drive

    After receiving the intermediate file and deployment configuration file, the deployment person saves them to the root directory of the USB flash drive.

  4. Powering on the device and inserting the USB flash drive
    After the unconfigured device is powered on and starts, the deployment person inserts the USB flash drive into the device, which then automatically loads the deployment configuration file based on the intermediate file and starts the deployment.
    1. The device is powered on and starts. After detecting the USB flash drive, the device enters the USB-based deployment process.
    2. The device reads the intermediate file in the root directory of the USB flash drive and obtains the deployment configuration file from the default directory specified by the intermediate file, that is, the root directory of the USB flash drive.
    3. The device parses the deployment configuration file to deliver related configurations and saves the delivered configurations as the configuration file for next startup.
  5. Automatically connecting to the network and registering with iMaster NCE-Campus
    1. After the device completes configurations, it automatically connects to the network based on the network access mode configured in the deployment configuration file. Streamlined USB-based deployment supports the following network access modes: static, DHCP, and Long-Term Evolution (LTE) dial-up.
    2. The device automatically initiates a NETCONF registration request to iMaster NCE-Campus based on the address and port number of iMaster NCE-Campus in the deployment configuration file. If the registration succeeds, the deployment process ends. If the registration fails, the deployment person needs to locate the fault. After the fault is rectified, the device initiates registration with iMaster NCE-Campus again.
  6. Removing the USB flash drive after the deployment is complete

    After the deployment is complete, the deployment person removes the USB flash drive.

  • When deploying an unconfigured device, you are advised not to manually deliver the same configurations as those delivered during ZTP. Doing so will cause the configurations to be deleted if the deployment fails.
  • ZTP depends on OPS. You can run the display ops process current command to obtain the task ID, which indicates the ZTP process ID, and then run the ops stop process process-id command to stop the ongoing ZTP process. This operation, however, may cause the configurations that have been delivered during ZTP to be retained on the device.
