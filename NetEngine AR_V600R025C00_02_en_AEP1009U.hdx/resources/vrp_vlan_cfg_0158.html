Understanding Voice VLANs

Definition and Classification of Voice VLANs

A voice VLAN is a dedicated VLAN used to transmit voice traffic.

Multiple types of traffic, such as data, voice, and video, are transmitted on a network simultaneously. Packet loss and delay have a great impact on the quality of voice services. Users are more sensitive to the quality of voice services than that of data or video services. Therefore, the quality of voice services must be ensured preferentially when the bandwidth is limited. To achieve this, you can configure a voice VLAN on the device. The device then can identify voice traffic, add the voice VLAN tag to the voice traffic for transmission in the voice VLAN, and provide QoS services for preferentially transmitting voice traffic in the case of network congestion.

The device configured with a voice VLAN can identify voice data packets in either of the following modes:

  • Based on source MAC addresses in received packets

    The device determines whether a data packet received by an interface is a voice data packet based on the source MAC address field in the packet. When the source MAC address in a data packet matches the organizationally unique identifier (OUI) that has been preconfigured in the system for a voice device, the device considers the data packet as a voice data packet. Such a preconfigured OUI applies to the scenario where IP phones send untagged voice packets.

  • Based on VLAN IDs in received packets

    It takes a long time to configure OUIs for IP phones if many of them are connected to the device. Instead, you can configure the device to increase the priority of voice data packets based on VLAN IDs. The device then determines whether a data packet received by an interface is a voice data packet based on the VLAN ID in the packet. When the VLAN ID in a data packet matches the voice VLAN ID configured in the system, the device considers the data packet as a voice data packet. For this mode to work, the IP phones must be able to obtain the information about the voice VLAN configured on the device. When many IP phones are connected to the device, the configuration can be simplified.

The solutions above simplify configurations. Whether or not the voice packets sent by IP phones are VLAN-tagged does not impact the device's ability to identify voice packets based on MAC addresses and VLAN IDs. Therefore, if IP phones send tagged voice packets, you can simply configure the voice VLAN function based on VLAN IDs, simplifying the configurations. However, if the packets are untagged, OUIs must be configured to distinguish voice packets from data packets.

MAC Address-based Voice VLAN

  • OUI

    An OUI refers to the first 24 bits of a MAC address and can be used to identify a MAC address range. The Institute of Electrical and Electronics Engineers (IEEE) assigns a unique OUI to each vendor. In addition, each vendor assigns another 24 bits to form a 48-bit MAC address. Therefore, voice packets from IP phones can be identified by the OUIs allocated to IP phone vendors based on MAC address ranges requested by IP phone vendors.

    An OUI in voice VLAN is different from a standard OUI. It is user-configured and can use a mask, whose length is not restricted to 24 bits but can be instead specified by the user. The OUI is the result of the AND operation between the values of the mac-address and oui-mask parameters in the voice-vlan mac-address command.

  • Implementation
    Figure 1 illustrates MAC address-based voice VLAN. After receiving untagged packets from the PC and IP phone, the device processes the packets as follows: If the source MAC address matches the OUI configured on the device (that is, the result of the AND operation between the source MAC address and the configured OUI mask is the same as the OUI), the device adds the voice VLAN tag to the packets and increases the packet priority, ensuring that the voice packets are sent preferentially. If the source MAC address does not match the configured OUI, the device adds the default VLAN tag (PVID) to the packets.

VLAN ID-based Voice VLAN

VLAN ID-based voice VLAN is implemented as follows:

After receiving packets from a PC and an IP phone, the device checks whether the VLAN ID of the packets is the same as the voice VLAN ID configured on the interface. If they are the same, the device considers the data packets as voice data packets and increases the packet priority. The device adds the default VLAN tag (PVID) to the untagged packets sent by the PC. Therefore, when VLAN ID-based voice VLAN is configured, the IP phone must be able to obtain the information about the voice VLAN configured on the device.

There are various ways in which IP phones can obtain voice VLAN information from the device. Figure 2 illustrates this process through LLDP.

Figure 2 VLAN ID-based voice VLAN
  1. In Figure 2, when the IP phone goes online, it sends an LLDPDU to the device to obtain the information about the voice VLAN configured on the device.
  2. After receiving the LLDPDU, the device adds the voice VLAN information to the response LLDPDU and sends it to the IP phone.
  3. After receiving the LLDPDU carrying the voice VLAN information, the IP phone sends tagged voice packets.
  4. The device receives the tagged voice packets. If the VLAN ID in the packets matches the voice VLAN ID configured on the device, the device increases the priority of the packets and forwards them.

After receiving untagged packets, the device still sends them in the VLAN specified by the PVID. In this way, the device sends voice packets preferentially when congestion occurs.

Secure and Common Modes of Voice VLANs

A voice VLAN can work in secure or common mode, depending on how the interface enabled with the voice VLAN function filters received data packets.

Table 1 describes these two voice VLAN working modes.

Table 1 Secure and common modes of voice VLANs

Mode

Scenario

Packet Processing

Precaution

Secure mode

The inbound interface enabled with the voice VLAN function allows only the received voice packets whose source MAC addresses match the OUI to pass through, discards non-voice packets from the voice VLAN, and forwards packets from other VLANs.

If the source MAC address of a packet does not match the OUI, the packet priority is not changed and the packet cannot be forwarded in the voice VLAN.

If the source MAC address of a packet matches the OUI, the packet priority is changed and the packet is allowed to be forwarded in the voice VLAN.

The secure mode takes effect only when the device is configured to increase the priority of voice packets based on MAC addresses.

Common mode

The inbound interface enabled with the voice VLAN function allows both voice packets and non-voice packets to pass through. In this mode, the interface is vulnerable to attacks from malicious data traffic.

If the source MAC address of a packet does not match the OUI, the packet priority is not changed and the packet is allowed to be forwarded in the voice VLAN.

If the source MAC address of a packet matches the OUI, the packet priority is changed and the packet is allowed to be forwarded in the voice VLAN.

It is not recommended that a VLAN be used to transmit both voice and data traffic. If a voice VLAN must be used to transmit both voice and data traffic, ensure that it works in common mode.
