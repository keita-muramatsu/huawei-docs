Configuring the Portal Server Function

Context

To ensure proper communication between the device and a Portal server for authentication, configure the following information:
  • Portal server template: manages the Portal server's parameters, such as the IP address.
  • Parameters for information exchange with the Portal server: When the device connects to the Portal server, you need to configure information such as the Portal protocol version, to ensure proper communication and security.

Procedure

  • Configure a Portal server template.

    1. Enter the system view.
      system-view

    2. Create a Portal server template and enter its view.

      web-auth-server server-name

      By default, no Portal server template is created.

    3. Configure the local gateway address used by the device to receive and respond to the packets sent by the Portal server.
      server-source ip-address ip-address

      By default, the device does not receive any packets from the Portal server.

      If Portal authentication is enabled on the device, you need to configure the local gateway address used by the device to receive and respond to the packets sent by the Portal server. You can use either of the following methods to configure the address:

      • Run the web-auth-server server-source all-interface command in the system view.
      • Run the server-source ip-address ip-address command in the Portal server template view.

    4. Set the protocol used in Portal authentication to Portal.

      protocol portal

      By default, the Portal protocol is used in Portal authentication.

    5. Configure an IP address for the Portal server.

      server-ip ip-address &<1-10>

      By default, no IP address is configured for a Portal server.

    6. Configure the shared key used by the device to exchange information with the Portal server.
      shared-key cipher key-string

      By default, no shared key is configured for the device to exchange information with the Portal server.

    7. (Optional) Configure the source IP address used by the device to communicate with the Portal server.

      • Configure the source IP address used by the device to communicate with the Portal server.
        source-ip ip-address
      • Configure the IP address of a specified interface as the source IP address used by the device to communicate with the Portal server.
        source-interface interface-type interface-number

      By default, no source IP address is configured for the device to communicate with the Portal server.

    8. Configure the destination port number used by the device to send packets to the Portal server.

      port port-number [ all ]

      By default, the device uses the destination port number 50100 to send packets to the Portal server.

    9. (Optional) Configure a VPN instance for the device to communicate with the Portal server.
      vpn-instance vpn-instance-name

      By default, no VPN instance is configured for the device to communicate with the Portal server.

    10. (Optional) Disable the Portal authentication redirection function.

      web-redirection [ ipv6 ] disable

      By default, the Portal authentication redirection function is enabled.

      The device redirects all unauthenticated users to the Portal authentication page when the users send HTTP access requests to external networks. However, in some special scenarios (for example, users need to manually enter the URL of the authentication page), you can run this command to disable the Portal authentication redirection function.

      The web-redirection disable command disables Portal authentication redirection for IPv4 and IPv6 packets. The web-redirection ipv6 disable command disables Portal authentication redirection for IPv6 packets.

  • Configure parameters for information exchange with the Portal server.

    1. Enter the system view.
      system-view
    2. Set the Portal protocol version supported by the device.
      web-auth-server version v3 [ v2 [ v1 ] ]

      By default, the device supports Portal 1.0, Portal 2.0, and Portal 3.0.

      Portal 1.0 does not perform security verification. The difference between Portal 2.0 and Portal 3.0 lies in the authentication field length and the used algorithm. Portal 2.0 uses the MD5 algorithm to authenticate packets, and the authentication field is 16 bytes. Portal 3.0 uses the SHA256 algorithm, which is more secure, to authenticate packets, and the authentication field is 32 bytes.
      • To ensure proper communication, you are advised to use the default device setting so that the device supports the three versions.
      • Currently, the commonly used Portal protocol version is Portal 2.0. Before using Portal 3.0 for interconnection, ensure that the interconnected Portal server supports Portal 3.0. Otherwise, the interconnection fails.
    3. Configure a port number used by the device to listen to Portal protocol packets.
      web-auth-server listening-port port-number

      By default, the device listens to Portal protocol packets through port 2000.

    4. Enable the device to transparently transmit the user authentication responses sent by the authentication server to the Portal server.
      web-auth-server reply-message enable

      By default, the device transparently transmits the user authentication responses sent by the authentication server to the Portal server.

    5. Configure a user-defined destination port number for HTTP packets that trigger Portal redirection.

      portal redirect-http-port port-number

      By default, the device redirects unauthenticated users to the Portal authentication page only when their browsers send HTTP packets with the destination port number 80.

    6. Enable HTTPS redirection for Portal or 802.1X authentication.
      authentication https-redirect enable [ ssl-policy policy-name ]

      By default, HTTPS redirection for Portal or 802.1X authentication is disabled.

      • If Portal authentication is triggered when users attempt to access an HTTPS website, the browser displays a security prompt, requiring users to click Continue to complete Portal authentication.
      • Redirection is not supported if the browser or website runs HTTP Strict Transport Security (HSTS).
      • If the destination port in HTTPS request packets sent by users is a non-well-known port (443), redirection cannot be performed.
      • This function takes effect only for new Portal authentication users.
      • This function takes effect only after a Portal server template is created.

    7. Enable Portal redirection.

      portal redirect-mode { redirect-302 | redirect-200 | redirect-js }

      By default, the device uses 200 OK redirection.

    8. Set the number of times that Portal authentication user logout packets are retransmitted and the retransmission interval.

      portal logout resend times timeout period

      By default, Portal authentication user logout packets can be retransmitted three times within five seconds.

    9. Enable the device to process the user logout requests sent by Portal servers other than the one from which users log in.

      portal logout different-server enable

      By default, the device does not process the user logout requests sent by Portal servers other than the one from which users log in.
