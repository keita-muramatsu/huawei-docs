Usage Precautions

Browser Requirements

The following browsers are recommended for logging in to WebMaster:

  • Firefox 107 or later

  • Chrome 107 or later

  • Edge 107 or later

Precautions

  • If the AR connects to a member device through a WAN interface, ensure that the interface has been configured to operate as a LAN interface using the portswitch command.
  • Member devices can be managed only through VLAN 1. Interconnection interfaces need to allow packets from VLAN 1 to pass through, which is a default configuration.
  • For wireless traffic, only direct forwarding can be deployed through WebMaster.
  • WebMaster does not support manual VLAN addition or deletion for interfaces. After you select interfaces connected to wired terminals during wired network deployment and deliver the configuration, all interconnection interfaces on the access, aggregation, and core switches are automatically added to the service VLAN. During wireless network deployment, no interface needs to be selected; after you deliver the configuration, interfaces connected to APs and all interconnection interfaces on the access, aggregation, and core switches are automatically added to the wireless service VLAN.
  • If you need to switch from WebMaster to the web system of a member device, ensure the PC used to log in to WebMaster is on the same network segment as VLANIF 1 on the member device, or on the same network segment as the virtual IP address of the master device.
  • For member devices with non-factory configurations, when configuring them for onboarding, ensure that the AAA username, password, and service type are consistent with those on the master device, and the DHCP client function is enabled on VLANIF 1. For details, see 3.
  • If member devices are switches running V200, ARs running V300, or CloudEngine S5731I series, both incorrect connection detection and blocked port location optimization are not supported. Therefore, if multiple links are configured between interconnection interfaces, you need to manually configure STP to eliminate the loop.
  • When a standalone WAC running V200 is used or an AR running V300 functions as a WAC, wireless services need to be deployed through the web system or CLI.
  • WebMaster does not support stack setup. You need to set up a stack using commands or dedicated stack cables and then manage the stack.
  • Switches running V200 cannot be managed by the master device in the following situations:
    • Devices are manufactured in March 2022 or earlier. You can check the production date on the device nameplate.
    • The display local certificate information command output contains the character & on devices.
  • Faulty device replacement:
    • Faulty member devices running V600R023C00 or a later version support configuration-free replacement with devices of the same model running V600R024C10 or a later version in the same topology.
    • The software version of the new device cannot be earlier than that of the faulty member device.
    • Each member device saves its configuration file to the master device every 30 minutes. If a member device fails but its latest configuration file has not been saved to the master device, the unsaved configuration will be lost after the member device is replaced.
    • The master device does not support configuration-free replacement.
    • Member devices can be replaced only when they are offline.
  • If the upper-layer devices of the S5751R-L, S3510-S, and S5731I-L are not managed by the master device, the master device may not be able to obtain correct topology information of the S5751R-L, S3510-S, and S5731I-L.
  • Only switches running V600 and AR routers running V600 support Eth-Trunk auto-negotiation. If V200 switches, V300 AR routers, or S5751R-L series switches are deployed on the network, Eth-Trunk auto-negotiation is not supported.
  • Eth-Trunk auto-negotiation is not supported on ERPS rings.
