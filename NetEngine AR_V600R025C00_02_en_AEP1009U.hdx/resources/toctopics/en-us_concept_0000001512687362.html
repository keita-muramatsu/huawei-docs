URL Matching Rules

URL Format

A URL uniquely identifies the address of a web page or other types of resource on the Internet. A URL is in the format "protocol://hostname:port/path?query". Table 1 describes the parameters in the format.

Table 1 Description of the parameters in the URL format

Field

Description

protocol

Application protocol used, with HTTP or HTTPS being the most common one.

hostname

Domain name or IP address of the web server.

:port

(Optional) Communication port. Application protocols have their respective default port numbers; for example, the default HTTP port is 80, and the default HTTPS port is 443. If the server uses the default port, you do not need to configure the port number in a URL filtering rule. If the server uses a non-default port number, the port number is mandatory in a URL filtering rule.

path

Directory or file path on the web server. The path is a character string that can be separated by slashes (/).

?query

(Optional) Used for transfer parameters to dynamic web pages.

Figure 1 URL example

  • 8088: indicates the communication port.

  • name=tom&age=20: indicates the parameter part.

URL Rule and Matching Mode

You can add URL rules and HOST rules in the blacklist and whitelist. A URL rule matches all parts of a URL, while a HOST rule matches only the hostname value (domain name or IP address). The two types of rules apply to the following scenarios:
  • For filtering URLs that are domain names (for example, www.example.com), both URL rules and host rules apply in most cases and have the same filtering effect.
  • For filtering URLs that contain a path or parameter information (for example, www.example.com/news), only URL rules apply.

When configuring URL rules and HOST rules, certain conditions must be met, otherwise the configuration will not take effect. The specific conditions for the two rules are as follows:

  • The URL rule is added in the form of a character string.
    • The string cannot contain the question mark (?).
    • The string cannot start with a slash (/) or backslash (\).
    • When an asterisk (*) is used, there must be at least three characters that are not the asterisk (*) before or after the asterisk (*) and the last character is not a dot (.). For example, ab.* or *ab. is not supported.
    • When using #, ensure that at least three characters are not # before # and the last character is not a dot (.). For example, ab.# is not supported.
    • When using spaces, enclose the string that contains spaces with double quotation marks ("") and ensure that the double quotation marks are in pairs, for example, "abc def".
    • f the entered character string contains the prefix http:// or https://, the device removes the prefix when storing the rule.
    • If the URL rule contains double quotation marks, use %22 to escape the character string, for example, "abc%22def".
  • The HOST rule is added in the form of a character string.
    • The string cannot contain special characters (including /, \, #, and ?) or spaces.
    • When an asterisk (*) is used, there must be at least three characters that are not the asterisk (*) before and after the asterisk (*) and the last character is not a dot (.). For example, ab.* or *ab. is not supported.
    • f the entered character string contains the prefix http:// or https://, the device removes the prefix when storing the rule.

URL matching modes include prefix matching, suffix matching, keyword matching, and exact matching. Both URL rules and HOST rules support these matching modes. Table 2 compares these modes.

Table 2 URL matching modes

Matching Mode

Function

Configuration Example

Prefix matching

Matches all URLs starting with a specified string, such as www.example*.

To control access to all websites starting with www.example, configure the URL filtering rule www.example*.

Suffix matching

Matches all URLs ending with a specified string, such as *aspx.

To control access to all image web pages, configure the URL filtering rules *.jpg, *.jpeg, *.gif, *.png, and *.bmp.

Keyword matching

Matches all the URLs containing a specified character string, such as *sport* and www.*ample.com.

To control access to all websites containing the word sport, configure the URL filtering rule *sport*.

To control access to all the websites starting with www. and ending with ample.com, configure the URL filtering rule www.*ample.com.

Exact matching

The system checks whether a URL matches the specified string. If not, the system removes the last directory from the URL and matches the URL with the specified string. If the URL is still not matched, the system removes the last directory from the URL and matches the URL with the specified string. The process repeats until the URL contains only the domain name, for example, www.example.com.

To control access to a fixed website such as www.example.com/news, configure the URL filtering rule www.example.com/news.

The priorities of URL matching modes are as follows:

Exact matching > suffix matching > prefix matching > keyword matching

For example, URL www.example.com/news first matches www.example.com/news in the following prefix matching rules:
  • Exact matching: www.example.com/news
  • Prefix matching: www.example.com/*
  • Keyword matching: *example*
In the same matching mode, a long matching rule is assigned a higher priority than a short one. For example, URL www.example.com/news/index.html first matches www.example.com/news/* in the following prefix matching rules:
  • www.example.com/news/*
  • www.example.com/*
