(Optional) Configuring Connection-based QoS

Prerequisites

Before configuring connection-based QoS, configure a traffic policy for each application. For details, see "Configuring CBQ" in "HQoS Configuration" in CLI-based Configuration > QoS Configuration.

This function is supported only on the AR6700-H series and AR8000 series.

In the SD-WAN EVPN dual-gateway site scenario, connection-based QoS can be used only after smart policy routing is configured and the local-network-prefer enable command is run to enable smart policy routing to preferentially select a local network link.

Context

Connection-based QoS is also called dynamic QoS. In the SD-WAN EVPN scenario, the link bandwidth of the HQ/DC (hub) is usually much higher than that of a branch (spoke). Traffic sent from the hub side may cause congestion on a branch link, leading to random packet loss. As a result, experience of key applications cannot be ensured. In this case, QoS policies can be configured on the hub based on the bandwidth of each branch link to implement differentiated rate limiting in advance, preventing network congestion and random packet loss and ensuring lossless key applications.

Procedure

  • Configure connection-based QoS on the hub.
    1. Enter the system view.

      system-view

    2. Create a site group and enter the site group view.

      evpn site-group name

    3. Add a peer site to the site group.

      peer-site { site-id | all } [ bandwidth percentage bandwidth-value ]

      By default, no peer site is added to a site group.

    4. Apply a traffic policy to the site group.

      traffic-policy policy-name outbound

      By default, no traffic policy is applied to a site group.

    5. (Optional) Specify a transport network and enable connection-based QoS based on the transport network to which the source TNP belongs.

      transport-network transport-network-name

      By default, no transport network is specified for a site group.

    6. Return to the system view.

      quit

    7. Enter the main interface view or create a sub-interface and then enter the sub-interface view.

      interface interface-type interface-number

    8. Configure the shaping rate for the interface.

      qos lr cir cir-value [ kbps | mbps | gbps ] [ cbs cbs-value [ bytes | kbytes | mbytes ] ] [ outbound ]

      By default, the traffic shaping rate of an interface is the maximum bandwidth of the interface.

    9. Apply a traffic policy to the interface.

      traffic-policy policy-name { inbound | outbound } [ preprocess | firstprocess ]

      By default, no traffic policy is applied to an interface.

      The traffic policy specified in this step is an escape policy. When configuring an escape policy on a sub-interface, you need to run the qos queue-scheduling enable command to enable the queue capability on the sub-interface.

  • Configure the hub-side downlink bandwidth on the spoke.
    1. Enter the system view.

      system-view

    2. Enter the site view.

      evpn site site-id

    3. Enter the TNP view.

      transport-network-port transport-network-port-id

    4. Configure the TNP inbound bandwidth.

      bandwidth input bandwidth-value

      By default, the TNP inbound bandwidth is not configured.
