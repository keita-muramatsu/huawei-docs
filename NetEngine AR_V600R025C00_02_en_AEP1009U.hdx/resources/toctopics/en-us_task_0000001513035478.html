(Optional) Configuring the Traffic Steering Mode in a Policy

Context

SPR supports two traffic steering modes: preferential occupation and load balancing.

  • Preferential occupation: The connection with the best quality on TNs is selected for traffic forwarding.
  • Load balancing: Connections on multiple TNs with the same priority load balance traffic.

On the network shown in Figure 1, Site1 is the local site, and Site2 is the remote site. Traffic is sent from Site1 to Site2. The traffic steering mode is load balancing, and Connection1 through Connection5 are selected for traffic steering. The outbound bandwidth values of TNP1, TNP2, TNP5 are 600 Mbit/s, 400 Mbit/s, and 50 Mbit/s, respectively. The inbound bandwidth values of TNP3, TNP4, and TNP6 are 80 Mbit/s, 20 Mbit/s, and 20 Mbit/s, respectively. The principles for calculating the bandwidth weights of connections are as follows:

  1. Connections are grouped by TNP, meaning that connections with overlapping TNPs are added to the same group. The grouping rules are as follows: First, the system finds an ungrouped connection, for example, Connection1. The system creates group A for Connection1 and searches for an ungrouped connection that has the same source or destination TNP as Connection1. The system finds that Connection2 has the same source TNP as Connection1 and Connection3 has the same destination TNP as Connection1, and so adds them to group A. Similarly, the system searches for an ungrouped connection that has the same source or destination TNP as Connection2. The system finds that Connection4 has the same destination TNP as Connection2, and so adds it to group A. When the system searches for ungrouped connections that have the same source or destination TNP as Connection3 and Connection4, no such ungrouped connection is found. Adding connections to group A is complete. Similarly, Connection5 is added to group B. To sum up, Connection1, Connection2, Connection3, and Connection4 are added to one group (group A), and Connection5 is added to another group (group B).
  2. The system determines the available bandwidth of a group and uses the smaller value between the total inbound bandwidth and the total outbound bandwidth. The total outbound bandwidth of group A is the sum of the outbound bandwidth values of TNP1 and TNP2, which is 1000 Mbit/s. The total inbound bandwidth of group A is the sum of the inbound bandwidth values of TNP3 and TNP4, which is 100 Mbit/s. Therefore, 100 Mbit/s is used as the available bandwidth of group A. The available bandwidth of group B, calculated in a similar way, is 20 Mbit/s.
  3. The system determines the connection bandwidth ratio based on the inbound and outbound TNP bandwidth ratios. The bandwidth ratio of TNP1 is 600 Mbit/s/(600 Mbit/s + 400 Mbit/s) = 0.6, and the bandwidth ratio of TNP3 is 80 Mbit/s/(80 Mbit/s + 20 Mbit/s) = 0.8. Therefore, the bandwidth ratio of Connection1 enumerated by TNP1 and TNP3 is 0.6 x 0.8 = 0.48. The system determines the actual bandwidth weight of a connection based on the available bandwidth of the group and the bandwidth ratio of the connection. The actual bandwidth weight of Connection1 is 100 x 0.48 = 48. The actual bandwidth weights of Connection1, Connection2, Connection3, Connection4, and Connection5 are 48, 12, 32, 8, and 20, respectively. The sum of the weights is 120.

When the actual rate of traffic passing through the connections is 100 Mbit/s, the actual traffic allocated to Connection1 is 100 Mbit/s x 48/120 = 40 Mbit/s. Similarly, the actual traffic allocated to Connection2, Connection3, Connection4, and Connection5 is 10 Mbit/s, 26.6 Mbit/s, 6.7 Mbit/s, and 16.7 Mbit/s, respectively.

For TNs with different priorities, the preferential occupation mode is recommended. For TNs with the same priority, the load balancing mode is recommended, as this mode improves bandwidth utilization while ensuring service experience.

When you configure the bandwidth threshold in a policy profile, link bandwidth thresholds, and application bandwidth thresholds, the traffic steering behavior varies according to the traffic steering mode:

  • Preferential occupation:
    • Upper bandwidth threshold: the switchover threshold for traffic steering. When the bandwidth usage of a link (or application bandwidth usage of a link) exceeds the upper bandwidth threshold (or upper application bandwidth threshold), the connection corresponding to the link does not meet the traffic steering conditions. Traffic is then switched to the connection corresponding to another link that meets the conditions.
    • Lower bandwidth threshold: the switchback threshold for traffic steering. When the bandwidth usage of a link (or application bandwidth usage of a link) falls below the lower bandwidth threshold (or lower application bandwidth threshold), the link meets the traffic steering conditions again. If the switchback function is configured, traffic is switched back to the connection corresponding to the link.
  • Load balancing:
    • When the bandwidth usage of a link (or application bandwidth usage of a link) falls below the lower bandwidth threshold (or lower application bandwidth threshold), both existing and new flows can be transmitted over the link. (The existing and new flows are distinguished based on 5-tuple information. If the 5-tuple information remains unchanged, the flows are existing flows. Otherwise, the flows are new flows.)
    • When the bandwidth usage of a link (or application bandwidth usage of a link) is between the lower and upper bandwidth thresholds (or lower and upper application bandwidth thresholds), existing flows continue to be transmitted over the link and new flows are switched to a low-priority link.
    • When the bandwidth usage of a link (or application bandwidth usage of a link) exceeds the upper bandwidth threshold (or upper application bandwidth threshold), both existing and new flows are switched to a low-priority link.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the SPR configuration view.

    smart-policy-route

  3. (Optional) Enable the function of calculating link quality based on bandwidth for SPR.

    link-quality based bandwidth enable

    By default, the function of calculating link quality based on bandwidth is enabled. This function takes effect only in load balancing mode.

  4. Configure the bandwidth threshold for SPR.

    bandwidth-threshold threshold-value

    By default, the bandwidth threshold for SPR is 95%. This function takes effect only in load balancing mode.

  5. Enter the policy profile view.

    spr-policy node node-index

  6. Configure the traffic steering mode in the SPR policy.

    routing-mode { path-prefer | load-balance }

    By default, the traffic steering mode in a policy is preferential occupation.

    When the traffic steering mode is set to load balancing, you need to run the bandwidth { input | output } bandwidth-value command on the CPE to configure the outbound bandwidth of the TNP.

  7. Configure the bandwidth threshold in the policy profile.

    bandwidth-threshold { lower-limit percentage lower-limit-percentage | upper-limit percentage upper-limit-percentage } *

    By default, no bandwidth threshold is configured in a policy profile.

  8. (Optional) Configure the application priority of the policy profile.

    application-priority priority

    By default, the application priority of a policy profile is not configured. This function takes effect only in load balancing mode.

  9. (Optional) In SPR policy-based load balancing mode, configure the function of ignoring the bandwidth threshold for traffic. (After the bandwidth threshold is configured for the first time, perform this step if you want to ensure that the configuration takes effect only for subsequent traffic and not for previous traffic.)

    traffic-hold bandwidth-ignore enable

    By default, the function of ignoring the bandwidth threshold for traffic is disabled in an SPR policy profile.

  10. Associate the policy with a link and enter the link configuration view.

    link transport-network name [ id id ]

    By default, a policy is not associated with a link.

  11. Configure link bandwidth thresholds.

    link-bandwidth-threshold lower-limit { percentage lower-limit-percentage | value lower-limit-value } upper-limit { percentage upper-limit-percentage | value upper-limit-value }

    By default, no link bandwidth threshold is configured.

  12. Configure application bandwidth thresholds.

    application-bandwidth-threshold lower-limit { percentage lower-limit-percentage | value lower-limit-value } upper-limit { percentage upper-limit-percentage | value upper-limit-value }

    By default, no application bandwidth threshold is configured.
