Configuring FEC

Context

For applications that are sensitive to packet loss and latency, such as video applications, you can configure FEC to mitigate packet loss for specific application traffic. This prevents frame freezing and ensures smooth application experience. When configuring FEC, you need to configure both the transmit and receive ends.

Table 1 describes the FEC policy parameters that you can modify based on your network conditions to achieve optimal user experience.

Table 1 FEC policy parameters

Parameter

Description

Recommended Configuration

FEC-correctable packet loss rate (packet-loss-ratio-value)
  • D-FEC: These parameters together determine the number of redundant packets generated during an FEC encoding. If the number of redundant packets calculated based on packet-loss-ratio-value is less than the value of burst-packet-loss-value, the number of generated redundant packets is the value of burst-packet-loss-value.
  • A-FEC: The two parameters do not take effect on A-FEC.

Set this parameter based on the packet loss situation on the network. The configured correctable packet loss rate must be greater than the actual packet loss rate.

Number of recoverable lost packets in a burst (burst-packet-loss-value)

Multiple packets may be lost in a burst. Set this parameter based on the packet loss rate on the network. The value must be greater than the number of lost packets in a burst.

Size of an FEC encoding block (block-size-value)

These parameters together determine the number of original packets in an FEC encoding. From the time when the first original packet is received in an encoding block:

  • When the number of original packets in an encoding block reaches the value of block-size-value within the timeout duration specified by timeout-value, the device starts generating redundant packets.
  • If the number of original packets in an encoding block does not reach the value of block-size-value within the timeout duration specified by timeout-value, the device starts generating redundant packets based on the accumulated original packets when the timeout duration expires.

Set this parameter based on the rate of network packets.

  • If this parameter is set to a small value, the traffic rate will be stable. If packet loss occurs on the network, the decoding end will quickly recover lost packets, but the packet loss correction effect is poor.
  • If this parameter is set to a large value, the decoding end will take a long time to recover lost packets.

Timeout duration for generating FEC redundant packets (timeout-value)

Set this parameter based on the rate of network packets.

Maximum transmission unit (MTU) before FEC encoding (mtu-value)

If an FEC-encoded packet is fragmented because its size exceeds the MTU of the outbound interface, FEC will be unable to correct for lost packets. As such, the packet size before FEC encoding needs to be limited.
  • If the MTU before FEC encoding is too small, unnecessary fragments are generated, degrading the device processing performance.
  • If the MTU before FEC encoding is too large, the packet loss correction effect is poor.

You are advised to set this parameter to half of the network MTU and ensure that the difference between the network MTU and the MTU before FEC encoding is greater than the maximum length of an FEC header (84 bytes).

Procedure

  1. Enter the system view.

    system-view

  2. Enter the FEC configuration view.

    forward-error-correction

  3. Configure an FEC service profile.
    1. Create an FEC service profile and enter its view.

      service-map name

    2. Bind an ACL, application, or application group to the service profile.

      match acl { acl-number | acl-name } application application-name
match acl { acl-number | acl-name }
match application-group application-group-name
match acl { acl-number | acl-name } application-group application-group-name
match application application-name

      By default, no ACL, application, or application group is bound to a service profile. You can run commands to bind ACLs, applications, or application groups based on your service requirements.

    3. Return to the FEC configuration view.

      quit

  4. Configure an FEC parameter profile.
    1. Create an FEC parameter profile and enter its view.

      fec profile profile-name

    2. Configure the FEC type.

      type { determined-fec | adaptive-fec }

      The default FEC type is determined-fec.

    3. (Optional) Configure the FEC-correctable packet loss rate.

      packet-loss-ratio packet-loss-ratio-value

      By default, the FEC-correctable packet loss rate is 20%.

    4. (Optional) Configure the number of recoverable lost packets in a burst.

      burst-packet-loss burst-packet-lossvalue

      By default, the number of recoverable lost packets in a burst is 3.

    5. (Optional) Configure the size of an FEC encoding block. The device starts generating redundant packets when the number of original packets in an FEC encoding block reaches this value.

      block-size block-size-value

      By default, the size of an FEC encoding block is 12.

    6. (Optional) Set the timeout duration for generating FEC redundant packets.

      timeout timeout-value

      By default, the timeout duration for generating FEC redundant packets is 35 ms.

    7. (Optional) Set the MTU before FEC encoding.

      mtu mtu-value

      By default, the MTU before FEC encoding is 1300 bytes.

    8. Return to the FEC configuration view.

      quit

  5. Configure an FEC policy.
    1. Create an FEC policy and enter its view.

      fec policy policy-name

    2. Bind the FEC service profile and FEC parameter profile.

      binding service-map name fec-profile profile-name precedence precedence-value

    3. Return to the FEC configuration view.

      quit

  6. (Optional) Enable the function of ignoring VPN instances in an FEC instance.

    fec-instance ignore-vpn enable

    By default, the function of ignoring VPN instances in an FEC instance is disabled. This function is supported only in SD-WAN scenarios.

  7. Return to the system view.

    quit

  8. Apply the FEC policy to a tunnel interface.
    1. Create a tunnel interface and enter its view.

      interface tunnel interface-number

    2. Set the encapsulation mode of the tunnel interface to GRE or SD-WAN.

      tunnel-protocol { gre | sd-wan }

      By default, no encapsulation mode is configured for a tunnel interface.

    3. Apply the FEC policy to the tunnel interface.

      fec-policy name

      When an FEC policy is applied to a tunnel interface, the system checks whether the tunnel type is SD-WAN or GRE. After the FEC policy is applied to a tunnel interface, the tunnel type cannot be changed.
