Understanding VDSL Interfaces

VDSL System

As shown in Figure 1, a VDSL system consists of a digital subscriber line access multiplexer (DSLAM) and a customer premises equipment (CPE).
  • A DSLAM is an aggregation device that terminates VDSL packets in a central office.
  • A CPE is a user-side device that provides interfaces for users, modulates and demodulates user data, and uploads the data to a DSLAM by using the VDSL technology.

The device functions as a CPE.

The device supports only the PTM mode. In this mode, the VDSL line transmits Ethernet packets.

In the VDSL system, downstream transmission refers to data transmission from a DSLAM to a CPE, and upstream transmission refers to data transmission from a CPE to a DSLAM. Therefore, VDSL interfaces on the device are upstream interfaces.

VDSL Interface Activation

Interface activation refers to the training between a DSLAM and a CPE. During the training, the two devices negotiate parameters such as the transmission standard, upstream and downstream line rates, and specified noise margin. The two devices check the line distance and status to determine whether they can work properly under the existing conditions. If the training succeeds, the DSLAM establishes a connection with the CPE. VDSL interfaces on the DSLAM and CPE are then activated and can transmit services between the two devices.

After the CPE is started, the VDSL interface is automatically activated.

VDSL Interface Parameters

VDSL interface parameters include the bit exchange status, seamless rate adaptation status, and trellis coding status.

Bit Exchange

During line activation, the signal-to-noise ratio (SNR) and the number of bits to be transmitted are independently calculated for each sub-channel. However, the SNR may change due to environmental factors after the line is activated. For example, the SNRs of some sub-channels reduce, whereas the SNRs of some other sub-channels increase. The line may be disconnected after an extended period. Bit exchange moves some bits from sub-channels with low SNRs to those with high SNRs. Alternatively, it decreases the transmit power for sub-channels with high SNRs and increases the transmit power for those with low SNRs in order to increase the low SNRs. This dynamic adjustment reduces the bit error rate without triggering line renegotiation.

Seamless Rate Adaptation

When the external environment changes, you can enable the bit exchange function to adjust either the bit distribution, or the power among sub-channels without deactivating the line, in order to prevent line disconnection. The bit exchange function, however, cannot change the line rate. When the line environment degrades, the bit exchange function alone cannot meet the requirement for the bit error rate. In this case, the bit exchange function just allows the line to be re-negotiated and activated at a lower rate. When the line environment improves, the bit exchange function cannot adjust the rate. As such, line resources cannot be effectively used.

Seamless rate adaptation solves the preceding problem. It dynamically adjusts the line rate without reactivating the line.

Trellis Coding

Trellis coding increases the SNR gain by using a coding algorithm with a high coding efficiency. The line activation rate is greatly increased after trellis coding is enabled.
