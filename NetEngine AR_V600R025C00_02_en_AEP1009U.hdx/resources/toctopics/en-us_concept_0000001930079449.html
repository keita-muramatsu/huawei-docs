L2TP Implementation

Typical Networking

Figure 1 shows the typical L2TP networking. An enterprise branch establishes an L2TP connection with the HQ through the Internet. The devices involved in the networking include the L2TP access concentrator (LAC) and L2TP network server (LNS).

Figure 1 Typical L2TP networking

LAC

An LAC, also known as an L2TP client, is a device that has PPP and L2TP processing capabilities. It establishes an L2TP connection with an LNS based on the user name or domain name in PPP packets to extend PPP negotiation to the LNS. An L2TP client is typically the gateway of an enterprise branch.

An L2TP client can establish multiple L2TP tunnels to isolate data flows.

LNS

An LNS acts as the side that terminates a PPP session. After passing the authentication performed by an LNS and succeeding in PPP session negotiation, an enterprise branch can access resources at the enterprise HQ. For L2TP negotiation, the LNS is the peer device of the L2TP client, and L2TP tunnels can be established between the L2TP client and LNS. For a PPP session, the LNS is the logical termination endpoint of the PPP session, and a point-to-point virtual link can be established between a PPP terminal and the LNS.

The LNS is located at the border between the HQ private network and the public network, and typically functions as the HQ gateway. If required, the LNS provides the network address translation (NAT) function to translate private IP addresses on the HQ network into public IP addresses.

Tunnel and session

There are two types of connections during the L2TP interaction between the L2TP client and LNS.

  • Tunnel connection

    Multiple L2TP tunnels can be established between a pair of L2TP client and LNS. An L2TP tunnel can contain multiple L2TP sessions.

  • Session connection

    An L2TP session is carried over an L2TP tunnel after the tunnel is successfully established. Each L2TP session corresponds to a PPP session. Data frames of the PPP session are transmitted through the L2TP tunnel over which the L2TP session is carried.

L2TP Tunnel Negotiation

After L2TP is configured on the L2TP client and LNS, the L2TP client sends a tunnel negotiation request to the LNS. Figure 2 shows the tunnel negotiation process.

Figure 2 L2TP tunnel establishment process

  1. The L2TP client establishes an L2TP tunnel with the LNS.

  2. The L2TP client establishes an L2TP session with the LNS.

    The L2TP session is used to record and manage the status of a PPP connection, which will be established between the L2TP client with the LNS in step 3. In this context, both ends of the tunnel need to negotiate an L2TP session before establishing a PPP connection.

  3. The L2TP client establishes a PPP connection with the LNS.

    The L2TP client obtains a private IP address assigned by the LNS through the PPP connection.

  4. An employee in the enterprise branch sends service packets to the server in the enterprise HQ. The packets are encapsulated and decapsulated by the L2TP client and LNS before reaching the peer end.

L2TP Protocol Architecture

L2TP involves two types of messages: control messages and data messages. These messages are transmitted between the L2TP client and LNS. L2TP extends PPP applications through the two types of messages.

  • Control message

    Used to establish, maintain, and tear down L2TP tunnels and session connections. During the transmission of control messages, mechanisms such as message retransmission and periodic tunnel connectivity check are used to ensure reliable transmission of control messages, and flow control and congestion control are supported for control messages.

  • Data message

    Used to encapsulate PPP data frames and transmitted over tunnels. Data messages are transmitted unreliably because lost data messages are not retransmitted. Flow control and congestion control are not supported for data messages.

Figure 3 illustrates the positions and relationships of PPP frames, control messages, and data messages in the L2TP protocol architecture.

Figure 3 L2TP protocol architecture

Control messages are carried over an L2TP control channel for reliable transmission, encapsulated in L2TP headers, and then transmitted over an IP network.

Data messages carrying L2TP-encapsulated PPP frames are transmitted over an unreliable data channel and then transmitted over an IP network.

L2TP uses UDP port 1701, which is used only for initial tunnel establishment. The L2TP tunnel initiator randomly selects an idle port to send packets to port 1701 of the tunnel terminator. After receiving the packets, the tunnel terminator randomly selects an idle port to send packets to the selected port of the L2TP tunnel initiator. Both ends use the selected ports to communicate until the tunnel is torn down.

L2TP Packet Structure

Figure 4 shows the format of L2TP-encapsulated PPP frames generated during dial-up of remote users.

Figure 4 L2TP packet format

An L2TP packet is encapsulated multiple times and is 38 bytes longer than the original packet (42 bytes longer than the original packet if the packet needs to carry the sequence number). This may result in the encapsulated packet being longer than the MTU of the transmitting interface. L2TP does not support packet fragmentation, and so the device must support IP packet fragmentation. When the length of an L2TP packet exceeds the MTU of the transmitting interface, the interface fragments the packet. The receiving interface then reassembles the received fragments into an L2TP packet.

L2TP Packet Encapsulation

Figure 5 shows the packet encapsulation and decapsulation process.

Figure 5 Packet encapsulation process

  1. An employee in the enterprise branch sends a request packet to access an intranet server at the enterprise HQ.

    The PC of the employee forwards the request packet to the L2TP client based on the local route.

  2. The L2TP client receives the packet and performs PPP encapsulation and L2TP encapsulation on the packet through a dialer interface.

    The L2TP client sends the encapsulated packet based on the public network route destined for the Internet.

  3. The LNS receives the packet, removes the L2TP header and PPP header from the packet, and forwards the packet to the HQ intranet server based on the route destined for the intranet.
  4. The HQ intranet server receives the packet and returns a response packet to the PC of the employee.
