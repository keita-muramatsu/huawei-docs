URL Filtering Process

When URL filtering is enabled and a user attempts to access a network resource, the device performs URL filtering on the user's URL access request packet. Figure 1 shows the URL filtering process.

Figure 1 URL filtering process

  1. A user initiates a URL access request. If the data flow matches a security policy with the allow action and this security policy references a URL filtering profile, the URL filtering process is triggered.

  2. The device extracts the URL from the user's URL access request packet.
  3. The device matches the URL against the whitelist.

    • If a match is found, the device permits the request.

    • If no match is found, the device proceeds with the next step.

  4. The device matches the URL against the blacklist.

    • If a match is found, the device denies the request.

    • If no match is found, the device proceeds with the next step.

  5. The device matches the URL against the predefined URL categories in the local cache.
    • If a match is found, the device takes the action configured for the predefined URL category.
    • If no match is found, the device proceeds with the next step.
  6. The device checks whether the remote query server is available.
    • If the remote query server is unavailable, the device takes the default action on the packet.
    • If the remote query server is available, the device performs remote URL category query.
  7. The device checks whether the remote URL category query times out.
    • If the query does not time out, the device processes the packet based on the action configured for the returned predefined URL category.
    • If the query times out, the device processes the packet based on the action configured for query timeout.

As for TCP traffic, if the handling action of the content security service is block, the device sends RST packets to the client or server through the ASE to disconnect TCP connections to block the traffic.
