HTTP or HTTPS Protocol

Overview

The device can interconnect with a client using HTTP or HTTPS:

  • HTTP is a transport protocol that transmits World Wide Web (WWW) data.

  • HTTPS is a secure HTTP and also known as Hypertext Transfer Protocol over Transport Layer Security (HTTP over TLS) or Hypertext Transfer Protocol over Secure Socket Layer (HTTP over SSL). HTTPS uses HTTP for communication and uses SSL or TLS for data encryption.

    HTTPS is primarily used for identity authentication to protect data privacy and integrity.

Client Request Methods

During Portal authentication, the Portal server instructs the client to use HTTP or HTTPS to initiate a Portal authentication request to an access device. The client then sends an authentication request to the access device. The request packet carries the HTTP request method and HTTP request body (the requested data includes the user name, password, and other parameters).

Currently, the device supports the following HTTP request methods:

  • POST: The requested data is enclosed in the body of an HTTP request, and is not a part of a URL. Therefore, the data is not easy to intercept and has high security. This request method is supported on Huawei access devices by default.

  • GET: The requested data is appended to a URL. A question mark (?) separates the URL and data. The data is a part of the URL, so it is visible to all users, is easy to intercept, and has poor security.

After the device receives an authentication request, it parses the request according to parameter names to obtain parameters including the user name and password, and then sends the obtained user name and password to the RADIUS server for authentication. The parameter names in a request must comply with specific specifications. Otherwise, the device cannot parse the request, leading to user authentication failures. Table 1 lists the parameters in a request. For example, after receiving a POST request (username=abc&password=YsHsjx_202203&client_mac=00e0fc123456&initurl=http://portalserver.example.com/login), the device using default parameter names fails to parse the request. This is because the client_mac parameter specifying the user MAC address in the request is different from the default macaddress parameter used on the device.

Therefore, when HTTP or HTTPS is used for Portal authentication, ensure that the parameter names configured on the Portal server are the same as those configured on the device.
