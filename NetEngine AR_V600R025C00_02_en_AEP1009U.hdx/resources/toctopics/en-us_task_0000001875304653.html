Configuring a Portal Server for a Portal Access Profile

Context

To perform Portal authentication on users, you need to configure the Portal server function and then configure the Portal server used by a Portal access profile. When a user using a Portal access profile attempts to access non-free network resources, the user is redirected to the authentication page of the Portal server for Portal authentication.

A Portal server template defines parameters of the Portal server. You need to configure a Portal server for the Portal access profile, that is, bind a Portal server template to the Portal access profile.

To improve Portal authentication reliability, you can bind the backup Portal server template to the Portal access profile. When the primary Portal server is disconnected, users are redirected to the backup Portal server for authentication. This function requires that the Portal server detection function be enabled on the device. For details, see (Optional) Configuring the Portal Server Detection Function.

Procedure

  1. Enter the system view.

    system-view

  2. Create a Portal access profile and enter the Portal access profile view.

    portal-access-profile name access-profile-name

  3. Configure the Portal server template used by the Portal access profile.

    web-auth-server server-name [ bak-server-name ] [ layer3 ]

    By default, no Portal server template is bound to a Portal access profile.

    For wired users, Portal authentication is classified into Layer 2 and Layer 3 Portal authentication.
    • Layer 2 Portal authentication (default): If there is no Layer 3 forwarding device between users and the device and the device can learn the users' MAC addresses, you only need to configure Layer 2 Portal authentication because the users can be identified using their MAC addresses.
    • Layer 3 Portal authentication (specified using layer3): If the device cannot obtain the MAC addresses of users regardless of whether there is a Layer 3 forwarding device between the users and the device, you need to configure Layer 3 Portal authentication because the users are uniquely identified using their IP addresses.

  4. (Optional) Configure the source subnet for Portal authentication. This configuration takes effect only for the Portal protocol and does not take effect for the HTTP or HTTPS protocol.

    portal auth-network network-address { mask-length | mask-address }

    By default, the source subnet for Portal authentication is 0.0.0.0/0, indicating that users in all subnets must pass Portal authentication.
