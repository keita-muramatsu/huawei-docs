One-click Troubleshooting

Context

One-click troubleshooting enables you to perform service diagnosis on basic test, network disconnection, and poor network quality for network-wide devices, facilitating quick locating of exceptions.

  • Basic test: used to detect common configurations and risks that may cause network communication exceptions.
  • Network disconnection: used to detect network connectivity faults. If you cannot access the Internet, you are advised to use this function.
  • Poor network quality: used to detect faults that affect Internet access experience. If the network speed is slow or the network is intermittent during Internet access, you are advised to use this function to locate the fault.

Procedure

  1. Choose Maintenance > One-click Troubleshooting. The One-click Troubleshooting page is displayed, as shown in Figure 1.

    Figure 1 One-click Troubleshooting page

  2. Select the scenario type to be diagnosed and click Diagnose.

    Only one scenario type can be selected for diagnosis at a time. After the diagnosis is complete, you can go to the diagnosis result page, as shown in Figure 2.

    Figure 2 Diagnosis result

  3. Perform the following operations on the diagnosis result page:
    • Re-diagnosis: Click Re-diagnose in the upper right corner to re-diagnose the entire network in the current scenario.
    • Returning to the diagnosis page: Click Return in the upper right corner.
    • Viewing diagnosis details: Click each diagnosis item to expand the detailed diagnosis item list. If an item is abnormal, click Show Detail next to the item. On the Diagnosis Item Details page that is displayed, view the exception details of the device.

      You can select Exceptions Only next to Diagnosis Details to view only abnormal diagnosis items.

Result

The following table lists the check items, diagnosis results, and repair suggestions of one-click troubleshooting.

  • For details about the alarms supported on a device, see the product documentation. For historical alarms, the one-click troubleshooting function checks alarms in the last three days based on the time on the master device. The time on the master device must be the same as that on the device being inspected.
  • If IP address parsing or processing is involved, only IPv4 addresses are supported in troubleshooting.
  • If the determination or calculation of uplink and downlink ports is involved in troubleshooting, only one uplink is supported. The load balancing scenario is not supported.
