Maintaining the FEC Probe Table

Context

When the transmit end receives traffic requiring FEC encoding, it negotiates with the receive end to determine whether the receive end has FEC capabilities. If the receive end supports FEC, the transmit end creates an FEC probe table.

An FEC probe table records information such as whether the peer end supports FEC and the probe status. You can query the FEC probe table to check the negotiation result.

Procedure

  • Run the display forward-error-correction probe-table tunnel-type gre [ interface tunnel tunnel-id | profile profile-name ] * or display forward-error-correction probe-table tunnel-type sd-wan [ connection-id connection-id-value | vpn-instance vpn-instance-name | profile profile-name ] * command in any view to check the FEC probe table.
  • Run the reset forward-error-correction probe-table all command in the user view to reset the FEC probe table.

    After a probe succeeds, the transmit end does not initiate a probe within a certain period of time, and the probe table does not age in this period. To immediately trigger a probe, reset the FEC probe table to immediately detect the FEC capability of the remote site.
