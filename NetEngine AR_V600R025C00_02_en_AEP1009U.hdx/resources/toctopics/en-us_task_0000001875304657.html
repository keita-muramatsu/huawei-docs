Configuring an Authentication Profile and Binding It to a Portal Access Profile

Prerequisites

A Portal access profile has been configured. For details, see Configuring a Portal Access Profile.

Context

The device uses an authentication profile to uniformly manage configurations that are irrelevant to the user access mode. You can bind a specified access profile to the authentication profile to determine the authentication mode used.

Procedure

  1. Enter the system view.

    system-view

  2. Create an authentication profile and enter the authentication profile view.

    authentication-profile name authentication-string

    To delete an authentication profile, ensure that it is not bound to any interface.

  3. Bind a Portal access profile to the authentication profile.

    portal-access-profile access-profile-name

  4. (Optional) Configure a default or forcible domain for users.

    access-domain name [ dot1x | mac-authen | portal ] * [ force ]

    By default, no default or forcible domain is configured for users in an authentication profile.

    • If the force parameter is specified in the command, a forcible domain is configured. Otherwise, a default domain is configured. If both a default domain and a forcible domain are configured for users, the device authenticates the users in the forcible domain.

    • If you do not specify dot1x, mac-authen or portal in the command, the configured domain takes effect for all users using the authentication profile. If you specify dot1x, mac-authen or portal in the command, the configured domain takes effect only for specified users.

    • For MAC address authentication users, you can also run the domain mac-authen force command in the system view to configure an authentication domain for these users. If both the access-domain mac-authen and domain mac-authen force commands are run, the domain mac-authen force command takes effect.

  5. (Optional) Configure the device to handshake with pre-connection and authorized users.

    1. Enable the handshake function.

      authentication handshake

      By default, the handshake with pre-connection and authorized users is enabled.

    2. Configure the handshake period.

      authentication timer handshake-period handshake-period-value [ handshake-times handshake-times-value ]

      By default, the handshake period of the device with pre-connection users and authorized users is 100 seconds and the number of handshakes is 3.

  6. (Optional) Enable the device to perform conflict detection on client IP addresses.

    authentication ip-conflict-check enable

    By default, the device performs conflict detection on client IP addresses.

  7. (Optional) Configure the delay after which users are logged out following an interface link fault.

    link-down offline delay { delay-value | unlimited }

    By default, the delay after which users are logged out following an interface link fault is 10 seconds.

    If the delay is set to 0, users are logged out immediately following an interface link fault. If the delay is set to unlimited, users are not logged out.

  8. (Optional) Configure the device to re-authenticate users when the timeout period in the Session-Timeout attribute delivered by the RADIUS server expires.

    authentication termination-action reauthenticate

    By default, the device does not re-authenticate users when the timeout period in the Session-Timeout attribute delivered by the RADIUS server expires.

    Only MAC address authentication on Layer 2 interfaces and 802.1X authentication support this function.

  9. (Optional) Specify the direction in which traffic needs to be controlled.

    authentication control-direction { all | inbound }

    By default, the device controls only uplink traffic.

  10. (Optional) Enable the function of triggering authentication by ARP reply packets.

    authentication arp-reply trigger

    By default, the function of triggering authentication by ARP reply packets is enabled.

  11. (Optional) Configure the device to send accounting packets following terminal roaming.

    authentication roam-accounting enable

    By default, the device sends accounting packets following terminal roaming.

  12. (Optional) Configure the device to send accounting packets following terminal address update.

    authentication update-ip-accounting enable

    By default, the device sends accounting packets following terminal address update.

  13. (Optional) Disable the device from responding to the EAP-Start packets sent from users who have passed MAC address authentication.

    authentication no-replace dot1x

    By default, the device responds to the EAP-Start packets sent from users who have passed MAC address authentication.

  14. (Optional) Configure MAC address authentication to take precedence over 802.1X authentication when authentication is triggered by EAP-Start packets.

    authentication order mac dot1x

    By default, 802.1X authentication takes precedence over MAC address authentication when authentication is triggered by EAP-Start packets.

  15. (Optional) Configure the device to allow users to use only one authentication mode.

    authentication single-access

    By default, the device allows users to use different authentication modes.
