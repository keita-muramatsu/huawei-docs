Example for Configuring L2TP over IPsec for Enterprise Interconnection

Applicable Products and Versions

This example applies to AR routers running V600R024C00 and later versions.

Overview

This document provides a typical configuration example for L2TP over IPsec. It presents a detailed plan of network deployment on branch and HQ routers, provides a configuration example based on the plan, and offers references for networking planning and device configuration.

Networking Requirements

As shown in Figure 1, Devices A and B are gateways of an enterprise's branch and HQ, respectively. DeviceA connects the branch to the HQ through an L2TP tunnel by using the automatic dial-up function. The enterprise requires that services transmitted over the L2TP tunnel be protected to prevent eavesdropping and tampering. To meet this requirement, L2TP over IPsec can be configured to encrypt service packets transmitted between the HQ and branch.
Figure 1 Network diagram of L2TP over IPsec

In this example, interface1 and interface2 represent 10GE 0/0/1 and 10GE 0/0/2, respectively.


Configuration Roadmap

Note: An AR router cannot function as an LNS. The configuration procedure varies according to the LNS device type. For details, see the relevant documentation.

  1. Configure IP addresses for interfaces on DeviceA.
  2. Configure L2TP on DeviceA.
  3. On DeviceA, configure a static route destined for the LNS and enable the automatic dial-up function.
  4. On DeviceA, configure a static route pointing to the HQ, with the dialer interface as the outbound interface.
  5. Configure an ISAKMP IPsec policy on DeviceA and apply the IPsec policy to 10GE0/0/1.

Procedure

  1. Configure IP addresses for interfaces on DeviceA.
    # Configure a public IP address.
    <Huawei> system-view
[Huawei] sysname DeviceA
[DeviceA] interface 10GE0/0/1
[DeviceA-10GE0/0/1] ip address 1.1.2.1 255.255.255.0 
[DeviceA-10GE0/0/1] quit
    # Configure a user-side IP address.
    [DeviceA] interface 10GE0/0/2
[DeviceA-10GE0/0/2] ip address 192.168.10.1 255.255.255.0 
[DeviceA-10GE0/0/2] quit
  2. Configure L2TP.
    # Enable L2TP globally, create an L2TP group, and establish an L2TP connection with DeviceB.
    [DeviceA] l2tp enable
[DeviceA] l2tp-group 1
[DeviceA-l2tp-group 1] tunnel name huawei
[DeviceA-l2tp-group 1] start l2tp ip 1.1.1.1
Warning: This operation may cause traffic interruption, Continue? [Y/N]:y
    # Enable tunnel authentication and set a password for tunnel authentication.
    [DeviceA-l2tp-group 1] tunnel authentication
[DeviceA-l2tp-group 1] tunnel password cipher YsHsjx_123456
Warning: This operation may cause traffic interruption, Continue? [Y/N]:y
[DeviceA-l2tp-group 1] quit
    # Configure a dialer interface and configure the user name, password, PPP authentication mode, and IP address of a PPP user.
    [DeviceA] interface Dialer 1
[DeviceA-Dialer1] link-protocol ppp
[DeviceA-Dialer1] ppp chap user huawei
[DeviceA-Dialer1] ppp chap password cipher YsHsjx_202206
[DeviceA-Dialer1] ip address ppp-negotiate
[DeviceA-Dialer1] quit
    # Configure a public network route to DeviceB. In this example, configure a static route with the next hop of 1.1.2.2.
    [DeviceA] ip route-static 1.1.1.1 255.255.255.255 1.1.2.2
    # Trigger dial-up to establish an L2TP tunnel.
    [DeviceA] interface Dialer 1
[DeviceA-Dialer1] l2tp-auto-client l2tp-group 1
[DeviceA-Dialer1] quit
    # Configure a private network route to allow access from enterprise branch users to the HQ private network.
    [DeviceA] ip route-static 192.168.20.0 255.255.255.0 Dialer 1
  3. Configure an ISAKMP IPsec policy on DeviceA and apply the IPsec policy to 10GE0/0/1.
    1. Create advanced ACL 3000 to define the data flows to be protected.
      [DeviceA] acl 3000
[DeviceA-acl4-advance-3000] rule 1 permit ip
[DeviceA-acl4-advance-3000] quit
    2. Configure an IPsec proposal.
      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceA-ipsec-proposal-tran1] quit
    3. Configure an IKE proposal.
      [DeviceA] ike proposal 10
[DeviceA-ike-proposal-10] authentication-method pre-share
[DeviceA-ike-proposal-10] prf hmac-sha2-256
[DeviceA-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceA-ike-proposal-10] dh group14
[DeviceA-ike-proposal-10] integrity-algorithm hmac-sha2-256  
[DeviceA-ike-proposal-10] quit
    4. Configure an IKE peer.
      [DeviceA] ike peer b
[DeviceA-ike-peer-b] ike-proposal 10
[DeviceA-ike-peer-b] remote-address 1.1.1.1
[DeviceA-ike-peer-b] pre-shared-key YsHsjx_202206
[DeviceA-ike-peer-b] quit
    5. Configure an IPsec policy.
      [DeviceA] ipsec policy map1 10 isakmp
[DeviceA-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceA-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceA-ipsec-policy-isakmp-map1-10] ike-peer b
[DeviceA-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceA-ipsec-policy-isakmp-map1-10] quit
    6. Apply the IPsec policy to 10GE 0/0/1.
      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ipsec policy map1
[DeviceA-10GE0/0/1] quit
