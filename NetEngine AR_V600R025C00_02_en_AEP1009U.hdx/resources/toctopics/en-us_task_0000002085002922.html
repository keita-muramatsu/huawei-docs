Configuring the Number of Available Sessions

Context

When a network device is attacked and a large number of sessions are created, other endpoints cannot run their corresponding services because session resources become exhausted and cannot be allocated to them. In this case, you can configure this function to limit the number of sessions that can be allocated to a user. When the number of sessions established by the user exceeds the configured limit, the device does not establish new sessions. In this way, the user is restricted on using session resources.

Procedure

  1. Enter the system view.

    system-view

  2. Configure the maximum number of sessions that can be allocated to a user.

    session limit limit-number { per-source-ip | per-destination-ip | per-source-port | per-destination-port } [ acl { acl-number | acl-name } ]

    By default, the maximum number of sessions that can be allocated to a user is not configured.

    In the dual-gateway scenario, the number of sessions synchronized between the two ends is not limited by session limit. The actual number of established sessions exceeds the configured limit. The maximum number is twice the limit. You can run the session dual-gateway-backup limit enable command to enable the function of limiting the number of available sessions for dual-gateway backup. After the function is enabled, the number of sessions for dual-gateway backup is limited by session limit. In this way, the maximum number of sessions that can be established is the same as the specified number.
