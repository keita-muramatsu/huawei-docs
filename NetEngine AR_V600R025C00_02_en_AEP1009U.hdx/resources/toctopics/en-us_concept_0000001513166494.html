Remote URL Query Process

A URL query typically involves three servers, namely, the scheduling center, scheduling server, and query server. The functions of each server are as follows:

  • Scheduling center: It authenticates devices. If a device passes the authentication, the scheduling center provides the device with the IP address and port number of the scheduling server in the country or region where the device resides.

  • Scheduling server: It provides a device with the IP address and port number of the query server in the country or region where the device resides. Because scheduling servers are deployed by region, devices must be configured with the correct country and region information. Otherwise, the devices cannot obtain the IP addresses and port numbers of the correct scheduling servers.

  • Query server: It interacts with devices to process their query requests and return query results. Query servers are also deployed by region and mapped with scheduling servers. A scheduling server only provides a device with the IP address and port number of the query server in the same region.

Figure 1 shows the interaction between the device and these servers in a remote URL query.

Figure 1 Remote URL query process

  1. The device sends an authentication request to the scheduling center and requests a scheduling server address.

  2. If the authentication succeeds, the scheduling center provides the device with the IP address and port number of the scheduling server in the country or region where the device resides.

  3. The device sends a message to the scheduling server, requesting the IP address and port number of a query server.

  4. The scheduling server confirms the device information and provides the device with the IP addresses and port numbers of several query servers.

  5. The device sends a speed test message to all the query servers, selects the query server with the shortest response time, and requests URL category information from this server.

  6. The query server sends the desired URL category information to the device, which then performs URL filtering based on the category information.

The remote URL query process does not interrupt existing connections.
