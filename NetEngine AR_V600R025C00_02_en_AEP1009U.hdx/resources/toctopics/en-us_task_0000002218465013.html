Configuring Session Link Stateful Inspection

Context

The device uses a detection mechanism based on the connection status and treats all packets exchanged between two communication parties over the same connection as one single data flow. The device considers the packets in the same data flow related to each other.

The device can perform stateful inspection for TCP and ICMP packets. If the connection status of a packet is valid, the device creates a session for the packet and records its connection status in the session. If the connection status of a packet is invalid, the device discards it.

The following uses TCP as an example. As shown in Figure 1, TCP provides reliable connection services. A connection channel must be established between two parties through a three-way handshake before one party sends data to the other.

Figure 1 TCP three-way handshake

A TCP connection involves three handshakes. If any handshake is missing, for example, the device receives the SYN-ACK packet for the second handshake but not a SYN packet for the first handshake, the device determines that the connection status of the SYN-ACK packet is invalid and discards the packet.

Procedure

  1. Enter the system view.

    system-view

  2. Enable the IPv4 link stateful inspection function.

    session link-state [ icmp | tcp ] check

    By default, the link stateful inspection function is disabled.

  3. (Optional) Disable link stateful inspection for traffic bound to a specified VPN instance.

    session link-state exclude vpn-instance vpn-instance-name

    By default, no VPN instance is bound to link stateful inspection. If link stateful inspection is enabled, the device detects traffic of all VPN instances.
