(Optional) Configuring the Portal Server Detection Function

Context

In Portal authentication application, if communication between the device and Portal server is interrupted due to a network failure or Portal server failure, new Portal authentication users cannot go online, and online Portal users cannot go offline as expected.

The Portal server detection function enables the device to generate logs and alarms for network failures and Portal server failures.

The device can detect the Portal server in Portal or HTTP mode. In Portal-based detection, the Portal server must use the Portal protocol and support the function of sending Portal heartbeat packets. If the Portal server does not meet the conditions for Portal-based detection, you can configure HTTP-based detection. After detecting that the server is down, the device can perform server down authorization for new access users in a timely manner.

When two Portal servers work in active/standby mode or the Portal bypass function is configured, enable the Portal server detection function on the device.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the Portal server template view.

    web-auth-server server-name

  3. Configure the mode in which the device detects the Portal server.

    server-detect type { portal | http }

    By default, the device detects the Portal server in Portal mode.

  4. Enable the Portal server detection function.

    server-detect [ interval interval-period | max-times times | critical-num critical-num | action { log | trap } * ] *

    By default, Portal server detection is disabled.
