Configuring CHAP Authentication

Prerequisites

Before configuring CHAP authentication on an interface, you have completed the following task:

  • Configure PPP as the link layer protocol of the interface.

Context

PPP supports PAP and CHAP authentication. CHAP authentication is initiated by the authenticator.

CHAP authentication involves two scenarios:

  • A CHAP user name is configured on the authenticator's interface: In this case, the authenticator sends the user name to the peer. The peer then queries the password corresponding to the received user name among the local access users.

    After obtaining the password, the peer encrypts the user name and password and sends them to the authenticator.

    The authenticator compares the received user name and password with the local access user name and password configured on itself. The authentication succeeds only when they are the same.

  • No user name is configured on the authenticator's interface: In this case, the authentication succeeds only when the local access user name and password configured on the peer's interface are the same as the authentication user name and password configured in the AAA view of the authenticator.

The user name and password of the peer can be added to the local user list of the authenticator in Authentication, Authorization and Accounting (AAA), Remote Authentication Dial-In User Service (RADIUS) authentication, or Huawei Terminal Access Controller Access Control System (HWTACACS) authentication mode. If the authenticator is not configured with a user name, the peer must be configured with a CHAP password. This section describes how to add the user name and password of the peer in AAA mode. For details about the configuration of RADIUS authentication and HWTACACS authentication, see "AAA Configuration" in Configuration Guide > User Access and Authentication Configuration.

CHAP supports unidirectional and bidirectional authentication.

  • In unidirectional authentication, the device on one end functions as the authenticator, and the device on the other end functions as the peer.
  • In bidirectional authentication, each device functions as both the authenticator and peer.

The device supports both CHAP authentication scenarios: a user name is configured on the authenticator or no user name is configured on the authenticator.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the interface view.

    interface interface-type interface-number

  3. Configure CHAP authentication.

    • Scenario 1: The authenticator is configured with a user name.

      You can configure the authenticator with a user name to authenticate its peer in CHAP mode. In this case, the authenticator's user name will be confirmed.

      • Configure the device as the authenticator in CHAP authentication.
        1. Set the PPP authentication mode to CHAP.
          ppp authentication-mode chap [ pap ]

          You can run the ppp authentication-mode chap [ pap ] command to enable CHAP negotiation to take precedence over PAP negotiation during LCP negotiation. If the peer does not support CHAP negotiation, PAP negotiation is performed. If the peer supports neither of the two modes, the negotiation fails. Only one authentication mode is negotiated during a PPP negotiation.

        2. Configure a CHAP user name on the authenticator.
          ppp chap user user-name

          The CHAP user name configured on the authenticator must be the same as the local access user name configured on the peer.

        3. Return to the system view.
          quit
        4. Enter the AAA view.
          aaa
        5. Create a local access user and configure the local access user name.
          local-access-user user-name
        6. Configure the password for the local access user.
          password cipher password

          The local access user name and password configured on the authenticator must be the same as those configured on the peer.

        7. Configure PPP as the access type of the local access user.
          service-type ppp
      • Configure the device as the peer in CHAP authentication.
        1. Configure the CHAP user name to be authenticated by the authenticator.
          ppp chap user user-name

          The CHAP user name configured on the peer must be the same as the CHAP user name configured on the authenticator.

        2. Return to the system view.
          quit
        3. Enter the AAA view.
          aaa
        4. Create a local access user and configure the local access user name.
          local-access-user user-name
        5. Configure the password for the local access user.
          password cipher password

          The local access user name and password configured on the peer must be the same as those configured on the authenticator.

        6. Configure PPP as the access type of the local access user.
          service-type ppp

    • Scenario 2: The authenticator is not configured with a user name.
      You can configure the authenticator without a user name to authenticate its peer in CHAP mode.
      • Configure the device as the authenticator in CHAP authentication.
        1. Set the PPP authentication mode to CHAP.
          ppp authentication-mode chap [ pap ]

          You can run the ppp authentication-mode chap [ pap ] command to enable CHAP negotiation to take precedence over PAP negotiation during LCP negotiation. If the peer does not support CHAP negotiation, PAP negotiation is performed. If the peer supports neither of the two modes, the negotiation fails. Only one authentication mode is negotiated during a PPP negotiation.

        2. Return to the system view.
          quit
        3. Enter the AAA view.
          aaa
        4. Create a local access user.
          local-access-user user-name
        5. Configure the password for the local access user.
          password cipher password

          The local access user name and password configured on the authenticator must be the same as the CHAP user name and password configured on the peer.

        6. Configure PPP as the access type of the local access user.
          service-type ppp
      • Configure the device as the peer in CHAP authentication.
        1. Configure a user name to be authenticated by the authenticator.
          ppp chap user user-name
        2. Configure a password for CHAP authentication.
          ppp chap password { simple password | cipher { password1 | password2 } }

          The CHAP user name and password configured on the peer must be the same as the local access user name and password configured on the authenticator.

    • If simple is specified, the password is saved in plain text in the configuration file. This presents potential security risks. You are advised to specify cipher so that the password is saved in cipher text in the configuration file.
    • After the configuration, run the shutdown command followed by the undo shutdown command in the interface view for the configuration to take effect.
