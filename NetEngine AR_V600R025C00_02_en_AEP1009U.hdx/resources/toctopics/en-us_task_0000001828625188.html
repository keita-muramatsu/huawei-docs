Configuring the Portal Server Function

Context

If a Portal server is used for authentication, you need to configure related parameters in the Portal server template, for example, the authentication protocol, to ensure that the device and Portal server can communicate.

Procedure

  1. Enter the system view.

    system-view

  2. Enable Portal interconnection of the HTTP or HTTPS protocol.

    portal web-authen-server { http | https ssl-policy policy-name } [ port port-number ]

    By default, the Portal interconnection function of the HTTP or HTTPS protocol is disabled.

    HTTPS is recommended, as it is more secure than HTTP.

  3. Configure the local gateway address for the device to receive and respond to the packets sent by terminals when the Portal interconnection function is enabled.

    portal web-authen-server server-source { all-interface | ip-address ip-address }

    By default, the device does not receive or respond to any packets sent by terminals when the Portal interconnection function of the HTTP or HTTPS protocol is enabled.

  4. Create a Portal server template and enter the Portal server template view.

    web-auth-server server-name

    By default, no Portal server template is created.

  5. Set the protocol used in Portal authentication to HTTP or HTTPS.

    protocol http [ password-encrypt { none | uam } ]

    By default, the Portal protocol is used in Portal authentication.

    The default password encoding mode is none. Set the password encoding mode on the device to be the same as that on the Portal server.

  6. (Optional) Configure the device to allow users to submit the user name and password to the device using the GET method during Portal authentication.

    http get-method enable

    By default, the device does not allow users to submit user name and password information using the GET method during Portal authentication.

    By default, the device allows users to submit the user name and password using the POST method during Portal authentication. Perform this step when the Portal server uses the GET method. The POST method is recommended because the GET method has the risk of password disclosure.

  7. (Optional) Configure parameters for parsing and replying to POST or GET requests of the HTTP or HTTPS protocol.

    http-method post { cmd-key cmd-key [ login login-key | logout 1-15 ] * | init-url-key init-url-key | login-fail response { err-msg { authenserve-reply-message | msg msg } | redirect-login-url | redirect-url redirect-url [ append-reply-message msgkey ] } | login-success response { msg msg | redirect-init-url | redirect-url redirect-url } | logout-fail response { msg msg | redirect-url redirect-url } | logout-success response { msg msg | redirect-url redirect-url } | password-key password-key | user-mac-key user-mac-key | userip-key userip-key | username-key username-key } *

    By default, the system has configured parameters for parsing and replying to POST or GET requests of the HTTP or HTTPS protocol. For details, see "Parameters"in the http-method post command. Set related parameters on the device based on the Portal server configuration.

  8. Return to the system view.

    quit
