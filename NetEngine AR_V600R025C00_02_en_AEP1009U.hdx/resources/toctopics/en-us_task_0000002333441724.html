Configuring Point-to-Multipoint IPsec

Context

Internet Protocol Security (IPsec) is a suite of protocols used to secure IP networks by allowing two devices to establish an IPsec-encrypted tunnel. Forwarding data through an IPsec-encrypted tunnel effectively protects the data.

On the Scenario Option page, set Scenario to Site-to-site or Site-to-multisite based on the actual situation. Select Site-to-multisite if you need to configure point-to-multipoint IPsec.

Point-to-multipoint IPsec is used to establish IPsec tunnels between one device and multiple devices, in order to secure communication between one LAN and multiple branch LANs.

      • Peer ID type: Select a peer ID type.
      • Peer ID: Enter the ID of the peer device. The ID is used for identity verification.
      • Pre-shared key: Set the key negotiated by administrators on both ends.
      • Assigned IP address: Enter the IP address assigned to the peer device. Set this parameter if the peer device requires that a specified IP address be assigned.
      • Primary DNS server: Enter the IP address of a DNS server allocated to the peer device. Set this parameter if the peer device requires that a specified DNS server be used.
      • Secondary DNS server: Enter the IP address of a secondary DNS server. When this parameter is configured, if the primary DNS server fails to resolve a domain name requested by a client, the client sends the request to the secondary DNS server. It is required that the IP address of the secondary DNS server be different from that of the primary DNS server.

      • Main: Only the main mode is acceptable in the negotiation. This mode is more secure.

      NOTE:

      Phase 2(IPSec)

      NOTE:

      All parameters except SA timeout must be set to the same values on both ends.

      -

      Encapsulation mode

      Encapsulation mode of IPsec:

      • Automatic: Both the transport mode and tunnel mode can be used to respond to negotiation requests, but only the tunnel mode can be used to initiate negotiation requests.
      • Transport: A tunnel is established between a mobile terminal and a VPN gateway.
      • Tunnel: A tunnel is established between VPN gateways.

      Security protocol

      IPsec security protocol:

      • ESP: encrypts and authenticates the packet payload.
      • AH: authenticates the entire packet, but does not encrypt the packet.
      • AH-ESP: encrypts and authenticates the entire packet.

      ESP encryption

      This parameter is available when you set Security protocol to ESP or AH-ESP.

      Algorithm used to prevent data from being stolen.

      NOTE:

      DES and 3DES algorithms are not secure enough. You are advised to use a secure algorithm such as AES256. If you want to use a weak algorithm, load the weak algorithm plug-in.

      ESP authentication

      This parameter is available when you set Security protocol to ESP or AH-ESP.

      Algorithm used for data source authentication.

      NOTE:

      MD5 and SHA1 algorithms are not secure enough. You are advised to use a secure algorithm such as SHA2-256. If you want to use a weak algorithm, load the weak algorithm plug-in.

      This parameter is available when you set Security protocol to AH or AH-ESP.

      Algorithm used for data source authentication.

      PFS

      This parameter is available when you expand Advanced Feature.

      Key exchange method.

      A larger group number indicates a longer key and higher security. Select NONE if no key exchange is required.

      SA timeout

      This parameter is available when you expand Advanced Feature.

      The IPsec tunnel is renegotiated to ensure security when the establishment time or transmitted traffic volume reaches the specified threshold.

      Specify the interval at which an IPsec SA is renegotiated in By time(s). Specify the maximum amount of traffic that an IPsec SA can process in By traffic (KB). The IPsec SA becomes invalid if either lifetime expires. In this case, the two ends start to renegotiate a new IPsec SA. Renegotiation does not interrupt operating tunnels.

      By time(s)

      Time-based IPsec SA lifetime, in seconds.

      By traffic (KB)

      Traffic-based IPsec SA lifetime, in KB.

      NOTE:

      IPsec SAs are renegotiated to ensure security when the SA lifetime expires.

      Dead Peer Detection (DPD)

      -

      Detection mode

      After Dead Peer Detection (DPD) is enabled, the local end sends DPD packets to detect whether the remote end is alive and tear down invalid tunnels in a timely manner.

      Two DAD modes are available:

      • Periodic: The local end sends DPD packets to the remote end if it does not receive packets from the remote end within the period specified in Detection interval(s).
      • On-demand: The local end sends DPD packets to the remote end only when it needs to communicate with the remote end and does not receive packets from the remote end within the period specified in Detection interval(s).

      Detection interval(s)

      DAD idle time, in seconds.

      Retry interval(s)

      DPD packet retransmission interval, in seconds. This parameter is valid only for IKEv1.

  • Delete an IPsec policy.

    1. Log in to the web system and choose Config > VPN > IPSec. The IPSec Policy Management page is displayed.
    2. Select next to the desired IPsec policy and click Delete. The system asks you whether to delete the IPsec policy.
    3. Click OK.
