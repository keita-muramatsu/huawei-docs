Understanding Data Compression

Data Compression Process

Figure 1 shows the data compression process. The transmit end (DeviceA) compresses to-be-sent IP packets, and the receive end (DeviceB) decompresses the IP packets received from DeviceA. Each IP packet is individually compressed and decompressed, and contains the same data throughout the entire process.

Figure 1 Data compression process

LZ4 Compression Algorithm

Data compression uses the LZ4 compression algorithm to implement high-speed compression through a non-conflicting hash table and 4-byte fast matching. Figure 2 shows the LZ4 compression process.

Figure 2 LZ4 compression process

Figure 3 shows an example of compressing the data abcdef_bcdefgh. The output after compression is abcdef_(6,5)gh.

Figure 3 Compression example

When decompressing abcdef_(6,5)gh, the LZ4 algorithm reads the offset and match length in sequence to restore the original data abcdef_bcdefgh.
