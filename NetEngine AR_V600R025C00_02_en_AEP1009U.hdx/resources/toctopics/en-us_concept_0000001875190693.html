Portal Timers

An access device supports the following Portal timers descried in Table 1.

Table 1 Portal timers

Portal Timer

Function

Application Scenario

Quiet Timer

Prevents frequent authentication upon user authentication failures. Frequent authentication may cause DoS attacks and waste system resources.

External Portal servers that use the Portal or HTTP/HTTPS protocol.

Portal Server Detection Timer

Ensures that online Portal users can go offline as expected and new Portal authentication users can go online if communication between the access device and Portal server is interrupted due to a network fault or the Portal server is faulty.

External Portal servers that use the Portal or HTTP/HTTPS protocol.

User Information Synchronization Timer

Ensures that online Portal users can go offline as expected and correct accounting is performed for users who have already gone offline if communication between the access device and Portal server is interrupted due to a network failure or a Portal server failure.

External Portal servers that use the Portal protocol

User Logout Retransmission Timer

Prevents the following situation: If the network between the access device and Portal server is unstable or packets are lost, the Portal server may fail to receive the user logout packet from the access device. In this case, the user is displayed as disconnected on the access device but is still displayed as online on the Portal server.

External Portal servers that use the Portal protocol

Quiet Timer

Portal Server Detection Timer

The device can detect the Portal server using Portal or HTTP. For Portal authentication based on the Portal protocol, the device supports both Portal- and HTTP-based detection modes. For Portal authentication based on the HTTP/HTTPS protocol, the device supports only HTTP-based detection.

In Portal-based Portal server detection: The Portal server periodically sends Portal heartbeat packets to the access device. If the access device receives Portal heartbeat packets or other authentication packets from the Portal server within the detection period specified using the server-detect interval interval-period command, the detection is successful and the access device considers the Portal server to be reachable and in up state. Otherwise, the detection fails. When the number of consecutive detection failures exceeds the maximum value (specified using the server-detect max-times times command), the access device changes the status of the Portal server from up to down.

In HTTP-based Portal server detection: The access device periodically sends HTTP packets to the Portal server and expects a response from the Portal server. If the access device receives a response within the detection period (specified using the server-detect interval interval-period command), the detection is successful. Otherwise, the detection fails. When the number of consecutive detection failures exceeds the maximum value (specified using the server-detect max-times times command), the access device changes the status of the Portal server from up to down.

Figure 2 and Figure 3 show the detection process.

It is recommended that the value of interval-period configured on the access device be greater than the heartbeat packet transmission interval configured on the Portal server.

In addition, the access device takes the following actions to inform administrators of the Portal server status in real time and ensure that users have certain network access rights:

  • Sends alarms: When the status of a Portal server is changed, the access device sends an alarm to the NMS. The alarm records the IP address and status of the Portal server.
  • Sends logs: When the status of a Portal server is changed, the access device sends a log to the NMS. The log records the IP address and status of the Portal server.
  • Enables the Portal bypass mechanism. If the number of Portal servers in up state is equal to or less than the minimum value (specified using the server-detect critical-num critical-num command), the access device disables Portal authentication on an interface that has Portal authentication enabled so that all Portal authentication users can access specified network resources. For details about authorization methods, see "The Portal server is down" in NAC Bypass Mechanism. When the access device receives a heartbeat packet from a Portal server or receives another authentication packet (for example, a user logout packet), or HTTP-based Portal server detection succeeds, the access device changes the status of the Portal server from down to up. If the number of Portal servers in up state is greater than the minimum value, Portal authentication of the interface is restored.

User Information Synchronization Timer

The Portal server periodically (at an interval of Tps) encapsulates online user information into a user information synchronization request (USER_SYN) packet and sends it to the access device. After Portal user information synchronization is enabled on the access device, the user information synchronization timer is started. In the user information synchronization period (specified using the user-sync interval interval-period command), the access device compares the online user information carried in the received USER_SYN packet with its online user information.

  • If the online user information in the USER_SYN packet is the same as its online user information, the access device does not respond to the packet but marks the user information as synchronized.
  • If the online user information in the USER_SYN packet is different from its online user information, the access device responds to the packet. If the synchronization fails after the maximum number of synchronizations (specified using the user-sync max-times times command) is reached, the device disconnects the user.
  • If a user exists only on the Portal server, the access device responds to the USER_SYN packet, and the Portal server deletes the user.

Figure 4 User information synchronization process

This function is applicable only to the external Portal server that uses the Portal protocol.

It is recommended that the product of interval-period and times be greater than the interval at which the Portal server sends USER_SYN packets. Otherwise, the access device may disconnect users if it receives no USER_SYN packet from the Portal server after the maximum number of synchronization failures is reached.

User Logout Retransmission Timer

To enable the Portal server to receive user logout packets and ensure that user online information on the Portal server is correct, the access device provides the user logout packet retransmission function. If the access device does not receive a user logout response packet from the Portal server within the user logout retransmission period (specified by period), the access device retransmits the user logout packet. The maximum number of retransmissions is specified using the portal logout resend times timeout period command.
