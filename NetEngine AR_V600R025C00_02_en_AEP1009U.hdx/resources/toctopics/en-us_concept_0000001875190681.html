Portal Protocol

The Portal protocol is a communications protocol that transfers parameters such as the user name and password between the Portal server and access devices. Currently, the device supports Portal 1.0, Portal 2.0, and Portal 3.0 (Huawei extended protocol).

Portal 1.0 does not perform security verification. The difference between Portal 2.0 and Portal 3.0 lies in the authentication field length and the used algorithm. Portal 2.0 uses the MD5 algorithm to authenticate packets, and the authentication field is 16 bytes. Portal 3.0 uses the SHA256 algorithm, which is more secure, to authenticate packets, and the authentication field is 32 bytes.
  • To ensure proper communication, you are advised to use the default device setting so that the device supports the three versions.
  • Currently, the commonly used Portal protocol version is Portal 2.0. Before using Portal 3.0 for interconnection, ensure that the interconnected Portal server supports Portal 3.0. Otherwise, the interconnection fails.

AuthType

Authentication mode. The length is 1 byte. Two authentication modes are supported:

  • CHAP authentication: is three-way handshake authentication and transmits the user name and password in cipher text. The AuthType field for CHAP authentication is 0.

  • PAP authentication: is two-way handshake authentication and transmits the user name and password in plain text. The AuthType field for PAP authentication is 0x01.

The REQ_CHALLENGE and ACK_CHALLENGE packets are exchanged only in CHAP authentication. CHAP authentication is more secure and reliable than PAP. CHAP is recommended if high security is required.

Rsvd

Reserved for future use. It is 1 byte in length and is 0 in all packets.

SerialNo

Serial number of a packet. It is 2 bytes in length and is randomly generated by the Portal server. The Portal server needs to ensure that the serial numbers of all packets in the same authentication process are the same and that the serial numbers of packets in different authentication processes are different within a certain period.

RequestID

Packet ID. It is 2 bytes in length, is generated by an access device, and is unique.

UserIP

IP address of a Portal user. It is 4 bytes in length.

UserPort

Reserved for future use. It is 2 bytes in length and is 0 in all packets.

ErrCode

Error code. It is 1 byte in length and is used together with the Type field.

Attribute

Variable-length field. It is composed of multiple attributes in the TLV format.

  • AttrType: indicates an attribute type. It is 1 byte in length.

  • AttrLen: indicates the length of the Attribute field, which is the sum of the lengths of the AttrType, AttrLen, and AttrValue fields. The Attribute field is 1 byte in length.

  • AttrValue: indicates a specific attribute value, for example, user name and password. The length cannot exceed 253 bytes.
