Server Mapping

Context

The Server Mapping menu allows you to configure NAT Server, which is a static destination address translation technology. It translates the public IP addresses in packets into private IP addresses in fixed mappings.

Procedure

  1. Log in to the web system and choose Config > IP Services > NAT Policy > Server Mapping. The page shown in Figure 1 is displayed.

    Figure 1 Server Mapping page

  2. Click Create and set parameters, as shown in Figure 2. Table 1 describes the parameters.

    Figure 2 Add Server Mapping page
    Table 1 Server mapping parameters

    Parameter

    Description

    Name

    Name of a server mapping.

    Description

    Server description.

    Public IP Address
    • Specify Public IP Address: Enter an available public IP address or public IP address range.
    • Use Interface: Select the WAN interface, whose public IP address will be automatically used in address translation.

    Private IP Address

    Range of private IP addresses of intranet servers. If there is only one intranet server, you only need to enter its private IP address.

    Specify Protocol

    -

    Protocol

    Protocol that an intranet server uses to provide services for Internet users.

    The available protocols include TCP, UDP, SCTP, ICMP, IPv6, GRE, ESP, and AH.

    Public Port

    Port number that an intranet server uses to provide services for Internet users. This parameter is available only when the protocol is set to TCP, UDP, or SCTP.

    Private Port

    Internal port number of an intranet server. This parameter is available only when the protocol is set to TCP, UDP, or SCTP.

    Allow Server to Use Public IP Address For Internet Access

    When this function is disabled, the device generates only forward server mapping entries. If an intranet server proactively initiates a connection to the Internet, the device cannot translate the private IP address of the intranet server into a public IP address. As a result, the intranet server fails to access the Internet. When this function is enabled, the device generates both forward and return server mapping entries, allowing the intranet server to access the Internet through a public IP address.

    For security purposes, you are advised to disable this function if intranet servers do not need to access the Internet.

    Autogenerate Blackhole Route

    When this function is enabled, a blackhole route to the public IP address is automatically delivered to prevent routing loops. In addition, after a dynamic routing protocol such as OSPF is configured to import static routes, public IP addresses can be advertised to the upstream and downstream routers through the dynamic routing protocol.

    If the NAT Server public address and the WAN interface address are in different network segments, a blackhole route is a mandatory.

    If the NAT Server public address and the WAN interface address are in the same network segment, a blackhole route is recommended.

    If the NAT Server public address and the WAN interface address are the same, no routing loop will occur, and therefore no blackhole route is required.

    When Public IP Address is set to Use Interface, Auto Generate Blackhole Route is unavailable.

  3. Click OK.
