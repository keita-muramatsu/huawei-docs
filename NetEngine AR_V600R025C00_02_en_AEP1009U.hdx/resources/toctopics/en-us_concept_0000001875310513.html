Logout of Portal Authentication Users

If a user goes offline but the access device, RADIUS server, and Portal server do not detect this event, the following problems may occur:
  • The RADIUS server still performs accounting for the user, causing incorrect accounting.
  • An unauthorized user can use this user's IP address and MAC address to access the network.
  • If there are many offline users, these users are still counted as online users of the device. As a result, other users may fail to access the network.

To avoid such problems, the access device needs to detect the user logout immediately, delete the user entry, and instruct the RADIUS server to stop accounting for the user.

User logouts may occur in the following situations: a client proactively logs out, an access device controls the user logout, and the authentication server or Portal server logs out the user.

The Client Proactively Logs Out

A user initiates a logout request. For example, if the user clicks the logout button, the client sends a logout request to the Portal server.

After receiving the logout request from the user, the Portal server notifies the client that the user goes offline, without waiting for the access device to confirm the logout. For Portal authentication based on the HTTP or HTTPS protocol, after receiving the logout request from the user, the Portal server instructs the client to send a logout notification to the access device.

Portal authentication based on the Portal protocol

Figure 1 shows the user logout process.

Figure 1 Client proactively logging out
  1. The client sends a logout request to the Portal server.
  2. The Portal server sends a user logout response to the client and sends a logout notification (REQ_LOGOUT) to the access device.

  3. The access device sends an Accounting-Request(Stop) packet to the RADIUS server and disconnects the user. The access device sends a logout response (ACK_LOGOUT) to the Portal server.

    After receiving the ACK_LOGOUT packet, the Portal server disconnects the user.

  4. The RADIUS server returns an Accounting-Response(Stop) packet and disconnects the user.

Portal authentication based on the HTTP or HTTPS protocol

Figure 2 shows the user logout process and uses HTTP as an example.
Figure 2 Client proactively logging out
  1. The client sends a logout request to the Portal server.
  2. The Portal server instructs the client to send a logout request to the access device and disconnects the user.
  3. The client sends a logout request to the access device.
  4. The access device sends an Accounting-Request(Stop) packet to the RADIUS server and disconnects the user. The access device sends a user logout response to the client.
  5. The RADIUS server returns an Accounting-Response(Stop) packet and disconnects the user.

The Authentication Server Logs Out a User

The authentication server logs out a user in either of the following ways:

  • The RADIUS server sends a Disconnect Message (DM) to disconnect a user. A DM refers to the packet proactively sent by the RADIUS server to disconnect a user.
  • The RADIUS server uses the standard RADIUS attributes Session-Timeout and Termination-Action. Session-Timeout specifies the online duration timer of a user. If the value of Termination-Action is 0, the user is disconnected. When the online duration of a user reaches the value specified by the timer, the device disconnects the user.

Figure 3 shows the user logout process. Here, the RADIUS server sends a DM.

Figure 3 Authentication server disconnecting a user

  1. The RADIUS server sends a DM Request to the access device.

  2. The access device sends an NTF_LOGOUT packet to the Portal server and disconnects the user. In addition, the access device sends a DM ACK and an Accounting-Request(Stop) packet to the RADIUS server.

    When HTTP or HTTPS is used, the access device does not send an NTF_LOGOUT packet to the Portal server.

  3. The Portal server sends an AFF_ACK_LOGOUT packet to the access device and disconnects the user. The RADIUS server sends an Accounting-Response(Stop) packet to the access device and disconnects the user.

The Portal Server Logs Out a User

When an administrator deregisters a user or the Portal server detects that a user is offline, the Portal server disconnects the user and sends a logout notification to the access device.

Figure 4 shows the user logout process. The following uses the Portal protocol as an example.

Figure 4 Portal server logging out a user
  1. The Portal server sends a logout notification (REQ_LOGOUT) to the access device.

  2. The access device sends an Accounting-Request(Stop) packet to the RADIUS server and disconnects the user. The access device sends a logout response (ACK_LOGOUT) to the Portal server.

    After receiving the ACK_LOGOUT packet, the Portal server disconnects the user.

  3. The RADIUS server returns an Accounting-Response(Stop) packet and disconnects the user.
