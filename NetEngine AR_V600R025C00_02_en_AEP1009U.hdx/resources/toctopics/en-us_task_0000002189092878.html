DHCP Address Pool

Context

A global address pool or an interface address pool can be configured to dynamically allocate IP addresses to clients on a network.

Procedure

  1. Create an address pool.
    1. Log in to the web system, choose Config > IP Services > DHCP, and enable DHCP globally, as shown in Figure 1.

      Figure 1 Enabling DHCP globally

    2. Click Create and configure basic information, as shown in Figure 2. Table 1 describes the parameters.

      Figure 2 Basic information

    3. Click next to Advanced Configuration to set advanced parameters, as shown in Figure 3. Table 1 describes the parameters.

      Figure 3 Advanced configuration
      • (Optional) To create a static IP-MAC binding, click Add and enter the IP address and MAC address to be bound, as shown in Figure 4. Table 1 describes the parameters.
        Figure 4 Configuring a static IP-MAC binding
      • (Optional) To configure an interface to use the address pool, click Add, select an interface, and click OK, as shown in Figure 5. This operation is applicable only when Address pool type is set to Global address pool. Table 1 describes the parameters.
        Figure 5 Configuring the interfaces that use the address pool

      The values of Gateway IP address, Reserved IP address, and Static binding IP address must be within the range of IP addresses in the address pool. To ensure correct configuration, the value of Subnet address/mask of the global address pool or the value of Interface of the interface address pool can be modified or selected only when these parameters are not configured.

      Table 1 Parameters for creating an address pool

      Parameter

      Description

      Address pool type

      Address pool type. You can select Global address pool or Interface address pool.

      Address pool name

      Name of the global address pool to be created. The value is a string of 1 to 64 characters, and can contain digits, lowercase letters, underscores (_), hyphens (-), and periods (.). The name cannot be - or --.

      Interface

      Interface corresponding to the interface address pool of the DHCP server. The IP addresses on the network segment where the interface IP address belongs can be allocated.

      Subnet address/mask

      Network segment address of IP addresses that can be allocated in the global address pool.

      Subnet mask of the IP addresses allocated to DHCP clients, that is, the subnet mask of the selected interface.

      Vendor-defined
      User-defined option for the global address pool. The options are as follows:
      • none: No user-defined option is configured for the global address pool.
      • ascii: The user-defined option is an ASCII character string.
      • cipher: The user-defined option is a ciphertext character string.
      • hex: The user-defined option is a hexadecimal number.
      • ip-address: The user-defined option is an IP address. One to eight IP addresses can be specified.
      • sub-option: A sub-option is configured for the user-defined option. If sub-option is selected, you also need to set the sub-option parameter.

      The vendor-defined field is the Option 43 field. If the AC and AP are on different network segments, you must configure the Option 43 field to specify the AC's IP address for the AP. Otherwise, the AP cannot discover the AC and cannot go online on the AC.

      Lease period

      Lease of an IP address allocated to a DHCP client, that is, the duration for the DHCP client to use the IP address allocated by the DHCP server.

      You can set an address lease based on the duration of a connection between a client using an IP address in the address pool and the physical network. For example, if clients on a wireless network frequently connect to and disconnect from the network, you can set a short address lease, for example, 0 days 8 hours 0 minutes. If clients are connected to the network for a long time, you can set a relatively long lease or even a permanent lease.

      Conflicting address recycling period

      Period for reclaiming conflicting addresses.

      Gateway IP address

      Egress gateway address of the global address pool.

      This parameter is configurable only when Address pool type is set to Global address pool.

      Reserved IP address

      IP address that is not automatically allocated. If some IP addresses have been allocated to other services (such as the DNS server), they cannot be automatically allocated to clients. In this case, you need to configure them as reserved IP addresses. This prevents address conflicts and shortens the detection time during address allocation, improving the DHCP address allocation efficiency.

      Static binding IP address

      Static binding between an allocatable IP address and a client's MAC address. When the DHCP server receives an IP address request from the client with the MAC address, it allocates the fixed IP address bound to the MAC address to the client.

      Interfaces use the address pool

      Interface that can use addresses in the address pool. Users going online through this interface can obtain configuration information, such as IP addresses, from the global address pool.

      This parameter is configurable only when Address pool type is set to Global address pool.

      DNS domain name

      Domain name suffix allocated by a DNS server to a DNS client.

      Primary DNS

      Primary DNS server address allocated to a DHCP client.

      Secondary DNS

      Secondary DNS server address allocated to a DHCP client. When the DHCP client fails to resolve domain names using the primary DNS server, it requests the secondary DNS server for domain name resolution.

      Primary WINS server

      Primary WINS server address allocated to a DHCP client. In the Windows operating system, the hosts that communicate through the NetBIOS protocol need to resolve host names into IP addresses. NetBIOS host name resolution includes local name resolution, broadcast query, and WINS server resolution. WINS server resolution is performed by the WINS server. Ensure that there are reachable routes between the primary WINS server and the DHCP server.

      Secondary WINS server

      Secondary WINS server address allocated to a DHCP client. When the DHCP client fails to resolve NetBIOS host names using the primary WINS server, it requests the secondary WINS server for host name resolution. Ensure that there are reachable routes between the secondary WINS server and the DHCP server.

      NetBIOS type

      NetBIOS node type for a client. The options are as follows:

      • Not specified: The NetBIOS node type is not specified.
      • b-node: b indicates broadcast. A node of this type obtains the mapping in broadcast mode.
      • p-node: p indicates peer-to-peer. A node of this type obtains the mapping by communicating with the NetBIOS server.
      • m-node: m indicates mixed. A node of this type is a p-type node with some broadcast features.
      • h-node: h indicates hybrid. A node of this type is a b-type node using the peer-to-peer communication mechanism.

    4. Click OK.
  2. Modify a DHCP address pool.

    1. Log in to the web system and choose Config > IP Services > DHCP. The DHCP Address Pool page is displayed.
    2. In the list of configured DHCP address pools, click on the right of the DHCP address pool to be modified. The Modify Address Pool page is displayed, as shown in Figure 6.
      Figure 6 Modifying a DHCP address pool
    3. On the Modify Address Pool page, modify the parameter settings. For details about the parameters, see Table 1.
    4. Click OK.

  3. Delete a DHCP address pool.

    1. Log in to the web system and choose Config > IP Services > DHCP. The DHCP Address Pool page is displayed.
    2. In the list of configured DHCP address pools, click on the right of the DHCP address pool to be deleted. In the dialog box that is displayed, click OK, as shown in Figure 7.
      Figure 7 Deletion page

  4. Refresh the DHCP address pool list.

    1. Log in to the web system, choose Config > IP Services > DHCP, click the DHCP Address Pool tab, and click Refresh to refresh the address pool list.
