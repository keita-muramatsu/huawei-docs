Overview of UDP

UDP is a simple datagram-oriented transport layer protocol. It does not provide reliability, flow control, or error recovery functions for IP. UDP is applicable to networks that have low reliability requirements and require low transmission costs.

UDP-based communication protocol.

Structure definition of the message header layer.

  • UDP-based Transport for Configured Subscriptions (UDP header in draft-ietf-netconf-udp-notif format)

Content layer

Telemetry layer

  • When the encoding format of the data to be sent is GPB, it is defined in the huawei-telemetry.proto file.
  • When the encoding format of the data to be sent is JSON, the .proto files at the telemetry layer are not required for decoding.

Service data layer

  • When the encoding format of the data to be sent is GPB, the value of the encoding field in the huawei-telemetry.proto file is 0, the data_gpb field carries sampled data in GPB format, and the data_str field is empty.
NOTE:

The data_gpb field needs to be decoded using the .proto file of the corresponding service, which is determined by the sensor_path field in the huawei-telemetry.proto file. For example, if the value of the sensor_path field is huawei-ifm:ifm/interfaces/interface, the .proto file is huawei-ifm.proto.

  • When the encoding format of the data to be sent is JSON, the value of the encoding field in the huawei-telemetry.proto file is 1, and the data_str field carries sampled data in JSON format.
NOTE:

When the JSON encoding format is used, you only need to use the .proto files at the RPC layer for decoding. The .proto files at the telemetry layer and the corresponding service .proto files are not required.

Interconnection When the Device Functions as a UDP Client

When the device functions as a UDP client, it can directly send data to the collector through UDP. Therefore, the data sending efficiency is high, but the reliability is lower than that of gRPC.

UDP has a lower requirement on the interconnection with a third-party collector than gRPC. Only the data model layer is concerned. Open-source software is not required for interconnection.

After an active/standby switchover is performed, or when the system restarts after saving the telemetry service configuration, the device reloads the telemetry service configuration so that the service can run properly. However, the data sampled during the restart or active/standby switchover is lost.
