Configuring an ISAKMP IPsec Policy

Prerequisites

  • An advanced ACL has been configured to define the data flows to be protected by IPsec.
  • An IPsec proposal has been configured.
  • IKE peers have been configured.

Context

Negotiated IPsec parameters of an ISAKMP IPsec policy are defined in the IPsec policy view, and the negotiation initiator and responder must use the same IPsec parameter settings. The device that has an ISAKMP IPsec policy configured can initiate negotiation. This situation applies when the remote IP address is fixed and is often used for branch configuration in point-to-multipoint IPsec networking.

Procedure

  1. Enter the system view.

    system-view

  2. Create an ISAKMP IPsec policy, and enter the ISAKMP IPsec policy view.

    ipsec policy policy-name seq-number isakmp

  3. Optional: Configure an alias for the IPsec policy.

    alias alias

    By default, the system uses the combination of the name and sequence number of an IPsec policy as the alias of the IPsec policy. If the default alias has been used by another IPsec policy, the system uses the combination of the name and sequence number of an IPsec policy as well as the current system time as the alias.

  4. Reference an advanced ACL.

    security acl [ ipv6 ] acl-number

    By default, an IPsec policy does not reference an ACL.

    acl-number specifies an existing advanced ACL. For details about how to create an advanced ACL, see Creating an Advanced ACL.

    An IPsec policy can reference only one ACL. Before an IPsec policy references a new ACL, you need to unbind the existing ACL from the IPsec policy.

  5. Reference an IPsec proposal.

    proposal proposal-name

    By default, an IPsec policy does not reference an IPsec proposal.

    proposal-name specifies an existing IPsec proposal. For details about how to configure an IPsec proposal, see Configuring an IPsec Proposal.

    An ISAKMP IPsec policy can reference a maximum of 12 IPsec proposals. During IKE negotiation, the two ends of an IPsec tunnel first use the IPsec proposals with the same parameter settings. If such IPsec proposals cannot be found, an SA cannot be established. When an IPsec policy needs to reference multiple IPsec proposals, ensure that all the IPsec proposals referenced in the IPsec policies at both ends of an IPsec tunnel use the same IPsec encapsulation mode.

  6. Reference an IKE peer.

    ike-peer peer-name

    By default, an IPsec policy does not reference an IKE peer.

    peer-name specifies an existing IKE peer. For details about how to configure an IKE peer, see Configuring an IKE Peer.

    IPsec policies with different sequence numbers in the same IPsec policy group cannot reference IKE peers with the same IP address.

  7. Optional: Configure the local IP address of an IPsec tunnel.

    tunnel local { { ipv4-address | ipv6-address } | applied-interface }

    By default, no local IP address is configured for an IPsec tunnel.

    For an IKE-negotiated IPsec policy, the local IPsec tunnel address configured using the tunnel local command on the local end must be the same as the remote address configured using the remote-address command on the remote end. In most cases, you do not need to manually configure the local IP address of an IPsec tunnel. During SA negotiation, the local IP address of an IPsec tunnel is automatically selected based on routes. In the following situations, however, you need to manually configure the local IP address of an IPsec tunnel:
    • There are equal-cost routes between the local and remote ends.

    • The IP address of the interface to which an IPsec policy is applied is not fixed or unpredictable.

    • Multiple IP addresses (one primary IP address and multiple secondary IP addresses) are configured on the interface to which an IPsec policy is applied.

    • An IPsec policy is applied to a tunnel interface, and an IP address is configured for the interface using the source { source-ip-address | interface-type interface-number } command.

  8. Optional: Configure the mode in which IPsec tunnel setup is triggered.

    sa trigger-mode { auto | traffic-based }

    By default, IPsec tunnel setup is triggered in traffic-based mode.

  9. Optional: Configure Perfect Forward Secrecy (PFS) used when the local end initiates negotiation.

    pfs { dh-group1 | dh-group2 | dh-group5 | dh-group14 | dh-group15 | dh-group16 | dh-group18 | dh-group19 | dh-group20 | dh-group21 | dh-group24 }

    By default, PFS is not used when the local end initiates negotiation.

    When the local end initiates negotiation, there is an additional DH exchange in IKEv1 phase 2 or IKEv2 Create_Child_SA Exchange, which ensures security of the IPsec SA key and improves communication security. Group 1, Group 2, and Group 5 are not recommended because they cannot meet security requirements.

    Table 1 lists the requirements for configuring PFS DH groups at both ends of an IPsec tunnel during PFS configuration.

    Table 1 Requirements for configuring PFS DH groups at both ends of an IPsec tunnel

    IPsec Policy Used at Both Ends

    Configuration Requirements

    Both ends use ISAKMP IPsec policies.

    The PFS DH groups specified on both ends must be the same. Otherwise, IPsec SA negotiation fails.

    One end uses a template IPsec policy, and the other end uses an ISAKMP IPsec policy.

    • If the PFS function is configured in the IPsec policy template view, the PFS DH groups specified at both ends must be the same. Otherwise, IPsec SA negotiation fails.

    • If the PFS function is not configured in the IPsec policy template view and the PFS DH groups specified at both ends are different, IPsec SA negotiation will succeed and the responder will use the DH group of the initiator.

  10. Optional: Configure the local end not to initiate negotiation.

    respond-only enable

    By default, if the local end establishes an IPsec tunnel based on an ISAKMP IPsec policy, the local end will initiate IPsec negotiation.

    If both the local and remote ends establish an IPsec tunnel based on ISAKMP IPsec policies, both ends will initiate IPsec negotiation. In this case, configure one end as the responder that does not initiate negotiation, which can help you check packet processing and locate IPsec faults.

  11. Optional: Enable an IPsec policy.

    policy enable

    By default, IPsec policies in an IPsec policy group are enabled.

Verifying the Configuration

Run the display ipsec policy [ brief | name policy-name [ seq-number ] ] [ slot slot-id cpu cpu-id ] command to check the IPsec policy configuration.
