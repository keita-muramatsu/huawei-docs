Example for Configuring Tunnel Interfaces on Gateways to Implement IPsec Link Redundancy

Networking Requirements

As shown in Figure 1, DeviceA and DeviceB connect networks A and B to the Internet, respectively, and have multiple links with reachable routes between them.

The requirements are as follows:

  • PC1 and PC2 can communicate with each other through the IPsec tunnel connecting networks A and B.

  • IPsec link redundancy is required between DeviceA and DeviceB. In this way, if one link is faulty, traffic of the IPsec tunnel can be switched to another link.

Figure 1 Networking diagram for configuring IPsec link redundancy

In this example, interface1, interface2, interface3, and interface4 represent 10GE 0/0/1, 10GE 0/0/2, 10GE 0/0/3, and 10GE 0/0/4, respectively.

Configuration Roadmap

The configuration procedure on DeviceA is similar to that on DeviceB. The following uses one of them as an example.

  1. Perform basic configurations, including configuring IP addresses for interfaces, adding interfaces to security zones, and configuring security policies.

  2. Create a tunnel interface and assign the tunnel interface to a security zone.

  3. Configure public network routes (typically static routes).

  4. Configure IPsec.

Procedure

  • Configure DeviceA.
    1. Configure IP addresses for interfaces.

      <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10ge 0/0/3
[DeviceA-10GE0/0/3] ip address 10.3.0.1 24
[DeviceA-10GE0/0/3] quit
      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ip address 1.1.1.1 24
[DeviceA-10GE0/0/1] quit
      [DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] ip address 2.2.2.2 24
[DeviceA-10GE0/0/2] quit
      [DeviceA] interface 10ge 0/0/4
[DeviceA-10GE0/0/4] ip address 3.3.3.3 24
[DeviceA-10GE0/0/4] quit

    2. Create and configure a tunnel interface.

      [DeviceA] interface tunnel 0
[DeviceA-tunnel0] tunnel-protocol ipsec
[DeviceA-tunnel0] ip address 192.0.2.1 24
[DeviceA-tunnel0] quit

    3. Configure a static route destined for network B. The following assumes that the outbound interface is Tunnel 0.

      [DeviceA] ip route-static 10.4.0.0 255.255.255.0 tunnel 0

    4. Configure three equal-cost routes to DeviceB. Next-hop addresses in the following are for reference only.

      [DeviceA] ip route-static 4.4.4.4 32 1.1.1.254
[DeviceA] ip route-static 4.4.4.4 32 2.2.2.254
[DeviceA] ip route-static 4.4.4.4 32 3.3.3.254

    5. Define the data flows to be protected by IPsec.

      [DeviceA] acl 3000
[DeviceA-acl4-advance-3000] rule 5 permit ip source 10.3.0.0 0.0.0.255 destination 10.4.0.0 0.0.0.255
[DeviceA-acl4-advance-3000] quit

    6. Configure an IPsec proposal named tran1.

      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] encapsulation-mode tunnel
[DeviceA-ipsec-proposal-tran1] transform esp
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256
[DeviceA-ipsec-proposal-tran1] quit

    7. Configure an IKE proposal numbered 10.

      [DeviceA] ike proposal 10
[DeviceA-ike-proposal-10] authentication-method pre-share
[DeviceA-ike-proposal-10] dh group14
[DeviceA-ike-proposal-10] quit

    8. Configure an IKE peer.

      [DeviceA] ike peer b
[DeviceA-ike-peer-b] ike-proposal 10
[DeviceA-ike-peer-b] remote-address 4.4.4.4
[DeviceA-ike-peer-b] pre-shared-key Test!123
[DeviceA-ike-peer-b] quit

      Set the remote address to the IP address of the interface connecting DeviceB to the Internet.

    9. Configure an IPsec policy named map1.

      [DeviceA] ipsec policy map1 10 isakmp
[DeviceA-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceA-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceA-ipsec-policy-isakmp-map1-10] ike-peer b
[DeviceA-ipsec-policy-isakmp-map1-10] quit

    10. Apply the IPsec policy map1 to the tunnel interface.

      [DeviceA] interface tunnel 0
[DeviceA-tunnel0] ipsec policy map1
[DeviceA-tunnel0] quit

  • Configure DeviceB.
    1. Perform basic configurations.

      Configure IP addresses for interfaces according to the data plan. The configuration procedure is similar to that on DeviceA.

    2. Configure a static route destined for network A. The following assumes that the next-hop address is 4.4.4.254.

      [DeviceB] ip route-static 10.3.0.0 255.255.255.0 4.4.4.254

    3. Configure a static route destined for the tunnel interface on DeviceA.

      [DeviceB] ip route-static 192.0.2.1 255.255.255.255 4.4.4.254

    4. Define the data flows to be protected by IPsec.

      [DeviceB] acl 3000
[DeviceB-acl4-advance-3000] rule 5 permit ip source 10.4.0.0 0.0.0.255 destination 10.3.0.0 0.0.0.255
[DeviceB-acl4-advance-3000] quit

    5. Configure an IPsec proposal named tran1.

      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] encapsulation-mode tunnel
[DeviceB-ipsec-proposal-tran1] transform esp
[DeviceB-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceB-ipsec-proposal-tran1] esp encryption-algorithm aes-256
[DeviceB-ipsec-proposal-tran1] quit

    6. Configure an IKE proposal numbered 10.

      [DeviceB] ike proposal 10 
[DeviceB-ike-proposal-10] authentication-method pre-share 
[DeviceB-ike-proposal-10] dh group14
[DeviceB-ike-proposal-10] quit

    7. Configure an IKE peer named a.

      [DeviceB] ike peer a 
[DeviceB-ike-peer-a] ike-proposal 10 
[DeviceB-ike-peer-a] remote-address 192.0.2.1 
[DeviceB-ike-peer-a] pre-shared-key Test!123 
[DeviceB-ike-peer-a] quit

    8. Configure an IPsec policy named map1 and numbered 10.

      [DeviceB] ipsec policy map1 10 isakmp 
[DeviceB-ipsec-policy-isakmp-map1-10] security acl 3000 
[DeviceB-ipsec-policy-isakmp-map1-10] proposal tran1 
[DeviceB-ipsec-policy-isakmp-map1-10] ike-peer a 
[DeviceB-ipsec-policy-isakmp-map1-10] quit

    9. Apply the IPsec policy map1 to 10GE 0/0/1.

      [DeviceB] interface 10ge 
[DeviceB-10GE0/0/1] ipsec policy map1
[DeviceB-10GE0/0/1] quit

    The IPsec tunnel is normal if the following conditions are met:

    • The outputs of the display ike sa and display ipsec sa commands show that IKE and IPsec SAs are normal.
    • Networks A and B can send packets to and receive packets from each other. The output of the display ipsec statistics command shows that the number of IPsec packets keeps increasing.

  • DeviceA

 sysname DeviceA
#
