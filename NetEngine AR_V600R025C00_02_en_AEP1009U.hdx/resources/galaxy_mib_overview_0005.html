SNMP Versions

SNMP versions include SNMPv1, SNMPv2c, and SNMPv3.

Both SNMPv1 and SNMPv2c use community name-based authentication. The NMS uses the community name list to control the device access rights, but the agent does not check whether the community name used by a given sender is authorized. Additionally, SNMP messages are not encrypted for transmission, so secure authentication and privacy are not ensured.

Compared with SNMPv1, SNMPv2c supports more operations, data types, error codes, and transport protocols.

SNMPv3 provides all the functions of SNMPv1 and SNMPv2c and also includes authentication and encryption of SNMP packets.

In terms of security, SNMPv3 emphasizes data security and access control.

SNMPv3 ensures the security of SNMP packets in the following ways:

  • Data integrity checks: Data cannot be modified without an authorization and the sequence of data cannot be modified beyond what is specifically authorized.
  • Data source verification: This verification makes it clear which user the received data comes from. SNMPv3 is user-based. Users who have generated data packets can be verified, but applications that generate the packets cannot.
  • Data confidentiality check: When the NMS or an agent receives a packet, it checks when the packet was generated. If the difference between the generation time and the current system time exceeds a specified time range, the packet is discarded. This prevents packets from being maliciously modified during transmission and prevents malicious packets from being received or processed.

SNMPv3 access control involves security check and controls access to managed objects based on protocol operations.

Different SNMP versions are used in different scenarios. The differences are described in Table 1.

Table 1 Usage scenarios of SNMP versions

SNMP Version

Application Scenario

SNMPv1

SNMPv1 is used for simple small-scale networks that are secure and stable or have low security requirements, such as campus networks and small enterprise networks.

SNMPv2c

SNMPv2c is used for medium- and large-scale networks, which are secure (such as VPN networks) or have low security requirements but may get congested due to heavy traffic.

SNMPv2c supports the Inform function, which ensures that the NMS can receive traps from managed devices.

SNMPv3

SNMPv3 is used for networks of any scale, particularly networks that have high security requirements and allow only authorized administrators to manage network devices. For example, in scenarios where the data exchanged between the NMS and managed devices needs to be transmitted over a public network, SNMPv3 can be used to authenticate and encrypt the data, ensuring the communication between the NMS and managed devices.

The features are as follows:
  • Access control is used to restrict a user's device management rights. This function allows a specified NMS to manage specified nodes on a device, achieving refined management.
  • Authentication and encryption are used to prevent data packets transmitted between the NMS and managed devices from being intercepted or tampered with.
  • Error codes help administrators to identify and rectify faults. The more varied and detailed the available error codes are, the easier it is for administrators to manage the devices.
  • Traps are sent by managed devices to the NMS so that the administrator can detect device exceptions in a timely manner. A managed device does not require an acknowledgement from the NMS after sending traps.
  • Inform alarms are sent from managed devices to the NMS as well. Upon receiving an Inform alarm from a managed device, the NMS needs to send a response packet for confirmation. If no response packet is received, the managed device sends Inform alarms repeatedly and generates the corresponding alarm log. In this way, if the NMS restarts, it can synchronize the Inform alarms sent during the restart. If no confirmation packet is received, the system saves the Inform alarms in the memory. That is why Inform alarms may consume a lot of system resources.
  • GetBulk allows an administrator to perform GetNextRequest operations in batches. This reduces the workload and improves management efficiency especially on large networks.
