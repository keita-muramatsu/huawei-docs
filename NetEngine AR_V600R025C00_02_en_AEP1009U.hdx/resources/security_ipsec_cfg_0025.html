Configuring a Template IPsec Policy

Prerequisites

  • An IPsec proposal has been configured.
  • IKE peers have been configured.

Context

A template IPsec policy reduces the configuration workload during the establishment of multiple IPsec tunnels. This situation applies when the remote IP address is not fixed or multiple peers exist. It is often used for headquarters configuration in point-to-multipoint IPsec networking.

When the local end uses a template IPsec policy to establish an IPsec tunnel, the local end cannot function as the initiator to initiate negotiation and can only function as the responder to accept negotiation requests from the remote end. The remote end must have an ISAKMP IPsec policy configured. In the IPsec policy template configuration, referencing an IPsec proposal and an IKE peer is mandatory, and other configurations are optional. The optional parameters that are not defined in an IPsec policy template are determined based on the proposal of the initiator.

Procedure

  1. Enter the system view.

    system-view

  2. Create an IPsec policy template, and enter the policy template view.

    ipsec policy-template template-name seq-number

  3. Optional: Configure an alias for the IPsec policy template.

    alias alias

    By default, the system uses the combination of the name and sequence number of an IPsec policy template as the alias of the IPsec policy template. If the default alias has been used by another IPsec policy template, the system uses the combination of the name and sequence number of an IPsec policy template as well as the current system time as the alias.

  4. Optional: Reference an advanced ACL.

    security acl [ ipv6 ] acl-number

    By default, an IPsec policy template does not reference an ACL.

    acl-number specifies an existing advanced ACL. For details about how to create an advanced ACL, see Creating an Advanced ACL.

    An IPsec policy template can reference only one ACL. Before an IPsec policy template references a new ACL, you need to remove the existing ACL that has been referenced.

    If data flows to be protected are not specified on the responder, the responder accepts the range of data flows to be protected on the initiator. If data flows to be protected need to be specified on the responder, the ACL on the responder must mirror the ACL on the initiator or the range specified by the ACL on the responder must include that on the initiator.

  5. Reference an IPsec proposal.

    proposal proposal-name

    By default, an IPsec policy template does not reference an IPsec proposal.

    proposal-name specifies an existing IPsec proposal. For details about how to configure an IPsec proposal, see Configuring an IPsec Proposal.

    An IPsec policy template can reference a maximum of 12 IPsec proposals. During IKE negotiation, the two ends of an IPsec tunnel first use the IPsec proposals with the same parameter settings. If such IPsec proposals cannot be found, an SA cannot be set up. When an IPsec policy needs to reference multiple IPsec proposals, ensure that all the IPsec proposals referenced in the IPsec policies at both ends of an IPsec tunnel use the same IPsec encapsulation mode.

  6. Reference an IKE peer.

    ike-peer peer-name

    By default, an IPsec policy template does not reference an IKE peer.

    peer-name specifies an existing IKE peer. For details about how to configure an IKE peer, see Configuring an IKE Peer.

  7. Optional: Configure the local IP address of an IPsec tunnel.

    tunnel local { ipv4-address | ipv6-address }

    By default, no local IP address is configured for an IPsec tunnel.

    For an IKE-negotiated IPsec policy, the local IPsec tunnel address configured using the tunnel local command on the local end must be the same as the remote address configured using the remote-address command on the remote end. In most cases, you do not need to manually configure the local IP address of an IPsec tunnel. During SA negotiation, the local IP address of an IPsec tunnel is automatically selected based on routes. In the following situations, however, you need to manually configure the local IP address of an IPsec tunnel:
    • There are equal-cost routes between the local and remote ends.

    • The IP address of the interface to which an IPsec policy is applied is not fixed or unpredictable.

    • Multiple IP addresses (one primary IP address and multiple secondary IP addresses) are configured on the interface to which an IPsec policy is applied.

    • An IPsec policy is applied to a tunnel interface, and an IP address is configured for the interface using the source { source-ip-address | interface-type interface-number } command.

  8. Optional: Configure PFS used when the local end initiates negotiation.

    pfs { dh-group1 | dh-group2 | dh-group5 | dh-group14 | dh-group15 | dh-group16 | dh-group18 | dh-group19 | dh-group20 | dh-group21 | dh-group24 }

    By default, PFS is not used when the local end initiates negotiation. When the local end initiates negotiation, there is an additional DH exchange in IKEv1 phase 2 or IKEv2 Create_Child_SA Exchange, which ensures security of the IPsec SA key and improves communication security. Group 1, Group 2, and Group 5 are not recommended because they cannot meet security requirements.

    Assume that one end of a tunnel uses a template IPsec policy and the other end uses an ISAKMP IPsec policy. If the PFS function is configured in the IPsec policy template view, the PFS DH groups specified at both ends must be the same. Otherwise, IPsec SA negotiation fails. If the PFS function is not configured in the IPsec policy template view and the PFS DH groups specified at both ends are different, IPsec SA negotiation will succeed and the responder will use the DH group of the initiator.

  9. Optional: Disable the device from immediately triggering IPsec tunnel re-negotiation after an ACL rule is modified.

    security acl-rule modification response disable

    By default, the device immediately triggers IPsec tunnel re-negotiation after an ACL rule is modified.

    After an ACL rule is modified, by default, the device immediately triggers IPsec tunnel re-negotiation, which results in a short interruption of IPsec traffic. To prevent this problem, perform this step so that the device does not re-negotiate an IPsec tunnel until the IPsec SA aging time expires. After the configuration is complete, use either of the following methods to trigger IPsec tunnel re-negotiation for a branch:

    • Run the reset ipsec sa remote ip-address command at the headquarters' device (the local end) to re-negotiate the IPsec SA of the branch.

    • Run the reset ipsec sa command on the branch's device (the remote end) to re-negotiate the IPsec SA.

  10. Optional: Enable an IPsec policy.

    policy enable

    By default, IPsec policies in an IPsec policy group are enabled.

  11. Return to the system view, create an IPsec policy, and reference the created IPsec policy template in the policy.

    quit
ipsec policy policy-name seq-number isakmp template template-name

    The referenced IPsec policy template name specified by template-name must be different from the IPsec policy name specified by policy-name.

    An IPsec policy group can contain only one template IPsec policy. It is recommended that the sequence number of a template IPsec policy be greater than that of other IPsec policies. That is, the template IPsec policy in an IPsec policy group must have the lowest priority. Otherwise, other IPsec policies may not take effect.

Verifying the Configuration

Run the display ipsec policy-template [ brief | name policy-template-name [ seq-number ] ] [ slot slot-id cpu cpu-id ] command to check the IPsec policy template configuration.
