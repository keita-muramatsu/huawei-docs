Configuring an IPsec Profile

Prerequisites

  • An IPsec proposal has been configured.
  • IKE peers have been configured.

Context

An IPsec profile defines how to protect data flows, including IPsec proposals, IKE negotiation parameters for SA establishment, SA lifetime, and Perfect Forward Secrecy (PFS). An IPsec profile is similar to an IPsec policy except that an IPsec profile is uniquely identified by its name and must be configured through IKE negotiation. For successful IKE negotiation, all the parameters specified in an IPsec profile on the local and remote ends must match.

Procedure

  1. Enter the system view.

    system-view

  2. Create an IPsec profile and enter the IPsec profile view.

    ipsec profile profile-name

  3. Reference an IPsec proposal.

    proposal proposal-name

    By default, an IPsec policy does not reference an IPsec proposal.

    proposal-name specifies an existing IPsec proposal. For details about how to configure an IPsec proposal, see Configuring an IPsec Proposal.

  4. Reference an IKE peer.

    ike-peer peer-name

    By default, an IPsec policy does not reference an IKE peer.

    peer-name specifies an existing IKE peer. For details about how to configure an IKE peer, see Configuring an IKE Peer.

    When an IPsec profile is used, the IP address configured using the destination command on a tunnel interface is preferentially used as the remote address for IKE negotiation. If this IP address is not configured, the IP address configured using the remote-address command in the IKE peer view is used for IKE negotiation. If both commands are run, ensure that the same IP address is configured using the two commands. Otherwise, IKE negotiation fails. If multiple IKE peers are referenced in an IPsec profile, do not run the destination command on a tunnel interface. Instead, you need to run the remote-address command on each IKE peer referenced in the IPsec profile.

  5. Optional: Configure PFS used when the local end initiates negotiation.

    pfs { dh-group1 | dh-group2 | dh-group5 | dh-group14 | dh-group15 | dh-group16 | dh-group18 | dh-group19 | dh-group20 | dh-group21 | dh-group24 }

    By default, PFS is not used when the local end initiates negotiation.

    When the local end initiates negotiation, there is an additional DH exchange in IKEv1 phase 2 or IKEv2 Create_Child_SA Exchange, which ensures security of the IPsec SA key and improves communication security. Group 1, Group 2, and Group 5 are not recommended because they cannot meet security requirements.

    During PFS configuration, the PFS DH groups specified on both ends must be the same. Otherwise, IPsec SA negotiation fails.

Verifying the Configuration

Run the display ipsec profile [ brief | name profile-name ] [ slot slot-id cpu cpu-id ] command to check the IPsec profile configuration.
