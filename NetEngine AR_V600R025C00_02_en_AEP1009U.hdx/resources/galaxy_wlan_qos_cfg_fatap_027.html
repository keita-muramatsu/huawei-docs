Understanding ACL-based Simplified Traffic Policies on the Wireless Side

An ACL-based simplified traffic policy enables the device to match packet information with ACL rules and provide the same QoS service for packets that match the same ACL rules, implementing differentiated services for different types of services.

To control traffic entering a network, you can configure ACL rules to match packets based on information such as the source IP address, fragment flag, destination IP address, source port number, and source MAC address in packets, and then configure an ACL-based simplified traffic policy so that the device can filter or re-mark packets that match the ACL rules.

Compared with a common traffic policy, an ACL-based simplified traffic policy is easier to configure because no traffic classifier, traffic behavior, or traffic policy needs to be created independently. However, an ACL-based simplified traffic policy defines fewer matching rules than a common traffic policy because only ACL rules are used to match packets.

ACL-based Packet Filtering

On a WLAN, administrators want to provide differentiated services for STAs. The services may include, but are not limited to the following:
  • Deny or permit access of specified STAs to specified LAN devices.
  • Deny access of specified STAs to specified invalid IP addresses.
You can configure ACL-based packet filtering in a traffic profile to provide differentiated services for STAs based on ACL rules.

After ACL-based packet filtering is configured in the traffic profile view, the device first matches packets against ACLs and then performs the action according to the matched policy.

A maximum of eight ACL-based packet filtering policies can be configured in one direction. When multiple ACL-based packet filtering commands are configured in the same direction in the same traffic profile, packets are matched against the next rule in the sequence in which the commands are configured. If packets match a rule, the device executes the specified policy and stops the matching process. Otherwise, the device continues to match packets against the next rule. If no rule is matched, the packets are allowed to pass through.

To change the sequence in which packets are filtered based on ACLs, delete all related configurations and reconfigure ACL-based packet filtering.

Note the following:

  • When a policy contains only one ACL: If a packet matches the ACL, the permit or deny action is performed based on the ACL.

  • When a policy contains two ACLs: Only when a packet matches both ACLs, the device considers that the packet matches the policy and performs the action based on the matched ACL.

    For example, if the actions in the two ACL rules are both permit, the permit action is performed. Otherwise, the deny action is performed.

If an ACL contains multiple rules, packets match against the rules in the ascending order of rule IDs. If packets match a rule, the device considers that the ACL is matched and stops the matching process. Otherwise, the device continues to match packets against the next rule. If no rule is matched, the device considers that this ACL is not matched. To improve match efficiency, you are advised to configure an ACL rule with a high match probability for packet priority re-marking. When configuring each ACL rule, set a small ID for the rule with a high match probability, reducing the number of times ACL rules are matched and saving resources.

For example, run the following commands to configure different rules for ACLs 4000, 3003, and 3005, and configure packet filtering based on these rules.
<HUAWEI> system-view
[HUAWEI] acl number 4000
[HUAWEI-acl-L2-4000] rule 5 deny source-mac 00e0-fc25-6110
[HUAWEI-acl-L2-4000] quit
[HUAWEI] acl 3003
[HUAWEI-acl4-advance-3003] rule 5 permit ip source 192.168.0.2 0
[HUAWEI-acl4-advance-3003] rule 10 deny ip source 192.168.0.1 0
[HUAWEI-acl4-advance-3003] quit
[HUAWEI] acl 3005
[HUAWEI-acl4-advance-3005] rule 5 permit ip source 192.168.2.0 0 destination 10.23.1.0 0.0.0.255
[HUAWEI-acl4-advance-3005] quit
[HUAWEI] wlan
[HUAWEI-wlan] traffic-profile name default
[HUAWEI-wlan-traffic-prof-default] traffic-filter inbound ipv4 acl 3003 //Policy 1
[HUAWEI-wlan-traffic-prof-default] traffic-filter inbound ipv4 acl 3005 l2 acl 4000 //Policy 2

ACL-based Packet Priority Re-marking

To re-mark packet priorities based on ACLs to provide differentiated services, you can run the traffic-remark command.

You can specify an empty ACL (numbered ACL) in this command, and configure this ACL later.

You can configure a maximum of eight ACL-based packet re-marking rules in the same direction. The sequence in which ACL rules takes effect follows the rule configuration sequence. To change the current packet re-marking rules, delete all the related configurations and reconfigure ACL-based packet re-marking.

When the traffic-remark command and the traffic-filter (traffic profile view) command are used simultaneously and the same ACL rule is associated:

  • If the deny action is configured in the ACL rule, the traffic-remark command does not take effect.
  • If the permit action is configured in the ACL rule, the command that was configured first takes effect.
