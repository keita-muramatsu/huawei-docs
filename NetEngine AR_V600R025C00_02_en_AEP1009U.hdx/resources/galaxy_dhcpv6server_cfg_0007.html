Enabling the DHCPv6 Server Function

Context

When the device functions as a DHCPv6 server, the DHCPv6 server function can be enabled in the system or interface view.

  • Enable the DHCPv6 server function in the interface view.

    After you enable the DHCPv6 server function on an interface and bind an IPv6 address pool to it, the device assigns IPv6 addresses or other configuration parameters (such as the DNS server address) to the clients connected to this interface from the bound address pool when the interface receives DHCPv6 request messages from the clients.

    • If a DHCPv6 server and clients reside on the same link (that is, a DHCPv6 relay agent does not exist), the device can assign IPv6 addresses or other configuration parameters (such as the DNS server address) to the clients.
    • If a DHCPv6 server and clients reside on different links (that is, a DHCPv6 relay agent exists), the device can assign IPv6 addresses or other configuration parameters (such as the DNS server address) to the clients in one network segment through the relay agent.

    • Only one IPv6 address pool can be specified on an interface.

    • If the DHCPv6 server function is enabled in the interface view, the configuration takes effect only on the interface.

  • Enable the DHCPv6 server function in the system view.

    When a DHCPv6 server and clients reside on different links (that is, a DHCPv6 relay agent exists), only one IPv6 address pool can be specified on an interface. As such, If the DHCPv6 server function is enabled in the interface view, configuration parameters such as IPv6 addresses can be assigned to the clients only in one network segment through the relay agent. To use the DHCPv6 relay agent to assign configuration parameters (such as IPv6 addresses) to DHCPv6 clients in multiple network segments, enable the DHCPv6 server function in the system view.

    If the DHCPv6 server function is enabled in the interface view and the interface is down, the DHCPv6 server cannot successfully assign configuration parameters to clients through the DHCPv6 relay agent. If the DHCPv6 server function is enabled in the system view, configuration parameters such as IPv6 addresses can be assigned to clients through the DHCPv6 relay agent as long as one route between the DHCPv6 relay agent and DHCPv6 server is reachable. This improves the reliability of the configuration obtained by the clients. In addition, requiring no configuration on the interface reduces the administrator's maintenance workload.

    • If the DHCPv6 server function is enabled in the system view, the configuration takes effect on all interfaces of the device.

    • If the DHCPv6 server function is enabled in both the system and interface views, the configuration in the interface view takes precedence over that in the system view.

Procedure

  • Enable the DHCPv6 server function in the interface view.
    1. Enter the system view.

      system-view

    2. Enable DHCP.

      dhcp enable

      By default, DHCP is disabled in the system.

    3. Enter the interface view.

      interface interface-type interface-number

    4. Switch the interface working mode to Layer 3.

      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    5. Enable IPv6 on the interface.

      ipv6 enable

      By default, IPv6 is disabled on an interface.

    6. Configure a global unicast IPv6 address for the interface.

      ipv6 address { ipv6-address prefix-length |ipv6-address/prefix-length }

    7. Enable the DHCPv6 server function on the interface.

      dhcpv6 server pool-name [ allow-hint | preference preference-value | rapid-commit | unicast ] *

      By default, the DHCPv6 server function is disabled on an interface.

  • Enable the DHCPv6 server function in the system view.
    1. Enter the system view.

      system-view

    2. Enable DHCP.

      dhcp enable

      By default, DHCP is disabled in the system.

    3. (Optional) Configure the behavior of the DHCPv6 server in the system view.

      dhcpv6 server { allow-hint | preference preference-value | rapid-commit | unicast } *

      By default, no behavior is configured for a DHCPv6 server in the system view.

    When the device functions as a DHCPv6 server, it may have multiple IPv6 address pools configured. After the DHCPv6 server receives a DHCPv6 request message, it selects an IPv6 address pool based on the following rules:

    • If a relay agent exists, the server selects the address pool that belongs to the same link scope with the network prefix (configured using the link-address command) or IPv6 address prefix (configured using the address prefix command) based on the first link-address field whose value is not 0 in the message. The link-address field identifies the link scope of DHCPv6 clients.

    • If no relay agent exists, the server cannot assign configuration parameters (including IPv6 addresses and DNS, NIS, and SNTP server addresses) to clients through DHCPv6. To resolve this issue, enable the DHCPv6 server function in the interface view.

Follow-up Procedure

For clients (such as PCs) that automatically obtain IPv6 addresses through IPv6 route advertisement by default, flags in RA messages need to be configured on the client gateway. This is necessary so that the clients can obtain IPv6 addresses using DHCPv6.

  • When no DHCPv6 relay agent exists and the DHCPv6 server functions as the gateway of clients, perform the following steps on the DHCPv6 server.

    1. Enter the system view.
      system-view
    2. Enter the interface view.
      interface interface-type interface-number
    3. Switch the interface working mode to Layer 3.
      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    4. Enable the system to send RA messages.

      ipv6 nd ra halt disable

      By default, the system is suppressed from sending all RA messages.

    5. Configure the managed address configuration flag of stateful address autoconfiguration in an RA message.

      ipv6 nd autoconfig managed-address-flag

      By default, the managed address configuration flag of stateful address autoconfiguration in an RA message is not configured.

    6. Configure the other configuration flag of stateful address autoconfiguration in an RA message.

      ipv6 nd autoconfig other-flag

      By default, the other configuration flag of stateful address autoconfiguration in an RA message is not configured.

      After the managed address configuration and other configuration flags of stateful address autoconfiguration in an RA message are configured, the clients can obtain IPv6 addresses using DHCPv6.

  • When a DHCPv6 relay agent exists and functions as a client gateway, perform the preceding operations on the DHCPv6 relay agent.

    When the device functions as a DHCPv6 client, you do not need to configure the flags in RA messages on the gateway. You can run the ipv6 address auto dhcp command to configure the device to automatically obtain an IPv6 address and other configuration parameters through DHCPv6.
