Configuring In-Service AP Upgrade

Prerequisites

The AP upgrade file has been uploaded to the WAC, SFTP server, or FTP server.

If the device has two main control boards, upload the upgrade file to the active main control board and run the copy source-filename destination-filename command to manually copy the upgrade file to the standby main control board. This ensures that the upgrade file is saved to both the active and standby main control boards.

Context

To upgrade the functions or versions of an existing WLAN, you can perform an in-service upgrade for APs on the WLAN.

An in-service upgrade can be carried out only for APs in normal or ver-mismatch state. If an AP finds its version different from the version in the AP upgrade file on the WAC, the AP starts the upgrade.

The following in-service upgrade modes are supported:
  • Upgrade of a single AP: allows you to upgrade a single AP to check whether the upgrade version can function properly. If the upgrade is successful, upgrade other APs in batches.
  • AP type–based upgrade: allows you to upgrade APs of the same type.
  • AP group–based upgrade: allows you to upgrade APs in the same AP group.
  • Channel group-based AP upgrade: allows you to upgrade APs in the same channel-based partition. If in-service upgrade is required for all APs on the network, you can pre-load the software package of the target version to all APs. To prevent service interruption caused by the restart of a large number of APs, you can divide APs into channel-based partitions and restart the APs by partition in sequence. This upgrade mode is also called multi-batch, scattered upgrade. During the reset of APs in a channel-based partition, their surrounding APs automatically fill coverage holes to ensure service continuity. Therefore, do not deploy only one AP for coverage at a site.
    APs with the same channel are grouped into the same channel-based partition. The details are as follows:
    • If 2.4 GHz and 5 GHz radios are both enabled on APs (including RUs), divide the APs based on the 5 GHz channel.
    • If the 2.4 GHz radio is disabled and the 5 GHz radio is enabled on APs (including RUs), divide the APs based on the 5 GHz channel.
    • If the 2.4 GHz radio is enabled and the 5 GHz radio is disabled on APs (including RUs), divide the APs based on the 2.4 GHz channel.
    • If the two 5 GHz radios are both enabled on APs (including RUs), divide the APs based on the 5 GHz channel with a smaller radio ID.
    • Add all central APs to the same channel-based partition.
  • During an in-service upgrade, if APs are reset before the upgrade file is loaded, the upgrade mode is switched to automatic.
  • If the space on an AP is found insufficient during the upgrade, the system automatically deletes redundant system software, patch files, and corefile folders from the AP. Run the display startup command on the AP to check the system software and patch files for the current and next startups. The system software and patch files that are not listed in the command output are considered redundant files.
  • Some APs do not support AP reset by channel-based partition.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Configure in-service upgrade.
    • Perform an in-service upgrade on a single AP.
      1. Upgrade the specified AP.
        ap update load { ap-mac ap-mac | ap-id ap-id } update-filename filename
      2. Reset the specified AP.
        ap update reset { ap-mac ap-mac-value | ap-id ap-id-value }
    • Configure batch upgrade for APs of an AP type.
      1. Specify the upgrade file for APs of the specified type.
        ap update update-filename filename ap-type type-id [ ap-group ap-group-name ]

        By default, no upgrade file is specified for APs of any type.

      2. Batch upgrade APs of the specified type.
        ap update multi-load ap-type type-id [ ap-group group-name | { ap-id ap-id } &<1-10> ]
      3. Batch reset APs of the specified type.
        ap update multi-reset ap-type type-id [ ap-group group-name | { ap-id ap-id } &<1-10> ]
    • Configure batch upgrade for APs in the same AP group.
      1. Specify the upgrade file for APs in the specified AP group.
        ap update update-filename filename ap-type type-id [ ap-group ap-group-name ]

        By default, no upgrade file is specified for APs of any type.

      2. Batch upgrade APs in the specified AP group.
        ap update multi-load ap-group group-name [ { ap-id ap-id } &<1-10> ]
      3. Batch reset APs in the specified AP group.
        ap update multi-reset ap-group group-name [ { ap-id ap-id } &<1-10> ]
    • Upgrade APs by channel-based partition.
      1. Specify the upgrade file for APs of the specified type.
        ap update update-filename filename ap-type type-id [ ap-group ap-group-name ]

        By default, no upgrade file is specified for APs of any type.

      2. Upgrade APs of the same type or in the same group in batches.
        ap update multi-load ap-type type-id [ ap-group group-name | { ap-id ap-id } &<1-10> ]

        Or

        ap update multi-load ap-group group-name [ { ap-id ap-id } &<1-10> ]
      3. Reset APs by channel-based partition.
        ap update multi-reset partition { all | partition-id partition-id }

Verifying the Configuration

  • Run the display ap update configuration command to check the AP upgrade configuration.
  • Run the display ap-type { all | id type-id | type ap-type } command to check information about AP types.
  • Run the display ap update status { all | downloading | failed | succeed | ap-id ap-id | ap-type ap-type | ap-group ap-group | waiting } command to check the AP upgrade progress.
  • Run the display ap update status partition { all | partition-id partition-id } command to check information about channel-based partitions.
