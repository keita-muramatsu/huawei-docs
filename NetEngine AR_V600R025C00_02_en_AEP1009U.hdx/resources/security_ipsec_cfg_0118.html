Understanding IPsec over GRE

Both IPsec over GRE and GRE over IPsec can secure data transmission. Their difference lies in the data encapsulation sequence. IPsec over GRE encapsulates packets using IPsec and then GRE, whereas GRE over IPsec encapsulates packets using GRE and then IPsec. As IPsec cannot encapsulate multicast packets, IPsec over GRE tunnels cannot transmit multicast data. Only GRE over IPsec can be used to securely transmit multicast data between two ends of a tunnel. In addition, GRE over IPsec supports NAT traversal when a NAT device is deployed between two ends of a tunnel, whereas IPsec over GRE does not.

If two LANs communicate with each other through a GRE tunnel and the security of the intranet needs to be enhanced without changing the original network deployment, you can perform IPsec encapsulation and then GRE encapsulation on traffic and establish an IPsec over GRE tunnel to protect traffic, as shown in Figure 1.

Table 1 Differences between GRE over IPsec and IPsec over GRE

Type

Encapsulation Order

Application Scenario

Feature

GRE over IPsec

First, a GRE header is added. Then, the packet, including the GRE header is encapsulated with IPsec.

This technology applies to scenarios where both ends have fixed IP addresses, or one end has a fixed IP address and the other end's IP address changes dynamically, or internal networks. The source and destination addresses of IPsec-protected data flows are GRE source and destination addresses.

All GRE-encapsulated data is encrypted by IPsec. IPsec on its own doesn't support the transmission of broadcast and multicast packets, but GRE can. Therefore, using IPsec over GRE enables the network to run protocols that rely on multicast and broadcast traffic.

IPsec over GRE

First, an IPsec header is added. Then, the packet, including the IPsec header is encapsulated with GRE.

This technology applies to the scenario where gateways at both ends have fixed IP addresses. IPsec policies are applied to physical interfaces to protect data flows on service network segments and encrypt only service data.

Fine-grained encryption control can be performed on the data to be protected.
