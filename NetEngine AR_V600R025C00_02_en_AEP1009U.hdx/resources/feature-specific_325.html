Example for Configuring Queue Scheduling HQoS in Parent and Child Traffic Policy Mode

Networking Requirements

In Figure 1, there are three types of users on the network: user1 (VIP), user2, and user3. They are assigned different IP address segments. Each user type has three types of services in descending order of priority: voice, video, and data, whose DSCP values are 46, 40, and 15, respectively. A minimum assured bandwidth is configured for each user type, and the interface bandwidth needs to be shared to maximize its usage. Traffic from users of type user1 must be preferentially transmitted.

Table 1 and Table 2 list the configuration requirements for different user types and services.

In this example, interface 1 represents 10GE 0/0/1.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Assign an IP address to 10GE 0/0/1 (where HQoS will be applied) on DeviceA.
  2. Configure an HQoS child traffic policy on DeviceA.
    1. Configure an FQ profile and set scheduling and shaping parameters for different services.
    2. Configure an FQ traffic policy. Classify traffic based on DSCP values and reference the FQ profile in a traffic behavior.
  3. Configure an HQoS parent traffic policy on DeviceA.
    1. Configure an SQ profile and set scheduling and shaping parameters for different users.
    2. Configure an SQ traffic policy. Classify traffic based on ACL rules and reference the SQ profile and HQoS child traffic policy in a traffic behavior.
  4. Apply the HQoS parent traffic policy to the outbound direction of 10GE 0/0/1 on DeviceA.

Procedure

  1. Configure 10GE 0/0/1 on DeviceA.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] undo portswitch
[DeviceA-10GE0/0/1] ip address 192.168.3.1 24
[DeviceA-10GE0/0/1] quit

  2. Configure an HQoS child traffic policy on DeviceA.

    # Configure an FQ profile.

    [DeviceA] flow-queue fq1
[DeviceA-flow-queue-fq1] queue voice pq shaping cir-shaping-percentage 15
[DeviceA-flow-queue-fq1] queue video drr weight 30 shaping cir-shaping-percentage 30
[DeviceA-flow-queue-fq1] queue data drr weight 10 shaping cir-shaping-percentage 45
[DeviceA-flow-queue-fq1] quit

    # Configure an FQ traffic policy.

    [DeviceA] traffic classifier voice
[DeviceA-classifier-voice] if-match dscp 46
[DeviceA-classifier-voice] quit
[DeviceA] traffic classifier video
[DeviceA-classifier-video] if-match dscp 40
[DeviceA-classifier-video] quit
[DeviceA] traffic classifier data
[DeviceA-classifier-data] if-match dscp 15
[DeviceA-classifier-data] quit
[DeviceA] traffic behavior voice
[DeviceA-behavior-voice] flow-queue fq1 queue voice
[DeviceA-behavior-voice] quit
[DeviceA] traffic behavior video
[DeviceA-behavior-video] flow-queue fq1 queue video
[DeviceA-behavior-video] quit
[DeviceA] traffic behavior data
[DeviceA-behavior-data] flow-queue fq1 queue data
[DeviceA-behavior-data] quit
[DeviceA] traffic policy sub-policy
[DeviceA-trafficpolicy-sub-policy] classifier voice behavior voice
[DeviceA-trafficpolicy-sub-policy] classifier video behavior video
[DeviceA-trafficpolicy-sub-policy] classifier data behavior data
[DeviceA-trafficpolicy-sub-policy] quit

  3. Configure an HQoS parent traffic policy on DeviceA.

    # Configure an SQ profile.

    [DeviceA] qos-user-profile uq1 
[DeviceA-qos-user-profile-uq1] user-queue user1 drr weight 30 cir 50000 cbs 1000000  
[DeviceA-qos-user-profile-uq1] user-queue user2 drr weight 10 cir 30000 cbs 750000 
[DeviceA-qos-user-profile-uq1] user-queue user3 drr weight 10 cir 20000 cbs 500000 
[DeviceA-qos-user-profile-uq1] quit

    # Configure an SQ traffic policy.

    [DeviceA] acl 2001
[DeviceA-acl4-basic-2001] rule permit source 10.10.10.0 24
[DeviceA-acl4-basic-2001] quit
[DeviceA] acl 2002
[DeviceA-acl4-basic-2002] rule permit source 10.10.20.0 24
[DeviceA-acl4-basic-2002] quit
[DeviceA] acl 2003
[DeviceA-acl4-basic-2003] rule permit source 10.10.30.0 24
[DeviceA-acl4-basic-2003] quit
[DeviceA] traffic classifier user1 
[DeviceA-classifier-user1] if-match acl 2001 
[DeviceA-classifier-user1] quit 
[DeviceA] traffic classifier user2 
[DeviceA-classifier-user2] if-match acl 2002 
[DeviceA-classifier-user2] quit
[DeviceA] traffic classifier user3 
[DeviceA-classifier-user3] if-match acl 2003
[DeviceA-classifier-user3] quit
[DeviceA] traffic behavior user1
[DeviceA-behavior-user1] qos-user-profile uq1 user-queue user1
[DeviceA-behavior-user1] traffic-policy sub-policy
[DeviceA-behavior-user1] quit
[DeviceA] traffic behavior user2
[DeviceA-behavior-user2] qos-user-profile uq1 user-queue user2
[DeviceA-behavior-user2] traffic-policy sub-policy                       
[DeviceA-behavior-user2] quit
[DeviceA] traffic behavior user3
[DeviceA-behavior-user3] qos-user-profile uq1 user-queue user3
[DeviceA-behavior-user3] traffic-policy sub-policy                      
[DeviceA-behavior-user3] quit
[DeviceA] traffic policy parent-policy
[DeviceA-trafficpolicy-parent-policy] classifier user1 behavior user1
[DeviceA-trafficpolicy-parent-policy] classifier user2 behavior user2
[DeviceA-trafficpolicy-parent-policy] classifier user3 behavior user3
[DeviceA-trafficpolicy-parent-policy] quit

  4. Apply the HQoS parent traffic policy to the outbound direction of the interface on DeviceA.

    [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] qos queue-scheduling enable   //Run this command if the queue capability is disabled on the device interface.
[DeviceA-10GE0/0/1] traffic-policy parent-policy outbound
[DeviceA-10GE0/0/1] quit
