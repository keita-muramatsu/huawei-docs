Example for Configuring Ethernet Interface Backup Association with NQA

Networking Requirements

On the network shown in Figure 1, the links between DeviceA, DeviceB, and DeviceD function as the primary links to transmit services between HostA and HostB. The links between DeviceA, DeviceC, and DeviceD function as the backup links.

Devices are required to monitor the primary link status in real time. When the primary link is faulty, services are transmitted on the backup link to reduce the impact of the primary link fault on service transmission.

Figure 1 Associating Ethernet interface backup with NQA

In this example, interface1 and interface2 represent 10GE0/0/1 and 10GE0/0/2, respectively.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure an IP address for each interface and a static route to ensure connectivity at the network layer.

  2. Configure an ICMP NQA test instance on DeviceA and DeviceD to monitor the primary link status in real time.

  3. Configure association between interface backup and NQA on the standby interfaces (10GE0/0/2) of DeviceA and DeviceD. When NQA detects a fault on the primary link, traffic can be rapidly switched to the backup link.

Procedure

  1. Configure connectivity at the network layer.
    # Assign an IP address to each interface. The following uses DeviceA as an example.
    <HUAWEI> system-view 
[HUAWEI] sysname DeviceA
[DeviceA] interface 10GE0/0/1
[DeviceA-10GE0/0/1] ip address 10.1.2.1 24
[DeviceA-10GE0/0/1] quit
[DeviceA] interface 10GE0/0/2
[DeviceA-10GE0/0/2] ip address 10.1.3.1 24
[DeviceA-10GE0/0/2] quit

    # On DeviceA, configure static routes to DeviceD's 10.1.4.0/24 and 10.1.5.0/24.

    [DeviceA] ip route-static 10.1.4.0 255.255.255.0 10.1.2.2 preference 80
[DeviceA] ip route-static 10.1.5.0 255.255.255.0 10.1.3.2 preference 60

    # On DeviceD, configure static routes to DeviceA's 10.1.2.0/24 and 10.1.3.0/24.

    [DeviceD] ip route-static 10.1.2.0 255.255.255.0 10.1.4.1 preference 80
[DeviceD] ip route-static 10.1.3.0 255.255.255.0 10.1.5.1 preference 60
  2. Configure an ICMP NQA test instance on DeviceA and DeviceD to monitor the primary link status in real time.

    # Configure the ICMP NQA test instance in the system view of DeviceA.

    [DeviceA] nqa test-instance user test
[DeviceA-nqa-user-test] test-type icmp
[DeviceA-nqa-user-test] destination-address ipv4 10.1.4.2
[DeviceA-nqa-user-test] frequency 10
[DeviceA-nqa-user-test] probe-count 2
[DeviceA-nqa-user-test] start now
[DeviceA-nqa-user-test] quit

    # Configure the ICMP NQA test instance in the system view of DeviceD.

    [DeviceD] nqa test-instance admin test
[DeviceD-nqa-admin-test] test-type icmp
[DeviceD-nqa-admin-test] destination-address ipv4 10.1.2.1
[DeviceD-nqa-admin-test] frequency 10
[DeviceD-nqa-admin-test] probe-count 2
[DeviceD-nqa-admin-test] start now
[DeviceD-nqa-admin-test] quit
  3. Configure association between interface backup and NQA on the standby interfaces (10GE0/0/2) of DeviceA and DeviceD. When NQA detects a fault on the primary link, traffic can be rapidly switched to the backup link.

    # Configure association between interface backup and NQA on DeviceA.

    [DeviceA] interface 10GE0/0/2
[DeviceA-10GE0/0/2] standby track nqa user test
[DeviceA-10GE0/0/2] quit

    # Configure association between interface backup and NQA on DeviceD.

    [DeviceD] interface 10GE0/0/2
[DeviceD-10GE0/0/2] standby track nqa admin test
[DeviceD-10GE0/0/2] quit

Configuration Scripts

  • DeviceA

    #
sysname DeviceA
#
interface 10GE0/0/1
 ip address 10.1.2.1 255.255.255.0
#
interface 10GE0/0/2
 ip address 10.1.3.1 255.255.255.0
 standby track nqa user test
#
ip route-static 10.1.4.0 255.255.255.0 10.1.2.2 preference 80
#
ip route-static 10.1.5.0 255.255.255.0 10.1.3.2
#
nqa test-instance user test
 test-type icmp
 destination-address ipv4 10.1.4.2
 frequency 10
 probe-count 2
 start now
#
return

    #
sysname DeviceB
#

#

#
return
