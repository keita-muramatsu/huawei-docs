Layer 3 Multicast Security

Overview

Layer 3 multicast security policies include PIM neighbor filtering, PIM Join message filtering, MSDP MD5 authentication, and MSDP keychain authentication.

  • PIM neighbor filtering

    ACL rules can be configured on interfaces to filter received Hello messages. Neighbor relationships can be established only after the Hello messages pass the filtering.

    If a large number of malicious Hello messages exist, configure rules on interfaces so that the interfaces allow only specified Hello messages to pass through and discard malicious Hello messages.

  • PIM Join message filtering

    ACL rules can be configured on interfaces to filter received Join messages. This can prevent attacks initiated using malicious Join messages.

    If a large number of malicious Join messages exist, configure rules on interfaces so that the interfaces allow only specified Join messages to pass through and discard malicious Join messages.

  • MSDP MD5 authentication

    MD5 authentication can be configured on MSDP peers to provide security protection. MD5 authentication must be enabled on both peers, and the authentication passwords configured for them must be the same. After this function is enabled, the transmit end peer sends an MD5-encrypted MSDP message, which is transferred to the receive end peer over a TCP connection. The receive end peer decrypts the MSDP message based on the uniform MD5 encryption rules and the key contained in the message. After decrypting the message successfully, the receive end peer sends the message to the MSDP module for processing.

    Only the MSDP messages passing MD5 authentication are processed. This effectively prevents attacks that are conducted through malicious messages.

  • MSDP keychain authentication

    Multicast MSDP supports keychains. Keychains and new TCP extension options can be used to configure a group of passwords for each TCP connection. Each password can be configured with different encryption algorithms and validity periods. Passwords can be changed at any time, which greatly improves the security of encrypted messages.

    Only the messages passing keychain authentication are processed. This effectively prevents attacks that are conducted through malicious messages.

Impact on the System

None

Procedure

  • Configure PIM neighbor filtering.
    1. Enter the system view.

      system-view

    2. Configure a basic numbered ACL or named ACL as needed.

      • Configure a basic ACL.
        acl [ number ] basic-acl-number
 rule [ rule-id ] [ name rule-name ] { deny | permit } source { source-ip-address { source-wildcard | 0 } | any }
 quit
      • Configure a named ACL.
        acl name acl-name basic
 rule [ rule-id ] [ name rule-name ] { deny | permit } source { source-ip-address { source-wildcard | 0 } | any }
 quit

    3. Enter the PIM interface view.

      interface interface-type interface-number

    4. Switch the interface working mode to Layer 3.

      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    5. Configure a neighbor filtering policy.

      pim neighbor-policy { basic-acl-number | acl-name acl-name }

      The neighbor filtering policy defines the range of valid neighbor addresses, and the device discards the Hello messages received from the neighbors whose addresses are beyond the range.

      • If a received message matches the ACL rule in permit mode, the device establishes a neighbor relationship with the remote end.
      • If a received message matches the ACL rule in deny mode, the device does not establish a neighbor relationship with the remote end.
      • If a received message does not match the ACL rule, the device does not establish a neighbor relationship with the remote end.
      • If a specified ACL does not exist or does not contain rules, the device does not establish a neighbor relationship with any other devices using any address.

  • Configure PIM Join message filtering.
    1. Enter the system view.

      system-view

    2. Configure a basic or an advanced ACL as needed.

      • Configure a basic ACL.
        acl [ number ] basic-acl-number
 rule [ rule-id ] [ name rule-name ] { deny | permit } source { source-ip-address { source-wildcard | 0 } | any }
 quit
      • Configure an advanced ACL.
        acl { name advance-acl-name [ advance | [ number ] advance-acl-number ] | [ number ] advance-acl-number }
 rule [ rule-id ] [ name rule-name ] { deny | permit } ip [ destination { destination-ip-address { destination-wildcard | 0 } | any } | source { source-ip-address { source-wildcard | 0 } | any } ] *
 quit

    3. Enter the PIM interface view.

      interface interface-type interface-number

    4. Switch the interface working mode to Layer 3.

      undo portswitch

      Determine whether to perform this step based on the current interface working mode.

    5. Configure a policy to filter join information in Join/Prune messages.

      pim join-policy { { advanced-acl-number | acl-name acl-name } | asm { basic-acl-number | acl-name acl-name } | ssm { advanced-acl-number | acl-name acl-name } }

      If asm is specified, set the multicast group address range for join information through the source parameter in the rule command in the basic ACL view.

      If ssm is specified, set the multicast source address range and multicast group address range for join information through the source and destination parameters, respectively, in the rule command in the advanced ACL view.

      • If a Join message's join information matches an ACL rule and the action is permit, the device permits this message.
      • If a Join message's join information matches an ACL rule and the action is deny, the device denies this message.
      • If a Join message's join information does not match any ACL rule, the device denies this message.
      • If a specified ACL does not exist or does not contain rules, the device denies all Join messages.

  • Configure MSDP MD5 authentication.
    1. Enter the system view.

      system-view

    2. Enter the MSDP view.

      msdp [ vpn-instance vpn-instance-name ]

    3. Configure MSDP MD5 authentication.

      peer peer-address password { cipher cipher-password | simple simple-password }

      After this function is enabled, the transmit end peer sends an MD5-encrypted MSDP message, which is transferred to the receive end peer over a TCP connection. The receive end peer decrypts the MSDP message based on the uniform MD5 encryption rules and the key contained in the message. After decrypting the message successfully, the receive end peer sends the message to the MSDP module for processing.

      MD5 authentication must be enabled on both peers, and the authentication passwords configured for them must be the same.

      • If simple is specified, the password is saved in the configuration file in cleartext. This brings security risks. You are advised to specify cipher so that the password is saved in ciphertext in the configuration file.

      • The password must be at least eight characters long and contains at least two of the following character types: uppercase letters, lowercase letters, digits, and special characters (excluding question marks and spaces).

      • For security purposes, you are advised to configure a ciphertext password and change it periodically.

  • Configure MSDP authentication.
    1. Enter the system view.

      system-view

    2. Enter the MSDP view.

      msdp [vpn-instance vpn-instance-name]

    3. Configure an MSDP keychain.

      peer peer-address keychain keychain-name

      Keychain authentication must be configured on both MSDP peers, and the keychains configured at both ends must use the same encryption algorithm and password so that a TCP connection can be set up and MSDP messages can be exchanged properly.

      The keychain specified by keychain-name must exist before you configure MSDP keychain authentication; otherwise, the TCP connection cannot be established.

      MD5 and keychain authentication modes are mutually exclusive.

      The encryption algorithm used for MD5 authentication poses security risks. Therefore, you are advised to use an authentication mode based on a supported more secure encryption algorithm.

Verifying the Security Hardening Result

Run the display msdp { vpn-instance vpn-instance-name | all-instance } peer-status [ peer-address ] command to check authentication information about MSDP peers.
