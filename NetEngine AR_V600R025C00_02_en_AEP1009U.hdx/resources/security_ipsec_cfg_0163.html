Example for Establishing IPsec Tunnels Between a Branch and the HQ with Redundant Gateways

Networking Requirements

As shown in Figure 1, the HQ has two redundant gateways, DeviceA and DeviceB, while the branch deploys DeviceC as its gateway. Communication between the branch and HQ is carried over the Internet and needs to be protected.

To meet this requirement, configure DeviceC to establish IPsec tunnels with both DeviceA and DeviceB. It first attempts to connect to DeviceA; if unsuccessful, it switches to DeviceB. This setup ensures redundant IPsec connectivity between the branch and HQ.

Figure 1 Network diagram for establishing IPsec tunnels between a branch and the HQ with redundant gateways

In this example, interface 1 and interface 2 represent 10GE 0/0/1 and 10GE 0/0/2, respectively.


Configuration Roadmap

This example uses default security algorithms of IPsec.

For security purposes, you are advised not to use the weak security algorithm or weak security protocol of this feature. If you must use such a weak security algorithm or protocol, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA.

  1. Complete the basic configuration, including interface IP addresses and routes, to ensure connectivity between the HQ and branch.

  2. Configure IPsec policies, including the data flows to be encrypted and negotiation parameters for both IKE and IPsec proposals.

    • Configure a template IPsec policy at the HQ to respond to requests from the branch.
    • Configure an ISAKMP IPsec policy at the branch to initiate requests.

      When configuring an IKE peer on the branch gateway, specify both HQ gateway addresses as the remote addresses. This allows the branch gateway to automatically switch to DeviceB if it fails to establish an IPsec tunnel with DeviceA.

  3. Apply IPsec policies to interfaces.

Procedure

  1. Configure DeviceA (HQ gateway 1).
    1. Configure IP addresses for interfaces.

      # Configure the Internet-facing interface 10GE 0/0/1.
      <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] interface 10GE0/0/1
[DeviceA-10GE0/0/1] ip address 60.1.1.1 24
[DeviceA-10GE0/0/1] quit
      # Configure the private network interface 10GE 0/0/2.
      [DeviceA] interface 10GE0/0/2
[DeviceA-10GE0/0/2] ip address 192.168.1.2 24
[DeviceA-10GE0/0/2] quit

    2. Configure static routes to the remote end. In this example, the next-hop address of the route to the branch gateway is 60.1.1.2.

      [DeviceA] ip route-static 70.1.1.0 255.255.255.0 60.1.1.2
[DeviceA] ip route-static 192.168.3.0 255.255.255.0 60.1.1.2

    3. Configure an IPsec policy and apply it to the required interface.

      In this example, template IPsec policies are configured on the HQ gateways (DeviceA and DeviceB); therefore, configuring an ACL is optional on them. If you configure an ACL on the HQ gateways, you must specify the destination address in the ACL rule.

      # Configure an IPsec proposal. You can use the default parameter settings.
      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceA-ipsec-proposal-tran1] quit
      # Configure an IKE proposal. You can use the default parameter settings.
      [DeviceA] ike proposal 5
[DeviceA-ike-proposal-5] authentication-method pre-share
[DeviceA-ike-proposal-5] prf hmac-sha2-256
[DeviceA-ike-proposal-5] encryption-algorithm aes-gcm-256
[DeviceA-ike-proposal-5] dh group14
[DeviceA-ike-proposal-5] integrity-algorithm hmac-sha2-256  
[DeviceA-ike-proposal-5] quit
      # Configure an IKE peer.
      [DeviceA] ike peer rut1
[DeviceA-ike-peer-rut1] ike-proposal 5
[DeviceA-ike-peer-rut1] pre-shared-key Test!1234
[DeviceA-ike-peer-rut1] quit

      The HQ gateways function as the responder during IKE negotiation and use a template IPsec policy. Therefore, there is no need to configure remote-address on them.

      # Configure a template IPsec policy and apply an IPsec policy group to the outbound interface.
      [DeviceA] ipsec policy-template use1 10 
[DeviceA-ipsec-policy-templet-use1-10] proposal tran1 
[DeviceA-ipsec-policy-templet-use1-10] ike-peer rut1
[DeviceA-ipsec-policy-templet-use1-10] quit 
[DeviceA] ipsec policy policy1 10 isakmp template use1
[DeviceA] interface 10GE0/0/1
[DeviceA-10GE0/0/1] ipsec policy policy1
[DeviceA-10GE0/0/1] quit

  2. Configure DeviceB (HQ gateway 2).
    1. Configure IP addresses for interfaces.

      # Configure the Internet-facing interface 10GE 0/0/1.
      <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10GE0/0/1
[DeviceB-10GE0/0/1] ip address 60.1.2.1 24
[DeviceB-10GE0/0/1] quit
      # Configure the private network interface 10GE 0/0/2.
      [DeviceB] interface 10GE0/0/2
[DeviceB-10GE0/0/2] ip address 192.168.1.3 24
[DeviceB-10GE0/0/2] quit

    2. Configure static routes to the remote end. In this example, the next-hop address of the route to the branch gateway is 60.1.2.2.

      [DeviceB] ip route-static 70.1.1.0 255.255.255.0 60.1.2.2
[DeviceB] ip route-static 192.168.3.0 255.255.255.0 60.1.2.2

    3. Configure an IPsec policy and apply it to the required interface.

      In this example, template IPsec policies are configured on the HQ gateways (DeviceA and DeviceB); therefore, configuring an ACL is optional on them. If you configure an ACL on the HQ gateways, you must specify the destination address in the ACL rule.

      # Configure an IPsec proposal. You can use the default parameter settings.
      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceB-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceB-ipsec-proposal-tran1] quit
      # Configure an IKE proposal. You can use the default parameter settings.
      [DeviceB] ike proposal 5
[DeviceB-ike-proposal-5] authentication-method pre-share
[DeviceB-ike-proposal-5] prf hmac-sha2-256
[DeviceB-ike-proposal-5] encryption-algorithm aes-gcm-256
[DeviceB-ike-proposal-5] dh group14
[DeviceB-ike-proposal-5] integrity-algorithm hmac-sha2-256  
[DeviceB-ike-proposal-5] quit
      # Configure an IKE peer.
      [DeviceB] ike peer rut1
[DeviceB-ike-peer-rut1] ike-proposal 5
[DeviceB-ike-peer-rut1] pre-shared-key Test!1234
[DeviceB-ike-peer-rut1] quit

      The HQ gateways function as the responder during IKE negotiation and use a template IPsec policy. Therefore, there is no need to configure remote-address on them.

      # Configure a template IPsec policy and apply an IPsec policy group to the outbound interface.
      [DeviceB] ipsec policy-template use1 10 
[DeviceB-ipsec-policy-templet-use1-10] proposal tran1 
[DeviceB-ipsec-policy-templet-use1-10] ike-peer rut1
[DeviceB-ipsec-policy-templet-use1-10] quit 
[DeviceB] ipsec policy policy1 10 isakmp template use1
[DeviceB] interface 10GE0/0/1
[DeviceB-10GE0/0/1] ipsec policy policy1
[DeviceB-10GE0/0/1] quit

  3. Configure the branch gateway DeviceC.
    1. Configure IP addresses for interfaces.

      # Configure the Internet-facing interface 10GE 0/0/1.
      <HUAWEI> system-view
[HUAWEI] sysname DeviceC
[DeviceC] interface 10GE0/0/1
[DeviceC-10GE0/0/1] ip address 70.1.1.1 24
[DeviceC-10GE0/0/1] quit
      # Configure the private network interface 10GE 0/0/2.
      [DeviceC] interface 10GE0/0/2
[DeviceC-10GE0/0/2] ip address 192.168.3.2 24
[DeviceC-10GE0/0/2] quit

    2. Configure a static route to the remote end. In this example, the next-hop address of the route to the HQ gateways is 70.1.1.2.

      [DeviceC] ip route-static 0.0.0.0 0.0.0.0 70.1.1.2

    3. Configure an IPsec policy and apply it to the required interface.

      # Configure an ACL to define the data flow from the subnet 192.168.3.0/24 to the subnet 192.168.1.0/24.
      [DeviceC] acl 3002
[DeviceC-acl4-advance-3002] rule 5 permit ip source 192.168.3.0 0.0.0.255 destination 192.168.1.0 0.0.0.255
[DeviceC-acl4-advance-3002] quit
      # Configure an IPsec proposal. You can use the default parameter settings.
      [DeviceC] ipsec proposal tran1
[DeviceC-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceC-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceC-ipsec-proposal-tran1] quit
      # Configure an IKE proposal. You can use the default parameter settings.
      [DeviceC] ike proposal 5
[DeviceC-ike-proposal-5] authentication-method pre-share
[DeviceC-ike-proposal-5] prf hmac-sha2-256
[DeviceC-ike-proposal-5] encryption-algorithm aes-gcm-256
[DeviceC-ike-proposal-5] dh group14
[DeviceC-ike-proposal-5] integrity-algorithm hmac-sha2-256  
[DeviceC-ike-proposal-5] quit
      # Configure an IKE peer.
      [DeviceC] ike peer rut1
[DeviceC-ike-peer-rut1] ike-proposal 5
[DeviceC-ike-peer-rut1] pre-shared-key Test!1234
[DeviceC-ike-peer-rut1] remote-address 60.1.1.1
[DeviceC-ike-peer-rut1] remote-address 60.1.2.1
[DeviceC-ike-peer-rut1] quit

      When configuring an IKE peer on the branch gateway, specify both HQ gateway addresses as the remote addresses. This allows the branch gateway to automatically switch to DeviceB if it fails to establish an IPsec tunnel with DeviceA.

      # Configure an IPsec policy and apply an IPsec policy group to the outbound interface.
      [DeviceC] ipsec policy policy1 10 isakmp
[DeviceC-ipsec-policy-isakmp-policy1-10] security acl 3002
[DeviceC-ipsec-policy-isakmp-policy1-10] proposal tran1
[DeviceC-ipsec-policy-isakmp-policy1-10] ike-peer rut1
[DeviceC-ipsec-policy-isakmp-policy1-10] sa trigger-mode auto
[DeviceC-ipsec-policy-isakmp-policy1-10] quit 
[DeviceC] interface 10GE0/0/1
[DeviceC-10GE0/0/1] ipsec policy policy1
[DeviceC-10GE0/0/1] quit
