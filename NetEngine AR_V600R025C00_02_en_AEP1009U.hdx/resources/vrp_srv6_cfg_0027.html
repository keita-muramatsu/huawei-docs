Configuring Public Network IPv4 over SRv6 TE Policy

Prerequisites

Before configuring public network IPv4 over SRv6 TE Policy, you have completed the following tasks:

  • Configure an SRv6 TE Policy manually or use a controller to dynamically deliver an SRv6 TE Policy.

  • Configuring Color-based Traffic Steering into an SRv6 TE Policy or Configuring TE-Class-based Traffic Steering into an SRv6 TE Policy.

Context

Public network IPv4 over SRv6 TE Policy uses SRv6 TE Policies on a public network to carry public network IPv4 data. Implementing public network IPv4 over SRv6 TE Policy involves establishing SRv6 TE Policies, advertising BGP routes, and forwarding data. As shown in Figure 1, PE1 and PE2 communicate through an IPv6 public network. An SRv6 TE Policy can be established on the IPv6 public network to carry public network IPv4 services.

Figure 1 Network diagram of public network IPv4 over SRv6 TE Policy

Procedure

  1. Configure IPv6 IS-IS on the PEs and P. For configuration details, see Configuring Basic IS-IS Functions.
  2. Establish an EBGP peer relationship between PE1 and DeviceA and another one between PE2 and DeviceB.
    1. Enter the system view.

      system-view

    2. Enter the BGP view.

      bgp as-number

    3. Configure a BGP router ID.

      router-id ipv4-address

    4. Configure a peer with a specified address and specify an AS number for the peer.

      peer ipv4-address as-number as-number

    5. Exit the BGP view.

      quit

  3. Establish an IBGP peer relationship between the PEs.
    1. Enter the BGP view.

      bgp as-number

    2. Specify a peer address and the AS where the peer resides.

      peer ipv6-address as-number as-number

    3. Specify the source interface and address used to establish a TCP connection.

      peer ipv6-address connect-interface interface-type interface-number

    4. Enter the BGP-IPv4 unicast address family view.

      ipv4-family unicast

    5. Enable the device to exchange routing information with the specified IPv6 peer.

      peer ipv6-address enable

    6. Exit the IPv4 unicast address family view.

      quit

    7. Exit the BGP view.

      quit

  4. Configure basic SRv6 functions.
    1. Enable Segment Routing in the IPv6 forwarding plane and enter the SRv6 view.

      segment-routing ipv6

    2. Configure a source address for SRv6 encapsulation.

      encapsulation source-address ipv6-address

      Alternatively:

      encapsulation source-interface { intfname | interfaceType interfaceNum }

      You only need to run one of the preceding commands. If they are both run, the later configuration overrides the previous one. If no IPv6 global address is configured for the interface specified using the encapsulation source-interface command, the source address for SRv6 encapsulation is not configured.

    3. Configure an SRv6 locator.

      locator locator-name [ ipv6-prefix ipv6-address mask-length [ static static-length | args args-length ] * ]

    4. (Optional) Configure a static SID opcode.

      opcode func-opcode end-dt4

      An End.DT4 SID can be dynamically allocated by BGP or be manually configured. If a dynamically allocated SID and a manually configured SID both exist, the latter takes effect. If you want to use the segment-routing ipv6 locator locator-name command to enable dynamic End.DT4 SID allocation through BGP in the future, skip this step.

    5. Exit the SRv6 locator view.

      quit

    6. Exit the SRv6 view.

      quit

  5. Enable IS-IS SRv6.
    1. Enter the IS-IS view.

      isis [ process-id ]

    2. Enable the IPv6 capability for the IS-IS process in the IPv6 topology.

      ipv6 enable topology ipv6

    3. Enable IS-IS SRv6.

      segment-routing ipv6 locator locator-name [ auto-sid-disable ]

    4. Exit the IS-IS view.

      quit

  6. Configure each PE to add color and SID attributes to public network routes to be advertised.
    1. Create a route-policy with a specified node and enter the route-policy view.

      route-policy route-policy-name { permit | deny } node node

    2. Specify the color extended community attribute.

      apply extcommunity color color

    3. Exit the route-policy view.

      quit

    4. Enter the BGP view.

      bgp as-number

    5. Enter the BGP-IPv4 unicast address family view.

      ipv4-family unicast

    6. Apply the export route-policy to routes to be advertised to the specified peer so that the color attribute can be carried in these routes.

      peer ipv6-address route-policy route-policy-name export

    7. Enable the device to advertise extended community attributes to the specified peer.

      peer peerIpv6Addr advertise-ext-community

    8. Enable the device to exchange prefix SID information with the specified peer.

      peer ipv6-address prefix-sid

    9. Enable the device to add SIDs to public network routes.

      segment-routing ipv6 locator locator-name

    10. Exit the BGP-IPv4 unicast address family view.

      quit

  7. Configure an SRv6 TE Policy. For details, see Configuring an SRv6 TE Policy (Manual Configuration) or Configuring an SRv6 TE Policy (Controller-based Dynamic Delivery).
  8. Configure the device to recurse public network routes to the SRv6 TE Policy.
    1. Create a tunnel policy and enter the tunnel policy view.

      tunnel-policy policy-name

    2. Specify the tunnel type to be selected and the maximum number of tunnels that can participate in load balancing.

      tunnel select-seq ipv6 srv6-te-policy load-balance-number loadBalanceNumber

    3. Exit the tunnel policy view.

      quit

    4. Create a tunnel selector and enter the tunnel selector view.

      tunnel-selector name { permit | deny } node node

    5. Apply a tunnel policy to routes.

      apply tunnel-policy tunnel-policy-name

    6. Exit the tunnel selector view.

      quit

    7. Enter the BGP view.

      bgp as-number

    8. Enter the BGP-IPv4 unicast address family view.

      ipv4-family unicast

    9. Enable the function to recurse public network routes to IPv6 tunnels.

      unicast-route recursive-lookup tunnel-v6 tunnel-selector tunnel-selector-name

    10. Enable the device to recurse routes to the SRv6 TE Policy based on the color and SID values carried in the routes.

      segment-routing ipv6 traffic-engineer

Verifying the Configuration

  • Run the display bgp routing-table ipv4-address [ mask | mask-length ] command to check BGP IPv4 routing table information.

  • Run the display segment-routing ipv6 locator [ locator-name ] verbose command to check SRv6 locator information.

  • Run the display segment-routing ipv6 local-sid [ locator locator-name ] forwarding command to check information about the SRv6 local SID table.
