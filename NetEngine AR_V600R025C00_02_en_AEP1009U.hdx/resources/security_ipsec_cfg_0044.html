Configuring IKEv2 Packet Fragmentation

Prerequisites

  • IKEv2 packet fragmentation takes effect only for IKEv2 negotiation.
  • IKEv2 packet fragmentation takes effect only for the following IPsec types:
    • ACL-based IPsec (involving ISAKMP IPsec policies and template IPsec policies)
    • Route-based IPsec (involving IPsec profiles)

Context

In IKEv2 scenarios, if the length of an encrypted IKEv2 packet exceeds the MTU of the outbound interface of the device, the device will fragment the IKEv2 packet for transmission. However, some network devices do not permit UDP fragments because of attack defense. As a result, IKEv2 fragments are discarded and IKEv2 negotiation between two IKE peers fails. In this case, you need to configure IKEv2 packet fragmentation so that the IKEv2 packets longer than the MTU specified by mtu-size can be fragmented before being encrypted. This configuration prevents the encrypted IKEv2 packets from being fragmented before transmission.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the IKE peer view.

    ike peer peer-name

  3. Enable IKEv2 packet fragmentation.

    ikev2 fragmentation [ mtu mtu-size ]

    By default, IKEv2 packet fragmentation is disabled.

    If this function is disabled, oversized IKEv2 packets will be fragmented after being encrypted. After this function is enabled, oversized IKEv2 packets will be fragmented before being encrypted.

    IKEv2 packet fragmentation must be enabled on both ends. Otherwise, this function does not take effect.

  4. Configure the next-payload field in IKEv2 packet fragments to be compliant with the RFC standard (that is, set the next-payload field to 0).

    ikev2 fragmentation next-payload standard

    The configurations on both ends of an IPsec tunnel must be the same. Otherwise, the interconnection may fail.
