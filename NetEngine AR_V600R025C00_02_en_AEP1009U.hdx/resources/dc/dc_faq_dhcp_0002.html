Does a Device Functioning as a DHCP Server Support Address Allocation Based on Secondary IP Addresses?

It supports address allocation based on secondary IP addresses.

Constraints:

  • Such address allocation is supported only by the global address pool in place of the interface address pool.
  • The DHCP server and clients are on the same network segment, meaning that no DHCP relay agent is deployed.

Allocation mechanism:

  1. The device preferentially allocates IP addresses that are statically bound (using the static-bind command in the global address pool view).
  2. The device uses the address pool for the primary IP address first. If no address is available, the device uses the address pools for secondary IP addresses. The device traverses secondary IP addresses in random order from an address pool. If the address pool is exhausted, it switches to the next address pool for traversal.

Configuration example:

#
ip pool 200
 gateway-list 10.200.1.1
 network 10.200.1.0 mask 255.255.255.0
 dns-list 10.114.114.114
#
ip pool 201
 gateway-list 10.201.1.1
 network 10.201.1.0 mask 255.255.255.0
 dns-list 10.114.114.114
#
interface Vlanif200
 ip address 10.200.1.1 255.255.255.0
 ip address 10.201.1.1 255.255.255.0 sub
 dhcp select global
#
