Example for Establishing IPsec Tunnels Between the HQ and Branches Using a Policy Template

Applicable Product and Version

This example applies to all models of routers running V600R025C00 and later versions.

Networking Requirements

In Figure 1, RouterA and RouterB are the gateways of enterprise branches. RouterA uses a fixed IP address to access the Internet, whereas B uses a dynamic IP address to access the Internet. RouterC is the gateway of the enterprise HQ. The branches and HQ communicate over the Internet.

The enterprise requires that traffic between the branches and HQ be protected and that the HQ gateway allow the access of specified branch gateways to ensure security.

To meet this requirement, establish IPsec tunnels between the branch gateways and HQ gateway to protect traffic transmitted between them over the Internet.

Figure 1 Establishing IPsec tunnels between the HQ and branches using a policy template

Context

1. On the Internet access wizard page, configure IP addresses for interfaces. Specifically, set the Internet access mode to static IP address mode, specify the interface for Internet access, and set the IP address, subnet mask, and gateway address of this interface.

2. On the static route page, configure static routes to ensure that the branches and HQ are reachable to each other.

3. On the IPsec policy management page, create IPsec tunnels to protect traffic between the branches and HQ.

Procedure

  1. Configure IP addresses for interfaces.
    1. Choose Config > Config Wizard > Online Config Wizard and set Internet access mode to Static IP, as shown in Figure 2.

      Figure 2 Internet access through a static IP address

    2. Click Confirm.

    Repeat this step to configure IP addresses for GE0/0/2 on RouterA and interfaces on RouterB and RouterC.

  2. Configure static routes.
    1. Choose Config > IP Services > Routing Protocol and click the Static Route tab, as shown in Figure 3.

      Figure 3 Static Route page

    1. On the Create Static Route page, set Destination IP, Subnet mask, and Next-hop address, and click OK, as shown in Figure 4.

      Figure 4 Creating a static route
    2. Configure static routes on RouterB and RouterC in the same way.

  3. Configure an ACL.

    1. Choose Config > Security > ACL. The Advanced ACL Settings page is displayed, as shown in Figure 5.

      Figure 5 Advanced ACL Settings page

    2. On the Advanced ACL Settings page, click Create, enter an ACL number, and click OK, as shown in Figure 6.

      Figure 6 Creating an advanced ACL

    3. On the Advanced ACL Settings page, click of an ACL. The Add Rule page is displayed, as shown in Figure 7.

      Figure 7 Adding a rule
    4. Configure an ACL on RouterB in the same way.

    An IPsec policy is created on RouterC using an IPsec policy template; therefore, referencing an ACL is optional on RouterC. If you configure an ACL on RouterC, you must specify the destination address in the ACL rule.

  4. Configure IPsec.

    1. Choose Config > VPN > IPsec. The IPSec Policy Management page is displayed, as shown in Figure 8.

      Figure 8 IPsec policy management

    2. Click Create. On the Add IPSec Policy page that is displayed, set Scenario to Site-to-site and click Next, as shown in Figure 9.
      Figure 9 Selecting a scenario

    3. On the Basic Configuration page shown in Figure 10, set the policy name, set Local interface to 10GE0/0/2, Local address to 1.1.1.1, Peer Address to 1.1.2.1, and Authentication type to Pre-shared key. Then click Next.
      Figure 10 Basic Configuration page
    4. On the Define Data Flow page, select the created ACL, as shown in Figure 11.
      Figure 11 Defining the data flows to be protected
    5. Click Next. On the IKE/IPSec Proposal page shown in Figure 12, set IKE and IPsec parameters. Specifically, set Negotiation mode to Main and Encapsulation mode to Tunnel. Set other parameters as needed, and then click OK to complete the IPsec configuration.
      Ensure that the IKE and IPsec settings, as well as the pre-shared key in the basic configuration, are the same on both ends.
      Figure 12 IKE/IPSec Proposal page

    Configure IPsec on RouterB and RouterC in the same way.

  5. Verify the configuration.

    # Verify that PC A and PC B can ping PC C and traffic transmitted between them is encrypted.
