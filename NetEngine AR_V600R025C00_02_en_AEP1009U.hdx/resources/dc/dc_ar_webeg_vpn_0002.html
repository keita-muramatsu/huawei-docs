Example for Configuring IPsec VPN

Applicable Product and Version

This example applies to all models of routers running V600R025C00 and later versions.

Networking Requirements

As shown in Figure 1, Router_1 is the gateway of an enterprise branch, and Router_2 is the gateway of the enterprise headquarters (HQ). Interconnection between them is achieved over the Internet using public IP addresses and gateway information provided by the carrier. The addresses in this example are for reference only and should be replaced with actual values obtained from the carrier.

The enterprise wants to protect traffic transmitted over the Internet between the branch and HQ. To meet this requirement, an IPsec tunnel needs to be established between them.

Figure 1 Network diagram for configuring IPsec VPN

Context

1. On the Internet access wizard page, configure IP addresses for interfaces. Specifically, set the Internet access mode to static IP address mode, specify an interface for Internet access, and set the IP address, subnet mask, and gateway address of this interface.

2. On the static route page, configure static routes to ensure that the branch and HQ are reachable to each other.

3. On the IPsec policy management page, create an IPsec tunnel to protect traffic between the branch and HQ.

Procedure

  1. Configure IP addresses for interfaces on Router_1. The configuration of Router_2 is similar to that of Router_1.
    1. Choose Config > Config Wizard > Online Config Wizard and set Internet access mode to Static IP, as shown in Figure 2.

      Figure 2 Internet access through a static IP address

    2. Set other parameters for 10GE0/0/2 and click Confirm.

    Repeat this step to configure the IP address 10.1.1.1 and subnet mask 255.255.255.0 for 10GE0/0/7.

  2. Configure static routes on Router_1. The configuration of Router_2 is similar to that of Router_1.
    1. Choose Config > IP Services > Routing Protocol and click the Static Route tab, as shown in Figure 3.

      Figure 3 Static Route page

    1. In the static route list, click Create to create two static routes. Define the first route with destination 1.1.2.1/24 and the second with destination 10.1.2.2/24, using 1.1.1.2 as the next hop for both. After the parameters are set in the dialog box shown in Figure 4, click OK.

      Figure 4 Creating a static route

  3. Configure IPsec on Router_1. The configuration of Router_2 is similar to that of Router_1.

    1. Choose Config > VPN > IPsec. The IPSec Policy Management page is displayed, as shown in Figure 5.

      Figure 5 IPsec policy management

    2. Click Create. On the Add IPSec Policy page that is displayed, set Scenario to Site-to-site and click Next, as shown in Figure 6.
      Figure 6 Selecting a scenario

    3. On the Basic Configuration page shown in Figure 7, set the policy name, set Local interface to 10GE0/0/2, Local address to 1.1.1.1, Peer Address to 1.1.2.1, and Authentication type to Pre-shared key. Then click Next.
      Figure 7 Basic Configuration page
    4. Define the data flows to be protected.
      1. Access the Define Data Flow page, as shown in Figure 8.
        Figure 8 Defining the data flows to be protected
      2. Click . The Local interface page is displayed, as shown in Figure 9.
        Figure 9 Local interface
      3. Click Create. On the Create Advanced ACL page that is displayed, enter an ACL ID and click OK, as shown in Figure 10.
        Figure 10 Creating an advanced ACL
      4. Click . On the Add Rule page shown in Figure 11, enter a rule ID, set Action to Permit, set Protocol type to TCP(6), set Source IP and Source IP wildcard to 10.1.1.0 and 0.0.0.255, set Dest IP and Destination IP wildcard to 10.1.2.0 and 0.0.0.255, and click OK.
        Figure 11 Adding a rule
      5. Select the created ACL and decide whether to enable reverse route injection, as shown in Figure 12.
        Figure 12 Defining the data flows to be protected
    5. Click Next. On the IKE/IPSec Proposal page shown in Figure 13, set IKE and IPsec parameters. Specifically, set Negotiation mode to Main and Encapsulation mode to Tunnel. Set other parameters as needed, and then click OK to complete the IPsec configuration.
      Ensure that the IKE and IPsec settings, as well as the pre-shared key in the basic configuration, are the same on both ends.
      Figure 13 IKE/IPSec Proposal page

  4. Verify the configuration.

    # Verify that PC_1 and PC_2 can ping each other, and verify that the numbers of encrypted and decrypted packets are not 0 in the display ipsec statistics command output on Router_1.

Precautions

  • The ACLs defined on the branch and HQ gateways must have identical but exchanged source and destination addresses.
  • There must be reachable external network routes between the HQ and branch.
