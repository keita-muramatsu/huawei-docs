VRRP Security

Overview

VRRP groups several routing devices into a virtual one. If one routing device fails, services are switched to another one, ensuring service continuity and reliability.

VRRP may have the following security risks:

  • A large number of valid VRRP packets are sent within a period of time to attack a device.
  • VRRP packets that do not meet VRRP security check requirements are constructed to attack a device.
To address the preceding risks, VRRP provides the following security hardening measures:
  • Attack packet suppression: If a device receives more than 20 packets within a period of time or receives packets sent from itself, it discards the packets.
  • VRRP authentication configuration: VRRP supports simple authentication and HMAC-MD5 authentication. You are advised to configure HMAC-MD5 authentication for VRRP to improve security.
  • Packet check: This function is supported by default and does not need to be configured.

Impact on the System

  • Receiving a large number of VRRP packets within a period of time may cause high CPU usage.
  • Receiving packets that do not meet VRRP security requirements may bring security risks.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the interface view.

    interface interface-type interface-number

  3. Switch the interface working mode to Layer 3.

    undo portswitch

    Determine whether to perform this step based on the current interface working mode.

  4. Configure an authentication mode for a specified VRRP group.

    vrrp vrid virtual-router-id authentication-mode { simple { [ plain ] key | cipher cipher-key } | md5 md5-key }

    VRRP supports only simple authentication and HMAC-MD5 authentication. HMAC-MD5 authentication with higher security is recommended.

Verifying the Security Hardening Result

Run the display vrrp [ interface { interface-name | interface-type interface-number } ] [ virtual-id ] verbose command. The Auth Type field in the command output indicates the authentication mode of VRRP packets.
