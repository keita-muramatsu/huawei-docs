Configuring Traffic Policing to Implement Interface-based Rate Limiting

Context

If the rate of traffic sent from users is not limited, burst data continuously sent by users may cause the network to become congested. Therefore, to limit the rate of traffic entering an interface, traffic policing can be configured in the inbound direction of the interface on a network device. When the rate of received packets exceeds the specified traffic policing rate, the device discards excess packets.

Procedure

  1. Enter the system view.

    system-view

  2. (Optional) Disable the device from counting the inter-frame gaps and preambles when calculating the traffic policing rate.

    qos car ifg disable

    By default, the device counts the inter-frame gaps and preambles when calculating the traffic policing rate.

    Only Ethernet links support this function.

  3. (Optional) Configure the function of counting the packet header length corresponding to the physical link when the device calculates the traffic policing rate.

    1. Enter the tunnel interface view.
      interface tunnel interface-number
    2. Enable the function of counting the packet header length corresponding to the physical link during traffic policing based on the mapping between the tunnel interface and the physical interface.
      qos overhead layer map interface { interface-type interface-number | interface-name }

      By default, the packet header length corresponding to the physical link is not counted during interface-based rate limiting. As a result, the actual rate of traffic passing through an interface may be greater than the rate limit on the interface.

    3. Return to the system view.
      quit

  4. Create and configure a CAR profile.

    qos car car-name { percent percent-value | cir cir-value [ kbps | mbps | gbps ] [ cbs cbs-value [ bytes | kbytes | mbytes ] [ pbs pbs-value [ bytes | kbytes | mbytes ] ] | pir pir-value [ kbps | mbps | gbps ] [ cbs cbs-value [ bytes | kbytes | mbytes ] pbs pbs-value [ bytes | kbytes | mbytes ] ] ] }

    By default, no CAR profile is created in the system.

    The CAR profile defines the rate limit of traffic policing.

  5. Enter the interface view.

    interface { interface-type interface-number | interface-name }

  6. Apply the CAR profile to the inbound or outbound direction of the interface.

    • Apply the CAR profile to the inbound direction of the interface.
      qos car inbound car-name

      By default, no CAR profile is applied to an interface.

      After the CAR profile is applied to the inbound direction of the interface, the device rate-limits all incoming service traffic on the interface.

      The device does not support the application of a CAR profile to a Layer 2 interface.

    • Apply the CAR profile to the outbound direction of the interface.
      qos car outbound car-name

      By default, no CAR profile is applied to an interface.

      After the CAR profile is applied to the outbound direction of the interface, the device rate-limits all outgoing service traffic on the interface.

Verifying the Configuration

  • Run the display qos car [ name car-name ] command to check the CAR profile configuration.
  • Run the display qos car statistics interface { interface-type interface-number | interface-name } { inbound | outbound } command to check statistics about packets forwarded and discarded on a specified interface on which traffic policing is configured.
