Configuring WPA/WPA2-PPSK Authentication

Context

WPA/WPA2-PSK authentication is easy to deploy, but the PSK is the same for all STAs connected to the same SSID. As a result, unauthorized users may share the key.

WPA/WPA2-PPSK authentication inherits the advantages of WPA/WPA2-PSK authentication. In addition to simple deployment, WPA/WPA2-PSK authentication provides different PSKs for different STAs, improving network security.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Create a security profile and enter its view.

    security-profile name profile-name

    By default, the security profile default exists in the system.

  4. Set the security policy to WPA/WPA2-PPSK.

    security { wpa | wpa2 | wpa-wpa2 } ppsk { aes | tkip | aes-tkip }

  5. Return to the WLAN view.

    quit

  6. Create a PPSK user and enter the PPSK user view.

    ppsk-user id id [ psk { pass-phrase pass-phrase-key-value | hex hex-key-value } ]

    By default, no PPSK user is created.

  7. (Optional) Configure the expiration time of the PPSK user.

    expire-date expire-date [ expire-hour expire-hour ]

    By default, there is no expiration time.

  8. (Optional) Configure the MAC address of the PPSK user allowed to access the network.

    mac-address mac-address

    By default, no MAC address is bound to a PPSK user.

  9. (Optional) Configure the SSID that provides access to PPSK users.

    ssid ssid

    By default, no SSID provide access to PPSK users.

  10. (Optional) Disable key negotiation for multicast traffic.

    wpa group-key-negotiation disable

    By default, key negotiation for multicast traffic is enabled.

  11. (Optional) Enable the function of disconnecting STAs when the device does not receive the last packet from the STAs during unicast key negotiation.

    wpa unicast-key-negotiation time-out kick-sta enable

    By default, the device does not disconnect STAs when it does not receive the last packet from the STAs during unicast key negotiation.
