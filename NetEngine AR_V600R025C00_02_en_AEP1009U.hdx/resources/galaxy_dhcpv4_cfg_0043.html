Client Cannot Obtain an IPv4 Address from a DHCPv4 Server

Possible Cause

DHCPv4 is not enabled.

Troubleshooting Roadmap

Run the display current-configuration | include dhcp enable command in the user view to check whether DHCPv4 is enabled. If the command output is empty, DHCPv4 is not enabled.

Solution

Run the dhcp enable command in the system view to enable DHCPv4.

By default, DHCPv4 is disabled in the system.

Possible Cause

The configuration is incorrect.

Troubleshooting Roadmap
For the DHCPv4 server:
  • Run the display ip pool command to check whether an address pool on the same network segment as the client is configured, and check whether the configuration is correct.
  • Run the display this command in the view of the interface connected to the client to check whether the DHCPv4 server function is enabled on the interface.
  • If a DHCPv4 relay agent is deployed between the server and client, check whether a route to the network segment of the client is configured on the server.

For the DHCPv4 relay agent:

  • Run the display dhcp relay command to check whether the configuration of the DHCPv4 relay agent is correct.
  • Run the display this command in the view of the interface connected to the client to check whether the DHCPv4 relay function is enabled on the interface.

Solution
Modify the configuration or deployment of the DHCPv4 server or relay agent.
  • For details about how to configure a DHCPv4 server, see "Configuring a Device to Function as a DHCPv4 Server."
  • For details about how to configure a DHCPv4 relay agent, see "Configuring a Device to Function as a DHCPv4 Relay Agent."

Possible Cause

The address pool has no available IPv4 addresses.

Troubleshooting Roadmap

Run the display ip pool command to check whether there are available IPv4 addresses in the address pool. The Idle(Expired) field in the command output indicates the number of idle IPv4 addresses in the address pool. If the value of this field is 0, there are no available IPv4 addresses in the address pool.

Solution

Determine the number of DHCPv4 clients on the network.

  • If the number of clients is greater than the number of available IPv4 addresses in the address pool, increase the address range.
    • Run the ip address ip-address { mask | mask-length } command in the interface view to increase the address range by reducing the mask length.
    • Run the network ip-address [ mask { mask | mask-length } ] command in the global address pool view to increase the address range by reducing the mask length.
  • If the number of clients is less than the number of available IPv4 addresses in the address pool, reduce the address lease to ensure that unused IPv4 addresses can be reclaimed promptly. You can configure the function of automatically reclaiming conflicting IPv4 addresses and set an automatic reclaiming interval, quickly reclaiming the conflicting IPv4 addresses.
    • Run the dhcp server conflict auto-recycle interval day day [ hour hour [ minute minute ] ] command in the interface view.
    • Run the conflict auto-recycle interval day day [ hour hour [ minute minute ] ] command in the global address pool view.

Possible Cause

STP is enabled on access devices of some diskless workstations.

Troubleshooting Roadmap

Check whether the timeout period of DHCPv4 request messages sent by the client is shorter than the STP convergence time. If so, the server cannot receive DHCPv4 request messages and therefore cannot allocate IPv4 addresses to the diskless workstations.

Solution

Disable STP on the access devices.

Possible Cause

The IPv4 address is manually configured for another host on the network. The DHCPv4 server does not exclude this IPv4 address from the address pool, leading to an IPv4 address conflict.

Troubleshooting Roadmap

Disable the network adapter of the client or disconnect the network cable. Perform a ping operation on another host to check whether any host with this IPv4 address exists. If the ping operation is successful, the IPv4 address has been manually configured.

Solution

  • Change the manually configured IPv4 address.

  • Exclude the conflicting IPv4 address from the DHCPv4 server's address pool.
    • If the device functions as a DHCPv4 server and an interface address pool is configured, run the dhcp server excluded-ip-address command.
    • If the device functions as a DHCPv4 server and a global address pool is configured, run the excluded-ip-address command.

  • Release the conflicting IPv4 address on the client and apply for a new IPv4 address. For example, run the cmd command on a PC running Windows 7 to enter the DOS environment, the ipconfig /release command in this environment to release the IPv4 address, and the ipconfig /renew command to apply for a new IPv4 address.

To prevent the client from obtaining a conflicting IPv4 address, configure IPv4 address conflict detection on the DHCPv4 server. After detecting an IPv4 address conflict, the server allocates another available IPv4 address. For details, see "Configure IPv4 address conflict detection."
