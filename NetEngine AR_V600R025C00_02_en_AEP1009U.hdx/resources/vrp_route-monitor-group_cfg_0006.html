Configuring an IPv6 Route Monitoring Group

Context

To improve network reliability, most carriers implement device-level redundancy by deploying two devices, which back up each other or balance traffic. In a dual-homing scenario where two devices work in active/standby mode, if one device fails, the other device takes over services from the faulty device.

In Figure 1, DeviceA and DeviceB back up each other. DeviceE, DeviceF, and DeviceG are dual-homed to DeviceA and DeviceB to implement load balancing. Network-side devices (DeviceC and DeviceD) are connected to the Internet.
  • If a link between DeviceA and DeviceC or between DeviceA and DeviceD fails, the link bandwidth between DeviceA and the Internet decreases. However, DeviceE, DeviceF, and DeviceG cannot detect the fault in time and keep sending packets to the Internet through DeviceA (rather than DeviceB). As a result, network congestion may occur between DeviceA and the Internet.
  • If all the links between DeviceA and DeviceC and between DeviceA and DeviceD fail, only the links between DeviceB and the Internet are available on the network side. However, DeviceE, DeviceF, and DeviceG cannot detect the fault in time and keep sending packets to the Internet through DeviceA (rather than DeviceB). As a result, traffic loss may occur between DeviceA and the Internet.
Figure 1 Typical network diagram with a route monitoring group

It is required that a route monitoring group be configured on DeviceA (active device) and that the network-side routes be added to the group so that their status can be monitored. When the status of a certain proportion of network-side routes changes, the RM module notifies the corresponding service module on DeviceA of the change. Then, a primary/backup link switchover is performed on the access side. This allows DeviceE, DeviceF, and DeviceG to access the network through DeviceB, preventing traffic loss and ensuring service continuity.

Procedure

  1. Enter the system view.

    system-view

  2. Create an IPv6 route monitoring group and enter its view.

    ipv6 route-monitor-group group-name

  3. Add an IPv6 route to the IPv6 route monitoring group.

    track ipv6 route [ vpn-instance vpn-instance-name ] destination mask-length [ down-weight down-weight-value ]

    To add more IPv6 routes to the IPv6 route monitoring group, repeat this step.

  4. (Optional) Configure a delay after which the RM module instructs the service modules associated with the IPv6 route monitoring group to perform a switchback.

    trigger-up-delay delay-value

    By default, the delay for the IPv6 RM module to instruct the service modules to perform a switchback is 5s.

    When an IPv6 route in an IPv6 route monitoring group becomes active again, the IPv6 RM module needs to re-deliver the route to the forwarding table and create forwarding entries, which takes some time. If the IPv6 RM module immediately instructs the service modules to perform a link switchback, packet loss may occur. To prevent this problem, run the trigger-up-delay command to configure a delay for the IPv6 RM module to instruct the service modules to perform a link switchback so that the RM module instructs the service modules to perform a link switchback after forwarding entries are created.

  5. Enable the IPv6 route monitoring group function.

    monitor enable

    By default, the IPv6 route monitoring group function is disabled.

    When a large number of IPv6 routes are added to or deleted from an IPv6 route monitoring group, the down-weight sum of the route monitoring group may change frequently, which in turn leads to service flapping of the service modules associated with the route monitoring group. To prevent such service flapping, run the undo monitor enable command to dissociate the IPv6 route monitoring group from all service modules. After the configuration is complete, run the monitor enable command to re-associate the IPv6 route monitoring group with the service modules.

Verifying the Configuration

After configuring the IPv6 route monitoring group, verify its configurations.

  • Run the display ipv6 route-monitor-group [ group-name ] command to check IPv6 route monitoring group information.
  • Run the display ipv6 route-monitor-group track-route [ vpn-instance vpn-instance-name ] destination mask-length command to check information about all IPv6 route monitoring groups to which a route has been added.
