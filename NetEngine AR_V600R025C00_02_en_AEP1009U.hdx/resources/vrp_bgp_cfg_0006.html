BGP Route Selection Rules

When a BGP device has multiple routes to the same destination, BGP selects routes based on the following rules, which are listed in descending order of priority:
  1. Prefers the routes received from the peers that are not in GR state.

    By default, the function of preferentially selecting the routes received from the peers that are not in GR state is not configured. In this case, this rule is skipped during route selection.

    After the bestroute non-gr-prior command is run, the device preferentially selects the routes received from the peers that are not in GR state. This rule takes effect only for routes in the BGP IPv6 SR-Policy address family and BGP IPv4 SD-WAN address family.

  2. Prefers the route with the largest PreVal value.

    PrefVal is Huawei-specific, and is valid only on the device with the attribute configured.

  3. Prefers the route with the largest Local_Pref value.

    If a route does not carry the Local_Pref, BGP uses the default value of 100 for this attribute during route selection. To change the default Local_Pref of BGP routes, run the default local-preference command.

  4. Prefers a locally originated route to a route learned from a peer.

    Locally originated routes include routes imported using the network or import-route command, as well as manually and automatically generated summary routes.
    1. Prefers a summary route to a non-summary route.
    2. Prefers a summary route manually generated using the aggregate command to a summary route automatically generated using the summary automatic command.
    3. Prefers a route imported using the network command to a route imported using the import-route command.
  5. Prefers the route with the shortest AS_Path length.
    • The AS_Path length excludes the AS_Confed_Sequence and AS_Confed_Set.
    • The length of AS_SET is 1, regardless of the number of AS numbers in AS_SET.

    After the bestroute as-path-ignore command is run, BGP does not compare the AS_Path attributes during route selection.

    After the load-balancing as-path-ignore command is run, the routes with different AS_Paths can load-balance traffic.

  6. Prefers routes with the Origin attribute in descending order of priority as follows: IGP > EGP > Incomplete.

  7. Prefers the route with the smallest MED value.

    If the bestroute med-plus-igp command is run, BGP preferentially selects the route with the smallest sum of the MED multiplied by a MED multiplier and the IGP cost multiplied by an IGP cost multiplier.

    • BGP compares the MEDs of only routes from the same AS (excluding sub-ASs in a confederation). That is, BGP compares the MEDs of two routes only when the first AS number in the AS_Sequence (excluding the AS_Confed_Sequence) of one route is the same as its counterpart in the other route.
    • If a route does not carry a MED, BGP considers its MED as the default value (0) during route selection. If the bestroute med-none-as-maximum command is run, BGP considers its MED as the largest MED value (4294967295) in this case.
    • If the compare-different-as-med command is run, BGP compares the MEDs of routes even when the routes are received from peers in different ASs. Do not use the compare-different-as-med command unless it is confirmed that different ASs use the same IGP and route selection mode. Otherwise, loops may occur.
    • If the deterministic-med command is run, routes are no longer selected in the sequence in which they are received.

  8. Prefers EBGP routes over IBGP routes among the routes learned from peers. In the VPNv4, EVPN, and VPNv6 address families, the routes sent by the local VRF take precedence over the routes learned from peers.

  9. Prefers the BGP route that recurses to an IGP route with the smallest cost.

    If the bestroute igp-metric-ignore command is run, BGP does not compare the IGP costs of candidate routes.

    After the load-balancing igp-metric-ignore command is run, the routes with different IGP metric values can participate in load balancing.

  10. Prefers the route with the shortest Cluster_List length.

    By default, Cluster_List comparison is prior to router ID comparison during BGP route selection. If the bestroute routerid-prior-clusterlist command is run, router ID comparison is prior to Cluster_List comparison during BGP route selection.

  11. Prefers the route advertised by the device with the smallest router ID.

    If the bestroute router-id-ignore command is run, BGP does not compare router IDs during route selection.

    If each candidate route carries an Originator_ID, BGP compares the Originator_IDs, rather than router IDs, during route selection, and selects the route with the smallest Originator_ID.

  12. Prefers the route learned from the peer with the smallest IP address.

  13. Prefers the routes in the RM routing table among locally imported routes.

    If a direct route, static route, and IGP route are all imported, BGP selects routes in descending order of priority as follows: direct route > static route > IGP route.

  14. Prefers the Add-Path route with the smallest recv pathID.

  15. Prefers locally received routes to the routes imported between VPN and public network instances.

  16. Prefers the route that was learned the earliest.
