Example for Rolling Back to a Configuration Rollback Point Based on a Label After a Configuration Change Fails

Networking Requirements

  • If a configuration error occurs, a configuration fault is generated, or a configuration causes an unexpected result, you can compare the differences between configuration rollback points to quickly restore configurations. Using the traditional method, you must delete the IP address of each interface and then reconfigure the IP address. Compared with the traditional method, configuration rollback has the following advantages:
    • The service recovery speed is improved, reducing the impact of misoperations.
    • Configuration security is enhanced and the risk of misoperations is reduced.
  • After the IP addresses of the interfaces shown in Figure 1 are configured, the user finds that IP addresses are incorrectly configured and wants to reconfigure them.
Figure 1 Configuration rollback

In this example, Interface1, Interface2, Interface3, and Interface4 represent 10GE0/0/1, 10GE0/0/2, 10GE0/0/3, and 10GE0/0/4 respectively.


Configuration Roadmap

The configuration roadmap is as follows:
  1. Configure IP addresses for interfaces on the device.
  2. Check information about configuration rollback points and the lastly committed configuration change.
  3. Perform configuration rollback by selecting a configuration rollback point to which system configurations are expected to roll back or the number of configuration rollback points that a configuration rollback operation is expected to undergo.

Procedure

  1. Generate a configuration rollback point.

    <HUAWEI> system-view
[HUAWEI] sysname Device
[Device] commit label label_test

  2. Set the IP addresses for 10GE0/0/1, 10GE0/0/2, 10GE0/0/3, and 10GE0/0/4 to 10.0.0.1/30, 10.0.1.1/30, 10.0.2.1/30, and 10.0.3.1/30, respectively.

    <HUAWEI> system-view
[HUAWEI] sysname Device
[Device] interface 10ge 0/0/1
[Device-10GE0/0/1] ip address 10.0.0.1 30
[Device-10GE0/0/1] quit
[Device] interface 10ge 0/0/2
[Device-10GE0/0/2] ip address 10.0.1.1 30
[Device-10GE0/0/2] quit
[Device] interface 10ge 0/0/3
[Device-10GE0/0/3] ip address 10.0.2.1 30
[Device-10GE0/0/3] quit
[Device] interface 10ge 0/0/4
[Device-10GE0/0/4] ip address 10.0.3.1 30
[Device-10GE0/0/4] quit
[Device] commit label label_ipaddress
[Device] quit

  3. Check information about configuration rollback points and the lastly committed configuration change.

  4. Perform configuration rollback.

    Roll back system configurations to what they are before the most recent configuration rollback point is generated.

    In this example, the rollback configuration last 1 command is equivalent to the rollback configuration to commit-id 1000000005 command, both indicating that system configurations are rolled back to what they are before configuration rollback point 6 is generated.

    <Device> rollback configuration last 1
