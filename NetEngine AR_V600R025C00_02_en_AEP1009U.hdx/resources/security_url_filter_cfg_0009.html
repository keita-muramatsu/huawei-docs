Configuring URL Category-based URL Filtering

Procedure

  1. Enter the system view.

    system-view

  2. Configure the service performance mode of the device.

    forward performance mode { routing | security | security-enhance }

    To enable security services, you are advised to switch the device's service performance mode to the secure forwarding mode (security) or enhanced security mode (security-enhance).

    You can run the display forward performance mode command to check the current service performance mode of the device.

    Some models do not support this command or some parameters. For details, see the command reference.

  3. Optional: Configure the language used on the push page.

    push-info module url-filter template { english | hindi | spanish | french | arabic | bengali | russian | portuguese | indonesian | german }

    The URL filtering push page of the device supports 10 language templates. By default, the push page uses English.

  4. Create a URL filtering profile.

    profile type url-filter name name

  5. Configure the default action in the URL filtering profile.

    default action { allow | block | alert }

    If a user attempts to access a URL that does not match any URL whitelist, URL blacklist, or URL category, the device processes the request according to the default action.

    When the default action is set to block and the URL to be accessed by a user does not match any URL whitelist, URL blacklist, or URL category, the device blocks the request and reports a log.

    When the default action is set to alert and the URL to be accessed by a user does not match any URL whitelist, URL blacklist, or URL category, the device permits the request and reports a log.

    When block or alert is selected, configure the remote query function and activate the remote query license. Otherwise, service traffic may not match any category. As a result, normal services are blocked or a large number of service logs are generated.

  6. Set the control actions for predefined URL categories. The device provides the following two methods for configuring control actions for URL categories. If two control actions both apply to a URL, the control action configured later takes precedence:

    • Method 1: Configure the control action level for predefined URL categories. This method is easy to use and suitable for scenarios that do not have special requirements for URL category control.
      category pre-defined control-level { high | low | medium }

      The device performs different actions on different types of websites at different control levels. To view the category control information at a specified level, run the display url-filter category pre-defined control-level [ high | low | medium ] command.

    • Method 2: Specify the control action for each category. This method is suitable for scenarios where you know which URL categories need to be restricted.
      category pre-defined [ category-id category-id-value | subcategory-id subcategory-id-value ] action { allow | block | alert }

      To view the category IDs (CIDs) and subcategory IDs (SIDs) of all predefined URL categories, run the display url-filter category pre-defined command.

    Typically, the predefined URL category database is preset before delivery and does not need to be manually loaded. If the system displays a message indicating that no predefined URL category database has been loaded, run the import url-sdb file filename command to load a predefined URL category database, for example, import url-sdb file flash:/url.sdb.

    If there is no predefined URL category database on the local device, log in to the Huawei security center platform (isecurity.huawei.com) to download it. On the home page of the security center platform, choose Security Signature Update > Downloading the Signature Database and Component Package, select the product model and version number, and click the Initial URL tab. Download the predefined URL category database, and upload it to the device.

  7. Configure the action mode of URL filtering.

    category action mode { strict | loose }

    The default action mode for a URL category is the strict mode.

    When the URL accessed by a user belongs to multiple categories (including predefined and user-defined categories), the response action is performed based on the action mode:

    • Strict: The device takes the strictest action among all the matched categories. For example, a URL matches two categories whose actions are alert and block, respectively. The device then takes the block action.

    • Loose: The device takes the loosest action among all the matched categories. For example, a URL matches two categories whose actions are alert and block, respectively. The device then takes the alert action.

  8. Return to the system view.

    quit

  9. Commit the configuration.

    engine configuration commit

    A new or modified URL filtering profile takes effect only after you commit the configuration.

  10. Enter the security policy view.

    security-policy

  11. Create a security policy rule and enter the security policy rule view.

    rule name rule-name

  12. Set the permit action for the security policy rule.

    action permit

  13. Reference the URL filtering profile in the security policy.

    profile url-filter profile-name

    This section provides only the configuration steps for referencing the URL filtering profile in a security policy. For details about how to configure matching conditions in a security policy, see "Security Policy Configuration" in CLI Configuration Guide > Security Configuration.

  14. Return to the system view.

    quit
quit

Verifying the Configuration

  • Run the display profile type url-filter [ name name [ pre-defined [ category-id category-id | subcategory-id subcategory-id ] ] ] command to check the configuration of the URL filtering profile.
  • Run the display url-filter category pre-defined [ category-id category-id | subcategory-id subcategory-id ] command to view the URL category list.
  • Run the display url-filter category pre-defined control-level [ high | low | medium ] command to check information about all predefined categories of a specified control level.
