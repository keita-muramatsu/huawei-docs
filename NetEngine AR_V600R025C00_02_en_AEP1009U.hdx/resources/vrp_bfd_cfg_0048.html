Understanding BFD for Link-Bundle

If two devices are connected through Layer 3 Eth-Trunk interfaces or a Layer 2 transmission device is deployed on the link between the two devices, you can configure BFD for link-bundle to detect link faults.

If common single-hop BFD is used to monitor a Layer 3 Eth-Trunk link with multiple member links, only one BFD session can be created. BFD then selects a board where an Eth-Trunk member interface resides as the state machine board, and monitors this member link only. If the member interface, member link, or the state machine board fails, the BFD session considers the entire Eth-Trunk link to have failed. However, the other Eth-Trunk member links are actually still available, and the Eth-Trunk interface is still up.

BFD for link-bundle resolves this problem. After a BFD for link-bundle session is bound to an Eth-Trunk interface, BFD creates a dynamic unicast BFD sub-session for each Eth-Trunk member interface, with each sub-session performing negotiation and detection independently. BFD also creates a main session to manage the link status reported by the sub-sessions, and this main session goes down only after all sub-sessions have gone down.

Figure 1 Network diagram of BFD for link-bundle
In Figure 1, a BFD for link-bundle session consists of one main session and multiple sub-sessions.
  • The main session creates a BFD sub-session for each Eth-Trunk member interface.
  • Each sub-session independently monitors an Eth-Trunk member link and reports the detection result to the main session. In addition, each sub-session uses the same detection parameters as the main session.
  • The main session summarizes the detection results from sub-sessions and determines the Eth-Trunk link status. Specifically:
    • The main session and the Eth-Trunk interface are up as long as one sub-session remains up.
    • If the Eth-Trunk interface has no member interface, no sub-session is created. In this case, if the main session goes down, BFD reports the Unknown state without determining the Eth-Trunk interface status.
    • If the Eth-Trunk interface has only one member interface and the corresponding sub-session is up, the main session goes down after the member interface exits the Eth-Trunk interface. In this case, the Eth-Trunk interface is up.

The local discriminator of a main session is allocated from a special range (0x00100000 to 0x00103fff) without consuming the discriminator resources reserved for BFD sessions. The main session does not learn the remote discriminator as it does not send or receive packets. A sub-session's local discriminator is allocated from the discriminator range reserved for dynamic BFD sessions using the same algorithm as a dynamic BFD session.

Only sub-sessions consume BFD session resources per board, and each sub-session must select the board where the physical member interface bound to this sub-session resides as a state machine board. If no BFD session resources are available on the board, board selection fails, and the sub-session's status is not reported to the main session.
