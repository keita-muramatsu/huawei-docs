IPsec Security Association

An IPsec security association (SA) needs to be established between IPsec peers (two IPsec endpoints) before IPsec implements secure data transmission. An IPsec tunnel can be established between IPsec peers through the SA.

An SA is an agreement between two IPsec peers on certain negotiated elements, and which describes how to use security services (such as data encryption) between IPsec peers for secure communication. The elements involved include security protocols used between peers, characteristics of data flows to be protected, encapsulation modes of data transmitted between peers, encryption and authentication algorithms, and lifetimes of keys (used for secure data conversion and transmission) and SAs.

An IPsec SA can be automatically established through IKE negotiation. Data flows to be protected must be imported into an IPsec tunnel. The peers at both ends of the tunnel use security protocols to encrypt and authenticate the data flows, ensuring secure data transmission across the Internet.

An IPsec SA is identified by three parameters: security parameter index (SPI), destination IP address, and security protocol (AH or ESP). The SPI is a 32-bit value generated to uniquely identify an SA, and is transmitted in an AH or ESP header. IPsec SAs are unidirectional logical connection and usually established in pairs (in both inbound and outbound directions). As such, at least one pair of IPsec SAs must be established between two IPsec peers to form a secure IPsec tunnel capable of protecting data flows in both directions, as shown in Figure 1.

The number of IPsec SAs required also depends on the security protocols used to protect traffic between two peers. If either AH or ESP is used to protect traffic between two peers, only two IPsec SAs need to be established between the peers (one SA in each direction). If both AH and ESP are used, four IPsec SAs are required (two SAs for each protocol).
