Configuring Interface Isolation

Context

The downlink interfaces on an RU are in the same broadcast domain and are not isolated by default. In authentication scenarios, unauthenticated users connected to the same RU can communicate with each other. In this case, you can configure interface isolation to prevent communication between such users. Once configured, unknown unicast and broadcast traffic from terminals connected to the RU is forwarded only to the uplink interface. Also, a proxy ARP should be configured on the gateway to enable terminals in different VLANs to communicate at Layer 3.

Procedure

  • Configure interface isolation in the global RU view.
    1. Enter the system view.
      system-view
    2. Enter the global RU view.
      remote-unit
    3. Configure isolation for the downlink interfaces of the RU.
      isolate enable
    4. Deliver the configuration to all RUs or a single RU.
      commit { all | name remote-unit-name | interface interface-type interface-number }
  • Configure interface isolation in the single RU view.
    1. Enter the system view.
      system-view
    2. Enter the single RU view.
      remote-unit { id | connect-interface interface-type interface-number | name remote-unit-name }
    3. Configure isolation for the downlink interfaces of the RU.
      isolate enable
    4. Deliver the configuration to the RU.
      commit
