Example for Configuring Branches to Access Headquarters Resources in Different VPN Instances Through IPsec Tunnels

Networking Requirements

In Figure 1, DeviceA is the gateway of the enterprise headquarters, DeviceB is the gateway of branch 1, and DeviceC is the gateway of branch 2. The VPNs isolate different resources at the headquarters. It is required that branches securely access these resources through IPsec tunnels.

Figure 1 Configuring branches to access headquarters resources in different VPN instances through IPsec tunnels

In this example, interface 1, interface 2, and interface 3 represent 10GE 0/0/1, 10GE 0/0/2, and 10GE 0/0/3, respectively.


Configuration Roadmap

This example uses default security algorithms of IPsec.

For security purposes, you are advised not to use the weak security algorithm or weak security protocol of this feature. If you must use such a weak security algorithm or protocol, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA.

On DeviceA, configure a template IPsec policy to respond to the access requests of the branches.

  1. Perform basic configurations, including configuring VPN instances, configuring IP addresses for interfaces, and configuring static routes.

  2. Configure an IPsec policy, including an IPsec proposal, IKE proposal, and IKE user table.

On DeviceB and DeviceC:

  1. Perform basic configurations, including configuring IP addresses for interfaces, and configuring static routes.

  2. Configure an IPsec policy, including the data flows to be encrypted, IPsec proposal, and IKE proposal.

Procedure

  • Configure DeviceA.
    1. Configure VPN instances.

      <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] ip vpn-instance vpn1
[DeviceA-vpn-instance-vpn1] route-distinguisher 100:1
[DeviceA-vpn-instance-vpn1-af-ipv4] quit
[DeviceA-vpn-instance-vpn1] quit
[DeviceA] ip vpn-instance vpn2
[DeviceA-vpn-instance-vpn2] route-distinguisher 200:1
[DeviceA-vpn-instance-vpn2-af-ipv4] quit
[DeviceA-vpn-instance-vpn2] quit
[DeviceA] ip vpn-instance vpn3
[DeviceA-vpn-instance-vpn3] route-distinguisher 300:1
[DeviceA-vpn-instance-vpn3-af-ipv4] quit
[DeviceA-vpn-instance-vpn3] quit

    2. Configure IP addresses for interfaces.

      # Configure IP addresses for interfaces.

      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ip binding vpn-instance vpn1
[DeviceA-10GE0/0/1] ip address 1.1.1.1 24
[DeviceA-10GE0/0/1] quit
[DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] ip binding vpn-instance vpn2
[DeviceA-10GE0/0/2] ip address 10.1.2.1 24
[DeviceA-10GE0/0/2] quit
[DeviceA] interface 10ge 0/0/3
[DeviceA-10GE0/0/3] ip binding vpn-instance vpn3
[DeviceA-10GE0/0/3] ip address 10.1.3.1 24
[DeviceA-10GE0/0/3] quit

    3. Configure static routes destined for the branches. The following assumes that the next-hop address is 1.1.1.2.

      [DeviceA] ip route-static vpn-instance vpn1 2.1.1.0 255.255.255.0 1.1.1.2
[DeviceA] ip route-static vpn-instance vpn1 2.1.2.0 255.255.255.0 1.1.1.2

    4. Configure routes between VPNs so that there are reachable routes between VPN 1, VPN 2 and VPN 3.

      [DeviceA] ip route-static vpn-instance vpn1 10.1.2.0 24 vpn-instance vpn2 10.1.2.2
[DeviceA] ip route-static vpn-instance vpn1 10.1.3.0 24 vpn-instance vpn3 10.1.3.2
[DeviceA] ip route-static vpn-instance vpn2 10.1.4.0 24 vpn-instance vpn1 1.1.1.2
[DeviceA] ip route-static vpn-instance vpn3 10.1.5.0 24 vpn-instance vpn1 1.1.1.2

    5. Configure an IPsec policy.

      # Configure an IPsec proposal.
      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceA-ipsec-proposal-tran1] quit
      # Configure an IKE proposal.
      [DeviceA] ike proposal 10
[DeviceA-ike-proposal-10] authentication-method pre-share
[DeviceA-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceA-ike-proposal-10] authentication-algorithm sha2-256
[DeviceA-ike-proposal-10] dh group14
[DeviceA-ike-proposal-10] prf hmac-sha2-256
[DeviceA-ike-proposal-10] integrity-algorithm hmac-sha2-256
[DeviceA-ike-proposal-10] quit
      # Create an IKE user table.
      [DeviceA] ike user-table 1
[DeviceA-ike-user-table-1] user vpn2 
[DeviceA-ike-user-table-1-vpn2] pre-shared-key YsHsjx_202206 
[DeviceA-ike-user-table-1-vpn2] vpn-instance-traffic name vpn2 
[DeviceA-ike-user-table-1-vpn2] id-type ip 2.1.1.1
[DeviceA-ike-user-table-1-vpn2] quit 
[DeviceA-ike-user-table-1] user vpn3
[DeviceA-ike-user-table-1-vpn3] pre-shared-key YsHsjx_202206 
[DeviceA-ike-user-table-1-vpn3] vpn-instance-traffic name vpn3 
[DeviceA-ike-user-table-1-vpn3] id-type ip 2.1.2.1
[DeviceA-ike-user-table-1-vpn3] quit
[DeviceA-ike-user-table-1] quit
      # Configure an IKE peer.
      [DeviceA] ike peer vpn
[DeviceA-ike-peer-vpn] ike-proposal 10
[DeviceA-ike-peer-vpn] local-id 1.1.1.1
[DeviceA-ike-peer-vpn] user-table 1
[DeviceA-ike-peer-vpn] quit
      # Configure an IPsec policy.
      [DeviceA] ipsec policy-template use1 10
[DeviceA-ipsec-policy-templet-use1-10] proposal tran1
[DeviceA-ipsec-policy-templet-use1-10] ike-peer vpn
[DeviceA-ipsec-policy-templet-use1-10] flow-vrf check disable
[DeviceA-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceA-ipsec-policy-templet-use1-10] quit
[DeviceA] ipsec policy map1 10 isakmp template use1

      If VPNs import routes from each other for inter-VPN traffic forwarding, you need to run the flow-vrf check disable command to disable the function of checking the VPN instance in data flows during IPsec encryption and decryption.

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply the IPsec policy to an interface.
      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ipsec policy map1
[DeviceA-10GE0/0/1] quit

  • Configure DeviceB.
    1. Configure IP addresses for interfaces.

      # Configure IP addresses for interfaces.
      <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] ip address 2.1.1.1 24
[DeviceB-10GE0/0/1] quit
[DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] ip address 10.1.4.1 24
[DeviceB-10GE0/0/2] quit

    2. Configure static routes to the headquarters. The following assumes that the next-hop address is 2.1.1.2.

      [DeviceB] ip route-static 1.1.1.0 255.255.255.0 2.1.1.2
[DeviceB] ip route-static 10.1.0.0 255.255.0.0 2.1.1.2

    3. Configure an IPsec policy.

      # Configure advanced ACL 3000.
      [DeviceB] acl 3000
[DeviceB-acl4-advance-3000] rule 10 permit ip source 10.1.4.0 0.0.0.255 destination 10.1.2.0 0.0.0.255
[DeviceB-acl4-advance-3000] rule 15 permit ip source 10.1.4.0 0.0.0.255 destination 10.1.3.0 0.0.0.255
[DeviceB-acl4-advance-3000] quit
      # Configure an IPsec proposal.
      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceB-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceB-ipsec-proposal-tran1] quit
      # Configure an IKE proposal.
      [DeviceB] ike proposal 10
[DeviceB-ike-proposal-10] authentication-method pre-share
[DeviceB-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceB-ike-proposal-10] authentication-algorithm sha2-256
[DeviceB-ike-proposal-10] dh group14
[DeviceB-ike-proposal-10] prf hmac-sha2-256
[DeviceB-ike-proposal-10] integrity-algorithm hmac-sha2-256
[DeviceB-ike-proposal-10] quit
      # Configure an IKE peer.
      [DeviceB] ike peer vpn
[DeviceB-ike-peer-vpn] ike-proposal 10
[DeviceB-ike-peer-vpn] remote-address 1.1.1.1
[DeviceB-ike-peer-vpn] pre-shared-key YsHsjx_202206
[DeviceB-ike-peer-vpn] quit
      # Configure an IPsec policy.
      [DeviceB] ipsec policy map1 10 isakmp
[DeviceB-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceB-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceB-ipsec-policy-isakmp-map1-10] ike-peer vpn
[DeviceB-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceB-ipsec-policy-isakmp-map1-10] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply the IPsec policy map1 to an interface.
      [DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] ipsec policy map1
[DeviceB-10GE0/0/1] quit

  • Configure DeviceC.
    1. Configure IP addresses for interfaces.

      # Configure IP addresses for interfaces.
      <HUAWEI> system-view

[DeviceC-ike-proposal-10] integrity-algorithm hmac-sha2-256
[DeviceC-ike-proposal-10] quit
      # Configure an IKE peer.

  1. Ping PC3 from PC1 and PC4 from PC2. The pings are successful.

  2. Run the display ike sa command to check SA information. The following shows the command output of DeviceA.
