Configuring the Remote End of a CAPWAP Tunnel to Obtain an IP Address

Context

To establish a CAPWAP tunnel, the remote end directly or indirectly connected to the local end of the tunnel needs to have an IP address, and network connectivity must be available between the devices on both ends of the tunnel.

You can configure the remote end of a CAPWAP tunnel to obtain an IP address using either of the following modes:

  • Static mode: Log in to the device and manually configure its IP address.
  • DHCP mode: Deploy a DHCP server on the network, and configure the device as a DHCP client to request an IP address from the DHCP server.
  • SLAAC mode: The AP obtains an IPv6 address through stateless address autoconfiguration (SLAAC).
Pay attention to the following when you configure DHCP:
  • A STA connected to an AP cannot function as a DHCP server.
  • A service DHCP address pool and a management DHCP address pool are used to assign IP addresses to STAs and APs, respectively. The two types of DHCP address pools must be configured separately.
  • When a DHCP server assigns IP addresses to APs running V600, the network segment configured on the server cannot be the same as that of 192.168.254.254.
  • When an enterprise branch has no independent DHCP server, configure a WAC as a DHCP server. For the detailed configuration, see "DHCPv4 Configuration and DHCPv6 Configuration" in CLI Configuration Guide > IP Addresses and Services.
  • An independent DHCP server applies to WLANs in medium- to large-sized campuses.
  • If the WAC and APs are on different network segments, you can configure Option fields to specify the WAC's CAPWAP source IP address for the APs or specify the WAC's domain name through DNS. Otherwise, the APs cannot discover the WAC and go online successfully.
You can configure APs to discover a WAC as follows:
  • Configuring Option 43 to specify the WAC's IPv4 address for APs
    • If the WAC is used as a DHCP server to assign IPv4 addresses to APs, see the description of the option or dhcp server option command.

      You can use any of the following commands to configure Option 43 as an example for a global address pool:

      • Run the option 43 hex 031D3139322e3136382e3139342e35302c3139322e3136382e3139342e3534 command to configure the device to specify the WACs' IP addresses 192.168.194.50 and 192.168.194.54 for APs.

        In this command, 03 is a fixed value; 1D indicates that the length of IP addresses (192.168.194.50,192.168.194.54) including dots (.) and the comma (,) is 29, and the IP addresses are separated by a comma (,); 3139322e3136382e3139342e3530 indicates the ASCII value of 192.168.194.50; 2C indicates the ASCII value of a comma (,); 3139322e3136382e3139342e3534 indicates the ASCII value of 192.168.194.54.

      • Run the option 43 sub-option 1 hex C0A80001C0A80002 command to configure the device to specify WACs' IP addresses 192.168.0.1 and 192.168.0.2 for APs. In the command, C0A80001 indicates the hexadecimal format of 192.168.0.1, and C0A80002 indicates the hexadecimal format of 192.168.0.2.
      • Run the option 43 sub-option 2 ip-address 192.168.0.1 192.168.0.2 command to configure the device to specify WACs' IP addresses 192.168.0.1 and 192.168.0.2 for APs.
      • Run the option 43 sub-option 3 ascii 192.168.0.1,192.168.0.2 command to configure the device to specify WACs' IP addresses 192.168.0.1 and 192.168.0.2 for APs.
        To configure the Option 43 field for APs to discover WACs, you are advised to run any of the following commands. If more than one of them is executed, all the executed commands take effect.
        • option 43 sub-option 3 ascii sub-ascii-string
        • option 43 sub-option 2 ip-address ip-address &<1-8>
        • option 43 sub-option 1 hex sub-hex-string
    • When an independent DHCP server is used to assign IPv4 addresses to APs, configure Option 43 to carry the WACs' IPv4 addresses; otherwise, the APs cannot discover the WACs. For details about the configuration, see the configuration guide of the corresponding device.

      For details about how to configure a DHCP server, see How to Configure Option 43 When Huawei APs Are Connected to DHCP Servers of Different Vendors.

  • Configuring DNS to specify the WAC's IPv4 address for APs

    In this mode, you need to specify both the domain name and IP address of the WAC on the DNS server.

    • If the WAC is used as a DHCP server to assign IPv4 addresses to APs, see "Configuring a Device to Function as a DHCPv4 Server" in CLI Configuration Guide > IP Addresses and Services Configuration > DHCPv4 Configuration. The key steps in configuring a global address pool are as follows:
      1. Run the system-view command to enter the system view.
      2. Run the ip pool ip-pool-name command to create a global address pool and enter its view.
      3. Run the dns-list ip-address command to configure a DNS server address.
      4. Run the domain-name domain-name command to configure a domain name suffix for APs. After obtaining the suffix, the APs concatenate the suffix and huawei-wlan-controller into a fully qualified domain name (FQDN). The APs then use this FQDN to request the WAC's IP address from the DNS server.
    • When an independent DHCP server is used to assign IPv4 addresses to APs, configure Option 15 to carry the domain name suffix of the WAC; otherwise, the APs cannot discover the WAC. For details about the configuration, see the configuration guide of the corresponding device. For example, if the domain name suffix is ipv4.com, its hexadecimal format is 0F08697076342E636F6D. In this value, 0F indicates that the option ID is 15; 08 indicates that the length of the domain name is 8; 697076342E636F6D indicates the ASCII code value of the characters in the domain name.
  • Configuring Option 52 to specify the WAC's IPv6 address for APs
    • If the WAC functions as a DHCPv6 server to assign IPv6 addresses to APs, perform the configuration according to "Configuring an IPv6 Address Pool" in CLI Configuration Guide > IP Addresses and Services Configuration > DHCPv6 Configuration > Configuring a DHCPv6 Server. The key steps are as follows:
      1. Run the system-view command to enter the system view.
      2. Run the dhcpv6 pool pool-name command to create an IPv6 address pool and enter its view.
      3. Run the capwap-ac ipv6-address command to configure an IPv6 address for the WAC.
    • If an independent DHCPv6 server is used to assign IPv6 addresses to APs, configure option 52 to carry the WAC's IPv6 address. Otherwise, the APs cannot discover the WAC and will fail to go online on the WAC. For details about the configuration, see the configuration guide of the corresponding device. For example, if the WAC's IPv6 address is fc01::1 (FC01:0000:0000:0000:0000:0000:0000:0001), the hexadecimal format of the option field is 00340010FC010000000000000000000000000001. In this value, 0034 indicates that the option ID is 52; 0010 indicates that the length of the hexadecimal IP address is 16; FC010000000000000000000000000001 indicates the hexadecimal IP address without colons.
  • Configuring DNS to specify the WAC's IPv6 address for APs

    In this mode, you need to specify both the domain name and IP address of the WAC on the DNS server.

    • If the WAC functions as a DHCPv6 server to assign IPv6 addresses to APs, perform the configuration according to "(Optional) Configuring Network Server Addresses for an IPv6 Address Pool" in CLI Configuration Guide > IP Addresses and Services Configuration > DHCPv6 Configuration > Configuring a DHCPv6 Server. The key steps are as follows:
      1. Run the system-view command to enter the system view.
      2. Run the dhcpv6 pool pool-name command to create an IPv6 address pool and enter its view.
      3. Run the dns-server ipv6-address command to configure an IPv6 address for the DNS server.
      4. Run the dns-domain-name dns-domain-name command to configure a domain name suffix for APs. After obtaining the suffix, the APs concatenate the suffix and huawei-wlan-controller into a fully qualified domain name (FQDN). The APs then use this FQDN to request the WAC's IP address from the DNS server.
    • If an independent DHCPv6 server is used to assign IPv6 addresses to APs, configure option 24 to carry the WAC's domain name suffix. Otherwise, the APs cannot discover the WAC and will fail to go online on the WAC. For details about the configuration, see the configuration guide of the corresponding device. For example, if the domain name suffix is ipv6.com, its hexadecimal format is 0018000A046970763603636F6D00. In this value, 0018 indicates that the option ID is 24; 000A indicates that the length of the uncompressed domain name format is 10; 04 indicates that the length of ipv6 is 4; 69707636 indicates the ASCII code value of ipv6 characters; 03 indicates that the length of com is 3; 636F6D indicates the ASCII code value of com characters; 00 indicates the end.
