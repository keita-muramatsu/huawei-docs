HTTPS Security

Overview

The RESTCONF service is based on HTTP/HTTPS connections. When the number of HTTP users reaches the upper limit, other users cannot log in to the device. This situation may occur when the server is attacked. To ensure that the HTTP server functions properly, you are advised to configure the HTTP server to reference the ACL in the Service-Restconf view so that the IP addresses of clients that can log in to the server are allowed through the ACL.

Impact on the System

None

Procedure

  1. Enter the system view.

    system-view

  2. Create a basic ACL. You can create a numbered or named basic ACL.

    • Create a numbered basic ACL and enter its view.
      acl [ number ] acl-number
    • Create a named basic ACL and enter its view.
      acl name basic-acl-name basic

  3. Configure a basic ACL rule.

    rule [ rule-id ] [ name rule-name ] { deny | permit } [ fragment-type fragment | source { source-ip-address { source-wildcard | 0 | src-netmask } | any } | time-range time-name | vpn-instance vpn-instance-name | logging ] *

  4. Exit the ACL view.

    quit

  5. Enter the HTTP view.

    http

  6. Create and enter the Service-Restconf view.

    service restconf

  7. Configure HTTP to reference the ACL.

    acl { acl-number |acl-name }

Verifying the Security Hardening Result

Run the display ssl policy command to check whether the HTTPS client is successfully configured.
