Configuring a Traffic Classifier

Prerequisites

Before configuring a traffic classifier, complete the following task:

  • Configure an ACL if it is required to classify packets.

Context

Multiple rules can be configured in a traffic classifier as long as they do not conflict with each other. You can configure rules based on your requirements.

  • A traffic classifier in which matching rules are ANDed cannot define duplicate matching rules. For example, a traffic classifier cannot define both if-match source-mac and an ACL rule that matches the same source MAC address.
  • To match multiple fields of packets of the same type (such as IPv6/IPv4 packets) in a view, apply one traffic policy in the view, and specify multiple traffic classifiers and associated traffic behaviors in the traffic policy. If both IPv4 and IPv6 packets need to be matched, create one traffic policy for each type of packet.
  • Before defining a matching rule based on an application or application group, load the signature database or configure a user-defined application or application group, and ensure that the sa enable command has been run to enable the application identification function on an interface.

Procedure

  1. Enter the system view.

    system-view

  2. Create a traffic classifier and enter the traffic classifier view, or enter the view of an existing traffic classifier.

    traffic classifier classifier-name [ type { and | or } ]
    and is the logical operator between the rules in a traffic classifier, which means that:

    • If the traffic classifier contains ACL rules, packets must match one ACL rule and all the non-ACL rules in order to match the traffic classifier.

    • If the traffic classifier does not contain any ACL rules, packets must match all rules in order to match the traffic classifier.

    The logical operator or means that packets match a traffic classifier if they match one or more rules in the traffic classifier.

    By default, the relationship between rules in a traffic classifier is OR.

    The device supports a maximum of 1024 traffic classifiers.

  3. Configure matching rules according to the following table.

    • Link-layer rule (Layer 2 rule)

      Matching Rule

      Command

      Destination MAC address

      if-match destination-mac mac-address [ mac-address-mask ]

      Source MAC address

      if-match source-mac mac-address [ mac-address-mask ]

      Protocol type in the Ethernet frame header

      if-match l2-protocol { arp | ip | rarp | protocol-value }

      VLAN ID

      if-match vlan start-vlan-value [ to end-vlan-value ]

      802.1p value in the outer tag of VLAN packets

      if-match 8021p 8021p-value &<1-8>
    • Network-layer rule (Layer 3 rule)

      Matching Rule

      Command

      DSCP value in IP packets

      if-match dscp dscp-value &<1-8>

      DSCP value in IPv6 packets

      if-match ipv6 dscp dscp-value &<1-8>

      IP precedence in IP packets

      if-match ip-precedence ip-precedence &<1-8>
    • Transport-layer rule (Layer 4 rule)

      Matching Rule

      Command

      TCP flag in the TCP packet header

      if-match tcp-flag { tcp-flag-value | { ack | fin | psh | rst | syn | urg } * }
    • ACL rule

      Matching Rule

      Command

      ACL rule

      if-match acl { acl-number | acl-name }

      NOTE:

      In the following scenarios, you need to run the qos pre-classify command to configure the pre-extraction function before configuring an ACL-based traffic classifier.

      • For tunnel packets such as GRE packets, traffic classification cannot be performed based on original IP packets because the device cannot obtain QoS fields in original IP packets that are encapsulated. You can run the qos pre-classify command in the tunnel interface view to pre-extract 5-tuple information from encapsulated IP packets to implement traffic classification based on original packets.
      • After NAT is configured on the device and private IP addresses of IP packets are translated into public IP addresses, the NAT-enabled device cannot identify the private IP addresses before translation on the outbound interface. As a result, traffic classification cannot be performed based on private IP addresses. You can run the qos pre-classify command on the outbound interface to allow packets to carry the private IP addresses before NAT to the outbound interface. Traffic classification then can be performed based on private IP addresses.

      ACL6 rule

      if-match ipv6 acl { acl-number | acl6-name }

    • Forwarding rule

      Matching Rule

      Command

      All packets

      if-match any

      Inbound interface

      if-match inbound-interface { { interface-type interface-number1 | interface-name1 } [ to { interface-type interface-number2 | interface-name2 } ] } &<1-8>
    • Application/Application group rule

      Matching Rule

      Command

      Application

      if-match application application-name [ time-range time-name ]

      NOTE:

      application-name specifies the name of an application. You can run the display application command to view application names.

      Application group

      if-match app-group app-group-name [ time-range time-name ]

      NOTE:

      app-group-name specifies the name of an application group. You need to run the application-group name command to create an application group, and then run the add application command in the application group view to add applications to the application group.
    • Other rules

      Matching Rule

      Command

      QoS local ID

      if-match qos-local-id qos-local-id

      NOTE:
      • Before configuring traffic classification based on the QoS local ID, you need to run the qos-local-id qos-local-id command to specify the QoS local ID for packets. Packets with the same QoS local ID are considered to belong to the same QoS group. In this way, traffic policies can be applied to different QoS groups.
      • Currently, the QoS local ID can be specified only for packets on the tunnel interface.

      EXP value of MPLS packets

      if-match mpls-exp mpls-exp-value &<1-8>
