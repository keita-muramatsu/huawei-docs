(Optional) Configuring Signatures

Configuring the States of Predefined Signatures

The state of a predefined signature can be enabled or disabled. You can change their state either in batches or individually.

If you find that some attacks are falsely reported when viewing threat logs, you can change the state of the corresponding signature to disabled.

  1. Enter the system view.

    system-view

  2. Set the states of predefined signatures as required.

    • Set the states of all predefined signatures.
      ips signature-state { enabled | disabled }
    • Set the state of a specific predefined signature.
      ips signature-state signature-id signature-id { enabled | disabled }

  3. Commit the configuration.

    engine configuration commit

Configuring Actions for Predefined Signatures

Each predefined signature has a default action, which can be allow, alert, or block. If you want to customize the actions of predefined signatures, you can perform this configuration to modify the action for a single predefined signature or for all predefined signatures.

You can change the action to alert for all predefined signatures. However, the action cannot be set to allow or block for all pre-defined signatures. You can run the ips signature-state disabled command to disable all IPS signatures.

The priorities of the actions set for predefined signatures are as follows: action set for a single predefined signature > action set in a batch > default action.

  1. Enter the system view.

    system-view

  2. Set the predefined signature action as required.

    • Set the action to alert for all predefined signatures.
      ips signature-action alert
    • Set the action of a specified predefined signature.
      ips signature-action signature-id signature-id { allow | alert | block }

  3. Commit the configuration.

    engine configuration commit

Modifying a Predefined Correlation Signature

Some attack behaviors are complex and cannot be accurately detected based on single-packet signature matching. In this manner, you need to perform correlation detection on packets of one or multiple data flows to detect the attacks. Correlation signatures are used to implement correlation detection. The device collects statistics on the number of times that traffic matches a correlation signature based on certain conditions. Only when the number of times that traffic matches the correlation signature exceeds the preset threshold, the device considers that an attack corresponding to this signature is detected.

The device already provides predefined correlation signatures. By default, signature information contains parameters such as the threshold for the number of times that the signature is matched, time range for collecting statistics on the matching times, and whether the statistics collection is performed based on the source or destination address. If the parameter values cannot meet actual requirements, you can modify them.

You can modify a correlation signature only when you are well aware of network attacks. Incorrect correlation signatures cannot help to defend against attacks or even will interrupt normal services. Therefore, you are advised not to modify correlation signatures in most cases.

  1. View the predefined correlation signatures provided by the device by default. The administrator can modify only the predefined correlation signatures provided by the device.

    display ips-signature pre-defined associated

  2. In the system view, modify a predefined correlation signature based on the signature ID obtained in the previous step.

    system-view
ips associated pre-defined signature-id signature-id { threshold threshold-value | interval interval-value | block-time block-time | correlateby { source | destination | source-destination } } *

  3. Commit the configuration.

    engine configuration commit

Configuring a User-Defined Signature

A user-defined signature consists of basic characteristics and rules. The basic characteristics reflect the characteristics of the signature, and the basic rules reflect the matching rules of the signature.

  1. Enter the system view.

    system-view

  2. Create a user-defined signature.

    ips signature-id signature-id

  3. Optional: Set the name of the user-defined signature.

    name name

  4. Configure the basic characteristics of the user-defined signature.

    Basic characteristics describe the characteristics of the signature instead of defining the signature. These characteristics are used by the signature filter to filter signatures in batches. When matching a data flow against the signature, the system matches the data flow against signature rules instead of basic characteristic items. Therefore, basic characteristic items do not need to fully match actual intrusion information corresponding to the signature.

    Item

    Command

    Configure a detection target for the user-defined signature.

    target { both | client | server }

    Configure a protocol for the user-defined signature.

    protocol protocol-name

    Configure a severity for the user-defined signature.

    severity { high | medium | low | information }

    Configure an action for the user-defined signature.

    action { alert | block | allow }

  5. Create a rule for the user-defined signature.

    rule name name

    Multiple rules can be configured for a user-defined signature. These rules do not affect each other and are not listed in sequence. If a packet matches at least one rule, the packet matches the signature.

  6. Configure check items for the user-defined signature rule.

    condition value text

    Only one check item can be configured for each rule. The IPS third-generation engine syntax provides more diversified configurations for check items.

    The check items for user-defined signature rules are configured in accordance with the IPS third-generation engine syntax. The IPS third-generation engine syntax greatly improves the processing efficiency while maintaining the detection accuracy of the existing syntax. It is also compatible with common syntax in the industry for better openness. For details about the IPS third-generation engine syntax, see IPS Syntax Manual.

    If the protocol to be detected is HTTP, you must specify both the signature string and protocol field (for example, condition value content:"abc";http_uri;). Otherwise, the detection will fail.

  7. Return to the system view.

    quit
quit

  8. Commit the configuration in the system view.

    engine configuration commit

    A new or modified user-defined signature takes effect only after you commit the configuration. To save time, you can commit the configuration after completing all operations on required user-defined signatures.

Viewing Signature Information

  • Check information about predefined or user-defined signatures.

    display ips-signature [ { pre-defined | user-defined } [ associated ] ] [  category { category-name | all } | os { all | android | ios | unix-like | windows | other } * | protocol { protocol-name | all } | severity { information | low | medium | high } * | state { disabled | enabled } | target { server | client | both } ] *

  • Check information about a specific signature.

    display ips-signature ips-signature-id

  • Check the user-defined signature rule with the specified name.

    display ips signature-id signature-id rule { name rule-name | all }

  • Check the action configuration of predefined signatures.

    display ips signature-action

  • Check the status of predefined signatures.

    display ips signature-state

  • View the signatures that are not in the current signature database but have been configured.

    display ips-signature not-in-current-library

  • Check statistics about the top-number signatures that are most frequently matched.

    display ips-signature statistics top-number [ slot slot-id cpu cpu-id ]
