Heartbeat Link

In hot standby networking, two devices exchange messages through heartbeat links to learn the peer status and back up various entries. The interfaces at both ends of a heartbeat link are called heartbeat interfaces. Huawei Redundancy Protocol (HRP) packets carry the exchanged messages, which include:

  • Heartbeat packets (Hello packets): used to check whether devices are alive. Two devices periodically (every 1s by default) send heartbeat packets to each other to check whether the peer device is alive. This also involves checking the priority of the peer device to determine whether the current status of the local and peer devices is stable and whether a switchover is required.
  • Entry backup packets: used to synchronize status information between two devices.
  • Heartbeat link detection packets: used to detect whether the peer heartbeat interface is available and can receive packets from the local heartbeat interface.

Heartbeat Interface Planning and Connecting

You are advised to plan and connect heartbeat interfaces as follows:

  • You can connect heartbeat interfaces directly or through a switch or router. For two devices that form a hot standby group, install them in the same or adjacent racks, and directly connect the heartbeat interfaces through a network or optical cable.

  • Plan a dedicated interface as a heartbeat interface. Such an interface can only send hot standby-related packets (for example, heartbeat and backup packets) and cannot receive service packets. In addition, add multiple Ethernet interfaces to an Eth-Trunk interface and use this Eth-Trunk interface as a heartbeat interface. The Eth-Trunk interface is configured to work in static LACP mode and enabled with per-packet load sharing. This improves link reliability and increases the backup channel's bandwidth.

  • To ensure the stability of the dual-device system and improve the reliability of heartbeat links, you can configure multiple heartbeat interfaces. Currently, by default, STP loop detection is enabled on the device, and multiple VLANs are considered existing in instance 0. In this case, STP considers that multiple heartbeat interfaces form a loop and reserves only one heartbeat interface. To prevent this, if multiple heartbeat interfaces are configured, you need to add each interface to a different VLAN and then add each VLAN to a different instance to ensure that all the directly connected interfaces are available.
  • The management interface cannot be used as a heartbeat interface.

Configuration Requirements for Heartbeat Interfaces

  • The heartbeat interfaces on the two devices must be of the same type, have the same ID, and run the same link protocol. This requirement also applies to member Eth-Trunk interfaces used as the heartbeat interfaces. If VLANIF interfaces are used as the heartbeat interfaces, the same requirement applies to the Layer 2 physical interfaces that transmit and receive packets.
  • The MTU values of all interfaces that send and receive HRP packets cannot be smaller than 1500 bytes. These interfaces include heartbeat interfaces and the interfaces of other network devices that HRP packets pass through. The maximum length of entry backup packets is 1500 bytes, and the packets cannot be fragmented. If the MTU values of the interfaces are smaller than 1500 bytes, packet processing will fail.
  • When an Eth-Trunk interface or its sub-interface is a heartbeat interface in the running state, adding an interface in the up state as its member interface may disconnect the heartbeat link. In this case, run the shutdown command to disable the interface and try again.
  • The IP address configured for the heartbeat interface must be the primary IP address.
