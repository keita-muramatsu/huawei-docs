Example for Configuring DSVPN over IPsec Tunnels Between the Hub and Spokes Across Different Networks

Networking Requirements

For security purposes, you are advised not to use weak security algorithms in this feature.

As shown in Figure 1, an enterprise has a headquarters (Hub) and multiple branches (Spoke1 and Spoke2 in this example). DSVPN is deployed to enable secure connectivity both between the spokes and between each spoke and the hub. Different types of services are transmitted over separate networks. For example, service 1 is carried over network 1, while service 2 is carried over network 2.

The enterprise requires that all data exchanged between the hub and spokes, as well as data transmitted between the spokes, be encrypted.

Figure 1 Network diagram for establishing DSVPN over IPsec tunnels between the headquarters and branch across different networks

In this example, interface1 represents 10GE 0/0/1.


Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure interface IP addresses and OSPF to ensure that there are reachable routes between the public and private networks.

  2. Configure DSVPN and use tunnel interfaces to distinguish services so that different services can be carried over different networks.
  3. Configure IPsec and use IPsec profiles to establish DSVPN over IPsec tunnels for data encryption.

    This section focuses on the DSVPN and IPsec configuration.

    In a DSVPN over IPsec scenario, if a NAT device is deployed, you are advised to set the IPsec encapsulation mode to transport. If two spokes are situated behind different NAT devices or the hub is situated behind a NAT device, the IPsec encapsulation mode can only be transport.

Procedure

  1. Configure interface IP addresses and OSPF.

    # Configure interface IP addresses on Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
    <HUAWEI> system-view
[HUAWEI] sysname Hub
[Hub] interface 10GE0/0/1
[Hub-10GE0/0/1] ip address 1.1.1.1 255.255.255.0
[Hub-10GE0/0/1] quit
[Hub] interface tunnel 0
[Hub-Tunnel0] ip address 10.2.1.1 255.255.255.0
[Hub-Tunnel0] quit
[Hub] interface tunnel 1
[Hub-Tunnel1] ip address 10.3.1.1 255.255.255.0
[Hub-Tunnel1] quit
[Hub] interface loopback 0
[Hub-LoopBack0] ip address 10.1.1.1 255.255.255.255
[Hub-LoopBack0] quit
    # Configure OSPF on Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
    [Hub] ospf 2 router-id 1.1.1.1 
[Hub-ospf-2] area 0.0.0.1 
[Hub-ospf-2-area-0.0.0.1] network 1.1.1.0 0.0.0.255 
[Hub-ospf-2-area-0.0.0.1] quit 
[Hub-ospf-2] quit 
[Hub] ospf 1 router-id 10.1.1.1 
[Hub-ospf-1] area 0.0.0.0 
[Hub-ospf-1-area-0.0.0.0] network 10.1.1.0 0.0.0.255 
[Hub-ospf-1-area-0.0.0.0] network 10.2.1.0 0.0.0.255 
[Hub-ospf-1-area-0.0.0.0] network 10.3.1.0 0.0.0.255 
[Hub-ospf-1-area-0.0.0.0] quit 
[Hub-ospf-1] quit

  2. Configure DSVPN.

    # Configure Hub.
    [Hub] interface tunnel 0 
[Hub-Tunnel0] tunnel-protocol gre p2mp 
[Hub-Tunnel0] source 10GE0/0/1 
[Hub-Tunnel0] gre key cipher 123 
[Hub-Tunnel0] nhrp enable
[Hub-Tunnel0] nhrp entry multicast dynamic 
[Hub-Tunnel0] ospf network-type p2mp 
[Hub-Tunnel0] nhrp redirect 
[Hub-Tunnel0] quit 
[Hub] interface tunnel 1 
[Hub-Tunnel1] tunnel-protocol gre p2mp 
[Hub-Tunnel1] source 10GE0/0/1 
[Hub-Tunnel1] gre key cipher 456 
[Hub-Tunnel0] nhrp enable
[Hub-Tunnel1] nhrp entry multicast dynamic 
[Hub-Tunnel1] ospf network-type p2mp 
[Hub-Tunnel1] nhrp redirect 
[Hub-Tunnel1] quit
    # Configure Spoke1. The configuration of Spoke2 is similar to that of Spoke1.
    [Spoke1] interface tunnel 0
[Spoke1-Tunnel0] tunnel-protocol gre p2mp 
[Spoke1-Tunnel0] source 10GE0/0/1  
[Spoke1-Tunnel0] gre key cipher 123 
[Hub-Tunnel0] nhrp enable
[Spoke1-Tunnel0] nhrp entry 10.2.1.1 1.1.1.1 register 
[Spoke1-Tunnel0] ospf network-type p2mp 
[Spoke1-Tunnel0] nhrp shortcut 
[Spoke1-Tunnel0] quit 
[Spoke1] interface tunnel 1 
[Spoke1-Tunnel1] tunnel-protocol gre p2mp 
[Spoke1-Tunnel1] source 10GE0/0/1  
[Spoke1-Tunnel1] gre key cipher 456 
[Spoke1-Tunnel1] nhrp enable
[Spoke1-Tunnel1] nhrp entry 10.3.1.1 1.1.1.1 register 
[Spoke1-Tunnel1] ospf network-type p2mp 
[Spoke1-Tunnel1] nhrp shortcut 
[Spoke1-Tunnel1] quit

  3. Enable NHRP globally.

    # Configure Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
    [Hub] nhrp enable

  4. Configure IPsec. Configure the same authentication mode, authentication algorithm, and encryption algorithm on the hub and spokes.
    1. Configure an IKE proposal.

      # Configure Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
      [Hub] ike proposal 1
[Hub-ike-proposal-1] encryption-algorithm aes-gcm-256
[Hub-ike-proposal-1] dh group14
[Hub-ike-proposal-1] authentication-algorithm sha2-256
[Hub-ike-proposal-1] authentication-method pre-share
[Hub-ike-proposal-1] quit

    2. Configure an IKE peer.

      # Configure Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
      [Hub] ike peer hub 
[Hub-ike-peer-hub] ike-proposal 1 
[Hub-ike-peer-hub] pre-shared-key YsHsjx_202206 
[Hub-ike-peer-hub] quit

    3. Create an IPsec proposal.

      # Configure Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
      [Hub] ipsec proposal pro1 
[Hub-ipsec-proposal-pro1] encapsulation-mode transport 
[Hub-ipsec-proposal-pro1] transform esp 
[Hub-ipsec-proposal-pro1] esp authentication-algorithm sha2-256 
[Hub-ipsec-proposal-pro1] esp encryption-algorithm aes-256-gcm-128 
[Hub-ipsec-proposal-pro1] quit

    4. Configure an IPsec profile.

      # Configure Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
      [Hub] ipsec profile profile1 
[Hub-ipsec-profile-profile1] ike-peer hub 
[Hub-ipsec-profile-profile1] proposal pro1 
[Hub-ipsec-profile-profile1] quit

    5. Apply the IPsec profile to tunnel interfaces.

      Because multiple tunnel interfaces borrow the same physical interface's address, you must specify the shared parameter when applying the IPsec profile to these tunnel interfaces. This ensures that the tunnel interfaces can share the physical interface.

      # Configure Hub. The configurations of Spoke1 and Spoke2 are similar to that of Hub.
      [Hub] interface tunnel 0
[Hub-Tunnel0] ipsec profile profile1 shared 
[Hub-Tunnel0] quit 
[Hub] interface tunnel 1 
[Hub-Tunnel1] ipsec profile profile1 shared 
[Hub-Tunnel1] quit

Configuration Scripts

  • Hub

    #
sysname Hub
#
ipsec proposal pro1
 encapsulation-mode transport
 esp authentication-algorithm sha2-256
 esp encryption-algorithm aes-256-gcm-128
#
ike proposal 1
 encryption-algorithm aes-gcm-256
 dh group14
 authentication-algorithm sha2-256
 authentication-method pre-share
 integrity-algorithm hmac-sha2-256
 prf hmac-sha2-256 
# 
ike peer hub
 pre-shared-key %^%#6n%Y;[:>0T\w~V2nMW//EnxY@k;[q0/x~`.gjZ>#%^%#
 ike-proposal 1
# 
ipsec profile profile1
 ike-peer hub
 proposal pro1
# 
nhrp enable
#
interface 10GE0/0/1
 ip address 1.1.1.1 255.255.255.0
# 
interface LoopBack0
 ip address 10.1.1.1 255.255.255.255
# 
interface Tunnel0
 ip address 10.2.1.1 255.255.255.0
 tunnel-protocol gre p2mp
 source 10GE0/0/1
 gre key cipher %^%#iPh1-~G^|K+|P44)07a&kw%V3s:4hI"\Lt,WG::J%^%#
 ospf network-type p2mp
 ipsec profile profile1 shared
 nhrp enable
 nhrp redirect
 nhrp entry multicast dynamic
# 
interface Tunnel1
 ip address 10.3.1.1 255.255.255.0
 tunnel-protocol gre p2mp
 source 10GE0/0/1
 gre key cipher %^%#iPh1-~G^|K+|P44)07a&kw%V3s:4hI"\Lt,WG::J%^%#

 ipsec profile profile1 shared
 nhrp enable
 nhrp redirect

  network 1.1.1.0 0.0.0.255
#
return
