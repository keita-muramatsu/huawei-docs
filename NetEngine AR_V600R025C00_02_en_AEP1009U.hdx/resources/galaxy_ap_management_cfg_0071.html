Configuring AP Onboarding Parameters (in the AP View)

Context

You can configure AP onboarding parameters on a WAC, including the IP address allocation mode, static IP address, gateway address, and WAC IP address list of APs. In this manner, you do not need to log in to APs one by one to configure these parameters.

You can configure AP onboarding parameters in either of the following views:
  • AP view
  • AP provisioning view

You are advised to configure AP onboarding parameters for a large number of APs in the AP provisioning view or for a single AP in the AP view.

By default, no configuration exists in the AP view. That means that an AP does not change the default onboarding parameter settings. You can run the display ap provision command to view the configuration in the AP view.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Enter the AP view.

    ap-id ap-id

  4. Configure an IP address and WAC IP address list for the AP.

    IPv4 and IPv6 addresses cannot be configured for an AP simultaneously.

    If an IP address has been configured in the AP view and the IP version is different from that configured in the AP provisioning view, delete the configuration in the AP view first.

    • Configure an IPv4 address and WAC IPv4 address list for the AP.

      1. Configure the mode in which the AP obtains an IPv4 address.
        address-mode { dhcp | static }

        By default, the mode in which an AP obtains an IP address is not configured.

      2. Optional: Configure a static IPv4 address and gateway for the AP.
        ip-address ipv4-address { mask | mask-length } [ gateway gateway ]

        By default, no static IPv4 address or gateway is configured for an AP.

        This step can be performed only when an AP is configured to obtain an IP address in static mode (that is, address-mode static is configured).

        Ensure that there are reachable routes between the configured IPv4 address and the WAC source address for an AP to go online. Otherwise, the AP may fail to go online.

        CAPWAP packets between the central AP and RUs in V200R019C10 or earlier are forwarded at Layer 2 and are independent of IP addresses on an agile distributed WLAN. Therefore, the configuration of an IP address does not affect the RU going online. Ensure that a route is reachable between the IP address of the RU and the central AP source address. Otherwise, services involving IP addresses may be affected, for example, STelnet.

        If the AP and WAC are connected through a Layer 3 network, the egress gateway for AP routes must be configured.

      3. Configure the WAC IPv4 address list for the AP.
        ac-list ipv4-address &<1-4>

        By default, no WAC IPv4 address list is configured.

    • Configure an IPv6 address and WAC IPv6 address list for the AP.

      1. Configure the mode in which the AP obtains an IPv6 address.
        address-mode { slaac | static }

        By default, the mode in which an AP obtains an IP address is not configured.

      2. Optional:
        Configure a static IPv6 address and gateway for the AP.
        ipv6-address { ipv6-address prefix-length | ipv6-address-with-prefix } [ gateway gateway ]

        By default, no static IPv6 address or gateway is configured for an AP.

        This step can be performed only when an AP is configured to obtain an IP address in static mode (that is, address-mode static is configured).

        Ensure that there are reachable routes between the configured IPv6 address and the WAC source address for an AP to go online. Otherwise, the AP may fail to go online.

        If the AP and WAC are connected through a Layer 3 network, the egress gateway for AP routes must be configured.

      3. Configure the WAC IPv6 address list for the AP.
        ac-list ipv6 ipv6-address &<1-4>

        By default, no WAC IPv6 address list is configured.

  5. Optional: Configure CAPWAP packets sent from the AP's wired interface to carry the management VLAN tag.

    management-vlan vlan-id

    By default, CAPWAP packets sent from an AP's wired interface do not carry a management VLAN tag.

    If the PVID of the access device has been used for other purposes (for example, as the default VLAN ID of wired users), the PVID cannot be configured as the management VLAN ID on the access device interface. In this case, configure CAPWAP packets sent from an AP's wired interface to carry the management VLAN tag. The AP then adds the management VLAN tag to the CAPWAP packets sent to the WAC. You only need to configure the access device to allow the packets carrying the management VLAN tag to pass.

    • After the management-vlan vlan-id command is executed, to configure the AP's wired interface to allow packets carrying the management VLAN tag to pass through, run the vlan tagged vlan-id command to add the AP's wired interface to the management VLAN in tagged mode.
    • After the management-vlan vlan-id command is executed, to disable packets sent from the AP's wired interface from carrying the management VLAN tag, run the vlan untagged vlan-id command to add this interface to the management VLAN in untagged mode.
    • After the management-vlan vlan-id command is executed, to add the management VLAN tag to untagged packets received on the AP's wired interface, run the vlan pvid vlan-id command to set the PVID of the AP's wired interface to the management VLAN ID.

  6. Configure the WAC authentication function for the AP.

    1. Restore the default state of the WAC authentication function for the AP.
      undo capwap dtls server-auth

      By default, the WAC authentication function for the AP is disabled.

    2. Restore the default CN field used by APs to verify a WAC's certificate.
      undo capwap dtls server-auth cn

      By default, no CN field is specified for APs to verify a WAC's certificate.

    In the AP view, you can only restore the default settings of the WAC authentication function and the CN field used by the AP to verify WAC certificates. To modify these configurations, run the capwap dtls server-auth { enable | disable } and capwap dtls server-auth cn cn-string commands in the AP provisioning view and run the commit command to deliver the configurations.

Verifying the Configuration

  • Run the display ap provision ap-id ap-id command to check the AP onboarding configuration.
