Adding APs

Context

You can add APs in any of the following ways:
  • Import APs.

    The MAC addresses and SNs of APs are preconfigured on a WAC before they go online. The WAC automatically starts to set up a connection with an AP if its MAC address or SN matches the preconfigured ones.

  • Discover APs automatically when the AP authentication mode is none authentication.

    Set the AP authentication mode to none authentication. When an AP connects to the WAC, the WAC automatically discovers the AP and allows it to go online.

  • Discover APs automatically when the AP authentication mode is MAC address or SN authentication.

    Set the AP authentication mode to MAC address or SN authentication and add APs to the AP whitelist. When an AP in the whitelist connects to the WAC, the WAC automatically discovers the AP and allows it to go online.

  • Manually confirm APs in the list of unauthorized APs.

    In MAC address or SN authentication mode, if an AP is not manually imported on the WAC or whitelisted, the WAC adds the AP to the list of unauthorized APs. The AP can go online only after its identity is manually confirmed.

When importing an AP, you can modify the default parameters of the AP (for example, the default AP group it joins). After the AP goes online, it works using the modified settings. In contrast, if an AP is discovered automatically, it can only use the default settings to go online. Importing APs is recommended when the MAC addresses or SNs of APs are available.

The AP blacklist and whitelist mentioned earlier are described as follows:
  • If the MAC address of an AP is in the AP blacklist, the AP cannot connect to the WAC.
  • The AP blacklist and whitelist can both be configured. However, the MAC address of an AP cannot be added to both of them.
  • If the AP whitelist and blacklist are both configured, the system checks an AP against the blacklist first.
Some APs on a WLAN may run versions later than the WAC. In this case, you can configure the WAC to support the types of these APs as follows:
  • When APs running later versions connect to a WAC, you used to have to upgrade the WAC version. However, upgrading the WAC version on the live network affects services of all APs. Additionally, if the WAC is involved in wired services, services of wired users will also be affected. In this case, you can configure the WAC to support the types of APs running later versions so that there is no need for an immediate WAC upgrade.
  • You can configure a WAC to support the types of APs running later versions through automatic import or manual configuration.

    In most cases, it is not recommended that the ap-type command be executed to create an AP type for a new model. If you have to, ensure that the mapping between type-id and type is configured correctly. Otherwise, APs of this new AP type will fail to connect to the WAC. For the mapping between type-id and type, see the AP Type Names and IDs sheet in the Quick Reference for WLAN AP Version Mapping and Models.

  • The WAC does not support the configuration for types of central APs running later versions and matching RUs.
The number of APs managed by a WAC is restricted by the following factors:
  • License resource items: The total number of common APs and central APs does not exceed the maximum number of local license resource items on the WAC. RUs do not occupy license resources.
  • Maximum number of APs managed by a WAC: The maximum number of central APs managed by a WAC is irrelevant to the maximum number of common APs and RUs that the WAC can manage.
    • The total number of common APs and RUs cannot exceed the maximum number that can be managed by a WAC.
    • The total number of central APs does not exceed the maximum number that can be managed by a WAC.

Assuming that the number of license resource items is 512 and the WAC has connected to 200 common APs, 30 central APs, and 24 RUs, 230 license resource items are occupied. The number of remaining license resources becomes 282 (512 – 200 – 30 = 282). The maximum number of common APs and RUs managed by the WAC is 6144, so the WAC can still support a maximum of 5920 RUs (6144 – 200 – 24 = 5920).

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Optional: Add specified APs to the AP blacklist.

    ap blacklist mac ap-mac1 [ to ap-mac2 ]

    By default, no APs exist in the AP blacklist.

  4. Add APs based on the authentication mode.

    • Import APs.
      1. Set the AP authentication mode to MAC address or SN authentication.
        ap auth-mode { mac-auth | sn-auth }
      2. Import an AP and enter the AP view.
        ap-id ap-id [ type-id type-id | ap-type ap-type ] { ap-mac ap-mac | ap-sn ap-sn | ap-mac ap-mac ap-sn ap-sn }
      3. Configure an AP name.
        ap-name ap-name

        By default, no AP name is configured.

      4. Add the AP to an AP group.
        ap-group ap-group

        By default, an AP is not added to any AP groups.

        Each AP must be added to an AP group. If no AP group is configured for an AP, the AP automatically joins the AP group default.

      When AP hardware replacement is required, run the ap modify ap-id mac mac command in the WLAN view to specify the MAC address of a new AP for an existing AP ID. After the change, the new AP goes online using the ID of the original AP so that all data configurations of the original AP directly take effect on the new AP.

    • Discover APs automatically when the AP authentication mode is none authentication.
      1. Set the AP authentication mode to none authentication.
        ap auth-mode no-auth

        The none authentication mode brings security risks. You are advised to set the authentication mode to MAC address or SN authentication, which is more secure.

    • Discover APs automatically when the AP authentication mode is MAC address or SN authentication.
      1. Set the AP authentication mode to MAC address or SN authentication.
        ap auth-mode { mac-auth | sn-auth }
      2. Add a specified AP to the whitelist. In MAC address authentication mode, the MAC address of the AP is added to the whitelist. In SN authentication, the AP SN is added to the whitelist.
        ap whitelist { mac ap-mac1 [ to ap-mac2 ] | sn ap-sn1 [ to ap-sn2 ] }
    • Manually confirm APs in the list of unauthorized APs.
      1. Set the AP authentication mode to MAC address or SN authentication.
        ap auth-mode { mac-auth | sn-auth }
      2. Check information about unauthorized APs.
        display ap unauthorized record
      3. Confirm the unauthorized APs and allow them to go online.
        ap-confirm { all | mac ap-mac | sn ap-sn }

  5. Configure the WAC to support the types of APs running later versions.

    1. Display the types of the APs that fail to connect to the WAC because the WAC does not support these AP types.
      display ap-type undefined record
    2. Configure automatic import of AP types. After the command is executed, the import result is automatically displayed.
      auto create ap-type { type-id type-id | type type | all }
    3. Manually add AP types. 
      ap-type ap-type type-id type-id
