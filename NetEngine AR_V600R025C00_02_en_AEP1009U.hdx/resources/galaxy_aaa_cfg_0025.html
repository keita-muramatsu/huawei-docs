RADIUS Packet Retransmission Mechanism

When a user is being authenticated, a device sends an Access-Request packet to the RADIUS server. To ensure that the device can receive a response packet from the server even if a network fault or delay occurs, a retransmission upon timeout mechanism is used. The number of retransmissions and retransmission interval are controlled using the retransmission timer.

RADIUS packet retransmission discussed here applies only to a single server. If multiple servers are configured in a RADIUS server template, the overall retransmission period depends on the retransmission interval, number of retransmissions, RADIUS server status, number of servers, and algorithm for selecting the servers.

You can set the retransmission timer using the following commands:

Command

Description

radius-server retransmit retry-times

Number of retransmissions.

radius-server timeout time-value

Retransmission interval.

In Figure 1, a Telnet user requests to log in to the device. After the device receives the request, it sends a RADIUS Access-Request packet to the RADIUS server and enables the retransmission timer. The retransmission timer defines the retransmission interval and number of retransmissions. If the device does not receive any response packet from the RADIUS server when the retransmission interval expires, it sends a RADIUS Access-Request packet again.

Figure 1 RADIUS authentication packet retransmission flowchart
The device stops packet retransmission if any of the following conditions is met:
  • The device receives a response packet from the RADIUS server. It then stops packet retransmission and marks the RADIUS server status as up.
  • The device detects that the RADIUS server status is down. After the device marks the RADIUS server status as down:
    • If the number of retransmitted packets has reached the upper limit, the device stops packet retransmission and retains the RADIUS server status as down.
    • If the number of retransmitted packets has not reached the upper limit, the device retransmits an Access-Request packet once again to the RADIUS server. If the device receives a response packet from the server, it stops packet retransmission and restores the RADIUS server status to up. Otherwise, it still stops packet retransmission and retains the RADIUS server status as down.
  • The number of retransmitted packets has reached the upper limit. The device then stops packet retransmission and performs the following:
    • If the device receives a response packet from the RADIUS server, it marks the RADIUS server status as up.
    • If the device has detected that the RADIUS server status is down, it marks the server status as down.
    • If the device receives no response packet from the RADIUS server and does not detect that the server status is down, the device does not change the server status. Actually, the server does not respond.

      The device does not definitely mark the status of the server that does not respond as down. The device marks the server status as down only if the corresponding conditions are met.

For the RADIUS server status and conditions for a device to mark the server status as down, see RADIUS Server Status Detection.
