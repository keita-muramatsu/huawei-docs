Understanding DNS Relay/Proxy

If the IP address of a DNS server changes, the configuration of each DNS client on the user network needs to be updated accordingly. This is both time consuming and error prone. To resolve this issue, you can deploy a DNS relay/proxy agent. After you configure the IP address of the DNS relay/proxy agent on a DNS client and that of the DNS server on the DNS relay/proxy agent, the client directly sends DNS request packets to the DNS relay/proxy agent, which then forwards them to the DNS server. In this way, you need to change the configuration only on the DNS relay agent if the DNS server's IP address changes, simplifying network management.

Differences Between DNS Relay and DNS Proxy

  • DNS relay and DNS proxy are functionally the same, differing only in whether the corresponding device searches the local domain name resolution table (including the static domain name resolution table and local domain name cache table) before forwarding DNS request packets.
  • After receiving a DNS request packet from a DNS client, the DNS proxy agent searches the local domain name resolution table. If no matching entry is found, it forwards the packet to the DNS server.
  • After receiving a DNS request packet from a DNS client, the DNS relay agent directly forwards the packet to the DNS server for resolution instead of searching the local domain name resolution table. This reduces the DNS cache overhead on the DNS relay agent and ensures that the DNS client can obtain the resolution result in real time. (If the domain name and IP address on the DNS server change but the cache table of the DNS proxy agent is not updated promptly, the resolution result obtained by the DNS client is incorrect.)

Working principle of the DNS relay agent

Figure 1 Working principle of the DNS relay agent
  1. The DNS client sends to the DNS relay agent a DNS request packet in which the destination address is the IP address of the DNS relay agent.
  2. After receiving the request packet, the DNS relay agent forwards it to the DNS server for domain name resolution.
    • The DNS relay agent sends a DNS request packet to the DNS server only when the DNS relay agent is configured with the IP address of the DNS server and has a route to the DNS server.
    • After receiving a DNS request packet from the DNS client, the DNS relay agent directly forwards the packet to the DNS server for resolution instead of searching the local domain name resolution table. This reduces the DNS cache overhead on the DNS relay agent and ensures that the DNS client can obtain the resolution result in real time. (If the domain name and IP address on the DNS server change but the cache table of the DNS relay agent is not updated promptly, the resolution result obtained by the DNS client is incorrect.)
