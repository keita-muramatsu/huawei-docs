Configuring DTLS Encryption for CAPWAP Tunnels

Context

To prevent security risks, it is recommended that DTLS encryption be enabled for CAPWAP tunnels. During CAPWAP tunnel establishment, DTLS negotiation is performed to determine whether to encrypt packets exchanged between the WAC and APs, thereby ensuring packet integrity and privacy.

Procedure

  1. Enter the system view.

    system-view

  2. Configure a PSK used for DTLS encryption.

    capwap dtls psk psk-value

    For security purposes, you are advised to periodically change the PSK.

  3. Configure DTLS encryption for CAPWAP control tunnels.

    capwap dtls control-link encrypt

    By default, DTLS encryption for CAPWAP control tunnels is disabled.

    To locate faults based on wired packets transmitted between a WAC and a Fit AP in O&M scenarios, run the capwap dtls control-link encrypt disable command in the AP system profile view to temporarily disable DTLS encryption for CAPWAP control tunnels of the Fit AP. After this function is disabled on a Fit AP, the security of the Fit AP deteriorates. After the fault is located, restore the default configuration immediately.

  4. Optional: Allow the CAPWAP DTLS server to establish a DTLS session with a DTLS client running an earlier version.

    CAPWAP clients running versions earlier than V200R021C00 support only DTLS CBC cipher suites and DTLS 1.0, which may impose security risks. To address this, perform this step to enable the function of establishing CAPWAP DTLS sessions with these clients. Pay attention to the following points during the configuration:
    • This function can be used only after the weak security algorithm/protocol feature package (WEAKEA) is installed by using the install feature-software WEAKEA command.
    • This function does not take effect after the Federal Information Processing Standards (FIPS) mode is enabled.
    1. Enable the CAPWAP DTLS server to establish DTLS sessions with DTLS clients running earlier versions using the CBC cipher suite.
      capwap dtls cbc enable

      By default, CAPWAP DTLS compatibility with CBC cipher suites is disabled.

    2. Enable the CAPWAP DTLS 1.0 compatibility for DTLS sessions between CAPWAP DTLS servers and DTLS clients running earlier versions.
      capwap dtls version1.0 enable

      By default, CAPWAP DTLS 1.0 compatibility is disabled.

  5. During deployment, configure the remote end to establish DTLS sessions in none authentication mode. After the remote end goes online, the local end sends a new DTLS certificate to the remote end to re-establish a DTLS session in secure mode. To ensure network security, undo this configuration immediately after the remote end goes online again, thereby preventing unauthorized access to the network.

    capwap dtls no-auth enable
undo capwap dtls no-auth enable

    By default, the function of establishing CAPWAP DTLS sessions in none authentication mode is disabled.

    APs running V200R021C00 or later support the initial certificate mode for establishing DTLS sessions. If all APs on the network meet this version requirement, you can configure the remote end to establish DTLS sessions in initial certificate mode. After the remote end is online for a period of time, undo this configuration.

    If an AP has been onboarded on another WAC where the PSK for DTLS encryption is configured, the AP will fail to go online after being steered to the local WAC. In this case, you need to enable APs to establish DTLS sessions through the initial certificate. After the AP goes online, it obtains a new DTLS credential to establish a DTLS session and go online again in secure mode. Then, disable this function.

    undo capwap dtls cert-mandatory-match disable
capwap dtls cert-mandatory-match disable

    By default, the function of establishing CAPWAP DTLS sessions through the initial certificate is enabled.

  6. Configure the WAC to verify the CN field of AP certificates in the AP system profile view.

    1. Enter the WLAN view.
      wlan
    2. Create an AP system profile and enter its view.
      ap-system-profile name profile-name

      By default, the AP system profile default exists on the device.

    3. Configure the WAC to verify the CN field of AP certificates.
      capwap dtls cert-cn { by-sn | cn-string string }

      By default, the function of verifying the CN field in certificates is disabled.
