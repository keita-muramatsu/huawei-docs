LLDP Working Modes

LLDP is working in one of the following modes:
  • Tx mode: enables a device only to send LLDP frames.
  • Rx mode: enables a device only to receive LLDP frames.
  • Tx/Rx mode: enables a device to send and receive LLDP frames.
  • Disabled mode: disables a device from sending or receiving LLDP frames.
The default working mode is Tx/Rx.

When the LLDP working mode changes on an interface, the interface initializes the LLDP state machines. To avoid frequent initializations caused by frequent changes of the working mode of an interface, the device supports an initial delay on an interface. When the working mode of an interface changes, the interface initializes the LLDP state machines after the set delay interval.

The following describes how LLDP frames are sent and received in LLDP mode.
  • Principles for sending LLDP frames

    Generally, after LLDP is enabled, the device periodically sends LLDP frames to neighboring nodes. When the configuration of the local device changes, the device immediately sends LLDP frames to neighboring devices to advertise the changes. If information changes frequently, the device allows setting a delay for an interface to send LLDP frames to reduce the number of LLDP frames. After an interface sends an LLDP frame, the interface sends another LLDP frame after the set delay interval.

    When a device detects a new neighbor (that is, when a device receives an LLDP frame sent by a transmit device, whereas the device has no information about the transmit device), or when LLDP is disabled for a device that previously had LLDP enabled, or the interface status of a device goes up, the fast sending mechanism shortens the interval at which the device to override pre-set delay intervals and advertise local information to other devices quickly. The fast sending mechanism allows the device to shorten the pre-set interval at which LLDP frames are sent to 1s. The pre-set interval is restored after a set number of LLDP frames are sent.

  • Principles for receiving LLDP frames

    A device checks whether TLVs carried in the LLDP frames it receives are valid. If yes, the device saves information about neighboring devices and uses the TTL value carried in the LLDPDU to set an aging time for the information. If the TTL value carried by a received LLDPDU is 0, information about neighboring devices is aged immediately.
