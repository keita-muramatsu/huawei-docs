Descriptions of Traps in the Trap Buffer

The output format of a trap on a CLI terminal is as follows:

Oct 19 2020 20:44:12 HUAWEI %%01FEI/4/hwBoardResWarningThresholdExceed(t):CID=0x0-OID=1.3.6.1.4.1.2011.5.25.227.2.1.20;
The number of forwarding resources reaches the alarm threshold. (Slot = 8, Threshold = 75, Reason = 2, Description : The percentage of used BFD entries exceeded the alarm threshold.)

Time

Timestamp, that is, time to output log information
The following timestamp formats are available:
  • boot: indicates that the timestamp is the period of time elapsed since the system startup. The format is xxxxxx.yyyyyy, where xxxxxx is the leftmost 32 bits of the milliseconds elapsed since system startup, and yyyyyy is the rightmost 32 bits of the milliseconds elapsed since system startup.
  • date: indicate that the timestamp is the current system date and time. The format is mm dd yyyy hh:mm:ss.
  • short-date: indicates that the timestamp uses the short date format, which is similar to the date format, except that the year is not displayed in the short-date format.
  • format-date: expressed in the format of YYYY-MM-DD hh:mm:ss.

The timestamp and hostname are separated by a space. The system supports the configuration of the information output time format.

Severity

Trap level

Indicates the severity of a trap.

Traps are classified into event traps and alarm traps.

  1. Event traps are classified into eight severity levels. The smaller the value of the trap level, the higher the severity. The trap severity levels are as follows:

    • 0: emergency

      A fault causes failure of the device to run properly, and a restart is required. For example, the device restarts because of a program exception or a fault relating to memory usage.

    • 1: alert

      A serious fault occurs. For example, device memory reaches the maximum limit. The fault must be rectified immediately.

    • 2: critical

      A critical fault occurs. For example, memory usage reaches the lower limit, the temperature reaches the lower limit, or error messages are generated by the local device. The fault must be analyzed and rectified.

    • 3: error

      An incorrect operation or unexpected process occurs. For example, users enter incorrect commands or passwords, or error protocol packets received by other devices are detected. The fault requires attention and cause analysis.

    • 4: warning

      An exception occurs. For example, users disable a routing process, or error protocol packets are detected. The fault requires attention.

    • 5: notice

      A key operation is performed to ensure that the device continues to run properly. For example, the shutdown command is used on an interface, a neighbor is discovered, or the protocol status is changed.

    • 6: informational

      A routine operation is performed to keep a device running properly. For example, the display command is used.

    • 7: debugging

      A routine operation is performed to keep a device running properly, and no action is required.

  2. Alarm traps are classified into four levels. The alarm severity levels are as follows:
    • Critical: A service affecting condition has occurred and an immediate corrective action is required. For example, when a managed object becomes totally out of service, its capability must be restored.
    • Major: A service affecting condition has developed, and an urgent corrective action is required. For example, when there is a severe degradation in the capability of a managed object, its full capability must be restored.
    • Minor: A fault that does not yet affect services has occurred, and a rectification measure is required to prevent the fault from affecting services. For example, when the detected alarm condition is not currently degrading the capacity of the managed object.
    • Warning: A potential fault that will affect services is detected. Actions should be taken to further diagnose the fault (if necessary) and rectify the fault before the fault grows in severity and affects services.

For the mappings between alarm severity levels and trap severity levels in the information center, see Table 2.
