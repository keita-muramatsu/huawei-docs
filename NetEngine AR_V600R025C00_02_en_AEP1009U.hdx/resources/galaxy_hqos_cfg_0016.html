HQoS Queue Scheduling

Conventional QoS schedules packets based on PQs (ranging from 0 to 7). Specifically, devices automatically place classified packets into queues based on the mappings between local priorities and queues, and then schedule the packets by queue. Figure 1 shows conventional QoS scheduling.

Figure 1 Conventional QoS scheduling

When HQoS is enabled, a device supports flow queues (FQs) and subscriber queues (SQs), which are used to differentiate user services and users, respectively. You can define QoS parameters for FQs or SQs based on traffic requirements. In HQoS scheduling, packets enter an FQ and then an SQ, before finally being sent out from the destination interface. Figure 2 shows HQoS queue scheduling.

Figure 2 HQoS queue scheduling
  • FQ

    For a given user, traffic of the same service type (for example, voice, data, or video) is considered to belong to the same service flow. HQoS places different service flows of a user into different FQs for scheduling.

    The following QoS parameters can be set for each FQ: the scheduling mode, traffic shaping rate, and drop policy.

  • SQ

    Traffic of all services from users of the same type (for example, users in a VLAN or VPN) is placed into the same SQ. HQoS allows all services in the SQ to share its bandwidth.

    The following QoS parameters can be set for each SQ: the scheduling mode and traffic shaping rate.

  • Destination interface

    The destination interface is the outbound interface of packets. You can configure outbound interface-based traffic shaping (interface-based rate limiting).

The following example describes HQoS queue scheduling. As shown in Figure 3, assume that there are common users and VIP users, and both types of users have data, voice, and video services. Voice services must be preferentially guaranteed, and voice, data, and video services are transmitted in descending order of priority. HQoS provides service-based scheduling and user-based scheduling. Service-based scheduling is performed for different services of each user to ensure that important services are preferentially processed. User-based scheduling ensures that packets of VIP users are preferentially sent, providing QoS guarantee for key users and services.
