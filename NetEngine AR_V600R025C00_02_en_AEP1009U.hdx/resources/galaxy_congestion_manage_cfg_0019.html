Configuring Congestion Management for Queues on an Interface

Context

Congestion management is a queue-based technology. With congestion management configured, if packets are buffered in queues due to congestion on a network, the device determines the sequence at which packets are forwarded according to the defined scheduling policy, thereby preferentially scheduling high-priority services.

There are eight queues on each interface, and each queue is able to use a different scheduling mode. During queue scheduling, PQ queues are scheduled first. Multiple PQ queues are scheduled in descending order of priority, with a larger queue index indicating a higher priority. After completing PQ scheduling, the device schedules the queues using WDRR scheduling.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the interface view.

    interface { interface-type interface-number | interface-name }

  3. (Optional) Enable the queue capability on the interface.

    qos queue-scheduling enable

    By default, the queue capability is disabled on an interface.

    After the queue capability is enabled on an Eth-Trunk interface or a tunnel interface, the loopback function is enabled by default.

    For other physical interfaces, when the queue capability is enabled on an interface, it is not enabled on a sub-interface of the interface. If the queue capability also needs to be used on a sub-interface, enable it in the sub-interface view.

    • Queue resources are not allocated to physical and logical interfaces by default for the AR5700 series, AR6710-L14T2X4, AR6710-L8T3TS1X2, and AR6710-L8T3TS1X2-T. This command can be configured on physical and logical interfaces. For other models, queue resources are allocated to physical interfaces, but are not allocated to logical interfaces by default. Therefore, this command can be configured only on logical interfaces.
    • This command cannot be configured on an MP-group interface or on a serial interface created on an E1 card. If queue resources are insufficient, creating these two types of interfaces will cause queue-related functions on the interfaces to become invalid. In this case, you need to create the interfaces again when queue resources are sufficient.

  4. Configure a scheduling mode for queues on the interface.

    qos { pq { start-queue-index [ to end-queue-index ] } &<1-8> | drr { start-queue-index [ to end-queue-index ] } &<1-8>* }*

  5. (Optional) Configure the queue weight in WDRR scheduling mode.

    qos queue queue-index drr weight weight-value

Verifying the Configuration

Run the display qos queue statistics { slot slotid | interface { interface-type interface-number | interface-name } } [ cpu ] command to check queue-based traffic statistics.
