(Optional) Enabling Proxy ARP on the VLANIF Interface of a Super-VLAN

Prerequisites

Before enabling this function, you have configured an IP address for the VLANIF interface of a super-VLAN.

Context

Although VLAN aggregation allows different sub-VLANs to use IP addresses on the same subnet, it creates a Layer 3 forwarding problem between sub-VLANs. In common VLAN mode, hosts in different VLANs can communicate with each other through Layer 3 forwarding by their respective gateways. However, in VLAN aggregation mode, hosts in a super-VLAN use IP addresses on the same network segment and share the same gateway address, whereas hosts in different sub-VLANs belong to the same subnet. As a result, hosts in sub-VLANs can communicate with each other only at Layer 2, but cannot communicate at Layer 3 through the gateway. Furthermore, hosts in different sub-VLANs are isolated at Layer 2, and therefore cannot communicate with each other.

The proxy ARP function is required to enable hosts in sub-VLANs to communicate with each other and with external networks. After creating a super-VLAN and a VLANIF interface for it, enable the proxy ARP function on the device so that it can forward and process ARP request and reply packets in the super-VLAN, thereby implementing Layer 3 communication between sub-VLANs. VLAN aggregation simplifies configurations when a large number of VLANs exist on an Ethernet network and hosts in different VLANs need to communicate with each other.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the view of the VLANIF interface of a super-VLAN.

    interface vlanif vlan-id

  3. Enable proxy ARP between sub-VLANs.

    arp proxy inter-vlan enable
