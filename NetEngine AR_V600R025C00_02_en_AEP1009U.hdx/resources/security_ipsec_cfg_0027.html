Applying an IPsec Policy Group

Prerequisites

  • IPsec policies have been configured.
  • Before applying an IPsec policy group to an interface, you have completed the following tasks according to your requirements:
    • If you need to apply the IPsec policy group to a Layer 3 interface, you need to configure an IP address on the Layer 3 interface.
    • If you need to apply the IPsec policy group to a sub-interface, you need to configure dot1q encapsulation on the sub-interface.
    • If you need to apply the IPsec policy group to a tunnel interface, you need to set the encapsulation mode of the interface to IPsec, multipoint Generic Routing Encapsulation (mGRE), or GRE and configure an IP address for the interface or configure the interface to borrow an IP address from another interface.

Context

Applying an IPsec policy group to an interface is equivalent to applying all the IPsec policies in the IPsec policy group to the interface. Therefore, different IPsec SAs can be used to protect different data flows.

Only one IPsec policy group can be applied to an interface, and an IPsec policy group can be applied to only one interface. When data is being sent from an interface, the interface searches for each IPsec policy in the IPsec policy group in ascending order of the sequence number. If the data flow matches an ACL referenced in a specific IPsec policy, the interface processes the data flow according to this IPsec policy. If no match is found in an IPsec policy, the interface matches the data flow against another IPsec policy. If the data flow does not match any ACL in all IPsec policies, the interface sends the data flow directly without performing IPsec protection.

After an IPsec policy group is applied to an interface, if you need to add or delete an IPsec policy, modify parameters in an IPsec proposal, you need to cancel applying the IPsec policy group to the interface and then apply the IPsec policy group to the interface again for the modification to take effect. In IKE negotiation mode, if you modify IKE negotiation parameters, the modification takes effect in the next IKE negotiation and does not take effect on the IPsec tunnel that has been successfully negotiated.

The interface to which an IPsec policy group is applied must be the interface on which an IPsec tunnel is established, and the interface must be the outbound interface of the private route from the local end to the remote end.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the interface view.

    interface interface-type interface-number

  3. Apply an IPsec policy group to the interface.

    ipsec policy policy-name

    After a manual IPsec policy is applied to an interface, an SA is generated immediately.

    After an IKE-negotiated IPsec policy is applied to an interface, IPsec tunnel negotiation is triggered in the mode configured using the sa trigger-mode { auto | traffic-based } command.

Verifying the Configuration

Run the display ipsec interface brief command to check information about the IPsec policy referenced by an interface.
