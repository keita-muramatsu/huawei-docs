Example for Configuring IPsec VPN in Different VPN Instances (Using Tunnel Interfaces for Inter-VPN Forwarding)

Networking Requirements

DeviceA is deployed by a carrier as an IPsec gateway, and is leased by multiple small companies to create VPN instances for them. Each company has an independent VPN network granting secure access to the headquarters' network for branch employees or those working remotely.

In Figure 1, PC1 is located on the branch network of company A, and PC2 is located on the branch network of company B. Branches of companies A and B are connected to the Internet through their respective IPsec gateways. On DeviceA, create VPN 1 for company A so that PC1 can securely access VPN 1, and create VPN 2 for company B so that PC2 can securely access VPN 2. There are reachable routes between DeviceA and DeviceB, and between DeviceA and DeviceC.

Figure 1 IPsec multi-instance

In this example, interface 1, interface 2, and interface 3 represent 10GE 0/0/1, 10GE 0/0/2, and 10GE 0/0/3, respectively.

Configuration Roadmap

This example uses default security algorithms of IPsec.

For security purposes, you are advised not to use the weak security algorithm or weak security protocol of this feature. If you must use such a weak security algorithm or protocol, run the install feature-software WEAKEA command to install the weak security algorithm or protocol feature package WEAKEA.

  1. 10GE 0/0/3 of DeviceA is connected to the Internet. 10GE 0/0/1 is connected to the intranet of company A and is bound to the VPN instance vpn1. 10GE 0/0/2 is connected to the intranet of company B and is bound to the VPN instance vpn2.
  2. Configure two tunnel interfaces (Tunnel 0 and Tunnel 1), and bind Tunnel 0 to vpn1 and Tunnel 1 to vpn2. This example uses tunnel interfaces to implement inter-VPN IPsec forwarding.
  3. Configure two IPsec policies with the local IP address set to the IP address of 10GE 0/0/3. Use the local and remote IP addresses (IP address of 10GE 0/0/1 on DeviceB and IP address of 10GE 0/0/1 on DeviceC) for tunnel negotiation.
  4. Apply the IPsec policies to the tunnel interfaces.

Procedure

  • Configure DeviceA.
    1. Configure VPN instances vpn1 and vpn2.

      <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] ip vpn-instance vpn1
[DeviceA-vpn-instance-vpn1] route-distinguisher 100:1
[DeviceA-vpn-instance-vpn1] quit
[DeviceA] ip vpn-instance vpn2
[DeviceA-vpn-instance-vpn2] route-distinguisher 200:1
[DeviceA-vpn-instance-vpn2] quit

    2. Configure IP addresses for interfaces.

      # Configure IP addresses for intranet interfaces 10GE 0/0/1 and 10GE 0/0/2.

      [DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] ip binding vpn-instance vpn1
[DeviceA-10GE0/0/1] ip address 10.1.1.1 24
[DeviceA-10GE0/0/1] quit
[DeviceA] interface 10ge 0/0/2
[DeviceA-10GE0/0/2] ip binding vpn-instance vpn2
[DeviceA-10GE0/0/2] ip address 10.1.0.1 24
[DeviceA-10GE0/0/2] quit

      # Configure an IP address for the interface 10GE 0/0/3.

      [DeviceA] interface 10ge 0/0/3
[Device-10GE0/0/3] ip address 1.1.3.1 24
[DeviceA-10GE0/0/3] quit

      # Create and bind Tunnel 0 and Tunnel 1 to VPN instances vpn1 and vpn2, respectively.

      [DeviceA] interface Tunnel 0
[DeviceA-tunnel0] tunnel-protocol ipsec
[DeviceA-tunnel0] ip binding vpn-instance vpn1
[DeviceA-tunnel0] ip address 10.10.1.2 24
[DeviceA-tunnel0] source 1.1.3.1 
[DeviceA-tunnel0] quit
[DeviceA] interface Tunnel 1
[DeviceA-tunnel1] tunnel-protocol ipsec
[DeviceA-tunnel1] ip binding vpn-instance vpn2
[DeviceA-tunnel1] ip address 10.10.1.1 24
[DeviceA-tunnel1] source 1.1.3.1
[DeviceA-tunnel1] quit

    3. Configure routes destined for the branch.

      [DeviceA] ip route-static vpn-instance vpn1 10.1.3.0 255.255.255.0 tunnel0 
[DeviceA] ip route-static vpn-instance vpn2 10.1.2.0 255.255.255.0 tunnel1

    4. Configure two IPsec policies and apply them to tunnel interfaces.

      # Define data flows to be protected.

      [DeviceA] acl 3000
[DeviceA-acl4-advance-3000] rule 5 permit ip source 10.1.1.0 0.0.0.255 destination 10.1.3.0 0.0.0.255 vpn-instance vpn1
[DeviceA-acl4-advance-3000] quit
[DeviceA] acl 3001
[DeviceA-acl4-advance-3001] rule 10 permit ip source 10.1.0.0 0.0.0.255 destination 10.1.2.0 0.0.0.255 vpn-instance vpn2
[DeviceA-acl4-advance-3001] quit

      # Configure an IPsec proposal. You can use the default parameter settings.

      [DeviceA] ipsec proposal tran1
[DeviceA-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceA-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceA-ipsec-proposal-tran1] quit

      # Configure IKE proposal 10. You can use the default parameter settings.

      [DeviceA] ike proposal 10
[DeviceA-ike-proposal-10] authentication-method pre-share
[DeviceA-ike-proposal-10] prf hmac-sha2-256
[DeviceA-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceA-ike-proposal-10] dh group14
[DeviceA-ike-proposal-10] integrity-algorithm hmac-sha2-256  
[DeviceA-ike-proposal-10] quit

      # Configure IKE peers.

      [DeviceA] ike peer vpn1
[DeviceA-ike-peer-vpn1] ike-proposal 10
[DeviceA-ike-peer-vpn1] remote-address 1.1.5.1
[DeviceA-ike-peer-vpn1] pre-shared-key YsHsjx_202206
[DeviceA-ike-peer-vpn1] sa binding vpn-instance vpn1
[DeviceA-ike-peer-vpn1] quit
[DeviceA] ike peer vpn2
[DeviceA-ike-peer-vpn2] ike-proposal 10
[DeviceA-ike-peer-vpn2] remote-address 1.1.6.1
[DeviceA-ike-peer-vpn2] pre-shared-key YsHsjx_202206
[DeviceA-ike-peer-vpn2] sa binding vpn-instance vpn2
[DeviceA-ike-peer-vpn2] quit

      # Configure two IPsec policies.

      [DeviceA] ipsec policy map1 10 isakmp
[DeviceA-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceA-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceA-ipsec-policy-isakmp-map1-10] ike-peer vpn1
[DeviceA-ipsec-policy-isakmp-map1-10] tunnel local 1.1.3.1
[DeviceA-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceA-ipsec-policy-isakmp-map1-10] quit
[DeviceA] ipsec policy map2 10 isakmp
[DeviceA-ipsec-policy-isakmp-map2-10] security acl 3001
[DeviceA-ipsec-policy-isakmp-map2-10] proposal tran1
[DeviceA-ipsec-policy-isakmp-map2-10] ike-peer vpn2
[DeviceA-ipsec-policy-isakmp-map2-10] tunnel local 1.1.3.1
[DeviceA-ipsec-policy-isakmp-map2-10] sa trigger-mode auto
[DeviceA-ipsec-policy-isakmp-map2-10] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply the IPsec policy map1 to Tunnel 0 and IPsec policy map2 to Tunnel 1.

      [DeviceA] interface tunnel 0
[DeviceA-tunnel0] ipsec policy map1
[DeviceA-tunnel0] quit
[DeviceA] interface tunnel 1
[DeviceA-tunnel1] ipsec policy map2
[DeviceA-tunnel1] quit

  • Configure DeviceB.
    1. Configure IP addresses for interfaces.

      # Configure an IP address for 10GE 0/0/3.
      <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] interface 10ge 0/0/3
[DeviceB-10GE0/0/3] ip address 10.1.3.1 24
[DeviceB-10GE0/0/3] quit
      # Configure an IP address for 10GE 0/0/1.
      [DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] ip address 1.1.5.1 24
[DeviceB-10GE0/0/1] quit

    2. Configure a static route destined for the network where the headquarters of company A resides. The following assumes that the next-hop IP address of the static route is 1.1.5.2.

      [DeviceB] ip route-static 10.1.1.0 255.255.255.0 1.1.5.2

    3. Configure an IPsec policy and apply it to an interface.

      # Configure advanced ACL 3000 to allow users on network segment 10.1.3.0/24 to access network segment 10.1.1.0/24.
      [DeviceB] acl 3000
[DeviceB-acl4-advance-3000] rule 5 permit ip source 10.1.3.0 0.0.0.255 destination 10.1.1.0 0.0.0.255
[DeviceB-acl4-advance-3000] quit
      # Configure an IPsec proposal named tran1. You can use the default parameter settings.
      [DeviceB] ipsec proposal tran1
[DeviceB-ipsec-proposal-tran1] esp authentication-algorithm sha2-256
[DeviceB-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128
[DeviceB-ipsec-proposal-tran1] quit
      # Configure IKE proposal 10. You can use the default parameter settings.
      [DeviceB] ike proposal 10
[DeviceB-ike-proposal-10] authentication-method pre-share
[DeviceB-ike-proposal-10] prf hmac-sha2-256
[DeviceB-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceB-ike-proposal-10] dh group14
[DeviceB-ike-proposal-10] integrity-algorithm hmac-sha2-256  
[DeviceB-ike-proposal-10] quit
      # Configure an IKE peer.
      [DeviceB] ike peer vpn1
[DeviceB-ike-peer-vpn1] ike-proposal 10
[DeviceB-ike-peer-vpn1] remote-address 1.1.3.1
[DeviceB-ike-peer-vpn1] pre-shared-key YsHsjx_202206
[DeviceB-ike-peer-vpn1] quit
      # Configure an IPsec policy with the name map1 and ID 10.
      [DeviceB] ipsec policy map1 10 isakmp
[DeviceB-ipsec-policy-isakmp-map1-10] security acl 3000
[DeviceB-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceB-ipsec-policy-isakmp-map1-10] ike-peer vpn1
[DeviceB-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceB-ipsec-policy-isakmp-map1-10] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply the IPsec policy map1 to 10GE 0/0/1.
      [DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] ipsec policy map1
[DeviceB-10GE0/0/1] quit

  • # Configure DeviceC.
    1. Configure IP addresses for interfaces.

      # Configure an IP address for 10GE 0/0/3.
      <HUAWEI> system-view

[DeviceC-10GE0/0/3] ip address 10.1.2.1 24

      [DeviceC] interface 10ge 0/0/1
[DeviceC-10GE0/0/1] ip address 1.1.6.1 24
[DeviceC-10GE0/0/1] quit

    2. Configure a static route destined for the network where the headquarters of company B resides. The following assumes that the next-hop IP address of the static route is 1.1.6.2.

      [DeviceC] ip route-static 10.1.0.0 255.255.255.0 1.1.6.2

    3. Configure an IPsec policy and apply it to an interface.

[DeviceC-ipsec-proposal-tran1] esp encryption-algorithm aes-256-gcm-128

      # Configure IKE proposal 10. You can use the default parameter settings.
      [DeviceC] ike proposal 10
[DeviceC-ike-proposal-10] authentication-method pre-share
[DeviceC-ike-proposal-10] prf hmac-sha2-256
[DeviceC-ike-proposal-10] encryption-algorithm aes-gcm-256
[DeviceC-ike-proposal-10] dh group14
[DeviceC-ike-proposal-10] integrity-algorithm hmac-sha2-256  
[DeviceC-ike-proposal-10] quit
      # Configure an IKE peer.
      [DeviceC] ike peer vpn2
[DeviceC-ike-peer-vpn2] ike-proposal 10
[DeviceC-ike-peer-vpn2] remote-address 1.1.3.1
[DeviceC-ike-peer-vpn2] pre-shared-key YsHsjx_202206

[DeviceC-ipsec-policy-isakmp-map1-10] security acl 3001
[DeviceC-ipsec-policy-isakmp-map1-10] proposal tran1
[DeviceC-ipsec-policy-isakmp-map1-10] ike-peer vpn2
[DeviceC-ipsec-policy-isakmp-map1-10] sa trigger-mode auto
[DeviceC-ipsec-policy-isakmp-map1-10] quit

      By default, the negotiation for IPsec tunnel establishment is triggered by traffic. To enable automatic negotiation for IPsec tunnel establishment, run the sa trigger-mode auto command.

      # Apply the IPsec policy map1 to 10GE 0/0/1.
      [DeviceC] interface 10ge 0/0/1
[DeviceC-10GE0/0/1] ipsec policy map1
[DeviceC-10GE0/0/1] quit
