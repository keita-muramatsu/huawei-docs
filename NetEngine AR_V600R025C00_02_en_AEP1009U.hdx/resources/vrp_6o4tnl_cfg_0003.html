Understanding IPv6 over IPv4 Tunnels

Fundamentals

IPv4 address exhaustion fuels the urgency to transition to IPv6, but this requires existing IPv4 devices to be replaced as these devices are incompatible with IPv6 networks. The main issue is that replacing a large number of IPv4 devices will incur huge costs and interrupt services on the live networks. Therefore, the transition from IPv4 to IPv6 must be a gradual process. During the early stage of IPv4-to-IPv6 transition, IPv6 networks are scattered across a large number of IPv4 networks. Connecting these isolated IPv6 networks using private lines is costly, so a general method is to leverage a tunneling technique, just as IPv6 over IPv4 tunneling does. With this technique, IPv6 over IPv4 tunnels can be created to enable interconnection between isolated IPv6 networks over an IPv4 network.

An IPv6 over IPv4 tunnel is established between border devices connecting two IPv6 networks to an IPv4 network. Therefore, the border devices must support IPv4/IPv6 dual stack, whereas other devices only need to support IPv4 or IPv6 single stack. Figure 1 shows how an IPv6 over IPv4 tunnel works.

Figure 1 Schematic diagram of an IPv6 over IPv4 tunnel

The process of transmitting IPv6 packets through an IPv6 over IPv4 tunnel is as follows:

  1. IPv4/IPv6 dual stack is enabled on border devices (DeviceA and DeviceB), and an IPv6 over IPv4 tunnel is configured between them.

  2. When receiving an IPv6 packet from the connected IPv6 network, DeviceA encapsulates it into an IPv4 packet by attaching an IPv4 header to the IPv6 packet. This is done only if the IPv6 packet is not destined for DeviceA and has a tunnel interface as the next hop.

  3. DeviceA transmits the resulting IPv4 packet to DeviceB over the IPv4 network.

  4. DeviceB decapsulates the IPv4 packet by removing the IPv4 header, and sends the resulting IPv6 packet to the destination IPv6 network.

Tunnel Configuration

A tunnel is determined by a source and a destination. The source and destination of an IPv6 over IPv4 tunnel need to be manually configured. A manual tunnel is a point-to-point tunnel. When a tunnel is created manually, the tunnel destination IPv4 address must be manually specified so that packets can be correctly sent to the destination, as border devices cannot automatically obtain the tunnel destination IPv4 address in this case.

A manual IPv6 over IPv4 tunnel is manually configured between two border devices, with the source and destination IPv4 addresses statically specified.

A manual tunnel provides a point-to-point connection. If a border device needs to establish tunnels with several devices, manually configuring multiple tunnels on the device is complex. Therefore, manual tunnels apply when two border devices connect only two IPv6 networks.

Figure 2 shows how an IPv6 over IPv4 tunnel works.

Figure 2 Schematic diagram of an IPv6 over IPv4 tunnel

The following describes how HostA accesses HostB:

  1. An IPv6 packet sent from HostA arrives at DeviceA.
  2. DeviceA searches its IPv6 routing table for an entry matching the destination address of the IPv6 packet, and discovers that the outbound interface is a tunnel interface.
  3. DeviceA encapsulates the IPv6 packet into an IPv4 packet. In the IPv4 packet header, the destination address is the source IPv4 address configured for the tunnel on the remote end (that is, DeviceB), and the source address is the source IPv4 address configured for the tunnel on the local end (that is, DeviceA). Then, DeviceA forwards the IPv4 packet from its tunnel interface to DeviceB over the IPv4 network.
  4. DeviceB decapsulates the received IPv4 packet, searches for a routing entry based on the destination address of the resulting IPv6 packet, and forwards the IPv6 packet to HostB.
  5. HostB responds to the received IPv6 packet. The response packet is processed in a similar way as the IPv6 packet sent from HostA.
  • Automatic tunnel: provides point-to-multipoint connections. When a tunnel is created automatically, special IPv6 addresses containing IPv4 addresses need to be configured for tunnel interfaces on both ends of the tunnel, so that border devices can automatically obtain the tunnel destination IPv4 address.
