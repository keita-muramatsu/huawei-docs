Configuring IP Address-based Traffic Policing

Context

If the rate of traffic sent from users is not limited, burst data continuously sent by users may cause the network to become congested. Therefore, to limit the rate of traffic entering an interface on a network device, IP address-based traffic policing can be configured on the interface. When the rate of received packets exceeds the specified traffic policing rate, the device discards excess packets.

The AR5710-S8T2S, AR5710-S8T2X, AR5710-S8T2X-LTE4EA, AR5710-S8P2X, and AR5710-S10T1X2 do not support this function.

When the value of cbs-value is smaller than the number of bytes in a single packet of the deployed service, packets of the service are discarded. To prevent packet color identification problems, you are advised to set the value of pbs-value to be greater than that of cbs-value.

Procedure

  1. Enter the system view.

    system-view

  2. (Optional) Disable the device from counting the inter-frame gaps and preambles when calculating the traffic policing rate.

    qos car ifg disable

    By default, the device counts the inter-frame gaps and preambles when calculating the traffic policing rate.

    Only Ethernet links support this function.

  3. (Optional) Configure the function of counting the packet header length corresponding to the physical link when the device calculates the traffic policing rate.

    1. Enter the tunnel interface view.
      interface tunnel interface-number
    2. Enable the function of counting the packet header length corresponding to the physical link during traffic policing based on the mapping between the tunnel interface and the physical interface.
      qos overhead layer map interface { interface-type interface-number | interface-name }

      By default, the packet header length corresponding to the physical link is not counted during interface-based rate limiting. As a result, the actual rate of traffic passing through an interface may be greater than the rate limit on the interface.

    3. Return to the system view.
      quit

  4. Enter the interface view.

    interface interface-type interface-number

  5. Configure IP address-based traffic policing.

    qos car { inbound | outbound } { destination-ip-address | source-ip-address } range start-ip-address to end-ip-address [ per-address ] [ time-range time-range-name ] cir cir-value [ pir pir-value ] [ cbs cbs-value pbs pbs-value ] [ green pass ] [ yellow { pass | discard } ] [ red { pass | discard } ]

    By default, IP address-based traffic policing is not configured on an interface.
