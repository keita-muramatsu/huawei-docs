Configuring TE-Class-based Traffic Steering into an SRv6 TE Policy

Context

In TE-Class-based traffic steering, the headend recurses traffic based on the next hop of the corresponding route in compliance with the configured tunnel policy. If traffic recursion to an SRv6 TE flow group is configured, the headend matches the traffic with an SRv6 mapping policy that has the same color value as the route. If such an SRv6 mapping policy exists, the headend dynamically generates an SRv6 TE flow group that contains multiple SRv6 TE Policies with the same endpoint but different color values.

If there is no such SRv6 mapping policy, the headend does not dynamically create an SRv6 TE flow group.

If multiple flows with the same color value but different next-hop addresses need to recurse to SRv6 TE flow groups, multiple dynamic SRv6 TE flow groups with different endpoints are created based on the configuration of the matching SRv6 mapping policy.

Procedure

  1. Enter the system view.

    system-view

  2. Enable Segment Routing in the IPv6 forwarding plane and enter the SRv6 view.

    segment-routing ipv6

  3. Create an SRv6 mapping policy and enter the SRv6 mapping policy view.

    mapping-policy name-value color color-value

  4. (Optional) Configure a description for the SRv6 mapping policy.

    description description-value

  5. Set the mapping type of the SRv6 mapping policy to TE-Class.

    match-type te-class

  6. Configure a rule for the mapping between SPR policies, SRv6 TE Policies, or native IP links in an SRv6 TE flow group and TE-Class values.

    • Configure a rule for the mapping between SPR policies in an SRv6 TE flow group and TE-Class values.
    index index-value te-class te-class-id match spr-policy spr-name
    default match spr-policy spr-name

    • Configure a rule for the mapping between SRv6 TE Policies in an SRv6 TE flow group and TE-Class values.
    index index-value te-class te-class-id match srv6-te-policy color color-value
    default match srv6-te-policy color color-value
    • Configure a rule for the mapping between native IP links in an SRv6 TE flow group and TE-Class values. Note that only one such rule can be configured in an SRv6 TE flow group.
    index index-value te-class te-class-id match native-ip
Alternatively:
default match native-ip

    Each SRv6 TE Policy in an SRv6 TE flow group has its own color attribute.

    The index te-class match and default match commands are used together to specify the mapping between color and TE-Class values.

    In an SRv6 TE flow group, TE-Class values and SRv6 TE Policies are associated using the color attribute. IP packets can then be steered into the specified SRv6 TE Policy based on their TE-Class values.

    • The index te-class match spr-policy and default match spr-policy commands configure the mapping between SPR policies and TE-Class values.
    • The index te-class match srv6-te-policy color and default match srv6-te-policy color commands configure the mapping between SRv6 TE Policies and TE-Class values.
    • The index te-class match native-ip and default match native-ip commands configure the mapping between native IP links and TE-Class values.

    During forwarding, IP packets are steered into the specified SRv6 TE Policy based on their TE-Class values. If no SRv6 TE Policy matching a specified TE-Class value is found, the packets are steered into the SRv6 TE Policy specified using the default match command.

  7. Return to the Segment Routing IPv6 view.

    quit

  8. Return to the system view.

    quit

  9. Create a tunnel policy and enter the tunnel policy view.

    tunnel-policy policy-name

  10. (Optional) Configure a description for the tunnel policy.

    description description-information

  11. Configure a tunnel selection policy.

    tunnel select-seq ipv6 srv6-te-flow-group load-balance-number loadBalanceNumber

  12. Return to the system view.

    quit

  13. Configure service recursion to an SRv6 TE Policy.
    • Configure EVPN L3VPN service recursion to an SRv6 TE Policy.
      1. Enter the VPN instance view.
        ip vpn-instance vpn-instance-name
      2. Enter the VPN instance IPv4/IPv6 address family view.
        IPv4:
ipv4-family
IPv6:
ipv6-family
      3. Apply the tunnel policy to an EVPN L3VPN instance.
        tnl-policy policy-name evpn
    • Configure public network IPv4/IPv6 service recursion to an SRv6 TE Policy.
      1. Create a tunnel selector and enter the tunnel selector view.
        tunnel-selector name matchMode node node
      2. Apply the tunnel policy to the tunnel selector.
        apply tunnel-policy tunnel-policy-name
      3. Return to the system view.
        quit
      4. Enter the BGP view.
        bgp as-number
      5. Enter the IPv4/IPv6 unicast address family view.
        IPv4:
ipv4-family unicast
IPv6:
ipv6-family unicast
      6. Enable the device to recurse IPv4/IPv6 unicast routes received from a BGP IPv6 peer to tunnels.
        unicast-route recursive-lookup tunnel-v6 tunnel-selector tunnel-selector-name
