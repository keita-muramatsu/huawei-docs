Example for Configuring CAPWAP

Networking Requirements

In Figure 1, DeviceB is directly connected to DeviceA and DeviceC. The requirements are as follows:

  • DeviceB functions as a DHCP server to assign an IP address to DeviceC.
  • A static IP address is configured for DeviceA.
  • DeviceA functions as a server, and DeviceC functions as a client. A CAPWAP tunnel is established between Device A and Device C, and DTLS encryption is implemented for the tunnel.
Figure 1 Network diagram of CAPWAP

In this example, interface1 and interface2 represent 10GE0/0/1 and 10GE0/0/2, respectively.


Procedure

  1. Create a VLAN and add interfaces to the VLAN.

    # Add interface1 on DeviceA to VLAN 100.

    <HUAWEI> system-view
[HUAWEI] sysname DeviceA
[DeviceA] vlan batch 100
[DeviceA] interface 10ge 0/0/1
[DeviceA-10GE0/0/1] portswitch
[DeviceA-10GE0/0/1] port link-type trunk
[DeviceA-10GE0/0/1] port trunk allow-pass vlan 100
[DeviceA-10GE0/0/1] quit
    # Add interface1 and interface2 on DeviceB to VLAN 100. In this example, DeviceB is a CloudEngine S series switch.
    <HUAWEI> system-view
[HUAWEI] sysname DeviceB
[DeviceB] vlan batch 100
[DeviceB] interface 10ge 0/0/1
[DeviceB-10GE0/0/1] portswitch
[DeviceB-10GE0/0/1] port link-type trunk
[DeviceB-10GE0/0/1] port trunk allow-pass vlan 100
[DeviceB-10GE0/0/1] quit
[DeviceB] interface 10ge 0/0/2
[DeviceB-10GE0/0/2] portswitch
[DeviceB-10GE0/0/2] port link-type trunk
[DeviceB-10GE0/0/2] port trunk pvid vlan 100
[DeviceB-10GE0/0/2] port trunk allow-pass vlan 100
[DeviceB-10GE0/0/2] quit

  2. Configure DeviceB as a DHCP server to assign an IP address to DeviceC.

    [DeviceB] dhcp enable
[DeviceB] interface vlanif 100
[DeviceB-Vlanif100] ip address 10.23.100.3 24
[DeviceB-Vlanif100] dhcp select interface
[DeviceB-Vlanif100] dhcp server excluded-ip-address 10.23.100.1
[DeviceB-Vlanif100] quit

  3. Configure the CAPWAP source interface and DTLS encryption on DeviceA.

    # Configure an IP address for the VLANIF interface, configure the VLANIF interface as the CAPWAP source interface, and configure DTLS encryption.

    [DeviceA] interface vlanif 100
[DeviceA-Vlanif100] ip address 10.23.100.1 24
[DeviceA-Vlanif100] quit
[DeviceA] capwap dtls psk Test321123
[DeviceA] capwap dtls control-link encrypt
Warning: This operation may cause devices using CAPWAP connections to reset or go offline. Continue? [Y/N]:y
[DeviceA] capwap dtls no-auth enable
Warning: This operation allows for device access in non-DTLS encryption mode even when DTLS is enabled and brings security risks. Af
ter the device goes online for the first time, disable this function to prevent security risks. Continue? [Y/N]:y
[DeviceA] capwap source interface vlanif 100  //Upon the first configuration, the CAPWAP source interface or source address can be successfully configured only when all of the following configurations exist: PSK used for DTLS encryption, the user name and password for AP login, and the global login password for the offline management VAP. If any of these configurations does not exist, the system prompts you to supplement the configurations first.

    After the peer device goes online, run the undo capwap dtls no-auth enable command to disable the function of establishing CAPWAP DTLS sessions in none authentication mode, thereby preventing unauthorized devices from accessing the network.

  4. After DeviceC is online for a period of time, disable the function of establishing CAPWAP DTLS sessions in none authentication mode.

    [DeviceA] undo capwap dtls no-auth enable
