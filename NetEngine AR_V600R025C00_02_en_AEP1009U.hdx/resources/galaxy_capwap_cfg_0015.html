(Optional) Enabling CAPWAP Inner Fragmentation

Context

Before the CAPWAP inner fragmentation function is enabled, an AP encapsulates a received service packet into a CAPWAP packet first. If the length of the encapsulated packet exceeds the interface MTU, the AP fragments the packet. The WAC can reassemble and decapsulate the packet only after receiving all the fragments of a packet. As a result, the WAC may forward the service packets in an out-of-order manner. To prevent failures in processing out-of-order packets on some devices, you need to enable the CAPWAP inner fragmentation function.

After the CAPWAP inner fragmentation function is enabled, an AP fragments received service packets at the IP layer prior to CAPWAP encapsulation, thereby eliminating the need for fragmentation at the CAPWAP layer. As a result, packets arrive at the WAC in order, without being reassembled.

Procedure

  1. Enter the system view.

    system-view

  2. Enter the WLAN view.

    wlan

  3. Create an AP system profile and enter its view.

    ap-system-profile name profile-name

    By default, the AP system profile default exists on the device.

  4. Enable CAPWAP inner fragmentation.

    capwap packet inner-fragment enable

    By default, CAPWAP inner fragmentation is disabled.

  5. Return to the WLAN view.

    quit

  6. Enter the AP view or AP group view.
    • Enter the AP group view.
      ap-group name group-name
    • Enter the AP view.
      ap-id ap-id
  7. Bind the AP system profile to an AP group or a single AP.

    ap-system-profile profile-name

    By default, the AP system profile default is bound to an AP group, but no AP system profile is bound to an AP.

Verifying the Configuration

Run the display ap-system-profile name profile-name command to check the CAPWAP inner fragmentation configuration.
