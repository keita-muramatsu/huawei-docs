Configuring PnP VLAN Auto-Negotiation

Context

The PnP VLAN auto-negotiation function needs to be configured on the device in the following scenarios:

When configuring the PnP VLAN on the downlink interface of the upstream device, ensure that vlan-id is within the range configured using port trunk allow-pass vlan { { { vlan-id1 [ tovlan-id2 ] } &<1-40> } | all } on the uplink interface of the downstream device to facilitate cloud migration.

  • The DHCP server does not use the default configuration VLAN1, and a new device needs to be connected.

    As shown in Figure 1, if the VLAN used by the DHCP server is not the default one (VLAN 1), DeviceB uses management VLAN 1 to send a request packet to the DHCP server to obtain the NETCONF enabling status, IP address, and iMaster NCE-Campus information after connecting to the network. However, DeviceB fails to obtain the information because the VLAN used by the DHCP server is not VLAN 1. To solve this problem, configure PnP VLAN auto-negotiation on the upstream device (DeviceA). If all devices can be managed by iMaster NCE-Campus, you can configure PnP VLAN auto-negotiation for DeviceA through the controller. If DeviceA cannot be managed by iMaster NCE-Campus, you can manually configure DeviceA. After DeviceA starts, it transmits the PnP VLAN to DeviceB through PnP VLAN negotiation so that DeviceB can use the PnP VLAN to obtain related information from the DHCP server.

    Figure 1 Campus network diagram
    When all devices can be managed by iMaster NCE-Campus, the upstream device DeviceA can transmit the PnP VLAN to the downstream device DeviceB only when the following conditions are met:
    • DeviceA has registered with iMaster NCE-Campus.
    • iMaster NCE-Campus has delivered the PnP VLAN ID to DeviceA. The configuration file contains the pnp startup-vlan vlan-id command or DeviceA has obtained the PnP VLAN ID through negotiation with its upstream device.
    • iMaster NCE-Campus has delivered the configuration of enabling the function of transmitting the PnP VLAN to downstream devices to DeviceA, and the configuration file contains the pnp startup-vlan send enable command.
    • The interface of DeviceA has been enabled to send PnP VLAN information to downstream devices. After DeviceA is enabled through iMaster NCE-Campus to transmit PnP VLAN information to downstream devices, interfaces on DeviceA are enabled to transmit PnP VLAN information to downstream devices by default. If the pnp startup-vlan send disable or pnp disable command exists in the interface configuration file, the function of transmitting PnP VLAN information to downstream devices is disabled on the interface. In this case, you can enable the function through iMaster NCE-Campus.
  • If the default management VLAN is changed on iMaster NCE-Campus, iMaster NCE-Campus needs to notify the downstream device of the new VLAN.

    On a campus network shown in Figure 2, when the management VLAN of iMaster NCE-Campus is changed from the default VLAN 1 to another VLAN, the core device needs to notify the downstream device of the new VLAN. In this case, you need to configure the PnP VLAN auto-negotiation function on the core device. If the core device is managed by iMaster NCE-Campus, you can configure it through the controller. If core devices are not managed by iMaster NCE-Campus, access devices and aggregation devices can be managed by iMaster NCE-Campus. In this case, you need to manually configure the core device.

Procedure

  1. Enter the system view.

    system-view

  2. Configure a wired PnP VLAN ID.

    pnp startup-vlan vlan-id

    By default, no wired PnP VLAN ID is configured on a device.

  3. (Optional) Configure the wireless PnP VLAN ID.

    pnp wireless startup-vlan vlan-id

    By default, no wireless PnP VLAN ID is configured on a device.

  4. Enable the device to transmit the PnP VLAN to a downstream device.

    pnp startup-vlan send enable
    • By default, a device is disabled from transmitting the PnP VLAN to its downstream device. After this function is enabled in the system view, each interface is enabled to transmit PnP VLAN information to downstream devices by default.
    • By default, a downstream device is enabled to receive the PnP VLAN negotiation packets sent by an upstream device.

  5. (Optional) If devices are connected through Eth-Trunk interfaces, enable the Eth-Trunk links to transmit PnP VLAN information to downstream devices.
    1. Enter the Eth-Trunk view.

      interface eth-trunk trunk-id

    2. Enable the Eth-Trunk link to transmit the PnP VLAN to downstream devices.

      pnp startup-link-aggregation send enable

      By default, a downstream device is enabled to receive the PnP VLAN negotiation packets sent by an upstream device.

      After PNP link aggregation is enabled, uplink interfaces of downstream devices automatically create Eth-Trunk 0 through the PNP mechanism and aggregate links into Eth-Trunk 0. Eth-Trunk 0 is not automatically deleted after being automatically created. The working mode of Eth-Trunk 0 is also automatically negotiated by the upstream device and cannot be manually changed. To manually change the working mode of Eth-Trunk 0, you need to first run the undo pnp startup-link-aggregation receive enable command to disable the PnP VLAN auto-negotiation function on the downstream device.

      If the downstream device starts to access the network with a non-empty configuration, you need to configure the management VLAN as the PnP VLAN in the system-view so that the device can go online.

      The device can only function as an upstream device and does not support the pnp startup-link-aggregation receive enable or undo pnp startup-link-aggregation receive enable command.

Follow-up Procedure

You can run the pnp startup-vlan send disable command in the interface view to disable an interface from transmitting the PnP VLAN to a downstream device.

You can run the pnp disable command in the interface view to disable PnP VLAN auto-negotiation.

You can run the display pnp trace command in the diagnostic view to check PnP VLAN auto-negotiation trace records.

You can run the reset pnp trace command in the user view to clear PnP VLAN auto-negotiation trace records.
