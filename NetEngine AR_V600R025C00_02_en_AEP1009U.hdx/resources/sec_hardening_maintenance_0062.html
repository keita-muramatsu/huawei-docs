Defense Against TCP SYN Flood Packets

Overview

A TCP SYN flood attack exploits the vulnerability of the TCP three-way handshake. As shown in Figure 1, during the TCP three-way handshake, when the receiver (target device) receives the initial SYN packet from the sender (attacker), it returns a SYN+ACK packet to the sender. The connection remains in a half-open state while the receiver waits for the final ACK packet from the sender. If the receiver does not receive the ACK packet, it retransmits a SYN+ACK packet to the sender. Finally, after several retransmission attempts, the receiver shuts down the session and then updates the session in memory. The period from the first SYN+ACK packet being sent to session teardown is approximately 30 seconds.

During this period, an attacker may send thousands of SYN packets to all open interfaces, and never responds to SYN+ACK packets from the receiver. This causes memory overloading on the receiver and prevents the receiver from accepting new connection requests. The receiver then disconnects all existing connections.

Figure 2 shows how the device defends against TCP SYN attacks. With TCP SYN flood attack defense enabled, the device rate-limits TCP SYN packets to ensure that system resources are not exhausted if an attack occurs.

Impact on the System

None

Procedure

  1. Enter the system view.

    system-view

  2. Enable defense against TCP SYN flood attacks.

    anti-attack tcp-syn enable

    You can also run the anti-attack enable command in the system view to enable attack defense against all attack packets, including TCP SYN flood attack packets.

  3. Configure the rate limit for TCP SYN packets.

    anti-attack tcp-syn car cir cir-num

Checking the Security Hardening Result

Run the display anti-attack statistics tcp-syn command to check statistics relating to defense against TCP SYN flood attacks.
