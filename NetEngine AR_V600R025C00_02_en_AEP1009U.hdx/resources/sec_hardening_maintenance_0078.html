GTSM

Overview

The Generalized TTL Security Mechanism (GTSM) is a protection mechanism based on the time to live (TTL) value. GTSM protects TCP/IP-based control plane protocols from CPU overload attacks by checking whether the TTL value in each IP packet header is within a pre-defined range and dropping invalid packets (with TTL values beyond the range).

GTSM can be enabled for OSPF, OSPFv3, BGP, BGP4+, and RIP.

  • If GTSM is disabled, protocol packets are directly sent to the control plane.
  • If GTSM is enabled:
    • If a packet matches the GTSM policy, its TTL value is checked. If the TTL value is within the pre-defined range, the packet is sent to the control plane. Otherwise, the packet is dropped.
    • If a packet does not match the GTSM policy, the default action is pass, and the packet is sent to the control plane. The default action can also be set to drop.

Impact on the System

After a GTSM policy is configured on a device, the device checks the TTL value of each protocol packet and drops the packets whose TTL values are not in the specified range.

Procedure

  • For details about how to configure GTSM for OSPF/OSPFv3, see OSPF/OSPFv3.
  • For details about how to configure GTSM for BGP/BGP4+, see BGP/BGP4+.
  • For details about how to configure GTSM for RIP, see RIP/RIPng.

Verifying the Security Hardening Result

Run the display gtsm statistics { slot-id | all } command to check the GTSM statistics on a specified board or all boards.
