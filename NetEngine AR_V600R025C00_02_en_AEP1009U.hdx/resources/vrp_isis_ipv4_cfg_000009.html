IS-IS NSR

Context

As networks develop, the demand for data, audio, and video services is growing, which imposes increasingly high requirements on IP network reliability. If a network node fails, or a master/slave main control board switchover is performed on a device during maintenance, routes may fail to converge, which results in traffic loss or even a network breakdown. Non-stop routing (NSR) can address this problem and ensure uninterrupted forwarding of critical services.

Related Concepts

High availability (HA): supports data backup between the master and slave main control boards.

Non-stop forwarding (NSF): enables a node to use the graceful restart (GR) mechanism to ensure uninterrupted forwarding during a master/slave main control board switchover.

NSR: allows a standby control plane to take over traffic if the active control plane fails, while the control planes of neighbors remain unaware of the local fault. NSR ensures that neighbor relationships, signaling protocol connections, and sessions of the protocols that are used to meet service requirements are not interrupted in such a scenario.

Implementation

With IS-IS NSR, IS-IS real-time data is synchronized between the master and slave main control boards. If a master/slave main control board switchover is performed on a device due to a fault, the new master main control board immediately takes over services from the original master main control board, while neighbors remain unaware of the local fault. In addition, the new master main control board immediately restores IS-IS based on the synchronized IS-IS real-time data. Therefore, neighbors are also unaware of the master/slave main control board switchover. IS-IS NSR requires synchronization of the following data:

  • All configuration data, such as information about neighbors, timer parameters, and process configurations.

  • Dynamic data, such as interface parameters and states, as well as neighbor and LSDB information.

    NSR is enabled by default.
