Example for Configuring USB-based Deployment (Unconfigured Device Scenario)

Networking Requirements

A new network needs to be deployed. DeviceA and DeviceB are two unconfigured devices, and the customer requires that they automatically load system software and configuration files after they are powered on to reduce labor costs and deployment time. Table 1 lists device information and files to be loaded to DeviceA and DeviceB.

Table 1 Device information and files to be loaded

New Device

Device ESN

Files to Be Loaded

DeviceA

2102311LDL0000000806

  • System software: software_file.cc

  • Configuration file: conf_file1.cfg

DeviceB

2102311LDL0000000918

  • System software: software_file.cc

  • Configuration file: conf_file2.cfg

Configuration Roadmap

The configuration roadmap is as follows:

  1. Make the intermediate file usb.ini to enable the devices to obtain their system software and configuration files according to the intermediate file.
  2. Save the intermediate file to the root directory of the USB flash drive and system software and configuration files to the directory specified by the DIRECTORY field in the intermediate file.
  3. Insert the USB flash drive into the devices and power them on.

Precautions

The file system format of a USB flash drive must be FAT32 or EXT4, and its port must support USB 2.0 or later.

The following uses Windows as an example to describe how to check the file system format of a USB flash drive:

  • After inserting the USB flash drive, open This PC, right-click the USB flash drive, and choose Properties from the shortcut menu.
  • In the displayed dialog box, check File system, which indicates the format of the USB flash drive.

If the file system format of the USB flash drive does not meet the requirements, perform the following steps to change the file system format of the USB flash drive to FAT32:

  • After inserting the USB flash drive, open This PC, right-click the USB flash drive, and choose Format from the shortcut menu.
  • In the dialog box that is displayed, set File system to FAT32, select Quick format, and click OK.

Procedure

  1. Make the intermediate file according to the requirements in Intermediate File in the INI Format or Intermediate File in Python Format. The intermediate file in .ini format is used as an example. The file name is usb.ini. The file format is as follows:

    ;BEGIN USB
[GLOBAL CONFIG]
*TIME_SN=20200526120159 
*DEVICE_TYPE_NUM=2

[DEVICE_TYPE_1 DESCRIPTION]
DEVICE_TYPE=
ESN=2102311LDL0000000806
MAC=
UNAME=
VRPVER=
SPACE_CLEAR=1
DIRECTORY=
ACTIVE_DELAYTIME=10
ACTIVE_INTIME=
*FILETYPENUM=2
*FILENAME_1=software_file.cc
*TYPE_1=SOFTWARE
*EFFECTIVE_MODE_1=0
ISBATCHPROCESS_1=0
SHA256_1=
HMAC_1=
COMPRESS_ENCRYTION_1=
*FILENAME_2=conf_file1.cfg
*TYPE_2=CFG
*EFFECTIVE_MODE_2=0
ISBATCHPROCESS_2=0
SHA256_2=
HMAC_2=
COMPRESS_ENCRYTION_2=

[DEVICE_TYPE_2 DESCRIPTION]
DEVICE_TYPE=
ESN=2102311LDL0000000918
MAC=
UNAME=
VRPVER=
SPACE_CLEAR=1
DIRECTORY=
ACTIVE_DELAYTIME=10
ACTIVE_INTIME=
*FILETYPENUM=2
*FILENAME_1=software_file.cc
*TYPE_1=SOFTWARE
*EFFECTIVE_MODE_1=0
ISBATCHPROCESS_1=0
SHA256_1=
HMAC_1=
COMPRESS_ENCRYTION_1=
*FILENAME_2=conf_file2.cfg
*TYPE_2=CFG
*EFFECTIVE_MODE_2=0
ISBATCHPROCESS_2=0
SHA256_2=
HMAC_2=
COMPRESS_ENCRYTION_2=
;END USB CONFIG

  2. Save the intermediate file, system software, and configuration files to the root directory of the USB flash drive.
  3. Insert the USB flash drive to DeviceA and power on the device.
  4. Observe the USB indicator on the device to determine the USB-based deployment progress.
    • Blinking green: USB-based deployment is in progress.
    • Steady green: USB-based deployment succeeds. If there is no deployment configuration file, deployment will be repeatedly performed. In this case, the indicator is also steady green.
    • Steady red: USB-based deployment fails.
    • Off: No USB flash drive is connected, or the indicator fails.
  5. If the USB indicator on DeviceA is steady green, DeviceA is successfully deployed. In this case, remove the USB flash drive and insert it to DeviceB. Then power on DeviceB to start automatic deployment.
