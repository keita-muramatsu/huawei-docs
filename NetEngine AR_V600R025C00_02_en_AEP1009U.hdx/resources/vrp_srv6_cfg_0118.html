(Optional) Configuring a Metric for an SRv6 TE Policy

This section describes how to configure a metric for an SRv6 TE Policy so that the ingress can select the optimal SRv6 TE Policy based on the metric configuration.

Context

By default, the metric of an SRv6 TE Policy is 0, and it is irrelevant to the cost of the IGP route on which the SRv6 TE Policy depends. As a result, the ingress cannot select the optimal SRv6 TE Policy based on the path metric. To address this issue, you can configure SRv6 TE Policies to inherit metrics. Alternatively, directly configure metrics for SRv6 TE Policies.

Metric inheritance configuration for SRv6 TE Policies:
  • By default, SRv6 TE Policies do not inherit metrics.
  • Metric inheritance can be configured in both the SRv6 and SRv6 TE Policy views. If this is the case, the configuration in the SRv6 TE Policy view takes effect.
  • The metric that can be inherited can be an IGP, TE, or delay metric. If metric inheritance is not configured for a specified SRv6 TE Policy, the metric of the SRv6 TE Policy is 0.

After metric inheritance is configured for an SRv6 TE Policy, the priorities for metrics to take effect are described as follows (in descending order):
  1. The configured static metric of the specified type takes effect.
  2. The metric of the specified type for the primary candidate path delivered by the controller takes effect.
  3. If the primary candidate path delivered by the controller does not have a metric of the specified type:
    • If the primary candidate path consists of only one segment list, the metric of the specified type for the segment list takes effect.
    • If the primary candidate path consists of multiple segment lists, the maximum metric of the specified type among all the segment lists that are up takes effect.
  4. If IGP metric inheritance is enabled, the cost of the route to the endpoint of the involved SRv6 TE Policy takes effect with the lowest priority.

Procedure

  1. Enter the system view.

    system-view

  2. Enable SRv6 and enter the SRv6 view.

    segment-routing ipv6

  3. Enable metric inheritance.

    Perform either of the following steps as needed:

    • Enable metric inheritance for all SRv6 TE Policies.
      srv6-te-policy metric { inherit-igp | inherit-te | inherit-delay }
    • Enable metric inheritance for a specified SRv6 TE Policy.
      1. Create an SRv6 TE Policy and enter the SRv6 TE Policy view.
        srv6-te policy name-value  [ endpoint endpoint-ip color color-value ]
      2. Enable metric inheritance for the SRv6 TE Policy.
        metric { inherit-igp | inherit-te | inherit-delay }
      3. Return to the SRv6 view.
        quit

      If metric inheritance is configured in both the SRv6 and SRv6 TE Policy views:

      • The configuration in the SRv6 TE Policy view takes effect preferentially.
      • You can run the metric inherit-disable command to disable metric inheritance for the specified SRv6 TE Policy.

  4. Create an SRv6 TE Policy and enter the SRv6 TE Policy view.

    srv6-te policy name-value  [ endpoint endpoint-ip color color-value ]

  5. Configure a metric for the SRv6 TE Policy.

    • Configure an IGP metric for the SRv6 TE Policy.
      igp metric absolute absoluteValue
    • Configure a TE metric for the SRv6 TE Policy.
      te metric absolute absoluteValue
    • Configure a delay metric for the SRv6 TE Policy.
      delay metric absolute absoluteValue

    The type of the metric configured for an SRv6 TE Policy must be the same as that of the metric to be inherited. Otherwise, the configured metric does not take effect.

    If metric inheritance is not enabled, the SRv6 TE Policy metric reported to the tunnel management module is 0.
