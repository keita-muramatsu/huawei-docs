Understanding ASE

Packet Processing of ASE

If a content security-related service is configured in a traffic matching policy, packets need to be sent to the ASE for content security detection and processing.

Figure 1 shows the processes involved in content security detection and processing.
Figure 1 Packet processing of ASE
  1. After service packets are sent to the ASE, it must first reassemble fragments and flows to ensure that the packets processed by subsequent service modules are sequential and do not overlap.
  2. After identifying the protocol, the device performs in-depth protocol decoding. In this phase, the fields or files required by the subsequent content security services are parsed in a batch, significantly improving the detection efficiency.
  3. The device performs the corresponding processing based on the configured content security services. Various services have different detection objects. For example, the antivirus service detects files, and the URL filtering service detects URLs. As such, service processing does not follow a strict sequence. This figure shows only the general service categories.

    As for TCP traffic, if the handling action of the content security service is block, the device sends RST packets to the client or server through the ASE to disconnect TCP connections to block the traffic.

ASE Features

Table 1 lists the features supported by the ASE.

Table 1 ASE features

Feature

Description

IPS

IPS is a security mechanism that detects intrusion behavior based on the attack signature database and takes certain response measures to terminate the intrusion in real time.

URL filtering

URL filtering controls the URL access requests of users and permits or denies user access to certain web page resources to regulate web access behavior.

Antivirus

Antivirus is a security mechanism that detects and processes malware files based on malware signatures. It prevents data corruption, permission changes, and system crashes caused by malware files, ensuring network security.
