Data Fails to Be Forwarded Along the RPT on a PIM-SM Network

Symptom

After a PIM-SM network in the ASM model is configured, user hosts cannot receive multicast data.

Possible Causes

Possible causes are as follows:

  • The unicast routes from multicast devices to the RP are unavailable.
  • The RP addresses of multicast devices are inconsistent.
  • The downstream interfaces of multicast devices do not receive any (*, G) Join messages.
  • PIM-SM is not enabled on interfaces.
  • The RPF route to the RP is incorrect (for example, the unicast route has a loop).
  • Configurations are improper (for example, the configuration of the MTU or multicast boundary is improper).

Procedure

  1. Run the display pim routing-table group-address command in any view to check whether the PIM routing table contains correct (*, G) entries.

    If no correct (*, G) entry exists in the PIM routing table, go to Step 2.

    If the correct (*, G) entry exists in the PIM routing table, run the display multicast ip fib group group-address command every 15 seconds to check whether the (S, G) entry corresponding to the (*, G) entry exists in the forwarding table and whether the value of the Matched field increases.

    • If the forwarding table contains the (S, G) entry and the value of the Matched field keeps increasing, data can be forwarded from the upstream device to the current device but cannot be forwarded to the downstream device due to certain reasons. In this case, check whether the TTL value is too small or a forwarding failure occurs.
    • If the forwarding table does not contain the (S, G) entry or the value of the Matched field does not increase:
      • If the current device is not an RP, it has not received any multicast data. In this case, the upstream device may be faulty. Check whether the PIM routing table on the upstream device contains the correct (S, G) entry.
      • If the current device is an RP, the RPT has been established successfully but the RP is unable to receive multicast data from the multicast source. One possible cause is that the source DR fails to be registered.
  2. Run the display pim control-message counters interface [ interface-name | interface-type interface-number ] message-type join-prune command in any view to check whether the downstream interface of the upstream device receives Join messages.

    • If the number of Join/Prune messages received by the downstream interface of the device does not increase, run the display pim control-message counters interface [ interface-name | interface-type interface-number ] message-type join-prune command on the downstream neighbor to check whether the downstream neighbor has sent Join/Prune messages to the upstream device.
      • If the number of Join/Prune messages increases, the downstream device has sent Join/Prune messages. In this case, communication between the PIM neighbors is abnormal.
      • If the number does not increase, the downstream device is not working properly. In this case, troubleshoot the downstream device.
    • If the number of Join/Prune messages received by the downstream interface increases, go to Step 3.

  3. Run the display pim interface [ interface-name | interface-type interface-number | up | down ] [ verbose ] command in any view to check whether PIM-SM is enabled on the interface.

    The common cause for the fault is that PIM-SM is not enabled on the following interfaces:
    • RPF neighbor interface to the RP
    • RPF interface to the RP
    • Interface directly connected to the subnet of user hosts (downstream interface of the receiver DR)

    Therefore, when checking PIM information, check whether PIM-SM is enabled on the preceding interfaces.
    • If PIM-SM is not enabled, enable PIM-SM on the interfaces. If the message "Error: Please enable multicast in the system view first." is displayed when you enable PIM-SM, run the multicast routing-enable command in the system view to enable multicast first.
    • If PIM-SM has been enabled on all the involved interfaces of the device, go to Step 4.

  4. Run the display pim vpn-instance vpn-instance-name rp-info [ group-address ] command in any view to check whether the device has learned information about the RP serving a multicast group and whether the learned RP information is the same as that on all other devices.

    • If no RP information exists on the device or RP information on the device is different from that on other devices, and a static RP is used on the network, run the static-rp command on the involved devices to configure the same RP address for the multicast group.
    • If RP information of a specific multicast group is consistent on all the devices, go to Step 5.

  5. Run the display multicast rpf-info source-address command in any view to check whether there is a reachable RPF route to the RP.

    • If the command output does not contain an RPF route to the RP, check the unicast route configuration: Run the ping command on both the involved device and RP to check the connectivity between them.
    • If the command output contains an RPF route to the RP:
      • If the RPF route is a multicast static route in the command output, run the display current-configuration command to check whether the multicast static route configuration is correct.
      • If the RPF route is a unicast route in the command output, run the display ip routing-table command to check whether the unicast route is consistent with the RPF route.
    • If the command output contains an RPF route to the RP and the configuration of the route is correct, go to Step 6.

  6. Run the display pim interface interface-type interface-number command in any view to check whether the interface forwarding multicast data is the receiver DR.

    • If the command output does not contain the local flag, the interface is not the receiver DR. In this case, perform Step 7 on the DR according to the DR address in the command output.
    • If the command output contains the local flag, the interface is the receiver DR. In this case, go to Step 7.

  7. Run the display current-configuration interface interface-type interface-number command in the user view to check whether the multicast boundary is configured on the interface.

    • If multicast boundary is displayed in the configuration of the interface, multicast boundary is configured on the interface. In this case, you are advised to run the undo multicast boundary { group-address { mask | mask-length } | all } command to delete the configuration or replan the network to ensure that no multicast boundary is configured on the RPF interface or the RPF neighbor interface.
    • If multicast boundary is not configured on the interface, go to Step 8.

  8. Run the display current-configuration configuration pim command in the PIM view to check whether the source-policy is configured.

    If the command output contains source-policy acl-number or source-policy acl-name, a source-based filtering policy is configured. Any multicast data that is not permitted by the ACL is then discarded. In this case, run the undo source-policy command to delete the configuration or configure a new ACL rule to permit the multicast data requested by the user hosts.
