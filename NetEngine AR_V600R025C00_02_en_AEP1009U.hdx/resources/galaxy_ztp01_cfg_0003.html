Understanding ZTP

ZTP includes multiple deployment modes, which are applicable to different scenarios, as described in Table 1. You can select a proper deployment mode as required.

Table 1 ZTP methods

Deployment Method

Fundamentals

Email-based deployment

Email-based deployment requires only simple operations on the web UI, lowering requirements on deployment personnel. This method applies to large-scale network site deployment scenarios. The network administrator configures a deployment email on iMaster NCE-Campus and sends the email to the deployment person's mailbox. After a device is delivered to the site, the deployment person powers on the device, connects the device to a deployment terminal such as a laptop, and clicks the URL in the deployment email to start the deployment process. After the device registers with the controller, the controller delivers configurations to the device, which then automatically completes deployment.

USB-based deployment

USB-based deployment is simple and has low skill requirements on deployment personnel. This method is applicable to batch deployment in warehouses. An engineer makes an intermediate file on a terminal in advance and saves the intermediate file and deployment files to the USB flash drive. During deployment, a deployment person powers on the device and inserts the USB flash drive into the device, which then automatically completes the deployment.

Streamlined USB-based deployment

NOTE:

For details about the supported models, see "Version Requirements" in SD-WAN Solution & iMaster NCE-Campus Product Documentation.

Streamlined USB-based deployment can be used only in the SD-WAN solution. A network administrator configures ZTP deployment parameters on iMaster NCE-Campus in advance. After deployment files are automatically generated, the network administrator saves the deployment files to the USB flash drive. During the deployment, a deployment person powers on the device and inserts the USB flash drive into the device, which then automatically completes the deployment.

Intermediate file-based deployment (without a controller)

In intermediate file-based deployment, only the DHCP server and file server need to be deployed. This method applies to batch deployment of devices without a controller. An engineer deploys the DHCP server and file server, and makes an intermediate file on a terminal such as a PC in advance. After a deployment person powers on a device, the device obtains the intermediate file information from the DHCP Option parameters and then obtains the deployment file information from the intermediate file. Then the device automatically completes deployment based on the deployment file information.

DHCP-based deployment (with a controller)

This deployment method simplifies device registration and onboarding, and therefore applies to the scenario where devices register with and go online on a controller in batches. After a deployment person powers on and starts a device, the device obtains the address of iMaster NCE-Campus from DHCP Option parameters and registers with the controller, which then delivers deployment configurations to the device. Then the device automatically completes deployment.

Registration query center-based deployment

Registration query center-based deployment applies to the scenario where iMaster NCE-Campus can connect to the Huawei registration query center, such as the Huawei public cloud, Managed Service Provider (MSP)-owned cloud, and on-premises scenarios. Devices are preconfigured with the domain name of the registration query center. After a deployment person powers on and starts a device, the device establishes a connection with the registration query center, obtains the address of iMaster NCE-Campus, and registers with the controller, which then delivers deployment configurations to the device. Then the device automatically completes deployment.

SZTP deployment

Secure Zero Touch Provisioning (SZTP) requires the deployment of a dedicated bootstrap server, a DHCP server, and a file server. This method applies to deployment scenarios that require high security. A customer deploys a dedicated bootstrap server, a DHCP server, and a file server. After a deployment person powers on and starts the device, the device obtains the bootstrap server address from DHCP Option parameters, establishes a trusted connection with the bootstrap server through two-way authentication, and obtains deployment file information. Then the device automatically completes deployment based on the deployment file information.

Compared with intermediate file-based deployment, SZTP ensures higher data reliability but is more complex.
