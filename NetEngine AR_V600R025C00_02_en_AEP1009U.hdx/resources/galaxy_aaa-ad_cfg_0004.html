AD Packets

AD authentication is an integration of LDAP and Kerberos authentications; therefore, AD packets are classified into Kerberos and LDAP packets. For details about LDAP packets, see LDAP Packets.

Kerberos Packet Format

Kerberos uses KDC-REQ and KDC-REP packets:
  • KDC-REQ includes authentication request packet (AS-REQ) and ticket request packet (TGS-REQ).
  • KDC-REP includes authentication response packet (AS-REP) and ticket response packet (TGS-REP).
Table 1 lists the Kerberos packet types.
Table 1 Kerberos packets

Packet

Description

AS-REQ

This is the first packet transmitted in a Kerberos packet exchange process. This packet carries user authentication information, such as user name and password. An AS-REQ is sent from a Kerberos client to an AS server. The AS server determines whether a user is allowed to access the network according to the user information carried in this packet.

AS-REP

This packet is sent by an AS server in response to the AS-REQ sent by a Kerberos client. If all attributes in the AS-REQ are acceptable, the server considers the authentication successful and sends this packet. After the client receives this packet, the user passes the authentication.

TGS-REQ

This packet is sent by a Kerberos client to a TGS server to request for a network service ticket.

TGS-REP

This packet is sent by a TGS server in response to the TGS-REQ.
Kerberos packets include KDC-REQ and KDC-REP.

    Table 3 Description of each field in a KDC-REP

    Field

    Description

    Pvno

    Kerberos protocol version. Currently, version 5 is supported.

    MSG Type

    Enc-part rc4-hmac(2)
    • AS-REP: Encrypted content includes the ticket used to access the TGS server and the session key used by the client and TGS server. The content is encrypted by using the shared key between AS and TGS.
    • TGS-REP: Encrypted content includes the ticket used to access the AD server and the session key used by the client and AD server. The content is encrypted by using the AD server password.

LDAP Packet Format

The LDAP packet format in AD authentication is the same as LDAP Packets in LDAP authentication. However, AD authentication encapsulates the session key and ticket returned by TGS-REP into the authentication field in a user bind request packet, but the authentication field in LDAP authentication is in plain text. Table 4 Description of fields in user bind request packets

Field

Description

LDAP Header

LDAP packet header, including the packet data type and data total length.

messageID

Message ID. A server identifies request packets sent by clients according to the message IDs and correctly returns response packets.

protocolOp

Packet body, which carries packet type and authentication as well authorization information. The current packet type is bindRequest(0).

version

LDAP protocol version. Currently, version 3 is supported.

name

LDAP DN. The name in a user bind request packet is user DN.

authentication
Authentication and encryption method:
  • simple: plain text (no encryption), used in the user bind request packet for LDAP authentication.
  • sasl: encryption through Kerberos, used in the user bind request packet for AD authentication.

Pvno

Kerberos protocol version.

MSG Type
Packet type:
  • 10: AS-REQ
  • 12: TGS-REQ

Ticket

Authorization ticket returned by the Kerberos server to the client. The ticket contains the session key, server name, server realm, and time.

Authenticator

The user name, password, and time in the authenticator are encrypted by using the session key.

Session key

Key used to encrypt sessions between client and server. The session key is generated by the Kerberos server.
