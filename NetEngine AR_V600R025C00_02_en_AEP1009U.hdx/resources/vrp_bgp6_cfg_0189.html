Configuring BGP4+ Graceful Degradation

BGP4+ can be enabled to discard newly received routes when the device memory is in the danger state and reset the corresponding process if the device memory remains in the danger state for a long time.

Prerequisites

Before configuring BGP4+ graceful degradation, you have completed the following task:

  • Configure basic BGP4+ functions.

  • Run the memory-usage reliability switch on command to enable memory overload reliability.

Context

Based on the device memory usage, the device memory states are classified as follows:

  1. Warning state: state when the device memory usage exceeds the warning threshold (also called the notification threshold). The default warning threshold is 70%, indicating that the device enters the warning state when the device memory usage exceeds 70%. You can set this threshold using the notice-threshold notice-threshold-value in the memory-usage reliability command.
  2. Danger state: state when the device memory usage exceeds the danger threshold (also called the overload threshold). The default danger threshold is 85%, indicating that the device enters the danger state when the device memory usage exceeds 85%. You can set this threshold using the overload-threshold overload-threshold-value in the memory-usage reliability command.
  3. Exception state: state when the device memory usage exceeds the exception threshold. The default exception threshold is 90%, indicating that the device enters the exception state when the device memory usage exceeds 90%. You can set this threshold using the exception-threshold exception-threshold-value in the memory-usage reliability command.

If BGP4+ keeps receiving new routes when the device memory is in the danger state, the device memory may be exhausted. As a result, the process or board is reset, or even the device is restarted. To solve this problem, you can configure the device to discard the routes newly received from IPv4, IPv6, VPNv4, VPNv6, and EVPN peers and the routes leaked from VPNv4, VPNv6, and EVPN address families to VPN instances in this case.

If BGP4+ has discarded newly received routes when the device memory is in the danger state but the device memory still remains in the danger state for a long time, you can enable BGP4+ to tear down peer relationships and reset the corresponding process to try to escape from the danger state.

To prevent key services from being interrupted, you can configure the device not to tear down peer relationships when the device memory is in the danger state.

Procedure

  1. Enter the system view.

    system-view

  2. Configure BGP4+ to process routes received from peers even when the device memory is in the danger state.
    • Configure BGP4+ to discard the following routes when the device memory is in the danger state: the routes newly received from peers, the routes newly leaked from the VPNv4, VPNv6, and EVPN address families to VPN instances, and the routes advertised by VPN instances to the VPNv4, VPNv6, and EVPN address families.
      bgp memory-usage danger-threshold discard new-route include { vrf-import-route | vrf-export-route }*
    • Configure BGP4+ to process the routes newly received from peers even when the device memory is in the danger state.
      bgp memory-usage danger-threshold discard new-route

    Configuring the bgp memory-usage danger-threshold discard new-route command may affect route learning and compromise services. Therefore, exercise caution when running this command.

  3. Configure the device to tear down peer relationships if the device memory remains in the danger state for a specified period and the memory usage of the BGP component ranks in the top 3, and to reset the BGP process if the danger state persists and the memory usage of the BGP component still ranks in the top 3 after the peer relationships are torn down.

    bgp memory-usage danger-threshold escape timeout time [ minute ]

    Configuring the bgp memory-usage danger-threshold escape timeout time [ minute ] command may interrupt services such as IGP and route management services. Therefore, exercise caution when running this command. You can run the bgp memory-usage danger-threshold escape disable command to disable BGP4+ from attempting to escape from the danger state when the device memory is in the danger state.

  4. (Optional) Configure the device not to establish peer relationships with the BGP peers that fail to go up within a specified period when the device memory is in the danger state.

    bgp memory-usage danger-threshold not-allow-connect [ escape time time-value ]

    By default, when the device memory is in the danger state and the memory usage of the BGP component ranks in the top 3, the device does not establish peer relationships with the BGP peers that fail to go up within 72 hours.

  5. (Optional) Configure the device not to tear down specified peer relationships when the device memory is in the danger state.
    1. Enter the BGP view.

      bgp as-number

    2. Configure the device not to tear down specified peer relationships when the device memory is in danger state. This prevents key services from being affected.

      peer { peerIpv6Addr | groupName } low-memory exempt

    3. Enter the system view.

      quit

  6. (Optional) Configure route rejection exemption that takes effect when the device memory is in the danger state.
    1. Enter the BGP view.

      bgp as-number

    2. Enter the BGP-IPv6 unicast address family view.

      ipv6-family unicast

    3. Configure the device to accept only the routes that match the specified IPv6 prefix list when the device memory is in the danger state.

      prefix low-memory exempt ipv6-prefix prefix6-filter-name

      When the device memory is in the danger state, the routes received from BGP peers are rejected. To restore the rejected routes after the prefix low-memory exempt ipv6-prefix command is run, run the refresh bgp ipv6 command.

    4. Enter the BGP view.

      quit

    5. Enter the system view.

      quit
