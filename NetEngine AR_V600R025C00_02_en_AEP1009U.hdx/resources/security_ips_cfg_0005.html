Intrusion Prevention Signatures

Intrusion prevention signatures describe the characteristics of network intrusion behaviors. The core of intrusion prevention is to compare packet content with signatures to detect intrusion behaviors.

Predefined Signatures

The Huawei security center (isecurity.huawei.com) on the cloud provides an intrusion prevention signature database that contains signatures for various known intrusion behaviors. These signatures are called predefined signatures. You need to download the latest signature database to the device to ensure that the device has the latest intrusion prevention capability.

Table 1 Predefined signature

Item

Description

ID

Unique identifier of a signature.

Status

Whether a signature is enabled. The device can detect only attacks corresponding to enabled signatures.

Target

Role of the attack target. The options are as follows:

  • Server: The attack is initiated against a server.
  • Client: The attack is initiated against a client.

Severity

Severity of the attack result. The value can be high, medium, low, or informational.

OS

Operating system at which the attack is targeted.

Protocol

Type of the protocol used by the attack behavior.

Category

Type of the attack behavior, for example, a Trojan horse, worm, injection attack, or overflow attack.

Action

Action taken on the attack packets that match corresponding signatures. The options are as follows:

  • Alert: The device allows the packets to pass through and records logs.
  • Block: The device discards the packets and records logs.

Reference

Other reference information, including the vulnerability ID assigned by a vulnerability authority and website providing vulnerability introduction. For example, CVE identifiers are used as vulnerability IDs in Common Vulnerabilities and Exposures.

User-defined Signatures

You are advised to configure user-defined signatures only when you understand the attack features. Incorrect signatures may be useless, cause packet loss, or interrupt services.

User-defined signatures are created by the administrator according to the characteristics of intrusion behaviors. Generally, there is a lag between the occurrence of a new intrusion and the update of the corresponding attack signature to the predefined signature database. To defend against intrusions in real time, the administrator can create user-defined signatures after in-depth intrusion feature analysis. After the predefined signature database is updated, the user-defined signatures take effect. In addition, the administrator can create a user-defined signature with the block action based on packet behavior characteristics to block a specific behavior (which may not be an intrusion behavior) for a certain reason.

After user-defined signatures are created, the system automatically checks the validity and regular expressions of the corresponding rules to prevent inefficient signatures from wasting resources.
