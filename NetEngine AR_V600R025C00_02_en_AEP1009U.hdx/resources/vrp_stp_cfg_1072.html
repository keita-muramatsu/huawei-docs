Topology Change Mechanism

When the network topology changes, for example, if a link fails or a port goes down, the upstream device may continuously send BPDUs through an unreachable link if the device is not immediately informed of any changes. This is caused by the aging delay of MAC addresses, which is 5 min by default. Taking the devices in Figure 1 as an example, normally, when the link between DeviceA and DeviceB is blocked, the traffic from DeviceA to DeviceB passes through DeviceA, DeviceC, DeviceD, and DeviceB in that sequence. If the link between DeviceC and DeviceD fails, DeviceA needs to directly forward the traffic to DeviceB. However, DeviceA still has a MAC address entry with an outbound interface connected to DeviceC, and so the traffic is sent to DeviceC before the MAC address entry ages. This can cause traffic loss, and therefore requires a mechanism that can immediately inform the entire network of the topology change.

Figure 2 TCN BPDU transmission and TC flooding after a topology change
  1. When the status of the interface at point T changes, a downstream device continuously sends TCN BPDUs to the upstream device to inform both the upstream device and root bridge of topology changes.
  2. The upstream device processes only the TCN BPDUs received on the designated port and drops TCN BPDUs received on other ports.
  3. The upstream device sets the TCA bit of the Flags field in the configuration BPDUs to 1 and returns the configuration BPDUs to instruct the downstream device to stop sending TCN BPDUs.
  4. The upstream device sends a copy of the TCN BPDUs toward the root bridge.
  5. Steps 1, 2, 3 and 4 are repeated until the root bridge receives the TCN BPDUs.
  6. The root bridge sets the TC and TCA bits of the Flags field in the configuration BPDUs to 1. The TC bit is set to 1 to inform the downstream device of the topology changes and instruct the downstream device to delete the specific MAC address entry. Then the TCA bit is set to 1 to instruct the downstream device to stop sending TCN BPDUs.
  • TCN BPDUs are sent to inform upstream devices and the root bridge that the topology changes.
  • Configuration BPDUs with specific TCA bits are sent to inform the downstream device that the topology changes are known and instruct the downstream device to stop sending TCN BPDUs.
  • Configuration BPDUs with specific TC bits are sent to inform the downstream device that the topology changes and instruct the downstream device to delete MAC address entries, thereby achieving fast network convergence.

RSTP considers that the network topology changes only when a non-edge port transitions to the Forwarding state.

When detecting a topology change, RSTP devices react in the following ways:

  • On the device with changed port states: On each non-edge designated port and the root port, the device starts a TC While timer, which is twice the value of the Hello timer.

    Within the TC While timer, the device clears MAC address entries learned on ports whose states have changed and sends out RST BPDUs with the TC bit set to 1 from these ports. When the TC While timer expires, the device stops sending RST BPDUs immediately.

  • On other devices: When other devices receive RST BPDUs, they clear MAC address entries learned on all their ports except those that receive the RST BPDUs. These devices also start a TC While timer on the root port and each non-edge designated port, and then send out RST BPDUs with the TC bit set to 1 from these ports. When the TC While timer expires, the devices stop sending RST BPDUs immediately.

RST BPDUs are then flooded throughout the entire network.
