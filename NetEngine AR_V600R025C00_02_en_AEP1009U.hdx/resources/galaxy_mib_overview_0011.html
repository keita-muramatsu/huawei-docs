MIB-related Concepts

MIB Objects and Nodes

In Figure 1, IF-MIB is used as an example. A MIB tree contains table objects, row objects, and column objects. A table object consists of row objects, and a row object consists of a series of column objects.

Nodes in a MIB tree can be leaf or non-leaf:

  • Leaf node

    A leaf node is a node that does not have any sub-nodes in the complete MIB tree. Leaf nodes are classified into scalar nodes and table nodes.

  • Non-leaf node

    A non-leaf node reflects the association between the sub-nodes, and cannot be accessed using SNMP.

Figure 1 MIB nodes and objects

In specific MIB references, the row object "Entry" is often described as a prefix. For example, the description of "The OID prefix of this table is 1.3.6.1.2.1.2.2" in ifTable corresponds to ifEntry.

MIB Compliance Statement

A MIB compliance statement is used to describe how a feature module complies with the SNMP entity structure. A MIB compliance statement cannot be executed using SNMP syntax. In Figure 2, LLDP-MIB is used as an example. A MIB compliance statement consists of compliances and groups, which respectively indicate the number of MIB statements and the collection of objects that are used to configure the corresponding function.

Figure 2 MIB compliance statement

A MIB compliance statement describes how a feature module complies with the SNMP entity structure, and cannot be executed using SNMP syntax, so it is not included in MIB reference.

Maximum Access Permission

The maximum access permission on MIB nodes specifies the operations that can be performed on the MIB nodes, as described in Table 1. For details about the operations that can be performed on a specified MIB node, see the MIB node description.

Table 1 Maximum access permission

Maximum Access Permission

Description

Operation

not-accessible

Inaccessible

No operation can be performed.

read-only

Read only

Reads information.

read-write

Readable and writable
  • Reads information.
  • Modifies configurations.

read-create

Readable and creatable
  • Reads information.
  • Modifies configurations.
  • Adds configurations.
  • Deletes configurations.

accessible-for-notify

Notification only

It can only be used as a variable bound to traps.
