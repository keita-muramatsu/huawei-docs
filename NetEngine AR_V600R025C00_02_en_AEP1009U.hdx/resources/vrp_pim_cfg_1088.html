Example for Configuring BFD for IPv4 PIM

Networking Requirements

In multicast applications, if the current DR on a shared network segment is faulty, other PIM neighbors trigger a new round of DR election only after the neighbor relationship times out. As a result, multicast data transmission is interrupted. The interruption time (usually in seconds) is not shorter than the timeout time of the neighbor relationship. BFD can detect changes in the status of a link on a shared network segment within milliseconds, enabling a device to rapidly respond to PIM neighbor faults. By configuring BFD for IPv4 PIM and the DR switchover delay function together, when the current DR on the shared network segment fails, the interruption time of multicast data transmission is shortened, improving the reliability of multicast data transmission.

On the network shown in Figure 1, the downstream interface interface2 of DeviceC functions as the current DR and is responsible for forwarding multicast data to Receiver, and the host can receive VoD information from the multicast source. BFD for IPv4 PIM is deployed on the shared network segment where DeviceB and DeviceC reside. When the downstream interface interface2 of DeviceC fails, PIM can rapidly detect the fault and trigger DR election. The interface2 of DeviceB is immediately elected as the new DR and is responsible for forwarding multicast data. Then, multicast data is immediately switched to the new path. This shortens the period during which multicast data transmission is interrupted and improves the reliability of multicast data transmission. In addition, configure the DR switchover delay. Then, after the faulty DR on the network recovers, DR election is re-performed and the routing table is rebuilt. During this process, the interface maintains the original multicast forwarding entry to shorten the interruption period of multicast data transmission to the maximum extent.

In this example, interface1, interface2, and interface3 represent 10GE0/0/1, 10GE0/0/2, and 10GE0/0/3, respectively.

Figure 1 Networking diagram of configuring BFD for IPv4 PIM

To complete the configuration, you need the following data:

  • Multicast source (S) address: 10.1.7.1/24

  • Multicast group (G) address: 225.1.1.1/24

  • BFD parameters: minimum sending interval, minimum receiving interval, and local detection multiplier
  • DR switchover delay

Configuration Roadmap

The configuration roadmap is as follows:

  1. Configure IP addresses and a unicast routing protocol for interfaces on each device.

  2. Enable multicast on all devices that provide multicast services, enable PIM-SM on each interface, and enable IGMP on the interface connected to the host.

  3. Configure an RP on DeviceA.

  4. Enable BFD globally. Enable BFD for IPv4 PIM on the interface connecting the device to the network segment to which user hosts belong and configure BFD parameters.
  5. Set the PIM DR switchover delay on the interfaces connected to the network segments of user hosts.

Procedure

  1. Assign an IP address to each device interface and configure a unicast routing protocol. For detailed configurations, see Configuration Scripts.
  2. Enable multicast on each device, PIM-SM on each interface, and IGMP on the interfaces that connect the device to the host.

    # Configure DeviceC. The configurations of DeviceA and DeviceC are similar to the configuration of DeviceB. For detailed configurations, see Configuration Scripts.

    [DeviceB] multicast routing-enable
[DeviceB] interface 10GE 0/0/2
[DeviceB-10GE0/0/2] pim sm
[DeviceB-10GE0/0/2] igmp enable
[DeviceB-10GE0/0/2] quit
[DeviceB] interface 10GE 0/0/1
[DeviceB-10GE0/0/1] pim sm
[DeviceB-10GE0/0/1] quit

  3. Configure RPs.

    # Create a loopback interface on DeviceA and enable PIM-SM; configure the loopback interface to function as both a C-RP and C-BSR.

    [DeviceA] interface loopback 0
[DeviceA-Loopback0] ip address 1.1.1.1
[DeviceA-Loopback0] pim sm
[DeviceA-Loopback0] quit
[DeviceA] pim
[DeviceA-pim] c-bsr Loopback0
[DeviceA-pim] c-rp Loopback0
[DeviceA-pim] quit

  4. Enable BFD globally on DeviceB and DeviceC, enable BFD for IPv4 PIM on the device's interface connected to the user host network segment, and configure BFD parameters.

    # Configure DeviceB. The configuration of DeviceC is similar to the configuration of DeviceB. For detailed configurations, see Configuration Scripts.

    [DeviceB] bfd
[DeviceB-bfd] quit
[DeviceB] interface 10GE 0/0/2
[DeviceB-10GE0/0/2] pim bfd enable
[DeviceB-10GE0/0/2] pim bfd min-tx-interval 100 min-rx-interval 100 detect-multiplier 3

  5. Configure the DR switchover delay on the interfaces connecting DeviceB and DeviceC to the user host network segment.

    # Configure DeviceB. The configuration of DeviceC is similar to the configuration of DeviceB. For detailed configurations, see Configuration Scripts.

    [DeviceB-10GE0/0/2] pim timer dr-switch-delay 20
[DeviceB-10GE0/0/2] quit

Configuration Scripts

  • DeviceA

    #
sysname DeviceA
#
multicast routing-enable
#
interface 10GE0/0/1
 ip address 10.1.7.2 255.255.255.0
 pim sm
#
interface 10GE0/0/2
 ip address 10.1.2.2 255.255.255.0
 pim sm
#
interface 10GE0/0/3
 ip address 10.1.3.2 255.255.255.0
 pim sm
#
interface Loopback
 ip address 1.1.1.1 255.255.255.255
 pim sm
#
pim
 c-bsr Loopback0
 c-rp Loopback0
#
ospf 1
 area 0.0.0.0
  network 10.1.7.0 0.0.0.255
  network 10.1.2.0 0.0.0.255
  network 10.1.3.0 0.0.0.255
  network 1.1.1.1 0.0.0.0
#
return

  • DeviceB

    #
sysname DeviceB
#
multicast routing-enable
#
bfd
#

#

 ip address 10.1.1.1 255.255.255.0

 pim sm

 igmp enable

return
