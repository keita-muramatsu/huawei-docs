Verifying the Configuration

Context

Before deploying APs onsite, complete network planning operations, for example, configure the WAC and involved NEs, and add APs on the WAC. After APs are connected to the network and powered on fully, they can automatically upgrade and go online. No other configurations are required for the APs onsite.

You can check whether the APs go online on the WAC as planned. If the AP status displays nor (indicating normal), the APs are properly online.

Procedure

  • Run the display ap { all | ap-group ap-group | by-mac mac-address | by-sn sn | [ ap-group ap-group ] by-ssid ssid | by-state state [ ap-group ap-group ] } command to check the AP onboarding result.
  • Run the display ap unauthorized record command to check information about unauthorized APs.
  • Run the display ap online-fail-record { all | mac mac-address } command to check onboarding failure records of APs.
  • Run the display ap offline-record { all | mac mac-address } command to check going-offline records of APs.
  • Run the display ap global configuration command to check the AP global configuration.
  • Run the display ap config-info ap-id ap-id command to check the AP configuration.
  • Run the display ap-group { all | name group-name } command to check configuration and reference information about an AP group.
  • Run the display ap whitelist { mac | sn } command to check the AP whitelist.
  • Run the display ap blacklist command to check the AP blacklist.
  • Run the display ap-type attributes abnormal-check-record command to check the records of AP attribute check exceptions that occur when AP types are created.
  • Run the display ap-type { all | id type-id | type ap-type } command to check information about AP types.
