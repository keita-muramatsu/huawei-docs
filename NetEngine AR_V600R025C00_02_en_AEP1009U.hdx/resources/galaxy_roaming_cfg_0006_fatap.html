Fast Roaming Using PMK Caching

Overview

On a WLAN, the roaming handover time is one of the key factors affecting user experience. Especially in 802.1X authentication scenarios, the traditional roaming process requires reauthentication and key negotiation, which increases the roaming latency and may even interrupt services. To solve this problem, fast roaming using PMK caching is introduced. This roaming mode caches PMK information so that STAs do not need to perform 802.1X authentication again during roaming. Only key negotiation is required after roaming, which significantly shortens the roaming handover time and improves user experience.

This roaming mode requires the STA support and applies when one of the following security policies is used:

  • WPA2-802.1X
  • WPA2-WPA3-802.1X
  • WPA3-802.1X-AES
  • WPA3-802.1X-GCMP256
  • WPA-WPA2-802.1X (WPA2 specified on the 802.1X client)

Implementation of Fast Roaming Using PMK Caching

Using intra-WAC roaming as an example, Figure 1 shows the typical network diagram of fast roaming using PMK caching on the WAC.

  1. The STA accesses the network for the first time through AP_1. When the WAC authenticates the STA and a PMK is generated, the STA and WAC save the PMK information. Each PMK has a PMK-ID, which is calculated based on the PMK, SSID, STA MAC address, and BSSID.
  2. During roaming, the STA sends AP_2 a Reassociation Request packet that carries the PMK-ID.
  3. AP_2 receives the Reassociation Request packet and then notifies the WAC that the STA needs to roam from AP_1 to AP_2.
  4. The WAC searches the PMK caching table for the PMK of the STA according to the PMK-ID carried in the Reassociation Request packet. If a matching PMK is found, the WAC considers that 802.1X authentication has been performed on the STA and uses the cached PMK for key negotiation.
