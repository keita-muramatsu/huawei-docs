After a Source DR Sent a Register Message to an RP, the Registration Outbound Interface Was Not Deleted As Expected

Symptom

After a multicast network is configured, the multicast source sends multicast data to the source DR. After the source DR encapsulates multicast data in a Register message and sends the Register message to the RP, the registration outbound interface in the corresponding multicast entry is not deleted as expected. As a result, no SPT is established between the source DR and the RP.

Possible Causes

If the source DR does not receive the Register-Stop message from the RP, the source DR does not delete the registration outbound interface from the corresponding multicast entry. A common cause of this problem is a unicast route failure between the source DR and RP.

Procedure

  1. Check whether the source DR and the RP have a unicast route to each other and can ping each other.
    • If the source DR has no unicast route to the RP or cannot ping the RP, the RP cannot receive Register messages and therefore will not send Register-Stop messages.
    • If the RP has no unicast route to the source DR or the RP has a unicast route to the source DR but cannot ping the source DR, the Register-Stop messages sent from the RP to the source DR will be lost.
    • If the unicast ping succeeds, go to Step 2.
  2. Run the display pim routing-table source-address command in any view of the RP to check whether the corresponding (S, G) entry exists.

    • If the (S, G) entry exists on the RP, the RP has completed the switchover to the SPT towards the source and established a multicast forwarding path to the source DR.
    • If no corresponding (S, G) entry exists on the RP, the RP has not completed the switchover to the SPT towards the source. In this case, the RP does not send a Register-Stop message. The possible cause is that different PIM working modes are configured on the interfaces of all the devices between the RP and the source DR.
